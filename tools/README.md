# tools

Build-time developer tooling (not part of any shipped artifact).

- [`doc-lint/`](doc-lint/README.md) — the comment-limit, doc-reference, `notes/` mirror and Markdown link checker; a standalone Rust workspace run by both platforms' gates.
- [`lint/`](lint/README.md) — the Bazel lint and format targets for the macOS host: clippy and rustfmt (Rust), swift-format (Swift), the markdown checker and the doc-lint comment check.
- [`wolf-pointer-inject/`](wolf-pointer-inject/README.md) — a long-lived Wayland `zwlr_virtual_pointer_v1` client that holds the seat's pointer capability open and injects motion / button / axis events; Linux-only, built by `flake.nix` into the devShell, used by the `wolf-gnome` cage pointer smokes.
- `wolf-macos-app-smoke.sh` — the on-demand macOS entry point of the app-launch smoke. It refuses off macOS, inside a regina worker or a Bazel test, outside this user's unlocked GUI session, with no `bazel` or `python3` on `PATH`, and given any argument ([why](../notes/tools/wolf-macos-app-smoke.sh.md#why-these-refusals)); otherwise it builds `//crates/wolf-macos:Wolf` and `exec`s the harness on the resolved `Wolf.zip`. It has no Bazel target and no gate runs it; [`build.md`](../build.md#the-app-launch-smoke) says when and how to.
- `wolf-macos-app-smoke.py` — the stdlib-only harness behind it. It launches a private copy of the bundle twice against isolated state and config directories and drives it only through Neovim over a prelude socket. Its checks: `:WolfSplitVertical`, `:WolfZoomPane` and `:WolfTerminal` take effect through the drained Ex-command route (C3, C1, C2), `:WolfQuitApplication` exits cleanly (Q) and saves the zoom (R1), the relaunch reopens zoomed (R2), and Toggle Terminal from that zoom unzooms (C2z). Its module docstring holds the scenario and each check's falsifying edit, and [its notes](../notes/tools/wolf-macos-app-smoke.py.md) the launch, isolation and Neovim-driving decisions.
- `wolf-package-smoke.sh` — the packaged-artifact evidence run: it builds `.#wolf-gnome`, prints the store path it resolved, and drives every `#[ignore]`d test that reads or launches that path. An ignored test is honest only when exactly one command runs it and always establishes its precondition; this is that command. Linux-only, run from anywhere, and never beside another `cargo test`, for the reason [`build.md`](../build.md#building-and-testing) gives.
