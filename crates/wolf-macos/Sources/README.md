# wolf-macos/Sources

The Swift sources for the macOS front-end, split into two modules. See the crate [`README.md`](../README.md) for the design decisions and the build workflow.

## `WolfKeyMap/` — the pure key seam (no AppKit)

Two deliberately AppKit-free files, so they are unit-testable headlessly (the macOS analog of wolf-gnome's `gdk_key` and pure picker seams). The Bazel `wolf_key_map` module compiles them together with the swift-bridge-generated Swift glue, so the rest of the app gets the generated types (`FfiKeyEvent`, `WolfCoreHandle`, `FfiFrame`, `FfiFileSearch`, `FfiFileEntry`, `FfiTreeNode`, the free `wolf_ffi_ancestors_to_reveal`, …) via `import WolfKeyMap`.

- **`KeyMap.swift`** — `WolfKeyMap.translate(keyCode:characters:charactersIgnoringModifiers:ctrl:shift:alt:meta:) -> FfiKeyEvent?`. It imports only Foundation and the generated FFI struct. Named keys (Return, Tab, arrows, F-keys, …) are recognized from the virtual `keyCode` first and **keep** the real `shift` flag; printable characters carry the already-shifted glyph in `ch` with `shift = false`; when ctrl/alt/meta are held the glyph comes from `charactersIgnoringModifiers` (lowercased); bare modifiers and unmodified control characters return `nil`. The `Kind` discriminants mirror `wolf_core::Key`'s variant order (and the Rust `key_event_from_ffi`).
- **`PickerSeam.swift`** — `public enum PickerSeam`, Foundation only, ports wolf-gnome's pure picker helpers: `isPickerTrigger(charactersIgnoringModifiers:ctrl:shift:) -> Bool` (the **Shift+Control+P** trigger — `ctrl && shift && first scalar lowercased == "p"`, alt/meta ignored — deliberately non-conflicting so every Neovim key including `<C-p>` is preserved), `nextSelection(current:delta:nRows:) -> Int?` (list-nav clamp, port of `next_selection`), and `restoredIndex(resetToTop:prev:newLen:) -> Int?` (selection restore across streaming result batches, port of `restored_index`).

## `WolfMacOS/` — the AppKit application

The `wolf_macos_lib` module: the native shell that links AppKit / CoreText / CoreGraphics and depends on `:wolf_key_map` and the `wolf-ffi` archive.

- **`main.swift`** — the entry point: `NSApplication.shared`, install the `AppDelegate`, `.regular` activation policy, `app.run()`.
- **`AppDelegate.swift`** — resolves `init_lua` (a `WOLF_INIT_LUA` override, else the bundled `Contents/Resources/init.lua`) and the cwd, calls `wolf_ffi_start`, installs the `WakeBridge`, `PickerWakeBridge`, and `TreeWakeBridge`, builds the window + `GridView`, builds/starts/holds the sidebar `FileTreeView` (registering it with BOTH `WakeBridge.registeredTree` — for current-file reveal on the render wake — and `TreeWakeBridge.registeredTree` — for row rebuilds on the tree wake), builds/holds the overlay `PickerView` (wiring `GridView.onPickerTrigger` to open it), terminates after the last window, and on terminate `close`s the tree + picker sessions before `shutdown`ing the core (showing a fatal alert if the core fails to start).
- **`MainWindow.swift`** — the single "Wolf" `NSWindow`, whose content view is a horizontal `NSSplitView`: the `FileTreeView` sidebar (fixed `treePaneWidth`) on the left and the `GridView` editor on the right. The content width is widened by `treePaneWidth + dividerThickness` so the editor pane keeps its full initial cols × rows cell size (the OCR-checked grid is undisturbed); the `GridView` stays the first responder.
- **`FileTreeView.swift`** — the file-tree sidebar `NSView` (an `NSOutlineView` in an `NSScrollView`), fed by an `FfiFileSearch` session started via `start_tree_search`. Data comes from the FFI projection (`children_of(dir)` → `FfiTreeNode`s, cached as identity-stable `TreeItem`s by `relPath` in `itemsByRelPath`); top level is `children_of("")`, dirs collapsed by default. A single click opens a file (`handle.open(absPath)` then refocus the `GridView`) or toggles a directory. `start()`/`refresh()`/`onRenderWake()`/`reveal(abs:)`/`activate(item:)`/`close()`: `refresh()` (tree wake) reloads rows preserving expansion + retries `pendingReveal`; `onRenderWake()` (editor wake) reads `current_file()`, guards on `lastCurrent`, and on a change re-bolds + reveals; `reveal` expands the ancestor dirs (`wolf_ffi_ancestors_to_reveal`, top-down) before `row(forItem:)`, leaving `pendingReveal` set when `rel_path_for` returns `""`. NSOutlineView glue is exercised by manual smoke only (it needs a window server), like the picker.
- **`GridView.swift`** — the editor `NSView` (flipped, first responder): `draw(_:)` reads an `FfiFrame`, fills each cell's background, draws its glyph via CoreText, and overlays the mode-aware cursor when `cursor_visible`; `keyDown(_:)` runs `WolfKeyMap.translate` → `send_key`; `setFrameSize` / `viewDidEndLiveResize` map the bounds to a `(cols, rows)` grid size → `resize`. It also holds an `onPickerTrigger` closure: `keyDown(_:)` first checks `PickerSeam.isPickerTrigger(...)` and, on a match, invokes the closure (to open the picker) instead of forwarding the key.
- **`PickerView.swift`** — the floating overlay `NSView` panel (an `NSSearchField`
  - an `NSTableView` in an `NSScrollView`) shown over the editor, fed by an `FfiFileSearch` session over the FFI. `open()` starts the session and makes the search field first responder; typing filters via `ranked` (ranking in Rust), Up/Down navigate (`PickerSeam.nextSelection`) with selection restored across streaming batches (`PickerSeam.restoredIndex`), Enter or a double-click calls `open(path)` and closes, Esc closes. While open the search field is first responder, so `GridView.keyDown` does not fire and keys are not forwarded to Neovim.
- **`PickerWakeBridge.swift`** — registers the picker's `extern "C"` wake (`wolf_ffi_set_filesearch_wake`) and, on each streaming-traversal wake, `DispatchQueue.main.async`es onto the main thread to call `PickerView.refresh()` (a late wake after the picker closes is a harmless no-op). It mirrors `WakeBridge`, but drives the picker independently of editor repaints.
- **`TreeWakeBridge.swift`** — registers the sidebar's `extern "C"` wake (`wolf_ffi_set_tree_wake`) and, on each streaming-traversal wake, `DispatchQueue.main.async`es onto the main thread to call `FileTreeView.refresh()` (a late wake after the tree closes is a harmless no-op). The clone of `PickerWakeBridge` for the tree's own long-lived `start_tree_search` session.
- **`CellMetrics.swift`** — measures a monospaced `CTFont` (advance width, ascent + descent + leading, baseline) for SF Mono with a Menlo fallback, `WOLF_FONT_PT` overridable. (Per-cell text attributes are packed by `wolf-ffi` but not yet painted, so only the base font is used.)
- **`Cursor.swift`** — pure cursor-rectangle geometry (block / horizontal / vertical bar from `cursor_shape` + `cursor_cell_percentage`), ported from wolf-gnome's `cursor.rs`; the reverse-video fill/glyph colors are resolved in Rust.
- **`Color.swift`** — converts a packed `FfiColor` (`0x00RRGGBB` + `set`) to a `CGColor`, applying the white/black fallbacks that mirror wolf-gnome's `paint.rs`.
- **`WakeBridge.swift`** — registers the `extern "C"` wake thunk with the core (`wolf_ffi_set_wake`); on each wake it `DispatchQueue.main.async`es onto the AppKit main thread, sets the registered `GridView`'s `needsDisplay` (the wake → dispatch-to-main → `setNeedsDisplay` realization), then calls the registered `FileTreeView.onRenderWake()` so the sidebar reveals + bolds the current buffer (a `current_file` change rides the render wake, not a separate traversal batch).
