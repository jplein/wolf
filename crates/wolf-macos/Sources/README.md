# wolf-macos/Sources

The Swift sources for the macOS front-end, split into two modules. See the crate [`README.md`](../README.md) for the design decisions and the build workflow.

## `WolfKeyMap/` — the pure key seam (no AppKit)

Ten deliberately AppKit-free files, so they are unit-testable headlessly (the macOS analog of wolf-gnome's `gdk_key`, pure picker, and pure pane-layout seams). The Bazel `wolf_key_map` module compiles them together with the swift-bridge-generated Swift glue, so the rest of the app gets the generated types (`FfiKeyEvent`, `FfiMouseEvent`, `FfiScrollEvent`, `WolfCoreHandle`, `FfiFrame`, `FfiConfig`, `FfiFileSearch`, `FfiFileEntry`, `FfiTreeNode`, `FfiLayoutIntent`, `FfiWinInfo`, `FfiState`, `FfiWindowState`, the free `wolf_ffi_ancestors_to_reveal`, `wolf_ffi_load_config`, `wolf_ffi_load_state`, …) via `import WolfKeyMap`.

- **`KeyMap.swift`** — `WolfKeyMap.translate(keyCode:characters:charactersIgnoringModifiers:ctrl:shift:alt:meta:) -> FfiKeyEvent?`. It imports only Foundation and the generated FFI struct. Named keys (Return, Tab, arrows, F-keys, …) are recognized from the virtual `keyCode` first and **keep** the real `shift` flag; printable characters carry the already-shifted glyph in `ch` with `shift = false`; when ctrl/alt/meta are held the glyph comes from `charactersIgnoringModifiers` (lowercased); bare modifiers and unmodified control characters return `nil`. The `Kind` discriminants mirror `wolf_core::Key`'s variant order (and the Rust `key_event_from_ffi`).
- **`PickerSeam.swift`** — `public enum PickerSeam`, Foundation only. Three ports of wolf-gnome's pure picker helpers: `isPickerTrigger(charactersIgnoringModifiers:command:) -> Bool` (the **Command+O** trigger — `command && first scalar lowercased == "o"`, other modifiers ignored — Command-modified keys are not Neovim keybindings, so the chord does not consume a Neovim key), `nextSelection(current:delta:nRows:) -> Int?` (list-nav clamp, port of `next_selection`), and `restoredIndex(resetToTop:prev:newLen:) -> Int?` (selection restore across streaming result batches, port of `restored_index`).
- **`ShortcutSeam.swift`** — `public enum ShortcutSeam`, Foundation only. `isNewWindowTrigger(charactersIgnoringModifiers:command:) -> Bool` — the **Command+N** new-window trigger predicate (`command && first scalar lowercased == "n"`, other modifiers ignored), the sibling of `PickerSeam.isPickerTrigger` matching "n" instead of "o". Headlessly unit-tested by `ShortcutSeamTests`.
- **`WindowIndexSeam.swift`** — `public enum WindowIndexSeam`, Foundation only. `nextFreeIndex(occupied: [Int]) -> Int` — the smallest non-negative integer NOT in `occupied`, so a new (Cmd-N) window reuses the lowest freed `state.json` slot within a session. Headlessly unit-tested by `WindowIndexSeamTests`.
- **`PaneTree.swift`** — a Foundation-only port of wolf-gnome's pure `layout.rs` pane-layout tree, `import Foundation` ONLY (it uses `Double`, not `CGFloat`, so it pulls in no CoreGraphics and stays in the headless test bundle). Public API: `typealias PaneId = UInt64`; `enum Orientation { horizontal, vertical }` and `enum FocusDir { left, right, up, down }` (each with an `init?(ffi:)` decoding the `wolf-ffi` discriminants); `struct Rect`; the `indirect enum PaneLayout { .leaf(PaneId); .split(orientation:children:weights:) }`; and `final class PaneTree` (a reference type, mutated in place) with `init(root:)`, `split(_:_:_:)`, `remove(_:)`, `leaves()`, `paneRects(width:height:)`, `neighbor(_:_:width:height:)`, and `layout()`. The free helpers (`splitIn`, `removeIn`, `normalize`, `collectLeaves`, `collectRects`, `directionalDistance`, `xOverlap`, `yOverlap`, `equalize`) are ported exactly: a SAME-orientation split inserts after the target then re-equalizes (FLATTENING into equal siblings), a PERPENDICULAR split nests, `remove` never empties the tree and re-equalizes / collapses a single child, and `neighbor` uses strictly-positive cross-axis overlap with stable DFS order. The macOS `PaneContainerView` consumes `paneRects()` to paint each pane into a computed rectangle — a single flat view, not an `NSSplitView` tree. Headlessly unit-tested by `PaneTreeTests` (a 1:1 port of the `layout.rs` suite + a discriminant-contract test).
- **`PaneGeometry.swift`** — `public struct PaneGeometry`, Foundation only (`Double`, reusing `Rect` from `PaneTree.swift`), the per-pane pixel↔cell mapping seam. It holds a **GRID RECT** inside a **PANE RECT**; `init(paneRect:cellWidth:cellHeight:maxCols:)` **caps the grid at `maxCols` columns and CENTERS it horizontally** when the pane is wider than that (leaving equal side margins, `paintOffsetX = inset`), while a pane no wider than the cap is unaffected (`gridRect == paneRect`, paint offsets `0`); `maxCols == nil` disables the cap entirely. `PaneContainerView` passes `maxCols: 90`, so a grid wider than 90 columns is centered with side margins. It exposes `cols` / `rows` (`max(1, floor(gridRect.size / cell))`), `paintOffsetX` / `paintOffsetY` (grid-rect origin − pane-rect origin, the centering inset when capped), and `cellAt(x:y:) -> (row, col)` mapping a pane-local point to a grid cell **clamped** into `[0, cols-1] × [0, rows-1]` (a margin / past-edge point lands on the nearest edge cell, so the side margins around a centered grid resolve to the nearest interior cell). Headlessly unit-tested by `PaneGeometryTests`.
- **`ScrollAccumulator.swift`** — `public struct ScrollAccumulator`, Foundation only, a pure signed pixel→line-step accumulator with a carried remainder. `consume(deltaY:cellHeight:) -> Int` returns the signed whole line steps for the delta (guarding `cellHeight <= 0` → `0`) and keeps the sub-cell remainder across calls so smooth trackpad scrolling accumulates; `reset()` clears it. Direction-agnostic (signed); the AppKit layer maps the sign to a scroll direction. Headlessly unit-tested by `ScrollAccumulatorTests`.
- **`CellMetricsMath.swift`** — `public enum CellMetricsMath`, Foundation only, the pure config-driven cell-geometry seam (extracted from `CellMetrics` so it stays headlessly testable). `cellHeight(fontSize:lineHeightPercent:ascent:descent:leading:) -> Double` returns `round(fontSize * lineHeightPercent / 100)`, guarding `lineHeightPercent <= 0` → the font's natural `ceil(ascent + descent + leading)`; `baseline(cellHeight:ascent:descent:) -> Double` returns `ascent + (cellHeight - ascent - descent) / 2`, recentering the glyph within a taller cell. `CellMetrics` feeds it the user config's line-height. Headlessly unit-tested by `CellMetricsMathTests` (130%@14, 100% natural, the degenerate guard, baseline recentering).
- **`GlyphStyle.swift`** — `public enum GlyphFace { regular, bold, italic, boldItalic }`, `public struct GlyphStyle` (`face`, `underline` + `underlineColor: FfiColor`, `strikethrough` + `strikethroughColor: FfiColor`, all `Equatable`), and `public enum GlyphStyleResolver` with `resolve(flags: UInt8, fg: FfiColor, special: FfiColor) -> GlyphStyle`, Foundation only. It maps a cell's packed style-flag bits (mirroring `mod flag` in `wolf-ffi/src/lib.rs`: bold/italic/underline/undercurl/strikethrough) to a face (boldItalic if both bold+italic, else bold, else italic, else regular), folds undercurl into a straight underline, colors the underline with `special` when set (else fg), and strikes through in fg. It also adds `extension FfiColor: Equatable` (component-wise on `rgb` + `set`) so `GlyphStyle` synthesizes `Equatable`. Headlessly unit-tested by `GlyphStyleTests`.
- **`StateSeam.swift`** — `public enum StateSeam` (a namespace mirroring `PickerSeam`), Foundation + CoreGraphics only (no AppKit — it takes scalar/`CGRect` inputs, so the AppKit glue feeds it real window frames, `NSScreen.screens` visible frames, and a FileManager-backed closure). The pure decision seams backing the state-restore path: `ToolbarMode` (a `UInt8` raw-valued enum on the wolf-ffi `toolbar_mode` discriminant table — `iconAndText = 0`, `iconOnly = 1`, `textOnly = 2`; `init?(rawValue:)` yields `nil` for an unknown discriminant so restore leaves the toolbar at its default, `.rawValue` maps back for the save path); `restoredWindowFrame(x:y:width:height:screenVisibleFrames:) -> CGRect?` (`nil` — restore then falls back to the default centered placement — when width/height is non-positive, the "unset" sentinel, or when the frame intersects NO screen visible frame, so a window is never restored fully offscreen); and `launchCwd(restored:fallback:isDirectory:) -> String` (the restored cwd only when non-empty AND `isDirectory(restored)` — it may have been deleted since the last run — else the fallback; the injected closure keeps the seam pure). Headlessly unit-tested by `StateSeamTests`.

## `WolfMacOS/` — the AppKit application

The `wolf_macos_lib` module: the native shell that links AppKit / CoreText / CoreGraphics and depends on `:wolf_key_map` and the `wolf-ffi` archive.

- **`main.swift`** — the entry point: `NSApplication.shared`, install the `AppDelegate`, `.regular` activation policy, `app.run()`.
- **`AppDelegate.swift`** — the app **coordinator**, a thin manager over a `controllers: [WolfWindowController]` collection (one per OS window). At launch it does the once-only, whole-process setup: install the three wake bridges (`WakeBridge` / `PickerWakeBridge` / `TreeWakeBridge`), then **register the bundled fonts, load the user config, then measure the cell metrics, in that order** (`FontRegistration.registerBundledFonts()` → `wolf_ffi_load_config()` → `CellMetrics.measured(config:)`), so both bundled families resolve — "iA Writer Mono S" (the default) and "JetBrains Mono" — and the config's font-family / size / line-height drive the shared grid geometry. Metrics + config are measured ONCE and passed to every controller. It then reads the saved application state (`wolf_ffi_load_state()` BEFORE any core starts) and creates ONE `WolfWindowController` per saved window (its `windowIndex` == its list position), copying each saved window OUT of the bridge's `RustVec<FfiWindowState>` immediately into a plain `RestoredWindowState` (element refs must not outlive the vec, an unknown toolbar discriminant → `nil`); with nothing saved it creates one default controller at index 0. A fatal alert (`presentStartupFailureAndQuit`) fires only when the FIRST window's core fails (a later window's core failing simply opens fewer windows). `makeNewWindow(originatingCwd:)` is the **Command+N** entry: it picks the first free slot via `WindowIndexSeam.nextFreeIndex(occupied:)`, roots the new window at `originatingCwd` (the originating window's live `handle.cwd()`, falling back to `FileManager.default.homeDirectoryForCurrentUser.path` when empty), and creates + `start()`s a controller with `restored: nil` (AppKit cascade placement). `removeController(_:)` drops a controller at window close. `applicationShouldTerminateAfterLastWindowClosed` stays `true`. `applicationWillTerminate` re-pushes each still-live window's snapshot at its own fixed `windowIndex` (NOT a dense re-index) then prunes ghost slots via `state_set_window_count(highestLiveIndex + 1)` (only when a window is still open at quit; see the crate README's v1 stale-restoration limitation), then tears down the remaining controllers as a backstop.
- **`WolfWindowController.swift`** — owns ONE window's stack (moved out of the old monolithic `AppDelegate`): its `handle`, `window`, `paneContainer`, `tree`, `picker`, `statePersistence`, fixed `windowIndex`, and per-window `wakeToken`. `start()` points wolf-core at the bundled Neovim (`WOLF_NVIM_BIN` via `setenv(..., 0)` so a dev override wins), resolves `init_lua` (`WOLF_INIT_LUA` else `Contents/Resources/init.lua`), calls `wolf_ffi_start(..., UInt16(windowIndex))`, reads `handle.wake_token()`, and **registers itself in `WindowRegistry` under that token** so wakes route back to this window; it then builds the pane container / sidebar `FileTreeView` / overlay `PickerView` / `MainWindow`, wires `paneContainer.onNewWindow` (→ `coordinator.makeNewWindow(originatingCwd: handle.cwd())`) and `onPickerTrigger`, restores the saved frame/sidebar/toolbar ONLY for a restored window (frame via `StateSeam.restoredWindowFrame` against `NSScreen.screens.map(\.visibleFrame)`, else `center()`; a fresh Cmd-N window keeps cascade placement), installs a `StatePersistence` + one `pushSnapshot()`, sets itself as the window delegate, shows the window, and makes the pane container first responder. Returns `false` (having built nothing) when the core fails to start. `onRenderWake()` drives `paneContainer.onRenderWake()` + `tree.onRenderWake()`. `windowWillClose(_:)` → `teardown()` (guarded once by `isTornDown`): push a final snapshot + `state_flush()`, close the tree + picker sessions, `shutdown` the core, unregister from `WindowRegistry`, and ask the coordinator to drop it — idempotent, so the terminate-time backstop is safe.
- **`WindowRegistry.swift`** — `final class WindowRegistry` (a `shared` singleton), the process-global, **main-thread-only** map from a core's per-window wake `token` (`UInt64`) to the owning `WolfWindowController`. The wake fires on a tokio worker thread with only a plain `Send` `u64`; the three `*WakeBridge` thunks hop onto the main thread and look the token up HERE (`controller(for:)`) to reach the right window. `register` / `unregister` / `controller(for:)`, no lock needed (every access is on the main thread).
- **`MainWindow.swift`** — the single "Wolf" `NSWindow`. Its `contentViewController` is an `EditorSplitViewController` (retained, so the sidebar split item stays reachable for state restore/persistence; the `sidebarItem` accessor forwards to it); the window uses a transparent `.fullSizeContentView` titlebar (`titlebarAppearsTransparent = true`, `titleVisibility = .visible`) and a minimal unified `NSToolbar` (`toolbarStyle = .unified`) vended by a retained `EditorToolbarDelegate` (`.toggleSidebar`, an `NSTrackingSeparatorToolbarItem` bound to the split divider, and `.flexibleSpace`; the delegate is held in a `let` because `NSToolbar.delegate` is weak), with `allowsDisplayModeCustomization = true` so the toolbar's icon+text / icon-only / text-only context menu exists (the chosen mode is persisted per window in `state.json`). After the content VC + toolbar are attached, it measures the titlebar/toolbar chrome (`contentView.bounds.height − contentLayoutRect.height`) and sets the content size to `treePaneWidth + dividerThickness + cols·cellWidth` × `rows·cellHeight + cmdlineStripHeight + chrome` so the editor PANE keeps its exact initial cols × rows below the titlebar with the **cmdline strip as EXTRA height** (the OCR-checked 80-col grid is undisturbed); it then pins the divider at `treePaneWidth` and sets `initialFirstResponder = paneContainer`. `.toggleSidebar` routes up the responder chain to the split VC (no wiring).
- **`EditorSplitViewController.swift`** — the `NSSplitViewController` backing the window content: a leading `.sidebar` split item (`NSSplitViewItem(sidebarWithViewController:)` → OS vibrancy, full-height under the titlebar, collapsible, with the higher holding priority that makes the EDITOR pane absorb resizing — NOT lowered) wrapping the `FileTreeView`, and a trailing content item wrapping the `PaneContainerView`; `minThickness` / `maxThickness` bound the sidebar width and `pinDivider()` pins it at `MainWindow.treePaneWidth`. The `sidebarItem` accessor exposes the leading split item so state restore can set — and `StatePersistence` can observe — `isCollapsed`. Both panes are hosted by a small `HostViewController`: the SIDEBAR host adopts the `FileTreeView` directly as its `view` (so the `.sidebar` material fills the pane), while the CONTENT host pins the `PaneContainerView` leading/trailing/bottom to a container and its **top to the container's `safeAreaLayoutGuide.topAnchor`**, so the editor is not obscured by the transparent titlebar/toolbar. Compile-verified + manual-smoke only (no window server).
- **`StatePersistence.swift`** — `final class StatePersistence: NSObject`, the write-only save glue owned by each `WolfWindowController` (weak refs to the window / sidebar split item / toolbar; the handle is held strongly). `install()` registers NotificationCenter observers for `NSWindow.didMoveNotification`, `didEndLiveResizeNotification`, and `didResizeNotification` (the last skipped while `inLiveResize` — live resize spams per-frame `didResize`, so only the end-of-live-resize push and discrete resizes like zoom / programmatic `setFrame` fire), KVO on the sidebar item's `isCollapsed`, and best-effort KVO on the toolbar's `displayMode` (not documented-guaranteed; the terminate-time snapshot is the correctness backstop). Each change pushes over the wolf-ffi bridge at the handle's fixed `window_index`: `state_set_geometry` (the window frame in AppKit bottom-left global points), `state_set_sidebar_visible` (the inverse of `isCollapsed`), and `state_set_toolbar_mode` (mapped through the shared `StateSeam.ToolbarMode` discriminant table; `.default` — the user never chose an explicit mode — and a missing toolbar clear the persisted mode with `set == false`, so restore leaves the system default alone). `pushSnapshot()` pushes all three facets at once, called once right after the window is shown (from the controller's `start()`) and from the controller's `teardown()` / the coordinator's `applicationWillTerminate`. It performs NO file IO (wolf-core's writer thread owns the file) and no restore (the controller restores before the window is shown); the cwd is persisted core-side (the `wolf_cwd` hook) with no involvement here. Observers are removed / invalidated in `deinit`. AppKit glue, so compile-verified + manual-smoke only; the pure decisions live in `StateSeam`.
- **`FileTreeView.swift`** — the file-tree sidebar `NSView` (an `NSOutlineView` in an `NSScrollView`), fed by an `FfiFileSearch` session started via `start_tree_search`. The cwd itself is shown as a single **synthetic root node** (`makeRoot(_:)`: a directory `TreeItem` whose name is the cwd's basename, with the sentinel rel-path `""`, kept OUT of `itemsByRelPath`); `children(of:)` branches explicitly — `nil` → `[rootItem]`, a `TreeItem` → `children_of(relPath)` (the root's `""` → `children_of("")`). Real children are cached as identity-stable `TreeItem`s by `relPath` in `itemsByRelPath`. The outline uses the standard `.sourceList` style (which drives the sidebar row metrics — no explicit `rowHeight`) and draws a **clear background** (`outlineView.backgroundColor = .clear`, `scrollView.drawsBackground = false`); the vibrancy material comes from the enclosing `.sidebar` split item, so the view adds **no own `NSVisualEffectView`** (avoiding double vibrancy). The synthetic cwd root stays a normal selectable/expandable row (no `isGroupItem` group-row styling). The root is **expanded on init** (`refresh()` calls `expandItem(rootItem)` once, guarded by `didInitialExpand`, after the root has streamed children) with its subdirectories collapsed — the VS Code / Snacks model, **divergent from the GNOME tree**. A single click opens a file (`handle.open(absPath)` then refocus the editor `PaneContainerView`) or toggles a directory. The sidebar **follows nvim's live cwd**: `start()` roots from `handle.cwd().toString()`; `onRenderWake()` (editor wake) reads `cwd()` FIRST and, when it changed, `reroot(to:)` (rebuild the root, restart `start_tree_search()`, clear `itemsByRelPath`, reset `didInitialExpand`, re-arm `pendingReveal = currentFileAbs`), THEN reads `current_file()`, guards on `lastCurrent`, and on a change re-bolds + reveals. `refresh()` (tree wake) reloads rows preserving expansion + retries `pendingReveal`; `reveal` expands the synthetic root, then the ancestor dirs (`wolf_ffi_ancestors_to_reveal`, top-down) before `row(forItem:)`, leaving `pendingReveal` set when `rel_path_for` returns `""`. NSOutlineView glue is exercised by manual smoke only (it needs a window server), like the picker.
- **`PaneContainerView.swift`** — the editor area's split-panes view (the macOS analog of wolf-gnome's `pane_view.rs`), and the editor area's first responder + single global key sink. It is a **single flat `NSView`** (flipped, the proven `GridView` pattern) that paints EVERY pane itself — deliberately NOT a tree of nested `NSSplitView`s, which composited unreliably when stacked under the source-list split. It owns the pure `WolfKeyMap.PaneTree` and a `panes: [PaneId: PaneBinding]` map (each `PaneBinding` is a Neovim `win` + its `boundGrid`, `nil` until resolved). `draw(_:)` computes every pane's rectangle via `PaneTree.paneRects(width, paneAreaHeight)` and, for each bound pane, clips+translates to that rect and paints the pane's window grid (cell backgrounds + CoreText glyphs — each glyph in the bold/italic/boldItalic face and with the underline/strikethrough decorations that `GlyphStyleResolver` resolves from the cell's `flags()` + `special()`, underline/strikethrough stroked manually in the resolved color since `CTLineDraw` ignores decoration-color attributes — plus the mode-aware cursor when `cursor_visible`); each pane is drawn **independently of Neovim**, so an INACTIVE pane gets a translucent dim scrim (`inactiveDim`) — a front-end-only treatment that is awkward to express inside Neovim. Thin separators are stroked between adjacent panes, and the bottom one-row **cmdline strip** paints Neovim's command line: under `ext_multigrid` the command line / messages live on a dedicated MESSAGE grid (NOT grid 1), positioned at the bottom via `msg_set_pos` (which the core drops), and the cursor moves onto it while the command line is open — so the strip identifies that grid as "the grid the cursor is on that is neither grid 1 nor a window grid" and paints its cursor row (with the cursor), falling back to grid 1's LAST row otherwise. `keyDown(_:)` checks `PickerSeam.isPickerTrigger` (→ `onPickerTrigger`) else runs `WolfKeyMap.translate` → `send_key` (keys go to nvim's current window globally). **Mouse / scroll** route through a per-pane `PaneGeometry` (`geometry(for:)`, `maxCols: nil`): `mouseDown` `focus_win`s the clicked pane (click-to-focus preserved) and `send_mouse`s a LEFT PRESS at `geo.cellAt(point)` on that pane's grid; `mouseDragged` / `mouseUp` send DRAG / RELEASE on the drag's grid (clamped), so `mouse=a` gives cursor-position + visual selection. `scrollWheel` hit-tests from the whole PANE rect (future side-margin still scrolls), accumulates `scrollingDeltaY` into line steps via a `ScrollAccumulator` (reset on grid change), and `send_scroll`s UP/DOWN on the pane's grid at the pointer cell (using `scrollingDeltaY`'s sign directly — it already reflects the user's natural-scroll setting, so `isDirectionInvertedFromDevice` is NOT re-applied, which would double-invert; a single commented flip point remains). **Synthetic scrollbars** are custom-drawn per pane in `draw(_:)` at each pane's right edge from the frame viewport (`topline` / `botline` / `linecount`, 0-based; thumb offset `topline / linecount`, underflow-safe, nothing drawn when the whole buffer is visible), following `NSScroller.preferredScrollerStyle` (`.legacy` always + faint track / `.overlay` fade after scroll) and reacting to `NSScroller.preferredScrollerStyleDidChangeNotification` (observer removed in `deinit`); the thumb is **non-interactive** (drag deferred). `onRenderWake()` mirrors GNOME's orchestration: `ensureInitialPane` (a `pick_initial_window` port — prefer `active_win()` if it is a real window grid `>= 2` and not hidden, else the lowest visible window grid from `windows()`, reusing the tree's root `firstPaneId`), `applyIntents` (`drain_intents` → SPLIT splits the `from`/active pane in the tree and binds a new pane to the new window via `grid_for_win` — 0 → pending; FOCUS_DIR resolves `tree.neighbor` and calls `focus_win`), `detectCloses` (the live-grid set from `windows()`; a pane whose bound grid vanished is removed, never below one leaf), `resolvePendingGrids`, `updateActivePane` (the pane whose `win == active_win()`, else whose bound grid `== read_frame().cursor_grid()`), then `syncGridSizes` (resize grid 1 to the whole view and each bound pane's grid to its rect, but ONLY when the size differs from nvim's current — so it converges, no resize-feedback loop) and a `needsDisplay`. **Divider drag-to-resize is deferred** (splits are equal-weighted, parity with wolf-gnome's v1 divider limitation; `NSSplitView` would have given drag for free but at the cost of the fragile nesting). AppKit glue, so compile-verified + manual-smoke only.
- **`PickerView.swift`** — the floating overlay `NSView` panel (a larger-font, focus-ring-less **search bar** — a rounded container holding a magnifier `NSImageView` + a borderless `NSTextField`, built by hand rather than an `NSSearchField` whose text cell clips a large font — plus an `NSTableView` in an `NSScrollView`) shown over the editor, fed by an `FfiFileSearch` session over the FFI. `open()` starts the session, focuses the search field, and does an initial `refresh()` so the picker opens already showing the empty-query MRU-first result seed (mirroring wolf-gnome's `PickerInner::open`); the panel height is **content-driven** (`updateResultsLayout` toggles the scroll view's top/height/bottom constraints against an empty-state bottom constraint) — just the search field when there are no rows, then the field plus the results sized to the content height and capped at `maxListHeight` (beyond which it scrolls); typing filters via `ranked` (ranking in Rust) and maps each `FfiFileEntry` into a file-agnostic `PickerRow` at the boundary (title = the entry's full working-directory-relative path (`display()`) — Neovim users expect to see paths, so the whole relative path is the single line, not just the base filename — payload = absolute path, icon = the Finder icon via `fileIcon(forPath:)` / `NSWorkspace`); Up/Down navigate (`PickerSeam.nextSelection`) with selection restored across streaming batches (`PickerSeam.restoredIndex`); `viewFor` dequeues a `PickerRowCellView` and calls `configure(with:)`; `activateSelection()` opens `rows[idx].payload` and closes; Esc closes. Row alignment insets (icon aligned with the magnifier, title with the typed text) are derived from the search-bar layout constants (the magnifier's inset and width). While open the text field is first responder, so `PaneContainerView.keyDown` does not fire and keys are not forwarded to Neovim.
- **`PickerRow.swift`** — a file-agnostic value type (`icon: NSImage?`, single-line `title`, opaque `payload: String`) describing one picker list row so the same panel can back other selectors (a buffer selector would set title = the buffer's path, payload = a buffer id/token). Only `activateSelection()` consumes the payload.
- **`PickerRowCellView.swift`** — a reusable `final class PickerRowCellView: NSTableCellView` rendering any `PickerRow`: a leading `NSImageView` (small icon, aligned with the magnifier) + a single title label (aligned with the typed text via the caller-injected `iconLeadingInset` / `labelLeadingInset`), with the icon's BOTTOM pinned to the text baseline. Exposes `configure(with:)`, static layout constants + fonts (`iconSize`, `titleFontSize`, `iconToTextGap`, …), and `static rowHeight(iconSize:titleFont:verticalPadding:)`.
- **`PickerWakeBridge.swift`** — installs the picker's `extern "C"` wake (`wolf_ffi_set_filesearch_wake`) ONCE at launch and, on each streaming-traversal wake, `DispatchQueue.main.async`es onto the main thread, looks the firing core's `token` up in `WindowRegistry`, and calls that window's `picker?.refresh()` (a late wake after the picker closes / the window is gone is a harmless no-op). It mirrors `WakeBridge`, but drives the picker independently of editor repaints.
- **`TreeWakeBridge.swift`** — installs the sidebar's `extern "C"` wake (`wolf_ffi_set_tree_wake`) ONCE at launch and, on each streaming-traversal wake, `DispatchQueue.main.async`es onto the main thread, looks the `token` up in `WindowRegistry`, and calls that window's `tree?.refresh()` (a late wake after the tree closes / the window is gone is a harmless no-op). The clone of `PickerWakeBridge` for the tree's own long-lived `start_tree_search` session.
- **`CellMetrics.swift`** — measures a monospaced `CTFont` (advance width, ascent + descent + leading, cell height, baseline) from the resolved user config: `measured(config: FfiConfig)` takes the point size from `config.font_size` (`WOLF_FONT_PT` still OVERRIDES it) and the family from `config.font_family` (case-insensitive via `CTFontCopyFamilyName`, **Menlo** fallback when it does not resolve — no longer the old "SF Mono → Menlo" default), and derives the cell height + baseline from `config.line_height` via the pure `CellMetricsMath` seam. It also derives and **caches the bold / italic / boldItalic faces** (via `CTFontCreateCopyWithSymbolicTraits`, falling back to the regular face when CoreText resolves no distinct face), exposed through `font(for: GlyphFace)`; `cellWidth` is measured from the REGULAR face only so every face paints into the same fixed-cell slot (advance-width stability).
- **`FontRegistration.swift`** — `enum FontRegistration`; `static func registerBundledFonts()` enumerates `Bundle.main.resourcePath + "/fonts"/*.ttf` (BOTH bundled families — the JetBrains Mono and iA Writer Mono S faces merged into the one `fonts/` dir) and registers them with CoreText via `CTFontManagerRegisterFontURLs(.process)` so both `"iA Writer Mono S"` (the default) and `"JetBrains Mono"` resolve in `CellMetrics`. It **logs, never fails** on an absent `fonts/` dir (dev / Linux parity). `AppDelegate` calls it at launch before loading the config + measuring. Compile-verified + manual-smoke only (font registration / on-screen resolution are not headlessly testable).
- **`Cursor.swift`** — pure cursor-rectangle geometry (block / horizontal / vertical bar from `cursor_shape` + `cursor_cell_percentage`), ported from wolf-gnome's `cursor.rs`; the reverse-video fill/glyph colors are resolved in Rust.
- **`Color.swift`** — converts a packed `FfiColor` (`0x00RRGGBB` + `set`) to a `CGColor`, applying the white/black fallbacks that mirror wolf-gnome's `paint.rs`.
- **`WakeBridge.swift`** — installs the editor `extern "C"` render wake (`wolf_ffi_set_wake`) ONCE at launch; on each wake it `DispatchQueue.main.async`es onto the AppKit main thread, looks the firing core's `token` up in `WindowRegistry`, and calls that window's `WolfWindowController.onRenderWake()` — which drives `PaneContainerView.onRenderWake()` (apply drained layout intents, then mark every pane + the cmdline strip for redisplay) then `FileTreeView.onRenderWake()` so the sidebar reveals + bolds the current buffer (a `current_file` change rides the render wake, not a separate traversal batch). The wake closures capture only the global `WindowRegistry` (no per-window state), so they stay `@convention(c)`.
