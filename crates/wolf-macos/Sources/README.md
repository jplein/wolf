# wolf-macos/Sources

The Swift sources for the macOS front-end, split into two modules. See the crate [`README.md`](../README.md) for the design decisions and the build workflow.

## `WolfKeyMap/` — the pure key seam (no AppKit)

Seventeen deliberately AppKit-free files, so they are unit-testable headlessly (the macOS analog of wolf-gnome's `gdk_key`, pure picker, and pure pane-layout seams). The Bazel `wolf_key_map` module compiles them together with the swift-bridge-generated Swift glue, so the rest of the app gets the generated types (`FfiKeyEvent`, `FfiMouseEvent`, `FfiScrollEvent`, `WolfCoreHandle`, `FfiFrame`, `FfiConfig`, `FfiFileSearch`, `FfiFileEntry`, `FfiTreeNode`, `FfiLayoutIntent`, `FfiWinInfo`, `FfiPaneStatus`, `FfiCommand`, `FfiCommandPalette`, `FfiCommandRow`, `FfiState`, `FfiWindowState`, the free `wolf_ffi_ancestors_to_reveal`, `wolf_ffi_load_config`, `wolf_ffi_load_state`, …) via `import WolfKeyMap`.

- **`KeyMap.swift`** — `WolfKeyMap.translate(keyCode:characters:charactersIgnoringModifiers:ctrl:shift:alt:meta:) -> FfiKeyEvent?`. It imports only Foundation and the generated FFI struct. Named keys (Return, Tab, arrows, F-keys, …) are recognized from the virtual `keyCode` first and **keep** the real `shift` flag; printable characters carry the already-shifted glyph in `ch` with `shift = false`; when ctrl/alt/meta are held the glyph comes from `charactersIgnoringModifiers` (lowercased); bare modifiers and unmodified control characters return `nil`. The `Kind` discriminants mirror `wolf_core::Key`'s variant order (and the Rust `key_event_from_ffi`).
- **`PickerSeam.swift`** — `public enum PickerSeam`, Foundation only. Three ports of wolf-gnome's pure picker helpers: `isPickerTrigger(charactersIgnoringModifiers:command:) -> Bool` (the **Command+O** trigger — `command && first scalar lowercased == "o"`, other modifiers ignored — Command-modified keys are not Neovim keybindings, so the chord does not consume a Neovim key), `nextSelection(current:delta:nRows:) -> Int?` (list-nav clamp, port of `next_selection`), and `restoredIndex(resetToTop:prev:newLen:) -> Int?` (selection restore across streaming result batches, port of `restored_index`).
- **`PickerRefreshCoalescer.swift`** — `public final class PickerRefreshCoalescer`, Foundation only (headlessly tested by `PickerRefreshCoalescerTests`), a debounce/coalescing seam SHARED by BOTH the file picker (`PickerView`) and the file-tree sidebar (`FileTreeView`). The name is historical; the seam is generic (its `schedule` / `perform` collaborators are injected). It exposes `static let refreshInterval: TimeInterval = 0.033` (~30 fps), `request()`, and `cancelPending()`: `request()` COALESCES a burst of streaming-traversal wakes into ONE trailing refresh (the first call arms the timer, later calls while armed drop, and the fire clears the flag so a later wake re-arms — the FINAL / complete wake is never dropped), and `cancelPending()` clears the armed flag (an already-armed timer still fires, but the caller's `refresh()` is a no-op once closed). Both wake bridges call the owning view's `scheduleRefresh()` → `request()`.
- **`PaletteSeam.swift`** — `public enum PaletteSeam`, Foundation only, the command-palette sibling of `PickerSeam`. `isPaletteTrigger(charactersIgnoringModifiers:command:) -> Bool` is the **Command+P** trigger (`command && first scalar lowercased == "p"`, other modifiers ignored) — matching "p" instead of "o". **DORMANT / UNWIRED:** ⌘P is a menu key-equivalent that preempts `keyDown` (exactly like ⌘N and `ShortcutSeam`), so the View-menu item is the real trigger and `PaletteSeam.isPaletteTrigger` is NOT called from `PaneContainerView.keyDown`; it is kept for consistency with `PickerSeam` and still pinned by `PaletteSeamTests`. The nested `PaletteRowKind: UInt8` (`staticCommand = 0`, `switchWindow = 1`, `openRecent = 2`) with a guarded `init?(ffi:)` mirrors `wolf-ffi`'s `mod palette_row_kind`. Headlessly unit-tested by `PaletteSeamTests`.
- **`ShortcutSeam.swift`** — `public enum ShortcutSeam`, Foundation only. `isNewWindowTrigger(charactersIgnoringModifiers:command:) -> Bool` — the **Command+N** new-window trigger predicate (`command && first scalar lowercased == "n"`, other modifiers ignored), the sibling of `PickerSeam.isPickerTrigger` matching "n" instead of "o". **NOW DORMANT / UNWIRED:** New Window moved to the menu's ⇧⌘N key-equivalent and plain ⌘N is the File > New (`:enew`) menu item, so `PaneContainerView` no longer intercepts Cmd-N in `keyDown` (menu key-equivalents preempt `keyDown`). The seam and `ShortcutSeamTests` are kept as a still-passing pure seam, but nothing in the live app calls `isNewWindowTrigger`. Headlessly unit-tested by `ShortcutSeamTests`.
- **`WindowIndexSeam.swift`** — `public enum WindowIndexSeam`, Foundation only. `nextFreeIndex(occupied: [Int]) -> Int` — the smallest non-negative integer NOT in `occupied`, so a new (Cmd-N) window reuses the lowest freed `state.json` slot within a session. Headlessly unit-tested by `WindowIndexSeamTests`.
- **`PaneTree.swift`** — a Foundation-only port of wolf-gnome's pure `layout.rs` pane-layout tree, `import Foundation` ONLY (it uses `Double`, not `CGFloat`, so it pulls in no CoreGraphics and stays in the headless test bundle). Public API: `typealias PaneId = UInt64`; `enum Orientation { horizontal, vertical }` and `enum FocusDir { left, right, up, down }` (each with an `init?(ffi:)` decoding the `wolf-ffi` discriminants); `struct Rect`; the `indirect enum PaneLayout { .leaf(PaneId); .split(orientation:children:weights:) }`; and `final class PaneTree` (a reference type, mutated in place) with `init(root:)`, `split(_:_:_:)`, `remove(_:)`, `leaves()`, `paneRects(width:height:)`, `neighbor(_:_:width:height:)`, and `layout()`. The free helpers (`splitIn`, `removeIn`, `normalize`, `collectLeaves`, `collectRects`, `directionalDistance`, `xOverlap`, `yOverlap`, `equalize`) are ported exactly: a SAME-orientation split inserts after the target then re-equalizes (FLATTENING into equal siblings), a PERPENDICULAR split nests, `remove` never empties the tree and re-equalizes / collapses a single child, and `neighbor` uses strictly-positive cross-axis overlap with stable DFS order. The macOS `PaneContainerView` consumes `paneRects()` to paint each pane into a computed rectangle — a single flat view, not an `NSSplitView` tree. Headlessly unit-tested by `PaneTreeTests` (a 1:1 port of the `layout.rs` suite + a discriminant-contract test).
- **`PaneGeometry.swift`** — `public struct PaneGeometry`, Foundation only (`Double`, reusing `Rect` from `PaneTree.swift`), the per-pane pixel↔cell mapping seam. It holds a **GRID RECT** inside a **PANE RECT**; `init(paneRect:cellWidth:cellHeight:maxCols:)` **caps the grid at `maxCols` columns and CENTERS it horizontally** when the pane is wider than that (leaving equal side margins, `paintOffsetX = inset`), while a pane no wider than the cap is unaffected (`gridRect == paneRect`, paint offsets `0`); `maxCols == nil` disables the cap entirely. `PaneContainerView` passes `maxCols: 90`, so a grid wider than 90 columns is centered with side margins. It exposes `cols` / `rows` (`max(1, floor(gridRect.size / cell))`), `paintOffsetX` / `paintOffsetY` (grid-rect origin − pane-rect origin, the centering inset when capped), and `cellAt(x:y:) -> (row, col)` mapping a pane-local point to a grid cell **clamped** into `[0, cols-1] × [0, rows-1]` (a margin / past-edge point lands on the nearest edge cell, so the side margins around a centered grid resolve to the nearest interior cell). Headlessly unit-tested by `PaneGeometryTests`.
- **`ScrollAccumulator.swift`** — `public struct ScrollAccumulator`, Foundation only, a pure signed pixel→line-step accumulator with a carried remainder. `consume(deltaY:cellHeight:) -> Int` returns the signed whole line steps for the delta (guarding `cellHeight <= 0` → `0`) and keeps the sub-cell remainder across calls so smooth trackpad scrolling accumulates; `reset()` clears it. Direction-agnostic (signed); the AppKit layer maps the sign to a scroll direction. Headlessly unit-tested by `ScrollAccumulatorTests`.
- **`CellMetricsMath.swift`** — `public enum CellMetricsMath`, Foundation only, the pure config-driven cell-geometry seam (extracted from `CellMetrics` so it stays headlessly testable). `cellHeight(fontSize:lineHeightPercent:ascent:descent:leading:) -> Double` returns `round(fontSize * lineHeightPercent / 100)`, guarding `lineHeightPercent <= 0` → the font's natural `ceil(ascent + descent + leading)`; `baseline(cellHeight:ascent:descent:) -> Double` returns `ascent + (cellHeight - ascent - descent) / 2`, recentering the glyph within a taller cell. `CellMetrics` feeds it the user config's line-height. Headlessly unit-tested by `CellMetricsMathTests` (130%@14, 100% natural, the degenerate guard, baseline recentering).
- **`FontSizeSeam.swift`** — `public enum FontSizeSeam`, Foundation only, the pure step+clamp math for the View font-size commands (extracted so it stays headlessly testable). It owns the constants `minPointSize = 6`, `maxPointSize = 72`, `step = 1` (all `Double`) plus `clamped(_:) -> Double`, `increased(_:) -> Double` (`clamped(current + step)`), and `decreased(_:) -> Double` (`clamped(current - step)`); it owns ONLY the increment/clamp math — RESET (to the window's stored default) is the `WolfWindowController`'s job, not the seam's. Headlessly unit-tested by `FontSizeSeamTests` (±1 step, clamp at 6/72, in-range pass-through, 71→72, 72→72, 7→6, 6→6).
- **`GlyphStyle.swift`** — `public enum GlyphFace { regular, bold, italic, boldItalic }`, `public struct GlyphStyle` (`face`, `underline` + `underlineColor: FfiColor`, `strikethrough` + `strikethroughColor: FfiColor`, all `Equatable`), and `public enum GlyphStyleResolver` with `resolve(flags: UInt8, fg: FfiColor, special: FfiColor) -> GlyphStyle`, Foundation only. It maps a cell's packed style-flag bits (mirroring `mod flag` in `wolf-ffi/src/lib.rs`: bold/italic/underline/undercurl/strikethrough) to a face (boldItalic if both bold+italic, else bold, else italic, else regular), folds undercurl into a straight underline, colors the underline with `special` when set (else fg), and strikes through in fg. It also adds `extension FfiColor: Equatable` (component-wise on `rgb` + `set`) so `GlyphStyle` synthesizes `Equatable`. Headlessly unit-tested by `GlyphStyleTests`.
- **`StateSeam.swift`** — `public enum StateSeam` (a namespace mirroring `PickerSeam`), Foundation + CoreGraphics only (no AppKit — it takes scalar/`CGRect` inputs, so the AppKit glue feeds it real window frames, `NSScreen.screens` visible frames, and a FileManager-backed closure). The pure decision seams backing the state-restore path: `restoredWindowFrame(x:y:width:height:screenVisibleFrames:) -> CGRect?` (`nil` — restore then falls back to the default centered placement — when width/height is non-positive, the "unset" sentinel, or when the frame intersects NO screen visible frame, so a window is never restored fully offscreen); and `launchDecision(restored:home:isDirectory:) -> LaunchDecision` (the launch model — `LaunchDecision` is `.folder(cwd:)` when `restored` is non-empty AND `isDirectory(restored)`, else `.emptyState(nvimCwd: home)` for an empty or deleted/replaced restored cwd; it NEVER returns the process working directory — the old `launchCwd` fallback that polluted the recent-dirs MRU is GONE; the injected closure keeps the seam pure). Headlessly unit-tested by `StateSeamTests`.
- **`StatusbarLayout.swift`** — `public struct StatusbarLayout`, Foundation only, the pure vertical-layout math for the per-pane statusbar strip. `init(primaryFontSize:secondaryFontSize:verticalPadding:lineGap:)` computes each line height as `ceil(fontSize * 1.25)` (a pinned `lineFactor`), places the primary (filename) line at `verticalPadding` and the secondary (path) line one `lineGap` below its bottom, and sizes the total `height` to leave a matching `verticalPadding` beneath the secondary line. It exposes `height`, `primaryLineTop`, `primaryLineHeight`, `secondaryLineTop`, `secondaryLineHeight` (all `Double`). `PaneContainerView` derives the strip height + line rects from it (primary/secondary font sizes from the grid's `CTFont`); the on-screen bg fill / NSString drawing / truncation are AppKit glue (manual-smoke only). Headlessly unit-tested by `StatusbarLayoutTests` (the exact height 37 for (13, 10, 3, 1) plus the structural invariants).
- **`CommandSeam.swift`** — `public enum CommandKind`, Foundation only, an AppKit-free command-kind decode seam (the sibling of `PaneTree`'s `Orientation(ffi:)` / `FocusDir(ffi:)`). The fourteen cases mirror `wolf-ffi`'s `mod command_kind` and the `wolf_core::Command` variant order: `newWindow == 0`, `closeWindow == 1`, `quitApplication == 2`, `hideApplication == 3`, `minimizeWindow == 4`, `goToFile == 5`, `openFile == 6`, `openFolder == 7`, `closePane == 8`, `newBuffer == 9`, `resetFontSize == 10`, `increaseFontSize == 11`, `decreaseFontSize == 12`, `commandPalette == 13`. `init?(ffi: UInt8)` decodes the FFI byte (`0..13` → the matching case, anything else → `nil`), guarding the discriminant contract; the byte is delivered either in an `NSMenuItem.tag` (the native menu path) or by a drained `FfiCommand.kind()` (the nvim-drained path), and both faces funnel through the one `CommandDispatcher`. Headlessly unit-tested by `CommandSeamTests`.

## `WolfMacOS/` — the AppKit application

The `wolf_macos_lib` module: the native shell that links AppKit / CoreText / CoreGraphics and depends on `:wolf_key_map` and the `wolf-ffi` archive.

- **`main.swift`** — the entry point: `NSApplication.shared`, install the `AppDelegate`, `.regular` activation policy, `app.run()`.
- **`AppMenu.swift`** — `enum AppMenu`, builds and installs the native **NSMenu app menu bar** once (`install(target: AppDelegate) -> InstalledMenus`, RETURNING the `InstalledMenus { window; openRecent }` pair of dynamic submenus so the `AppDelegate` can rebuild both dynamic tails) from wolf-macos's OWN hardcoded item description (it does NOT read the core registry over FFI — only the `command_kind` discriminant crosses the bridge): **App** (About / Hide `⌘H` / Quit `⌘Q`), **File** (New `⌘N` / New Window `⇧⌘N` / separator / Go to File `⌘O` / Open File _(no shortcut)_ / Open Folder `⇧⌘O` / **Open Recent** _(dynamic submenu, no shortcut)_ / separator / Close `⌘W` / Close Window `⇧⌘W`), **View** (**Toggle Sidebar** `⌃⌘S` / separator / Reset Font Size `⌘0` / Increase Font Size `⌘=` / Decrease Font Size `⌘-` / separator / **Command Palette…** `⌘P` / separator / **Enter Full Screen** `⌃⌘F`), **Window** (Minimize `⌘M` / separator / a DYNAMIC list of one item per open window, titled with its cwd). The item titles mirror `wolf_core::COMMAND_SPECS` (ellipses are single U+2026); a private `Tag` enum holds the FFI `command_kind` discriminants `0..13` (`closePane = 8`, `newBuffer = 9`, `resetFontSize = 10`, `increaseFontSize = 11`, `decreaseFontSize = 12`, `commandPalette = 13`). **Enter Full Screen is NET-NEW and is NOT a Wolf command** (a spec-vs-implementation deviation flagged per CLAUDE.md — no fullscreen item existed before): it is a STANDARD AppKit item whose action is `#selector(NSWindow.toggleFullScreen(_:))` with a `nil` target (routed to the key `NSWindow`) and mask `[.control, .command]`; it carries no `Tag`/`command_kind`, AppKit owns its validation + Enter/Exit title toggle, and `validateMenuItem` needs no change for it. **Toggle Sidebar is likewise a STANDARD AppKit item and NOT a Wolf command** (no core registry entry — it is the FIRST View item, with a separator immediately below it): its action is `#selector(NSSplitViewController.toggleSidebar(_:))` with a `nil` target, so it routes up the responder chain to the `EditorSplitViewController` (the window's `contentViewController`); its mask is `[.control, .command]` (⌃⌘S); it carries no `Tag`/`command_kind`, and `validateMenuItem` needs no change for it (its action differs from `handleCommandMenuItem`, so it falls through to `true`). Every Wolf command item carries its discriminant in `NSMenuItem.tag`, targets the `AppDelegate`, and fires `#selector(AppDelegate.handleCommandMenuItem(_:))`. The private `commandItem(title:tag:keyEquivalent:target:modifiers:)` helper takes `modifiers: NSEvent.ModifierFlags = .command` and sets `keyEquivalentModifierMask`, so `⇧⌘N` / `⇧⌘O` / `⇧⌘W` use a lowercase key equivalent plus an explicit `[.command, .shift]` mask (not a capital letter); `New Window` moved to `⇧⌘N` (plain `⌘N` is now File > New / `:enew`) and `Close` (the former "Close File") now runs `:close`. `viewMenuItem(...)` builds the View items, and the static `rebuildWindowMenu(_:controllers:target:)` clears the Window menu and rebuilds Minimize + separator + one item per controller (title = its `currentCwd`, fallback "Wolf"; action `#selector(AppDelegate.raiseWindowMenuItem(_:))`; `tag = windowIndex`). The File menu's **Open Recent** parent item (`openRecentItem`, inserted right after "Open Folder…") carries a dynamic `NSMenu` — a NATIVE dynamic submenu (like the Window menu, NOT a `Command`, since an Open Recent entry is path-parameterized and does not fit the no-arg `command_kind` model), seeded with a disabled "No Recent Folders" placeholder so it is never empty before the first rebuild; the static `rebuildOpenRecentMenu(_:recentDirs:target:)` (the sibling of `rebuildWindowMenu`) clears it and, when the MRU is empty, re-adds the disabled placeholder, else builds one item per path titled with the full path (action `#selector(AppDelegate.openRecentMenuItem(_:))`, target the delegate, `tag = ` the list index). The `Tag` enum / `command_kind` discriminants are UNCHANGED (Open Recent items use `openRecentMenuItem(_:)`, not the tag-as-`command_kind` path). Compile-verified + manual-smoke only.
- **`CommandDispatcher.swift`** — `enum CommandDispatcher`, the single funnel every command flows through. `dispatch(_ kind: CommandKind, window: NSWindow?, coordinator: AppDelegate?, originatingCwd: String, controller: WolfWindowController?)` maps a decoded `CommandKind` to its native action: `.newWindow` → `coordinator?.makeNewWindow(originatingCwd:)`, `.closeWindow` → `window?.performClose`, `.quitApplication` → `NSApp.terminate`, `.hideApplication` → `NSApp.hide`, `.minimizeWindow` → `window?.miniaturize`, `.goToFile` → `controller?.openFilePicker()`, `.openFile` → `controller?.presentOpenFileDialog()`, `.openFolder` → `controller?.presentOpenFolderDialog()`, `.closePane` → `controller?.closePane()` (`:close`), `.newBuffer` → `controller?.newBuffer()` (`:enew`), `.resetFontSize` → `controller?.resetFontSize()`, `.increaseFontSize` → `controller?.increaseFontSize()`, `.decreaseFontSize` → `controller?.decreaseFontSize()`, `.commandPalette` → `controller?.openCommandPalette()`. Both the native-menu path (`handleCommandMenuItem`, targeting `NSApp.keyWindow`) and the nvim-drained path (`WolfWindowController.drainAndDispatchCommands`, targeting the draining controller's own window) route here, so a command has ONE implementation regardless of face. `controller` is the target window's controller (the menu path finds the key window's controller via `owns(_:)`, the nvim-drained path passes `self`), through which the four File commands reach that window's picker / core handle; `originatingCwd` (the originating window's live `handle.cwd()`) is inherited only by `.newWindow`. Compile-verified + manual-smoke only; the pure decode lives in `CommandSeam`.
- **`AppDelegate.swift`** — the app **coordinator** (also conforming to **`NSMenuItemValidation`** and **`NSMenuDelegate`**), a thin manager over a `controllers: [WolfWindowController]` collection (one per OS window). At launch it does the once-only, whole-process setup: install the three wake bridges (`WakeBridge` / `PickerWakeBridge` / `TreeWakeBridge`), install the native menu bar (stashing the `AppMenu.install(target: self)` result — the Window `NSMenu` into `windowMenu`, then `rebuildWindowMenu()` once the controllers exist, and the Open Recent `NSMenu` into `openRecentMenu` with `openRecentMenu?.delegate = self` so it rebuilds lazily), then **register the bundled fonts, load the user config, then measure the cell metrics, in that order** (`FontRegistration.registerBundledFonts()` → `wolf_ffi_load_config()` → `CellMetrics.measured(config:)`), so both bundled families resolve — "iA Writer Mono S" (the default) and "JetBrains Mono" — and the config's font-family / size / line-height drive the shared grid geometry. Metrics + config are measured ONCE and passed to every controller. It then reads the saved application state (`wolf_ffi_load_state()` BEFORE any core starts) and creates ONE `WolfWindowController` per saved window (its `windowIndex` == its list position), copying each saved window OUT of the bridge's `RustVec<FfiWindowState>` immediately into a plain `RestoredWindowState` (element refs must not outlive the vec); with nothing saved it creates one default controller at index 0. **Launch is empty-state-aware:** each window's `(launchCwd, hasFolder)` is derived by feeding the (possibly empty/deleted) restored cwd through the pure `StateSeam.launchDecision(restored:home:isDirectory:)` (`home = FileManager.default.homeDirectoryForCurrentUser.path`) and mapping the result with the private `dir(_:)` helper — `.folder(cwd)` → `(cwd, hasFolder: true)`, `.emptyState(nvimCwd)` → `(nvimCwd, hasFolder: false)`. So a fresh launch with an empty state file, and a restored window whose saved cwd is `""` or no longer a directory, both open an EMPTY-STATE window (Wolf never opens the process working directory); a valid saved cwd opens that folder. A fatal alert (`presentStartupFailureAndQuit`) fires only when the FIRST window's core fails (a later window's core failing simply opens fewer windows). `makeNewWindow(originatingCwd:)` is the **Command+N** (New Window, ⇧⌘N) entry: it IGNORES `originatingCwd` and ALWAYS opens a new empty-state window — it picks the first free slot via `WindowIndexSeam.nextFreeIndex(occupied:)`, builds `(launchCwd, hasFolder)` from `launchDecision(restoredCwd: "")` (always `.emptyState(home)`), and creates + `start()`s a controller with `restored: nil` (AppKit cascade placement). `makeController(windowIndex:launchCwd:restored:hasFolder:)` threads `hasFolder` into each controller. `handleCommandMenuItem(_:)` is the native menu-item entry point: it decodes the item's `tag` (an FFI `command_kind` byte set by `AppMenu`) into a `CommandKind` via `CommandKind(ffi:)`, finds the key window's controller (`controllers.first { $0.owns(NSApp.keyWindow) }`), and funnels through `CommandDispatcher.dispatch(..., window: NSApp.keyWindow, coordinator: self, originatingCwd:, controller:)` — the SAME dispatcher the nvim-drained command path uses. `removeController(_:)` drops a controller at window close. The **dynamic Window menu** is owned here: `rebuildWindowMenu()` (→ `AppMenu.rebuildWindowMenu(windowMenu, controllers:, target: self)`) runs at startup, in `makeNewWindow`, in `removeController`, and on `windowCwdDidChange(_:)` (a controller's per-window cwd-change hook); `@objc raiseWindowMenuItem(_:)` maps `sender.tag` (a window's `windowIndex`) to `controllers.first { $0.windowIndex == sender.tag }` and calls its `raise()`. Three coordinator helpers back the **command palette**: `otherWindows(excluding:) -> [(index: Int, cwd: String)]` (every live controller EXCEPT the argument, mapped to `(windowIndex, currentCwd)` — the palette's "Switch to Window" candidate source, current window excluded), `controllerForCwd(_ path:) -> WolfWindowController?` (the first live controller whose `currentCwd == path` — the "Open Recent Folder" raise target), and `raiseWindow(windowIndex:)` (the "Switch to Window" action; `raiseWindowMenuItem`'s logic exposed by index). The **dynamic Open Recent submenu** is rebuilt lazily via the `NSMenuDelegate` conformance: `menuNeedsUpdate(_:)` (guarded on `menu === openRecentMenu`) reads the key-window controller's `recentDirs()` (`controllers.first { $0.owns(NSApp.keyWindow) } ?? controllers.first`, `[]` when none), stashes it in the `recentDirs` field, and hands it to `AppMenu.rebuildOpenRecentMenu` — so it is always fresh at menu-open time (unlike the Window menu's explicit lifecycle-hook rebuilds); `@objc openRecentMenuItem(_:)` bounds-guards `sender.tag`, resolves `recentDirs[sender.tag]`, and calls `changeDirectory(_:)` on the key-window controller (chdir — the same effect as Open Folder, with no panel). `validateMenuItem(_:)` is UNCHANGED — Open Recent items use `openRecentMenuItem(_:)` (not `handleCommandMenuItem`) so they fall through to `true`, and the placeholder's `action: nil` auto-disables it. It still returns `true` for every item EXCEPT the `.closePane` (Close) command item, enabled only when the key window's controller `paneCount > 1` (so the last split cannot be closed, matching Neovim's E444 — the dynamic window items short-circuit before the tag-as-`command_kind` cast because their action differs). `applicationShouldTerminateAfterLastWindowClosed` stays `true`. `applicationWillTerminate` re-pushes each still-live window's snapshot at its own fixed `windowIndex` (NOT a dense re-index) then prunes ghost slots via `state_set_window_count(highestLiveIndex + 1)` (only when a window is still open at quit; see the crate README's v1 stale-restoration limitation), then tears down the remaining controllers as a backstop.
- **`WolfWindowController.swift`** — owns ONE window's stack (moved out of the old monolithic `AppDelegate`): its `handle`, `window`, `paneContainer`, `tree`, `picker`, `palette`, `statePersistence`, fixed `windowIndex`, and per-window `wakeToken`. `start()` points wolf-core at the bundled Neovim (`WOLF_NVIM_BIN` via `setenv(..., 0)` so a dev override wins), resolves `init_lua` (`WOLF_INIT_LUA` else `Contents/Resources/init.lua`), calls `wolf_ffi_start(..., UInt16(windowIndex))`, reads `handle.wake_token()`, and **registers itself in `WindowRegistry` under that token** so wakes route back to this window; it then builds the pane container / sidebar `FileTreeView` / overlay `PickerView` / overlay `CommandPaletteView` (built parallel to the picker, added as a `paneContainer` subview, with `palette.onActivate = { [weak self] row in self?.activatePaletteRow(row) }`) / centered "Open folder…" overlay `EmptyStateView` / `MainWindow`, wires `paneContainer.onPickerTrigger` (the old `onNewWindow` wiring is GONE — New Window is the menu's ⇧⌘N item, no longer a Cmd-N keyDown interception) and the empty-state overlay's `onOpenFolder = { [weak self] in self?.presentOpenFolderDialog() }`, restores the saved frame ONLY for a restored window (frame via `StateSeam.restoredWindowFrame` against `NSScreen.screens.map(\.visibleFrame)`, else `center()`; a fresh window keeps cascade placement), installs a `StatePersistence` + one `pushSnapshot()`, sets itself as the window delegate, shows the window, and makes the pane container first responder. It carries a stored `hasFolder: Bool` init param that drives the empty-state gating: the `EmptyStateView` overlay is `isHidden = hasFolder`; the file tree is only `start()`ed when `hasFolder` (an empty-state window must not scan `home`); and the sidebar is set per `hasFolder` — an empty-state window (`hasFolder == false`) ALWAYS collapses the sidebar (ignoring any stored `sidebar_visible`), a restored FOLDER window honors `isCollapsed = !restored.sidebarVisible`, and a fresh folder keeps the default (visible). Returns `false` (having built nothing) when the core fails to start. - **`PaneContainerView.swift`** — the editor area's split-panes view (the macOS analog of wolf-gnome's `pane_view.rs`), and the editor area's first responder + single global key sink. The grid paint is cell backgrounds + CoreText glyphs — each glyph in the bold/italic/boldItalic face and with the underline/strikethrough decorations that `GlyphStyleResolver` resolves from the cell's `flags()` + `special()`, underline/strikethrough stroked manually in the resolved color since `CTLineDraw` ignores decoration-color attributes — plus the mode-aware cursor when `cursor_visible`; each pane is drawn **independently of Neovim**, so an INACTIVE pane gets a translucent dim scrim (`inactiveDim`) over the WHOLE pane (strip + grid) — a front-end-only treatment that is awkward to express inside Neovim. **The per-pane statusbar** (`paintStatusbar`) fills the strip with the macOS titlebar background (the window's own `backgroundColor`, kept in sync with the `WolfTitlebar` theme by `MainWindow.applyTitlebarBackground`, falling back to `theme_titlebar_bg()` / the editor fallback when there is no window), then draws the pane's base filename (primary line) and its display path (secondary, smaller line) from `handle.pane_status_for_grid(grid)` — `filename()` / `display_path()` — via `NSString.draw(in:withAttributes:)` with a `.byTruncatingTail` paragraph style; the text left edge aligns with the grid's text left edge (`paneRect.minX + geo.paintOffsetX`), the strip height + line rects come from the pure `WolfKeyMap.StatusbarLayout` (font sizes from the grid's `CTFont`), and the colors are the themed titlebar fg (secondary at a lower alpha) when set, else `labelColor` / `secondaryLabelColor`. Its `metrics` is now a `var`: `applyMetrics(_:)` sets it, calls `syncGridSizes()`, and marks `needsDisplay` (the View font-size reflow path — the window frame is unchanged so cols/rows recompute), and `paneCount` (`tree.leaves().count`) exposes the live split count for `AppDelegate.validateMenuItem`. **Mouse / scroll** route through a per-pane `PaneGeometry` (`geometry(for:)`, `maxCols: nil`): `mouseDown` `focus_win`s the clicked pane (click-to-focus preserved) and `send_mouse`s a LEFT PRESS at `geo.cellAt(point)` on that pane's grid; a single commented flip point remains). **Synthetic scrollbars** are custom-drawn per pane in `draw(_:)` at each pane's right edge from the frame viewport (`topline` / `botline` / `linecount`, 0-based; thumb offset `topline / linecount`, underflow-safe, nothing drawn when the whole buffer is visible), following `NSScroller.preferredScrollerStyle` (`.legacy` always + faint track / `.overlay` fade after scroll) and reacting to `NSScroller.preferredScrollerStyleDidChangeNotification` (observer removed in `deinit`); the thumb is **non-interactive** (drag deferred). `onRenderWake()` mirrors GNOME's orchestration: `ensureInitialPane` (a `pick_initial_window` port — prefer `active_win()` if it is a real window grid `>= 2` and not hidden, else the lowest visible window grid from `windows()`, reusing the tree's root `firstPaneId`), `applyIntents` (`drain_intents` → SPLIT splits the `from`/active pane in the tree and binds a new pane to the new window via `grid_for_win` — 0 → pending;
