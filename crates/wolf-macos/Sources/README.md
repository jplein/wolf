# wolf-macos/Sources

The Swift sources for the macOS front-end, split into two modules. See the crate [`README.md`](../README.md) for the design decisions and the build workflow.

## `WolfKeyMap/` — the pure key seam (no AppKit)

Thirty-four deliberately AppKit-free files, so they are unit-testable headlessly (the macOS analog of wolf-gnome's `gdk_key`, pure picker, and pure pane-layout seams). The Bazel `wolf_key_map` module compiles them together with the swift-bridge-generated Swift glue, so the rest of the app gets the generated types (`FfiKeyEvent`, `FfiMouseEvent`, `FfiScrollEvent`, `WolfCoreHandle`, `FfiFrame`, `FfiConfig`, `FfiFileSearch`, `FfiFileEntry`, `FfiTreeNode`, `FfiLayoutIntent`, `FfiWinInfo`, `FfiPaneStatus`, `FfiCmdline`, `FfiPum`, `FfiPumItem`, `FfiToast`, `FfiToastLine`, `FfiToastChunk`, `FfiCommand`, `FfiCommandPalette`, `FfiCommandRow`, `FfiBufferPicker`, `FfiBufferRow`, `FfiPreview`, `FfiHistoryEntry`, `FfiOpenFiles`, `FfiState`, `FfiWindowState`, `FfiTabState`, `FfiPaneNode`, the free `wolf_ffi_ancestors_to_reveal`, `wolf_ffi_load_config`, `wolf_ffi_load_state`, `wolf_ffi_state_layout_push_leaf`, …) via `import WolfKeyMap`.

- **`KeyMap.swift`** — `WolfKeyMap.translate(keyCode:characters:charactersIgnoringModifiers:ctrl:shift:alt:meta:) -> FfiKeyEvent?`. It imports only Foundation and the generated FFI struct. Named keys (Return, Tab, arrows, F-keys, …) are recognized from the virtual `keyCode` first and **keep** the real `shift` flag; printable characters carry the already-shifted glyph in `ch` with `shift = false`; when ctrl/alt/meta are held the glyph comes from `charactersIgnoringModifiers` (lowercased); bare modifiers and unmodified control characters return `nil`. The `Kind` discriminants mirror `wolf_core::Key`'s variant order (and the Rust `key_event_from_ffi`).
- **`PickerSeam.swift`** — `public enum PickerSeam`, Foundation only. Three ports of wolf-gnome's pure picker helpers: `isPickerTrigger(charactersIgnoringModifiers:command:) -> Bool` (the **Command+O** trigger — `command && first scalar lowercased == "o"`, other modifiers ignored — Command-modified keys are not Neovim keybindings, so the chord does not consume a Neovim key), `nextSelection(current:delta:nRows:) -> Int?` (list-nav clamp, port of `next_selection`), and `restoredIndex(resetToTop:prev:newLen:) -> Int?` (selection restore across streaming result batches, port of `restored_index`).
- **`PickerRefreshCoalescer.swift`** — `public final class PickerRefreshCoalescer`, Foundation only (headlessly tested by `PickerRefreshCoalescerTests`), a debounce/coalescing seam SHARED by BOTH the file picker (`PickerView`) and the file-tree sidebar (`FileTreeView`). The name is historical; the seam is generic (its `schedule` / `perform` collaborators are injected). It exposes `static let refreshInterval: TimeInterval = 0.033` (~30 fps), `request()`, and `cancelPending()`: `request()` COALESCES a burst of streaming-traversal wakes into ONE trailing refresh (the first call arms the timer, later calls while armed drop, and the fire clears the flag so a later wake re-arms — the FINAL / complete wake is never dropped), and `cancelPending()` clears the armed flag (an already-armed timer still fires, but the caller's `refresh()` is a no-op once closed). Both wake bridges call the owning view's `scheduleRefresh()` → `request()`.
- **`TreeChildrenMemo.swift`** — `public final class TreeChildrenMemo<Item>`, Foundation only, the per-directory memo for the sidebar file tree's child projection (perf plan Layer 1) and a sibling of the `PickerRefreshCoalescer` / `TreeRefreshGate` sidebar-perf seams. `init(project: @escaping (String) -> [Item])` injects the projection (in production `FileTreeView.projectChildren(dir:)`, which maps the FFI `search.children_of(dir)` into `TreeItem`s), `children(ofDir dir: String) -> [Item]` returns the cached array or computes-and-stores it, and `invalidate()` drops every cached projection (`removeAll(keepingCapacity: true)`). The point is that `NSOutlineView` asks for one directory's children in a STORM (`numberOfChildrenOfItem`, then `child:index:` once per child), each of which would otherwise re-run the O(N) flat-list scan; the memo makes `project` run at most ONCE per directory per invalidation window. Generic over `Item` so the seam is unit-testable without AppKit or a live search. Two non-obvious invariants: it caches the SAME `TreeItem` INSTANCES that `itemsByRelPath` hands out, so memoizing does not disturb the outline's stable item identity; and `FileTreeView` invalidates it ONLY inside the `TreeRefreshGate.shouldReload` branch (plus on reroot), so a version-unchanged refresh — an expand/collapse or a cursor move — keeps serving children from the still-valid memo. `FileTreeView` builds it with a `[weak self]` closure because the view owns the memo which owns the closure. Headlessly unit-tested by `TreeChildrenMemoTests`.
- **`TreeRefreshGate.swift`** — `public final class TreeRefreshGate`, Foundation only, the sidebar file tree's visibility + snapshot-version refresh gate (perf plan Layer 3), removing two kinds of redundant work: refreshing while the sidebar is COLLAPSED (which is why hiding the sidebar did not relieve the freeze), and running a full `reloadData()` on every render wake even when nothing structural changed. `init(isVisible: Bool)`; `requestRefresh() -> Bool` returns `true` while visible (the caller proceeds) and while hidden records that a catch-up is OWED and returns `false`; `setVisible(_:) -> Bool` returns `true` **iff** the transition was hidden→visible AND a refresh was deferred while hidden (clearing the flag), so exactly ONE catch-up refresh runs on reappear — a visible→visible or a no-work reappear returns `false`; `shouldReload(version: UInt64) -> Bool` returns `true` iff `version` differs from the last reloaded one (recording it), so a repeat at an unchanged version skips the redundant `reloadData`; `resetReloadTracking()` clears that memory so the next `shouldReload` reloads unconditionally, called on reroot where the outline is rebuilt wholesale. `FileTreeView` relays the sidebar's real `isCollapsed` KVO into `setVisible` and passes `search.version()` into `shouldReload`; the initial `lastReloadedVersion` is `nil`, so the FIRST call at any version — including `0` — reloads. Headlessly unit-tested by `TreeRefreshGateTests`.
- **`PaletteSeam.swift`** — `public enum PaletteSeam`, Foundation only, the command-palette sibling of `PickerSeam`. `isPaletteTrigger(charactersIgnoringModifiers:command:) -> Bool` is the **Command+P** trigger (`command && first scalar lowercased == "p"`, other modifiers ignored) — matching "p" instead of "o". **DORMANT / UNWIRED:** ⌘P is a menu key-equivalent that preempts `keyDown` (exactly like ⌘N and `ShortcutSeam`), so the View-menu item is the real trigger and `PaletteSeam.isPaletteTrigger` is NOT called from `PaneContainerView.keyDown`; it is kept for consistency with `PickerSeam` and still pinned by `PaletteSeamTests`. The nested `PaletteRowKind: UInt8` (`staticCommand = 0`, `switchWindow = 1`, `openRecent = 2`) with a guarded `init?(ffi:)` mirrors `wolf-ffi`'s `mod palette_row_kind`. Headlessly unit-tested by `PaletteSeamTests`.
- **`CmdlineSeam.swift`** — `public enum CmdlineSeam`, Foundation only, the command-line sibling of `PaletteSeam`: the pure line-composition + caret-prefix math painted by `CmdlineView` (`ext_cmdline`), taking scalar inputs only (no `FfiCmdline`, no NSView, no CoreText) so it is unit-testable headlessly. `composedLine(prompt:firstc:text:) -> String` is the full drawn line `prompt + firstc + text` (an empty `prompt` yields the same `firstc + text` as before the seam existed); `caretPrefix(prompt:firstc:text:byteCount:) -> String` is `prompt + firstc + bytePrefix(of: text, byteCount:)`, the prefix whose measured width places the caret (the prompt width included so the caret sits after it); and `bytePrefix(of:byteCount:) -> String` is the UTF-8 prefix of at most `byteCount` bytes decoded back to a `String` (`<= 0` → `""`, `>= len` → the whole string), MOVED here from `CmdlineView` and made `public` so both `CmdlineView` and `PaneContainerView` (the `pumAnchorX` caller) share the one tested impl; `caretPrefix` is defined in terms of `bytePrefix`. Headlessly unit-tested by `CmdlineSeamTests`.
- **`ShortcutSeam.swift`** — `public enum ShortcutSeam`, Foundation only. `isNewWindowTrigger(charactersIgnoringModifiers:command:) -> Bool` — the **Command+N** new-window trigger predicate (`command && first scalar lowercased == "n"`, other modifiers ignored), the sibling of `PickerSeam.isPickerTrigger` matching "n" instead of "o". **NOW DORMANT / UNWIRED:** New Window moved to the menu's ⇧⌘N key-equivalent and plain ⌘N is the File > New (`:enew`) menu item, so `PaneContainerView` no longer intercepts Cmd-N in `keyDown` (menu key-equivalents preempt `keyDown`). The seam and `ShortcutSeamTests` are kept as a still-passing pure seam, but nothing in the live app calls `isNewWindowTrigger`. Headlessly unit-tested by `ShortcutSeamTests`.
- **`CwdTitleSeam.swift`** — `public enum CwdTitleSeam`, Foundation only. `displayTitle(cwd: String, home: String) -> String` computes the window/tab title text from a working-directory path, abbreviating the injected `home` prefix to `~` per the macOS convention: an empty or all-whitespace `cwd` → `""` (the caller substitutes a `"Wolf"` fallback); `home` is normalized by stripping ONE trailing `/`, and an empty (or empty-after-normalize) `home` disables abbreviation and returns `cwd` unchanged; `cwd == home` → `"~"`; a `cwd` beginning with `home + "/"` → `"~/" + remainder` (a full path-SEGMENT-boundary match only, so `/Users/janet/x` is NOT abbreviated against home `/Users/jane`); any other `cwd` is returned verbatim (full absolute path). The `home` is ALWAYS injected — no implicit `$HOME` / `FileManager` — which is load-bearing for determinism. The coordinator feeds it each tab's `persistedCwd` + `homeDir()` in `refreshTabTitles(forGroupOf:)` and sets the result as the tabs' `NSWindow.title` (plus a `representedURL` proxy). Headlessly unit-tested by `CwdTitleSeamTests`. (The former filename-based `TabTitleSeam` — and before it `WindowIndexSeam` + `WindowTitleSeam` — are REMOVED: tab identity is a monotonic `tabId` on the coordinator, and the OS window/tab title now derives from the WORKING DIRECTORY via this seam, with the filename basename disambiguation retired.)
- **`PaneTree.swift`** — a Foundation-only port of wolf-gnome's pure `layout.rs` pane-layout tree, `import Foundation` ONLY (it uses `Double`, not `CGFloat`, so it pulls in no CoreGraphics and stays in the headless test bundle). Public API: `typealias PaneId = UInt64`; `enum Orientation { horizontal, vertical }` and `enum FocusDir { left, right, up, down }` (each with an `init?(ffi:)` decoding the `wolf-ffi` discriminants); `struct Rect`; the `indirect enum PaneLayout { .leaf(PaneId); .split(orientation:children:weights:) }`; and `final class PaneTree` (a reference type, mutated in place) with `init(root:)`, `split(_:_:_:)`, `remove(_:)`, `leaves()`, `paneRects(width:height:)`, `neighbor(_:_:width:height:)`, and `layout()`. The TOPOLOGY contract still matches `layout.rs` EXACTLY (a SAME-orientation split inserts a flat sibling after the target, a PERPENDICULAR split nests, `remove` never empties the tree / collapses a single child, `neighbor` uses strictly-positive cross-axis overlap with stable DFS order). The **WEIGHT POLICY divergence and the DIVIDER API are macOS-only** (gnome has no weight-mutation API): a same-orientation split RE-EQUALIZES the row/column to `1/n` each — matching the gnome port, where `:vsplit`/`:split` redistributes to equal shares (a fresh two-child split is 0.5/0.5). The ONE remaining divergence from gnome is REMOVE: it RE-NORMALIZES survivors PROPORTIONALLY (relative sizes preserved, not re-equalized) — so a user-resized layout survives an adjacent pane closing and tab switches. The new divider surface: `public struct Divider: Equatable` (`orientation` / `path: [Int]` / `boundary: Int` / zero-thickness `lineRect: Rect` / `pairStart` / `pairSpan` / `before: PaneId` / `after: PaneId` / `fraction`, with a public memberwise init); `dividers(width:height:) -> [Divider]` (one Divider per interior boundary, recursing like `paneRects`); `setPairFraction(path:boundary:leftFraction:)` (reweights the two adjacent children of the split at `path`, clamped away from the `0`/`1` extremes, other children + the global sum untouched — a no-op on an invalid path/boundary); and the static `rebuilt(from saved: SavedPaneNode, firstLeafId: PaneId) -> (tree: PaneTree, leafIds: [PaneId])` (builds a tree directly from a `SavedPaneNode` topology + weights, assigning leaf ids sequentially in DFS order — the SAME order as `leaves()` — for the restore path). The macOS `PaneContainerView` consumes `paneRects()` to paint each pane into a computed rectangle (a single flat view, not an `NSSplitView` tree) plus `dividers()` / `setPairFraction()` to drag interior dividers to resize. Headlessly unit-tested by `PaneTreeTests` (a 1:1 port of the `layout.rs` topology suite + a discriminant-contract test) and `PaneTreeWeightsTests` (the weight-preservation + `setPairFraction` + `rebuilt` coverage).
- **`DividerHitTest.swift`** — `public enum DividerHitTest`, Foundation only, the pure divider PICKING seam (enumeration lives on `PaneTree` because it needs the private `Frame`; picking is pure over the public list). `hit(_ dividers: [PaneTree.Divider], point: (x: Double, y: Double), tolerance: Double) -> PaneTree.Divider?` returns the NEAREST divider whose zero-thickness line is within `tolerance` of `point` AND whose point falls within the divider's span, else `nil` (a `.vertical` divider is a vertical segment at `lineRect.x` over its y-span with distance `|point.x − lineRect.x|`; `.horizontal` is the transpose; a point off the ends of the line does NOT hit even on the axis). `PaneContainerView.mouseDown` calls it against `PaneTree.dividers()` BEFORE forwarding to nvim. Headlessly unit-tested by `DividerHitTestTests`.
- **`DividerDragSeam.swift`** — `public enum DividerDragSeam`, Foundation only, the pure divider-drag CLAMP (it lives here, not in the pixel-free `PaneTree`, because it needs cell size + pixel spans). `clampedLeftFraction(pairStart:pairSpan:pointerPos:orientation:cellWidth:cellHeight:minCols:minRows:leadingOverhead:trailingOverhead:) -> Double` maps a pointer position along the drag axis to the clamped left-child fraction: the raw fraction is `(pointerPos − pairStart) / pairSpan`; per-side minimum pixels are `minCols * cellWidth + overhead` (vertical) or `minRows * cellHeight + overhead` (horizontal), the LEFT/TOP side using `leadingOverhead` and the RIGHT/BOTTOM side `trailingOverhead`; the fraction is clamped to `[minLeft / pairSpan, 1 − minRight / pairSpan]`, and a pair too small to hold both minima (an inverted range, or a non-positive `pairSpan`) yields the midpoint `0.5`. `PaneContainerView.mouseDragged` feeds it the divider's `pairStart` / `pairSpan`, the pointer axis position, the cell metrics, and `minCols: 10` / `minRows: 3` (the 3-row / 10-column floor). Headlessly unit-tested by `DividerDragSeamTests`.
- **`PaneLayoutCodec.swift`** — Foundation only, the pure codec bridging the `PaneTree` layout to the persistable + FFI shapes. `public enum SavedPaneNode: Hashable { case leaf(path: String, preview: Bool); case split(orientation: Orientation, weights: [Double], children: [SavedPaneNode]) }` is the serializable mirror keyed by per-leaf buffer PATH plus a per-leaf `preview` flag (when `preview` is `true` the pane is a Markdown preview and `path` is the SOURCE Markdown file's ABS path, restored via `wolf_preview_file` not `:edit`; `Hashable` because `RestoreSeam.PlannedTab` is; it also exposes `leafCount`, the count the rebuild path zips window handles to, and `isEmptyLeaf` — `true` ONLY for a `.leaf(path: "", preview: false)` (an unnamed, non-preview lone pane; a preview leaf or non-empty path is NOT empty, a `.split` never is) — which `layoutSnapshot()` checks to SUPPRESS persisting a layout for an empty-state lone pane). `public enum PaneLayoutCodec` holds three transforms: `encode(_ layout: PaneLayout, paths: [PaneId: String], previews: Set<PaneId>) -> SavedPaneNode` (maps leaf ids to buffer paths, an unmapped leaf → `""`, and marks a leaf a `preview` when its id is in `previews`); `postOrderTokens(_:) -> [LayoutToken]` (flattens to the post-order token stream the FFI push-builder replays — `.leaf(path, preview, weight)` / `.split(orientation, childCount, weight)`, children before their split, root weight `1.0`, `tokens.count == node count`) with its inverse `decodeTokens(_:) -> SavedPaneNode?`; and `specJSON(_:) -> String` (renders the JSON `runtime/nvim/init.lua`'s `wolf_rebuild_layout` decodes — a leaf is `{ "leaf": true, "path": …, "preview": true|false }`, a split is `{ "orientation": "v"|"h", "weights": [...], "children": [...] }`). `PaneContainerView.layoutSnapshot()` calls `encode`, `AppDelegate.snapshotNow` replays `postOrderTokens` into the FFI push-builder, and the restore path passes `specJSON` to `WolfCoreHandle.rebuild_layout`. Headlessly unit-tested by `PaneLayoutCodecTests`.
- **`PaneGeometry.swift`** — `public struct PaneGeometry`, Foundation only (`Double`, reusing `Rect` from `PaneTree.swift`), the per-pane pixel↔cell mapping seam. It holds a **GRID RECT** inside a **PANE RECT**; `init(paneRect:cellWidth:cellHeight:maxCols:)` **caps the grid at `maxCols` columns and CENTERS it horizontally** when the pane is wider than that (leaving equal side margins, `paintOffsetX = inset`), while a pane no wider than the cap is unaffected (`gridRect == paneRect`, paint offsets `0`); `maxCols == nil` disables the cap entirely. `PaneContainerView`'s `geometry(for:fullWidth:)` seam passes `maxCols: fullWidth ? nil : 90` PER PANE, so a NON-full-width grid wider than 90 columns is centered with side margins, while a full-width pane lifts the cap and fills the pane rect. It exposes `cols` / `rows` (`max(1, floor(gridRect.size / cell))`), `paintOffsetX` / `paintOffsetY` (grid-rect origin − pane-rect origin, the centering inset when capped), and `cellAt(x:y:) -> (row, col)` mapping a pane-local point to a grid cell **clamped** into `[0, cols-1] × [0, rows-1]` (a margin / past-edge point lands on the nearest edge cell, so the side margins around a centered grid resolve to the nearest interior cell). Headlessly unit-tested by `PaneGeometryTests`.
- **`ScrollAccumulator.swift`** — `public struct ScrollAccumulator`, Foundation only, a pure signed pixel→line-step accumulator with a carried remainder. `consume(deltaY:cellHeight:) -> Int` returns the signed whole line steps for the delta (guarding `cellHeight <= 0` → `0`) and keeps the sub-cell remainder across calls so smooth trackpad scrolling accumulates; `reset()` clears it. Direction-agnostic (signed); the AppKit layer maps the sign to a scroll direction. Headlessly unit-tested by `ScrollAccumulatorTests`.
- **`CellMetricsMath.swift`** — `public enum CellMetricsMath`, Foundation only, the pure config-driven cell-geometry seam (extracted from `CellMetrics` so it stays headlessly testable). `cellHeight(fontSize:lineHeightPercent:ascent:descent:leading:) -> Double` returns `round(fontSize * lineHeightPercent / 100)`, guarding `lineHeightPercent <= 0` → the font's natural `ceil(ascent + descent + leading)`; `baseline(cellHeight:ascent:descent:) -> Double` returns `ascent + (cellHeight - ascent - descent) / 2`, recentering the glyph within a taller cell. `CellMetrics` feeds it the user config's line-height. Headlessly unit-tested by `CellMetricsMathTests` (130%@14, 100% natural, the degenerate guard, baseline recentering).
- **`FontSizeSeam.swift`** — `public enum FontSizeSeam`, Foundation only, the pure step+clamp math for the View font-size commands (extracted so it stays headlessly testable). It owns the constants `minPointSize = 6`, `maxPointSize = 72`, `step = 1` (all `Double`) plus `clamped(_:) -> Double`, `increased(_:) -> Double` (`clamped(current + step)`), and `decreased(_:) -> Double` (`clamped(current - step)`); it owns ONLY the increment/clamp math — RESET (to the window's stored default) is the `WolfWindowController`'s job, not the seam's. Headlessly unit-tested by `FontSizeSeamTests` (±1 step, clamp at 6/72, in-range pass-through, 71→72, 72→72, 7→6, 6→6).
- **`GlyphStyle.swift`** — `public enum GlyphFace { regular, bold, italic, boldItalic }`, `public struct GlyphStyle` (`face`, `underline` + `underlineColor: FfiColor`, `strikethrough` + `strikethroughColor: FfiColor`, all `Equatable`), and `public enum GlyphStyleResolver` with `resolve(flags: UInt8, fg: FfiColor, special: FfiColor) -> GlyphStyle`, Foundation only. It maps a cell's packed style-flag bits (mirroring `mod flag` in `wolf-ffi/src/lib.rs`: bold/italic/underline/undercurl/strikethrough) to a face (boldItalic if both bold+italic, else bold, else italic, else regular), folds undercurl into a straight underline, colors the underline with `special` when set (else fg), and strikes through in fg. It also adds `extension FfiColor: Equatable` (component-wise on `rgb` + `set`) so `GlyphStyle` synthesizes `Equatable`. Headlessly unit-tested by `GlyphStyleTests`.
- **`HistorySeam.swift`** — `public enum HistorySeam`, Foundation only, the pure decision seam behind the **per-pane navigation history** (the History menu + its two toolbar buttons), a sibling of `PickerSeam` / `RestoreSeam`. TWO small concerns share ONE file because they share the identifier constants. (a) `rows(displays: [String], indices: [Int], currentFlags: [Bool]) -> [Row]` zips the three parallel arrays derived from `WolfCoreHandle.history_entries(win)` into `Row { title: String, index: Int, isCurrent: Bool }` (`Equatable`, public memberwise init), preserving core's NEWEST-FIRST order verbatim — it never re-sorts and never renumbers, because a non-negative `index` is a STACK index handed straight back to `history_jump`; mismatched lengths TRUNCATE to the shortest array, a NEGATIVE index is DROPPED, at most ONE row keeps `isCurrent` (the FIRST if several arrive), and empty input yields `[]` (the caller substitutes `emptyPlaceholderTitle`). (b) `itemIdentifiers(toggleSidebar:trackingSeparator:) -> [String]` owns the LOCKED toolbar ordering after the traffic lights — `[toggleSidebar, trackingSeparator, backIdentifier, forwardIdentifier]` — returned as raw strings so the seam stays AppKit-free (`MainWindow` maps them back to `NSToolbarItem.Identifier`). The constants: `emptyPlaceholderTitle = "No History"` (the disabled empty-state row, so the menu is never empty), `backIdentifier = "com.wolf.editor.toolbar.back"` / `forwardIdentifier = "com.wolf.editor.toolbar.forward"`, and `backSymbolName = "chevron.backward"` / `forwardSymbolName = "chevron.forward"` (chosen over `chevron.left`/`.right` because they are RTL-aware, and over `NSImage.Name.goBackTemplate` because the toolbar is already SF-Symbol-styled `.iconOnly` unified). Wolf holds NO copy of the history — core is the single source of truth and the rows are rebuilt from it on every `menuNeedsUpdate`. Headlessly unit-tested by `HistorySeamTests`.
- **`StateSeam.swift`** — `public enum StateSeam` (a namespace mirroring `PickerSeam`), Foundation + CoreGraphics only (no AppKit — it takes scalar/`CGRect` inputs, so the AppKit glue feeds it real window frames, `NSScreen.screens` visible frames, and a FileManager-backed closure). The pure decision seams backing the state-restore path: `restoredWindowFrame(x:y:width:height:screenVisibleFrames:) -> CGRect?` (`nil` — restore then falls back to the default centered placement — when width/height is non-positive, the "unset" sentinel, or when the frame intersects NO screen visible frame, so a window is never restored fully offscreen); and `launchDecision(restored:home:isDirectory:) -> LaunchDecision` (the launch model — `LaunchDecision` is `.folder(cwd:)` when `restored` is non-empty AND `isDirectory(restored)`, else `.emptyState(nvimCwd: home)` for an empty or deleted/replaced restored cwd; it NEVER returns the process working directory — the old `launchCwd` fallback that polluted the recent-dirs MRU is GONE; the injected closure keeps the seam pure). Headlessly unit-tested by `StateSeamTests`.
- **`RestoreSeam.swift`** — `public enum RestoreSeam` (a namespace mirroring `StateSeam` / `CwdTitleSeam`), Foundation only, the pure **group-by-cwd** restore planner for the project/tabpage-per-view model (plan §4.2 + OD5). `plan(windows: [SavedWindow], home: String, isDirectory: (String) -> Bool) -> RestorePlan` rebuilds PROJECTS from the saved `(window, tab, cwd)` tree (project identity is NOT persisted): a tab whose saved `cwd` is non-empty AND `isDirectory(cwd)` joins the folder project keyed by that cwd STRING (merging same-dir tabs across windows into one project); anything else — an empty `""` cwd, or a since-deleted / non-directory path — is an empty-state tab that gets a UNIQUE project of its own (`launchCwd == home`), never collapsed (OD5). The value types: `SavedTab { cwd, sidebarVisible, layout: SavedPaneNode? }`, `SavedWindow { tabs }`, `PlannedTab { groupIndex, positionInGroup, cwd, sidebarVisible, layout: SavedPaneNode? }` (`Hashable` — retains each tab's ORIGINAL saved placement + cwd + pane-split `layout` for Phase-B window re-assembly, even for a deleted-dir tab whose GROUPING key differs), `ProjectPlan { launchCwd, tabs }`, and `RestorePlan { projects }`. The `layout` is a pure PASSTHROUGH — grouping is still by cwd only; `plan` carries each tab's `layout` straight into its `PlannedTab` so the AppKit restore path can rebuild the split tree. The ONLY injected impurity is `isDirectory` (the AppKit caller passes a FileManager-backed check; tests pass a set lookup); the seam does NOT canonicalize (the caller persists an already-canonical cwd via `cwd_for_tabpage`, so grouping is on the string as-saved). Headlessly unit-tested by `RestoreSeamTests`.
- **`StatusbarLayout.swift`** — `public struct StatusbarLayout`, Foundation only, the pure vertical-layout math for the per-pane statusbar strip. `init(primaryFontSize:secondaryFontSize:verticalPadding:lineGap:)` computes each line height as `ceil(fontSize * 1.25)` (a pinned `lineFactor`), places the primary (filename) line at `verticalPadding` and the secondary (path) line one `lineGap` below its bottom, and sizes the total `height` to leave a matching `verticalPadding` beneath the secondary line. It exposes `height`, `primaryLineTop`, `primaryLineHeight`, `secondaryLineTop`, `secondaryLineHeight` (all `Double`). `PaneContainerView` derives the strip height + line rects from it (primary/secondary font sizes from the grid's `CTFont`); the on-screen bg fill / NSString drawing / truncation are AppKit glue (manual-smoke only). Headlessly unit-tested by `StatusbarLayoutTests` (the exact height 37 for (13, 10, 3, 1) plus the structural invariants). Its HORIZONTAL sibling is `StatusbarTextSpan.swift` below, which owns the statusbar text's left edge + width; the two seams are disjoint (this one takes font sizes, that one takes rect scalars + pane kind) and neither should absorb the other.
- **`StatusbarTextSpan.swift`** — `public enum PaneContentKind { case editor; case preview }` and `public struct StatusbarTextSpan`, Foundation only (`Double`, no `CGFloat`/CoreGraphics), the pure HORIZONTAL sibling of `StatusbarLayout`: it decides the per-pane statusbar TEXT's left edge and width, while `StatusbarLayout` owns the strip's vertical math. `init(gridLeft:gridWidth:paintOffsetX:kind:)` takes the pane's ABSOLUTE grid-rect x origin + width (as produced by `PaneContainerView.gridRect(ofPane:)`), the grid-centering inset `PaneGeometry.paintOffsetX`, and the pane's content kind, and exposes `left` / `width`. With `w = max(0, gridWidth)` and `offset = min(max(0, paintOffsetX), w)`: both kinds now give `left = gridLeft + offset`, `width = max(0, w − offset)` — `.preview` was REDEFINED to MIRROR `.editor` (they are now IDENTICAL) because the "Use full width for content" feature reframes the preview `WKWebView` to the capped+CENTERED `gridRect` (`PaneContainerView.geometry(…, fullWidth:).gridRect`) in the ~90-char default, so the content's left edge is `gridRect.minX + paintOffsetX` and the statusbar must indent to match; in full-width mode `paintOffsetX == 0`, so both kinds land the text flush at `gridLeft`. - **`PaneOcclusion.swift`** — `public struct OccluderGeometry` and `public enum PaneOcclusion`, Foundation only (`Double`, reusing `Rect` from `PaneTree.swift` as `EditorInset` / `PickerPanelSeam` do), the pure arithmetic behind the preview-web-view OCCLUSION skip: may a pane's text grid be skipped entirely because a `WKWebView` fully covers it? `OccluderGeometry` is a headless SAMPLE of a live preview web view, taken by `PaneContainerView` at paint time — `frame: Rect` (in the same coordinate space as the pane's grid rect), `isHidden: Bool` (fed from `isHiddenOrHasHiddenAncestor`, NOT the bare `isHidden`), `isAttached: Bool` (`superview === self && window != nil`), `alpha: Double`, `hasLoadedContent: Bool` — `Equatable`, with a PUBLIC MEMBERWISE INIT (matching the `FrameStats.BucketSummary` convention) so tests build fixtures with no AppKit view. `PaneOcclusion.isFullyOccluded(gridRect: Rect, by occluder: OccluderGeometry?) -> Bool` returns `true` ONLY when skipping the grid paint is invisible to the user; ALL EIGHT rules must hold, and any one failing yields `false` (PAINT): 1. `occluder != nil` (no web view exists yet — the `previewWebViews[win] == nil` path); 2. `hasLoadedContent` (a web view that exists but has loaded nothing is blank/white); 3. `isAttached` (detached, or in no window); 4. `!isHidden` (the view or an ancestor is hidden); 5. `alpha >= 1.0` (anything less lets the grid show through); 6. `frame.w > 0 && frame.h > 0` (a zero-size view covers nothing); 7. `gridRect.w > 0 && gridRect.h > 0` (a degenerate grid rect reports NOT occluded, conservatively — there is no paint work to save, and `true` would be a claim about a rectangle that does not exist); 8. containment on all four edges (`frame.x <= gridRect.x`, `frame.y <= gridRect.y`, and the inline-computed far edges `frame.x + frame.w >= gridRect.x + gridRect.w`, `frame.y + frame.h >= gridRect.y + gridRect.h` — `Rect` has no `maxX` / `maxY`), equality counting as containment. **The containment tolerance is EXACTLY 0.0, and no epsilon may be introduced**: `syncPreviewWebViews` assigns the web view's frame from the SAME `gridRect(ofPane:)` expression the painter is handed, so the two rectangles are bit-identical whenever the view tree and the paint are in sync, and whenever they are OUT of sync (mid-live-resize, just after a split, just before a close) containment FAILS and the grid paints — that is what makes "a pane-geometry change restores painting immediately" a STRUCTURAL property rather than a bookkeeping one, whereas an epsilon would let a stale, slightly-too-small web view suppress the paint underneath it and leave a garbage region on screen. PARTIAL coverage always returns `false`: the seam answers only "fully occluded", never "partly occluded", so the caller's choice stays binary. Headlessly unit-tested by `PaneOcclusionTests` (the two `true` cases — exact-equality and strictly-larger containment — plus one case per rule, the alpha ladder `0.0` / `0.5` / `0.999` → `false` and `1.0` → `true`, the five partial-coverage directions, the `maxX`-short-by-`0.5` case that PINS tolerance 0.0, and flag-interaction cases proving the rules AND rather than short-circuiting on geometry alone).
- **`FrameStats.swift`** — `public enum FrameStatsBucket: Int, CaseIterable` and `public struct FrameStats`, Foundation only, the pure frame-time aggregation seam behind the dev-only instrumentation (the process-global glue lives in `WolfMacOS/FrameMetrics.swift`). The eight buckets are the instrumented regions of the keystroke-to-pixel path, and their **raw values are the storage indices** into the per-bucket accumulator array (so the hot path does no dictionary hashing and no string allocation): `controllerWake == 0` (label `"ctrl.wake"`, `WolfWindowController.onRenderWake()`), `containerWake == 1` (`"cont.wake"`, `PaneContainerView.onRenderWake()`), `draw == 2` (`"draw"`, `PaneContainerView.draw(_:)`), `previewReload == 3` (`"prev.reload"`, `reloadDirtyPreviews()`), `previewRender == 4` (`"prev.render"`, one `render_preview` FFI round-trip including the `toString()` bridge copy), `previewLoadHTML == 5` (`"prev.html"`, one `loadHTMLString` call), `drawPaneEditor == 6` (`"draw.pane"`, ONE `paintPane` call for an ORDINARY editor pane) and `drawPanePreview == 7` (`"draw.prev"`, ONE `paintPane` call for a PREVIEW pane, i.e. one whose grid is a Markdown-preview scratch buffer sitting under a `WKWebView`; the bucket is selected by `previewNamesByGrid[grid] != nil`). The last two PARTITION the per-pane paint work inside a single `draw`, so their counts are per-pane-per-frame (an N-pane window records N samples per `draw`) and **their sum is bounded ABOVE by `draw`'s total, never equal to it** — `draw` also covers the whole-`bounds` background fill, the dividers and the synthetic scrollbars (measured at only ~1.6 ms of a ~45.8 ms `draw`, so the pane loop is essentially all of it). These two are what made the preview-occlusion cost visible and are kept PERMANENTLY as the before/after instrument: with a preview open, `draw.prev` measured **22 ms**, essentially identical to `draw.pane`'s 22 ms, because nvim's blank cells hold a literal `" "` rather than `""` — so every "blank" cell of the preview's scratch grid still ran a full `CTLineCreateWithAttributedString` + `CTLineDraw`. A blank grid costs very nearly what a text-full one does; see `PaneOcclusion.swift`, which is the fix. **`previewLoadHTML` measures ONLY the SYNCHRONOUS `loadHTMLString` call** — the async WebKit parse / layout / paint it queues happens off that call stack and is NOT included, so a small `prev.html` does not mean the preview reload was cheap. `FrameStats` is a plain value type with **no locking and is documented MAIN-THREAD-ONLY** (the invariant is enforced by a DEBUG-only `dispatchPrecondition` in the `FrameMetrics` facade, deliberately kept out of this file so the type stays pure and testable off the main thread). Per bucket it keeps EXACT, unbounded `count` / `sumNanos` / `maxNanos` plus a ring buffer of the last `public static let sampleCapacity = 4096` samples — only the PERCENTILE window is bounded (~200 KB total regardless of session length), and a bucket whose `count` EXCEEDS `sampleCapacity` reports `truncated == true` (exactly at capacity the window is lossless, so `count == sampleCapacity` → `false`). Mutating API: `record(_:nanos:)` (O(1), no allocation — every ring reserves capacity in `init`), `recordKeystroke()`, `recordWake()`, `reset()` (zeroes everything, keeps the allocated storage, so each report covers only its own interval). Non-mutating: `summarize(index:elapsedSeconds:) -> Report` (copies and sorts each ring — the ONLY sorting in the design, once per report, never per frame — omitting zero-count buckets) and `retainedSampleCount(_:) -> Int`. Statics: `percentile(_ sorted:_ p:) -> UInt64` (**nearest-rank**, `index = clamp(Int(ceil(p * n)) - 1, 0, n - 1)`, `0` for empty input — it always returns an actually-observed value), `delta(start:end:) -> UInt64` (saturating: `0` rather than a `UInt64` underflow when `end` precedes `start`, which also absorbs the disabled `0` sentinel), `format(_ report:) -> String` (the fixed-width, `diff`-able table — every line prefixed `wolf-frame-stats `, rows sorted by `rawValue`, label left-14, count right-5 with a `*` suffix INSIDE the field when truncated, then mean/p50/p95/max right-9 each in milliseconds to two decimals, `window=5.0s` to one decimal, `wakes/key=n/a` when `wakesPerKeystroke` is nil, and a trailing newline on every line including the last), `isEnabled(env:) -> Bool` (`WOLF_FRAME_STATS` trimmed + lowercased ∈ `1`/`true`/`yes`/`on`; absent/empty/anything else → false), and `reportInterval(env:) -> TimeInterval` (`WOLF_FRAME_STATS_INTERVAL` in seconds; absent, unparseable or non-positive → `5.0`). The value types `BucketSummary` (`bucket`, `count`, `meanNanos` — truncating integer division — `p50Nanos`, `p95Nanos`, `maxNanos` tracked outside the ring, `truncated`) and `Report` (`index`, `elapsedSeconds`, `buckets`, `keystrokes`, `wakes`, `wakesPerKeystroke: Double?` — nil when `keystrokes == 0`) both carry PUBLIC MEMBERWISE INITS so fixtures can be built. `wakesPerKeystroke` is a counter RATIO, not real attribution: wakes from mouse, scroll, resize, `:cd` and out-of-band core notifications inflate it, so it is an **UPPER BOUND** valid only for a session where the user does nothing but type. Headlessly unit-tested by `FrameStatsTests`.

## `WolfMacOS/` — the AppKit application

The `wolf_macos_lib` module: the native shell that links AppKit / CoreText / CoreGraphics and depends on `:wolf_key_map` and the `wolf-ffi` archive.

- **`main.swift`** — the entry point: `NSApplication.shared`, install the `AppDelegate`, `.regular` activation policy, `app.run()`.
- **`AppMenu.swift`** — `enum AppMenu`, builds and installs the native **NSMenu app menu bar** once (`install(target: AppDelegate) -> InstalledMenus`, RETURNING the `InstalledMenus { window; openRecent; history }` TRIO of dynamic submenus so the `AppDelegate` can rebuild all three dynamic tails) from wolf-macos's OWN hardcoded item description (it does NOT read the core registry over FFI — only the `command_kind` discriminant crosses the bridge): **App** (About / Hide `⌘H` / Quit `⌘Q`), **File** (New `⌘N` / New Window `⇧⌘N` / New Tab `⌘T` / separator / Go to File `⌘O` / Open File _(no shortcut)_ / Open Folder `⇧⌘O` / **Open Recent** _(dynamic submenu, no shortcut)_ / separator / Close `⌘W` / Close Window `⇧⌘W`), **Edit** (Copy `⌘C` / Paste `⌘V`, inserted between File and View — its ONLY two entries), **View** (**Toggle Sidebar** `⌃⌘S` / separator / Reset Font Size `⌘0` / Increase Font Size `⌘=` / Decrease Font Size `⌘-` / separator / **Command Palette…** `⌘P` / **Buffer Picker…** `⌘E` / **Preview** _(no shortcut)_ / **Edit Source** _(no shortcut)_ / **Terminal** `` ⌃` `` / **Preview in Browser** _(no shortcut)_ / **Use full width for content** _(no shortcut)_ / separator / **Enter Full Screen** `⌃⌘F`), **History** (Back `⌘[` / Forward `⌘]` / separator / the active pane's recently-visited rows), **Window** (Minimize `⌘M` / separator / a DYNAMIC list of one item per open window, titled with its cwd). **History sits BETWEEN View and Window** — the conventional place for a navigation menu — so the bar is now SEVEN menus.

  The **History menu** is built by the private `historyMenuItem(target:)` and rebuilt at menu-open time by the static `rebuildHistoryMenu(_:rows:target:)`. Both share `addHistoryFixedItems(to:target:)`, which adds the FIXED head so the initial build and every rebuild can never drift: **Back** (`keyEquivalent: "["`, `.command` → `⌘[`, action `#selector(AppDelegate.historyBackMenuItem(_:))`), **Forward** (`"]"` → `⌘]`, `historyForwardMenuItem`), then a separator. `historyPlaceholderItem()` is the disabled `HistorySeam.emptyPlaceholderTitle` ("No History") row (`action: nil` auto-disables it), seeded at build time so the menu is never empty before the first rebuild and re-added whenever `rows` is empty. Otherwise `rebuildHistoryMenu` does `removeAllItems()`, re-adds the fixed head, then one clickable item per `HistorySeam.Row` — `title: row.title`, `action: #selector(AppDelegate.historyJumpMenuItem(_:))`, `target: target`, `tag: row.index`, `state: row.isCurrent ? .on : .off`. **NOTE:** a row item's `tag` is a STACK INDEX, **not** a `command_kind` discriminant like every `commandItem` tag in this file; the distinct `historyJumpMenuItem(_:)` selector is what keeps the two unambiguous. These are FRONT-END-ONLY items, like Toggle Sidebar — no `wolf_core::Command` variant exists for them, so they do NOT route through `handleCommandMenuItem` / `CommandDispatcher`. The item titles mirror `wolf_core::COMMAND_SPECS` (ellipses are single U+2026); a private `Tag` enum holds the FFI `command_kind` discriminants `0..22` (`closePane = 8`, `newBuffer = 9`, `resetFontSize = 10`, `increaseFontSize = 11`, `decreaseFontSize = 12`, `commandPalette = 13`, `copy = 14`, `paste = 15`, `bufferPicker = 16`, `newTab = 17`, `preview = 18`, `edit = 19`, `terminal = 20`, `previewInBrowser = 21`, `fullWidth = 22`). - **`CommandDispatcher.swift`** — `enum CommandDispatcher`, the single funnel every command flows through. `dispatch(_ kind: CommandKind, window: NSWindow?, coordinator: AppDelegate?, originatingCwd: String, controller: WolfWindowController?)` maps a decoded `CommandKind` to its native action: `.newWindow` → `coordinator?.makeNewWindow(originatingCwd:)`, `.closeWindow` → `window?.performClose`, `.quitApplication` → `NSApp.terminate`, `.hideApplication` → `NSApp.hide`, `.minimizeWindow` → `window?.miniaturize`, `.goToFile` → `controller?.openFilePicker()`, `.openFile` → `controller?.presentOpenFileDialog()`, `.openFolder` → `controller?.presentOpenFolderDialog()`, `.closePane` → `controller?.closePane()` (`:close`), `.newBuffer` → `controller?.newBuffer()` (`:enew`), `.resetFontSize` → `controller?.resetFontSize()`, `.increaseFontSize` → `controller?.increaseFontSize()`, `.decreaseFontSize` → `controller?.decreaseFontSize()`, `.commandPalette` → `controller?.openCommandPalette()`, `.copy` → `controller?.copy()`, `.paste` → `controller?.paste()`, `.bufferPicker` → `controller?.openBufferPicker()`, `.newTab` → `controller.map { coordinator?.makeNewTab(from: $0) }` (open a new native tab in the target controller's window group), `.preview` → `controller?.openPreview()` (open the Markdown preview pane), `.edit` → `controller?.editSource()` (navigate a preview pane back to its source), `.terminal` → `controller?.toggleTerminal()` (toggle the per-project terminal drawer), `.previewInBrowser` → `controller?.openInBrowser()` (render the active Markdown buffer and open it in the system default browser), `.fullWidth` → `controller?.toggleFullWidth()` (toggle the active buffer between the ~90-char default content width and full pane width). Both the native-menu path (`handleCommandMenuItem`, targeting `NSApp.keyWindow`) and the nvim-drained path (`WolfWindowController.drainAndDispatchCommands`, targeting the draining controller's own window) route here, so a command has ONE implementation regardless of face. `controller` is the target window's controller (the menu path finds the key window's controller via `owns(_:)`, the nvim-drained path passes `self`), through which the four File commands reach that window's picker / core handle; `originatingCwd` (the originating window's live `handle.cwd()`) is inherited only by `.newWindow`. Compile-verified + manual-smoke only; the pure decode lives in `CommandSeam`.
- **`AppDelegate.swift`** — the app **coordinator** (also conforming to **`NSMenuItemValidation`** and **`NSMenuDelegate`**), a thin manager over a `controllers: [WolfWindowController]` collection (one per TAB/VIEW; each its own OS window, several may share a native tab group) AND a `projects: [Project]` collection (one captive Neovim per project, shared by N views; a project removes itself via `removeProject(_:)` when its last view closes). It mints a monotonic `tabId` per controller (via `mintTabId()` / a `nextTabId` counter) — the Window-menu / raise key — and owns the coalesced whole-tree state snapshot (`scheduleStateSnapshot()` → a ~150ms `DispatchWorkItem` debounce → `snapshotNow()`, which walks every controller, groups windows by `NSWindow.tabGroup` — a solo window is its own group — orders tabs via `tabGroup.windows`, takes each group's geometry from `tabGroup.selectedWindow?.frame ?? first.frame`, and drives `wolf_ffi_state_snapshot_begin` / `add_window` / `add_tab(view.persistedCwd, …)` / `commit` — each tab's cwd being the view's TAB-LOCAL `persistedCwd` via `cwd_for_tabpage`, since project membership is NOT persisted) and the tab titles (`refreshTabTitles(forGroupOf:)` → `CwdTitleSeam.displayTitle` over each tab's `persistedCwd` + `homeDir()`, set as the tabs' `NSWindow.title` with a `"Wolf"` fallback for an empty cwd, plus a `representedURL` proxy directory URL — `nil` in the empty state). At launch it does the once-only, whole-process setup: install the three wake bridges (`WakeBridge` / `PickerWakeBridge` / `TreeWakeBridge`), install the native menu bar (stashing the `AppMenu.install(target: self)` result — the Window `NSMenu` into `windowMenu`, then `rebuildWindowMenu()` once the controllers exist, the Open Recent `NSMenu` into `openRecentMenu` with `openRecentMenu?.delegate = self` so it rebuilds lazily, and the History `NSMenu` into `historyMenu` with `historyMenu?.delegate = self` for the same lazy rebuild), then **register the bundled fonts, load the user config, then measure the cell metrics, in that order** (`FontRegistration.registerBundledFonts()` → `wolf_ffi_load_config()` → `CellMetrics.measured(config:)`), so both bundled families resolve — "iA Writer Mono S" (the default) and "JetBrains Mono" — and the config's font-family / size / line-height drive the shared grid geometry. Metrics + config are measured ONCE and passed to every controller. It then reads the saved application state (`wolf_ffi_load_state()` BEFORE any core starts) and restores by a **two-phase GROUP-BY-CWD** materialize (plan §4.2 + OD5; project identity is NOT persisted): `restoredGroups(from:)` copies each `FfiWindowState`'s geometry + its `FfiTabState` list OUT of the bridge vecs into plain `RestoredWindowGroup { x, y, width, height, tabs: [RestoredTabState] }`; `savedWindows(from:)` projects those into `RestoreSeam.SavedWindow`s and `RestoreSeam.plan(windows:home:isDirectory:)` groups them into PROJECTS (one per distinct real cwd, merged across windows; each empty-state / deleted-dir tab its own project). **Phase A** (`materializeProjects`): per `ProjectPlan`, `Project.start(launchCwd:coordinator:)` (a fresh nvim; a failed start drops its tabs), then the first tab binds the project's implicit tabpage 1 (`bindFirstTabpage()`) and tabs 2..N create fresh tabpages (`addTabpage(cwd:)`, `0` → the tab is dropped); each surviving tab builds a `WolfWindowController` bound to `(project, tabpageHandle)` (`makeController` + `build()`), appended to `controllers` and recorded by its ORIGINAL `(groupIndex, positionInGroup)`; a project with no surviving view has its idle core shut down. **Phase B** (`assembleWindows`): for each saved group in order, anchor the first surviving view at the group's validated frame (`StateSeam.restoredWindowFrame`) and `addTabbedWindow` the rest into its tab group. So a runtime project whose views `:tcd`'d to different dirs is SPLIT on restore, and same-dir tabs from different runtime nvims are MERGED — every restored project is uniform-cwd (the accepted OD5 consequence). With nothing saved it creates one default empty-state view (`startEmptyStateWindow`). **Launch is empty-state-aware:** each window's `(launchCwd, hasFolder)` is derived by feeding the (possibly empty/deleted) restored cwd through the pure `StateSeam.launchDecision(restored:home:isDirectory:)` (`home = FileManager.default.homeDirectoryForCurrentUser.path`) and mapping the result with the private `dir(_:)` helper — `.folder(cwd)` → `(cwd, hasFolder: true)`, `.emptyState(nvimCwd)` → `(nvimCwd, hasFolder: false)`. So a fresh launch with an empty state file, and a restored window whose saved cwd is `""` or no longer a directory, both open an EMPTY-STATE window (Wolf never opens the process working directory); a valid saved cwd opens that folder. A fatal alert (`presentStartupFailureAndQuit`) fires only when EVERY restored core failed (`controllers.isEmpty` after both phases). `makeNewWindow(originatingCwd:)` is the **New Window** (⇧⌘N) entry: it IGNORES `originatingCwd` and ALWAYS opens a new STANDALONE empty-state window via `startEmptyStateWindow()` — `Project.start(launchCwd: home, coordinator: self)` (a FRESH nvim / project), binds its implicit tabpage 1, builds + `build()`s a `hasFolder == false` view, appends the project + controller, and `setCurrent`s it (fresh `tabId`, cascade placement), then `scheduleStateSnapshot()`. `makeNewTab(from key:)` is the **⌘T / `:WolfNewTab`** entry: it REUSES `key.project` (a new tab ≈ a new window in the SAME nvim/project) — `key.project.addTabpage(cwd: key.hasFolder ? key.currentCwd : "")` (guard `!= 0`), builds a view bound to `(key.project, tabpage)`, `addTabbedWindow`s its window into `key`'s group and selects it, then rebuilds the Window menu + `scheduleStateSnapshot()`. `@objc newWindowForTab(_:)` (the native "+" button, NSApp → delegate) routes to `makeNewTab(from: keyController)`. `makeController(tabId:project:tabpageHandle:restoredTab:anchorFrame:hasFolder:)` threads the project + tabpage into each controller. `removeProject(_:)` drops a project from `projects` when its last view shuts the core down. `handleCommandMenuItem(_:)` is the native menu-item entry point: it decodes the item's `tag` (an FFI `command_kind` byte set by `AppMenu`) into a `CommandKind` via `CommandKind(ffi:)`, finds the key window's controller (`controllers.first { $0.owns(effectiveKeyWindow) }`), and funnels through `CommandDispatcher.dispatch(..., window: effectiveKeyWindow, coordinator: self, originatingCwd:, controller:)` — the SAME dispatcher the nvim-drained command path uses. (`effectiveKeyWindow` is a private helper — `NSApp.keyWindow.parent ?? NSApp.keyWindow` — used at every owning-controller LOOKUP site: while a picker panel is key, `NSApp.keyWindow` is the borderless child panel that no controller owns, so it resolves to the panel's parent `MainWindow`; `snapshotNow` / `refreshTabTitles` / `otherWindows` walk `controllers` / `tabGroup.windows` and are unaffected.) `removeController(_:)` drops a controller at window close. The **dynamic Window menu** is owned here: `rebuildWindowMenu()` (→ `AppMenu.rebuildWindowMenu(windowMenu, controllers:, target: self)`) runs at startup, in `makeNewWindow`, in `removeController`, and on `windowCwdDidChange(_:)` (a controller's per-window cwd-change hook); `@objc raiseWindowMenuItem(_:)` maps `sender.tag` (a controller's `tabId`) to `controllers.first { $0.tabId == sender.tag }` and calls its `raise()`. The **dynamic Open Recent and History submenus** are BOTH rebuilt lazily via the `NSMenuDelegate` conformance, `menuNeedsUpdate(_:)` now dispatching on menu IDENTITY: it resolves the source controller ONCE (`controllers.first { $0.owns(effectiveKeyWindow) } ?? controllers.first`) and then branches. The History branch (`menu === historyMenu`) calls `AppMenu.rebuildHistoryMenu(menu, rows: source?.historyRows() ?? Three `@objc` actions back it, each resolving the key controller through the picker-panel-aware `effectiveKeyWindow` with the SAME `?? controllers.first` fallback: `historyBackMenuItem(_:)` → `historyBack()`, `historyForwardMenuItem(_:)` → `historyForward()`, and `historyJumpMenuItem(_:)` → `historyJump(index: sender.tag)` (that `tag` is a STACK index, not a `command_kind` discriminant — the distinct selector is what keeps it unambiguous, and the checkmarked row's tag is the cursor's own index, which core rejects as a no-op). `validateMenuItem(_:)` gains three explicit branches BEFORE its `handleCommandMenuItem` guard, since these items carry no `command_kind` tag: Back → `historyCanBack ?? false`, Forward → `historyCanForward ?? false`, and a dynamic row → `true`. Open Recent items are still untouched by it — they use `openRecentMenuItem(_:)` (not `handleCommandMenuItem`) so they fall through to `true`, and each menu's placeholder (`action: nil`) auto-disables itself. It still returns `true` for every item EXCEPT three: the `.closePane` (Close) command item, enabled only when the key window's controller `paneCount > 1` (so the last split cannot be closed, matching Neovim's E444 — the dynamic window items short-circuit before the tag-as-`command_kind` cast because their action differs); the `.copy` (Edit > Copy) command item, enabled only when the key window's controller `isVisualMode` (there is no selection to copy otherwise); the `.preview` (View > Preview) command item, enabled only when the key window's controller `isMarkdownActive` (the active buffer is Markdown); the `.edit` (View > Edit Source) command item, enabled only when the key window's controller `isPreviewActive` (the active pane is a preview); and the `.previewInBrowser` (View > Preview in Browser) command item, enabled only when the key window's controller `isMarkdownActive` (the same Markdown gate as `.preview`); Paste and every other item stay enabled. The `.fullWidth` (View > Use full width for content) command item is a special FOURTH-plus case: it is ALWAYS enabled (returns `true` — OQ-2), but its `NSMenuItem.state` is set to `.on` / `.off` from the key window's controller `isFullWidthActive` (the checkmark tracks the active buffer's full-width state). `applicationShouldTerminateAfterLastWindowClosed` stays `true`. `applicationWillTerminate` walks the whole live window/tab tree SYNCHRONOUSLY (`snapshotNow()` — each tab's cwd taken from the view's `persistedCwd`, a cheap out-of-band snapshot read), blocks briefly on the writer (`wolf_ffi_state_flush()`), then iterates the PROJECTS (a copy, since `shutdown()` mutates `projects` via `removeProject`) and `project.shutdown()`s each as a backstop. It ALSO forwards OS app focus to every project: `applicationDidBecomeActive` → `pushUiFocusToAllProjects(gained: true)` and `applicationWillResignActive` → `pushUiFocusToAllProjects(gained: false)`, the private fan-out (a sibling of `pushAppearanceToAllProjects`) calling `project.setUiFocus(gained:)` (→ `handle.set_ui_focus` → `nvim_ui_set_focus`) on every project (a no-op before any project exists). BOTH edges are wired because nvim only fires `FocusGained` on a real unfocused→focused transition — reporting `false` on resign makes each subsequent reactivation a genuine refocus (a lone repeated `true` would de-dupe), so a Dock reactivation of Wolf fires `FocusGained` → the init.lua `WolfAutoRead` augroup's `:checktime` → an externally-changed, unmodified buffer reloads (this is what makes external-file reload happen when the user reactivates the app). App-level (not per-window) fan-out means switching between two windows of the SAME project sends nothing. `windowDidBecomeKey` is deliberately UNTOUCHED (it still drives the tabpage / `BufEnter` path via `setCurrent` + `markRefocusRebind`). `applicationDidFinishLaunching` also calls `FrameMetrics.start()` (which forces the once-only `enabled` evaluation at launch so that one-time `ProcessInfo` read can never land mid-frame, and arms the report timer only when the flag is set), and `applicationWillTerminate` calls `FrameMetrics.emit()` to best-effort flush the final partial interval.
- **`FrameMetrics.swift`** — `enum FrameMetrics`, the thin process-global glue around the pure `WolfKeyMap.FrameStats` seam (Foundation + Dispatch + `import WolfKeyMap`; it owns only what needs a running app — the once-only `enabled` evaluation, the clock reads, the report `Timer`, and the writes). **OFF BY DEFAULT and main-thread-only.** `static let enabled: Bool` is initialized exactly once (Swift `static let` → `swift_once`) from `FrameStats.isEnabled(env: ProcessInfo.processInfo.environment)`, so there is NO per-frame `ProcessInfo` lookup; `AppDelegate.applicationDidFinishLaunching` touches it via `start()` so the one-time init happens at launch. Hot path: `@inline(__always) begin() -> UInt64` (`enabled ? DispatchTime.now().uptimeNanoseconds : 0`) and `@inline(__always) end(_ bucket:_ start:)` (`guard enabled`, one clock read, `FrameStats.delta` saturating subtraction, one `record`), plus `noteKeystroke()` / `noteWake()`. **When the flag is off the entire cost at each call site is one `Bool` test** — no formatting, no allocation; when on, per sample it is one monotonic clock read, one integer subtraction, a few integer accumulates and one array-slot write, with no locks taken and the snapshot lock never held. `DispatchTime.now().uptimeNanoseconds` is used because it is monotonic (unaffected by wall-clock/NTP adjustments), allocation-free, and already integer nanoseconds; it does not advance during sleep, which is correct for frame timing. `end` / `noteKeystroke` / `noteWake` each carry a `#if DEBUG` `dispatchPrecondition(condition: .onQueue(.main))` (compiled out of release) enforcing the main-thread invariant `FrameStats` documents. `start()` is a no-op when disabled; otherwise it baselines the interval, writes a one-line `wolf-frame-stats enabled interval=<n>s` header, and installs a repeating `Timer` on `RunLoop.main` in **`.common` mode** (so reports keep firing during tracking / scrolling run-loop modes — exactly the moments worth measuring) calling `emit()`. `emit()` is silent when disabled, and **suppresses a fully-idle interval** (no buckets and both counters zero → it just re-baselines and returns, so an idle app produces no output); otherwise it summarizes, writes `FrameStats.format(...)`, then `reset()`s and re-baselines. `write(_:)` does ONE `FileHandle.standardError.write` per report and additionally appends to `WOLF_FRAME_STATS_FILE` when set (opened and cached once, seek-to-end, creating the file if absent; an open failure degrades silently to stderr-only). The call sites are `WolfWindowController.onRenderWake()` and `PaneContainerView.onRenderWake()` / `draw(_:)` / `reloadDirtyPreviews()` (all `begin()` + `defer { end(...) }` at the TOP, so early-return paths are still measured), explicit start/stop pairs around `render_preview(...).toString()` and `loadHTMLString(...)` inside the per-preview loop (one sample per preview, not per call), `FrameMetrics.noteKeystroke()` in `PaneContainerView.keyDown` immediately before `handle.send_key` (so only keys actually delivered to Neovim count), and `FrameMetrics.noteWake()` in `Project.onWake()` (exactly one per core wake, independent of view count). This is a DEV-ONLY measurement surface: it changes no render behavior. See `WolfKeyMap/FrameStats.swift` for the bucket set and the three env vars, and [`build.md`](../../../build.md) for how to run it from a terminal. Compile-verified + manual-smoke only (the pure half is headlessly tested by `FrameStatsTests`).
- **`WolfWindowController.swift`** — a VIEW: owns ONE tab's stack (a tab is its own OS window; several may share a native tab group), bound to `(project, tabpageHandle)`. It holds an injected `let project: Project` (STRONG — the shared core must outlive a view teardown while a sibling still binds it; the project holds its views WEAK, so no cycle), a `private(set) var tabpageHandle: Int64` (the first view's is the project's implicit tabpage 1 via `project.bindFirstTabpage()`; a joining/restored view creates a fresh one via `project.addTabpage(cwd)`), its `window`, `paneContainer`, `tree`, `picker`, `palette`, `bufferPicker`, `statePersistence`, and a monotonic `tabId`. Its `handle` is `project.handle` and its wake token is the project's — the controller NO LONGER calls `wolf_ffi_start` or registers in `WindowRegistry` (that is `Project.start`'s job). `build() -> Bool` (renamed from the old core-starting `start()`) returns `false` (having built nothing) when `tabpageHandle == 0`; otherwise it builds the pane container (`PaneContainerView(handle:metrics:tabpageHandle:)`) / sidebar `FileTreeView` / `PickerView` / `CommandPaletteView` (built parallel to the picker, with `palette.onActivate = { [weak self] row in self?.activatePaletteRow(row) }`) / `BufferPickerView` (built parallel to the palette, with `bufferPicker.onActivate = { [weak self] row in self?.activateBufferRow(row) }`) / centered "Open folder…" overlay `EmptyStateView` / `MainWindow`. Each of the three pickers is hosted in its OWN `PickerPanelHost` — `PickerPanelHost(parentWindow: window, paneContainer: paneContainer, contentView: picker, onResignKey: { [weak picker] in picker?.close() })`, the host strong-stored on the controller (`pickerHost` / `paletteHost` / `bufferPickerHost`) and set as the view's `host` — so each picker floats in a child panel in front of the window rather than a pane-container subview; only `EmptyStateView` remains a `paneContainer` overlay. It wires `paneContainer.onPickerTrigger` (the old `onNewWindow` wiring is GONE — New Window is the menu's ⇧⌘N item, no longer a Cmd-N keyDown interception) and the empty-state overlay's `onOpenFolder = { [weak self] in self?.presentOpenFolderDialog() }`, anchors the saved frame ONLY when the coordinator passes an `anchorFrame` (the first tab of a restored group; validated coordinator-side via `StateSeam.restoredWindowFrame`), else keeps AppKit's cascade placement (a joining tab is `addTabbedWindow`-ed by the coordinator), installs a `StatePersistence` (whose `onChange` calls `coordinator?.scheduleStateSnapshot()`), assigns `window.historyNav = self` right after the window is constructed (the toolbar's Back / Forward buttons delegate here EXPLICITLY — this controller is not an `NSWindowController`, so it is not in the responder chain and a `target: nil` action could never reach it), sets itself as the window delegate, shows the window, and makes the pane container first responder. - **`Project.swift`** — `final class Project` (main-thread-only), one captive Neovim instance shared by N views (each view bound to one nvim TABPAGE). It owns the single `WolfCoreHandle` and the per-PROJECT `wakeToken`, holds its views WEAK (the coordinator's `controllers` array owns their lifetime) plus a `private(set) weak var currentView`, and a weak `coordinator`. `static func start(launchCwd:coordinator:) -> Project?` is the **SOLE caller of `wolf_ffi_start`** (it resolves the bundled nvim / `WOLF_INIT_LUA`, calls the 4-arg `wolf_ffi_start`, reads `handle.wake_token()`, and `WindowRegistry.register`s under the token). `bindFirstTabpage() -> Int64` returns `handle.current_tabpage()` (the fresh nvim's implicit tabpage 1 — no `tabnew`); `addTabpage(cwd:) -> Int64` is `handle.create_tabpage(cwd)` (a joining/restored view; `0` → the caller drops the view). `attach(_:)` / `detach(_:)` maintain the weak view list — `detach` reassigns `currentView` when the removed view was current and, when NO views remain, calls `shutdown()` (the ONLY core-shutdown path). `setCurrent(_:)` guards a no-op change then `handle.set_current_tabpage(view.tabpageHandle)` (drives every tabpage switch); `closeTabpage(for:)` calls `handle.close_tabpage(view.tabpageHandle)` ONLY for a non-last view (the last view's `detach` shuts the whole core down instead). **Crash/stall recovery.** `onWake()` reads `handle.liveness()` FIRST (a hand-kept `Liveness` mirror of the FFI `mod liveness` discriminants): `Dead` fans `showNvimOverlay(.dead)` to ALL `views.allObjects` + calls `restartNeovim()` and returns (skipping the stale render), `NotResponding` fans `showNvimOverlay(.notResponding)` and returns (waits for the manual button), and `Alive` fans `hideNvimOverlay()` then the normal fan-out to `currentView`. `restartNeovim()` (guarded by a `restarting` bool) CAPTURES each view's `capturedOpenFiles()` + cwd BEFORE `handle.restart()`; only on `restart() == true` (an ACTUAL restart) does it rebind each view to a fresh tabpage (first → `bindFirstTabpage()`, rest → `addTabpage(cwd:)`, then `view.rebind(toTabpage:)` + `set_current_tabpage`) and reopen the captured files (`handle.open`, ACTIVE last so it lands focused), restore the current view, hide every overlay, and — LAST — fan `flashRestartNotice()` to every view (the transient "Neovim was restarted" banner over the now-working editor, independent of the liveness overlay the fresh nvim's `Alive` wake clears immediately;
