# wolf-macos/Sources

The Swift sources for the macOS front-end, split into two modules. See the crate [`README.md`](../README.md) for the design decisions and the build workflow.

## `WolfKeyMap/` — the pure key seam (no AppKit)

Twenty-one deliberately AppKit-free files, so they are unit-testable headlessly (the macOS analog of wolf-gnome's `gdk_key`, pure picker, and pure pane-layout seams). The Bazel `wolf_key_map` module compiles them together with the swift-bridge-generated Swift glue, so the rest of the app gets the generated types (`FfiKeyEvent`, `FfiMouseEvent`, `FfiScrollEvent`, `WolfCoreHandle`, `FfiFrame`, `FfiConfig`, `FfiFileSearch`, `FfiFileEntry`, `FfiTreeNode`, `FfiLayoutIntent`, `FfiWinInfo`, `FfiPaneStatus`, `FfiCommand`, `FfiCommandPalette`, `FfiCommandRow`, `FfiBufferPicker`, `FfiBufferRow`, `FfiState`, `FfiWindowState`, the free `wolf_ffi_ancestors_to_reveal`, `wolf_ffi_load_config`, `wolf_ffi_load_state`, …) via `import WolfKeyMap`.

- **`KeyMap.swift`** — `WolfKeyMap.translate(keyCode:characters:charactersIgnoringModifiers:ctrl:shift:alt:meta:) -> FfiKeyEvent?`. It imports only Foundation and the generated FFI struct. Named keys (Return, Tab, arrows, F-keys, …) are recognized from the virtual `keyCode` first and **keep** the real `shift` flag; printable characters carry the already-shifted glyph in `ch` with `shift = false`; when ctrl/alt/meta are held the glyph comes from `charactersIgnoringModifiers` (lowercased); bare modifiers and unmodified control characters return `nil`. The `Kind` discriminants mirror `wolf_core::Key`'s variant order (and the Rust `key_event_from_ffi`).
- **`PickerSeam.swift`** — `public enum PickerSeam`, Foundation only. Three ports of wolf-gnome's pure picker helpers: `isPickerTrigger(charactersIgnoringModifiers:command:) -> Bool` (the **Command+O** trigger — `command && first scalar lowercased == "o"`, other modifiers ignored — Command-modified keys are not Neovim keybindings, so the chord does not consume a Neovim key), `nextSelection(current:delta:nRows:) -> Int?` (list-nav clamp, port of `next_selection`), and `restoredIndex(resetToTop:prev:newLen:) -> Int?` (selection restore across streaming result batches, port of `restored_index`).
- **`PickerRefreshCoalescer.swift`** — `public final class PickerRefreshCoalescer`, Foundation only (headlessly tested by `PickerRefreshCoalescerTests`), a debounce/coalescing seam SHARED by BOTH the file picker (`PickerView`) and the file-tree sidebar (`FileTreeView`). The name is historical; the seam is generic (its `schedule` / `perform` collaborators are injected). It exposes `static let refreshInterval: TimeInterval = 0.033` (~30 fps), `request()`, and `cancelPending()`: `request()` COALESCES a burst of streaming-traversal wakes into ONE trailing refresh (the first call arms the timer, later calls while armed drop, and the fire clears the flag so a later wake re-arms — the FINAL / complete wake is never dropped), and `cancelPending()` clears the armed flag (an already-armed timer still fires, but the caller's `refresh()` is a no-op once closed). Both wake bridges call the owning view's `scheduleRefresh()` → `request()`.
- **`PaletteSeam.swift`** — `public enum PaletteSeam`, Foundation only, the command-palette sibling of `PickerSeam`. `isPaletteTrigger(charactersIgnoringModifiers:command:) -> Bool` is the **Command+P** trigger (`command && first scalar lowercased == "p"`, other modifiers ignored) — matching "p" instead of "o". **DORMANT / UNWIRED:** ⌘P is a menu key-equivalent that preempts `keyDown` (exactly like ⌘N and `ShortcutSeam`), so the View-menu item is the real trigger and `PaletteSeam.isPaletteTrigger` is NOT called from `PaneContainerView.keyDown`; it is kept for consistency with `PickerSeam` and still pinned by `PaletteSeamTests`. The nested `PaletteRowKind: UInt8` (`staticCommand = 0`, `switchWindow = 1`, `openRecent = 2`) with a guarded `init?(ffi:)` mirrors `wolf-ffi`'s `mod palette_row_kind`. Headlessly unit-tested by `PaletteSeamTests`.
- **`ShortcutSeam.swift`** — `public enum ShortcutSeam`, Foundation only. `isNewWindowTrigger(charactersIgnoringModifiers:command:) -> Bool` — the **Command+N** new-window trigger predicate (`command && first scalar lowercased == "n"`, other modifiers ignored), the sibling of `PickerSeam.isPickerTrigger` matching "n" instead of "o". **NOW DORMANT / UNWIRED:** New Window moved to the menu's ⇧⌘N key-equivalent and plain ⌘N is the File > New (`:enew`) menu item, so `PaneContainerView` no longer intercepts Cmd-N in `keyDown` (menu key-equivalents preempt `keyDown`). The seam and `ShortcutSeamTests` are kept as a still-passing pure seam, but nothing in the live app calls `isNewWindowTrigger`. Headlessly unit-tested by `ShortcutSeamTests`.
- **`TabTitleSeam.swift`** — `public enum TabTitleSeam`, Foundation only. `labels(activeBufferPaths: [String]) -> [String]` computes the per-tab titles for the tabs in ONE window from their active buffer paths: 1:1 and order-preserving; each label starts as the path's basename (last `/`-separated component); `""` / `"[No Name]"` / other unnamed inputs → `"untitled"` (untitled entries are EXCLUDED from disambiguation — a pathless tab cannot be disambiguated by a path); when two or more REAL-path tabs share a basename, each colliding label extends to `"<basename> — <minimal trailing parent segments>"` (EM DASH U+2014, one space each side), growing the trailing-segment count minimally until that colliding set is all-distinct (segments joined path-order with "/"). The coordinator feeds it each tab's `activeBufferPath` and sets the results as the tabs' `NSWindow.title`. Headlessly unit-tested by `TabTitleSeamTests`. (The former `WindowIndexSeam` + `WindowTitleSeam` are REMOVED: tab identity is now a monotonic `tabId` on the coordinator, and the OS window/tab title derives from the active buffer via this seam.)
- **`PaneTree.swift`** — a Foundation-only port of wolf-gnome's pure `layout.rs` pane-layout tree, `import Foundation` ONLY (it uses `Double`, not `CGFloat`, so it pulls in no CoreGraphics and stays in the headless test bundle). Public API: `typealias PaneId = UInt64`; `enum Orientation { horizontal, vertical }` and `enum FocusDir { left, right, up, down }` (each with an `init?(ffi:)` decoding the `wolf-ffi` discriminants); `struct Rect`; the `indirect enum PaneLayout { .leaf(PaneId); .split(orientation:children:weights:) }`; and `final class PaneTree` (a reference type, mutated in place) with `init(root:)`, `split(_:_:_:)`, `remove(_:)`, `leaves()`, `paneRects(width:height:)`, `neighbor(_:_:width:height:)`, and `layout()`. The free helpers (`splitIn`, `removeIn`, `normalize`, `collectLeaves`, `collectRects`, `directionalDistance`, `xOverlap`, `yOverlap`, `equalize`) are ported exactly: a SAME-orientation split inserts after the target then re-equalizes (FLATTENING into equal siblings), a PERPENDICULAR split nests, `remove` never empties the tree and re-equalizes / collapses a single child, and `neighbor` uses strictly-positive cross-axis overlap with stable DFS order. The macOS `PaneContainerView` consumes `paneRects()` to paint each pane into a computed rectangle — a single flat view, not an `NSSplitView` tree. Headlessly unit-tested by `PaneTreeTests` (a 1:1 port of the `layout.rs` suite + a discriminant-contract test).
- **`PaneGeometry.swift`** — `public struct PaneGeometry`, Foundation only (`Double`, reusing `Rect` from `PaneTree.swift`), the per-pane pixel↔cell mapping seam. It holds a **GRID RECT** inside a **PANE RECT**; `init(paneRect:cellWidth:cellHeight:maxCols:)` **caps the grid at `maxCols` columns and CENTERS it horizontally** when the pane is wider than that (leaving equal side margins, `paintOffsetX = inset`), while a pane no wider than the cap is unaffected (`gridRect == paneRect`, paint offsets `0`); `maxCols == nil` disables the cap entirely. `PaneContainerView` passes `maxCols: 90`, so a grid wider than 90 columns is centered with side margins. It exposes `cols` / `rows` (`max(1, floor(gridRect.size / cell))`), `paintOffsetX` / `paintOffsetY` (grid-rect origin − pane-rect origin, the centering inset when capped), and `cellAt(x:y:) -> (row, col)` mapping a pane-local point to a grid cell **clamped** into `[0, cols-1] × [0, rows-1]` (a margin / past-edge point lands on the nearest edge cell, so the side margins around a centered grid resolve to the nearest interior cell). Headlessly unit-tested by `PaneGeometryTests`.
- **`ScrollAccumulator.swift`** — `public struct ScrollAccumulator`, Foundation only, a pure signed pixel→line-step accumulator with a carried remainder. `consume(deltaY:cellHeight:) -> Int` returns the signed whole line steps for the delta (guarding `cellHeight <= 0` → `0`) and keeps the sub-cell remainder across calls so smooth trackpad scrolling accumulates; `reset()` clears it. Direction-agnostic (signed); the AppKit layer maps the sign to a scroll direction. Headlessly unit-tested by `ScrollAccumulatorTests`.
- **`CellMetricsMath.swift`** — `public enum CellMetricsMath`, Foundation only, the pure config-driven cell-geometry seam (extracted from `CellMetrics` so it stays headlessly testable). `cellHeight(fontSize:lineHeightPercent:ascent:descent:leading:) -> Double` returns `round(fontSize * lineHeightPercent / 100)`, guarding `lineHeightPercent <= 0` → the font's natural `ceil(ascent + descent + leading)`; `baseline(cellHeight:ascent:descent:) -> Double` returns `ascent + (cellHeight - ascent - descent) / 2`, recentering the glyph within a taller cell. `CellMetrics` feeds it the user config's line-height. Headlessly unit-tested by `CellMetricsMathTests` (130%@14, 100% natural, the degenerate guard, baseline recentering).
- **`FontSizeSeam.swift`** — `public enum FontSizeSeam`, Foundation only, the pure step+clamp math for the View font-size commands (extracted so it stays headlessly testable). It owns the constants `minPointSize = 6`, `maxPointSize = 72`, `step = 1` (all `Double`) plus `clamped(_:) -> Double`, `increased(_:) -> Double` (`clamped(current + step)`), and `decreased(_:) -> Double` (`clamped(current - step)`); it owns ONLY the increment/clamp math — RESET (to the window's stored default) is the `WolfWindowController`'s job, not the seam's. Headlessly unit-tested by `FontSizeSeamTests` (±1 step, clamp at 6/72, in-range pass-through, 71→72, 72→72, 7→6, 6→6).
- **`GlyphStyle.swift`** — `public enum GlyphFace { regular, bold, italic, boldItalic }`, `public struct GlyphStyle` (`face`, `underline` + `underlineColor: FfiColor`, `strikethrough` + `strikethroughColor: FfiColor`, all `Equatable`), and `public enum GlyphStyleResolver` with `resolve(flags: UInt8, fg: FfiColor, special: FfiColor) -> GlyphStyle`, Foundation only. It maps a cell's packed style-flag bits (mirroring `mod flag` in `wolf-ffi/src/lib.rs`: bold/italic/underline/undercurl/strikethrough) to a face (boldItalic if both bold+italic, else bold, else italic, else regular), folds undercurl into a straight underline, colors the underline with `special` when set (else fg), and strikes through in fg. It also adds `extension FfiColor: Equatable` (component-wise on `rgb` + `set`) so `GlyphStyle` synthesizes `Equatable`. Headlessly unit-tested by `GlyphStyleTests`.
- **`StateSeam.swift`** — `public enum StateSeam` (a namespace mirroring `PickerSeam`), Foundation + CoreGraphics only (no AppKit — it takes scalar/`CGRect` inputs, so the AppKit glue feeds it real window frames, `NSScreen.screens` visible frames, and a FileManager-backed closure). The pure decision seams backing the state-restore path: `restoredWindowFrame(x:y:width:height:screenVisibleFrames:) -> CGRect?` (`nil` — restore then falls back to the default centered placement — when width/height is non-positive, the "unset" sentinel, or when the frame intersects NO screen visible frame, so a window is never restored fully offscreen); and `launchDecision(restored:home:isDirectory:) -> LaunchDecision` (the launch model — `LaunchDecision` is `.folder(cwd:)` when `restored` is non-empty AND `isDirectory(restored)`, else `.emptyState(nvimCwd: home)` for an empty or deleted/replaced restored cwd; it NEVER returns the process working directory — the old `launchCwd` fallback that polluted the recent-dirs MRU is GONE; the injected closure keeps the seam pure). Headlessly unit-tested by `StateSeamTests`.
- **`RestoreSeam.swift`** — `public enum RestoreSeam` (a namespace mirroring `StateSeam` / `TabTitleSeam`), Foundation only, the pure **group-by-cwd** restore planner for the project/tabpage-per-view model (plan §4.2 + OD5). `plan(windows: [SavedWindow], home: String, isDirectory: (String) -> Bool) -> RestorePlan` rebuilds PROJECTS from the saved `(window, tab, cwd)` tree (project identity is NOT persisted): a tab whose saved `cwd` is non-empty AND `isDirectory(cwd)` joins the folder project keyed by that cwd STRING (merging same-dir tabs across windows into one project); anything else — an empty `""` cwd, or a since-deleted / non-directory path — is an empty-state tab that gets a UNIQUE project of its own (`launchCwd == home`), never collapsed (OD5). The value types: `SavedTab { cwd, sidebarVisible }`, `SavedWindow { tabs }`, `PlannedTab { groupIndex, positionInGroup, cwd, sidebarVisible }` (`Hashable` — retains each tab's ORIGINAL saved placement + cwd for Phase-B window re-assembly, even for a deleted-dir tab whose GROUPING key differs), `ProjectPlan { launchCwd, tabs }`, and `RestorePlan { projects }`. The ONLY injected impurity is `isDirectory` (the AppKit caller passes a FileManager-backed check; tests pass a set lookup); the seam does NOT canonicalize (the caller persists an already-canonical cwd via `cwd_for_tabpage`, so grouping is on the string as-saved). Headlessly unit-tested by `RestoreSeamTests`.
- **`StatusbarLayout.swift`** — `public struct StatusbarLayout`, Foundation only, the pure vertical-layout math for the per-pane statusbar strip. `init(primaryFontSize:secondaryFontSize:verticalPadding:lineGap:)` computes each line height as `ceil(fontSize * 1.25)` (a pinned `lineFactor`), places the primary (filename) line at `verticalPadding` and the secondary (path) line one `lineGap` below its bottom, and sizes the total `height` to leave a matching `verticalPadding` beneath the secondary line. It exposes `height`, `primaryLineTop`, `primaryLineHeight`, `secondaryLineTop`, `secondaryLineHeight` (all `Double`). `PaneContainerView` derives the strip height + line rects from it (primary/secondary font sizes from the grid's `CTFont`); the on-screen bg fill / NSString drawing / truncation are AppKit glue (manual-smoke only). Headlessly unit-tested by `StatusbarLayoutTests` (the exact height 37 for (13, 10, 3, 1) plus the structural invariants).
- **`CommandSeam.swift`** — `public enum CommandKind`, Foundation only, an AppKit-free command-kind decode seam (the sibling of `PaneTree`'s `Orientation(ffi:)` / `FocusDir(ffi:)`). The eighteen cases mirror `wolf-ffi`'s `mod command_kind` and the `wolf_core::Command` variant order: `newWindow == 0`, `closeWindow == 1`, `quitApplication == 2`, `hideApplication == 3`, `minimizeWindow == 4`, `goToFile == 5`, `openFile == 6`, `openFolder == 7`, `closePane == 8`, `newBuffer == 9`, `resetFontSize == 10`, `increaseFontSize == 11`, `decreaseFontSize == 12`, `commandPalette == 13`, `copy == 14`, `paste == 15`, `bufferPicker == 16`, `newTab == 17`. `init?(ffi: UInt8)` decodes the FFI byte (`0..17` → the matching case, anything else → `nil`), guarding the discriminant contract; the byte is delivered either in an `NSMenuItem.tag` (the native menu path) or by a drained `FfiCommand.kind()` (the nvim-drained path), and both faces funnel through the one `CommandDispatcher`. Headlessly unit-tested by `CommandSeamTests`.
- **`AppearanceSeam.swift`** — `public enum AppearanceMode: UInt8`, Foundation only, the pure appearance-mode decode seam (the sibling of `CommandSeam`'s `CommandKind(ffi:)` decode). The three cases `auto == 0`, `dark == 1`, `light == 2` mirror `wolf-ffi`'s `mod appearance` and `wolf_core::Appearance`'s variant order (plan OD-a). `AppDelegate` reads `FfiConfig.appearance()` (a `u8`) and maps it via `AppearanceMode(rawValue:)` — an out-of-range discriminant decodes to `nil` (falling back to `.auto`). No AppKit / NSApp / NSAppearance / live Neovim. Headlessly unit-tested by `AppearanceSeamTests`.
- **`EditorInset.swift`** — `public struct EditorInset`, Foundation only (`Double`, reusing `Rect` from `PaneTree.swift`), the pure arithmetic for the PER-PANE text-grid inset: it insets each pane's text grid by `padding` on the left/right, and by `statusbarHeight + padding` on top (the statusbar strip sits flush at the pane's top) / `padding` on the bottom. It owns `public static let padding: Double = 20` — the single source of truth (points) consumed by both `PaneContainerView` and `MainWindow`. `init(paneWidth:paneHeight:statusbarHeight:padding:)` echoes its inputs and derives the PANE-LOCAL `gridRect: Rect` (origin at the pane's top-left): `x = padding`, `y = statusbarHeight + padding`, `w = max(0, paneWidth − 2*padding)`, `h = max(0, paneHeight − statusbarHeight − 2*padding)` — only `w` / `h` clamp to a non-negative floor (so a pane narrower than `2*padding`, or shorter than `statusbarHeight + 2*padding`, never yields negative grid dimensions), while `x` / `y` are FIXED offsets and are NOT clamped. It also derives `textLeftInset: Double` (`== padding`), the horizontal inset the statusbar / cmdline text share so their text left-aligns with the grid text. The caller offsets `gridRect` into the pane's view rectangle; the padding regions are painted in the editor background by the view filling its whole `bounds`. Headlessly unit-tested by `EditorInsetTests`.

## `WolfMacOS/` — the AppKit application

The `wolf_macos_lib` module: the native shell that links AppKit / CoreText / CoreGraphics and depends on `:wolf_key_map` and the `wolf-ffi` archive.

- **`main.swift`** — the entry point: `NSApplication.shared`, install the `AppDelegate`, `.regular` activation policy, `app.run()`.
- **`AppMenu.swift`** — `enum AppMenu`, builds and installs the native **NSMenu app menu bar** once (`install(target: AppDelegate) -> InstalledMenus`, RETURNING the `InstalledMenus { window; openRecent }` pair of dynamic submenus so the `AppDelegate` can rebuild both dynamic tails) from wolf-macos's OWN hardcoded item description (it does NOT read the core registry over FFI — only the `command_kind` discriminant crosses the bridge): **App** (About / Hide `⌘H` / Quit `⌘Q`), **File** (New `⌘N` / New Window `⇧⌘N` / New Tab `⌘T` / separator / Go to File `⌘O` / Open File _(no shortcut)_ / Open Folder `⇧⌘O` / **Open Recent** _(dynamic submenu, no shortcut)_ / separator / Close `⌘W` / Close Window `⇧⌘W`), **Edit** (Copy `⌘C` / Paste `⌘V`, inserted between File and View — its ONLY two entries), **View** (**Toggle Sidebar** `⌃⌘S` / separator / Reset Font Size `⌘0` / Increase Font Size `⌘=` / Decrease Font Size `⌘-` / separator / **Command Palette…** `⌘P` / **Buffer Picker…** `⌘E` / separator / **Enter Full Screen** `⌃⌘F`), **Window** (Minimize `⌘M` / separator / a DYNAMIC list of one item per open window, titled with its cwd). The item titles mirror `wolf_core::COMMAND_SPECS` (ellipses are single U+2026); a private `Tag` enum holds the FFI `command_kind` discriminants `0..17` (`closePane = 8`, `newBuffer = 9`, `resetFontSize = 10`, `increaseFontSize = 11`, `decreaseFontSize = 12`, `commandPalette = 13`, `copy = 14`, `paste = 15`, `bufferPicker = 16`, `newTab = 17`). The File menu adds a **New Tab** `commandItem` (tag `.newTab`, key `"t"` → ⌘T) right after New Window. The View menu's `viewMenuItem(...)` adds a **Buffer Picker…** `commandItem` (tag `.bufferPicker`, key `"e"` → ⌘E) right after Command Palette…. The private `editMenuItem(target:)` (mirroring `viewMenuItem`) builds the Edit `NSMenu` with the two `commandItem`s — Copy (tag `.copy`, key `"c"` → ⌘C) and Paste (tag `.paste`, key `"v"` → ⌘V) — both wired to `handleCommandMenuItem`; Copy is enabled only in visual mode (gated by `AppDelegate.validateMenuItem`), Paste is always enabled. **Enter Full Screen is NET-NEW and is NOT a Wolf command** (a spec-vs-implementation deviation flagged per CLAUDE.md — no fullscreen item existed before): it is a STANDARD AppKit item whose action is `#selector(NSWindow.toggleFullScreen(_:))` with a `nil` target (routed to the key `NSWindow`) and mask `[.control, .command]`; it carries no `Tag`/`command_kind`, AppKit owns its validation + Enter/Exit title toggle, and `validateMenuItem` needs no change for it. **Toggle Sidebar is likewise a STANDARD AppKit item and NOT a Wolf command** (no core registry entry — it is the FIRST View item, with a separator immediately below it): its action is `#selector(NSSplitViewController.toggleSidebar(_:))` with a `nil` target, so it routes up the responder chain to the `EditorSplitViewController` (the window's `contentViewController`); its mask is `[.control, .command]` (⌃⌘S); it carries no `Tag`/`command_kind`, and `validateMenuItem` needs no change for it (its action differs from `handleCommandMenuItem`, so it falls through to `true`). Every Wolf command item carries its discriminant in `NSMenuItem.tag`, targets the `AppDelegate`, and fires `#selector(AppDelegate.handleCommandMenuItem(_:))`. The private `commandItem(title:tag:keyEquivalent:target:modifiers:)` helper takes `modifiers: NSEvent.ModifierFlags = .command` and sets `keyEquivalentModifierMask`, so `⇧⌘N` / `⇧⌘O` / `⇧⌘W` use a lowercase key equivalent plus an explicit `[.command, .shift]` mask (not a capital letter); `New Window` moved to `⇧⌘N` (plain `⌘N` is now File > New / `:enew`) and `Close` (the former "Close File") now runs `:close`. `viewMenuItem(...)` builds the View items, and the static `rebuildWindowMenu(_:controllers:target:)` clears the Window menu and rebuilds Minimize + separator + one item per controller (title = its `currentCwd`, fallback "Wolf"; action `#selector(AppDelegate.raiseWindowMenuItem(_:))`; `tag = tabId`). The File menu's **Open Recent** parent item (`openRecentItem`, inserted right after "Open Folder…") carries a dynamic `NSMenu` — a NATIVE dynamic submenu (like the Window menu, NOT a `Command`, since an Open Recent entry is path-parameterized and does not fit the no-arg `command_kind` model), seeded with a disabled "No Recent Folders" placeholder so it is never empty before the first rebuild; the static `rebuildOpenRecentMenu(_:recentDirs:target:)` (the sibling of `rebuildWindowMenu`) clears it and, when the MRU is empty, re-adds the disabled placeholder, else builds one item per path titled with the full path (action `#selector(AppDelegate.openRecentMenuItem(_:))`, target the delegate, `tag = ` the list index). The `Tag` enum / `command_kind` discriminants are UNCHANGED (Open Recent items use `openRecentMenuItem(_:)`, not the tag-as-`command_kind` path). Compile-verified + manual-smoke only.
- **`CommandDispatcher.swift`** — `enum CommandDispatcher`, the single funnel every command flows through. `dispatch(_ kind: CommandKind, window: NSWindow?, coordinator: AppDelegate?, originatingCwd: String, controller: WolfWindowController?)` maps a decoded `CommandKind` to its native action: `.newWindow` → `coordinator?.makeNewWindow(originatingCwd:)`, `.closeWindow` → `window?.performClose`, `.quitApplication` → `NSApp.terminate`, `.hideApplication` → `NSApp.hide`, `.minimizeWindow` → `window?.miniaturize`, `.goToFile` → `controller?.openFilePicker()`, `.openFile` → `controller?.presentOpenFileDialog()`, `.openFolder` → `controller?.presentOpenFolderDialog()`, `.closePane` → `controller?.closePane()` (`:close`), `.newBuffer` → `controller?.newBuffer()` (`:enew`), `.resetFontSize` → `controller?.resetFontSize()`, `.increaseFontSize` → `controller?.increaseFontSize()`, `.decreaseFontSize` → `controller?.decreaseFontSize()`, `.commandPalette` → `controller?.openCommandPalette()`, `.copy` → `controller?.copy()`, `.paste` → `controller?.paste()`, `.bufferPicker` → `controller?.openBufferPicker()`, `.newTab` → `controller.map { coordinator?.makeNewTab(from: $0) }` (open a new native tab in the target controller's window group). Both the native-menu path (`handleCommandMenuItem`, targeting `NSApp.keyWindow`) and the nvim-drained path (`WolfWindowController.drainAndDispatchCommands`, targeting the draining controller's own window) route here, so a command has ONE implementation regardless of face. `controller` is the target window's controller (the menu path finds the key window's controller via `owns(_:)`, the nvim-drained path passes `self`), through which the four File commands reach that window's picker / core handle; `originatingCwd` (the originating window's live `handle.cwd()`) is inherited only by `.newWindow`. Compile-verified + manual-smoke only; the pure decode lives in `CommandSeam`.
- **`AppDelegate.swift`** — the app **coordinator** (also conforming to **`NSMenuItemValidation`** and **`NSMenuDelegate`**), a thin manager over a `controllers: [WolfWindowController]` collection (one per TAB/VIEW; each its own OS window, several may share a native tab group) AND a `projects: [Project]` collection (one captive Neovim per project, shared by N views; a project removes itself via `removeProject(_:)` when its last view closes). It mints a monotonic `tabId` per controller (via `mintTabId()` / a `nextTabId` counter) — the Window-menu / raise key — and owns the coalesced whole-tree state snapshot (`scheduleStateSnapshot()` → a ~150ms `DispatchWorkItem` debounce → `snapshotNow()`, which walks every controller, groups windows by `NSWindow.tabGroup` — a solo window is its own group — orders tabs via `tabGroup.windows`, takes each group's geometry from `tabGroup.selectedWindow?.frame ?? first.frame`, and drives `wolf_ffi_state_snapshot_begin` / `add_window` / `add_tab(view.persistedCwd, …)` / `commit` — each tab's cwd being the view's TAB-LOCAL `persistedCwd` via `cwd_for_tabpage`, since project membership is NOT persisted) and the tab titles (`refreshTabTitles(forGroupOf:)` → `TabTitleSeam.labels` over each tab's `activeBufferPath`, set as the tabs' `NSWindow.title`). At launch it does the once-only, whole-process setup: install the three wake bridges (`WakeBridge` / `PickerWakeBridge` / `TreeWakeBridge`), install the native menu bar (stashing the `AppMenu.install(target: self)` result — the Window `NSMenu` into `windowMenu`, then `rebuildWindowMenu()` once the controllers exist, and the Open Recent `NSMenu` into `openRecentMenu` with `openRecentMenu?.delegate = self` so it rebuilds lazily), then **register the bundled fonts, load the user config, then measure the cell metrics, in that order** (`FontRegistration.registerBundledFonts()` → `wolf_ffi_load_config()` → `CellMetrics.measured(config:)`), so both bundled families resolve — "iA Writer Mono S" (the default) and "JetBrains Mono" — and the config's font-family / size / line-height drive the shared grid geometry. Metrics + config are measured ONCE and passed to every controller. It also resolves the config's **`appearance`** mode BEFORE any project starts (`applyResolvedAppearance()`, decoding `config.appearance()` via `AppearanceMode(rawValue:)`): **auto** sets `NSApp.appearance = nil` (follow the system), reads `resolvedDark` from `NSApp.effectiveAppearance.bestMatch(from: [.aqua, .darkAqua])`, and installs an `NSApp.effectiveAppearance` **KVO observer** (`installAppearanceObserverIfNeeded`, the token STORED in `appearanceObservation` so it is not deallocated) that re-resolves + re-pushes live when the OS toggles (`systemAppearanceChanged`, no-op when unchanged, no debounce — OD-c); **dark** / **light** force `NSApp.appearance = NSAppearance(named: .darkAqua)` / `.aqua` so the whole app chrome (menus, titlebar, dialogs) matches (OD-e), fix `resolvedDark`, and REMOVE the observer (no feedback loop). Changing the `appearance` config value is restart-only (read once at launch); only `auto`'s response to OS changes is live. The NSApp appearance forcing + KVO are macOS-runtime-specific (manual-smoke only, per §5.5); the pure decode lives in `AppearanceSeam` and the `set_background` push path is covered by the `wolf-ffi` / `wolf-core` appearance tests. It then reads the saved application state (`wolf_ffi_load_state()` BEFORE any core starts) and restores by a **two-phase GROUP-BY-CWD** materialize (plan §4.2 + OD5; project identity is NOT persisted): `restoredGroups(from:)` copies each `FfiWindowState`'s geometry + its `FfiTabState` list OUT of the bridge vecs into plain `RestoredWindowGroup { x, y, width, height, tabs: [RestoredTabState] }`; `savedWindows(from:)` projects those into `RestoreSeam.SavedWindow`s and `RestoreSeam.plan(windows:home:isDirectory:)` groups them into PROJECTS (one per distinct real cwd, merged across windows; each empty-state / deleted-dir tab its own project). **Phase A** (`materializeProjects`): per `ProjectPlan`, `Project.start(launchCwd:coordinator:)` (a fresh nvim; a failed start drops its tabs), then the first tab binds the project's implicit tabpage 1 (`bindFirstTabpage()`) and tabs 2..N create fresh tabpages (`addTabpage(cwd:)`, `0` → the tab is dropped); each surviving tab builds a `WolfWindowController` bound to `(project, tabpageHandle)` (`makeController` + `build()`), appended to `controllers` and recorded by its ORIGINAL `(groupIndex, positionInGroup)`; a project with no surviving view has its idle core shut down. **Phase B** (`assembleWindows`): for each saved group in order, anchor the first surviving view at the group's validated frame (`StateSeam.restoredWindowFrame`) and `addTabbedWindow` the rest into its tab group. So a runtime project whose views `:tcd`'d to different dirs is SPLIT on restore, and same-dir tabs from different runtime nvims are MERGED — every restored project is uniform-cwd (the accepted OD5 consequence). With nothing saved it creates one default empty-state view (`startEmptyStateWindow`). **Launch is empty-state-aware:** each window's `(launchCwd, hasFolder)` is derived by feeding the (possibly empty/deleted) restored cwd through the pure `StateSeam.launchDecision(restored:home:isDirectory:)` (`home = FileManager.default.homeDirectoryForCurrentUser.path`) and mapping the result with the private `dir(_:)` helper — `.folder(cwd)` → `(cwd, hasFolder: true)`, `.emptyState(nvimCwd)` → `(nvimCwd, hasFolder: false)`. So a fresh launch with an empty state file, and a restored window whose saved cwd is `""` or no longer a directory, both open an EMPTY-STATE window (Wolf never opens the process working directory); a valid saved cwd opens that folder. A fatal alert (`presentStartupFailureAndQuit`) fires only when EVERY restored core failed (`controllers.isEmpty` after both phases). `makeNewWindow(originatingCwd:)` is the **New Window** (⇧⌘N) entry: it IGNORES `originatingCwd` and ALWAYS opens a new STANDALONE empty-state window via `startEmptyStateWindow()` — `Project.start(launchCwd: home, coordinator: self)` (a FRESH nvim / project), binds its implicit tabpage 1, builds + `build()`s a `hasFolder == false` view, appends the project + controller, and `setCurrent`s it (fresh `tabId`, cascade placement), then `scheduleStateSnapshot()`. `makeNewTab(from key:)` is the **⌘T / `:WolfNewTab`** entry: it REUSES `key.project` (a new tab ≈ a new window in the SAME nvim/project) — `key.project.addTabpage(cwd: key.hasFolder ? key.currentCwd : "")` (guard `!= 0`), builds a view bound to `(key.project, tabpage)`, `addTabbedWindow`s its window into `key`'s group and selects it, then rebuilds the Window menu + `scheduleStateSnapshot()`. `@objc newWindowForTab(_:)` (the native "+" button, NSApp → delegate) routes to `makeNewTab(from: keyController)`. `makeController(tabId:project:tabpageHandle:restoredTab:anchorFrame:hasFolder:)` threads the project + tabpage into each controller. `removeProject(_:)` drops a project from `projects` when its last view shuts the core down. `handleCommandMenuItem(_:)` is the native menu-item entry point: it decodes the item's `tag` (an FFI `command_kind` byte set by `AppMenu`) into a `CommandKind` via `CommandKind(ffi:)`, finds the key window's controller (`controllers.first { $0.owns(NSApp.keyWindow) }`), and funnels through `CommandDispatcher.dispatch(..., window: NSApp.keyWindow, coordinator: self, originatingCwd:, controller:)` — the SAME dispatcher the nvim-drained command path uses. `removeController(_:)` drops a controller at window close. The **dynamic Window menu** is owned here: `rebuildWindowMenu()` (→ `AppMenu.rebuildWindowMenu(windowMenu, controllers:, target: self)`) runs at startup, in `makeNewWindow`, in `removeController`, and on `windowCwdDidChange(_:)` (a controller's per-window cwd-change hook); `@objc raiseWindowMenuItem(_:)` maps `sender.tag` (a controller's `tabId`) to `controllers.first { $0.tabId == sender.tag }` and calls its `raise()`. Three coordinator helpers back the **command palette**: `otherWindows(excluding:) -> [(index: Int, cwd: String)]` (every live controller EXCEPT the argument, mapped to `(tabId, currentCwd)` — the palette's "Switch to Window" candidate source, current tab excluded), `controllerForCwd(_ path:) -> WolfWindowController?` (the first live controller whose `currentCwd == path` — the "Open Recent Folder" raise target), and `raiseWindow(tabId:)` (the "Switch to Window" action). The **dynamic Open Recent submenu** is rebuilt lazily via the `NSMenuDelegate` conformance: `menuNeedsUpdate(_:)` (guarded on `menu === openRecentMenu`) reads the key-window controller's `recentDirs()` (`controllers.first { $0.owns(NSApp.keyWindow) } ?? controllers.first`, `[]` when none), stashes it in the `recentDirs` field, and hands it to `AppMenu.rebuildOpenRecentMenu` — so it is always fresh at menu-open time (unlike the Window menu's explicit lifecycle-hook rebuilds); `@objc openRecentMenuItem(_:)` bounds-guards `sender.tag`, resolves `recentDirs[sender.tag]`, and calls `changeDirectory(_:)` on the key-window controller (chdir — the same effect as Open Folder, with no panel). `validateMenuItem(_:)` is UNCHANGED — Open Recent items use `openRecentMenuItem(_:)` (not `handleCommandMenuItem`) so they fall through to `true`, and the placeholder's `action: nil` auto-disables it. It still returns `true` for every item EXCEPT two: the `.closePane` (Close) command item, enabled only when the key window's controller `paneCount > 1` (so the last split cannot be closed, matching Neovim's E444 — the dynamic window items short-circuit before the tag-as-`command_kind` cast because their action differs), and the `.copy` (Edit > Copy) command item, enabled only when the key window's controller `isVisualMode` (there is no selection to copy otherwise); Paste and every other item stay enabled. `applicationShouldTerminateAfterLastWindowClosed` stays `true`. `applicationWillTerminate` walks the whole live window/tab tree SYNCHRONOUSLY (`snapshotNow()` — each tab's cwd taken from the view's blocking `persistedCwd`), blocks briefly on the writer (`wolf_ffi_state_flush()`), then iterates the PROJECTS (a copy, since `shutdown()` mutates `projects` via `removeProject`) and `project.shutdown()`s each as a backstop.

NSOutlineView glue is exercised by manual smoke only (it needs a window server), like the picker.

It is a **single flat `NSView`** (flipped, the proven `GridView` pattern) that paints EVERY pane itself — deliberately NOT a tree of nested `NSSplitView`s, which composited unreliably when stacked under the source-list split. It is `init(handle:metrics:tabpageHandle:)` — the injected `controllerTabpageHandle` is this VIEW's tabpage, used as the refocus-rebind gate — and sets `wantsLayer = true` so a VISIBLE non-key window (two side-by-side windows of the SAME project) keeps its last-painted layer while it is not the current view (the project drives wakes only to `currentView`). **REFOCUS REBIND (OD2):** `markRefocusRebind()` (called by the controller's `windowDidBecomeKey` after it drives `project.setCurrent`) sets a `pendingRefocusRebind` flag; the next `onRenderWake()` consumes it ONLY once `handle.active_tabpage() == controllerTabpageHandle` (the snapshot reflects THIS view's tabpage), then `rebindStaleGrids()` (nulls every pane's `boundGrid` and re-resolves it via `grid_for_win(binding.win)` on the PRESERVED `PaneTree` — nvim window handles survive a tabpage switch while grid ids churn, so a multi-pane layout restores by rebinding grids, no geometry rebuild) + `updateActivePane` + `syncGridSizes`, SKIPPING `detectCloses` on the rebind pass (the just-vacated tabpage's destroyed grids would wrongly prune live panes; the next normal pass reconciles real closes). **Each pane's text grid is inset by a 20pt padding on all four sides** via the pure `WolfKeyMap.EditorInset` seam, applied ONLY in `gridRect(ofPane:)`: it builds an `EditorInset(paneWidth:paneHeight:statusbarHeight:padding:)` from the pane rect and offsets the seam's pane-local `gridRect` into the pane's view rect, so the grid sits below the top statusbar strip and inset by `padding` on the left/right/bottom (all downstream per-pane geometry / hit-testing routes through this reduced grid rect). The other consumers are back on the FULL `bounds`: `paneRects()` / `paneAreaHeight` size the layout from `bounds` at `(0, 0)` origin (no offset), `applyFocus` passes the full pane-area dims to `tree.neighbor`, `syncGridSizes()` sizes grid 1 from the whole `bounds`, `paintCmdlineStrip` builds a TOP-flush full-`bounds`-width strip at `y = paneAreaHeight`, and `drawDividers` compares against the full-bounds edges. The statusbar strip is TOP-FLUSH and full pane width; the cmdline strip text is indented by `EditorInset.padding` (in `paintStripRow`) so it aligns with the grid text. `draw(_:)` fills the whole `bounds` with the **live grid default background** (grid 1's `default_bg()`, with `WolfColor.fallbackBg` only as a fallback), now painting the per-pane padding regions so they match the text area exactly rather than reading darker than it under a themed background. `draw(_:)` computes every pane's rectangle via `PaneTree.paneRects(width, paneAreaHeight)` and, for each bound pane, calls `paintPane` which clips to the pane rect, paints a **top statusbar strip** (`statusbarRect(ofPane:)`), then the pane's window grid into the remaining **grid rect** (`gridRect(ofPane:)` — the pane minus the strip, so all pixel↔cell mapping and grid painting route through the reduced rect and the grid never draws under the strip). The grid paint is cell backgrounds + CoreText glyphs — each glyph in the bold/italic/boldItalic face and with the underline/strikethrough decorations that `GlyphStyleResolver` resolves from the cell's `flags()` + `special()`, underline/strikethrough stroked manually in the resolved color since `CTLineDraw` ignores decoration-color attributes — plus the mode-aware cursor when `cursor_visible`; each pane is drawn **independently of Neovim**, so an INACTIVE pane gets a translucent dim scrim (`inactiveDim`) over the WHOLE pane (strip + grid) — a front-end-only treatment that is awkward to express inside Neovim. **The per-pane statusbar** (`paintStatusbar`) fills the strip with the macOS titlebar background (the window's own `backgroundColor`, kept in sync with the `WolfTitlebar` theme by `MainWindow.applyTitlebarBackground`, falling back to `theme_titlebar_bg()` / the editor fallback when there is no window), then draws the pane's base filename (primary line) and its display path (secondary, smaller line) from `handle.pane_status_for_grid(grid)` — `filename()` / `display_path()` — via `NSString.draw(in:withAttributes:)` with a `.byTruncatingTail` paragraph style; the text is horizontally aligned to the grid text (left edge `gridRect.minX + geo.paintOffsetX`, right edge at the grid right edge) even though the strip bg fills the full strip width, the strip height + line rects come from the pure `WolfKeyMap.StatusbarLayout` (font sizes from the grid's `CTFont`), and the colors are the themed titlebar fg (secondary at a lower alpha) when set, else `labelColor` / `secondaryLabelColor`. An unnamed buffer shows `[No Name]` with no path line. `syncGridSizes` sizes each pane's grid from its `gridRect`, so nvim sees the REDUCED rows the grid actually paints into, and the synthetic scrollbar track spans the grid rect (never riding up over the strip). Thin separators are stroked between adjacent panes, and the bottom one-row **cmdline strip** paints Neovim's command line: under `ext_multigrid` the command line / messages live on a dedicated MESSAGE grid (NOT grid 1), positioned at the bottom via `msg_set_pos` (which the core drops), and the cursor moves onto it while the command line is open — so the strip identifies that grid as "the grid the cursor is on that is neither grid 1 nor a window grid" and paints its cursor row (with the cursor), falling back to grid 1's LAST row otherwise. `keyDown(_:)` checks `PickerSeam.isPickerTrigger` (→ `onPickerTrigger`) else runs `WolfKeyMap.translate` → `send_key` (keys go to nvim's current window globally); the old `onNewWindow` property and the `ShortcutSeam.isNewWindowTrigger` Cmd-N interception have been REMOVED (Cmd-N is now the File > New menu item; menu key-equivalents preempt `keyDown`). Its `metrics` is now a `var`: `applyMetrics(_:)` sets it, calls `syncGridSizes()`, and marks `needsDisplay` (the View font-size reflow path — the window frame is unchanged so cols/rows recompute), and `paneCount` (`tree.leaves().count`) exposes the live split count for `AppDelegate.validateMenuItem`. **Mouse / scroll** route through a per-pane `PaneGeometry` (`geometry(for:)`, `maxCols: nil`): `mouseDown` `focus_win`s the clicked pane (click-to-focus preserved) and `send_mouse`s a LEFT PRESS at `geo.cellAt(point)` on that pane's grid; `mouseDragged` / `mouseUp` send DRAG / RELEASE on the drag's grid (clamped), so `mouse=a` gives cursor-position + visual selection. `scrollWheel` hit-tests from the whole PANE rect (future side-margin still scrolls), accumulates `scrollingDeltaY` into line steps via a `ScrollAccumulator` (reset on grid change), and `send_scroll`s UP/DOWN on the pane's grid at the pointer cell (using `scrollingDeltaY`'s sign directly — it already reflects the user's natural-scroll setting, so `isDirectionInvertedFromDevice` is NOT re-applied, which would double-invert; a single commented flip point remains). **Synthetic scrollbars** are custom-drawn per pane in `draw(_:)` at each pane's right edge from the frame viewport (`topline` / `botline` / `linecount`, 0-based; thumb offset `topline / linecount`, underflow-safe, nothing drawn when the whole buffer is visible), following `NSScroller.preferredScrollerStyle` (`.legacy` always + faint track / `.overlay` fade after scroll) and reacting to `NSScroller.preferredScrollerStyleDidChangeNotification` (observer removed in `deinit`); the thumb is **non-interactive** (drag deferred). `onRenderWake()` mirrors GNOME's orchestration: `ensureInitialPane` (a `pick_initial_window` port — prefer `active_win()` if it is a real window grid `>= 2` and not hidden, else the lowest visible window grid from `windows()`, reusing the tree's root `firstPaneId`), `applyIntents` (`drain_intents` → SPLIT splits the `from`/active pane in the tree and binds a new pane to the new window via `grid_for_win` — 0 → pending; FOCUS_DIR resolves `tree.neighbor` and calls `focus_win`), `detectCloses` (the live-grid set from `windows()`; a pane whose bound grid vanished is removed, never below one leaf), `resolvePendingGrids`, `updateActivePane` (the pane whose `win == active_win()`, else whose bound grid `== read_frame().cursor_grid()`), then `syncGridSizes` (resize grid 1 to the whole view and each bound pane's grid to its rect, but ONLY when the size differs from nvim's current — so it converges, no resize-feedback loop) and a `needsDisplay`. **Divider drag-to-resize is deferred** (splits are equal-weighted, parity with wolf-gnome's v1 divider limitation; `NSSplitView` would have given drag for free but at the cost of the fragile nesting). AppKit glue, so compile-verified + manual-smoke only.

- **`CellMetrics.swift`** — measures a monospaced `CTFont` (advance width, ascent + descent + leading, cell height, baseline) from the resolved user config: `measured(config: FfiConfig)` measures at the config's default point size (via the internal `defaultPointSize(config:)`, which takes `config.font_size` unless `WOLF_FONT_PT` OVERRIDES it), while `measured(config: FfiConfig, pointSize: Double)` measures at an ARBITRARY point size (the View font-size re-measure path — each `WolfWindowController` owns its own metrics and re-measures here on reset/increase/decrease).
