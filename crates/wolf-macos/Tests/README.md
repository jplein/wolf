# wolf-macos/Tests

The Swift tests for the macOS front-end. The Bazel target is `//crates/wolf-macos:WolfKeyMapTests`; it runs regardless of `WOLF_NVIM_BIN` (it needs no Neovim) and covers the pure seams — the key seam (`KeyMapTests.swift`), the picker seam (`PickerSeamTests.swift`), the command-palette seam (`PaletteSeamTests.swift`), the pane-layout seam (`PaneTreeTests.swift`), the per-pane geometry seam (`PaneGeometryTests.swift`), the scroll-accumulator seam (`ScrollAccumulatorTests.swift`), the glyph-style seam (`GlyphStyleTests.swift`), the state-restore seam (`StateSeamTests.swift`), the command-decode seam (`CommandSeamTests.swift`), the Markdown-preview placement seam (`PreviewSeamTests.swift`), the Markdown-edit placement seam (`EditSeamTests.swift`), the Markdown-preview link-classification seam (`PreviewLinkSeamTests.swift`), the font-size seam (`FontSizeSeamTests.swift`), the per-pane statusbar layout seam (`StatusbarLayoutTests.swift`), the new-window trigger seam (`ShortcutSeamTests.swift`), the tab-title seam (`TabTitleSeamTests.swift`), the editor-inset seam (`EditorInsetTests.swift`), the picker-panel positioning seam (`PickerPanelSeamTests.swift`), the group-by-cwd restore seam (`RestoreSeamTests.swift`), the appearance-decode seam (`AppearanceSeamTests.swift`), and the frame-time aggregation seam (`FrameStatsTests.swift`).

## `WolfKeyMapTests/KeyMapTests.swift`

Pure, headless `XCTest` coverage of the AppKit-free `WolfKeyMap.translate(...)` seam — the macOS analog of wolf-gnome's headless `gdk_key` tests. It exercises the function with scalar inputs only (no `NSEvent`, no window, no event loop) — exactly the data an `NSView.keyDown(_:)` pulls off an `NSEvent` — and asserts the **Shift contract**, which must match `wolf-core/src/input.rs`:

- a plain printable char maps to `Char` with all flags false;
- a shifted printable (`Shift+a` → `A`, `Shift+1` → `!`) delivers the already-shifted glyph in `ch` with `shift = false` (Swift never sets `shift` on a `Char`);
- named keys (Return, Escape, Tab, forward-delete, the arrows, Home/End/PageUp/ PageDown, F1/F5) are recognized from `keyCode` and **keep** the real `shift` (`Shift+Tab`, `Shift+Left` stay `shift = true`);
- ctrl/alt/meta combos take the glyph from `charactersIgnoringModifiers` (lowercased) — `Ctrl+w` → `w` (not U+0017), `Alt+x` → `x`, `Cmd+s` → `s`, `Ctrl+Shift+w` → `w` with `shift = false`;
- bare modifier keys and unmodified control characters map to `nil`.

The test pins the `Kind` discriminants and the `kVK_*` virtual key codes (notably Backspace = `kVK_Delete` 0x33 and forward-delete = `kVK_ForwardDelete` 0x75) so they stay in lockstep with the Rust `FfiKeyEvent` `kind` scheme and the Swift `WolfKeyMap`.

## `WolfKeyMapTests/FrameStatsTests.swift`

Pure, headless `XCTest` coverage of the AppKit-free `WolfKeyMap.FrameStats` frame-time aggregation seam (`@testable import WolfKeyMap`, table-driven in the style of `PaneGeometryTests` / `StatusbarLayoutTests`; no Neovim, no window, no `Dispatch` timers). It pins: the **bucket discriminant contract** (`controllerWake == 0` → `"ctrl.wake"`, `containerWake == 1` → `"cont.wake"`, `draw == 2` → `"draw"`, `previewReload == 3` → `"prev.reload"`, `previewRender == 4` → `"prev.render"`, `previewLoadHTML == 5` → `"prev.html"`, and that `allCases` is dense and ascending from zero — the raw values ARE the storage indices); **env parsing** (`isEnabled`: absent / `""` / whitespace / `0` / `false` / `no` / `off` / `maybe` / only the interval var set → `false`, and `1` / `true` / `TRUE` / `Yes` / `on` / `" on "` → `true`; `reportInterval`: absent / `""` / `"0"` / `"-1"` / `"abc"` → the `5.0` default, `"2.5"` → 2.5, `"10"` → 10.0); **accumulation** (`meanNanos` is TRUNCATING integer division — `61 / 3 == 20`, not 20.33 or 21 — plus the single-sample case where every statistic collapses to that sample); **nearest-rank percentiles** (`index = clamp(Int(ceil(p * n)) - 1, 0, n - 1)` over an already-sorted input: empty → `0`, single element → itself, the exact two- and three-element rounding boundaries, an all-equal input, `1...100` → p50 50 / p95 95 / p100 100, `p == 0` clamping up to the smallest sample, plus a 1…50 sweep asserting `min <= p50 <= p95 <= max`); **bucket isolation** (recording `.draw` leaves `.previewRender` empty and `summarize` OMITS zero-count buckets, and two buckets keep independent counts/maxes); the **ring bound + truncation** (record `sampleCapacity + 100` with a distinguishable tiny-prefix-then-large pattern, so a wrong window is detectable: `count` and `maxNanos` stay EXACT and unbounded, `meanNanos` uses the exact unbounded sum, the percentiles reflect ONLY the last `sampleCapacity` samples, `truncated == true`, and `retainedSampleCount` never exceeds `sampleCapacity`; plus the boundary case that `count == sampleCapacity` is NOT truncated, since at exactly capacity the window is lossless); the **wakes/keystrokes ratio** (`keystrokes == 0` → `nil` even with wakes recorded, 30/10 → 3.0, 0/5 → 0.0, 2/4 → 0.5); **`reset()`** (everything zeroed, `summarize` yields no buckets, and a fresh post-reset window with NO leakage from large pre-reset samples into the new max/percentiles); **format stability / diffability** — a fixed `Report` built with buckets deliberately OUT of order asserts a BYTE-EXACT expected table (fixed column widths — label left-14, count right-5 with the `*` truncation marker inside the field, mean/p50/p95/max right-9 in milliseconds to two decimals; `window=5.0s` to one decimal; rows sorted by `rawValue`, not input order; the `wolf-frame-stats ` prefix on EVERY line; a trailing newline on every line including the last), plus a counters-only report still emitting the header and column rows with `wakes/key=n/a` for a nil ratio, a structural grep-prefix + line-count guard, and a reverse-record ordering guard — this is what guarantees two runs are `diff`-able; and the **saturating delta** (`FrameStats.delta(start:end:)`: a normal forward delta, identical stamps → `0`, an end BEFORE the start → `0` rather than a `UInt64` wraparound, the `(0, 0)` disabled sentinel → `0`, and a maximal forward delta preserved).

**Known coverage gaps** (compile-verified + manual-smoke only, consistent with how `PreviewSeamTests` / `StateSeamTests` document their glue): everything in `Sources/WolfMacOS/FrameMetrics.swift` — the once-only `static let enabled` initialization, `Timer` scheduling on `RunLoop.main` in `.common` mode, the stderr / `WOLF_FRAME_STATS_FILE` emission, the DEBUG `dispatchPrecondition` main-thread guard, and specifically **`emit()`'s idle-suppression branch** (the "no buckets and both counters zero → emit nothing, just re-baseline" path) — plus every instrumentation call site in `WolfWindowController` / `PaneContainerView` / `Project` / `AppDelegate`. These need a running app with a window server; the repo has **no macOS UI test target** and creating one was out of scope for an instrumentation-only pass. The repo's "prefer real integration tests over mocks" rule targets the Neovim boundary, and this change adds no FFI surface at all (no Rust was modified), so the existing real-nvim `wolf-ffi` suite still covers that boundary. To smoke the glue by hand, see the "Frame-time instrumentation (macOS)" section of [`build.md`](../../../build.md).

That idle-suppression gap has a **known structural weakness** worth recording: `FrameMetrics.emit()` decides an interval was fully idle by reading a private `recordedAnything` flag, hand-maintained in `FrameMetrics`'s three mutator wrappers (`end` / `noteKeystroke` / `noteWake`), which only MIRRORS the real condition "all buckets empty AND both counters zero". `testSummarizeOfUntouchedStatsIsEmpty` pins the `FrameStats` side of that contract, but it cannot observe the flag itself — the flag lives in `WolfMacOS`, which has no test target and is window-server-bound. So a FOURTH mutator added to `FrameStats` without a matching `FrameMetrics` wrapper would leave the suite green while idle-interval suppression silently broke. The known fix, deliberately not taken in this pass: hoist the flag onto `FrameStats` as a `public var hasActivity`, maintained in the mutators and cleared by `reset()`, with `emit()` reading it — that makes the invariant directly assertable, at the cost of widening a pinned API on a measurement surface that is expected to change.

## `WolfKeyMapTests/PickerPanelSeamTests.swift`

Pure, headless `XCTest` coverage of the AppKit-free `WolfKeyMap.PickerPanelSeam.frame(parentContentWidth:parentContentHeight:panelWidth:panelHeight:topMargin:)` seam (`@testable import WolfKeyMap`, reusing `PaneGeometryTests`' / `EditorInsetTests`' `eps` / `approx` + `assertRectEqual` style) — the picker-panel positioning arithmetic that centers a floating picker top-center over its parent window's content (the AppKit glue `PickerPanel` / `PickerPanelHost` maps this top-left content rect to a bottom-left screen frame).
