# wolf-gnome/tests

Tests for the seams and the windowed application. They split into **headless** checks (no display, no nvim), one **real-Neovim** end-to-end round-trip (no mocks, per project policy), and fourteen **headless-compositor** cage smoke tests that launch the real window (one window-render smoke, two file-picker smokes, one file-tree-sidebar smoke, five split-pane smokes — vertical split, horizontal split, a three-pane same-orientation split, focus move, close pane — and five command-drain smokes: the empty state, the Ctrl+Shift+N new-untitled-buffer chord, `:q` closing the focused pane, `:qa` closing the window, and the Ctrl+Shift+W close-pane chord) plus one pure guard on the smokes' own fixture, which needs no compositor. Everything runs through `nix develop --command` so the GTK toolchain, the pinned font, and `WOLF_NVIM_BIN` are present:

```sh
nix develop --command cargo test -p wolf-gnome
```

The default run **does** include all fourteen cage smokes, and they are the slowest part of the suite — see [the smoke test section](#smoke_headlessrs--windowed-app--picker--tree--panes--commands-real-compositor). They are part of the Linux verification gate; see [`build.md`](../../../build.md), "The Linux verification gate", for the authoritative full check.

## `grid_size_for` unit tests (in `src/geometry.rs`, headless)

The pure pixel-to-grid geometry is unit-tested **inside its own module** (a `#[cfg(test)] mod tests` in [`src/geometry.rs`](../src/geometry.rs)), needing no GTK, display, or nvim. A table-driven `grid_size_for_table` covers the typical exact-division case (`800×592` with `8×16` cells → `100×37`), flooring of partial cells (`17×17` → `2×1`), the min-1 clamp for tiny/zero/negative dims, the whole-result collapse to `(1, 1)` for degenerate cell sizes (zero/negative/NaN/ infinite, including a single-axis NaN), and the upper clamp of `i32::MAX` dims to `u16::MAX`. A second test, `grid_size_for_independent_axes`, proves cols and rows are computed separately (wide-but-short and narrow-but-tall grids).

## `cursor.rs` unit tests (in `src/cursor.rs`, headless)

The pure cursor geometry and color logic is unit-tested **inside its own module** (a `#[cfg(test)] mod tests` in [`src/cursor.rs`](../src/cursor.rs)), needing no GTK, display, or nvim. A table-driven `cursor_rect_table` covers the geometry per shape: `Block` always returns the full cell (ignoring `cell_percentage`); `Vertical` is a left bar of full height whose width is `cell_percentage` of `cell_w` (default `0.25`), floored to `MIN_BAR_PX` for tiny percentages and capped at `cell_w` for out-of-range ones; `Horizontal` is the analogous bottom bar against `cell_h` (anchored to the bottom edge). Deliberately non-square cells and a non-zero origin keep width/height math and offsets distinguishable. `named_constants_match_contract` pins `MIN_BAR_PX` / `DEFAULT_CELL_PCT` / `PCT_DENOM`.

A second group covers `cursor_colors` over hand-built `Snapshot`s: the **honor** path (a mode cursor highlight with distinct fg + bg → `(bg, fg)`, including with editor defaults set); the **inversion** path (bg-only, fg-only, `attr_id` `None`, out-of-range `mode_idx`, and empty `mode_infos` all fall through to `(cell_fg, cell_bg)` without panicking); the **guard** cases where a degenerate honored pair must NOT be honored (fill equal to the underlying cell background, or fill equal to glyph) and instead inverts; and the **fallback** case where unset cell colors reach the white/black `FALLBACK_FG` / `FALLBACK_BG`.

## `picker.rs` unit tests (in `src/picker.rs`, headless)

The picker's pure seams are unit-tested **inside their own module** (a `#[cfg(test)] mod tests` in [`src/picker.rs`](../src/picker.rs)), needing no GTK, display, or nvim:

- `next_selection_table` — down/up within range, clamp at both ends with NO wrap, empty list → `None`, single row, and out-of-range/negative `current` clamped.
- `restored_index_table` — empty list → `None` regardless of reset/prev; reset → `Some(0)`; preserve in range; preserve clamped when `prev` exceeds the new len; preserve with no prev defaults to `0`.

There is no trigger-predicate test here any more: `is_picker_trigger` was deleted along with its `is_picker_trigger_table`, and the picker's chord is now resolved by `actions::action_for_key` (covered by `action_for_key_table` below).

## `actions.rs` unit tests (in `src/actions.rs`, headless)

The whole action namespace is unit-tested **inside its own module** (a `#[cfg(test)] mod tests` in [`src/actions.rs`](../src/actions.rs)), needing no GTK, display, or nvim — `gdk::Key` and `gdk::ModifierType` are plain value types, and keyvals are built with the same `key_from_char` helper used by `gdk_key.rs` (which is what lets a case spell the SHIFTED glyph `'O'` a real keymap delivers for Ctrl+Shift+O):

- `every_accel_parses` — `parse_accel` returns `Some` for every declared accelerator. It first asserts the table declares at least one accelerator at all, so an emptied `ACTION_TABLE` cannot make every per-row test below pass vacuously.
- `accels_use_key_names_not_symbols` — the `<Control>-` vs `<Control>minus` trap: no key part may be a single punctuation character, and each must be either all-lowercase or one of the known named keys (`Left` / `Right`). `gtk_accelerator_parse` lowercases key names, so an uppercase spelling does NOT imply Shift.
- `no_accel_makes_a_neovim_key_unreachable` — `forbidden_reason` is `None` for every row (including the Reserved ones), **plus** explicit negative cases proving the checker bites: `<Control>p`, `<Super>n`, `<Primary>p` and `<Alt>p` are all refused, while `<Alt>Left` is accepted. (Which mechanism refuses a chord is an implementation detail — `<Super>` / `<Primary>` fail `parse_accel`'s grammar, `<Control>p` / `<Alt>p` parse and are refused by `forbidden_reason` — so the test asserts the composed contract.)
- `accels_are_unique` — no accelerator string is declared twice; a duplicate means one action silently never fires.
- `action_names_are_valid` — every action matches `^(app|win)\.[a-z0-9]+(-[a-z0-9]+)*$`. `gio` rejects a malformed name with a runtime warning, not a compile error, so this is the only cheap place to catch a typo.
- `bound_set_is_exactly_this_unit` — the `Bound` rows are exactly `win.go-to-file`, `win.new-buffer`, `win.close-pane`, `app.quit`, and each really has a chord to register.
- `action_for_key_table` (20 rows) — the LIVE matcher, and therefore user-visible behaviour, since `shell::AppShell::install_chord_controller` calls it from a capture-phase controller: each of the four bound chords fires in BOTH letter cases (a case-sensitive comparison would mean the chord never fires on real hardware while a lowercase-only test still passed); a bare `Ctrl+<letter>` does NOT fire, so `<C-o>` / `<C-n>` / `<C-w>` / `<C-q>` still reach Neovim; a Reserved row does NOT fire; the Ctrl/Shift/Alt match is EXACT (adding Alt misses); and a modifier bit outside the grammar is IGNORED, pinned from both sides — `Super+Shift+o` → `None` (Super can never supply the missing Ctrl) while **`Ctrl+Shift+Super+o` → `win.go-to-file`**. That last row is deliberate: an unintercepted Super chord is actively harmful, since Neovim drops the modifier in normal mode and inserts literal `<D-x>` text in insert mode, so intercepting it is strictly better than forwarding it.
- `key_name_matches_table` (21 rows) — every key-NAME shape `ACTION_TABLE` uses, including the named-key and punctuation-name branches that `action_for_key` cannot otherwise reach today (all four bound rows are single letters, while a later unit promotes exactly those Reserved rows). The negative rows are the point: an unknown name is `false` rather than a guess, and a punctuation name against a non-printable keyval (whose `to_unicode()` is `None`) is `false` rather than a panic.
- `command_action_round_trip` — command ↔ action is a bijection over the rows that carry a command.
- `menu_items_reference_declared_actions` — every `MenuItemSpec.action` is in `ACTION_TABLE` (a `gio::Menu` item naming an unknown action renders INSENSITIVE at popup time — a silent, visual-only failure). It also asserts `MENU_SECTIONS` is non-empty and no section is empty.
- `menu_never_lists_a_reserved_action` — a Reserved action is not installed this unit, so a menu item pointing at one would appear and do nothing.
- `menu_labels_match_the_registry` — where a menu item's action maps to a command, its label equals `Command::spec().title`, so a registry rename cannot silently desync the GTK menu.

## `command_action.rs` unit tests (in `src/command_action.rs`, headless)

The total `Command` → `UiAction` mapping is unit-tested **inside its own module** (a `#[cfg(test)] mod tests` in [`src/command_action.rs`](../src/command_action.rs)):

- `ui_action_table` — one row per `Command` variant in discriminant order, pinning the classification. Its length is asserted equal to `wolf_core::COMMAND_SPECS.len()`, which is what makes the table non-vacuous: a newly appended core command cannot be absorbed silently. Rows pin the CLASS for the two unimplemented variants, not their reason strings — duplicating ~18 sentences here would make a wording tweak look like a behaviour regression.
- `every_registered_command_maps` — walks `COMMAND_SPECS` and asserts each command appears in the table exactly once. Belt-and-braces for the totality guard: the `_`-free match already makes a new variant a compile error, but that evaporates the moment anyone adds a catch-all arm, whereas this check walks the registry rather than the match.
- `dispatched_commands_are_the_expected_set` — the commands whose action is neither `Deferred` nor `NoGnomeEquivalent` are exactly the eight this unit dispatches (`close_pane`, `close_window`, `go_to_file`, `minimize_window`, `new_buffer`, `open_file`, `open_folder`, `quit_application`), by registry `id` so the failure message names a row a reader can grep for. Nothing quietly promoted, nothing quietly demoted.
- `unimplemented_reasons_are_distinct_and_non_empty` — every `Deferred` / `NoGnomeEquivalent` reason is non-empty, reads as a mid-sentence clause (an ALL-CAPS opener such as "GNOME" is allowed, since the reason is interpolated into `"wolf-gnome: command {cmd:?} not dispatched: {reason}"`), and is UNIQUE — so no two rows of the README's command table can collapse into one indistinguishable entry, and a future pedantic `clippy::match_same_arms` run stays clean.

## `workspace.rs` unit tests (in `src/workspace.rs`, headless)

The launch decision and the re-root settle are unit-tested **inside their own module** (a `#[cfg(test)] mod tests` in [`src/workspace.rs`](../src/workspace.rs)). `launch_decision` takes `is_dir` as an injected predicate, so these need no temp directories and no real `$HOME`:

- `launch_decision_table` — a real project dir that is neither home nor `/` → `Folder`; `cwd == home` → `EmptyState { home }` (the desktop-launcher shape); `cwd == "/"` → `EmptyState { home }`; no process cwd at all → `EmptyState { home }`; a cwd the injected `is_dir` rejects → `EmptyState { home }`; `home == None` with a real project cwd → still `Folder`; `home == None` with an unusable cwd → `EmptyState { FALLBACK_CWD }`; and `home` set but not a directory → `EmptyState { FALLBACK_CWD }`.
- `reroot_ready_table` — `pending` `None` → false; `live` `None` → false; neither known → false; equal → true; a still-old `live` → false; a **trailing separator is NOT a difference** (`Path: PartialEq` compares components, so `/a/b/` == `/a/b` — the implementation is a plain `==` and must not be hand-rolled into a byte comparison); but an unnormalized `..` **is** a difference, which is exactly why callers canonicalize first.

## `tree.rs` projection (a re-export; tests live in `wolf-core`)

[`src/tree.rs`](../src/tree.rs) is a ten-line shim whose entire body is `pub use wolf_core::tree::*;`. It carries no `#[cfg(test)] mod tests` of its own. The pure hierarchical projection — `TreeNode`, `children_of`, `ancestors_to_reveal`, `node_rel_path`, `rel_path_for`, plus the `TreeIndex` / `TreeIndexCache` incremental layer (`TreeIndex::build`, `TreeIndex::children_of`, `TreeIndexCache::index_for`, `TreeIndexCache::build_count`) — and **all of its unit tests** live in `wolf-core`'s `tree` module, so that a single FFI-expressible source of truth is shared by every front-end. The shim exists only so the GTK glue in `tree_view.rs` (and `lib.rs`'s re-exports) keeps compiling against the `crate::tree::…` paths unchanged.

See [`crates/wolf-core/src/README.md`](../../wolf-core/src/README.md) for the projection's contract and its test coverage; do not duplicate that enumeration here.

## `layout.rs` unit tests (in `src/layout.rs`, headless)

The pure **N-ary frame** pane-layout tree (`PaneTree`, matching Neovim's window model) is unit-tested **inside its own module** (a `#[cfg(test)] mod tests` in [`src/layout.rs`](../src/layout.rs)), needing no GTK, display, or nvim — twenty tests covering:

- **construction / split** — `new` is a single leaf; a `Vertical` split yields two leaves side by side and a `Horizontal` split stacks them; `pane_rects` tiles the bounds for both; a perpendicular nested split produces the expected nested rectangles.
- **flatten vs. nest (the N-ary frame model)** — a split whose orientation MATCHES the containing frame FLATTENS into an equal-sized sibling row/column (a row `[P1, P2]` vsplit on `P1` becomes equal thirds `[P1, P3, P2]`, not a nested 25/25/50; repeated same-orientation vsplits stay flat at four equal columns), while a PERPENDICULAR split (an hsplit of a row member) NESTS into a sub-frame.
- **remove / collapse / re-equalize** — removing a leaf collapses its sibling (and a sibling _subtree_) into the parent's slot; removing a flat-row member re-equalizes the survivors (nvim `equalalways`); a now-1-child split collapses into its sole child; a surviving same-orientation split merges upward into the parent; removing the last pane is a no-op.
- **neighbor** — basic Left/Right (`Vertical`) and Up/Down (`Horizontal`) neighbours, a nested 2x2 case, a flat row of three, and `None` for an unknown pane.
- **ordering** — `leaves` and `pane_rects` enumerate in a stable DFS order.

## `gdk_key.rs` — input translation (headless, table-driven)

Table-driven unit tests for `wolf_gnome::gdk_key`, layout-independent: assertions cover only letter casing and named keys, never shifted-punctuation unicode (which is keyboard-layout dependent and would be flaky). These need no display server and no nvim — `gdk::Key` constants are compile-time and printable keyvals are built via the local `key_from_char` helper.

Cases cover: the Enter/Return family (incl. `KP_Enter`), `ISO_Left_Tab` + SHIFT → `Tab { shift: true }`, arrows, `Home`/`End`, `PageUp`/`PageDown`, `F1`/`F5`/`F12`, printable chars with the shift contract (`'a'` and `'A'` both → `Char(..)` with `shift: false`, `'<'`), modifiers on named keys (`Ctrl+Left`, `Ctrl+Shift+Left`), modifiers on printables (`Super+s`, `Alt+x`, `Ctrl+a` carries the base letter + ctrl, never a raw control char), and the `None` cases (`Shift_L`, `Control_L`, `Super_L`, `Caps_Lock`).

## `paint_golden.rs` — paint (headless, offscreen)

Builds a deterministic 4×2 `Snapshot` via core's public constructors (`Snapshot::new`, `HighlightTable::set_defaults`/`define`, `Grid::set_cell`), including one defined `hl_id` with distinct fg/bg and a wide-trailing empty-text cell. It measures `CellMetrics` against a throwaway 1×1 probe surface, sizes a real offscreen `ImageSurface` (ARGB32) to exactly the grid, paints, and samples pixels.

**Primary gate — structural ARGB center-sampling** (always on; deliberately _not_ a whole-image hash, which is too brittle across freetype/fontconfig):

- Known background fills are rasterizer-independent, so the center of the defined-bg empty cell and a default-bg cell are asserted for **exact** equality.
- The empty wide-trailing cell's interior is sampled at several inset points and must be background-only (verifying the "skip the glyph" path).
- The glyph cell's rect must contain at least one non-background pixel (the glyph was actually drawn).

Pixel reads assume little-endian ARGB32 (in-memory byte order `B, G, R, A`), which holds on the x86_64 Linux target.

**Dev aid (not part of the gate)** — `regenerate_png_golden` is `#[ignore]`d; it writes `tests/testdata/paint_golden.png` via `ImageSurface::write_to_png` (which needs the `cairo-rs` `png` feature). Run it explicitly:

```sh
nix develop --command cargo test -p wolf-gnome --test paint_golden \
    -- --ignored regenerate_png_golden
```

It is now the **only** `#[ignore]`d test in the whole repo, so a bare `cargo test -p wolf-gnome -- --ignored` runs nothing but this golden rewrite.

Font determinism relies on the pinned `DejaVu Sans Mono` exposed via `FONTCONFIG_FILE` (set by the flake devShell from [`testdata/fonts.conf`](../testdata/fonts.conf)).

## `roundtrip_nvim.rs` — end-to-end (real Neovim)

Exercises the full input seam against a real, hermetic Neovim (no mocks): `gdk_key` translates GDK keyvals → `InputEvent::Key` → `WolfCore` → nvim, then the snapshot is asserted. It enters insert mode, types `"Hello"` (the leading `H` is fed as the already-uppercased keyval _with_ the SHIFT mask, exercising the shift-glyph contract end-to-end), leaves insert mode with `Escape`, waits for and drains flushes, and asserts row 0 contains the word. Requires `WOLF_NVIM_BIN` (`common::require_nvim_bin` fails loud if unset).

## `smoke_headless.rs` — windowed app + picker + tree + panes + commands (real compositor)

Fourteen `#[test]` cage smokes that prove the whole stack actually draws a window, drives the file picker, populates the file-tree sidebar, creates / focuses / closes native split panes, and dispatches drained commands (the empty state, the accelerators, `:q` and `:qa`). They run in the **default** suite: the compositor and OCR toolchain they need comes from the flake devShell, so a normal `cargo test` run _inside `nix develop`_ does have it, and `require_smoke_env` fails loud if it does not. To run them:

```sh
nix develop --command cargo test -p wolf-gnome --test smoke_headless
```

That target reports **`15 passed`**, not `14`: the file also carries one pure, compositor-free guard, `sidebar_filler_names_cannot_satisfy_any_smoke_assertion` (last bullet below), which does **not** call `require_smoke_env` and needs none of the toolchain.

**Serialization (`CAGE_LOCK`).** Each smoke launches its own `cage` compositor, and two compositors started concurrently contend for the same Wayland socket under `XDG_RUNTIME_DIR` (lockfile error), which would fail both under the default parallel harness. So all fourteen smokes acquire a shared `static CAGE_LOCK: Mutex<()>` for their whole body, forcing serial execution; poisoning is recovered from (`into_inner`) so one panicking test does not cascade into the others. This serialization is why the smokes are the slowest part of the suite.

**Mechanism (common to all fourteen).** Each locates the built binary via `CARGO_BIN_EXE_wolf-gnome` and runs its interactive scenario as one `sh -c` string **inside `cage`** (the headless wlroots compositor) so that `wtype` and `grim` inherit cage's `WAYLAND_DISPLAY` (cage exports it only to its child process tree). The scenario launches the app in the background, polls (not a fixed sleep) until the window maps, drives it via `wtype`, captures the live window with `grim` to a PNG under `XDG_RUNTIME_DIR`, then OCRs it on the host with `tesseract … stdout --psm 11` ("sparse text" mode — the default page-segmentation mode returns empty on the sparse light-on-dark editor grid). The app is launched with `WOLF_FONT_PT=28` so glyphs are large enough to OCR, and a stale screenshot is removed first so a previous run cannot make a test pass. The one exception is `colon_qa_closes_the_window_under_cage`, which captures no image at all: its assertion is a property of the process table, so it calls neither `grim` nor `tesseract`.

**Every one of the fourteen launches in a FRESH temp working directory** (`make_temp_cwd()`, passed to the `cage` command as its `current_dir`), not in the repo. That isolation is mandatory, not tidiness. The app derives `CoreConfig.cwd` from `std::env::current_dir()`, and the captive Neovim keeps a **durable, per-project swap directory keyed on that cwd** (`wolf_core::state::swap_dir_for` → `state_dir()/swap/<hash of cwd>`), which deliberately outlives the process so a fresh nvim can recover a crashed one's unsaved edits. Every scenario ends by `kill`ing the app, so its nvim never cleans up. At a **fixed** cwd those two facts compose into a self-poisoning test: run _N_ leaves a stale `%…%Untitled.md.swp` behind and run _N+1_ finds it at startup, where naming the startup buffer `<cwd>/Untitled.md` collides with it inside `nvim_buf_set_name` and raises a blocking ATTENTION dialog that eats the first keystroke — so the smoke goes red for whatever change happens to be in flight, and points at the wrong cause. A fresh cwd makes each run idempotent. (The product-level guard for that swap collision is deliberate, headless and lives in [`crates/wolf-core/tests/swap_recovery.rs`](../../wolf-core/tests/swap_recovery.rs), `stale_untitled_swap_does_not_block_a_fresh_start`.) A side benefit: the app no longer traverses the entire repository through `FileSearch` on launch, and no longer writes into the working tree. That last point has one deliberate exception, `window_renders_typed_text_under_cage`, which writes nine tiny marker `.md` files into its own temp cwd purely so the tree sidebar has rows of text to draw — the repo listing used to supply that page density accidentally, and OCR has always depended on it (see that test's bullet below for the measurement). The temp dirs are **not** auto-deleted, to aid post-mortem inspection; each run therefore also leaves one new `state_dir()/swap/<hash>/` holding at most one `.swp`, which is harmless because no future run resolves to that hash.

- **`window_renders_typed_text_under_cage`** — types `ihello` (insert mode + the word) and `Escape`, then moves the cursor off row 0 (a normal-mode `o` + `Escape` parks the block cursor on an empty row 1 so it does not OCR-distort the asserted word), and asserts the OCR loosely `contains("hello")`. Before launching, and unlike every other smoke, it writes `SIDEBAR_FILLER_COUNT` (nine) tiny marker `.md` files (`SIDEBAR_FILLER_FILES`) into its temp cwd. Those are **fixture, not assertion** — nothing in the test looks at them — and they exist because `tesseract` classifies a word by the whole page, not just its own pixels: on an otherwise-empty page the isolated leading `h` is read as the ligature `ﬁ`, so the OCR comes back `ﬁello` even though the editor drew `hello` correctly (confirmed pixel by pixel, and reproduced by cropping a _passing_ repo-cwd screenshot down to the editor region). The measured floor on this host is 5 files; 3 and fewer fail, so nine leaves margin. The other OCR-asserting smokes get the same density incidentally from the fixture files their scenarios drop (the two that drop none — the empty state, whose sidebar is hidden entirely, and `:qa`, which captures no image — need none), and before the temp cwd landed this test got it accidentally from the ~35-entry repo listing — the fillers make a dependency the assertion always had explicit and deliberate. If it ever regresses, add filler files; do not touch the assertion. Their names are also kept clear of every smoke's OCR constant, so a sidebar row can never satisfy an assertion on its own — enforced mechanically by `sidebar_filler_names_cannot_satisfy_any_smoke_assertion` (last bullet), not by comment. Its failure message is worth reading in full before diagnosing: an OCR miss where the window, sidebar, tildes and cursor all drew but row 0 is empty and the cursor sits two rows down means the leading `i` was consumed by the swap modal above, not that rendering failed.
- **`picker_opens_and_loads_selected_file_under_cage`** — drops a `ptarget.md` fixture (heading `# PICKERTARGET`) into a fresh temp dir launched as the app's working directory; opens the picker with **Ctrl+Shift+O** (`wtype -M ctrl -M shift -k o -m shift -m ctrl`), types the query `ptarget`, presses `Return`, and asserts the OCR contains `pickertarget` — proving the picker opened, matched, selected, and nvim `:e`'d the file. The filename and the asserted word are deliberately different; see [Fixture naming](#fixture-naming-a-smokes-own-files-can-disarm-its-assertion) below.
- **`picker_arrow_navigation_selects_second_match_under_cage`** — drops two matching files (`pick1.md` → row 0, `pick2.md` → row 1 by the rank tiebreaks, neither in the MRU) into the temp cwd; opens the picker with **Ctrl+Shift+O**, types `pick`, presses `Down` once to move the **list** selection to row 1, then `Return`, and asserts the OCR contains `picktwo` (row 1's heading) and does NOT contain `pickone` (row 0's) — proving `Down` moved the selection off the top row and `Enter` opened the selected row.
- **`tree_sidebar_shows_files_under_cage`** — drops a distinctively-named `treenode.md` into a fresh temp cwd launched as the app's working directory, then (with **no keyboard interaction**) waits an extra settle for the long-lived `FileSearch` to stream the cwd listing into the sidebar, screenshots, and asserts the OCR contains `treenode` — proving the tree **populated** from the same FileSearch mechanism as the picker (`children_of` projection + the `ListView` drew the row). It verifies population only; single-click-open and the highlight/reveal of the current file are covered by the S1 `current_file` core tests and the `tree.rs` / `rel_path_for` pure unit tests (OCR cannot reliably confirm a highlight color, and pixel-accurate row clicking is deliberately avoided as too flaky).
- **`vertical_split_shows_two_panes_under_cage`** — drops two files (`pleft.md` → `# PANELEFT`, `pright.md` → `# PANERIGHT`) into a fresh temp cwd, opens file A, fires `<C-w>v` and `:e`s file B into the new pane, and asserts the OCR contains BOTH headings at once — proving the vertical split created a second pane bound to the new nvim window/grid and painted it beside the first (and that the first pane kept rendering, the `Grid::resize` content-preserving regression guard). The filenames are deliberately unlike the asserted `paneleft` / `paneright`; see [Fixture naming](#fixture-naming-a-smokes-own-files-can-disarm-its-assertion) below.
- **`horizontal_split_shows_two_panes_under_cage`** — the same, with `<C-w>s`, so the two files render stacked top/bottom.
- **`three_panes_keep_all_files_visible_under_cage`** — the N-ary flatten regression guard: opens file A, `<C-w>v` + `:e` file B (a side-by-side `A | B`), focuses the left pane (`<C-w>h`), then `<C-w>v` + `:e` file C in it, producing a flat row of THREE equal columns. It asserts the OCR contains ALL THREE headings at once — the load-bearing assertion being the pre-existing RIGHT pane (B), which the old binary always-nest model collapsed/blanked when a same-orientation third split nested into 25/25/50 instead of flattening into equal thirds.
- **`focus_move_returns_to_first_pane_under_cage`** — vsplits (A left, B right), inserts a marker, then `<C-w>h` back to the left pane and inserts again; asserts the OCR contains the marker AND both headings (so the focus-move plumbing reached a focused pane and the split survived). It proves the plumbing end to end but does NOT pixel-verify which pane got the marker — the pure `layout::neighbor` unit tests cover neighbour selection.
- **`close_pane_leaves_one_under_cage`** — vsplits (a survivor file `ckeep.md` + a to-close file `cgone.md`), `<C-w>c` on the focused pane, and asserts the OCR contains the survivor's heading but NOT the closed pane's — proving `<C-w>c` removed the focused pane and the survivor reclaimed the width.
- **`empty_state_shows_open_folder_button_under_cage`** — launches in a fresh temp cwd with **no** fixture files and with `HOME` set to that same directory, which fires `workspace::launch_decision`'s `cwd == home` branch using the production rule and no test-only env var (and keeps `state_dir` / the MRU sqlite / the swap dir inside the temp dir too). No keyboard interaction: it settles and screenshots, then asserts the OCR contains `folder`. The word renders three times (status-page title, description, button), which is the OCR-robustness margin — and unlike the sparse light-on-dark editor grid the status page is large, theme-font and dark-on-light. Its failure message separates the three plausible causes: the launch decision returned `Folder`, the overlay was built but never shown, or it was shown but is transparent/behind the editor `DrawingArea`. The `gtk::FileDialog` the button opens is deliberately **not** driven; see [Deliberate test gaps](#deliberate-test-gaps) below.
- **`new_untitled_buffer_replaces_open_file_under_cage`** — the accelerator → action → direct-dispatch path (no round trip through the core's command queue): opens `nbase.md` (heading `# NEWBUFBASE`), fires **Ctrl+Shift+N**, types the marker `ZZFRESH` into the fresh buffer, parks the cursor off the marker's row, and asserts the OCR contains `zzfresh` but NOT `newbufbase`. The base file's name deliberately differs from its heading word so nvim's `:e` toast (`"nbase.md" 1L, …`) cannot satisfy the must-NOT-contain assertion.
- **`colon_q_closes_focused_pane_under_cage`** — the `:q` half of the `:q` / `:qa` remapping, exercised on the nvim side and observed by `pane_view::detect_closes`. It mirrors the `<C-w>c` smoke step for step (`qkeep.md` → `# QUITKEEP` survives, `qgone.md` → `# QUITGONE` is closed) but replaces the chord with `:q<CR>`, and asserts `quitkeep` is present and `quitgone` is not.
- **`colon_qa_closes_the_window_under_cage`** — the load-bearing end-to-end proof of the whole command drain: `:qa` → `init.lua`'s `do_quit` fires `wolf_command "close_window"` → `redraw.rs` queues it **and** fires the wake → `AppShell::on_render_wake` drains → `UiAction::CloseWindow` → `window.close()` → `wire_close` → a clean `WolfCore::shutdown`. It captures **no PNG** and calls neither `grim` nor `tesseract`: its assertion is that the app is gone AND that it went cleanly, which is a property of the process table and an exit status, not of any pixel — so it POLLS `kill -0 "$app_pid"` rather than sleeping and hoping, then `wait`s on the app to collect its status. Scenario exit codes: `0` the app exited cleanly; `11` it died before the window mapped; `12` it was still alive after the poll budget — i.e. the drained `close_window` never reached `window.close()`; `13` it did exit, but with a NON-ZERO status — the window closed, so the drain worked, but the teardown behind it (`wire_close` → picker/tree close → `WolfCore::shutdown` → nvim exit) failed or panicked. `13` is the code that distinguishes "closed" from "closed **cleanly**", which is why it is worth a distinct exit rather than being folded into `12`. It contributes no `ASSERTED_OCR_TERMS` rows.
- **`close_pane_chord_closes_focused_pane_under_cage`** — the same shape as `colon_q_closes_focused_pane_under_cage` (`wkeep.md` → `# CHORDKEEP` survives, `wgone.md` → `# CHORDGONE` goes) but closes the focused pane with the **Ctrl+Shift+W accelerator**. It exists because the `:q` smoke exercises only the nvim-side path, leaving `UiAction::ClosePane` — the action → `InputEvent::ClosePane` half — with no end-to-end coverage.
- **`sidebar_filler_names_cannot_satisfy_any_smoke_assertion`** — the one test in this file that is **not** a cage smoke. It is pure: no compositor, no `require_smoke_env`, no `CAGE_LOCK`, no subprocess, microseconds to run, so it still guards the fixture on a machine without the smoke toolchain. It reads two const tables and asserts that no `SIDEBAR_FILLER_FILES` name contains any term in `ASSERTED_OCR_TERMS` — the table of every substring the smokes assert OCR must or must not contain, built from the OCR consts themselves rather than re-typed literals so it cannot drift. Thirteen of the fourteen smokes appear there; `colon_qa_closes_the_window_under_cage` contributes none, since it captures no image. The terms are `hello`, `pickertarget`, `picktwo` / `pickone`, `treenode`, `paneleft` / `paneright`, `htopfile` / `hbotfile`, `focusone` / `focustwo` / `zzleft`, `closekeep` / `closegone`, `triaone` / `tribtwo` / `tricthree`, and — added with the command-drain unit — `folder`, `zzfresh`, `newbufbase`, `quitkeep`, `quitgone`, `chordkeep` and `chordgone`. The must-NOT-contain terms are listed deliberately: a filler row carrying one would make its smoke fail SPURIOUSLY rather than pass vacuously — the opposite symptom, but the same fixture bug. Were a filler ever named `fillhello.md`, the sidebar would render `hello` on a row of its own, `window_renders_typed_text_under_cage`'s assertion would be satisfied by that row, and the smoke would pass green forever with an editor pane that drew nothing — the silent false positive `CLAUDE.md` warns about, and one that is invisible in review because the fixture and the assertion it can defeat sit a thousand lines apart. It also pins that every asserted term is lowercase (OCR output is lowercased before every `contains`, so an uppercase const could never match, which would make the filename check vacuous too) and that the filler names are distinct (duplicates collapse on disk and would silently thin the page density). A fixture that can disarm the assertion it exists to support needs an executable guard, not prose.

Required toolchain + env for the **fourteen cage smokes** (all from the flake devShell smoke toolchain, and now **gate-required** rather than optional): `cage`, `wtype`, `grim`, `tesseract` on `PATH`; `WOLF_NVIM_BIN` set; and a set, writable `XDG_RUNTIME_DIR`. Per project policy `require_smoke_env` **fails loud** (not a silent skip) on any missing precondition, since absence means the smoke toolchain was not provisioned. A stale screenshot is removed first so a previous run cannot make the test pass. The fifteenth test needs none of this.

**NOTE:** the smoke test asserts only the typed `hello`, not the cursor; cursor geometry and color are covered by the pure `cursor.rs` unit tests above plus visual confirmation (OCR is too fragile to couple to the cursor).

### Fixture naming: a smoke's own files can disarm its assertion

**The rule, and it is a convention rather than a changelog entry: when a smoke asserts on a file's CONTENT, that file's NAME must not contain the asserted word.**

The file-tree sidebar renders every file in the cwd by name, and nvim's `:e` toast echoes the filename too. So a fixture whose name contains the smoke's own OCR term satisfies the assertion whether or not the feature under test did anything — a permanent silent false positive, not a flake.

Two pre-existing smokes were passing exactly that way and are now fixed:

- **`picker_opens_and_loads_selected_file_under_cage`** shipped a `pickertarget.md` fixture against the asserted `pickertarget`. That is not a theory: during the command-drain unit's broken-accelerator run — GTK's keymap-aware accel matching never fired under `wtype`, so Ctrl+Shift+O was forwarded to Neovim instead of opening the picker — this smoke **passed green while the picker demonstrably never opened**. Fixed by renaming the fixture to `ptarget.md` (and the query to `ptarget`); the heading `# PICKERTARGET` and the asserted term are unchanged, so the word now lives ONLY in the buffer and only a rendered buffer can satisfy the assertion.
- **`vertical_split_shows_two_panes_under_cage`** shipped `paneleft.md` / `paneright.md` against `paneleft` / `paneright`, so BOTH assertions were satisfiable by sidebar rows alone: the smoke would have passed green if `<C-w>v` had never split anything. Fixed by the same rename shape (`pleft.md` / `pright.md`), terms unchanged.

Both changes **strengthen** the tests; nothing was weakened, no assertion or OCR const moved. `picker_arrow_navigation_selects_second_match_under_cage` was checked and does not share the defect (`pick1.md` / `pick2.md` against `picktwo` / `pickone` — it failed correctly during the broken run), and every other smoke was audited and is clean.

The **one deliberate exception** is `tree_sidebar_shows_files_under_cage`, where `treenode.md` carries the asserted `treenode` on purpose: there the sidebar row IS the feature under test. That exception is also why `sidebar_filler_names_cannot_satisfy_any_smoke_assertion` cannot simply be widened to cover fixture names — generalizing it would need an explicit opt-out list. The guard therefore covers the FILLER filenames only, and this rule covers the rest by convention; the gap is recorded in the guard's own doc comment.

### Deliberate test gaps

Three things this unit's behaviour deliberately does **not** smoke, with what covers them instead:

- **The primary menu popover is not smoked.** `wtype` cannot click the header-bar `MenuButton`, and keyboard-navigating to it is too fragile to be worth the flake. It is covered by the pure `actions.rs` menu tests (every item references a declared, implemented, non-Reserved action; every label matches the registry title) plus the fact that three of its seven items' actions are proven end-to-end by the accelerator and `:qa` smokes.
- **The `gtk::FileDialog`s (Open Folder… / Open File…) are not smoked.** There is no portal backend under `cage`, so the dialog cannot be driven at all. Their callback bodies are trivial; the empty state's _presentation_ is smoked.
- **The sidebar re-root after Open Folder is not smoked** (same reason). `workspace::reroot_ready` is unit-tested, and `TreeHandle::reroot` reuses the already-smoked `FileSearch` refresh path.

## The `key_from_char` helper

`gdk_key.rs`, `roundtrip_nvim.rs` and `src/actions.rs`'s `mod tests` each define a small `key_from_char(c: char) -> gdk::Key` helper, because gdk4-rs has no `Key::from_unicode`. It builds the keyval exactly as GDK would from a Unicode scalar:

```rust
use gdk::glib::translate::from_glib;
fn key_from_char(c: char) -> gdk::Key { unsafe { from_glib(gdk::unicode_to_keyval(c as u32)) } }
```

This is test-side only and does not change `gdk_key`'s contract: printables still carry the exact glyph, and `gdk_key` reads `keyval.to_unicode()` and sets `shift: false` for `Key::Char`.
