# wolf-ffi/src

The `wolf-ffi` source. Two files: `lib.rs` (the swift-bridge module + the hand-written Rust glue behind it) and `bin/gen_bindings.rs` (the committed-binding codegen). See the crate [`README.md`](../README.md) for the surface overview and the build/regen workflow.

## `lib.rs`

The crate root: the single `#[swift_bridge::bridge] mod ffi` plus the glue that backs it. swift-bridge is confined here, so `wolf-core` stays GUI-free and gains no new dependency.

- **The bridge module (`mod ffi`).** Declares the transparent structs `FfiColor` (`{ rgb: u32, set: bool }` — a packed `0x00RRGGBB` plus an "is set" flag), `FfiKeyEvent` (`{ kind, ch, fnum, ctrl, shift, alt, meta }`, Swift fills it from an `NSEvent`), `FfiMouseEvent` (`{ button, action, grid, row, col, ctrl, shift, alt }`), and `FfiScrollEvent` (`{ direction, grid, row, col }`), and the opaque `extern "Rust"` types `WolfCoreHandle`, `FfiFrame`, `FfiCell`, `FfiFileSearch`, `FfiFileEntry`, `FfiTreeNode`, `FfiLayoutIntent`, `FfiCommand`, `FfiCommandPalette`, `FfiCommandRow`, `FfiWinInfo`, `FfiState`, and `FfiWindowState` with their methods. `FfiColor` / `FfiKeyEvent` / `FfiMouseEvent` / `FfiScrollEvent` are re-exported at the crate root (`pub use ffi::{FfiColor, FfiKeyEvent, FfiMouseEvent, FfiScrollEvent}`) so the rlib integration tests can name them. A scoped `#[allow(clippy::all, missing_docs, unused)]` keeps the macro expansion off this crate's stricter lint bar (with a crate-level `#![allow(clippy::unnecessary_cast)]` for the same-type pointer casts the expansion emits in sibling code).

- **`WolfCoreHandle`** — the opaque, **main-thread-only** handle wrapping a `RefCell<Option<WolfCore>>` (`WolfCore` is not `Send`). Methods: `read_frame` (reads the snapshot and packs the ACTIVE grid into an `FfiFrame`), `read_frame_for_grid` (packs a SPECIFIC grid — used per pane plus grid 1 for the cmdline strip; an absent grid yields an empty `0x0` frame), `send_key` (maps the event and forwards it), `resize`, `resize_grid` (per-pane window-grid resize; nvim echoes the authoritative size back), `drain_intents` (drains the layout-intent queue, each mapped through `FfiLayoutIntent::from_intent`; empty `Vec` when the core is gone), `windows` (maps `snapshot.windows.values()` through `FfiWinInfo::from_win_info` — ALL windows, the Swift side filters), `grid_for_win` (`snapshot.grid_for_win(win).unwrap_or(0)`), `active_win` (`snapshot.active_win.unwrap_or(0)`), `focus_win` (`core.focus_win(win)`), `send_mouse` / `send_scroll` (map the transparent `FfiMouseEvent` / `FfiScrollEvent` through `mouse_event_from_ffi` / `scroll_event_from_ffi` — each returning `None`, and dropping the event, on a bad discriminant — then call `WolfCore::send_mouse` / `send_scroll`, so mouse/scroll target the pane's window grid with grid-local row/col), `start_file_search` (starts a `FileSearch` session — wired to the picker wake — and wraps it as an `FfiFileSearch`), `open` (issues `InputEvent::Open { path }`; the MRU is recorded by core's input pump), `recent_dirs` (the GLOBAL recent-directories MRU newest-first — capped at 20 — delegating to `WolfCore::recent_dirs()` and mapping each `PathBuf` via `to_string_lossy().into_owned()`; an empty `Vec` when the store is disabled/unreadable or the core is gone; the `Vec<String>` crosses the bridge as `RustVec<RustString>`, and it drives the File > Open Recent submenu), `wake_token` (the per-window `u64` wake-routing identity minted at start — see "The wake" below), the state setters `state_set_geometry` / `state_set_sidebar_visible` / `state_set_toolbar_mode` (each records THIS window's facet into the handle's live `StateStore` at the handle's fixed `window_index`; `state_set_toolbar_mode(mode, set)` decodes `mode` through the `toolbar_mode` discriminant module — `set == false` clears to `None`, an unrecognized discriminant is a logged no-op; all no-ops when no store is attached), `state_set_window_count(count)` (truncates the persisted `windows` list to `count` — the terminate-time ghost-slot cleanup, a no-op when no store is attached), plus `state_flush` (blocks up to `STATE_FLUSH_TIMEOUT` ≈ 2 s; `true` when no store exists), and `shutdown` (flushes the state store bounded by the same timeout, then takes the core out via `.take()` so a second call is a no-op, then `WolfCore::shutdown`; any error is logged, not returned — the bridge is infallible). The handle carries `store: Option<StateStore>`, `window_index: usize`, and `wake_token: u64` beside the core. `wolf_ffi_start(init_lua, cwd, cols, rows, window_index)` builds a `CoreConfig` (the two strings are filesystem **paths**), mints a fresh `wake_token` from the process-global `NEXT_WAKE_TOKEN` counter and wires a token-carrying wake, calls `WolfCore::start`, and returns `Option<WolfCoreHandle>` (`None` after logging on error); after a successful start it clones the **process-wide** `StateStore` (opened once, lazily, over `wolf_core::state_dir()` in the `SHARED_STORE` `OnceLock` — all windows share one store, since opening the same `state.json` dir twice would race the per-store writer threads), attaches it via `core.attach_state_store(store, window_index)` (so cwd changes persist core-side at this window's slot), and stashes the store + index + token in the handle (an unresolvable dir logs and disables persistence, never fatal).

- **`FfiFrame` + `FfiCell`** — the opaque per-frame snapshot of a single grid. `FfiFrame::from_snapshot_grid(&wolf_core::Snapshot, grid_id)` (public, so the headless `frame_pack` test can drive it without a live `WolfCore`) resolves that grid's cells against the snapshot's `HighlightTable` **in Rust** — reusing `HighlightTable::resolve` / `ResolvedStyle`, never re-resolving in Swift — into a flat row-major `Vec<FfiCell>`, computes the cursor's reverse-video fill/glyph colors (`cursor_colors`, ported from wolf-gnome's `cursor.rs`) against the REQUESTED grid's cell under the cursor, and sets `cursor_visible = (cursor.grid == grid_id)` (per-grid) plus the `grid_id` / `cursor_grid` fields. An absent grid yields `FfiFrame::empty()` (`cols()` / `rows()` 0 — "grid gone"). `FfiFrame::from_snapshot(snap)` delegates to `from_snapshot_grid(snap, snap.active_grid_id())`, so `read_frame` keeps its active-grid behavior. `from_snapshot_grid` also reads the requested grid's `viewport` (`snapshot.windows.get(&grid_id).map(|w| w.viewport).unwrap_or_default()`) into the frame's `topline` / `botline` / `curline` / `linecount` fields (all 0-based, as nvim's `win_viewport` reports; `botline` is one-past-the-last-visible line), defaulting to all-zero when the grid has no associated window. Scalar accessors expose the dims, cursor position/shape/percentage, `cursor_visible`, `grid_id`, `cursor_grid`, the default + cursor colors, and the four viewport accessors (`topline` / `botline` / `curline` / `linecount`) that drive the synthetic scrollbar. `FfiCell` is opaque (swift-bridge does not emit `Vec` support for transparent structs) with `text()` / `fg()` / `bg()` / `special()` (the resolved special / underline color, mirroring `fg()` / `bg()`) / `flags()`; its `text` field is `pub` so the Rust tests read it directly.

- **`FfiLayoutIntent` + `FfiWinInfo`** — the opaque split-pane projections (opaque so a `Vec<T>` is supported, like `FfiCell` / `FfiTreeNode`). `FfiLayoutIntent::from_intent` flattens `wolf_core::LayoutIntent`'s two variants into a tagged `{ kind, orientation, dir, from, win }` struct (a SPLIT carries `orientation` + `from` + `win`; a FOCUS_DIR carries `dir` + `from`, the unused scalars zeroed), packing discriminants from the `intent_kind` / `orientation` / `focus_dir` modules; accessors `kind()` / `orientation()` / `dir()` / `from()` / `win()`. `FfiWinInfo::from_win_info` projects a `wolf_core::WinInfo`'s pane-relevant `{ grid, win, hidden }`; accessors `grid()` / `win()` / `hidden()`.

- **`FfiState` + `FfiWindowState`** — the saved-application-state restore surface (opaque, like the other Vec-carried types). The free `wolf_ffi_load_state()` is the PRE-START restore read: it delegates to `wolf_core::state_dir().and_then(load_state)` — never creating/modifying the file and never opening the live store — and yields an `FfiState` whose `windows()` is empty on an absent/corrupt file or an unresolvable dir (infallible across the bridge, parallel to `wolf_ffi_load_config`). `FfiWindowState::from_window` flattens a `wolf_core::WindowState`, turning the `Option<ToolbarMode>` into the `{value, set}` accessor pair `toolbar_mode()` / `toolbar_mode_set()` via the `toolbar_mode` discriminants (the `FfiColor` precedent); scalar accessors expose `x` / `y` / `width` / `height` / `cwd` / `sidebar_visible`.

- **`FfiFileSearch` + `FfiFileEntry`** — the picker surface. `FfiFileSearch` wraps core's `FileSearch` session in an `Option` (so `start_file_search` stays infallible across the bridge; `None` yields no entries, mirroring `read_frame`'s empty-frame fallback). `ranked(query, max)` reads the session's results snapshot, runs `wolf_core::rank_matches_top_n(&query, &entries, max)` **in Rust** (the BOUNDED top-N variant — it selects the top `max` via an `O(M log max)` heap instead of sorting the whole match set, then clones only the survivors), and clones the matched entries into a `Vec<FfiFileEntry>` (the read guard is held only for that scope). `FfiFileEntry { path: PathBuf, display: String }` exposes `display()` / `path()` (path via `to_string_lossy().into_owned()`); both are opaque because swift-bridge only emits `Vec<T>` for opaque `T` — the same reason `FfiCell` is opaque.

- **`FfiCommand`** — one drained user-triggered command (opaque so a `Vec<FfiCommand>` is supported). `WolfCoreHandle::drain_commands()` drains core's command queue (`:Wolf<Pascal>` Ex-commands / `require('wolf')` Lua calls) and maps each through `FfiCommand::from_command`, an EXHAUSTIVE match over `wolf_core::Command` packing the `command_kind` discriminant (a future variant add/reorder is a compile error). Accessor `kind() -> u8`.

- **`FfiCommandPalette` + `FfiCommandRow`** — the command-palette session surface (opaque; `FfiCommandRow` opaque so a `Vec` is supported). `WolfCoreHandle::command_palette()` builds a session seeded with `core.recent_dirs()` + `core.command_mru()` (empty-backed — no recent dirs, a disabled MRU — when the core is gone, mirroring `start_file_search`). `FfiCommandPalette { recent_dirs: Vec<PathBuf>, windows: RefCell<Vec<PaletteWindow>>, command_mru: CommandMru }` is a **main-thread-only** handle (the `RefCell` gives interior mutability for `add_window` behind the bridge's `&self`): `add_window(index: u16, cwd: String)` pushes one OTHER open window (the current window is excluded by the caller); `ranked(query: String, max: usize) -> Vec<FfiCommandRow>` clones the window vec out of the `RefCell` then delegates to `wolf_core::rank_palette(&recent_dirs, &windows, &command_mru.recent(), &query, max)` — assembling the static commands (minus `CommandPalette`) + windows + recent dirs, ranked MRU-first — and maps each `PaletteRow` through `FfiCommandRow::from_row`; `record(key: String)` writes the row's `mru_key` into the global `command-mru.sqlite`. `FfiCommandRow` flattens a `PaletteRow` into `{ display, row_kind, command_kind, window_index, path, mru_key }` with matching accessors: `row_kind()` uses the `palette_row_kind` discriminants; `command_kind()` reuses `FfiCommand::from_command`'s mapping for a `Static` row (0 for dynamic rows); `path()` is the recent-folder path for an `OpenRecent` row (`""` otherwise); `window_index()` the raise target for a `SwitchWindow` row (0 otherwise). There is NO wake: candidates are fixed at open and `ranked()` re-filters synchronously per keystroke.

- **The wake (Swift-free, multi-window routed).** `#[no_mangle] pub extern "C" fn wolf_ffi_set_wake` registers (or clears) the front-end wake callback in a global `AtomicPtr`; the callback ABI is `extern "C" fn(uint64_t token)`. `registered_wake(token)` builds the `WakeFn` core fires on flush, which loads and calls the registered pointer passing THIS core's per-window `wake_token` (a no-op if none is registered). Declared via a hand-written C header (`generated/wolf_ffi_wake.h`) rather than an `extern "Swift"` symbol, so the rlib links with no Swift present. The token (minted in `wolf_ffi_start` from `NEXT_WAKE_TOKEN`) is a plain `Send` scalar the closure captures — it touches no `WolfCore` state — so ONE process-global callback per channel routes each wake to the right window (the front-end looks the token up in its `WindowRegistry`) without two windows clobbering each other. A **second**, parallel registration — `wolf_ffi_set_filesearch_wake` with its own `registered_filesearch_wake(token)` and `AtomicPtr` — backs the file picker (a `start_file_search` session fires it after each streaming traversal batch, so the picker refreshes independently of editor repaints), and a **third** — `wolf_ffi_set_tree_wake` / `registered_tree_wake(token)` — backs the file-tree sidebar's `start_tree_search` session. All three are identical in shape — token-carrying, no-op when unregistered — and declared in `generated/wolf_ffi_wake.h`.

- **Helpers.** `key_event_from_ffi` maps an `FfiKeyEvent` into a `wolf_core::KeyEvent` (the `kind` discriminants — `mod kind`, `CHAR = 0` … `F = 14` — mirror `wolf_core::Key`'s variant order and are the single source of truth shared with the Swift `WolfKeyMap` and the test suites); `mouse_event_from_ffi` / `scroll_event_from_ffi` map an `FfiMouseEvent` / `FfiScrollEvent` into a `wolf_core::MouseEvent` / `ScrollEvent`, matching the `button`/`action`/`direction` discriminants onto the core enums and returning `None` on any unknown value (the caller drops the event); `pack_flags` packs the style bitset (`mod flag`); `pack_cursor_shape` maps `CursorShape` to its `u8` (`mod cursor_shape`); `FfiColor::from_rgb` / `from_opt` do the `0x00RRGGBB` packing (with `FALLBACK_FG` white / `FALLBACK_BG` black mirroring wolf-gnome's `render`).

- **Discriminant modules.** Three more discriminant modules sit beside `mod kind` and are the single source of truth shared with the Swift `PaneTree` port (`Orientation.init?(ffi:)` / `FocusDir.init?(ffi:)`) and the `WolfKeyMapTests` / `tests/panes.rs` discriminant contracts: `mod intent_kind` (`SPLIT = 0`, `FOCUS_DIR = 1`), `mod orientation` (`HORIZONTAL = 0`, `VERTICAL = 1` — `wolf_core::SplitOrientation` order), and `mod focus_dir` (`LEFT = 0`, `RIGHT = 1`, `UP = 2`, `DOWN = 3` — `wolf_core::FocusDir` order). `FfiLayoutIntent::from_intent` reads from them. Three more sit beside them for the mouse/scroll surface — `mod mouse_button` (`LEFT = 0`, `RIGHT = 1`, `MIDDLE = 2` — `wolf_core::MouseButton` order), `mod mouse_action` (`PRESS = 0`, `RELEASE = 1`, `DRAG = 2` — `wolf_core::MouseAction` order), and `mod scroll_dir` (`UP = 0`, `DOWN = 1`, `LEFT = 2`, `RIGHT = 3` — `wolf_core::ScrollDirection` order); `mouse_event_from_ffi` / `scroll_event_from_ffi` read from them, and they are the single source of truth shared with the Swift `PaneContainerView` consts and the `tests/mouse_scroll.rs` local consts. One more backs the state surface: `mod toolbar_mode` (`ICON_AND_TEXT = 0`, `ICON_ONLY = 1`, `TEXT_ONLY = 2` — `wolf_core::ToolbarMode` order), read by `state_set_toolbar_mode` and `FfiWindowState::from_window`, and the single source of truth shared with the Swift `StateSeam.ToolbarMode` raw values and the `tests/state.rs` local consts. Two more back the command surface: `mod command_kind` (`NEW_WINDOW = 0` … `DECREASE_FONT_SIZE = 12`, `COMMAND_PALETTE = 13` — `wolf_core::Command` order), read by `FfiCommand::from_command` and shared with the Swift `CommandKind` port and the `tests/commands.rs` / `tests/command_palette.rs` contract guards; and `mod palette_row_kind` (`STATIC = 0`, `SWITCH_WINDOW = 1`, `OPEN_RECENT = 2` — `wolf_core::PaletteRowKind` order), read by `FfiCommandRow::from_row` and shared with the Swift `PaletteSeam.PaletteRowKind` port.

## `bin/gen_bindings.rs`

The standalone codegen binary (`//crates/wolf-ffi:gen_bindings`, run via `bazel run`). It invokes `swift-bridge-build`'s parser over `lib.rs` and writes the Swift

- C output into `$BUILD_WORKSPACE_DIRECTORY/crates/wolf-ffi/generated/`, prepending the `import WolfFFI` line the Swift glue needs. It writes **in-tree** (only `bazel run` sets `BUILD_WORKSPACE_DIRECTORY` and may write into the source tree — a genrule cannot), so the generated files stay **committed** and are refreshed explicitly after a bridge change.
