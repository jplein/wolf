# wolf-ffi/src

The `wolf-ffi` source. Two files: `lib.rs` (the swift-bridge module + the hand-written Rust glue behind it) and `bin/gen_bindings.rs` (the committed-binding codegen). See the crate [`README.md`](../README.md) for the surface overview and the build/regen workflow.

## `lib.rs`

The crate root: the single `#[swift_bridge::bridge] mod ffi` plus the glue that backs it. swift-bridge is confined here, so `wolf-core` stays GUI-free and gains no new dependency.

- **The bridge module (`mod ffi`).** Declares the transparent structs `FfiColor` (`{ rgb: u32, set: bool }` — a packed `0x00RRGGBB` plus an "is set" flag) and `FfiKeyEvent` (`{ kind, ch, fnum, ctrl, shift, alt, meta }`, Swift fills it from an `NSEvent`), and the opaque `extern "Rust"` types `WolfCoreHandle`, `FfiFrame`, `FfiCell`, `FfiFileSearch`, `FfiFileEntry`, `FfiTreeNode`, `FfiLayoutIntent`, and `FfiWinInfo` with their methods. `FfiColor` / `FfiKeyEvent` are re-exported at the crate root (`pub use ffi::{FfiColor, FfiKeyEvent}`) so the rlib integration tests can name them. A scoped `#[allow(clippy::all, missing_docs, unused)]` keeps the macro expansion off this crate's stricter lint bar (with a crate-level `#![allow(clippy::unnecessary_cast)]` for the same-type pointer casts the expansion emits in sibling code).

- **`WolfCoreHandle`** — the opaque, **main-thread-only** handle wrapping a `RefCell<Option<WolfCore>>` (`WolfCore` is not `Send`). Methods: `read_frame` (reads the snapshot and packs the ACTIVE grid into an `FfiFrame`), `read_frame_for_grid` (packs a SPECIFIC grid — used per pane plus grid 1 for the cmdline strip; an absent grid yields an empty `0x0` frame), `send_key` (maps the event and forwards it), `resize`, `resize_grid` (per-pane window-grid resize; nvim echoes the authoritative size back), `drain_intents` (drains the layout-intent queue, each mapped through `FfiLayoutIntent::from_intent`; empty `Vec` when the core is gone), `windows` (maps `snapshot.windows.values()` through `FfiWinInfo::from_win_info` — ALL windows, the Swift side filters), `grid_for_win` (`snapshot.grid_for_win(win).unwrap_or(0)`), `active_win` (`snapshot.active_win.unwrap_or(0)`), `focus_win` (`core.focus_win(win)`), `start_file_search` (starts a `FileSearch` session — wired to the picker wake — and wraps it as an `FfiFileSearch`), `open` (issues `InputEvent::Open { path }`; the MRU is recorded by core's input pump), and `shutdown` (takes the core out via `.take()` so a second call is a no-op, then `WolfCore::shutdown`; any error is logged, not returned — the bridge is infallible). `wolf_ffi_start(init_lua, cwd, cols, rows)` builds a `CoreConfig` (the two strings are filesystem **paths**), wires the wake, calls `WolfCore::start`, and returns `Option<WolfCoreHandle>` (`None` after logging on error).

- **`FfiFrame` + `FfiCell`** — the opaque per-frame snapshot of a single grid. `FfiFrame::from_snapshot_grid(&wolf_core::Snapshot, grid_id)` (public, so the headless `frame_pack` test can drive it without a live `WolfCore`) resolves that grid's cells against the snapshot's `HighlightTable` **in Rust** — reusing `HighlightTable::resolve` / `ResolvedStyle`, never re-resolving in Swift — into a flat row-major `Vec<FfiCell>`, computes the cursor's reverse-video fill/glyph colors (`cursor_colors`, ported from wolf-gnome's `cursor.rs`) against the REQUESTED grid's cell under the cursor, and sets `cursor_visible = (cursor.grid == grid_id)` (per-grid) plus the `grid_id` / `cursor_grid` fields. An absent grid yields `FfiFrame::empty()` (`cols()` / `rows()` 0 — "grid gone"). `FfiFrame::from_snapshot(snap)` delegates to `from_snapshot_grid(snap, snap.active_grid_id())`, so `read_frame` keeps its active-grid behavior. Scalar accessors expose the dims, cursor position/shape/percentage, `cursor_visible`, `grid_id`, `cursor_grid`, and the default + cursor colors. `FfiCell` is opaque (swift-bridge does not emit `Vec` support for transparent structs) with `text()` / `fg()` / `bg()` / `flags()`; its `text` field is `pub` so the Rust tests read it directly.

- **`FfiLayoutIntent` + `FfiWinInfo`** — the opaque split-pane projections (opaque so a `Vec<T>` is supported, like `FfiCell` / `FfiTreeNode`). `FfiLayoutIntent::from_intent` flattens `wolf_core::LayoutIntent`'s two variants into a tagged `{ kind, orientation, dir, from, win }` struct (a SPLIT carries `orientation` + `from` + `win`; a FOCUS_DIR carries `dir` + `from`, the unused scalars zeroed), packing discriminants from the `intent_kind` / `orientation` / `focus_dir` modules; accessors `kind()` / `orientation()` / `dir()` / `from()` / `win()`. `FfiWinInfo::from_win_info` projects a `wolf_core::WinInfo`'s pane-relevant `{ grid, win, hidden }`; accessors `grid()` / `win()` / `hidden()`.

- **`FfiFileSearch` + `FfiFileEntry`** — the picker surface. `FfiFileSearch` wraps core's `FileSearch` session in an `Option` (so `start_file_search` stays infallible across the bridge; `None` yields no entries, mirroring `read_frame`'s empty-frame fallback). `ranked(query, max)` reads the session's results snapshot, runs `wolf_core::rank_matches` **in Rust**, takes the top `max`, and clones the matched entries into a `Vec<FfiFileEntry>` (the read guard is held only for that scope). `FfiFileEntry { path: PathBuf, display: String }` exposes `display()` / `path()` (path via `to_string_lossy().into_owned()`); both are opaque because swift-bridge only emits `Vec<T>` for opaque `T` — the same reason `FfiCell` is opaque.

- **The wake (Swift-free).** `#[no_mangle] pub extern "C" fn wolf_ffi_set_wake` registers (or clears) the front-end wake callback in a global `AtomicPtr`; `registered_wake()` builds the `WakeFn` core fires on flush, which loads and calls the registered pointer (a no-op if none is registered). Declared via a hand-written C header (`generated/wolf_ffi_wake.h`) rather than an `extern "Swift"` symbol, so the rlib links with no Swift present. The callback captures nothing and touches no `WolfCore` state, so it is `Send + Sync` and the only thing that crosses threads. A **second**, parallel registration — `wolf_ffi_set_filesearch_wake` with its own `registered_filesearch_wake` and `AtomicPtr` — backs the file picker: a `start_file_search` session fires it after each streaming traversal batch, so the picker refreshes independently of editor repaints. It is identical in shape to the editor wake (also declared in `generated/wolf_ffi_wake.h`).

- **Helpers.** `key_event_from_ffi` maps an `FfiKeyEvent` into a `wolf_core::KeyEvent` (the `kind` discriminants — `mod kind`, `CHAR = 0` … `F = 14` — mirror `wolf_core::Key`'s variant order and are the single source of truth shared with the Swift `WolfKeyMap` and the test suites); `pack_flags` packs the style bitset (`mod flag`); `pack_cursor_shape` maps `CursorShape` to its `u8` (`mod cursor_shape`); `FfiColor::from_rgb` / `from_opt` do the `0x00RRGGBB` packing (with `FALLBACK_FG` white / `FALLBACK_BG` black mirroring wolf-gnome's `render`).

- **Discriminant modules.** Three more discriminant modules sit beside `mod kind` and are the single source of truth shared with the Swift `PaneTree` port (`Orientation.init?(ffi:)` / `FocusDir.init?(ffi:)`) and the `WolfKeyMapTests` / `tests/panes.rs` discriminant contracts: `mod intent_kind` (`SPLIT = 0`, `FOCUS_DIR = 1`), `mod orientation` (`HORIZONTAL = 0`, `VERTICAL = 1` — `wolf_core::SplitOrientation` order), and `mod focus_dir` (`LEFT = 0`, `RIGHT = 1`, `UP = 2`, `DOWN = 3` — `wolf_core::FocusDir` order). `FfiLayoutIntent::from_intent` reads from them.

## `bin/gen_bindings.rs`

The standalone codegen binary (`//crates/wolf-ffi:gen_bindings`, run via `bazel run`). It invokes `swift-bridge-build`'s parser over `lib.rs` and writes the Swift

- C output into `$BUILD_WORKSPACE_DIRECTORY/crates/wolf-ffi/generated/`, prepending the `import WolfFFI` line the Swift glue needs. It writes **in-tree** (only `bazel run` sets `BUILD_WORKSPACE_DIRECTORY` and may write into the source tree — a genrule cannot), so the generated files stay **committed** and are refreshed explicitly after a bridge change.
