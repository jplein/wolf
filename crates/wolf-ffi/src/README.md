# wolf-ffi/src

The `wolf-ffi` source. Two files: `lib.rs` (the swift-bridge module + the hand-written Rust glue behind it) and `bin/gen_bindings.rs` (the committed-binding codegen). See the crate [`README.md`](../README.md) for the surface overview and the build/regen workflow.

## `lib.rs`

The crate root: the single `#[swift_bridge::bridge] mod ffi` plus the glue that backs it. swift-bridge is confined here, so `wolf-core` stays GUI-free and gains no new dependency.

- **The bridge module (`mod ffi`).** Declares the transparent structs `FfiColor` (`{ rgb: u32, set: bool }` — a packed `0x00RRGGBB` plus an "is set" flag), `FfiKeyEvent` (`{ kind, ch, fnum, ctrl, shift, alt, meta }`, Swift fills it from an `NSEvent`), `FfiMouseEvent` (`{ button, action, grid, row, col, ctrl, shift, alt }`), and `FfiScrollEvent` (`{ direction, grid, row, col }`), and the opaque `extern "Rust"` types `WolfCoreHandle`, `FfiFrame`, `FfiCell`, `FfiFileSearch`, `FfiFileEntry`, `FfiTreeNode`, `FfiLayoutIntent`, `FfiCommand`, `FfiCommandPalette`, `FfiCommandRow`, `FfiBufferPicker`, `FfiBufferRow`, `FfiPreview`, `FfiOpenFiles`, `FfiWinInfo`, `FfiPaneStatus`, `FfiCmdline`, `FfiPum`, `FfiPumItem`, `FfiToast`, `FfiToastLine`, `FfiToastChunk`, `FfiState`, `FfiWindowState`, and `FfiTabState` with their methods, plus the write-side snapshot-builder free functions (`wolf_ffi_state_snapshot_begin` / `add_window` / `add_tab` / `commit` / `wolf_ffi_state_flush`). `FfiColor` / `FfiKeyEvent` / `FfiMouseEvent` / `FfiScrollEvent` are re-exported at the crate root (`pub use ffi::{FfiColor, FfiKeyEvent, FfiMouseEvent, FfiScrollEvent}`) so the rlib integration tests can name them. A scoped `#[allow(clippy::all, missing_docs, unused)]` keeps the macro expansion off this crate's stricter lint bar (with a crate-level `#![allow(clippy::unnecessary_cast)]` for the same-type pointer casts the expansion emits in sibling code).

- **`WolfCoreHandle`** — the opaque, **main-thread-only** handle wrapping a `RefCell<Option<WolfCore>>` (`WolfCore` is not `Send`). Methods: `read_frame` (reads the snapshot and packs the ACTIVE grid into an `FfiFrame`), `read_frame_for_grid` (packs a SPECIFIC grid — used per pane plus grid 1 for the editor default fg/bg the bottom overlays paint against; an absent grid yields an empty `0x0` frame), `send_key` (maps the event and forwards it), `resize`, `resize_grid` (per-pane window-grid resize; nvim echoes the authoritative size back), `drain_intents` (drains the layout-intent queue, each mapped through `FfiLayoutIntent::from_intent`; empty `Vec` when the core is gone), `windows` (maps `snapshot.windows.values()` through `FfiWinInfo::from_win_info` — ALL windows, the Swift side filters), `grid_for_win` (`snapshot.grid_for_win(win).unwrap_or(0)`), `active_win` (`snapshot.active_win.unwrap_or(0)`), `focus_win` (`core.focus_win(win)`), `send_mouse` / `send_scroll` (map the transparent `FfiMouseEvent` / `FfiScrollEvent` through `mouse_event_from_ffi` / `scroll_event_from_ffi` — each returning `None`, and dropping the event, on a bad discriminant — then call `WolfCore::send_mouse` / `send_scroll`, so mouse/scroll target the pane's window grid with grid-local row/col), `start_file_search` (starts a `FileSearch` session — wired to the picker wake — and wraps it as an `FfiFileSearch`), `open` (issues `InputEvent::Open { path }`; the MRU is recorded by core's input pump), `copy_selection` (the visual-mode selection yanked to text via `WolfCore::copy_visual_selection` — blocking — or the empty string when not in visual mode / empty / core gone), `paste(text)` (`core.paste(text)` → `InputEvent::Paste` → `nvim_paste`), `set_background(dark)` (`core.set_background(dark)` → `InputEvent::SetBackground` → `:set background=dark|light`, the appearance push face — re-sources the colorscheme so the existing `wolf_theme` path repaints; a no-op when the core is gone), `is_visual_mode` (`snapshot.is_visual_mode()` under a read guard, gating the Edit > Copy menu item; false once shut down), `buffer_picker` (builds an `FfiBufferPicker` seeded from a BLOCKING `core.list_buffers()` snapshot + the live cwd — empty-backed when the core is gone), `switch_buffer(bufnr)` (resolves the active window LIVE from the snapshot and, when nonzero, calls `core.switch_buffer(active_win, bufnr)` — a window-scoped switch + per-pane view restore; a no-op when the core is gone or no active window is known), `toggle_terminal` (`core.toggle_terminal()` → `InputEvent::ToggleTerminal` → the `wolf_toggle_terminal` init.lua helper: open/hide the per-tabpage bottom `:terminal` drawer showing the shared per-project terminal buffer; a no-op when the core is gone), `is_markdown_active` (`snapshot.is_markdown_active()` under a read guard, gating the View > Preview menu item; false once shut down), `is_preview_active` (`snapshot.is_preview_active()` under a read guard, gating the View > Edit Source menu item — the mirror of `is_markdown_active`; false once shut down), `toggle_full_width` (`core.toggle_full_width()` → `InputEvent::ToggleFullWidth` → the `wolf_toggle_full_width` init.lua helper: flip `b:wolf_full_width` on the effective buffer — the SOURCE buffer for a preview scratch, OQ-1 — and re-emit the current-file / per-window full-width / previews notifications; a no-op when the core is gone), `is_full_width_active` (`snapshot.is_full_width_active()` under a read guard, driving the View > Use full width for content menu CHECKMARK — the item is always enabled, OQ-2; false once shut down), `full_width_for_win(win)` (`snapshot.full_width_for_win(win)` under a read guard — the per-window `full_width` map, threaded into a pane's geometry as `maxCols: nil`/`90`; false once shut down or `win` absent), `open_preview(mode)` (`core.open_preview(&mode)` — the preview scratch buffer's number or 0 on error / not-markdown / core gone), `edit_source(mode)` (`core.edit_source(&mode)` — Preview's inverse: the source buffer's number, or 0 on error / not-a-preview / core gone; `mode` is `"split_left"` / `"reuse_editor_pane"` / `"active"`), `render_preview(source_bufnr)` (`core.render_preview(source_bufnr)` — the themed HTML document or `""` on error / core gone), `open_in_browser()` (`core.open_in_browser()` — lazily starts/reuses the per-core loopback preview server pinned at the active Markdown buffer and returns its `http://127.0.0.1:<port>/<relpath>` URL — where `<relpath>` is the pinned file's project-root-relative path (so relative links between Markdown files resolve) — or `""` when not markdown / on error / core gone; the front-end opens it via `NSWorkspace`), `preview_file(win, path) -> i64` (the preview LINK-follow bridge: `core.preview_file(win, &path)`, repointing preview window `win` at the Markdown file at `path` — the linked file's SOURCE bufnr, or `0` when `path` is empty / unreadable / non-markdown, on error, or the core is gone; `path` is ABSOLUTE — the front-end resolves it from WebKit's `file://` URL, no relative resolution — and on `0` the front-end applies its own O3 fallback), `previews` (maps `snapshot.previews` through `FfiPreview::from_preview`, joining each source bufnr's `snapshot.markdown_ticks` tick — the `0` fallback until the first `wolf_markdown_dirty`; an empty `Vec` when the core is gone), `recent_dirs` (the GLOBAL recent-directories MRU newest-first — capped at 20 — delegating to `WolfCore::recent_dirs()` and mapping each `PathBuf` via `to_string_lossy().into_owned()`; an empty `Vec` when the store is disabled/unreadable or the core is gone; the `Vec<String>` crosses the bridge as `RustVec<RustString>`, and it drives the File > Open Recent submenu), `pane_status_for_grid(grid)` (the per-pane statusbar strings for the window drawing into `grid`, as an opaque `FfiPaneStatus` — see below), `cmdline()` / `pum()` / `toast()` (the native command line / completion popup / message toast, as opaque `FfiCmdline` / `FfiPum` / `FfiToast` projections of `Snapshot.cmdline` / `pum` / `toast`, each with an empty/hidden fallback when the core is gone; the toast's chunk colors are resolved IN RUST against the `HighlightTable` at pack time — see below), `current_file` (this tab's active-buffer absolute path, or `""` — read by the coordinator for the tab title), `cwd` (nvim's live cwd, or `""`), the six TABPAGE methods (`create_tabpage(cwd)` → `tabnew` + optional `:tcd`, the new tabpage HANDLE or 0; `current_tabpage()` → the blocking first-view-bind handle or 0; `active_tabpage()` → the CHEAP `read_snapshot().current_tabpage` refocus gate, no RPC, 0 when gone; `cwd_for_tabpage(tab)` → a NON-current view's tab-local `:tcd` cwd, `""` when gone/invalid; `set_current_tabpage(tab)` / `close_tabpage(tab)` → no-ops when gone — each with the `borrow().as_ref()` core-gone neutral fallback), the three CRASH-RECOVERY methods (`liveness() -> u8` → maps `WolfCore::liveness()` through the `liveness` discriminant module — `ALIVE`/`NOT_RESPONDING`/`DEAD` — `DEAD` when the core is gone; `restart() -> bool` → `WolfCore::restart_nvim()` mapped `Ok(true) → true` else `false` (`Ok(false)` no-op / `Err` respawn-failure both `false`, logged), so Swift rebinds+reopens only on `true`; `open_files_for_tabpage(tab: i64) -> FfiOpenFiles` → the Tier-1 mirror captured before a restart, empty-backed when gone/unknown), `wake_token` (the per-PROJECT `u64` wake-routing identity minted at start — see "The wake" below), and `shutdown` (flushes `SHARED_STORE` bounded by `STATE_FLUSH_TIMEOUT` ≈ 2 s, then takes the core out via `.take()` so a second call is a no-op, then `WolfCore::shutdown`; any error is logged, not returned — the bridge is infallible). The handle carries only `wake_token: u64` beside the core (the state store is no longer held per-handle). `wolf_ffi_start(init_lua, cwd, cols, rows)` FIRST installs the process-global stderr tracing subscriber via `wolf_core::init_tracing()` (idempotent — only the first call across all projects/windows wins, subsequent calls are harmless no-ops; verbosity via the `WOLF_LOG` env var, default `warn` — see [`wolf-core/src/README.md`](../../wolf-core/src/README.md), "`logging.rs`"), then builds a `CoreConfig` (the two strings are filesystem **paths**), starts ONE captive Neovim = one PROJECT, mints a fresh per-PROJECT `wake_token` from the process-global `NEXT_WAKE_TOKEN` counter and wires a token-carrying wake, calls `WolfCore::start`, and returns `Option<WolfCoreHandle>` (`None` after logging on error). One handle is shared by all of the project's views (each bound to a distinct tabpage via the six tabpage methods). State persistence is decoupled from the handle: the **write-side snapshot-builder free functions** — `wolf_ffi_state_snapshot_begin()` (clear the scratch tree), `wolf_ffi_state_snapshot_add_window(x, y, width, height)` (push a window with empty tabs), `wolf_ffi_state_snapshot_add_tab(cwd, sidebar_visible)` (push a tab onto the last window), `wolf_ffi_state_snapshot_commit()` (clone the scratch tree and `set_snapshot` it into the process-wide `SHARED_STORE`), and `wolf_ffi_state_flush() -> bool` — build the whole tree over a `static SCRATCH: OnceLock<Mutex<WolfState>>` and commit it into `SHARED_STORE` (opened once, lazily, over `wolf_core::state_dir()` in a `OnceLock` — all windows share one store; an unresolvable dir disables persistence, never fatal).

- **`FfiFrame` + `FfiCell`** — the opaque per-frame snapshot of a single grid. `FfiFrame::from_snapshot_grid(&wolf_core::Snapshot, grid_id)` (public, so the headless `frame_pack` test can drive it without a live `WolfCore`) resolves that grid's cells against the snapshot's `HighlightTable` **in Rust** — reusing `HighlightTable::resolve` / `ResolvedStyle`, never re-resolving in Swift — into a flat row-major `Vec<FfiCell>`, computes the cursor's reverse-video fill/glyph colors (`cursor_colors`, ported from wolf-gnome's `cursor.rs`) against the REQUESTED grid's cell under the cursor, and sets `cursor_visible = (cursor.grid == grid_id)` (per-grid) plus the `grid_id` / `cursor_grid` fields. An absent grid yields `FfiFrame::empty()` (`cols()` / `rows()` 0 — "grid gone"). `FfiFrame::from_snapshot(snap)` delegates to `from_snapshot_grid(snap, snap.active_grid_id())`, so `read_frame` keeps its active-grid behavior. `from_snapshot_grid` also reads the requested grid's `viewport` (`snapshot.windows.get(&grid_id).map(|w| w.viewport).unwrap_or_default()`) into the frame's `topline` / `botline` / `curline` / `linecount` fields (all 0-based, as nvim's `win_viewport` reports; `botline` is one-past-the-last-visible line), defaulting to all-zero when the grid has no associated window. Scalar accessors expose the dims, cursor position/shape/percentage, `cursor_visible`, `grid_id`, `cursor_grid`, the default + cursor colors, and the four viewport accessors (`topline` / `botline` / `curline` / `linecount`) that drive the synthetic scrollbar. `FfiCell` is opaque (swift-bridge does not emit `Vec` support for transparent structs) with `text()` / `fg()` / `bg()` / `special()` (the resolved special / underline color, mirroring `fg()` / `bg()`) / `flags()`; its `text` field is `pub` so the Rust tests read it directly.

- **`FfiLayoutIntent` + `FfiWinInfo`** — the opaque split-pane projections (opaque so a `Vec<T>` is supported, like `FfiCell` / `FfiTreeNode`). `FfiLayoutIntent::from_intent` flattens `wolf_core::LayoutIntent`'s three variants into a tagged `{ kind, orientation, dir, from, win }` struct (a SPLIT carries `orientation` + `from` + `win`; a FOCUS_DIR carries `dir` + `from`; a DRAWER_OPEN REUSES the existing `win` field for the new drawer window — no new bridged field or method — with the unused scalars zeroed), packing discriminants from the `intent_kind` / `orientation` / `focus_dir` modules; accessors `kind()` / `orientation()` / `dir()` / `from()` / `win()`. `FfiWinInfo::from_win_info` projects a `wolf_core::WinInfo`'s pane-relevant `{ grid, win, hidden }`; accessors `grid()` / `win()` / `hidden()` (the last now effectively always `false` per OD8 — a `win_hide` / tabpage switch removes the window from the snapshot rather than flagging it; the accessor is kept to avoid FFI churn).

- **`FfiPaneStatus`** — the opaque per-pane statusbar projection (opaque so its owned `String`s are read back via accessors). `WolfCoreHandle::pane_status_for_grid(grid: u64) -> FfiPaneStatus` delegates to `WolfCore::pane_status(grid)` (joining grid → window → buffer path, formatted over nvim's live cwd + home) and projects the resulting `wolf_core::PaneStatus` via `FfiPaneStatus::from_pane_status`; a shut-down core yields the empty status (`[No Name]` filename, empty path) via `FfiPaneStatus::empty`. Accessors `filename() -> String` (the base filename, or `[No Name]` for an unnamed buffer) and `display_path() -> String` (the cwd-relative / `~`-prefixed / absolute path, empty for an unnamed buffer). The macOS `PaneContainerView` reads both to paint each pane's top statusbar strip.

- **`FfiCmdline` + `FfiPum` + `FfiPumItem` + `FfiToast` + `FfiToastLine` + `FfiToastChunk`** — the native command-line / completion-popup / message-toast projections (all opaque; the `Vec`-carried ones for the usual `Vec<T>`-needs-opaque-`T` reason as `FfiCell`). `WolfCoreHandle::cmdline()` projects `Snapshot.cmdline` via `FfiCmdline::from_cmdline` (empty via `FfiCmdline::empty()` when the core is gone) — the content chunks are FLATTENED to a single `text()` String (OD1 — the cmdline is not styled across the FFI), with `active` / `firstc` / `prompt` / `pos` (a BYTE offset) / `indent` / `level`. `pum()` projects `Snapshot.pum` via `FfiPum::from_pum`: `visible` / `selected` / `anchor_grid` (-1 = cmdline-anchored) / `anchor_row` / `anchor_col` (a byte offset when cmdline-anchored) / `items()` (each an `FfiPumItem` with `word` / `kind` / `menu` / `info`). `toast()` projects `Snapshot.toast` via `FfiToast::from_toast(&snapshot.toast, &snapshot.highlights)` — it takes the `HighlightTable` because, UNLIKE the flattened cmdline, each `FfiToastChunk` carries its `fg()` / `bg()` / `special()` colors RESOLVED IN RUST against that table at pack time (exactly like `FfiCell` — message color is load-bearing, OD1) plus the packed style `flags()`; `FfiToast` exposes `visible` / `kind()` (the last message's kind) / `lines()` (each an `FfiToastLine` whose `chunks()` are the `FfiToastChunk`s). The bindings are regenerated after adding this surface (`bazel run //crates/wolf-ffi:gen_bindings`); `generated/wolf_ffi_wake.h` is UNCHANGED (no new wake channel — the overlays ride the existing editor render wake).

- **`FfiState` + `FfiWindowState` + `FfiTabState`** — the saved-application-state restore surface (opaque, like the other Vec-carried types). The free `wolf_ffi_load_state()` is the PRE-START restore read: it delegates to `wolf_core::state_dir().and_then(load_state)` — never creating/modifying the file and never opening the live store — and yields an `FfiState` whose `windows()` is empty on an absent/corrupt/old-flat file or an unresolvable dir (infallible across the bridge, parallel to `wolf_ffi_load_config`). `FfiWindowState::from_window` projects a `wolf_core::WindowState`; scalar accessors expose `x` / `y` / `width` / `height` plus `tabs() -> Vec<FfiTabState>`. `FfiTabState::from_tab` projects a `wolf_core::TabState`; accessors `cwd()` / `sidebar_visible()`.

- **`FfiFileSearch` + `FfiFileEntry`** — the picker surface. `FfiFileSearch` wraps core's `FileSearch` session in an `Option` (so `start_file_search` stays infallible across the bridge; `None` yields no entries, mirroring `read_frame`'s empty-frame fallback). `ranked(query, max)` reads the session's results snapshot, runs `wolf_core::rank_matches_top_n(&query, &entries, max)` **in Rust** (the BOUNDED top-N variant — it selects the top `max` via an `O(M log max)` heap instead of sorting the whole match set, then clones only the survivors), and clones the matched entries into a `Vec<FfiFileEntry>` (the read guard is held only for that scope). `FfiFileEntry { path: PathBuf, display: String }` exposes `display()` / `path()` (path via `to_string_lossy().into_owned()`); both are opaque because swift-bridge only emits `Vec<T>` for opaque `T` — the same reason `FfiCell` is opaque.

- **`FfiCommand`** — one drained user-triggered command (opaque so a `Vec<FfiCommand>` is supported). `WolfCoreHandle::drain_commands()` drains core's command queue (`:Wolf<Pascal>` Ex-commands / `require('wolf')` Lua calls) and maps each through `FfiCommand::from_command`, an EXHAUSTIVE match over `wolf_core::Command` packing the `command_kind` discriminant (a future variant add/reorder is a compile error). Accessor `kind() -> u8`.

- **`FfiCommandPalette` + `FfiCommandRow`** — the command-palette session surface (opaque; `FfiCommandRow` opaque so a `Vec` is supported). `WolfCoreHandle::command_palette()` builds a session seeded with `core.recent_dirs()` + `core.command_mru()` (empty-backed — no recent dirs, a disabled MRU — when the core is gone, mirroring `start_file_search`). `FfiCommandPalette { recent_dirs: Vec<PathBuf>, windows: RefCell<Vec<PaletteWindow>>, command_mru: CommandMru }` is a **main-thread-only** handle (the `RefCell` gives interior mutability for `add_window` behind the bridge's `&self`): `add_window(index: u16, cwd: String)` pushes one OTHER open window (the current window is excluded by the caller); `ranked(query: String, max: usize) -> Vec<FfiCommandRow>` clones the window vec out of the `RefCell` then delegates to `wolf_core::rank_palette(&recent_dirs, &windows, &command_mru.recent(), &query, max)` — assembling the static commands (minus `CommandPalette`) + windows + recent dirs, ranked MRU-first — and maps each `PaletteRow` through `FfiCommandRow::from_row`; `record(key: String)` writes the row's `mru_key` into the global `command-mru.sqlite`. `FfiCommandRow` flattens a `PaletteRow` into `{ display, row_kind, command_kind, window_index, path, mru_key }` with matching accessors: `row_kind()` uses the `palette_row_kind` discriminants; `command_kind()` reuses `FfiCommand::from_command`'s mapping for a `Static` row (0 for dynamic rows); `path()` is the recent-folder path for an `OpenRecent` row (`""` otherwise); `window_index()` the raise target for a `SwitchWindow` row (0 otherwise). There is NO wake: candidates are fixed at open and `ranked()` re-filters synchronously per keystroke.

- **`FfiBufferPicker` + `FfiBufferRow`** — the buffer-picker session surface (opaque; `FfiBufferRow` opaque so a `Vec` is supported). `WolfCoreHandle::buffer_picker()` builds `FfiBufferPicker { buffers: core.list_buffers(), cwd: core.live_cwd() }` (empty-backed — no buffers, no cwd — when the core is gone, mirroring `command_palette`). `ranked(query: String, max: usize) -> Vec<FfiBufferRow>` delegates to `wolf_core::rank_buffers(&buffers, cwd.as_deref(), &query, max)` (MRU-ordering by `lastused` DESC among matches, current buffer at row 0 for an empty query) and maps each `BufferRow` through `FfiBufferRow::from_row`. `FfiBufferRow` flattens a `BufferRow` into `{ bufnr, display, modified }` with matching accessors: `bufnr() -> i64` (passed back to `switch_buffer`), `display() -> String` (the cwd-relative / absolute / `[No Name]` label, also the ranked string), `modified() -> bool`. There is NO wake (candidates fixed at open) and NO `add_window` / `record` — activation is on the HANDLE (`switch_buffer`), so nothing is recorded on activation.

- **`FfiPreview`** — the opaque Markdown-preview projection (opaque so a `Vec<FfiPreview>` is supported, like `FfiBufferRow`; re-exported at the crate root as `wolf_ffi::FfiPreview` so the `:preview` integration test names it). `WolfCoreHandle::previews()` maps each `Snapshot.previews` entry through `FfiPreview::from_preview(win, &PreviewInfo, source_tick, source_display_path)`, joining the preview WINDOW handle + its `PreviewInfo { source_bufnr, source_path, source_full_width }` to the source buffer's live `changedtick` (looked up in `Snapshot.markdown_ticks`, `0` until the first `wolf_markdown_dirty`) and to the source's cwd/home-relative DISPLAY path (computed in `previews()` via `WolfCore::display_path(&info.source_path.to_string_lossy())`); the constructor derives the basename from `source_path`'s final component (empty for a pathless source) and copies `source_full_width`. Accessors `win() -> i64` (the preview window the front-end overlays a web view on), `source_bufnr() -> i64` (passed back to `render_preview`), `source_name() -> String` (the basename for the primary `Preview: <name>` statusbar line), `source_path() -> String`, `source_display_path() -> String` (the cwd-relative / `~`-prefixed / absolute display path — the preview pane's SECONDARY statusbar line, empty for a pathless source), `source_tick() -> u64` (the front-end reloads the web view when it advances), and `source_full_width() -> bool` (whether the SOURCE buffer is full-width — the front-end frames this preview pane's web view to the full inset pane when `true`, or the capped+centered ~90-char rect when `false`).

- **`FfiOpenFiles`** — the opaque Tier-1 open-file mirror projection (opaque so its `String` / `Vec<String>` fields read back via accessors, like `FfiPaneStatus`). `WolfCoreHandle::open_files_for_tabpage(tab)` calls `WolfCore::open_files_for_tabpage(tab)` and projects the optional `wolf_core::TabFiles` via `FfiOpenFiles::from_tab_files` — `None` (a gone core / unknown tabpage) yields an empty-backed value. Accessors `active_path() -> String` (the tabpage's active buffer's absolute path, `""` unnamed) and `files() -> Vec<String>` (the file-backed open buffer paths, absolute — reopened active-last after a restart). `files()` is the instance-GLOBAL buflisted set (the known Tier-1 multi-view over-reopen limitation).

- **The captive-nvim liveness discriminant module (`mod liveness`).** `ALIVE = 0` / `NOT_RESPONDING = 1` / `DEAD = 2`, mirroring `wolf_core::Liveness::to_u8`. `WolfCoreHandle::liveness()` maps the core's `Liveness` through it (returning `DEAD` when the core is gone), and it is the single source of truth shared with the Swift `Project.Liveness` mirror. Sits beside the other discriminant modules below.

- **The wake (Swift-free, multi-window routed).** `#[no_mangle] pub extern "C" fn wolf_ffi_set_wake` registers (or clears) the front-end wake callback in a global `AtomicPtr`; the callback ABI is `extern "C" fn(uint64_t token)`. `registered_wake(token)` builds the `WakeFn` core fires on flush, which loads and calls the registered pointer passing THIS core's per-PROJECT `wake_token` (a no-op if none is registered). Declared via a hand-written C header (`generated/wolf_ffi_wake.h`) rather than an `extern "Swift"` symbol, so the rlib links with no Swift present. The token (minted in `wolf_ffi_start` from `NEXT_WAKE_TOKEN`) is a plain `Send` scalar the closure captures — it touches no `WolfCore` state — so ONE process-global callback per channel routes each wake to the right PROJECT (the front-end looks the token up in its `WindowRegistry` to reach the owning `Project`, which fans the wake out to its current view) without two projects clobbering each other. A **second**, parallel registration — `wolf_ffi_set_filesearch_wake` with its own `registered_filesearch_wake(token)` and `AtomicPtr` — backs the file picker (a `start_file_search` session fires it after each streaming traversal batch, so the picker refreshes independently of editor repaints), and a **third** — `wolf_ffi_set_tree_wake` / `registered_tree_wake(token)` — backs the file-tree sidebar's `start_tree_search` session. All three are identical in shape — token-carrying, no-op when unregistered — and declared in `generated/wolf_ffi_wake.h`.

- **Helpers.** `key_event_from_ffi` maps an `FfiKeyEvent` into a `wolf_core::KeyEvent` (the `kind` discriminants — `mod kind`, `CHAR = 0` … `F = 14` — mirror `wolf_core::Key`'s variant order and are the single source of truth shared with the Swift `WolfKeyMap` and the test suites); `mouse_event_from_ffi` / `scroll_event_from_ffi` map an `FfiMouseEvent` / `FfiScrollEvent` into a `wolf_core::MouseEvent` / `ScrollEvent`, matching the `button`/`action`/`direction` discriminants onto the core enums and returning `None` on any unknown value (the caller drops the event); `pack_flags` packs the style bitset (`mod flag`); `pack_cursor_shape` maps `CursorShape` to its `u8` (`mod cursor_shape`); `FfiColor::from_rgb` / `from_opt` do the `0x00RRGGBB` packing (with `FALLBACK_FG` white / `FALLBACK_BG` black mirroring wolf-gnome's `render`).

- **Discriminant modules.** Three more discriminant modules sit beside `mod kind` and are the single source of truth shared with the Swift `PaneTree` port (`Orientation.init?(ffi:)` / `FocusDir.init?(ffi:)`) and the `WolfKeyMapTests` / `tests/panes.rs` / `tests/terminal.rs` discriminant contracts: `mod intent_kind` (`SPLIT = 0`, `FOCUS_DIR = 1`, `DRAWER_OPEN = 2` — append-only/last, never reordered; the drawer-open intent reuses the `win` field), `mod orientation` (`HORIZONTAL = 0`, `VERTICAL = 1` — `wolf_core::SplitOrientation` order), and `mod focus_dir` (`LEFT = 0`, `RIGHT = 1`, `UP = 2`, `DOWN = 3` — `wolf_core::FocusDir` order). `FfiLayoutIntent::from_intent` reads from them. Three more sit beside them for the mouse/scroll surface — `mod mouse_button` (`LEFT = 0`, `RIGHT = 1`, `MIDDLE = 2` — `wolf_core::MouseButton` order), `mod mouse_action` (`PRESS = 0`, `RELEASE = 1`, `DRAG = 2` — `wolf_core::MouseAction` order), and `mod scroll_dir` (`UP = 0`, `DOWN = 1`, `LEFT = 2`, `RIGHT = 3` — `wolf_core::ScrollDirection` order); `mouse_event_from_ffi` / `scroll_event_from_ffi` read from them, and they are the single source of truth shared with the Swift `PaneContainerView` consts and the `tests/mouse_scroll.rs` local consts. Two more back the command surface: `mod command_kind` (`NEW_WINDOW = 0` … `DECREASE_FONT_SIZE = 12`, `COMMAND_PALETTE = 13`, `COPY = 14`, `PASTE = 15`, `BUFFER_PICKER = 16`, `NEW_TAB = 17`, `PREVIEW = 18`, `EDIT = 19`, `TERMINAL = 20`, `PREVIEW_IN_BROWSER = 21`, `FULL_WIDTH = 22` — `wolf_core::Command` order), read by `FfiCommand::from_command` and shared with the Swift `CommandKind` port and the `tests/commands.rs` / `tests/command_palette.rs` / `tests/copy_paste.rs` / `tests/buffer_picker.rs` / `tests/preview.rs` / `tests/edit.rs` / `tests/terminal.rs` / `tests/full_width.rs` contract guards; and `mod palette_row_kind` (`STATIC = 0`, `SWITCH_WINDOW = 1`, `OPEN_RECENT = 2` — `wolf_core::PaletteRowKind` order), read by `FfiCommandRow::from_row` and shared with the Swift `PaletteSeam.PaletteRowKind` port. One more — `mod appearance` (`AUTO = 0`, `DARK = 1`, `LIGHT = 2` — `wolf_core::Appearance` order) — backs the config surface: `wolf_ffi_load_config` maps `config.appearance` onto it for `FfiConfig::appearance()`, and it is the single source of truth shared with the Swift `AppearanceMode` port (a `UInt8` raw-value enum in `WolfKeyMap`) and the `AppearanceSeamTests` contract.

## `bin/gen_bindings.rs`

The standalone codegen binary (`//crates/wolf-ffi:gen_bindings`, run via `bazel run`). It invokes `swift-bridge-build`'s parser over `lib.rs` and writes the Swift and C output into `$BUILD_WORKSPACE_DIRECTORY/crates/wolf-ffi/generated/`, prepending the `import WolfFFI` line the Swift glue needs to the `.swift` files. It writes **in-tree** (only `bazel run` sets `BUILD_WORKSPACE_DIRECTORY` and may write into the source tree — a genrule cannot), so the generated files stay **committed** and are refreshed explicitly after a bridge change.
