# wolf-ffi

The swift-bridge FFI surface over [`wolf-core`](../wolf-core). This crate is the seam between the platform-agnostic Rust core and the macOS (AppKit) front-end in [`wolf-macos`](../wolf-macos). It holds the single `#[swift_bridge::bridge]` module and the hand-written Rust glue behind it, and is built as both a `staticlib` (the archive the `.app` links through the generated Swift) and an `rlib` (so the Rust integration test can link the same surface headlessly).

swift-bridge is confined to this crate. `wolf-core` gains no new dependency and no GUI-toolkit dependency; the Linux/GTK front-end keeps consuming `wolf-core` directly.

## Bridge surface

All types are re-exported at the crate root (`wolf_ffi::…`).

- `wolf_ffi_start(init_lua: String, cwd: String, cols: u16, rows: u16) -> Option<WolfCoreHandle>` — starts the core against the pinned Neovim (ONE captive Neovim = one PROJECT). `init_lua` and `cwd` are filesystem **paths** (mirroring `CoreConfig`). Returns `None` (after logging) on error. A fresh per-PROJECT wake token is minted (see "The wake" below) and captured by the core's `WakeFn` so wakes route back to this project (which the front-end fans out to its current view). State persistence is no longer wired per-core — the coordinator walks the whole window/tab tree and commits it via the `wolf_ffi_state_snapshot_*` builder free functions (below).

- `WolfCoreHandle` — an opaque, **main-thread-only** handle wrapping a `RefCell<Option<WolfCore>>` (`WolfCore` is not `Send`). It carries only its per-PROJECT `wake_token` (the state store is now a process-wide `SHARED_STORE` the free-fn snapshot builder commits into, not held per handle). One handle is shared by all of a project's views (each bound to a distinct nvim TABPAGE). Methods:
  - `wake_token(&self) -> u64` — the per-project wake-routing identity token (minted fresh per `wolf_ffi_start`). The front-end registers ONE process-global callback per wake channel and looks this token up (in its `WindowRegistry`) to route each wake to the owning `Project`, which fans it out to its current view.
  - `create_tabpage(&self, cwd: String) -> i64` — creates a new nvim TABPAGE (a joining/restored view), optionally rooted at `cwd` via `:tcd` (empty string = no `:tcd`), returning its stable HANDLE. Blocks briefly on the captive nvim. `0` when the core is gone (the caller then drops the would-be view).
  - `current_tabpage(&self) -> i64` — the current tabpage's stable HANDLE via a blocking RPC (`nvim_get_current_tabpage`) — the authoritative first-view bind. `0` when the core is gone.
  - `active_tabpage(&self) -> i64` — the CHEAP `Snapshot.current_tabpage` refocus gate (updated out-of-band via `wolf_tabpage`), read from the snapshot with NO RPC. `0` when the core is gone / not yet known. Mirrors `active_win`; the front-end polls it to decide whether its tabpage is current (the refocus-rebind barrier), vs the authoritative bind-time `current_tabpage()`.
  - `cwd_for_tabpage(&self, tab: i64) -> String` — a tabpage's tab-local `:tcd` cwd (canonicalized), AUTHORITATIVE for a NON-current view. Blocks briefly on the captive nvim. Empty when the core is gone or the handle is invalid (e.g. a closed tabpage).
  - `set_current_tabpage(&self, tab: i64)` — makes tabpage `tab` current (the front-end drives every tabpage switch when a view becomes key). A no-op when the core is gone.
  - `close_tabpage(&self, tab: i64)` — closes tabpage `tab` (a non-last view close; the shared nvim stays alive until its LAST view closes — the front-end shuts the core down then instead). A no-op when the core is gone.
  - `read_frame(&self) -> FfiFrame` — the **active** grid's paint-ready frame.
  - `read_frame_for_grid(&self, grid: u64) -> FfiFrame` — the paint-ready frame for a SPECIFIC grid. The pane container reads one per pane (its bound window grid) plus grid 1 for the editor default fg/bg colors the bottom overlays paint against. An absent grid (e.g. a closed window) yields an empty `0x0` frame, which the front-end treats as "grid gone".
  - `send_key(&self, ev: FfiKeyEvent)`
  - `resize(&self, cols: u16, rows: u16)`
  - `resize_grid(&self, grid: u64, cols: u16, rows: u16)` — resizes a single window grid (in cells) on a per-pane resize; nvim echoes the authoritative size back via `grid_resize`. A no-op once the core is shut down.
  - `drain_intents(&self) -> Vec<FfiLayoutIntent>` — drains all pending layout intents (splits + focus moves) in arrival order, each mapped into an opaque `FfiLayoutIntent`. Empty `Vec` when the core is gone.
  - `drain_commands(&self) -> Vec<FfiCommand>` — drains all pending user-triggered commands (`:Wolf<Pascal>` Ex-commands / `require('wolf')` Lua calls) in arrival order, each mapped into an opaque `FfiCommand`. Empty `Vec` when the core is gone (and right after start — commands are user-triggered only).
  - `windows(&self) -> Vec<FfiWinInfo>` — ALL windows nvim currently reports (the Swift side filters live editor windows, mirroring the GNOME reading of `snapshot.windows`), each an opaque `FfiWinInfo`. Empty `Vec` when the core is gone.
  - `grid_for_win(&self, win: i64) -> u64` — the grid id bound to window handle `win`, or `0` if none maps to it (e.g. it was closed) / the core is gone.
  - `active_win(&self) -> i64` — the currently active Neovim window handle, or `0` if not yet known / the core is gone.
  - `focus_win(&self, win: i64)` — focuses a specific Neovim window (click-to-focus, or after resolving a focus-direction intent into a concrete neighbour). A no-op once the core is shut down.
  - `send_mouse(&self, ev: FfiMouseEvent)` — forwards a mouse click / drag / release. Rust maps the transparent `FfiMouseEvent` into a `wolf_core::MouseEvent` via `mouse_event_from_ffi` (`None` on a bad `button`/`action` discriminant, then dropped) and calls `WolfCore::send_mouse`, so it targets the pane's window grid with grid-local row/col. A no-op once the core is shut down.
  - `send_scroll(&self, ev: FfiScrollEvent)` — forwards a scroll-wheel / trackpad event. Rust maps the transparent `FfiScrollEvent` into a `wolf_core::ScrollEvent` via `scroll_event_from_ffi` (`None` on a bad `direction` discriminant) and calls `WolfCore::send_scroll`. A no-op once the core is shut down.
  - `start_file_search(&self) -> FfiFileSearch` — starts a streaming file-search session over the cwd (registering the picker wake) and wraps it as an `FfiFileSearch`. Infallible across the bridge: when no core is present the result simply yields no entries. It is infallible but NOT entirely non-blocking: it resolves the search root synchronously via a bounded `getcwd()` RPC (`WolfCore::resolve_search_root`), so a wedged nvim can stall it for up to `RPC_TIMEOUT` (default 5s, `WOLF_RPC_TIMEOUT_MS`) before it falls back to the configured cwd and streams from there (see "RPC timeout" below).
  - `start_tree_search(&self) -> FfiFileSearch` — starts a **separate**, long-lived streaming file-search session for the file-tree sidebar, registering the **tree** wake (`registered_tree_wake`) instead of the picker wake. Same infallible empty-backed fallback as `start_file_search`. The sidebar owns this session for its whole lifetime, independent of the transient picker session.
  - `current_file(&self) -> String` — the absolute path of the buffer currently being edited (canonicalized by core via the `wolf_current_file` notification), or the empty string for an unnamed buffer / shut-down core. Read on each editor wake to highlight + reveal the sidebar's current file.
  - `cwd(&self) -> String` — Neovim's LIVE, already-canonicalized working directory (the `wolf_cwd`/`DirChanged`-tracked cell, tracking `:cd`/`:lcd`/`:tcd`), or the empty string until nvim first reports it / after shutdown. Routes through `WolfCore::live_cwd` (a cheap synchronous read — cwd is NOT in the render snapshot, so unlike `current_file` it does not read `read_snapshot()`). Read on each editor wake by the sidebar to re-root the file tree when the cwd changed.
  - `recent_dirs(&self) -> Vec<String>` — the GLOBAL recent-directories MRU, newest-first (capped at 20), as owned `String`s; an empty `Vec` when the store is disabled/unreadable or the core is shut down. Delegates to `WolfCore::recent_dirs()`, mapping each `PathBuf` via `to_string_lossy().into_owned()`. The `Vec<String>` crosses the bridge as `RustVec<RustString>` (the same clean glue as `wolf_ffi_ancestors_to_reveal`). Read lazily at Open-Recent-menu open time by the macOS shell to build the File > Open Recent submenu.
  - `command_palette(&self) -> FfiCommandPalette` — starts a command-palette session seeded with `recent_dirs()` + `command_mru()` (empty-backed when the core is gone, mirroring `start_file_search`). The front-end feeds it the OTHER open windows one at a time (`add_window`) then calls `ranked` per keystroke; see `FfiCommandPalette` below.
  - `theme_titlebar_bg(&self) -> FfiColor` — the `WolfTitlebar` theme group's background color (`Snapshot.theme.titlebar.bg`), following the `default_fg`/`default_bg` unset convention: `set == false` when the group is absent or cleared, or once the core is shut down. Read on each render wake by the macOS shell, which applies it to (or reverts it from) `NSWindow.backgroundColor`.
  - `theme_titlebar_fg(&self) -> FfiColor` — the `WolfTitlebar` foreground, carried across the bridge for future title-text coloring (applied on macOS this pass as the per-pane statusbar text color). Same unset convention as `theme_titlebar_bg`.
  - `pane_status_for_grid(&self, grid: u64) -> FfiPaneStatus` — the per-pane statusbar strings for the window drawing into `grid` (base filename + display path), delegating to `WolfCore::pane_status(grid)`; a shut-down core yields the empty status (`[No Name]` filename, empty path). `FfiPaneStatus` is opaque, read back via `filename()` / `display_path()`. The macOS `PaneContainerView` reads it to paint each pane's top statusbar strip.
  - `cmdline(&self) -> FfiCmdline` — the native command line (`ext_cmdline`) as an opaque `FfiCmdline` (`Snapshot.cmdline` flattened to a single `text()` String, OD1). An empty (inactive) `FfiCmdline` when the core is shut down.
  - `pum(&self) -> FfiPum` — the completion popup (`ext_popupmenu`) as an opaque `FfiPum` (its items projected from `Snapshot.pum`). An empty (hidden) `FfiPum` when the core is shut down.
  - `toast(&self) -> FfiToast` — the message toast (`ext_messages`) as an opaque `FfiToast`, its chunk colors RESOLVED in Rust against the snapshot's `HighlightTable` at pack time (like `FfiCell` — message color is load-bearing, OD1). An empty (hidden) `FfiToast` when the core is shut down. The macOS `PaneContainerView` reads all three on each render wake to refresh its bottom overlays.
  - `open(&self, path: String)` — issues `InputEvent::Open { path }` to open the file; the MRU is recorded by core's input pump.
  - `chdir(&self, path: String)` — changes the current VIEW's working directory to `path` (an absolute filesystem path) via `InputEvent::Chdir { path }` (`:tcd`, the TAB-LOCAL cwd — each view/tabpage owns its own working directory, so this never moves a sibling view); the sidebar follows the live cwd. A no-op once the core is shut down.
  - `set_background(&self, dark: bool)` — pushes the resolved appearance to nvim via `InputEvent::SetBackground` (`:set background=dark|light`, delegating to `WolfCore::set_background`); the re-sourced colorscheme re-fires the existing `wolf_theme` path so the grid + titlebar repaint. Fire-and-forget; a no-op once the core is shut down. The macOS `AppDelegate` fans it out to every project from the `appearance` config (at launch, and — in `auto` mode — live on an OS toggle).
  - `close_pane(&self)` — closes the current split via `InputEvent::ClosePane` (`:close`, NOT the buffer; errors harmlessly with E444 on the last split). A no-op once the core is shut down.
  - `new_buffer(&self)` — opens a new empty buffer in the current window via `InputEvent::NewBuffer` (`:enew`). A no-op once the core is shut down.
  - `copy_selection(&self) -> String` — the visual-mode selection yanked to text (delegating to `WolfCore::copy_visual_selection`, which blocks briefly on the captive nvim), or the empty string when not in visual mode / the selection is empty / the core is gone. The macOS front-end writes a non-empty result to `NSPasteboard`.
  - `paste(&self, text: String)` — pastes `text` into the active document via `InputEvent::Paste` (`nvim_paste`); the front-end reads the string from `NSPasteboard` first. A no-op once the core is shut down.
  - `is_visual_mode(&self) -> bool` — whether the active document is in Neovim visual mode (`Snapshot::is_visual_mode` under a read guard). Gates the Edit > Copy menu item (`validateMenuItem`). False once the core is shut down.
  - `buffer_picker(&self) -> FfiBufferPicker` — starts a buffer-picker session seeded from a BLOCKING `list_buffers()` snapshot of the captive nvim's `buflisted` buffers plus the live cwd (empty-backed when the core is gone, mirroring `command_palette`). The front-end filters per keystroke via `ranked`; see `FfiBufferPicker` below. Candidates are FIXED at open — a fresh session sees any newly-opened buffers.
  - `switch_buffer(&self, bufnr: i64)` — switches the ACTIVE window to buffer `bufnr` via `InputEvent::SwitchBuffer` (window-scoped `nvim_win_set_buf` + per-pane view restore). It resolves the active window LIVE from the snapshot (`active_win()`); when that is nonzero it calls `WolfCore::switch_buffer(active_win, bufnr)`. A no-op when the core is gone or no active window is known. Activation is placed on the HANDLE (not the session), mirroring the file picker's `open(path)`.
  - `is_markdown_active(&self) -> bool` — whether the active buffer is a Markdown file (`Snapshot::is_markdown_active` — `current_filetype == "markdown"`, fed out-of-band via `wolf_current_file`) under a read guard. Gates the View > Preview menu item + palette row (`validateMenuItem`). False once the core is shut down (the Copy/visual-mode precedent).
  - `is_preview_active(&self) -> bool` — whether the active pane is a PREVIEW pane (`Snapshot::is_preview_active` — `current_is_preview`, fed out-of-band via the `wolf_current_file` notification's 3rd bool arg) under a read guard. Gates the View > Edit Source menu item (`validateMenuItem`), the mirror of `is_markdown_active`. False once the core is shut down.
  - `open_preview(&self, mode: String) -> i64` — opens (or reuses) the Markdown preview pane for the active source buffer and returns the preview scratch buffer's number (delegating to `WolfCore::open_preview`, which blocks briefly on the captive nvim). `mode` is `"split_right"` (single-pane: new pane to the right), `"active"` (multi-pane: replace the active pane's buffer), or `"reuse_preview_pane"` (exactly two panes with the OTHER pane already a preview: bind into that OTHER preview window, leaving the active editor untouched; falls back to `"active"` when no other preview window exists) — chosen by the front-end via `PreviewSeam.placementMode`. Returns `0` when the active buffer is not Markdown, on error, or once the core is shut down.
  - `edit_source(&self, mode: String) -> i64` — Preview's INVERSE: navigates the active preview pane back to its SOURCE Markdown file and returns the source buffer's number (delegating to `WolfCore::edit_source`, which blocks briefly on the captive nvim). `mode` is `"split_left"` (single-pane: a new editor pane to the LEFT, preview stays right), `"reuse_editor_pane"` (exactly two panes with the OTHER pane a non-preview editor: bind the source into + focus that pane, falling back to the current), or `"active"` (else: replace the preview in the active pane) — chosen by the front-end via `EditSeam.placementMode`. Returns `0` when the active pane is not a preview, on error, or once the core is shut down.
  - `render_preview(&self, source_bufnr: i64) -> String` — renders the Markdown SOURCE buffer `source_bufnr` to a themed HTML document the front-end web view loads (delegating to `WolfCore::render_preview`, which blocks briefly on the captive nvim). The empty string on error / when the core is gone.
  - `open_in_browser(&self) -> String` — the "Preview in Browser" bridge: lazily starts (or reuses) the per-core loopback preview HTTP server pinned at the active Markdown buffer and returns its `http://127.0.0.1:<port>/<relpath>` URL — where `<relpath>` is the pinned file's project-root-relative path, so relative links between Markdown files resolve as the server follows them (delegating to `WolfCore::open_in_browser`, which blocks briefly on the captive nvim). The empty string when the active buffer is not Markdown, on error, or when the core is gone. The macOS front-end opens a non-empty URL in the system default browser via `NSWorkspace`.
  - `previews(&self) -> Vec<FfiPreview>` — a snapshot of the open preview panes: one opaque `FfiPreview` per window showing a `b:wolf_preview_source` scratch buffer (from `Snapshot.previews`), each joined to its source buffer's live `changedtick` (from `Snapshot.markdown_ticks`, `0` until the first `wolf_markdown_dirty`) and to its source's cwd/home-relative display path (computed here via `WolfCore::display_path` over the `PreviewInfo.source_path`, exposed as `FfiPreview.source_display_path()` for the preview pane's secondary statusbar line). Empty once the core is shut down.
  - `shutdown(&self)` — flushes the state store (bounded via `SHARED_STORE`, so shutdown never hangs), then takes the core out and shuts it down (idempotent; infallible across the bridge — any error is logged).

  **RPC timeout.** Every bridge method that reaches the captive nvim with a blocking RPC — the "blocks briefly on the captive nvim" methods above (`create_tabpage`, `current_tabpage`, `cwd_for_tabpage`, `copy_selection`, `buffer_picker`'s `list_buffers()` seed, `open_preview`, `edit_source`, `render_preview`, `open_in_browser`, and `start_file_search`'s search-root resolution) — is bounded core-side by `RPC_TIMEOUT` (default 5s, overridable via the `WOLF_RPC_TIMEOUT_MS` env var; see [`wolf-core/src/api.rs`](../wolf-core/src/api.rs)'s `block_on_rpc`). When nvim is wedged, the call returns its documented fallback (the empty `String`/`Vec`, `0`, `None`, or the configured cwd) after at most `RPC_TIMEOUT` rather than hanging the AppKit main thread indefinitely.

  The per-index handle state setters (`state_set_geometry` / `state_set_sidebar_visible` / `state_set_window_count` / `state_flush`) are GONE. State persistence is now a WHOLE-TREE write driven by free functions over the process-wide `SHARED_STORE` (opened once, lazily, over `wolf_core::state_dir()` in a `OnceLock` — all windows SHARE one store, since opening the same `state.json` dir twice would race the per-store writer threads) plus a `static SCRATCH: OnceLock<Mutex<WolfState>>` the coordinator builds up:
  - `wolf_ffi_state_snapshot_begin()` — clears the scratch tree, starting a fresh snapshot.
  - `wolf_ffi_state_snapshot_add_window(x, y, width, height: f64)` — pushes a window with the given geometry (points; AppKit bottom-left global coords) and an empty tab list.
  - `wolf_ffi_state_snapshot_add_tab(cwd: String, sidebar_visible: bool)` — pushes a tab onto the most recently added window (a defensive no-op when no window has been added yet).
  - `wolf_ffi_state_snapshot_commit()` — commits the scratch tree into `SHARED_STORE` via a whole-tree `set_snapshot` (an identical tree is a no-op there, so a redundant snapshot causes no disk churn). A no-op when no state dir resolved.
  - `wolf_ffi_state_flush() -> bool` — blocks until every pending state write has been attempted (bounded by `STATE_FLUSH_TIMEOUT` ~2 s). Returns whether everything pending flushed in time (`true` when no store exists — nothing to flush). `shutdown` and `applicationWillTerminate` also perform this flush.

- `FfiFileSearch` — an opaque handle wrapping core's `FileSearch` session (`Option`, so `start_file_search` / `start_tree_search` stay infallible) plus an interior `RefCell<wolf_core::tree::TreeIndexCache>` for the sidebar's per-directory projection. Methods:
  - `ranked(&self, query: String, max: usize) -> Vec<FfiFileEntry>` runs the ranking **in Rust** (`wolf_core::rank_matches` over the current results snapshot) and returns the top-`max` entries; it yields an empty `Vec` when the session is absent.
  - `children_of(&self, dir: String) -> Vec<FfiTreeNode>` projects the IMMEDIATE children of `dir` (`""` = the cwd root), served from a per-snapshot `wolf_core::tree::TreeIndex` cached in the interior `TreeIndexCache` keyed on the search snapshot's `version`: the index is rebuilt at most once per snapshot, and each per-directory lookup is then an O(children) borrowed-slice probe (so AppKit's numberOfChildren/child:index callback storm no longer re-scans the flat entry list per call). Projection semantics are unchanged: directories-first then files, each case-insensitive by name; dotfiles are listed and gitignored files are excluded. Empty `Vec` when the session is absent.
  - `rel_path_for(&self, abs: String) -> String` maps an absolute path to its tree-display rel-path via an **exact** entry-path match (`wolf_core::tree::rel_path_for`), or the empty string when no streamed entry matches.
  - `version(&self) -> u64` returns the current file-search snapshot version (0 when no session backs this handle; live snapshots start at 1). The sidebar's refresh gate reloads its outline only when this advances.

  Dropping the handle cancels the background traversal.

- `FfiFileEntry` — opaque; `display() -> String` (the relative display name) and `path() -> String` (the absolute path). Opaque because swift-bridge only emits `Vec<T>` support for opaque `T` — the same reason `FfiCell` is opaque.

- `FfiTreeNode` — opaque; a flattened `wolf_core::tree::TreeNode`. Accessors: `name() -> String` (the immediate component), `rel_path() -> String` (the full `/`-separated path from the cwd root), `abs_path() -> String` (the absolute path for a file; empty for a directory), and `is_dir() -> bool`. Opaque so a `Vec<FfiTreeNode>` is supported.

- `wolf_ffi_ancestors_to_reveal(rel_path: String) -> Vec<String>` — a free FFI fn (no live session needed) delegating to `wolf_core::tree::ancestors_to_reveal`: the ancestor directory rel-paths from the cwd root down to the node's parent (`"src/main.rs"` → `["src"]`, `"README.md"` → `[]`). swift-bridge emits clean `RustVec<RustString>` Swift glue for the `Vec<String>` return.

- `FfiConfig` — opaque; the resolved user-level preferences (`wolf-config.yaml`). Accessors `font_family() -> String`, `font_size() -> f64`, `line_height() -> f64` (the line-height PERCENTAGE, `130` = 130%), and `appearance() -> u8` (the appearance-mode discriminant from the `appearance` module: `0` auto / `1` dark / `2` light — mirroring `wolf_core::Appearance` and the single source of truth shared with the Swift `AppearanceMode` port). Opaque because it wraps the Rust `wolf_core::WolfConfig` and hands its `String` field out through accessors (swift-bridge does not marshal a `String` field inside a transparent struct — the same reason `FfiFileEntry` is opaque).

- `wolf_ffi_load_config() -> FfiConfig` — a free FFI fn (no live session, does NOT hang off `WolfCoreHandle` — like `wolf_ffi_ancestors_to_reveal`). It delegates to `wolf_core::preferences_dir().map(load_or_create).unwrap_or_else(default_config)`: resolve the platform preferences dir, load-or-create `wolf-config.yaml` there, and fall back to the built-in defaults when the dir cannot be resolved. Infallible across the bridge. The macOS `AppDelegate` calls it once at launch (after registering the bundled fonts, before measuring the cell metrics) and passes the result into `CellMetrics.measured(config:)`.

- `FfiState` — opaque; the saved application state as loaded by `wolf_ffi_load_state`. One method, `windows() -> Vec<FfiWindowState>` — the restored per-window entries (empty when nothing usable was saved). `FfiWindowState` is opaque so the `Vec` is supported.

- `FfiWindowState` — opaque; one saved window's geometry + tabs (a projection of `wolf_core::WindowState`). Accessors: `x()` / `y()` / `width()` / `height()` (points; a non-positive width/height is the "unset" sentinel — do not restore) and `tabs() -> Vec<FfiTabState>` (the window's ordered tabs; `FfiTabState` is opaque so the `Vec` is supported).

- `FfiTabState` — opaque; one saved tab's state (a projection of `wolf_core::TabState`). Accessors: `cwd() -> String` (`""` when never reported) and `sidebar_visible() -> bool`.

- `wolf_ffi_load_state() -> FfiState` — a free FFI fn (standalone, like `wolf_ffi_load_config`): the PRE-START restore read the front-end performs before `wolf_ffi_start`. It delegates to `wolf_core::state_dir().and_then(load_state)`: it NEVER creates or modifies the file and NEVER opens the live store (the handle does that at start); an absent/corrupt file or an unresolvable state dir all yield an empty window list — infallible across the bridge.

- `FfiFrame` — an opaque, owned, paint-ready snapshot of a single grid (the **active** grid via `read_frame`, or any grid via `read_frame_for_grid`), with every cell already resolved against the highlight table **in Rust** (reusing `HighlightTable::resolve` / `ResolvedStyle` — never re-resolved in Swift). Accessors: `cols`, `rows`, `cursor_row`, `cursor_col`, `cursor_shape` (0 = Block, 1 = Horizontal, 2 = Vertical), `cursor_cell_percentage`, `cursor_visible` (whether the cursor lives on THIS frame's grid — **per-grid**, so only the pane owning the cursor's grid draws it), `grid_id` (the grid this frame was packed from), `cursor_grid` (the grid the cursor currently lives on, so a pane can tell whether the cursor belongs to it even when it is not its own grid), `default_fg`, `default_bg`, `cursor_fill`, `cursor_glyph` (cursor colors, ported from — and kept in lockstep with — wolf-gnome's `cursor.rs`, computed against the REQUESTED grid's cell under the cursor: the `WolfCursor` theme group wins first when its bg is set — fill = theme bg, glyph = theme fg or the cell bg — else the reverse-video/mode-attr logic applies, so the themed cursor needs no new FFI surface), `cells() -> Vec<FfiCell>` (one flat, row-major handoff per frame), and the four **viewport** accessors that drive the synthetic scrollbar — `topline` (the 0-based first-visible buffer line index, as nvim's `win_viewport` reports), `botline` (one-past-the-last-visible line), `curline` (the 0-based cursor buffer line), and `linecount` (the buffer's total line count). The viewport values are read in `from_snapshot_grid` from `snapshot.windows[grid].viewport` (defaulting to all-zero when the grid has no associated window, e.g. grid 1 or a closed pane).

- `FfiLayoutIntent` — opaque; one drained layout intent (a flattened `wolf_core::LayoutIntent`). Accessors `kind() -> u8` (`intent_kind::SPLIT` / `FOCUS_DIR` / `DRAWER_OPEN`), `orientation() -> u8` (for a SPLIT: `orientation::HORIZONTAL` / `VERTICAL`; 0 otherwise), `dir() -> u8` (for a FOCUS_DIR: `focus_dir::LEFT` / `RIGHT` / `UP` / `DOWN`; 0 otherwise), `from() -> i64` (the origin window handle), and `win() -> i64` (for a SPLIT: the new window handle; for a DRAWER_OPEN: the newly opened drawer window handle; 0 otherwise). Opaque because swift-bridge only emits `Vec<T>` support for opaque `T` — the same reason `FfiTreeNode` is opaque.

- `FfiCommand` — opaque; one drained command (a `wolf_core::Command`). Single accessor `kind() -> u8` (a `command_kind` discriminant). Opaque for the same `Vec<T>` reason as `FfiLayoutIntent` / `FfiTreeNode`. ## The wake (Swift-free link path)

`wolf-core` fires a `WakeFn` on each `flush`; the front-end must marshal it onto the AppKit main thread and trigger a repaint. Rather than an `extern "Swift"` symbol — which a Rust-only integration test could never resolve at link time — the wake is a globally **registered** `extern "C"` function pointer:

```c
void wolf_ffi_set_wake(void (*wake)(uint64_t token)); // generated/wolf_ffi_wake.h
```

Each callback carries the firing core's per-PROJECT wake **token** (a `u64`, minted in `wolf_ffi_start` from the `NEXT_WAKE_TOKEN` counter and captured by the core's `WakeFn` closure), so a SINGLE process-global callback can route each wake to the right PROJECT WITHOUT clobbering — the multi-project wake-routing layer. The token identifies a PROJECT (one captive Neovim shared by N views); the front-end fans the wake out to the project's CURRENT view (other views hold their last paint). The wake fires on a tokio worker thread and must not touch the `!Send` handle, so identity crosses the boundary as a plain `Send` scalar. Swift's `WakeBridge` registers ONE `DispatchQueue.main.async { WindowRegistry.shared.project(for: token)?.onWake() }` thunk once at startup (capturing only the global registry, so it stays `@convention(c)`), where `Project.onWake()` drives its `currentView`. The Rust integration test registers its own recording callback; the wake is a harmless no-op when unregistered, and `wolf_ffi_start` links and runs with no Swift runtime present.

There is a **second**, parallel registered wake for the file picker:

```c
void wolf_ffi_set_filesearch_wake(void (*wake)(uint64_t token)); // generated/wolf_ffi_wake.h
```

It is a separate global `extern "C"` callback (its own `registered_filesearch_wake(token)`), fired after each streaming traversal batch of a `start_file_search` session, so the picker can refresh its results independently of editor repaints (Swift's `PickerWakeBridge` routes `token` to `WindowRegistry.shared.project(for: token)?.onPickerWake()`, which refreshes the current view's picker). It is otherwise identical in shape to the editor wake — token-carrying, no-op when unregistered.

There is a **third** parallel registered wake for the file-tree sidebar:

```c
void wolf_ffi_set_tree_wake(void (*wake)(uint64_t token)); // generated/wolf_ffi_wake.h
```

It is its own global `extern "C"` callback (`registered_tree_wake(token)`), fired after each streaming traversal batch of a `start_tree_search` session, so the sidebar can rebuild its outline rows independently of the picker and editor repaints (Swift's `TreeWakeBridge` routes `token` to `WindowRegistry.shared.project(for: token)?.onTreeWake()`, which refreshes the current view's sidebar). The sidebar's current-file reveal + bold rides the **editor** wake instead (the controller's `onRenderWake()` calls `FileTreeView.onRenderWake()` right after `setNeedsDisplay`, reading `current_file()`), because a `current_file` change is delivered on the render wake, not a separate traversal batch. The tree wake is otherwise identical in shape — token-carrying, no-op when unregistered.

## Generated bindings

The committed `generated/` tree is the swift-bridge output plus two hand-written files:

- `SwiftBridgeCore.swift` / `SwiftBridgeCore.h` — the shared swift-bridge runtime.
- `wolf-ffi.swift` / `wolf-ffi.h` — this crate's bridge.
- `wolf_ffi_wake.h` — the hand-written wake-registration declaration.
- `module.modulemap` — exposes the C headers to Swift as the `WolfFFI` module (matched by the `import WolfFFI` line `gen_bindings` prepends to the generated Swift, and by the `swift_interop_hint` in `BUILD.bazel`).

The six tabpage methods (`create_tabpage` / `current_tabpage` / `active_tabpage` / `cwd_for_tabpage` / `set_current_tabpage` / `close_tabpage`) are all ADDITIVE `WolfCoreHandle` methods (no discriminant table changed), so their regen only touched `wolf-ffi.swift` / `wolf-ffi.h`; because they ride the EXISTING editor render wake (no new wake channel), `wolf_ffi_wake.h` stays **byte-identical**. The Markdown-preview surface is the same story: the four ADDITIVE `WolfCoreHandle` methods (`is_markdown_active` / `open_preview` / `render_preview` / `previews`), the new opaque `FfiPreview` type, and the appended `command_kind::PREVIEW = 18` only change `wolf-ffi.swift` / `wolf-ffi.h` (regenerated + committed); preview rides the existing editor render wake, so `wolf_ffi_wake.h` stays **byte-identical**. The later ADDITIVE `FfiPreview.source_display_path()` accessor (the preview pane's secondary statusbar line) is likewise regen-only — an added extern bridge fn touching just `wolf-ffi.swift` / `wolf-ffi.h`, no new wake. The **Edit** command surface is the same story: the two ADDITIVE `WolfCoreHandle` methods (`is_preview_active` / `edit_source`) and the appended `command_kind::EDIT = 19` only change `wolf-ffi.swift` / `wolf-ffi.h` (regenerated + committed), and Edit rides the existing editor render wake, so `wolf_ffi_wake.h` stays **byte-identical**. The appearance surface (the additive `WolfCoreHandle::set_background` method + the `FfiConfig::appearance()` accessor) is the same shape: its regen touched only `wolf-ffi.swift` / `wolf-ffi.h`, leaving `wolf_ffi_wake.h` unchanged. The **Preview in Browser** surface is the same story once more: the single ADDITIVE `WolfCoreHandle::open_in_browser(&self) -> String` method and the appended `command_kind::PREVIEW_IN_BROWSER = 21` only change `wolf-ffi.swift` / `wolf-ffi.h` (regenerated + committed), and it rides the existing editor render wake, so `wolf_ffi_wake.h` stays **byte-identical**.

Regenerate after changing the bridge:

```sh
bazel run //crates/wolf-ffi:gen_bindings   # rewrites generated/, then commit
```

`gen_bindings` writes in-tree (it reads `BUILD_WORKSPACE_DIRECTORY`, which only `bazel run` provides — a genrule cannot write into the source tree). After changing Cargo dependencies, repin:

```sh
CARGO_BAZEL_REPIN=1 bazel build //crates/wolf-ffi:wolf_ffi   # then commit lockfiles
```
