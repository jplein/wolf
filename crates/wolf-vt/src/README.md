# wolf-vt/src

The crate's two modules. The crate-level view, how it links and how it is tested, is in [`../README.md`](../README.md).

## Files

#### `lib.rs`

Purpose: the safe API. A `Terminal` feeds program output through libghostty-vt's VT parser and reads back the viewport, and encodes key, mouse, paste and focus input as the program expects it.

**Public API**

- `Terminal::screen()` returns the viewport's cells, cursor and colours, with `dirty` and `row_dirty(row)` saying what changed since the previous call. Reading consumes that change state, so the next call reports only later changes.
- A `Cell`'s `fg` and `bg` are `None` when it has no colour of its own, never a black `Rgb`, and are not swapped for `inverse`. `Screen.cursor` is `None` while the viewport is scrolled away from the cursor.
- `set_palette(None)` and `set_cursor_color(None)` restore libghostty-vt's built-ins. Cells keep palette indices, so a palette change recolours text already on screen.
- `pwd()` is the report as the program sent it, URI or path.
- `encode_key` and `encode_mouse` read the terminal's modes on every call; the mouse encoder converts pixels with the cell size of the last `resize`. `paste_encode` and `focus_encode` are free functions.

**Decisions**

- The C callbacks only push an `Effect` onto a queue the `Terminal` owns, whose address is the userdata, and the caller drains it with `take_effects` after a mutating call. A callback runs inside a library call, so it must not write to a pty or take a lock.
- Alt is the encoder's alt on every platform (`MACOS_OPTION_AS_ALT`), so alt+`x` sends `ESC x` on macOS as on Linux.

#### `ffi.rs`

Purpose: private `extern "C"` declarations of exactly the libghostty-vt subset `lib.rs` calls.

**Decisions**

- Hand-written rather than generated by bindgen: the subset is small, and generating it would put libclang in both builds. Every name, value and layout is checked against `include/ghostty/vt/*.h` in the pinned release tarball, and a new declaration must be too: a wrong constant compiles, links, and fails only at run time. On Linux the headers are under `$WOLF_GHOSTTY_VT_DIR/include/ghostty/vt/`. On macOS no build exposes them, so extract the source tarball [`@ghostty_vt_src`](../../../bazel/ghostty-vt/README.md) pins, which Bazel's repository cache already holds.
- `GhosttyResult` and every `GHOSTTY_ENUM_TYPED` enum are C `int`, so they are `c_int` constants rather than Rust enums, in which a value the library adds would be undefined behaviour.
