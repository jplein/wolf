# wolf-vt/src

The crate's two modules. The crate-level view, how it links and how it is tested, is in [`../README.md`](../README.md).

## Files

#### `lib.rs`

Purpose: the safe API. A `Terminal` feeds program output through libghostty-vt's VT parser and reads back the viewport's cells, the cursor and the colours.

**Public API**

- `version() -> String` — the linked release, read at run time from `ghostty_version()`.
- `Terminal::new(cols, rows)`, `feed`, `resize(cols, rows, cell_width_px, cell_height_px)`, `size`, `cursor`, `set_default_colors`, `foreground`, `background`, `palette`, `screen`. Sizes are above zero.
- `Screen` — `cols`, `rows`, `cell(col, row)` and `row_text(row)`, row-major over the viewport. `row_text` reads an empty cell and a wide character's spacer as a space and trims trailing spaces.
- `Cell` — `text`, the grapheme cluster, `""` when empty; `fg` and `bg`, resolved through the palette.
- `Cursor` — 0-based in the active area; `visible` is `DEC` mode 25.
- `Rgb` — laid out as `GhosttyColorRgb`. `Error::code()` is the `GhosttyResult`.

**Decisions**

- A cell's `fg` or `bg` is `None` when the cell has no colour of its own, never a black `Rgb`: the painter then takes the terminal's default, which `foreground()` and `background()` report.

**Gotchas**

- `feed` drops the reply a query asks for, such as a device status report, because the binding registers no `WRITE_PTY` callback.
- `screen()` takes `&mut self` because it updates the render state, which consumes libghostty-vt's dirty tracking. Anything that later reads dirty rows must take them from that same update.

#### `ffi.rs`

Purpose: private `extern "C"` declarations of exactly the libghostty-vt subset `lib.rs` calls.

**Decisions**

- Hand-written rather than generated by bindgen: the subset is small, and generating it would put libclang in both builds. Every name, value and layout is checked against `include/ghostty/vt/*.h` in the pinned release tarball, and a new declaration must be too: a wrong constant compiles, links, and fails only at run time.
- `GhosttyResult` and every `GHOSTTY_ENUM_TYPED` enum are C `int`, so they are `c_int` constants rather than Rust enums, in which a value the library adds would be undefined behaviour.
