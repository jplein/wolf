# wolf-core/src

The `wolf-core` source modules. Each is a single file (not a subdirectory). Data flows: `nvim` spawns the captive Neovim and hands its `redraw` stream to a `redraw::RedrawHandler`, which folds events into the `render` snapshot (and parses the Neovim→shell `wolf_layout` intents into `layout::LayoutIntent`s on a sibling queue); `input` translates abstract events back into RPC; `api` ties it together behind the FFI-shaped `WolfCore`. The file picker adds three more modules: `mru` (the SQLite most-recently-used cache), `files` (the async streaming file-list traversal + the `FileSearch` session), and `rank` (the pure fuzzy-match/ranking function the front-end calls to order results). The sidebar CONTENT search adds two more: `search` (the `rg --json` subprocess + the streaming `SearchSession`, sibling of `files`) and `search_tree` (the pure, GUI-free projection + context-window display math, sibling of `tree`).

Dependency order: `render` → `layout` → `state` → `input` → `nav_history` → `redraw` → `nvim` → `files` → `search` → `mru` → `rank` → `tree` → `search_tree` → `api`. (`layout` is the pure intent types parsed by `redraw`; `nav_history` is the pure per-pane back/forward navigation model — it depends only on `render::WinBuffer`, and `redraw` FOLDS a derived per-window target into it, so it sits after `render` and before `redraw`; `state` is the application-state persistence layer (`StateStore`, whole-tree `set_snapshot`); it is no longer wired into `redraw`/`api` (the front-end owns all writes); `files` uses `redraw::WakeFn`; `mru`, `rank`, and `tree` all build on `files::FileEntry` — `FileEntry`'s home is `files.rs`, re-exported from `mru` and the crate root. `tree` is the pure hierarchical projection of the flat file list, shared by every front-end's file-tree sidebar. `buffer_picker` is a pure `palette`-shaped module reusing `rank::rank_matches` over `files::FileEntry` for the buffer picker; `config` and `markdown` (the pure Markdown → themed-HTML preview renderer, used by `nvim::render_preview`) both stay fully standalone.)

## `config.rs`

The user-level preferences reader — resolves the platform preferences directory and reads (or creates) the `wolf-config.yaml` file. Standalone (it does not touch `WolfCore`, the snapshot, or nvim) and GUI-toolkit-free; the macOS front-end reaches it over the `wolf-ffi` bridge. Has its own `#[cfg(test)] mod tests`, mirroring `rank.rs`/`tree.rs`.

- `WolfConfig { font_family: String, font_size: f64, line_height: f64, appearance: Appearance }` — the resolved config. `line_height` is stored as the PERCENTAGE of the font size (`130` = 130%). The on-disk form is a private serde `ConfigFile { config: ConfigSection }`, where `ConfigSection` is `#[serde(rename_all = "kebab-case")]` so it maps to `font-family` / `font-size` / `line-height` / `appearance` under a top-level `config:` key.
- `Appearance` (`Auto` / `Dark` / `Light`, `#[serde(rename_all = "kebab-case")]` → `auto` / `dark` / `light`; derives `Copy` + `PartialEq`) — the app appearance mode surfaced to the front-end. `Auto` (the built-in default via `DEFAULT_APPEARANCE`) follows the live OS appearance; `Dark` / `Light` force one. The `appearance` field carries `#[serde(default = "default_appearance")]`, so a config predating the key parses to `Auto` (preserving the required font fields) rather than failing the section; a PRESENT-but-invalid value (e.g. `purple`) fails the enum, so the whole section fails and `load_or_create` returns the defaults, leaving the user's file untouched.
- `preferences_dir() -> Option<PathBuf>` — honors a `WOLF_CONFIG_DIR` env override FIRST (a determinism/test hook); otherwise macOS `dirs::preference_dir()?.join("Wolf")` (`~/Library/Preferences/Wolf`), Linux `dirs::config_dir()?.join("wolf")` (`~/.config/wolf`). Both platform paths resolve in code even though only macOS consumes prefs this increment.
- `default_config() -> WolfConfig` — font-family `"iA Writer Mono S"`, line-height `130`, and a platform-specific font-size via `cfg!(target_os = "macos")` (14 macOS / 10 Linux).
- `load_or_create(dir: &Path) -> WolfConfig` — **infallible** (defaults-on-error). Reads `<dir>/wolf-config.yaml`: absent → create the parent + write the serialized defaults, return defaults; present + parses → the parsed config; present + malformed / wrong-shape → `tracing::warn!` + defaults, **never clobbering** the user's file (it only writes when the file is absent). This graceful-degradation posture keeps a broken hand-edit from being silently overwritten.

The schema:

```yaml
config:
  font-family: "iA Writer Mono S"
  font-size: 14
  line-height: 130
  appearance: auto
```

## `liveness.rs`

The captive-nvim LIVENESS state model (crash + stall detection), a single lock-free `Alive` / `NotResponding` / `Dead` state the supervisor (crash) and `block_on_rpc`'s timeout path (stall) write from tokio worker threads and the front-ends read from their own UI thread — the FFI accessor on the AppKit main thread, and `WolfCore::liveness()` directly on the GTK main thread, where `wolf-gnome` reads it at the top of every wake. GUI-free, with its own `#[cfg(test)] mod tests` (15 transition/wake/terminal-`Dead`/no-downgrade unit cases).

- `Liveness { Alive, NotResponding, Dead }` (derives `Debug, Clone, Copy, PartialEq, Eq`; re-exported from the crate root) — the STABLE discriminants `0 / 1 / 2` the FFI `liveness` module mirrors as `ALIVE` / `NOT_RESPONDING` / `DEAD`. `Alive`: responding normally. `NotResponding`: a synchronous RPC elapsed the timeout budget (a stall) — recoverable (the next successful RPC clears it, or the user restarts). `Dead`: process death (stdout EOF, clean or crash) — TERMINAL, only `reset_alive` (the restart path) leaves it. `to_u8(self) -> u8` and `from_u8(v: u8) -> Liveness` (any unknown byte clamps to `Dead`, the safe terminal state).
- Storage is an `Arc<std::sync::atomic::AtomicU8>` (never contends the snapshot lock), mutated ONLY through the free transition helpers over `&AtomicU8` + `&WakeFn`, each firing the wake ONLY on an actual state change: `get(state) -> Liveness`; `mark_dead(state, wake)` (unconditional store `Dead`, wake iff it was not already `Dead` — terminal); `mark_not_responding(state, wake)` (`compare_exchange(Alive → NotResponding)` ONLY — never downgrades `Dead`, never re-fires when already `NotResponding`); `reset_alive(state, wake)` (unconditional store `Alive`, the ONLY exit from `Dead`, wake iff it changed — the RESTART path). The RPC-success auto-clear (`compare_exchange(NotResponding → Alive)`, never touching `Dead`) is a CALL-SITE guard in `api.rs`'s `block_on_rpc`, NOT `reset_alive` (which is unconditional and used only by restart).

## `state.rs`

The application-state persistence layer — resolves the platform state directory, reads/writes the pretty-printed `state.json` (a `version: 1` header wrapping a TREE of windows: each window carries geometry plus its ordered list of tabs, and each tab carries its own cwd, sidebar visibility, and an OPTIONAL full pane-split layout tree), and renders a saved pane tree back into the wire shape Neovim's rebuild helper decodes. GUI-toolkit-free, modeled on `config.rs`. Both front-ends own ALL writes and submit the whole tree via `set_snapshot`: macOS reaches the module over the `wolf-ffi` bridge (its coordinator walks its live windows/tabs), and `wolf-gnome` consumes it directly (one window, one tab; see [`wolf-gnome/README.md`](../../wolf-gnome/README.md), "Application state persistence"). Core no longer mirrors cwd into a store (`attach_state_store` is gone). Documented in full in the crate [`README.md`](../README.md) ("Application state — `state`"); the module internals:

- `STATE_FILE_NAME` (`"state.json"`, `pub`); private consts for the sibling tmp name, the schema version (`1`), the write-coalesce delay (~100 ms), and the writer's idle re-check cadence (~500 ms).
- `TabState { cwd: String, sidebar_visible: bool, layout: Option<PaneNode> }` / `WindowState { x, y, width, height: f64, tabs: Vec<TabState> }` / `WolfState { windows: Vec<WindowState> }` — the public schema types (all derive `Clone, Debug, Default, PartialEq`; the serde-bearing ones also `Serialize, Deserialize`). `TabState::default()` is empty cwd + `sidebar_visible: true` + `layout: None`; `WindowState::default()` is zero geometry + no tabs. There is NO `#[serde(default)]` on `tabs`, so an old FLAT (pre-tabs) file carrying a window-level `cwd`/`sidebar_visible` and no `tabs` fails deserialization and is silently ignored (no migration path). A private serde wrapper `StateFile { version, windows }` is the on-disk shape.
- `PaneOrientation` (`Horizontal` / `Vertical`, `#[serde(rename_all = "snake_case")]` → the JSON strings `"horizontal"` / `"vertical"`; derives `Copy` + `Eq`) and `PaneNode` (`#[serde(tag = "type", rename_all = "snake_case")]` internally-tagged enum) — the per-tab pane-split schema (re-exported at the crate root, mirroring the front-end `SavedPaneNode`). `PaneNode::Leaf { path: String, preview: bool }` is a single pane showing the buffer at `path` (`""` for an unnamed buffer, JSON `{"type":"leaf","path":…,"preview":…}`); when `preview` is `true` the pane is a Markdown PREVIEW and `path` is the SOURCE Markdown file's ABS path (restored via `wolf_preview_file`, not `:edit`). `preview` carries `#[serde(default)]`, so an old v1 file without it loads with `preview = false` (STATE_VERSION stays `1`). `PaneNode::Split { orientation: PaneOrientation, weights: Vec<f64>, children: Vec<PaneNode> }` is an n-ary split with a per-child `weights` vector parallel to `children` in DFS order (JSON `{"type":"split","orientation":…,"weights":[…],"children":[…]}`). A `.vertical` split divides WIDTH (side-by-side), a `.horizontal` split divides HEIGHT (stacked); the discriminant table (`horizontal == 0`, `vertical == 1`) matches the macOS `PaneTree` / `wolf-ffi` orientation byte.
- `TabState.layout: Option<PaneNode>` carries `#[serde(default, skip_serializing_if = "Option::is_none")]`, so it is OMITTED from `state.json` ONLY for an empty-state (unnamed, non-preview) lone pane — a lone pane showing a file persists a single `leaf` and a lone preview pane persists a single `leaf` with `preview: true` — and an old v1 file that predates the field loads with `layout: None`; `STATE_VERSION` STAYS `1` (the field is purely additive/back-compatible via `serde(default)`, and this behavior change only affects WHEN a layout is written — the wire format is unchanged since a single `.leaf` was always representable).
- `state_dir() -> Option<PathBuf>` — `WOLF_STATE_DIR` override first, else macOS `dirs::data_dir()/"Wolf"`, else Linux `dirs::state_dir().or_else(dirs::data_dir()).map(|d| d.join("wolf"))` — per-OS `cfg` like `preferences_dir()`.
- `swap_dir_for(cwd: &Path) -> Option<PathBuf>` (`pub`, `#[must_use]`) — the DURABLE, Wolf-owned, per-project SWAP directory for the crash-recovery of unsaved edits: `state_dir()/swap/<stable-hex-hash-of-cwd>` (a plain `std::hash::DefaultHasher` of the assumed-canonical project `cwd`, rendered as hex — not cryptographic, just a stable, collision-unlikely name). STABLE + DETERMINISTIC, so the SAME project reuses the SAME swap dir across respawns AND separate Wolf processes (letting a fresh nvim find a dead nvim's swap), while DISTINCT projects get distinct dirs. `None` only when `state_dir()` cannot be resolved; `WolfCore::start` then falls back to an ephemeral swap dir under the nvim state root (documented, no panic). Wired into nvim via `NvimConfig.swap_dir` → the `WOLF_SWAP_DIR` env var → init.lua's `'directory'`. Its stability is unit-tested by `tests/state_unit.rs`.
- `load_state(dir) -> Option<WolfState>` — infallible, STRICTLY read-only (never creates/rewrites/deletes): absent file → silent `None` (debug log); any read/parse/shape/version failure — including the old flat format that lacks `tabs` — → `tracing::warn!` + `None`, bytes preserved verbatim. Unknown extra fields tolerated (no `deny_unknown_fields`).
- `rebuild_layout_spec(node: &PaneNode) -> String` (`pub`, `#[must_use]`) + the private recursive `spec_value(node) -> serde_json::Value` — renders a `PaneNode` into the JSON string `runtime/nvim/init.lua`'s `_G.wolf_rebuild_layout` decodes, i.e. the exact input `WolfCore::rebuild_layout` takes. **This is NOT `PaneNode`'s serde shape**, and that is the whole reason the function exists: the Lua helper reads a different, terser document — a leaf is `{"leaf": true, "path": …, "preview": …}` and a split is `{"orientation": "v" | "h", "weights": […], "children": […]}`, where `"v"` is `PaneOrientation::Vertical` (side by side) and `"h"` is `Horizontal` (stacked) — whereas the serde form is the internally-tagged `{"type": "leaf" | "split", …}` with `"vertical"` / `"horizontal"` spelled out. It is the Rust twin of the macOS `PaneLayoutCodec.specJSON`, and it lives here — next to the type it renders, inside the crate that already depends on `serde_json` — rather than being re-derived once per front-end; a hand-rolled renderer is a real correctness hazard, since an unescaped `"` in a buffer path makes the Lua side's `pcall(vim.json.decode, …)` fail and the whole restore silently abort. Children, and therefore LEAVES, are emitted in DFS order — exactly the order `rebuild_layout` returns window handles in, so a front-end can zip them onto its own DFS leaf order. TOTAL: it cannot fail and never panics. A NON-FINITE weight (NaN, ±inf) is emitted as `0.0`, because `serde_json::Number::from_f64` rejects one and an unsanitized value would become `null` and change the document's SHAPE; the substitution is purely cosmetic, since `wolf_rebuild_layout` produces the window count and topology only and never reads `weights`. Serializing an already-built `Value` cannot fail either, but the `Err` arm degrades to `"{}"` rather than panicking — precisely what the Lua side's `pcall` failure path yields, i.e. a no-op rebuild returning no handles. PURELY ADDITIVE: no existing signature, type or behaviour changed, `STATE_VERSION` stays `1`, and the on-disk schema is untouched.
- `StateStore` — `Clone` over an `Arc<StoreInner>` (`dir` + a `parking_lot::Mutex<StateCell>` + a `Condvar`; `StateCell` is the in-memory `WolfState` plus `generation`/`written` counters). `open(dir)` loads via `load_state` (defaults on `None`) and spawns the named `wolf-state-writer` thread (a spawn failure only warns — the store still serves reads/mutations). `set_snapshot(next: WolfState)` replaces the whole tree: under the mutex it compares `next` against the current tree and — ONLY when it differs — swaps it in, bumps `generation`, and notifies the writer (an identical snapshot is a no-op, so a redundant re-submit causes no disk churn). `flush(timeout) -> bool` waits until `written >= generation`. The old granular per-index setters (`set_geometry`/`set_cwd`/`set_sidebar_visible`/`truncate_windows`) and the shared `mutate` body are GONE — the front-end owns the whole tree.
- `writer_loop` — waits on the condvar for a pending generation, sleeps the coalesce delay with the lock DROPPED, snapshots the latest state + target generation under a brief lock, then performs the atomic write (`create_dir_all` → `to_string_pretty` → write `state.json.tmp` → rename) with NO lock held, advances `written`, and notifies flushers. Write errors warn but still advance `written` (flush cannot hang on a read-only disk). While idle it re-checks every idle-poll whether it holds the last `Arc` and exits only when it timed out, every front-end handle is gone, AND nothing is pending (the pending check is re-read under the lock, so a mutate-then-drop by the last handle is still written).

Opening the same directory twice in one process is unsupported (two writer threads would race on the shared tmp file — clone one store instead); concurrent Wolf processes are last-writer-wins (each write is atomic, so the file is never torn).

## `render.rs`

The toolkit-agnostic render-state model — the in-memory description of what should be drawn. Nothing here references a GUI toolkit or draws pixels.

Key types:

- `Rgb { r, g, b }` — `Rgb::from_packed(u32)` unpacks Neovim's `0xRRGGBB`.
- `HlAttr` — one highlight group's attributes (`fg`/`bg`/`special` as `Option<Rgb>`, plus `bold`/`italic`/`underline`/`undercurl`/`strikethrough`/ `reverse`).
- `DefaultColors { fg, bg, special }` — from `default_colors_set`.
- `ResolvedStyle` — a highlight resolved against defaults, `reverse` already applied (fg/bg swapped), ready to paint.
- `HighlightTable { defaults, attrs }` — `new()`, `define(hl_id, HlAttr)`, `set_defaults(DefaultColors)`, and `resolve(hl_id) -> ResolvedStyle` (`hl_id == 0` resolves to the defaults).
- `Cell { text: String, hl_id: u64 }` — `text` is one grapheme cluster, or `""` for the trailing placeholder cell of a double-width character.
- `Grid { cols, rows, .. }` — `new`, `resize`, `clear`, `cell(row, col)`, `set_cell(row, col, Cell)` (out-of-bounds ignored), `scroll(top, bot, left, right, rows)` (positive `rows` = content moves up), and `row_text(row)` (empty cells render as a single space to preserve column alignment).
- `CursorShape` (`Block` | `Horizontal` | `Vertical`), `ModeInfo { name, shape, cell_percentage, attr_id }`, `Cursor { grid, row, col, mode_idx }` — `grid` is the grid id the cursor lives on (the active window grid; set by `grid_cursor_goto`).
- `Viewport { topline, botline, curline, linecount }` (all `u64`, as nvim's `win_viewport` reports; `topline` is the 0-based first-visible buffer line index, `botline` is one-past-the-last-visible line, `curline` is the 0-based cursor buffer line).
- `WinInfo { grid, win: i64, start_row, start_col, width, height, viewport, hidden }` — per-window layout + viewport, learned from `win_pos`/`win_viewport`. Keyed in `Snapshot.windows` by the window's grid id; `win` is the Neovim window handle as an `i64` (the same form used for `nvim_set_current_win`/`win_close` later), decoded by `redraw.rs`'s `ext_handle`. `hidden` is now effectively ALWAYS `false` / dead (OD8): a `win_hide` (most notably a tabpage switch) REMOVES the window from `Snapshot.windows` rather than flagging it, so a window either IS in `windows` (visible on the current tabpage) or is absent. The field is kept only to avoid churning the FFI + Swift surface.
- `ThemeGroup { fg: Option<Rgb>, bg: Option<Rgb> }` and `ThemeColors { cursor: ThemeGroup, titlebar: ThemeGroup }` — the effective colors of the optional `WolfCursor` / `WolfTitlebar` app-theme highlight groups (all-`None` default = group absent/cleared; both `Copy` + `Default` + `PartialEq`).
- `TabFiles { active: Option<PathBuf>, files: Vec<PathBuf> }` (derives `Clone, Debug, Default, PartialEq, Eq`) — the Tier-1 open-file mirror for ONE tabpage: `files` are its file-backed (non-empty, non-preview) open buffer paths and `active` its active buffer's path (`None` when unnamed), paths canonicalized (raw fallback). Maintained out-of-band via the `wolf_open_files` notification (the `WolfOpenFiles` autocmds), wholesale-replaced per tabpage in `Snapshot.open_files`, and read (per tabpage handle) by `WolfCore::open_files_for_tabpage` BEFORE a crash-restart so the front-end can reopen a crashed nvim's files. **Known Tier-1 limitation:** `files` is the instance-GLOBAL `getbufinfo({buflisted=1})` set attached to every tabpage (only `active` is per-tabpage), so a multi-view restart reopens every project file in every view. Re-exported from the crate root.
- `WinBuffer { bufnr: i64, path: Option<PathBuf>, is_terminal: bool, is_drawer: bool }` (derives `Clone, Debug, Default, PartialEq, Eq`) — what ONE window is showing, the PARALLEL companion to `Snapshot.buffers` (which stays byte-identical for its existing consumers). Where `buffers` carries only a NAMED window's path, this carries everything the per-pane navigation history needs to derive a `nav_history::NavTarget`: the buffer number (so an unnamed buffer keeps an identity across navigation), the canonicalized `path` (`None` for an UNNAMED buffer — unlike `buffers`, which omits unnamed windows entirely), `is_terminal` (`vim.bo[buf].buftype == "terminal"`), and `is_drawer` (the per-project terminal DRAWER — `b:wolf_terminal` on the buffer OR `w:wolf_terminal` on the window — which is EXCLUDED from history, while a `:terminal` in a normal split is not). Learned from the (now 5-element) `wolf_buffers` tuple. Re-exported from the crate root.
- `PreviewInfo { source_bufnr: i64, source_path: PathBuf, source_full_width: bool }` (derives `Clone, Debug, Default, PartialEq, Eq`) — where a preview pane's source Markdown lives, learned from the `wolf_preview` notification: the SOURCE Markdown buffer's number (keys into `Snapshot.markdown_ticks` for the live tick), its absolute path, and `source_full_width` — whether that SOURCE buffer carries a truthy `b:wolf_full_width` (the 4th tuple element of the `wolf_preview` emit). The front-end frames the preview pane's web view to the capped+centered rect when `false`, or the full inset pane when `true`. Re-exported from the crate root.
- **Native command line (`ext_cmdline`).** `CmdlineChunk { text: String, attr_id: u64 }` is one styled run of command-line text; `Cmdline { active, firstc, prompt, content: Vec<CmdlineChunk>, pos, indent, level }` is the folded command line (`active` between `cmdline_show` and `cmdline_hide`; `firstc` the `:` / `/` / `?` prefix; `pos` a BYTE offset into the concatenated text; `level` the recursion level). `Cmdline::text()` concatenates every chunk's text (the front-ends flatten to plain text over the FFI — the caret contract is byte-based). All derive `Clone, Debug, Default, PartialEq, Eq`.
- **Completion popup (`ext_popupmenu`).** `PumItem { word, kind, menu, info }` is one completion item (`word` the primary label, `kind` the single-letter hint); `Pum { visible, items: Vec<PumItem>, selected: i64, row: i64, col: i64, grid: i64 }` is the folded popup. `grid == -1` anchors the popup to the command line, with `col` a BYTE offset into the cmdline text; otherwise `grid`/`row`/`col` locate it on an editor window grid. `selected == -1` means no selection.
- **Message toast (`ext_messages`).** `ToastChunk { text: String, attr_id: u64 }` is one styled run of message text (UNLIKE `CmdlineChunk`, the toast keeps its `attr_id` across the FFI — message color is load-bearing, resolved against the `HighlightTable` at pack time like a cell, OD1); `Message { kind: String, id: i64, lines: Vec<Vec<ToastChunk>> }` is one folded `msg_show` / `msg_history_show` entry (a message spans one or more visual `lines`, content split on `"\n"`; `id` is `0` for none / a non-integer id per OD7); `Toast { visible, messages: Vec<Message> }` accumulates messages in arrival/history order. Helpers: `Toast::lines() -> Vec<Vec<ToastChunk>>` (every message's lines flattened, OWNED), `Toast::kind() -> String` (the last message's kind, or `""`), and `Toast::is_prompt() -> bool` (true when the last kind is `"confirm"` — a real prompt that must NOT be dismissed by a passing input).
- **Multigrid model.** Under `ext_multigrid` the snapshot holds MULTIPLE grids: `Snapshot { grids: HashMap<u64, Grid>, windows: HashMap<u64, WinInfo>, highlights, cursor, mode_infos, active_win: Option<i64>, current_tabpage: i64, current_file, buffers: HashMap<i64, PathBuf>, win_buffers: HashMap<i64, WinBuffer>, theme, current_filetype: String, current_is_preview: bool, current_is_full_width: bool, full_width: HashMap<i64, bool>, previews: HashMap<i64, PreviewInfo>, markdown_ticks: HashMap<i64, u64>, open_files: HashMap<i64, TabFiles>, tab_cwds: HashMap<i64, PathBuf>, cmdline: Cmdline, pum: Pum, toast: Toast, seq }`.
  - `grids` always contains the outer grid (`OUTER_GRID_ID = 1`, the global grid Neovim resizes and where the command line/messages live); editor window content lives on grids `>= 2`. Grid 1 is never painted as window content.
  - `windows` maps each window's grid id to its `WinInfo`.
  - `active_win` is the active Neovim window handle, or `None` if not yet known. It is updated out-of-band via the `wolf_active_win` notification (the `WinEnter` autocmd; see `redraw.rs`), so the front-end can mark the active pane. (`Snapshot::new` starts it at `None`.)
  - `current_tabpage: i64` is the current tabpage handle (`0` = unknown), updated out-of-band via the `wolf_tabpage` notification (the `TabEnter`/`TabNewEntered` autocmds; see `redraw.rs`), mirroring `active_win`. Under the project/tabpage-per-view model each macOS view binds one tabpage; the front-end uses this as the cheap refocus-rebind gate (only the current tabpage's windows are in `windows`). A `current_tabpage` change does NOT bump `seq`.
  - `current_file: Option<PathBuf>` is the absolute, canonicalized path of the buffer currently being edited (or `None` for an unnamed buffer), updated out-of-band via the `wolf_current_file` notification (see `redraw.rs`).
  - `buffers: HashMap<i64, PathBuf>` is the PER-WINDOW buffer-path map, keyed by the Neovim window handle (`WinInfo.win`), each an absolute canonicalized buffer path (unnamed windows are ABSENT). Updated out-of-band via the `wolf_buffers` notification (see `redraw.rs`), WHOLESALE-REPLACED on each emit so stale/closed windows vanish; the macOS front-end joins a grid → window → buffer path via `WolfCore::pane_status`. Defaults to empty; a `buffers` change does NOT bump `seq`. Its shape and contents are UNCHANGED by the navigation-history work — the extra `wolf_buffers` tuple elements feed the parallel map below instead, so its only production consumer (`pane_status`) cannot regress.
  - `win_buffers: HashMap<i64, WinBuffer>` is the PARALLEL per-window buffer map, keyed by the same Neovim window handle but `WinBuffer`-valued: the bufnr, the canonicalized path (`None` for an UNNAMED buffer — unlike `buffers`, which OMITS unnamed windows), and the two terminal flags. Preview scratch panes are EXCLUDED (they are in `previews` instead), which is what keeps the two maps DISJOINT. Filled from the SAME `wolf_buffers` notification in the same pre-guard pass and WHOLESALE-REPLACED on each emit; does NOT bump `seq`; defaults to empty. Read by the navigation-history fold (`nav_history::derive_target`).
  - `theme: ThemeColors` holds the `WolfCursor` / `WolfTitlebar` app-theme colors, updated out-of-band via the `wolf_theme` notification (see `redraw.rs`); all-`None` by default and whenever a group is absent or cleared.
  - `current_filetype: String` is the active buffer's `vim.bo.filetype` (empty when unknown), updated out-of-band via the (now 3-arg) `wolf_current_file` notification — whose autocmd also fires on `FileType` (see `redraw.rs`). Drives `is_markdown_active()`.
  - `current_is_preview: bool` is whether the active buffer is a PREVIEW scratch buffer (carrying `b:wolf_preview_source`), updated out-of-band via the `wolf_current_file` notification's 3rd boolean arg — a preview buffer emits `("", "", true, …)`, so `current_is_preview` and (markdown) `current_filetype` are never both truthy. Drives `is_preview_active()` (the Edit command's enable gate). Defaults to `false`.
  - `current_is_full_width: bool` is whether the buffer currently being edited is in FULL-WIDTH mode (it carries a truthy `b:wolf_full_width`), updated out-of-band via the `wolf_current_file` notification's 4th boolean arg — for a preview scratch this is the SOURCE buffer's flag (OQ-1), so the checkmark tracks the document. Drives `is_full_width_active()`, the View-menu "Use full width for content" checkmark. Does NOT bump `seq`. Defaults to `false`.
  - `full_width: HashMap<i64, bool>` is the per-window full-width map, keyed by the Neovim WINDOW handle (`WinInfo.win`), updated out-of-band via the `wolf_full_width` notification (see `redraw.rs`), WHOLESALE-REPLACED on each emit so stale/closed windows vanish; a window ABSENT from the map defaults to `false` (the ~90-char default). The front-end threads a pane's flag (via `full_width_for_win`) into its geometry (`maxCols: nil` for full width, `90` for the default). Empty by default; does NOT bump `seq`.
  - `previews: HashMap<i64, PreviewInfo>` is the per-preview-window source map, keyed by the preview WINDOW handle, updated out-of-band via the `wolf_preview` notification (see `redraw.rs`), WHOLESALE-REPLACED on each emit so closed preview windows vanish. Empty by default.
  - `markdown_ticks: HashMap<i64, u64>` is the per-source-buffer `changedtick`, keyed by the SOURCE Markdown buffer number, upserted out-of-band via the `wolf_markdown_dirty` notification (see `redraw.rs`). The front-end joins a preview's `source_bufnr` to its tick to decide when to re-pull rendered HTML. Empty by default.
  - `open_files: HashMap<i64, TabFiles>` is the Tier-1 open-file mirror, keyed by the Neovim TABPAGE handle, updated out-of-band via the `wolf_open_files` notification (see `redraw.rs`'s `apply_open_files`), WHOLESALE-replaced per emit (no `seq` bump). Read by `WolfCore::open_files_for_tabpage` before a crash-restart. Empty by default.
  - `tab_cwds: HashMap<i64, PathBuf>` is the per-tabpage tab-local working directory, keyed by the Neovim TABPAGE handle, each an absolute canonicalized cwd (`getcwd(-1, n)`). Updated out-of-band via the `wolf_tab_cwds` notification (the `WolfTabs` `DirChanged`/`TabNewEntered`/`TabClosed` autocmds; see `redraw.rs`'s `apply_tab_cwds`), WHOLESALE-REPLACED on each emit so a closed tabpage vanishes (a `TabClosed` cannot report the closed handle, so the replacement is how it is pruned). Read by `WolfCore::cwd_for_tabpage` as a cheap, lock-free snapshot lookup (no RPC), authoritative even for a NON-current view. Empty by default; a `tab_cwds` change does NOT bump `seq`.
  - `cmdline: Cmdline` / `pum: Pum` / `toast: Toast` are the native command line, completion popup, and message toast, folded IN the redraw batch (so they DO bump `seq`) from the `ext_cmdline` / `ext_popupmenu` / `ext_messages` protocols (see `redraw.rs`). Inactive/hidden/empty by default. The front-ends paint the command line + popup + toast natively at the bottom of the editor area (the outer grid 1 empties under `cmdheight=0`).
  - `pending_confirm: Option<PendingConfirm>` (`pub(crate)`, `PendingConfirm { messages: Vec<Message>, prompt: String }`) is PURELY INTERNAL bookkeeping — it is NEVER rendered and NEVER crossed over the FFI (no `wolf-ffi` code enumerates `Snapshot` fields). It bridges the one-flush window between a `confirm()` dialog's `cmdline_hide` (which stashes the hidden confirm toast here) and a possible matching `cmdline_show` re-prompt (which restores it); see the confirm-prompt stash / restore paragraph in `redraw.rs`. `None` by default; `clear_toast` also resets it.
  - `seq` is a monotonic frame counter bumped on each `flush` (a `current_file`, `current_filetype`, `buffers`, `theme`, `previews`, or `markdown_ticks` change does NOT bump it; a `cmdline`/`pum`/`toast` fold IS part of the redraw batch, so it DOES).
  - Accessors: `Snapshot::new(cols, rows)` (inserts grid 1 sized `cols*rows`, `cursor.grid = 1`, empty `windows`, `active_win = None`, `current_tabpage = 0`); `active_grid_id()` (cursor's grid if present, else the highest non-1 grid id, else 1, else 0); `active_grid() -> &Grid` (the active grid, or a shared empty `0x0` grid fallback); `grid(id) -> Option<&Grid>`; `grid_mut(id) -> &mut Grid` (get-or-create a `0x0` grid a later `grid_resize` sizes); `active_viewport() -> Viewport`; `grid_for_win(win: i64) -> Option<u64>`; `clear_toast()` (empties `toast.messages` + hides it AND resets `pending_confirm`; called from the input pump on the next dismissing input — NOT a redraw frame, so it does not bump `seq`); `is_visual_mode() -> bool` (resolves the cursor's cached `ModeInfo` — `mode_infos[cursor.mode_idx]` — and returns true when its `name == "visual"`, i.e. nvim's single cursor-mode-info for `v`/`V`/`<C-v>`; `"visual_select"` is excluded — the macOS Copy menu item is gated on this over the FFI); `is_markdown_active() -> bool` (returns true iff `current_filetype == "markdown"`, mirroring `is_visual_mode`'s "resolve one field, match a string" shape — the macOS Preview menu item is gated on this over the FFI); `is_preview_active() -> bool` (returns `current_is_preview`, mirroring `is_markdown_active` — the macOS Edit menu item is gated on this over the FFI, and a preview buffer's `("", "", true, …)` emit keeps the two mutually exclusive); `is_full_width_active() -> bool` (returns `current_is_full_width`, mirroring `is_preview_active` — drives the macOS View-menu "Use full width for content" checkmark over the FFI); `full_width_for_win(win: i64) -> bool` (looks up `win` in the `full_width` map, defaulting to `false` — the front-end threads it into a pane's geometry as `maxCols: nil`/`90`).
- `SharedSnapshot` — `Arc<RwLock<Snapshot>>` wrapper: `new`, `read()`, `read_arc()` (owned guard), `write()`, `write_async()` (cooperative, non-pinning acquire from async code), `clone_handle()`. `OwnedSnapshotReadGuard` is the owned read-guard type returned by `read_arc`.

**Locking invariant:** exactly one `RwLock`; the redraw handler takes the write lock once per batch, never across an `.await`, and wakes only after it drops.

## `layout.rs`

The Neovim→shell **INTENT CHANNEL** types. The shell owns the pane layout, so `runtime/nvim/init.lua` overrides the split/focus chords and Ex-commands to `rpcnotify` a `wolf_layout` payload; `redraw.rs` parses each payload into a `LayoutIntent` and pushes it onto a drainable queue the front-end consumes via `WolfCore::drain_intents`.

- `SplitOrientation` (`Horizontal` = panes stacked top/bottom, `Vertical` = side by side).
- `FocusDir` (`Left`/`Right`/`Up`/`Down`).
- `LayoutIntent` — `Split { orientation, from, win }` (a split nvim already PERFORMED: `from` is the window that was current before, `win` the new window; the shell splits the `from` pane and binds the new pane to `win`), `FocusDir { dir, from }` (a PURE focus-move request: nvim did NOT change focus; the shell resolves the neighbour and drives the change), and `DrawerOpen { win }` (the terminal drawer nvim already OPENED: `win` is the new `botright` split window showing the terminal buffer; the shell renders it as a full-width, root-bottom pane at a fixed ~1/3 height held OUTSIDE its pure `PaneTree` and binds it to `win`'s grid). A CLOSE has no intent — nvim performs a guarded `nvim_win_close` and the shell observes the `win_close` redraw event. The DRAWER has the matched asymmetry: opening REPORTS a `DrawerOpen` intent, but HIDING is a guarded `nvim_win_close` the shell observes via `win_close` (no drawer-close intent) — symmetric with the split-close path.
- `LayoutIntent::from_payload(&rmpv::Value) -> Option<Self>` — parses the single map argument by its `action` discriminator (`"split"` / `"focus_dir"` / `"drawer_open"`), tolerating any malformed/partial payload by returning `None`. Window handles arrive as plain integers (Lua numbers) but the msgpack-`Ext` encoding is also tolerated (private `handle_i64`). Table-driven `#[cfg(test)]` unit tests cover valid splits/focus/drawer-open and every malformed case (including a `drawer_open` missing its `win`).

## `command.rs`

The canonical, GUI-free **COMMAND REGISTRY**. A `Command` is a no-parameter, no-return user action; unlike a layout intent it is ONLY user-triggered (no emit-on-attach). Pure data + enums (honors the one hard rule).

- `Command` — `NewWindow`, `CloseWindow`, `QuitApplication`, `HideApplication`, `MinimizeWindow`, `GoToFile`, `OpenFile`, `OpenFolder`, `ClosePane`, `NewBuffer`, `ResetFontSize`, `IncreaseFontSize`, `DecreaseFontSize`, `CommandPalette`, `Copy`, `Paste`, `BufferPicker`, `NewTab`, `Preview`, `Edit`, `Terminal`, `PreviewInBrowser`, `FullWidth`, `ToggleSidebar`, `SidebarShowProject`, `SearchInProject`. The variant order is the discriminant contract shared with `wolf-ffi`'s `command_kind` and the Swift `CommandKind` port (APPEND-ONLY: existing discriminants never move; `ClosePane` is the old `CloseFile` renamed IN PLACE at position 8, `NewBuffer`..`DecreaseFontSize` are appended at 9..12, `CommandPalette` at 13, `Copy`(14) / `Paste`(15) past it, `BufferPicker`(16), `NewTab`(17), `Preview`(18), `Edit`(19), `Terminal`(20), `PreviewInBrowser`(21), `FullWidth`(22), and the three native-only sidebar commands `ToggleSidebar`(23), `SidebarShowProject`(24), `SearchInProject`(25) appended last). `Preview` (`:WolfPreview` / `require('wolf').preview()`, View menu) renders the active Markdown buffer as HTML in a preview pane; its native face is `WolfWindowController.openPreview`, ENABLED only when the active buffer is Markdown (`Snapshot::is_markdown_active`, bridged as `WolfCoreHandle::is_markdown_active`). `Edit` (`:WolfEdit` / `require('wolf').edit()`, title "Edit Source", View menu) is Preview's inverse — it navigates a preview pane back to its source Markdown file; its native face is `WolfWindowController.editSource`, ENABLED only when the active pane is a preview pane (`Snapshot::is_preview_active`, bridged as `WolfCoreHandle::is_preview_active`). `Terminal` (`:WolfTerminal` / `require('wolf').terminal()`, View menu) toggles the per-project terminal drawer; it is editor-affecting (see `input.rs`'s `ToggleTerminal`), reaching the `wolf_toggle_terminal` `init.lua` helper, and its menu item is NEVER gated. `PreviewInBrowser` (`:WolfPreviewInBrowser` / `require('wolf').preview_in_browser()`, View menu) renders the active Markdown buffer and opens it in the system default web browser, backed by the lazily-started loopback-only HTTP server in `browser_preview.rs` (see the crate [`README.md`](../README.md), "The browser preview server"); its native face is `WolfWindowController.openInBrowser` (which opens the returned `http://127.0.0.1:<port>/<relpath>` URL via `NSWorkspace`), ENABLED only when the active buffer is Markdown (`Snapshot::is_markdown_active`, the same gate as `Preview`). `FullWidth` (`:WolfFullWidth` / `require('wolf').full_width()`, title "Use full width for content", View menu) toggles the active buffer between the ~90-char default content width and full pane width by flipping the buffer-local `b:wolf_full_width`; it is editor-affecting (see `input.rs`'s `ToggleFullWidth`), reaching the `wolf_toggle_full_width` `init.lua` helper (which targets the SOURCE buffer when the active pane is a preview scratch — OQ-1), and its native face is `WolfWindowController.toggleFullWidth`. Its menu item is NEVER gated (always enabled — OQ-2) but shows a CHECKMARK when `Snapshot::is_full_width_active` (bridged as `WolfCoreHandle::is_full_width_active`). `NewTab` (`:WolfNewTab` / `require('wolf').new_tab()`, File menu) opens a new tab in the current window (a new captive Neovim in the same directory); its native face is `AppDelegate.makeNewTab`. The File commands map to native actions on macOS: `GoToFile` opens the existing file-picker overlay, `OpenFile` opens a native file dialog (then `handle.open`), `OpenFolder` opens a native folder dialog (then `:cd`), `ClosePane` closes the current split (`:close`, NOT the buffer), and `NewBuffer` opens a new empty buffer in the current window and names it the next free `Untitled N.md` (the `wolf_new_untitled` helper: `:enew` then name + `filetype=markdown`, never written to disk). The three `*FontSize` commands are front-end-only View actions (per-window, ephemeral font size): they carry no core input path — only their discriminants cross the FFI for the nvim-drained face — so the macOS controller handles them entirely (re-measure cell metrics + reflow). `CommandPalette` opens the macOS command-palette overlay. The two Edit commands map to clipboard actions on macOS: `Copy` yanks the visual-mode selection over RPC (via `WolfCore::copy_visual_selection`) so the front-end writes it to `NSPasteboard` (its menu item is enabled only when the active window is in visual mode), and `Paste` inserts the clipboard string via `nvim_paste` (via `WolfCore::paste`). `BufferPicker` opens the macOS buffer-picker overlay (reachable from both the View menu and, as a static palette row, the command palette). `ToggleSidebar` (`:WolfToggleSidebar` / `require('wolf').toggle_sidebar()`, title "Toggle sidebar", View menu), `SidebarShowProject` (`:WolfSidebarShowProject` / `require('wolf').sidebar_show_project()`, title "Sidebar: Show project", View menu), and `SearchInProject` (`:WolfSearchInProject` / `require('wolf').search_in_project()`, title "Search in project", View menu) are the three native-only (flavor a) sidebar UI actions: their native faces are `WolfWindowController.toggleSidebar` (toggles the sidebar's collapsed state) and `WolfWindowController.showSidebar(panel:)` (revealing the `.tree` project panel and the `.search` search panel respectively); they never touch the captive nvim (no `InputEvent`), so they surface as palette rows / menu items only. The full command lifecycle — the registry, its two faces, and the drain→dispatch path — is documented end-to-end in [`command-lifecycle.md`](../../../command-lifecycle.md).
- `MenuGroup` — `App`/`File`/`Window`/`View`/`Edit` (menu-grouping metadata; `View` groups the three font-size commands, `CommandPalette`, `BufferPicker`, `Preview`, `Edit`, `Terminal`, `PreviewInBrowser`, `FullWidth`, `ToggleSidebar`, `SidebarShowProject`, and `SearchInProject`, `Edit` (the menu group) groups `Copy` / `Paste`, and `File` additionally groups `NewTab`). - `COMMAND_SPECS: &[CommandSpec]` — one row per command, in variant order (slice index == FFI discriminant).
- `Command::from_id(id) -> Option<Command>` (linear scan, resolves the `wolf_command` payload) and `Command::spec(self) -> &'static CommandSpec`.

## `markdown.rs`

The pure, GUI-free, IO-free Markdown → themed-HTML renderer for the preview pane (requirement 6) — like `rank.rs` it touches NO GUI toolkit and NO filesystem, a `&str` → `String` transform with its own `#[cfg(test)] mod tests`. The Markdown engine is `pulldown-cmark` + `pulldown-latex` (both added to core's deps, denylist re-verified clean — `pulldown-latex` adds only `bumpalo`). `pulldown-cmark` is chosen for `Parser::into_offset_iter`, which pairs each event with its SOURCE byte range — the basis of the marker scheme; `pulldown-latex` (pure Rust, MIT) converts LaTeX math to MathML. See the CSS/font assets in [`markdown/README.md`](markdown/README.md) and the decisions in [`preview-math-and-fonts-decisions.md`](../../../preview-math-and-fonts-decisions.md).

- `render_html(source: &str, theme: PreviewTheme, width_mode: WidthMode) -> String` (`#[must_use]`, re-exported) — renders `source` to a complete themed HTML document with the position markers embedded, wrapped as `<!doctype html><html><head><meta charset="utf-8"><style>{INTER_FONT_FACE}{MATH_FONT_FACE}{BASE_CSS}{MATH_CSS}{theme_css}{width_css}</style></head><body class="wolf-markdown">{body}</body></html>`. Enables the tables/footnotes/strikethrough/tasklists `pulldown_cmark::Options` PLUS `Options::ENABLE_HEADING_ATTRIBUTES` (O5, explicit-vs-auto heading ids) PLUS `Options::ENABLE_MATH` (yields `Event::InlineMath` / `Event::DisplayMath` for `$…$` / `$$…$$` LaTeX). The document `<style>` now ALSO inlines the Inter + Latin Modern Math `@font-face` data URIs (`INTER_FONT_FACE` / `MATH_FONT_FACE`) and `MATH_CSS`, so the preview's body font, math font, and MathML styling never depend on host-installed assets (see below and [`markdown/README.md`](markdown/README.md)). The trailing `{width_css}` (appended AFTER the theme CSS so it wins the cascade) is selected by `width_mode`: `WidthMode::Full` appends nothing; `WidthMode::Capped` appends the horizontal-only content cap `CAPPED_WIDTH_CSS`. Its body is now a ONE-LINE delegate to `render_html_with_highlights(source, theme, width_mode, &[])` (an empty highlight slice = every code block plain = the historical behavior, so every existing call site is byte-for-byte unchanged). The Markdown `pulldown_cmark::Options` are factored into a private `markdown_options()` shared by `render_html_with_highlights`, the `heading_slugs` pre-pass, and `code_blocks` so all three parse with identical flags.
- `render_html_with_highlights(source: &str, theme: PreviewTheme, width_mode: WidthMode, code_highlights: &[Option<BlockHighlight>]) -> String` (`#[must_use]`, re-exported) — the real renderer (the moved `render_html` body). `code_highlights[i]`, indexed by DOCUMENT ORDER (aligned with `code_blocks`), carries the treesitter spans for the i-th code block: `Some(block)` rewrites that block's interior text into inline-styled `<span>`s, while `None` — or an index past the end of the slice — leaves it PLAIN (`<pre><code>`). Passing `&[]` reproduces `render_html` exactly. The highlight data is produced OUTSIDE this pure module by `crate::nvim` (see [`nvim.rs`](#nvimrs)); this module only enumerates and applies.
- `code_blocks(source: &str) -> Vec<CodeBlockInfo>` (`#[must_use]`, re-exported) — enumerates every fenced/indented code block in `source` in DOCUMENT ORDER via a fresh `Parser::new_ext` pass with `markdown_options()`. The i-th returned block ALIGNS with the i-th `Start(CodeBlock)` the internal `CodeHighlighter` counts, so a caller keys per-block highlight data by index. `crate::nvim::render_source_html` uses it to build the batch highlight request.
- `CodeBlockInfo { lang: Option<String>, text: String }` (`Clone`, re-exported) — one enumerated block. `lang` is the lowercased first whitespace-token of a fenced info string (`None` for an indented block or a bare fence); `text` is the in-order concatenation of the block's `Event::Text` bodies — byte-identical to what the render pipeline concatenates, INCLUDING pulldown-cmark's trailing newline (the load-bearing alignment invariant, so nvim's `(row, byte-col)` indices match `text.split('\n')`).
- `HighlightStyle { color: Option<u32>, bold: bool, italic: bool, underline: bool }` (`Copy`, re-exported) — the visual style for one span: a `0xRRGGBB`-packed foreground (`None` = no fg; mirrors `render::Rgb::from_packed`) plus the three carried emphases. NO background and no other attribute (locked decision 3).
- `HighlightSpan { row: u32, start_col: u32, end_col: u32, style: HighlightStyle }` (`Copy`, re-exported) — one highlighted run: a half-open `[start_col, end_col)` BYTE-column range on a single 0-based `row` (relative to `text.split('\n')`), plus its `HighlightStyle`. Spans are single-line, non-overlapping, and sorted by `(row, start_col)` (the nvim-side helper guarantees this; the renderer is nonetheless defensive against malformed/overlapping input — it byte-clamps and overlap-guards so it never panics or nests spans).
- `BlockHighlight { spans: Vec<HighlightSpan> }` (`Clone`, re-exported) — all spans for ONE code block.
- `WidthMode { Capped, Full }` (`Copy` + `Default` = `Full`, re-exported) — how the rendered body's content area is sized horizontally. `Full` is the full-bleed / historical behavior (no `max-width` cap, no centering — the in-app webview FRAME does any capping); `Capped` appends `CAPPED_WIDTH_CSS` = `body.wolf-markdown{max-width:45rem;margin-left:auto;margin-right:auto;padding-left:24px;padding-right:24px}`, capping the content to `45rem` and centering it. `45rem` ≈ 90 proportional Inter characters (at the 16px root the average Inter glyph advance is ~half the em, so `45rem = 720px` holds ~90 chars — honoring the user's "~90 characters", OQ-3, the same target as the 90-column editor cap). ONLY horizontal properties are set (the two side margins + paddings) so the preview's 24px vertical baseline grid is untouched. The BROWSER preview (a standalone document, no frame) and static `.md` disk renders always pass `Capped`; the IN-APP preview passes `Full` and lets the webview frame cap it.
- `PreviewTheme { Default }` (`Copy` + `Default`, re-exported) — the preview themes; one variant ships (`Default`, which declares `color-scheme: light dark` with a dark default palette plus a `@media (prefers-color-scheme: light)` block so the preview follows the app's resolved dark/light appearance — still NOT wired to the live nvim colorscheme, OD5), structured so more themes + a config-driven selector drop in later.
- `theme_css(PreviewTheme) -> &'static str` (`#[must_use]`, re-exported) — the theme's CSS, `include_str!`'d from `src/markdown/themes/<theme>.css` (embedded AFTER `BASE_CSS` + `MATH_CSS`). `BASE_CSS` is `include_str!`'d from `src/markdown/base.css` (the `.wolf-src` marker rule + the structural layout, governed by a **24px baseline grid** — the documented `--wolf-baseline: 24px` token, every vertical margin and border-box height 0 or a whole multiple of 24px, `line-height` declared as a LENGTH so it inherits unchanged into smaller-font descendants, with borders compensated into padding or an explicit height; see [`markdown/README.md`](markdown/README.md) — its `body.wolf-markdown` stack `"Inter"`-fronted with the system fallback retained); `MATH_CSS` from `src/markdown/math.css` (MathML styling adapted from pulldown-latex's `styles.css`, with the Latin Modern Math font pin). All CSS/font assets are NOT Markdown docs (no prettier) — see [`markdown/README.md`](markdown/README.md). `base.css`'s `h1..h6` rule carries `scroll-margin-top: 48px` (2 baselines of clearance; the body itself has no padding, so this is the only thing keeping a jumped-to heading off the top edge) so a fragment scrolled into view by the preview's anchor-link handling clears the top edge.

**Math rendering (LaTeX → MathML).** With `ENABLE_MATH` on, the render chain is `offset_iter → HeadingIdAssigner → MathRenderer → CodeHighlighter → MarkerInjector → html::push_html`. `MathRenderer` (positioned BETWEEN `HeadingIdAssigner` and `CodeHighlighter`) converts each `Event::InlineMath` / `Event::DisplayMath` LaTeX fragment to inline MathML via the `render_math(latex, DisplayMode)` helper (which wraps `pulldown_latex::mathml::push_mathml` with an explicit `Result` match — NEVER an `unwrap`) and emits it as an `Event::InlineHtml`. `InlineHtml` is load-bearing on two counts: the HTML writer passes it through verbatim so the `<math>` markup is NOT double-escaped, and because `is_block_start` never matches an `InlineHtml`, `MarkerInjector` never injects a `wolf-src` marker inside a `<math>` element. Inline math uses `DisplayMode::Inline`, display math `DisplayMode::Block` (its `<math>` carries `display="block"`). Malformed LaTeX degrades gracefully: pulldown-latex renders it into a `<merror>` node (still `Ok`), and the unreachable I/O-error path falls back to a plain `Event::Text` of the original `$…$` source — no panic.

**Code-block syntax highlighting (treesitter → inline spans).** `CodeHighlighter` sits BETWEEN `MathRenderer` and `MarkerInjector` in the chain above. It counts `Start(CodeBlock)` events and, for the i-th block, consults `code_highlights[i]`: `None` (or an index past the slice) passes the block through verbatim (the plain fallback); `Some(block)` eagerly drains the block's interior `Event::Text` into one string (byte-identical to `code_blocks`) and swaps it for a single `Event::InlineHtml` of inline-styled `<span>`s built by `build_highlighted_html`. The block-level `Start`/`End(CodeBlock)` are passed through UNTOUCHED, so pulldown-cmark still emits the `<pre><code class="language-xxx">` wrapper and — because `CodeHighlighter` runs BEFORE `MarkerInjector` — the injector still sees the real `Start(CodeBlock)` and flushes source markers BEFORE the block, never inside `<pre>`. Like `MathRenderer`'s MathML, the `InlineHtml` interior is written verbatim (never double-escaped); `build_highlighted_html` itself HTML-escapes every gap and span body exactly once via `escape_html_into`, and `style_css` emits the fixed-order `color:#{:06x};font-weight:bold;font-style:italic;text-decoration:underline;` declaration for each set field. Slicing is byte-clamped and overlap-guarded, so malformed spans never panic. The highlight data is obtained by `crate::nvim` (see [`nvim.rs`](#nvimrs)); this module stays pure. See [`preview-code-block-syntax-highlighting-decisions.md`](../../../preview-code-block-syntax-highlighting-decisions.md).

- `MARKER_COLUMN_STRIDE: usize = 100` (re-exported) — the per-column marker stride (a named const, no magic number).
- Internal: `desired_markers(source) -> Vec<(usize byte, u32 line, u32 col)>` (a `(L, 0)` marker for every hard line `source.split('\n')`, plus `(L, k*100)` for each multiple strictly less than the line's CHARACTER length — the byte offset computed from the char count so multibyte lines resolve correctly, OD4); `marker_span(line, col)` emits the exact `<span class="wolf-src" id="wl-{line}-{col}" data-line="{line}" data-col="{col}"></span>` (double-quoted `id`, real `</span>` close); `MarkerInjector` is an iterator adapter over the offset iterator that flushes every pending marker with byte offset `< range.end` as a raw `Event::Html` immediately BEFORE each block-level `Start` tag (`is_block_start`: `Paragraph`/`Heading`/`BlockQuote`/`CodeBlock`/`HtmlBlock`/`List`/`Item`/`FootnoteDefinition`/`Table`/`TableHead`/`TableRow` — inline tags and `TableCell` are NOT injection points), then flushes any remainder as trailing spans. Consequence (v1, documented): a block's interior line markers COLLAPSE to immediately before that block's opening tag (a container collapses all its interior markers to the container top) — every `wl-{L}-0` id still EXISTS but resolves to the block top; the per-100-column markers are mostly redundant until inline-level anchoring lands. `HeadingIdAssigner` is a second iterator adapter (mirroring `MarkerInjector`, `next_heading` advancing on EVERY heading `Start` so it stays aligned) that rewrites each auto-id heading `Start` with the slug computed by `heading_slugs(source, options)` — a fresh pre-pass `Parser::new_ext` (O6: the extra parse is accepted; renders are debounced) yielding one entry per heading in document order (`Some(slug)` for an auto-id heading, `None` for one carrying an explicit `{#custom}` id, whose id is still REGISTERED in the shared `seen` dedup map so later auto-slugs suffix around it). The accumulated heading text is the in-order concat of every `Event::Text` + `Event::Code` between the heading's `Start`/`End`. §SLUG (`slugify` + `dedup`, EXACT): (1) `str::to_lowercase()` (full Unicode — `"Café Ω"` → `"café-ω"`); (2) walk char-by-char with NO hyphen collapsing — `is_alphanumeric()` → push, `'-'` → push `'-'`, `is_whitespace()` → push `'-'`, else DROP (so `"C++ & Rust"` → `"c--rust"`, `"foo  bar"` → `"foo--bar"`); (3) empty-after-strip → the base `"section"`; (4) dedup against the shared `HashMap<String, u32>` in document order — unseen → `base` (count 1), seen → `"{base}-{n}"` (count n+1); explicit ids are registered the same way. The rare literal `"foo-1"`-heading-vs-dedup collision is documented + accepted (O2). The forward-compat contract (a Neovim→web-view cursor signal + the cursor-follow JS, converting nvim's byte column to a character column) is DESIGNED but NOT built here.

## `input.rs`

Abstract input events (front-end → core) and their translation into Neovim notation and generic RPC.

Types: `Key` (`Char(char)`, `Enter`, `Esc`, `Tab`, `Backspace`, `Delete`, arrows, `Home`, `End`, `PageUp`, `PageDown`, `F(u8)`); `KeyEvent { key, ctrl, shift, alt, meta }`; `MouseButton`, `MouseAction`, `MouseEvent { button, action, grid, row, col, ctrl, shift, alt }`; `ScrollDirection`, `ScrollEvent { direction, grid, row, col }`; and the top-level `InputEvent` enum. Both `MouseEvent` and `ScrollEvent` carry a target `grid: u64` with GRID-LOCAL `row`/`col`: under `ext_multigrid` the front-end targets the pane's WINDOW grid (`>= 2`), so mouse/scroll land on that pane rather than the hardcoded global grid 0.

Functions:

- `key_to_notation(&KeyEvent) -> String` (public) — modifier order `C-`, `S-`, `A-`, `D-`; named keys map to angle-bracket names (`<CR>`, `<Esc>`, `<Tab>`, `<BS>`, `<Del>`, `<Left>`, `<F1>`, …); a bare printable char maps to itself, except `<` → `<lt>`. **Shift contract:** `S-` is _not_ emitted for printable chars (deliver the shifted glyph in the char); it applies only to named keys.
- `apply(nvim, &InputEvent)` (crate-internal) — `Key` → `nvim_input(notation)`; `Mouse` → `nvim_input_mouse` targeting `MouseEvent::grid` with grid-local row/col (no longer hardcoded to grid 0); `Scroll` → wheel via `nvim_input_mouse` targeting `ScrollEvent::grid` (empty modifiers); `Resize` → `nvim_ui_try_resize` (the authoritative grid size arrives via `grid_resize`, so the local grid is never resized here); `ResizeGrid { grid, cols, rows }` → `nvim_ui_try_resize_grid` (per-window-grid resize); `FocusWin { win }` → `nvim_set_current_win` (focus a pane's window, the `win` handle as a plain `i64`); `Open` → `edit <fnameescape path>`; `OpenAt { path, line, col }` → `edit <fnameescape path>` FOLLOWED by `nvim_win_set_cursor(0, [line, col])` back-to-back in one input-pump step (so the edit and the cursor placement are ordered) — the sidebar search panel's click-to-jump: `line` is 1-based (ripgrep's `line_number`), `col` a 0-based BYTE offset (ripgrep's first-submatch start), and Neovim clamps an out-of-range line/column so a stale match never errors; `Save` → `write`; `SaveAs` → `saveas <fnameescape path>`; `Chdir { path }` → `tcd <fnameescape path>` (the TAB-LOCAL working directory — each view/tabpage owns its own cwd, so a global `:cd` would move every view of the shared nvim), then the `wolf_name_untitled_current` helper over `nvim_exec_lua` (a GUARDED re-home that names the untouched anonymous buffer `Untitled.md` in the opened folder — a no-op for real files / modified buffers); `SetTabpage { handle }` → `nvim_set_current_tabpage` (make a view's tabpage current); `CloseTabpage { handle }` → the `wolf_close_tabpage` helper (`<n>tabclose` under `pcall`, for a non-last view close); `ClosePane` → `close` (close the current split, NOT the buffer — errors harmlessly with E444 on the last split); `NewBuffer` → the private `new_untitled` helper, which calls `nvim_exec_lua("wolf_new_untitled()")` (`:enew`, then names the fresh buffer the next free `Untitled N.md` + `filetype=markdown`, never written to disk); `Paste { text }` → the private `nvim_paste` helper, which calls `nvim_paste(text, crlf = true, phase = -1)` (a single-shot paste, correct in normal/insert/visual/cmdline modes with no mode branching); `SwitchBuffer { win, bufnr }` → the private `switch_buffer` helper, which calls `nvim_exec_lua("wolf_switch_buffer(...)", [win, bufnr])` — the `init.lua` helper does a window-scoped `nvim_win_set_buf` (NOT `:edit`) plus per-pane view restoration, atomic in one Lua call so the set-buffer and restore never race; `SetBackground { dark }` → `set background=dark` / `set background=light` (fed by `WolfCore::set_background`, the appearance push face — re-sourcing the colorscheme so the existing `wolf_theme` path repaints); `ToggleTerminal` → the private `toggle_terminal` helper, which calls `nvim_exec_lua("wolf_toggle_terminal()", [])` (no args) — the `init.lua` helper opens/hides a per-tabpage bottom `:terminal` drawer window showing the shared, tagged per-project terminal buffer (the buffer/job persist across a hide, and are recreated if the user exited the shell); `ToggleFullWidth` → the private `toggle_full_width` helper, which calls `nvim_exec_lua("wolf_toggle_full_width()", [])` (no args) — the `init.lua` helper flips `b:wolf_full_width` on the EFFECTIVE buffer (the SOURCE buffer when the active pane is a preview scratch — OQ-1) and re-emits the current-file / per-window full-width / previews notifications so the front-end resizes the content; `SetUiFocus { gained }` → `nvim_ui_set_focus(gained)` (inlined like `Resize`, no `NvimProcess` wrapper) — `true` fires nvim `FocusGained` (→ the init.lua `WolfAutoRead` `:checktime` reload-on-refocus), `false` fires `FocusLost`; a front-end reports both edges since nvim only fires `FocusGained` on a real unfocused→focused transition.
- `InputEvent::is_toast_dismissing(&self) -> bool` (public) — whether this event is a deliberate user action that should DISMISS a showing message toast (OD8): a `Key`, `Mouse`, or `Scroll`. A scroll IS dismissing here; the scroll-over-toast exemption is realized entirely in the front-end (it never forwards that wheel gesture, so no `Scroll` reaches core). Resize / focus / open / tabpage events are not user-facing input and never dismiss. The input pump in `api.rs` scans a batch with this before applying it.
- `apply_batch(nvim, &[InputEvent])` (crate-internal) — applies a batch in order, fusing a run of consecutive `Key` events into one `nvim_input` call (so a burst yields a single redraw flush); non-key events are applied individually.

All RPC is generic/untyped; key delivery flows through a single shared `nvim_input` helper. Paths are escaped with a Vim-style `fnameescape`.

## `redraw.rs`

The `redraw` handler: folds Neovim's redraw stream into the shared snapshot.

- `WakeFn = Arc<dyn Fn() + Send + Sync>` — fired once per `flush`, after the lock drops.
- `IntentQueue = Arc<Mutex<VecDeque<LayoutIntent>>>` — the shared, drainable queue of layout intents. It is a SIBLING of the render snapshot (NOT part of it): pushing an intent does not bump the snapshot `seq`. Owned by `WolfCore` (drained via `drain_intents`) and cloned into the handler.
- `CommandQueue = Arc<Mutex<VecDeque<Command>>>` — the shared, drainable queue of user-triggered commands, a sibling of `IntentQueue` (pushing does not bump `seq`). Owned by `WolfCore` (drained via `drain_commands`) and cloned into the handler, which pushes onto it on each `wolf_command` notification.
- `TrackedCwd = Arc<parking_lot::RwLock<Option<PathBuf>>>` — a shared cell holding the captive Neovim's live working directory. Like `IntentQueue` it is a SIBLING of the render snapshot (updating it does not bump `seq`): nvim's cwd is not render state. Owned by `WolfCore` (read by the input pump to scope the global MRU store by nvim's live cwd) and cloned into the handler, which writes it on each `wolf_cwd` notification. `None` until nvim first reports its cwd.
- `NavHistoryCell = Arc<parking_lot::Mutex<nav_history::NavHistory>>` — a shared cell holding every pane's navigation history (back/forward). Like `IntentQueue` / `TrackedCwd` it is a SIBLING of the render snapshot (NOT part of it): history is out-of-band app state mutated from FFI accessors that also do blocking RPC, so it must not ride on the `Clone`-per-frame `Snapshot`, and updating it does not bump `seq`. Owned by `WolfCore` (read and moved by its six `history_*` methods) and cloned into the handler, which FOLDS a derived per-window `NavTarget` into it after every `wolf_buffers` / `wolf_preview` emit and PRUNES a closed window's stack on `win_close`. **Lock order:** the fold takes the snapshot write lock FIRST and this mutex second, with no `.await` or RPC between; the `WolfCore::history_*` side takes this mutex ALONE (never while holding the snapshot lock, never across a `block_on_rpc`) — so there is no lock-order cycle.
- `RedrawHandler { snapshot, intents, commands, cwd, recent_dirs, nav_history, wake }` — `RedrawHandler::new(SharedSnapshot, IntentQueue, CommandQueue, TrackedCwd, RecentDirs, NavHistoryCell, WakeFn)` (the `nav_history` cell is the 6th param, inserted after `recent_dirs` and before `wake`). Core no longer mirrors cwd into a `StateStore` (the `SharedStateStore` cell and `attach_state_store` are removed): with the whole-tree snapshot model the front-end reads each tab's live cwd (over the FFI `cwd()` accessor) when it walks the window/tab tree at snapshot time. The `recent_dirs` field is the always-on global recent-directories MRU that `apply_cwd` records each GENUINE `DirChanged` cwd change into (the flagged initial/launch emit is tracked-only and NOT recorded, so the MRU reflects only directories the user actually opened). Implements `nvim_rs::Handler` with `type Writer = Compat<ChildStdin>`; `handle_notify` routes thirteen notifications and ignores the rest: `"redraw"` → `apply_redraw`; `CURRENT_FILE_EVENT` (`"wolf_current_file"`) → `apply_current_file` (now reading a 4th boolean arg → `current_is_full_width`); `BUFFERS_EVENT` (`"wolf_buffers"`) → `apply_buffers`; `FULL_WIDTH_EVENT` (`"wolf_full_width"`) → `apply_full_width` (wholesale-replaces the per-window `full_width` map, mirroring `apply_buffers`); `ACTIVE_WIN_EVENT` (`"wolf_active_win"`) → `apply_active_win`; `TABPAGE_EVENT` (`"wolf_tabpage"`) → `apply_tabpage`; `LAYOUT_EVENT` (`"wolf_layout"`) → `LayoutIntent::from_payload` then push onto the intent queue; `COMMAND_EVENT` (`"wolf_command"`) → `Command::from_id` then push onto the command queue; `THEME_EVENT` (`"wolf_theme"`) → `apply_theme`; `PREVIEW_EVENT` (`"wolf_preview"`) → `apply_previews` (now reading a 4th tuple element → `PreviewInfo.source_full_width`); `MARKDOWN_DIRTY_EVENT` (`"wolf_markdown_dirty"`) → `apply_markdown_dirty`; `OPEN_FILES_EVENT` (`"wolf_open_files"`) → `apply_open_files` (wholesale-replaces the Tier-1 per-tabpage `open_files` map, mirroring `apply_tab_cwds`); and `CWD_EVENT` (`"wolf_cwd"`) → `apply_cwd`. All but `CWD_EVENT` fire the wake AFTER their lock (snapshot write or intent/command `Mutex`) drops; `CWD_EVENT` does NOT wake (cwd is not render state and the triggering `:cd` already flushes via the `redraw` path). `apply_full_width` builds the new map BEFORE taking the write lock, assigns it wholesale, and does NOT bump `seq` (it is not a redraw frame).

`apply_redraw` takes the write lock once via `write_async`, walks the batch, and returns whether a `flush` was seen so the caller can wake after the lock drops. It also declares a `closed_wins: Vec<i64>` collector before the batch loop and threads it through `apply_event` → `win_close`: a `win_close` payload carries only the GRID, so `win_close` resolves the nvim WINDOW handle from `snap.windows.get(&grid)` BEFORE removing the entry and pushes it onto the collector; after the loop (still under the guard, no `.await` in between) a non-empty collector drives `nav_history.lock().prune_many(&closed_wins)`, dropping those panes' navigation histories.

**Multigrid routing.** The grid events carry their target grid id in `params[0]` and are routed to that grid: `grid_resize` (`grid_mut(id).resize(..)` — get-or-create), `grid_clear`/`grid_line`/`grid_scroll` (operate on the existing grid; an unknown grid id is dropped quietly so no phantom grid is created), `grid_cursor_goto` (sets `cursor.grid` + row/col). Window events: `grid_destroy` (removes the grid and its `windows` entry), `win_pos` (upserts `windows[grid]` with the decoded `win` + layout rect), `win_viewport` (upserts the per-window `viewport`), `win_hide` (REMOVES the `windows` entry but KEEPS the grid — see below), `win_close` (removes both the `windows` entry and the grid — idempotent with the `grid_destroy` Neovim also emits). `grid_line` walks cell tuples `[text]` / `[text, hl]` / `[text, hl, repeat]`, carrying `hl_id` forward, expanding `repeat` (a `repeat` count of how many columns the cell occupies including the first — so Neovim's zero-width trailing clear-to-EOL cell `[" ", 0, 0]` expands to NOTHING; clamping it to one cell would paint a spurious default-background space just past the event's span that Neovim never repaints), and storing Neovim's empty trailing cell of a wide glyph **verbatim** (no synthesized placeholder). Non-grid events: `hl_attr_define`, `default_colors_set`, `mode_info_set`, `mode_change`, and `flush` (bumps `seq`). Unknown events are ignored. The **intentionally-ignored** list (documented in the module doc, like `win_float_pos`): `win_float_pos` / `win_external_pos` / `msg_set_pos` (floats/external windows not rendered; message placement handled natively); `cmdline_special_char` (OD6 — the `?`/`^R` insert-hint char); `cmdline_block_show` / `cmdline_block_append` / `cmdline_block_hide` (OD5 — interactive `:function` blocks); `msg_showmode` / `msg_showcmd` (showcmd off) / `msg_ruler` (ruler off).

**Native command line / popup / messages (`ext_cmdline` / `ext_popupmenu` / `ext_messages`).** Nine more events fold into `Snapshot.cmdline` / `Snapshot.pum` / `Snapshot.toast` (all IN the redraw batch, so they bump `seq` on the batch's `flush`):

- `cmdline_show` `[content, pos, firstc, prompt, indent, level]` → `cmdline` active with the parsed content chunks; `cmdline_pos` `[pos, level]` → updates `cmdline.pos` (byte offset) + level; `cmdline_hide` → clears `cmdline` to its default (any recursion level collapses to the one surface — a v1 limitation) AND, if a lingering `confirm` prompt toast is showing (`toast.is_prompt()`), captures the just-hidden options-line prompt, MOVES the confirm messages out of the toast into `pending_confirm`, and hides the toast (so a genuine resolve shows cleared immediately — see the restore-on-reprompt paragraph below).
- `popupmenu_show` `[items, selected, row, col, grid]` (item `[word, kind, menu, info]`) → `pum` visible with the parsed items; `selected`/`row`/`col`/`grid` decoded as SIGNED (`selected == -1` = none; `grid == -1` = anchored to the command line, `col` a byte offset). `popupmenu_select` `[selected]` → updates `pum.selected`; `popupmenu_hide` → clears `pum`.
- `msg_show` `[kind, content, replace_last, history, append, id, trigger]` folds into `toast.messages` by these steps: (1) `kind == "search_count"` → suppressed entirely; (2) an `empty` message with no content → `clear_toast`; (3) `append == true` onto an existing message → fuse the first appended line onto that message's last line (`:echon` semantics) via `append_lines_to_last`; (4) else `replace_last == true` → replace the last message in place; (5) else a non-zero integer `id` matching a visible message → replace THAT message (OD7 — integer id only; a string/absent id is `0`); (6) else push a fresh message. `history` is ignored (render regardless). `msg_show` and `msg_history_show` both DROP `pending_confirm` as their first step (a new / re-rendered message supersedes any confirm stashed mid-resolve, so a later prompt-style `cmdline_show` cannot resurrect a stale confirm toast underneath it); `clear_toast` — which backs `msg_clear` and the input-pump dismiss — likewise resets it. `msg_clear` → `clear_toast`. `msg_history_show` `[entries, prev_cmd]` (entry `[kind, content, append]`) → replaces `toast.messages` with one `Message` per entry (honoring `append`) and shows the toast, so `:messages` works.

**Confirm-prompt stash / restore-on-reprompt.** A Neovim `confirm()` dialog is TWO coupled surfaces: the prompt text arrives as a `msg_show` `kind == "confirm"` toast, and the options line (`"[y]es, (n)o: "`) as a prompt-style `cmdline_show`. When the dialog resolves Neovim emits ONLY a `cmdline_hide` (never `msg_clear`), so without intervention the confirm toast would linger forever. The catch: an INVALID key produces a `cmdline_hide` batch BYTE-IDENTICAL to a valid answer's — the two are distinguished only TEMPORALLY, because an invalid key makes Neovim RE-PROMPT with a matching `cmdline_show` in a LATER flush while a valid answer emits nothing further. So `cmdline_hide` STASHES the confirm toast (its messages + the options-line prompt) into `pending_confirm` and hides it, and `cmdline_show` decides what the stash meant: if the incoming cmdline is prompt-style (empty `firstc`, non-empty `prompt`) AND its prompt EXACTLY matches the stashed options-line prompt, it is the confirm's own re-prompt after an invalid key → RESTORE the messages and re-show the toast; ANY other cmdline (a `:`/`/` command line, or a different prompt such as a fresh `input("Name: ")`) means the dialog already resolved → the taken stash simply drops, leaving the toast cleared. The exact-prompt match (not a plain restore) is what keeps an unrelated `input()` right after an answered confirm from resurrecting the stale prompt. On an invalid key this is a one-flush hide-then-restore blink, but the two batches arrive sub-frame so it is imperceptible, and it is the only design that also clears on a valid answer (where Neovim sends no follow-up). This is safe because `confirm()` is modal — no other cmdline can be active while it waits.

Two shared parse helpers back these folds: `parse_content_chunks(&Value) -> Vec<(String, u64)>` tolerates BOTH chunk forms — `msg_show`'s `[attr_id, text, hl_id]` (elem[0] an integer highlight-attr id) and `cmdline_show`'s `[attrs, text]` (elem[0] may be an ATTRS-DICT map, in which case the attr id defaults to 0) — reading elem[0] via `Value::as_u64` with a `0` fallback; `split_content_into_lines` breaks each chunk's text on `"\n"` into one `Vec<ToastChunk>` per visual line. The `msg_show` fold steps 4–6 (`append` / `replace_last` / id-match) are covered by an inline `#[cfg(test)] mod tests` in this SOURCE file (`redraw::tests::msg_show_*`, driving synthetic `msg_show`-shaped params straight through `msg_show` — these branches are not uniquely triggerable by a headless keystroke), which runs under the crate's lib unit-test target (`//crates/wolf-core:wolf_core_lib_test`); the observable push + clear-on-input paths are covered by the real-nvim `tests/messages.rs`.

`ext_handle(&rmpv::Value) -> Option<i64>` decodes a Neovim window handle, which `nvim-rs` delivers either as a plain `Value::Integer` or as a `Value::Ext` (type 1 = Window) wrapping a msgpack-encoded integer; the inner bytes are decoded with `rmpv::decode::read_value`. The handle is stored as `i64` so the same form serves `nvim_set_current_win`/`nvim_win_close` later.

**Current-file tracking.** `CURRENT_FILE_EVENT = "wolf_current_file"` names an out-of-band notification carrying the active buffer's absolute path (`expand('%:p')`), (a 2nd argument) its `vim.bo.filetype`, (a 3rd boolean argument) whether the active buffer is a PREVIEW scratch buffer, AND (a 4th boolean argument) whether it carries a truthy `b:wolf_full_width`, emitted by the `WolfCurrentFile` autocmd in `runtime/nvim/init.lua` (which now also fires on `FileType`). `apply_current_file` parses the first argument: an empty string (unnamed buffer) becomes `None`; otherwise the path is canonicalized (to match the canonical paths the file picker emits, falling back to the raw path if canonicalization fails) and stored in `Snapshot.current_file`. The 2nd argument is stored in `Snapshot.current_filetype` (a missing arg → empty string → not markdown), driving `Snapshot::is_markdown_active`. The 3rd argument is decoded via `Value::as_bool` (a missing arg → `false`) into `Snapshot.current_is_preview`, driving `Snapshot::is_preview_active` (the Edit menu gate); a preview buffer emits `("", "", true, full_width)`, so markdown-active and preview-active are never both true. The 4th argument is decoded via `Value::as_bool` (a missing arg → `false`) into `Snapshot.current_is_full_width`, driving `Snapshot::is_full_width_active` (the "Use full width for content" menu checkmark; for a preview scratch it is the SOURCE buffer's flag — OQ-1). It acquires the write lock via `write_async` and does **not** hold it across an `.await`; it does **not** bump `seq` (a current-file change is not a redraw frame). The lock drops before returning, then `handle_notify` fires the wake — same wake-after-unlock invariant as the redraw path — so the front-end re-reads the snapshot (e.g. to highlight/reveal the file tree's current file, or re-validate the Preview menu item).

**Markdown preview tracking.** `PREVIEW_EVENT = "wolf_preview"` names an out-of-band notification carrying a msgpack array of `[preview_win, source_bufnr, source_abs_path, source_full_width]` tuples (one per window showing a `b:wolf_preview_source` scratch buffer; the 4th element the SOURCE buffer's `b:wolf_full_width`, folded into `PreviewInfo.source_full_width`), emitted by the `WolfPreview` window-scan autocmd in `runtime/nvim/init.lua` (and once immediately at setup). `apply_previews` BUILDS the new `HashMap<i64, PreviewInfo>` BEFORE taking the write guard (each `preview_win` / `source_bufnr` decoded via `ext_handle`; a tuple missing either handle SKIPPED), then assigns it WHOLESALE to `Snapshot.previews` under the guard (dropping any closed preview windows), acquires the lock via `write_async`, holds it across no `.await`, does not bump `seq`, and drops it before the caller wakes — the same wholesale-replace shape as `apply_buffers`. `MARKDOWN_DIRTY_EVENT = "wolf_markdown_dirty"` carries a `[source_bufnr, changedtick]` pair for a Markdown source buffer that changed, emitted by the markdown-guarded `TextChanged`/`TextChangedI`/`BufWritePost` autocmds. `apply_markdown_dirty` decodes `source_bufnr` via `ext_handle` and `changedtick` via `as_u64` (a payload missing either is dropped), UPSERTS the pair into `Snapshot.markdown_ticks` under a brief `write_async` guard (no `seq` bump), and wakes after the lock drops. The front-end joins a preview's `source_bufnr` to its tick to decide when to re-pull rendered HTML via `WolfCore::render_preview`.

**Per-window buffer tracking.** `BUFFERS_EVENT = "wolf_buffers"` names an out-of-band notification carrying what EVERY window of the current tabpage is showing — a msgpack array of (now FIVE-element) `[win_id, buf_path, bufnr, is_terminal, is_drawer]` tuples, emitted by the `WolfBuffers` autocmds in `runtime/nvim/init.lua` (which SKIP preview scratch panes emit-side, keeping this map DISJOINT from `Snapshot.previews`). `apply_buffers` BUILDS BOTH maps in the SAME pre-guard pass (so no filesystem work happens under the lock, sidestepping `clippy::significant_drop_in_scrutinee`), then assigns them WHOLESALE under the guard, dropping any stale/closed windows — by DELIBERATELY different rules:

- `Snapshot.buffers` is character-for-character UNCHANGED from before the tuple grew: each `win_id` decoded via `ext_handle`, a missing/non-string element 2 skipped, an EMPTY path skipped (so unnamed windows are ABSENT), a non-empty path canonicalized with a raw fallback. Its only production consumer is `WolfCore::pane_status`, which must not regress.
- `Snapshot.win_buffers` gets an entry for EVERY tuple that decodes a `win`, including unnamed windows (with `path: None`); it REUSES the same canonicalized value (never canonicalizing twice) and decodes `bufnr` via `ext_handle` (defaulting `0`) plus the two booleans via `Value::as_bool` (defaulting `false`). A legacy 2-element tuple therefore yields `bufnr: 0` and both flags `false`.

It acquires the write lock via `write_async`, does not hold it across an `.await`, does not bump `seq`, and drops it before returning so `handle_notify` fires the wake after the lock is released. The macOS front-end joins grid → window → path via `WolfCore::pane_status`.

**Navigation-target fold (`fold_nav_targets`).** A private `RedrawHandler::fold_nav_targets(&self, snap: &Snapshot)` runs at the TAIL of BOTH `apply_buffers` and `apply_previews`, under the snapshot write guard — in both places, because the derived target JOINS `Snapshot.win_buffers` and `Snapshot.previews` and EITHER notification can complete a transition. The candidate windows are the UNION of the two maps' keys, materialized into a local `Vec` BEFORE the nav mutex is taken (so no `MutexGuard` is ever a `for`/`match` scrutinee — `clippy::significant_drop_in_scrutinee`); for each it computes `nav_history::derive_target(snap.win_buffers.get(&win), <that window's non-empty preview source path>)` and, when `Some`, calls `NavHistory::observe(win, target)`. A window in NEITHER map is simply not in the union — **no entry, no push, no prune**, the locked rule realized structurally. There is NO `.await` in the function (so `clippy::await_holding_lock` does not fire), and the mutex is released before it returns.

**`win_close` pruning and its `win_hide` limit.** `win_close` resolves the closing grid's nvim WINDOW handle from `snap.windows` BEFORE removing the entry and hands it to `apply_redraw`'s collector, which prunes that pane's history after the batch (see above). **Known limit, documented and deliberately not fixed:** `win_hide` — fired for every window of a tabpage being LEFT — ALREADY removes the `windows` entry, so a later `win_close` for such a grid cannot recover the handle and that pane's history is ORPHANED. nvim never reuses window handles, so an orphan is only memory (bounded at `MAX_ENTRIES` per orphaned pane per nvim-process lifetime). An "absent from `wolf_buffers` for N emits" reaper would be WRONG: a window in a non-current tabpage is absent from BOTH maps by construction, and pruning it would violate the locked no-prune rule.

**Active-window + layout intents.** Two more out-of-band notifications come from the `WolfLayout` setup in `runtime/nvim/init.lua`. `ACTIVE_WIN_EVENT = "wolf_active_win"` carries the active window handle (from a `WinEnter` autocmd); `apply_active_win` decodes it via `ext_handle` and stores it in `Snapshot.active_win` (no `seq` bump). `LAYOUT_EVENT = "wolf_layout"` carries a split/focus payload; `handle_notify` parses it with `LayoutIntent::from_payload` and pushes the result onto the sibling `IntentQueue` (a brief `Mutex`, never held across an `.await`, no `seq` bump). Both wake the front-end after their lock drops so it can re-read `active_win` and `drain_intents`.

**Tabpage tracking (project/tabpage-per-view).** `TABPAGE_EVENT = "wolf_tabpage"` names an out-of-band notification carrying the current tabpage handle (`nvim_get_current_tabpage()`), emitted by the `TabEnter`/`TabNewEntered` autocmds in the `wolf_setup_tabs` block of `runtime/nvim/init.lua` (plus one initial emit). `apply_tabpage` decodes it via `ext_handle` and stores it in `Snapshot.current_tabpage` (no `seq` bump), then wakes the front-end after the lock drops (same wake-after-unlock invariant as `apply_active_win`). The macOS front-end uses this as the cheap "is my tabpage current" gate for its refocus rebind (see the `wolf-macos` README); the authoritative bind-time value is the blocking `WolfCore::current_tabpage` RPC. A macOS view = one nvim tabpage; only the current tabpage's windows appear in `Snapshot.windows` (the `win_hide` contract below), so a view's pane→grid bindings go stale across a tabpage switch and are re-derived on refocus.

**Per-tabpage cwd tracking (out-of-band `cwd_for_tabpage`).** `TAB_CWDS_EVENT = "wolf_tab_cwds"` names an out-of-band notification carrying every tabpage's tab-local working directory (a msgpack array of `[tabpage_handle, cwd]` pairs for ALL tabpages), emitted by the second `WolfTabs` autocmd (`DirChanged`/`TabNewEntered`/`TabClosed`) in the `wolf_setup_tabs` block of `runtime/nvim/init.lua` (plus one initial emit). `apply_tab_cwds` BUILDS the new `HashMap<i64, PathBuf>` BEFORE taking the write guard (each `tabpage_handle` decoded via `ext_handle`; empty `cwd`s SKIPPED; non-empty paths canonicalized, falling back to the raw path) — mirroring `apply_buffers` — then assigns it WHOLESALE to `Snapshot.tab_cwds` under the guard, dropping any closed tabpages (a `TabClosed` cannot report the closed handle, so the replacement is how they are pruned). It acquires the write lock via `write_async`, does not hold it across an `.await`, does not bump `seq`, and drops it before the wake fires. This is what lets `WolfCore::cwd_for_tabpage` be a cheap, lock-free `Snapshot.tab_cwds` read (no blocking RPC) — authoritative even for a NON-current view — replacing the old blocking `tab_cwd` round-trip that could loop under a wedged nvim.

**Tier-1 open-file mirror (`wolf_open_files`).** `OPEN_FILES_EVENT = "wolf_open_files"` names an out-of-band notification carrying a `{ tp_handle, active_path, files }` triple per tabpage (a msgpack array), emitted by the `WolfOpenFiles` autocmds in the `wolf_setup_open_files` block of `runtime/nvim/init.lua` (plus one initial emit). `apply_open_files` BUILDS the new `HashMap<i64, TabFiles>` BEFORE taking the write guard (each `tp_handle` decoded via `ext_handle`; `active_path` / `files` canonicalized with a raw fallback; a preview/unnamed name skipped nvim-side) — mirroring `apply_tab_cwds` — then assigns it WHOLESALE to `Snapshot.open_files` under a `write_async` guard (no `.await` held, no `seq` bump), waking the front-end after the lock drops. Read by `WolfCore::open_files_for_tabpage` before a crash-restart. `files` is the instance-GLOBAL buflisted set (the known Tier-1 over-reopen limitation).

**`win_hide` on a tabpage switch (OD8).** On a tabpage switch nvim emits `win_hide` for every window of the tabpage being LEFT (NOT `win_close`/`grid_destroy`), then re-emits `win_pos` for them on the way back — reusing the SAME grid id + window handle. `win_hide` therefore REMOVES the window from `Snapshot.windows` (so `windows`/`grid_for_win` reflect only the current tabpage — the contract the front-end's refocus rebind relies on) but KEEPS the grid in `Snapshot.grids` (nvim reuses it, so a rebound window always resolves to a live, paintable grid). Consequence: `WinInfo.hidden` is now effectively always-false / dead — a window either IS in `windows` or is absent, never flagged hidden. nvim WINDOW handles are STABLE across the switch (only grid ids churn), so the front-end re-binds each preserved pane's grid via `grid_for_win(win)`.

**Commands.** `COMMAND_EVENT = "wolf_command"` carries a command id (a user-triggered `:Wolf<Pascal>` Ex-command or `require('wolf').<snake>()` Lua call), registered by the `WolfCommands` setup in `runtime/nvim/init.lua`. `handle_notify` resolves the id via `Command::from_id` (an unknown id is dropped) and pushes the `Command` onto the sibling `CommandQueue` (a brief `Mutex`, never held across an `.await`, no `seq` bump), then wakes the front-end so it can `drain_commands`. There is no autocmd and no emit-on-attach — commands are user-triggered only.

**Theme tracking.** `THEME_EVENT = "wolf_theme"` names an out-of-band notification carrying the effective colors of the optional `WolfCursor` / `WolfTitlebar` app-theme highlight groups, emitted by the `WolfTheme` `ColorScheme` autocmd in `runtime/nvim/init.lua` (and once immediately at setup, so the startup colorscheme is reported). The payload is FOUR flat integers — `[cursor_fg, cursor_bg, titlebar_fg, titlebar_bg]` — each a packed `0xRRGGBB` color or `-1` for an unset channel (flat scalars sidestep the empty-Lua-table map-vs-array msgpack ambiguity a table payload would have for a cleared group). `apply_theme` accepts a value only when it is a valid 24-bit color (`0..=0xFFFFFF`); everything else (including the `-1` sentinel and missing args) maps to `None`. The args are parsed BEFORE the `write_async` lock is taken (the guard is held only for the bare `snap.theme` assignment, never across an `.await`); it does NOT bump `seq` (a theme change is not a redraw frame), and `handle_notify` fires the wake after the lock drops so front-ends repaint the cursor / re-apply the titlebar color.

**Directory tracking.** `CWD_EVENT = "wolf_cwd"` names an out-of-band notification carrying the captive nvim's working directory (`getcwd()`), emitted by the `WolfDir` `DirChanged` autocmd in `runtime/nvim/init.lua` (and once immediately at setup). `apply_cwd` parses the first argument: a non-empty value is canonicalized (to match the canonical cwds the MRU cache keys on, falling back to the raw path if canonicalization fails) and stored in the sibling `TrackedCwd` cell; an empty/missing value leaves it unchanged. The canonicalize is performed BEFORE taking the `RwLock` write guard, so the guard is held only for the bare assignment (never across filesystem work, also sidestepping `clippy::significant_drop_in_scrutinee`). Unlike the other out-of-band paths, `apply_cwd` is synchronous and fires NO wake: nvim's cwd is not render state, and the `:cd`/`:lcd`/`:tcd` that triggered it already produces its own redraw flush. The input pump reads this cell to scope the global MRU store by nvim's live cwd when recording an opened file. `apply_cwd` also decodes a second argument, `is_initial = matches!(args.get(1).and_then(Value::as_bool), Some(true))`, that `init.lua` sets on the one-shot INITIAL (setup-time) emit. For that initial emit the tracked cell is updated as above but `apply_cwd` returns EARLY, skipping the MRU record: the passive launch cwd is not a directory the user opened, so it must not pollute the recent-dirs MRU. For a genuine `DirChanged` (unflagged — any real `:cd` / `:lcd` / `:tcd`, including the Open-Folder chdir) the (already-canonical) target is recorded into the always-on global `RecentDirs` MRU (`self.recent_dirs.record(&target)`), so every directory the user changes into is moved-or-added to the top of `folder-mru.sqlite`; that record is fire-and-forget and never bumps `seq` or wakes the front-end. Per-tab cwd is NO LONGER mirrored core-side into a state store — the front-end reads each tab's live cwd at snapshot time.

## `nvim.rs`

Spawning and supervising the captive, hermetic Neovim child process.

- `NvimConfig { nvim_bin, init_lua, appname, state_root, swap_dir, cwd, initial_cols, initial_rows, .. }` — `from_env(init_lua, cwd, swap_dir: Option<PathBuf>, cols, rows)` reads `WOLF_NVIM_BIN` (erroring `BinNotSet` if unset/empty) and creates a private temp dir to host the isolated `XDG_*` state. The temp dir is kept alive by an internal guard. `cwd` is the working directory the captive nvim is launched in (so its `getcwd()` starts there rather than inheriting the host process's cwd). `swap_dir` is the DURABLE, per-project SWAP directory (from [`state::swap_dir_for`](#staters), STABLE across respawns of the same project — NOT the ephemeral `TempDir`/`state_root`), exported to nvim as the `WOLF_SWAP_DIR` env var so init.lua points `'directory'` at it; an unresolvable `state_dir()` falls back to `state_root.join("swap")` (ephemeral, documented — no panic).
- `NvimError` — `BinNotSet`, `StateDir(io::Error)`, `Spawn(io::Error)`, `Rpc(String)`, `Attach(String)`, `Timeout(&'static str, Duration)`. The `Timeout` variant (message `nvim RPC '{0}' timed out after {1:?}`) is emitted ONLY by `api::WolfCore::block_on_rpc` when an interactive synchronous RPC exceeds the core's `rpc_timeout` budget (see [`api.rs`](#apirs)); each guarded call site already matches `Err(_) => <fallback>`, so it needs no per-site branch and degrades to that fallback instead of hanging the main thread. It is never constructed by `nvim.rs` itself.
- `spawn(&NvimConfig, RedrawHandler, liveness: Arc<AtomicU8>, wake: WakeFn) -> Result<NvimProcess, NvimError>` — creates the isolated XDG dirs + the durable `swap_dir` (`create_dir_all`) and launches `nvim --embed --clean -u <init.lua> -i NONE` (the former `-n` flag REMOVED — it zeroed `updatecount` and disabled swap) with `NVIM_APPNAME` and `XDG_{CONFIG,DATA,STATE,CACHE}_HOME` pinned under `state_root` PLUS `WOLF_SWAP_DIR = cfg.swap_dir` (stdin/stdout piped, and stderr PIPED — no longer null), and sets the child's working directory to `cfg.cwd`, wiring the handler via `new_child_cmd`. stderr is drained to the log by a `tokio::spawn`ed `BufReader::lines()` task (`tracing::warn!(target: "nvim_stderr", …)`), and the moved io-loop `JoinHandle` is owned by a SUPERVISOR task that marks the shared `liveness` `Dead` (firing `wake`) on stdout EOF — UNLESS the per-process `shutting_down` flag is set (an intentional exit). The `liveness` + `wake` are cloned into the process for the supervisor; the same pair is reused verbatim on a restart respawn.
- `NvimProcess` — its fields now include `child`, a per-process `shutting_down: Arc<AtomicBool>`, and the `supervisor: JoinHandle<()>` (the io-loop handle is MOVED into the supervisor, no longer a `NvimProcess` field). Methods: `handle()` (clone the RPC handle), `ui_attach(cols, rows)` (attaches `ext_linegrid` + `ext_multigrid` + `ext_popupmenu` + `ext_messages` + `rgb` — `ext_messages` IMPLICITLY enables `ext_cmdline` and forces `cmdheight=0`, so grid 1 empties and the front-ends paint the command line / messages natively from `Snapshot.cmdline` / `Snapshot.toast`), `try_resize(cols, rows)` (`nvim_ui_try_resize`, drives the outer grid 1), `try_resize_grid(grid, cols, rows)` (`nvim_ui_try_resize_grid`, drives a single window grid), `current_dir()` (see below), `list_buffers()` (see below), `yank_visual_selection()` (see below), `setup_current_file_tracking()` (see below), `setup_buffer_tracking()` (see below), `setup_full_width()` (see below), `setup_layout()` (see below), `setup_dir_tracking()` (see below), `setup_theme_tracking()` (see below), `setup_commands()` (see below), `setup_tabs()` (see below), `setup_view_tracking()` (see below), `setup_preview()` (see below), `render_preview(source_bufnr)` / `open_preview(mode)` / `edit_source(mode)` / `preview_file(win, path)` / `current_markdown_bufnr()` (see below), `setup_open_files()` (see below), the tabpage RPCs `create_tabpage`/`current_tabpage`/`set_current_tabpage`/`close_tabpage` (see below), `kill_in_place(&mut self)` (the crash/stall-restart force-kill: sets `shutting_down` FIRST so the old supervisor won't re-fire `Dead`, `start_kill`s the child, bounds `child.wait()`, then `supervisor.abort()`s — used by `WolfCore::restart_nvim`), and `shutdown(self)` (sets `shutting_down` FIRST, sends `qa!` bounded by a grace timeout, reaps via a bounded `child.wait()` + `start_kill()` on overrun — no longer awaits the io loop, the supervisor owns it — then `supervisor.abort()`s; force-kills a WEDGED child).
- `current_dir(&self) -> Result<PathBuf, NvimError>` — returns the captive nvim's current working directory via `nvim_call_function("getcwd", [])` (no-arg `getcwd`, so it honors the window/tab-local cwd set by `:cd`/`:lcd`/`:tcd`). The result is extracted via `Value::as_str`; a missing or empty-after-trim value yields `NvimError::Rpc` so the caller (`WolfCore::open_in_browser`, which uses it to root the loopback preview site) can fall back rather than serving from an unusable path. (The file-search picker no longer calls this — `resolve_search_root` now resolves its root out-of-band via `live_cwd()`.)
- `ignorecase(&self) -> impl Future<Output = Result<bool, NvimError>> + Send + 'static` — reads the captive nvim's global `ignorecase` option via `nvim_get_option_value("ignorecase", {})`, extracting the result via `Value::as_bool` (defaulting to `false` when missing or non-boolean). Modeled on `current_dir` (clones the RPC handle into an `async move` so it satisfies the `Send + 'static` `block_on_rpc` bound). Read ONCE by `WolfCore::ignorecase` when the sidebar search panel is first shown, to seed the "case sensitive" toggle (which is INVERTED: `case_sensitive = !ignorecase`).
- `list_buffers(&self) -> Result<Vec<BufInfo>, NvimError>` — the blocking buffer-picker query: `nvim_call_function("getbufinfo", [{buflisted = 1}])` returns only `buflisted` buffers (loaded or not — a `:badd` buffer appears, possibly with `lastused == 0`). The result is an array of maps; each is decoded into a `BufInfo` by reading `bufnr` (i64), `name` (str), `lastused` (i64), and `changed` (i64 → `modified = changed != 0`), skipping any malformed entry (missing `bufnr`). A non-array result is an `NvimError::Rpc`. `WolfCore::list_buffers` `block_on`s this and MRU-orders/ranks the result via `buffer_picker::rank_buffers`.
- `yank_visual_selection(&self) -> Result<Option<String>, NvimError>` — the synchronous copy path: runs ONE mode-guarded STATIC Lua snippet via `nvim_exec_lua` (no string interpolation, so no injection hazard). The snippet reads `nvim_get_mode().mode` and returns `vim.NIL` UNLESS the mode is visual (`v`), visual-line (`V`), or visual-block (`<C-v>` = `"\22"`); otherwise it yanks synchronously (`nvim_feedkeys('y', 'nx', false)` — the `x` drains typeahead so the yank completes before the call returns) and returns the unnamed register `getreg('"')` (matching vim's visual-`y` semantics). The mode guard prevents a `y` operator-pending hang when invoked outside visual mode. `as_str` → `Some`, `Nil`/absent → `None`; RPC errors → `NvimError::Rpc`. `WolfCore::copy_visual_selection` `block_on`s this.
- `setup_current_file_tracking(&self) -> Result<(), NvimError>` — installs the current-file autocmd inside the captive nvim. It looks up this RPC channel's id via `nvim_get_api_info` (which returns `[channel_id, metadata]`), then calls the `_G.wolf_setup_current_file_tracking` helper (defined in `runtime/nvim/init.lua`) over `nvim_exec_lua`, passing the channel id as a Lua vararg (`...`) rather than interpolating it into the code string (no injection/formatting hazard). The helper registers a `BufEnter`/`BufWinEnter`/`BufFilePost` autocmd that `rpcnotify`s `wolf_current_file` and emits once immediately. `api::WolfCore::start` calls this after `ui_attach`, so the front-end learns the active buffer's path as soon as the UI is attached and on every later buffer switch / rename.
- `setup_buffer_tracking(&self) -> Result<(), NvimError>` — installs the per-window buffer-tracking autocmds inside the captive nvim. Mirrors `setup_current_file_tracking`: it looks up this RPC channel's id via `nvim_get_api_info`, then calls the `_G.wolf_setup_buffer_tracking` helper (defined in `runtime/nvim/init.lua`) over `nvim_exec_lua`, passing the channel id as a Lua vararg. The helper registers `BufEnter`/`BufWinEnter`/`BufFilePost`/`WinEnter`/`WinNew`/`WinClosed` autocmds that `rpcnotify` `wolf_buffers` with a list of `[win, nvim_buf_get_name(buf)]` pairs for ALL windows, emitting once immediately. `api::WolfCore::start` calls it after `setup_current_file_tracking`, so the front-end learns each window's buffer path (for the per-pane statusbar) as soon as the UI is attached and on every later buffer/window change.
- `setup_full_width(&self) -> Result<(), NvimError>` — installs the per-window full-width tracking autocmds inside the captive nvim. Mirrors `setup_buffer_tracking`: it looks up this RPC channel's id via `nvim_get_api_info`, then calls the `_G.wolf_setup_full_width` helper (defined in `runtime/nvim/init.lua`) over `nvim_exec_lua`, passing the channel id as a Lua vararg. The helper registers `BufEnter`/`BufWinEnter`/`WinEnter`/`WinNew`/`WinClosed` autocmds that `rpcnotify` `wolf_full_width` with a list of `[win, vim.b[buf].wolf_full_width == true]` pairs for ALL windows (emitting once immediately) and exposes `_G.wolf_emit_full_width` so `wolf_toggle_full_width` can re-emit after a background flip. `api::WolfCore::start` calls it after `setup_buffer_tracking`, so the front-end learns each editor pane's content-width mode (to thread into its geometry) as soon as the UI is attached and on every later change.
- `setup_layout(&self) -> Result<(), NvimError>` — installs the split-panes layout overrides inside the captive nvim. Like the current-file setup, it looks up this RPC channel's id via `nvim_get_api_info`, then calls the `_G.wolf_setup_layout` helper (defined in `runtime/nvim/init.lua`) over `nvim_exec_lua`, passing the channel id as a Lua vararg. The helper rebinds the `<C-w>` split/close/focus chords and the `:split`/`:vsplit`/`:close` Ex-commands to `rpcnotify` `wolf_layout` intents, and registers a `WinEnter` autocmd that `rpcnotify`s `wolf_active_win`. `api::WolfCore::start` calls it after `setup_current_file_tracking`. (There is no standalone `set_current_win` method: pane focus flows through the ordered input pump as `InputEvent::FocusWin`, so it never races pending keystrokes.)
- `setup_dir_tracking(&self) -> Result<(), NvimError>` — installs the directory-tracking autocmd inside the captive nvim. Mirrors `setup_current_file_tracking`: it looks up this RPC channel's id via `nvim_get_api_info`, then calls the `_G.wolf_setup_dir_tracking` helper (defined in `runtime/nvim/init.lua`) over `nvim_exec_lua`, passing the channel id as a Lua vararg. The helper registers a `DirChanged` autocmd (covering `:cd`/`:lcd`/`:tcd`) that `rpcnotify`s `wolf_cwd` with `getcwd()`, emitting once immediately so the startup cwd is reflected. `api::WolfCore::start` calls it after `setup_layout`, so core learns nvim's live cwd as soon as the UI is attached and on every later directory change — which the directory-scoped MRU (`self.mru.recent`/`record`, filtered by that live cwd) follows for both the picker seed and the record-on-open path.
- `setup_theme_tracking(&self) -> Result<(), NvimError>` — installs the theme-tracking autocmd inside the captive nvim. Mirrors `setup_dir_tracking`: it looks up this RPC channel's id via `nvim_get_api_info`, then calls the `_G.wolf_setup_theme_tracking` helper (defined in `runtime/nvim/init.lua`) over `nvim_exec_lua`, passing the channel id as a Lua vararg. The helper registers a `ColorScheme` autocmd (covering `:colorscheme` and `:set background=...`, which re-sources the active scheme) that `rpcnotify`s `wolf_theme` with the effective `WolfCursor` / `WolfTitlebar` colors, emitting once immediately so the startup colorscheme is reflected. `api::WolfCore::start` calls it after `setup_dir_tracking`.
- `setup_commands(&self) -> Result<(), NvimError>` — registers the Wolf command faces inside the captive nvim. Mirrors `setup_theme_tracking`: it looks up this RPC channel's id via `nvim_get_api_info`, then calls the `_G.wolf_setup_commands` helper (defined in `runtime/nvim/init.lua`) over `nvim_exec_lua`, passing the channel id AND the command list as Lua varargs (never interpolated). The helper seeds `package.loaded['wolf']` (so `require('wolf')` resolves under `--clean`) and, per pair, registers a `require('wolf').<id>()` Lua function and a `:<ex_command>` user command (`nargs=0, force=true`), each `rpcnotify`ing `wolf_command '<id>'`. `api::WolfCore::start` calls it after `setup_theme_tracking`. - `setup_tabs(&self) -> Result<(), NvimError>` — registers the tabpage tracking + lifecycle helpers inside the captive nvim (the same channel-id-via-`nvim_get_api_info` pattern). It invokes `_G.wolf_setup_tabs(chan)` (in `runtime/nvim/init.lua`), which registers the `TabEnter`/`TabNewEntered` autocmds that `rpcnotify` `wolf_tabpage` (plus one initial emit), registers a second `DirChanged`/`TabNewEntered`/`TabClosed` autocmd that `rpcnotify`s `wolf_tab_cwds` with a list of `[tabpage_handle, getcwd(-1, n)]` pairs for ALL tabpages (plus one initial emit — the out-of-band feed `cwd_for_tabpage` reads), locks out nvim-internal tabpage navigation/creation (OD4: the `gt`/`gT`/`<C-w>gt`/`<C-w>gT`/`<C-PageUp>`/`<C-PageDown>` chords → `<Nop>` and the typed `:tabnew`/`:tabnext`/`:tabprevious`/`:tabonly`/`:tabclose`/`:tabmove` Ex-commands — but NOT `:tcd`/`:lcd`/`:cd`), and defines the `wolf_create_tabpage` / `wolf_close_tabpage` helpers. `api::WolfCore::start` calls it after `setup_commands`.
- `create_tabpage(&self, cwd: &str) -> Result<i64, NvimError>` — runs the `_G.wolf_create_tabpage` helper (`tabnew`; `:tcd` when `cwd` is non-empty) and returns the new tabpage's stable HANDLE (decoded via `ext_handle`).
- `current_tabpage(&self) -> Result<i64, NvimError>` — `nvim_get_current_tabpage`, decoded via `ext_handle` (the authoritative first-view bind read right after attach).
- `set_current_tabpage(&self, handle: i64) -> Result<(), NvimError>` — `nvim_set_current_tabpage` (make a view's tabpage current).
- `close_tabpage(&self, handle: i64) -> Result<(), NvimError>` — runs `_G.wolf_close_tabpage` (resolves the handle to its NUMBER and runs `<n>tabclose` under `pcall`, swallowing a last-tabpage `E784`).
- `setup_open_files(&self) -> Result<(), NvimError>` — installs the Tier-1 open-file mirror inside the captive nvim (the same channel-id-via-`nvim_get_api_info` pattern). It invokes `_G.wolf_setup_open_files(chan)` (in `runtime/nvim/init.lua`), which installs the `WolfOpenFiles` augroup emitting `wolf_open_files` (a `{ tp_handle, active_path, files }` triple per tabpage; `files` the instance-GLOBAL buflisted set). `api::WolfCore::start` calls it after `setup_tabs`; `restart_nvim` re-runs the identical setup chain.
- `setup_view_tracking(&self) -> Result<(), NvimError>` — installs the buffer-picker per-pane view tracking inside the captive nvim. UNLIKE the other `setup_*` helpers it passes NO channel id and NO payload: `_G.wolf_setup_view_tracking()` (in `runtime/nvim/init.lua`) emits no `rpcnotify` — it only maintains an in-nvim `(winid, bufnr) -> winsaveview()` cache (via `BufLeave`/`WinLeave`/`WinClosed` autocmds) and defines the `_G.wolf_switch_buffer(win, buf)` helper (a window-scoped `nvim_win_set_buf` + conditional `winrestview`) that the `SwitchBuffer` input event calls. So this is a bare `nvim_exec_lua("wolf_setup_view_tracking()", [])`. `api::WolfCore::start` calls it after `setup_tabs`, keeping core view-agnostic (no view payload crosses the boundary).
- `setup_preview(&self) -> Result<(), NvimError>` — installs the Markdown-preview tracking + dirty-signal autocmds inside the captive nvim. Mirrors `setup_buffer_tracking` (the channel-id-via-`nvim_get_api_info` pattern): it invokes `_G.wolf_setup_preview(chan)` (in `runtime/nvim/init.lua`), which registers the `WolfPreview` augroup — a `WinEnter`/`BufWinEnter`/`WinNew`/`WinClosed`/`BufWinLeave` window-scan that `rpcnotify`s `wolf_preview` with `[preview_win, source_bufnr, source_abs_path, source_full_width]` tuples (the 4th element the SOURCE buffer's `b:wolf_full_width`; emitting once immediately), plus markdown-guarded `TextChanged`/`TextChangedI`/`BufWritePost` autocmds that `rpcnotify` `wolf_markdown_dirty` with `[source_bufnr, changedtick]`. `api::WolfCore::start` calls it LAST, after `setup_view_tracking`.
- `render_preview(&self, source_bufnr: i64) -> Result<String, NvimError>` — the blocking preview render: delegates to the crate-internal free function `render_source_html(&self.nvim, source_bufnr, WidthMode::Full)` (see below) — the IN-APP preview renders full-bleed and lets the webview FRAME cap it to the ~90-char width. That path now ALSO enumerates the buffer's fenced code blocks and asks the captive Neovim's treesitter to highlight them (see `render_source_html` / `highlight_code_blocks` below), so the returned HTML carries inline-styled code tokens; any block that cannot be highlighted degrades to plain `<pre><code>`. A non-array result / RPC error (e.g. an unloaded buffer) is an `NvimError::Rpc`; `WolfCore::render_preview` `block_on`s this and maps the error to an empty string.
- `current_markdown_bufnr(&self) -> Result<i64, NvimError>` — runs ONE static, mode-agnostic Lua snippet over `nvim_exec_lua` (no string interpolation): it returns `nvim_get_current_buf()` when the current buffer's `&filetype == "markdown"`, else `0`. The browser-preview command (`WolfCore::open_in_browser`) uses this to PIN the source buffer the loopback server re-renders, gating on markdown the same way the in-app preview does. An RPC error is propagated as `NvimError::Rpc`.
- `buffer_path(&self, bufnr: i64) -> Result<String, NvimError>` — reads buffer `bufnr`'s full name via `nvim_buf_get_name`, returning the absolute path (or the EMPTY string for an unnamed buffer). `WolfCore::open_in_browser` calls it (before the `browser_preview` lock) to root the static site at the pinned file — `browser_preview::build_target` canonicalizes the returned path and computes its root-relative URL. An RPC error is propagated as `NvimError::Rpc`.
- `render_source_html(nvim: &Neovim<..>, source_bufnr: i64, width_mode: WidthMode) -> Result<String, NvimError>` (a crate-internal FREE function, not a method) — `nvim_buf_get_lines(source_bufnr, 0, -1, false)` reads the whole SOURCE buffer and joins the lines with `\n`, then enumerates its code blocks (`crate::markdown::code_blocks`), asks the captive Neovim to treesitter-highlight them (`highlight_code_blocks`, below — skipped entirely when there are no blocks), and renders via `crate::markdown::render_html_with_highlights` with the fixed `PreviewTheme::Default` (OD5), the given `width_mode`, and the per-block highlight results. The highlight pass is TOTALLY graceful: any block Neovim cannot highlight (unknown language, missing parser/query, or the no-op treesitter path on Linux/cargo) renders as plain `<pre><code>`. Shared by `NvimProcess::render_preview` (the in-app preview pane, passing `WidthMode::Full` so the webview frame caps it) and the `browser_preview` accept loop's LIVE-PINNED-BUFFER path (each `GET /<relpath>` for the pinned source buffer, passing `WidthMode::Capped` so the standalone browser document caps + centers itself to ~90 chars). The browser server's STATIC arbitrary-`.md`-from-disk path does NOT go through here (no live nvim buffer to highlight against) and stays plain. A non-array result / RPC error is an `NvimError::Rpc`.
- `highlight_code_blocks(nvim: &Neovim<..>, blocks: &[markdown::CodeBlockInfo]) -> Vec<Option<markdown::BlockHighlight>>` (a crate-internal async FREE function) — asks the captive Neovim to treesitter-highlight a BATCH of code blocks in ONE RPC round-trip via `nvim_exec_lua("return wolf_highlight_code_blocks(...)", …)`, passing an array of `[text, lang]` pairs (`lang` empty when the fence declares none; see `runtime/nvim/README.md`). The reply is an array whose i-th entry is either `false`/nil (not highlightable) or an array of 7-element span tuples `[row, start_col, end_col, fg, bold, italic, underline]`. This is TOTAL graceful fallback: any RPC error, a non-array reply, or a length mismatch yields `vec![None; blocks.len()]` (every block plain), and any individual malformed entry decodes to `None`. It never unwraps and never panics. The private `decode_block_highlight` decodes one entry into an `Option<BlockHighlight>` (`Boolean(false)`/`Nil` → `None`; a `fg < 0` → `color: None`), and `value_is_true` reads a flag as either a real boolean or a nonzero integer.
- `open_preview(&self, mode: &str) -> Result<i64, NvimError>` — runs the `_G.wolf_open_preview` helper (defined in `runtime/nvim/init.lua`) over `nvim_exec_lua`, passing `mode` as a Lua vararg (never interpolated). `mode` is `"split_right"` (single-pane: reuse `wolf_do_split('v')` then `nvim_win_set_buf(0, previewbuf)`), `"active"` (multi-pane: just `nvim_win_set_buf(0, previewbuf)`), or `"reuse_preview_pane"` (exactly two panes with the OTHER pane already a preview: scan the current tabpage for the other window carrying `b:wolf_preview_source` and `nvim_win_set_buf(target, previewbuf)` into it, leaving the current window untouched; falls back to the `"active"` current-window bind when none). The helper no-ops (returns `0`) unless `&filetype == "markdown"`, else creates-or-reuses the per-source scratch buffer and returns its bufnr (decoded via `Value::as_i64`); after any placement it re-emits `_G.wolf_emit_previews` (so a background reuse rebind is learned) and `_G.wolf_emit_current_file` (so `is_markdown_active` stays correct). `WolfCore::open_preview` `block_on`s this.
- `edit_source(&self, mode: &str) -> Result<i64, NvimError>` — the INVERSE of `open_preview`: runs the `_G.wolf_edit_source` helper (defined in `runtime/nvim/init.lua`) over `nvim_exec_lua`, passing `mode` as a Lua vararg (never interpolated). It navigates the ACTIVE preview pane back to its SOURCE Markdown file. `mode` is `"split_left"` (single-pane: `wolf_do_split('v')` then bind the source into the ORIGINAL window so the editor lands on the LEFT and the preview on the RIGHT), `"reuse_editor_pane"` (exactly two panes with the OTHER pane a non-preview editor: bind the source into + focus that window, falling back to the current), or `"active"` (else: replace the preview in the active window). The helper reads `b:wolf_preview_source` / `b:wolf_preview_source_bufnr` off the CURRENT buffer and no-ops (returns `0`) unless it is a preview; it prefers `nvim_win_set_buf(win, source_bufnr)` when the bufnr is valid (no disk re-read, no MRU churn), else focuses the target window + `:edit fnameescape(source_path)`; NO MRU is recorded. After any placement it re-emits `_G.wolf_emit_previews` + `_G.wolf_emit_current_file` and returns the source bufnr (decoded via `Value::as_i64`). `WolfCore::edit_source` `block_on`s this.
- `preview_file(&self, win: i64, path: &str) -> Result<i64, NvimError>` — repoints the preview window `win` at the Markdown file at absolute `path` (a linked file the user clicked in the preview), replacing that pane's current preview with the linked file's. Runs the `_G.wolf_preview_file` helper (defined in `runtime/nvim/init.lua`) over `nvim_exec_lua`, passing `win` and `path` as Lua varargs (never interpolated). The helper `bufadd`+`bufload`s `path`, gates it through `vim.filetype.match` (setting `filetype=markdown` when it matches), creates or reuses that source's preview scratch buffer via `_G.wolf_ensure_preview_buf`, binds it into `win` (falling back to the current window when `win` is missing/zero/invalid), and re-emits the previews / current-file snapshots. Returns the linked file's SOURCE bufnr (`> 0`) on success; `0` when `path` is empty, unreadable, or not Markdown (decoded via `Value::as_i64`). `path` is ABSOLUTE — the helper does NO relative resolution (the front-end resolves it from WebKit's `file://` URL). RPC failure maps to `NvimError::Rpc`; `WolfCore::preview_file` `block_on`s this and maps that to `0`.
- `history_open(&self, win: i64, path: &str)` and `history_set_buf(&self, win: i64, bufnr: i64)` — both `fn(&self) -> impl Future<Output = Result<i64, NvimError>> + Send + 'static`, mirroring `preview_file` exactly (clone the handle + own the args, so `block_on_rpc` can spawn+detach them). They back the per-pane navigation history's `Edit` and `Terminal`/`Untitled` targets by running the `_G.wolf_history_open` / `_G.wolf_history_set_buf` helpers over `nvim_exec_lua` with Lua varargs. Both are WINDOW-SCOPED (`nvim_win_set_buf` via `wolf_switch_buffer`, plus that pane's saved-view restore), never `:edit`, and both return the bufnr actually bound (`> 0`) or `0` — for an invalid window/bufnr, an empty/unreadable path, or a bind that FAILED (the cmdwin is open, the window is `'winfixbuf'`, a modified buffer cannot be abandoned). `WolfCore::apply_nav` turns a `0` into a cursor REVERT. `history_open` prefers an EXISTING buffer whose name equals — or symlink-resolves to — `path` before falling back to `bufadd` + `bufload`, which is what makes navigating back to an unsaved `Untitled N.md` rebind that same MODIFIED buffer rather than reading a file that was never written.

All RPC is generic/untyped (`Neovim::call`).

## `browser_preview.rs`

The lazily-started, LOOPBACK-ONLY HTTP server behind `api::WolfCore::open_in_browser` (the "Preview in Browser" command). One server per `WolfCore` (per project), serving a tiny STATIC SITE rooted at the project so relative links in the rendered Markdown resolve in URL space. It is hand-rolled HTTP/1.1 on the core's existing tokio runtime — only tokio's `net` feature, NO HTTP-server crate — so it honors the crate's one hard rule (no GUI toolkit in the dependency tree) and adds no new crate node. File I/O for the static site is blocking `std::fs` (tiny local files); the write path is `Vec<u8>` end-to-end so binary assets are never lossily transcoded.

- `Target { bufnr: i64, root: PathBuf, pinned_abs: PathBuf, pinned_relpath: String }` (crate-internal, `Clone`) — the pinned target the server serves: the PINNED source buffer re-rendered live at `/<relpath>`, the canonical `root` the static site is served from (the traversal guard's containment boundary), the pinned file's canonical absolute path (empty for an unnamed buffer), and its `/`-joined path relative to `root` (empty when unnamed or not under `root`). Rebuilt by `build_target` on each `open_in_browser` and swapped in via `set_target`.
- `BrowserPreview` (the public type, re-exported at the crate root) — a live server handle: `port() -> u16` (the OS-assigned loopback port), `set_target(Target)` (re-point the PINNED target, a short `Mutex` swap; each connection clones the current target out, so no coordination with the accept loop is needed), and `abort()` (idempotent accept-loop cancellation; dropping the core's runtime cancels the task too). It holds the bound `port`, the pinned `target: Arc<Mutex<Target>>`, and the accept task's `AbortHandle`. Owned by `WolfCore` so it outlives any single `open_in_browser` call.
- `spawn(runtime, nvim, snapshot: SharedSnapshot, initial: Target) -> io::Result<BrowserPreview>` (crate-internal) — binds `(Ipv4Addr::LOCALHOST, 0)` (loopback only, random port; NEVER `0.0.0.0`, a hard security requirement) via `runtime.block_on`, reads the assigned port back from `local_addr()`, and spawns the accept loop on `runtime` pinned initially at `initial`. A bind failure surfaces as an `io::Error` (the caller logs it and returns no URL).
- The accept loop spawns a per-connection handler that reads the request head (capped at `MAX_HEAD_BYTES = 8 KiB`), parses the request target, and hands it to the async `route`, which clones the `Target` out under a SHORT lock DROPPED before any `.await` (so no lock is held across an await — `clippy::await_holding_lock`) and routes: `GET /tick` → the pinned buffer's current `changedtick` (from `Snapshot.markdown_ticks`, `0` until first dirtied) as plain text; `GET /` → the pinned buffer rendered live when it is unnamed (empty relpath), else a 302 redirect to `/<relpath>`; the PINNED file (matched on its stored `pinned_relpath`, or defensively its `pinned_abs`) → `nvim::render_source_html` wrapped by `render_page` (the auto-reload `<script>` injected immediately before the single `</body>` via `replacen(…, 1)`), on a render error the `fallback_page` (still carrying the reload script); any other target → `resolve_path` (the traversal guard) then a linked Markdown file rendered STATICALLY from disk via `markdown::render_html` with `WidthMode::Capped` (no reload script), or an existing non-Markdown file served as RAW bytes with `content_type_for`; a target that does not exist or escapes `root` → `not_found_response` (404).
- **Injected reload JS** (`reload_script(tick)`) polls `GET /tick` every 1000ms with `fetch('/tick', { cache: 'no-store' })`, `parseInt`s the reply, and calls `location.reload()` when it is a number that differs from the render-time `baseline` (a `.catch` swallows fetch errors so polling continues). Embedding the render-time tick as the baseline avoids a spurious first-poll reload. Only the pinned page carries it — `/tick` tracks only the pinned buffer, so a navigated-to linked page is a static snapshot.
- `build_target(bufnr, cwd: Option<PathBuf>, pinned_raw: &str) -> Target` (crate-internal) — canonicalizes `pinned_raw` (empty stays empty), then picks `root` = `canonicalize(cwd)` when that succeeds AND the pinned file lives under it, else falls back to `canonicalize(pinned_abs.parent())`; `pinned_relpath` is `relpath_between(root, pinned_abs)`.
- Path/URL + traversal helpers — `resolve_path(root, url_target) -> Option<PathBuf>` (strips `?query`/`#fragment`, percent-decodes, trims a leading `/`, joins onto `root`, `std::fs::canonicalize`s — a non-existent path yields `None` — and requires the result to `starts_with(root)`, the HARD path-traversal guard, so `root` must itself be canonical, e.g. macOS `/var`→`/private/var`); `relpath_between(root, abs) -> String` (pure, the `/`-joined relative path or `""`); `encode_url_path(rel)` (percent-encodes each `/`-split segment, unreserved `A-Za-z0-9-_.~` kept, e.g. `a b.md`→`a%20b.md`); `percent_decode(s)`; `is_markdown_path(path) -> bool` (case-insensitive `md`/`markdown`/`mdown`/`mkd`/`mkdn`/`mdwn`); `content_type_for(path) -> &'static str` (a hand-written extension table — `image/png`, `image/jpeg`, `image/svg+xml`, `text/css; charset=utf-8`, etc., unknown → `application/octet-stream` — no `mime` crate).
- Response/render helpers — `parse_request_target` (GET-only, first-line target), `render_page`, `reload_script`, `fallback_page`, `render_pinned_live`, `http_response` (frames a `&str` body), `http_response_bytes` (frames raw `&[u8]` — the binary-safe path), `redirect_response` (a `302 Found` with `Location`), `not_found_response`, `current_tick` — plus a module `#[cfg(test)] mod tests` (parse/render_page/reload_script/fallback, the `Vec<u8>` `http_response`/`http_response_bytes` byte-exact non-UTF8 body / `redirect_response` / `not_found_response`, `content_type_for` / `is_markdown_path` / `relpath_between` / `encode_url_path` / `percent_decode`, a tempdir `resolve_path` traversal-guard test, and a `#[tokio::test]` asserting the listener binds loopback-only). The tick read drops the snapshot guard before the caller `.await`s a render, and the bufnr/pinned path/cwd are resolved OUTSIDE the `browser_preview` lock in `api.rs`, so no lock is ever held across an `.await` or the nvim RPC `block_on`.

## `files.rs`

The async, streaming file-list traversal and its `FileSearch` session. This is the picker's view of "all files under the search root": the synchronous MRU seed plus the background walk's results, streamed in as they are found.

Key types:

- `FileEntry { path: PathBuf, display: String, mru_rank: Option<u32> }` — the canonical home of `FileEntry` (re-exported from `mru` and the crate root). `path` is absolute (used to issue `InputEvent::Open`); `display` is the path relative to the search root (what the UI shows and `rank` ranks); `mru_rank` is `Some(0)` for the most recently opened file, `None` if not in the MRU.
- `FileSearchState { entries: Vec<FileEntry>, complete: bool, truncated: bool, version: u64, .. }` — the collected state behind one `RwLock`. `entries` is the MRU seed first, then streamed traversal results in discovery order; `complete` flips true once the walk finishes; `truncated` flips true when the walk stopped early at a cap (the entry cap or the time budget) — the result is complete but NOT exhaustive (more files exist under the root than were streamed); `version` is a monotonic counter bumped on every append so readers can detect change. A cap-truncated search still sets `complete = true` (the picker treats it as done); a real `cancel` sets neither `complete` nor `truncated`; depth pruning is SILENT (invisible in the `ignore` API) and does NOT set `truncated`. A private `seen: HashSet<PathBuf>` dedups the MRU seed against rediscovered files. `FileSearchState::seeded(seed)` (crate-internal) builds the initial state at `version = 1`, `complete = false`, `truncated = false`.
- `FileSearchReadGuard` — an OWNED read guard (`ArcRwLockReadGuard`) that `Deref`s to `FileSearchState`, so a reader holds `guard.entries` / `.complete` / `.truncated` / `.version` independently of the `FileSearch`'s lifetime (mirrors `OwnedSnapshotReadGuard`).
- `FileSearch { .. }` — a live search session: `read() -> FileSearchReadGuard`, `cancel()` (sets an `AtomicBool`), and `Drop` also cancels (so closing the picker or starting a new search stops the old walk promptly). `FileSearch::from_parts(state, cancel)` is crate-internal.

`spawn_traversal(root, state, cancel, wake, handle, bounds)` (crate-internal) runs the walk on `handle.spawn_blocking` (the `ignore` walk is blocking IO). It appends found files in `TRAVERSAL_BATCH` (256) chunks — bumping `version` and calling `wake` **after** the write lock drops — checks `cancel` each iteration, and on finish appends the remainder, sets `complete` (unless cancelled), and fires a final `wake`. The write lock is held only for the short, IO-free append.

**Bounded traversal.** The walk is BOUNDED by a `bounds: SearchBounds` argument so it cannot run away on a large root (e.g. a fallback walk of the entire `$HOME` tree). `SearchBounds { max_entries: usize, budget: Duration, max_depth: usize, skip_dirs: HashSet<PathBuf> }` (crate-internal) carries four bounds; `SearchBounds::from_env()` (crate-internal) resolves the three scalar caps once, synchronously, on the calling thread (`api::WolfCore::start_file_search`), falling back to a default on any unset / unparsable / zero value (a `> 0` guard, mirroring the `WOLF_RPC_TIMEOUT_MS` pattern) and starting `skip_dirs` empty for the caller to populate:

- **Entry cap** — `max_entries`, default `SEARCH_MAX_ENTRIES_DEFAULT = 50_000` accepted (listable) files, env override `WOLF_SEARCH_MAX_ENTRIES`. Once this many files have been streamed the walk stops early, logs a `warn!`, and sets `truncated`.
- **Wall-clock budget** — `budget`, default `SEARCH_BUDGET_DEFAULT = 5s`, env override `WOLF_SEARCH_BUDGET_MS` (milliseconds). Checked each iteration against an `Instant` started at the walk's outset; once elapsed the walk stops early, logs a `warn!`, and sets `truncated`.
- **Max depth** — `max_depth`, default `SEARCH_MAX_DEPTH_DEFAULT = 64`, env override `WOLF_SEARCH_MAX_DEPTH`. Applied via `WalkBuilder::max_depth` using `ignore`'s convention (the root is depth 0, so a file directly in the root is depth 1). Depth pruning is SILENT — it is invisible in the `ignore` API, so it does NOT set `truncated`.
- **Skip dirs** — `skip_dirs`, a set of absolute directories pruned outright (never descended into) via `filter_entry`. `SearchBounds::from_env` leaves it empty; `start_file_search` populates it from `canonical_home()` with `~/Library`, `~/.Trash`, and `~/.cache` (pathological home subtrees that a fallback `$HOME` walk should never enter).

A cap-truncated search still ends `complete` (via `complete = !cancel`), so the picker treats it as done; only a real `cancel` leaves it incomplete (and sets neither flag). `append_batch(state, batch, complete, truncated)` propagates both flags into the shared state under the short write lock (mid-loop batches pass `false`/`false`; the final append passes the computed values).

**Traversal rules (plan §D3/§D6).** The `ignore` crate (ripgrep's walker) is configured `parents(true)`, `hidden(false)`, `git_ignore`/`git_global`/ `git_exclude(true)`, `ignore(false)`, `require_git(false)`, `follow_links(false)` — behaving like `git ls-files --others --exclude-standard` inside a repo and a plain recursive walk outside one. So: dotfiles are shown (only `.gitignore` filters), `.gitignore` is honored in the cwd or any ancestor up to the repo root, untracked-but-not-ignored files are included, symlink loops cannot hang it, and `.git/` and our own `.wolf/` cache are never descended into (via `filter_entry`, with a defensive `has_excluded_component` backstop). `is_listable_file` classifies each entry: plain files are kept, a symlink is kept only when its target is a plain file (`std::fs::metadata` follows the link), and directories / broken or directory symlinks are dropped. Display strings are built via `display_for` (relative to the root using the platform separator).

## `search.rs`

The ripgrep-backed, streaming CONTENT search and its `SearchSession` — the sidebar search panel's view of "every line under the search root that matches the query". Created by [`api::WolfCore::start_search`](#apirs), which spawns a pinned `rg --json` subprocess and streams its JSON match events into a versioned snapshot behind one lock. Structurally it is [`files.rs`](#filesrs)'s traversal with the `ignore`-crate walk swapped for an `rg` subprocess: same `RwLock` snapshot, same `spawn_blocking` streaming task, same batch-append + wake-after-unlock, same cancel-on-`Drop`. (The ONLY other `std::process::Command` in core is the nvim spawn.)

Key types:

- `SearchOptions { query: String, use_regex: bool, case_sensitive: bool, all_files: bool }` (`Clone, Debug`) — the knobs from the panel's text field + three toggle buttons. `use_regex` (default ON in the front-end) treats `query` as a regex, else literally (rg `-F`); `case_sensitive` (seeded from nvim's `ignorecase`) picks rg `-s` vs `-i`; `all_files` (default OFF) removes the Markdown-only glob filter.
- `SearchMatch { abs_path: PathBuf, rel_path: String, line_number: u64, column: u32, line_text: String, match_ranges: Vec<(u32, u32)> }` (`Clone, Debug, PartialEq, Eq`) — one matching line: `abs_path` (used to issue `open_at`), `rel_path` (the `/`-separated path relative to the search root — the display/sort key, falling back to the absolute path string when not under the root, via a private `display_for` mirroring `files`), the 1-based `line_number`, the 0-based BYTE `column` of the FIRST submatch, the raw matched `line_text` with any trailing `\n`/`\r\n` stripped, and the byte `[start, end)` `match_ranges` of every submatch into `line_text`.
- `SearchState { matches: Vec<SearchMatch>, complete: bool, error: Option<String>, version: u64 }` — the collected state behind one `parking_lot::RwLock` (mirrors `FileSearchState`, minus `truncated`/`seen`). `matches` accumulate in rg EMISSION order (per-file grouped, ascending line within a file, but NOT cross-file sorted — the display order is imposed later at projection time by [`search_tree::project`](#search_treers)); `complete` flips true once rg finishes (or will never run); `error` carries a human-readable string (rg failed to spawn, exited abnormally `>= 2`, or `WOLF_RG_BIN` unset); `version` starts at `1` and bumps on every append. `SearchState::new()` is the fresh empty state; `SearchState::errored(msg)` an immediately-`complete` state carrying `error` (used when rg cannot run at all).
- `SearchReadGuard` — an OWNED read guard (`ArcRwLockReadGuard`) that `Deref`s to `SearchState`, so a reader holds `guard.matches` / `.complete` / `.error` / `.version` independently of the `SearchSession`'s lifetime (mirrors `FileSearchReadGuard`).
- `SearchHandles { state, cancel, child }` (crate-internal, `Clone`) — the three shared handles the session and its streaming task both hold: the result `state: Arc<RwLock<SearchState>>`, the `cancel: Arc<AtomicBool>` flag, and the `child: Arc<Mutex<Option<std::process::Child>>>` slot (the rg process, so a cancel can kill it). Bundled into one struct so `spawn_search` / `from_parts` take one value (also resolving `clippy::too_many_arguments`).
- `SearchSession { handles: SearchHandles }` — a live content-search session: `read() -> SearchReadGuard`, `cancel()` (sets the `AtomicBool` AND `child.kill()`s the rg process — idempotent), and `from_parts(handles)` (crate-internal). `Drop` calls `cancel()`, so closing the panel or starting a new search stops the old rg promptly (no zombie).

`spawn_search(root, opts, rg_bin, handles: &SearchHandles, wake, handle: tokio::runtime::Handle)` (crate-internal) is the analog of `files::spawn_traversal`. On `handle.spawn_blocking` it builds the rg command line (below), spawns it with piped stdout/stderr (stderr drained to `tracing` on a helper thread, like the nvim stderr drain), publishes the `Child` into `child` so a concurrent `cancel()` can kill it, then `BufReader::lines()`-loops stdout: each line checks `cancel` (break + kill), parses via `parse_rg_line`, and on a `Match` pushes a converted `SearchMatch` into a batch. It flushes the batch under a brief write lock — bumping `version` and calling `wake` AFTER the lock drops — every `SEARCH_BATCH` (128) matches OR on each per-file `end` event (so a file's matches surface as a group promptly). On EOF it reaps the child, classifies its exit (rg: `0` = matches, `1` = no matches, `>= 2` = a real error → `state.error`; a `cancel` leaves the result incomplete + error-free), appends the remainder, sets `complete = !cancelled`, and fires a final `wake`. `append_batch` / `finalize` hold the write lock only for the short, IO-free append.

**rg command line** (built in `spawn_search`, in order): `<WOLF_RG_BIN> --json --no-config --hidden [ -F ]? [ -s | -i ] [ --glob '*.md' --glob '*.markdown' ]? -e <query> -- <root>`. `--no-config` for determinism; `--hidden` mirrors `files.rs`'s `.hidden(false)` (rg still honors `.gitignore` and excludes `.git`); `-F` is added ONLY when `!use_regex` (literal); `-s` when `case_sensitive` else `-i` (NOT smart-case); the two `--glob`s are added ONLY when `!all_files` (Markdown-only); `-e <query>` protects a leading dash; `--` separates the root.

**The rg `--json` event model** (private, serde). `parse_rg_line(&str) -> Option<RgEvent>` decodes one newline-delimited JSON object, returning `None` on any JSON error (a malformed/partial line is skipped, not fatal). `RgEvent` (`#[serde(tag = "type", content = "data", rename_all = "snake_case")]`) is `Begin`/`Match`/`End`/`Summary`/`Context`; only `Match` carries data we keep (`End` triggers a per-file batch flush; the rest decode so a well-formed stream never errors but are ignored). `match_from_event(root: &Path, m: &RgMatch) -> Option<SearchMatch>` strips the trailing newline, builds `rel_path` via `display_for`, sets `column` to the first submatch's byte start, and collects every submatch into `match_ranges`; it returns `None` when a required field is missing. **Non-UTF-8 limitation:** rg emits a path/line as a `{"bytes": …}` (base64) object rather than `{"text": …}` when it is not valid UTF-8; the private `RgText` deserializes ONLY the `text` form, so `match_from_event` SKIPS any event whose required path/line text (or `line_number`) is absent — a documented limitation (no base64 dependency), so a non-UTF-8 file/line simply does not appear. The private parse/skip cases (event decode, multi-submatch → multiple ranges, `column` = first submatch start, CRLF/LF stripping, non-UTF-8 path/line → `None`, missing `line_number` → `None`, malformed → `None`, absolute-fallback `rel_path`) are covered by this module's inline `#[cfg(test)] mod tests`; the public pure fns are covered by the external `tests/search_projection.rs`.

## `mru.rs`

The GLOBAL recent-files MRU cache: a single SQLite database at `state_dir()/file-mru.sqlite` (macOS `~/Library/Application Support/Wolf/file-mru.sqlite`, plus its `-wal`/`-shm` sidecars) so the picker can offer recent files synchronously (before the async traversal completes) and rank them first. Every row carries the project `directory` it was recorded under, and `recent(directory)` FILTERS to just that directory — so a single store serves every project while keeping their recent lists ISOLATED (per-project MRU without a per-project DB). Mirrors the sibling `recent_dirs.rs` / `command_mru.rs` stores' infallible-open, self-heal, disabled-fallback shape; the distinctive parts are the `opened_at` timestamp ordering and the inline missing-file prune.

- `MRU_LIMIT = 50` (re-exported from the crate root) — the per-directory newest-first cap `recent()` returns. Private constants `MRU_DB_NAME = "file-mru.sqlite"` and `MRU_BUSY_TIMEOUT_MS = 2000` mirror the siblings. The pragma ORDER in `init` is load-bearing: `busy_timeout` is installed as the FIRST statement after `Connection::open`, BEFORE `journal_mode=WAL`, because the rollback-journal → WAL conversion is the one statement that can need an exclusive lock and a connection with no back-off installed fails it outright with `SQLITE_BUSY` when several handles open the same not-yet-converted database at once.
- `MruStore` (`Clone`, `Arc`-backed) — holds `dir: Option<PathBuf>` (the state dir; `None` disables the store) and `conn: Arc<parking_lot::Mutex<Option<Connection>>>` (lazily (re)opened, self-healing). Schema: `mru(directory TEXT NOT NULL, file TEXT NOT NULL, opened_at INTEGER NOT NULL, PRIMARY KEY (directory, file))`; the wrong-schema probe is `SELECT directory, file, opened_at FROM mru LIMIT 0` (an old single-`path` DB heals).
- `MruStore::open(dir: &Path) -> MruStore` — **infallible**: stores `dir` and eagerly opens/creates `<dir>/file-mru.sqlite` (so the file exists right after `open`); a failed open is silent (the connection stays `None`, retried-with-heal on the next call). Does NOT create any `.wolf` directory.
- `MruStore::disabled() -> MruStore` — `dir: None`; every method is a silent no-op (used when `state_dir()` cannot be resolved).
- `record(&self, directory: &Path, file: &Path)` — **fire-and-forget**: normalizes `directory` (canonicalize, else as-given — the SAME normalization `recent` applies), computes the stored `file` (canonical if it exists, else absolutized against the normalized directory), stamps `opened_at = now-millis`, and upserts `(directory, file, opened_at)` (`ON CONFLICT(directory, file) DO UPDATE SET opened_at = excluded.opened_at`). Errors are swallowed (self-healing on corruption), so opening a file is never blocked by a cache hiccup.
- `recent(&self, directory: &Path) -> Vec<FileEntry>` — the most-recently-opened files UNDER `directory` newest-first (`WHERE directory = ?1 ORDER BY opened_at DESC, rowid DESC LIMIT MRU_LIMIT`, `directory` normalized the same way `record` normalizes it). Entries whose backing file no longer exists are **pruned inline** — omitted from the result AND `DELETE`d via the same connection with a BEST-EFFORT `let _ = conn.execute(...)` (NOT `?`, so a transient prune failure never triggers a whole-DB heal); `FileEntry.path = PathBuf::from(file)`, `FileEntry.display = strip_prefix(normalized-directory)`, and `mru_rank` is the 0-based position in the returned list. Returns an empty `Vec` on a disabled store or a SELECT error.

`FileEntry` is re-exported here from `files.rs` (its true home). Self-heal uses the same `with_conn` (guard locked into a NAMED LOCAL to avoid `clippy::significant_drop_in_scrutinee`) / `open_or_heal` / `init` / `warrants_recreate` / `remove_db_files` machinery as `recent_dirs.rs`. Recreate policy: every failure is handled SILENTLY (`tracing::debug!`, never `warn!`), but the RESPONSE depends on WHY it failed. A private `warrants_recreate(&rusqlite::Error) -> bool` classifies the error: `true` for `SQLITE_CORRUPT` / `SQLITE_NOTADB` / `SQLITE_SCHEMA` and for the `SQLITE_ERROR` (`ErrorCode::Unknown`) whose message names a missing table or column (the wrong-schema case `init`'s probe exists to raise); `false` for `SQLITE_BUSY`, `SQLITE_LOCKED`, I/O failures, read-only or full disks, and every variant that carries no SQLite error code at all. It must destructure **both** code-carrying variants — `rusqlite::Error::SqliteFailure` AND `rusqlite::Error::SqlInputError` — because rusqlite splits a failure SQLite can attribute to a byte offset in the SQL text (a valid `sqlite3_error_offset` on an `ErrorCode::Unknown`) out into `SqlInputError`, which is NOT a `SqliteFailure` variant and is exactly the shape the schema probe's `prepare` raises. Matching only `SqliteFailure` would silently disable the wrong-schema recreation path; `tests/mru.rs`'s `wrong_schema_db_is_silently_recreated` is the regression guard, and it is deliberately distinct from `a_corrupt_database_is_still_healed`, whose `SQLITE_NOTADB` arrives as a plain `SqliteFailure`. Only a `true` verdict reaches `remove_db_files` — anything else degrades to an empty result / a dropped record and LEAVES THE FILE ALONE. That distinction is load-bearing, not cosmetic: deleting the sqlite file unlinks it from under every other live connection in the process, so recreating for a merely-busy database silently destroys data. Two Wolf windows contending on the same global store used to be enough to wipe it. All SQLite work is synchronous, guarded by the mutex, with short critical sections that never span an `.await`.

`WolfCore` owns a single `mru: MruStore`, constructed always-on in `start` from `state_dir()` (or `MruStore::disabled()`). To make the MRU follow Neovim's live cwd (`:cd`/`:lcd`/`:tcd`), `api.rs` passes that live cwd as the `directory` on every operation: the picker seed (read) is `self.mru.recent(&root)` and the record-on-open (write) is `pump_mru.record(&record_cwd, path)`, both scoped to nvim's tracked cwd. So per-project isolation is a `directory` FILTER over the one global DB, not a per-project file.

## `recent_dirs.rs`

The GLOBAL recent-directories MRU cache: a single SQLite database at `state_dir()/folder-mru.sqlite` (macOS `~/Library/Application Support/Wolf/folder-mru.sqlite`, plus its `-wal`/`-shm` sidecars) recording every directory the captive Neovim changes into — via the "open folder" command OR a typed `:cd`/`:lcd`/`:tcd` — so a future picker can offer the user's recent project directories. Like the sibling `mru.rs` / `command_mru.rs` stores it is GLOBAL (one DB under `state::state_dir`) and self-heals on corruption, but it is keyed on the directory PATH (one row per directory) and capped at 20 entries. Depends only on `state::state_dir`; sits alongside `mru`/`state`.

- `RECENT_DIRS_LIMIT = 20` (re-exported from the crate root) — the newest-first cap `recent()` returns and `record()` prunes down to. Private constants `RECENT_DIRS_DB_NAME = "folder-mru.sqlite"` and `RECENT_DIRS_BUSY_TIMEOUT_MS = 2000` mirror `mru.rs`.
- `RecentDirs` (`Clone`, `Arc`-backed) — holds `dir: Option<PathBuf>` and `conn: Arc<parking_lot::Mutex<Option<Connection>>>` (lazily (re)opened, self-healing). Schema: `recent_dirs(path TEXT PRIMARY KEY, seq INTEGER NOT NULL)`; ordering is a monotonic `seq` (`MAX(seq)+1` per insert), NOT a timestamp, so move-to-top and the cap are deterministic even for same-millisecond inserts (no test sleeps).
- `RecentDirs::open(dir: &Path) -> RecentDirs` — **infallible**: stores `dir` and eagerly opens/creates the DB (so the file exists right after `open`); a failed open is silent (the connection stays `None`, retried-with-heal on the next call).
- `RecentDirs::disabled() -> RecentDirs` — `dir: None`; every method is a silent no-op (used when `state_dir()` cannot be resolved).
- `record(&self, path: &Path)` — **fire-and-forget**: a short run of autocommit statements (no explicit `BEGIN`/`COMMIT`) — read the next `seq` (`SELECT MAX(seq)+1`), upsert `(path, seq)` (`ON CONFLICT(path) DO UPDATE SET seq = excluded.seq` — move-or-add-to-top), then prune rows beyond `RECENT_DIRS_LIMIT` (`DELETE … WHERE path NOT IN (SELECT path … ORDER BY seq DESC LIMIT ?)`). `path` is stored as-given (`to_string_lossy`); it arrives already-canonical from `apply_cwd`, so it is NOT re-canonicalized. Errors are swallowed.
- `recent(&self) -> Vec<PathBuf>` — the recorded directories newest-first (`ORDER BY seq DESC LIMIT RECENT_DIRS_LIMIT`); returns an empty `Vec` on any failure. Unlike `MruStore::recent` it does NOT prune missing directories.

Self-heal: nothing panics and no error is propagated. `init` installs `busy_timeout` FIRST (before `journal_mode=WAL` — same load-bearing ordering as `mru.rs`), runs `CREATE TABLE IF NOT EXISTS`, THEN a probe `SELECT path, seq FROM recent_dirs LIMIT 0` that forces a garbage DB or a wrong-schema table (one missing `seq`) to surface as an `Err`. Recreate policy: every failure is handled SILENTLY (`tracing::debug!`, never `warn!`), but the RESPONSE depends on WHY it failed. A private `warrants_recreate(&rusqlite::Error) -> bool` classifies the error: `true` for `SQLITE_CORRUPT` / `SQLITE_NOTADB` / `SQLITE_SCHEMA` and for the `SQLITE_ERROR` (`ErrorCode::Unknown`) whose message names a missing table or column (the wrong-schema case `init`'s probe exists to raise); `false` for `SQLITE_BUSY`, `SQLITE_LOCKED`, I/O failures, read-only or full disks, and every variant that carries no SQLite error code at all. Like `mru.rs` it destructures **both** code-carrying variants, `rusqlite::Error::SqliteFailure` AND `rusqlite::Error::SqlInputError` — the latter is not a `SqliteFailure` variant and is the shape the schema probe's `prepare` raises, so matching only `SqliteFailure` would silently disable the wrong-schema recreation path. Only a `true` verdict reaches `remove_db_files` — anything else degrades to an empty result / a dropped record and LEAVES THE FILE ALONE. That distinction is load-bearing, not cosmetic: deleting the sqlite file unlinks it from under every other live connection in the process, so recreating for a merely-busy database silently destroys data. Two Wolf windows contending on the same global store used to be enough to wipe it. `open_or_heal` creates the dir and tries `init`; on a recreate-worthy failure it deletes the DB files (`remove_db_files`: the sqlite file + `-wal`/`-shm` sidecars, ignoring NotFound) and tries once more before giving up (`debug!` + `None`), and on any other failure it returns `None` without touching the file (the handle is retried on the next call). `with_conn` is the single lock+heal choke point (guard locked into a NAMED LOCAL to avoid `clippy::significant_drop_in_scrutinee`): it lazily (re)opens, runs the closure, and on a recreate-worthy `Err` drops the connection, deletes the files, reopens, and retries ONCE; any other `Err` returns `None` leaving both the file and the open connection alone. All SQLite work is synchronous, short, and never spans an `.await`.

## `command_mru.rs`

The GLOBAL command-palette MRU cache: a near-clone of `recent_dirs.rs` keyed on an OPAQUE command KEY string rather than a directory path. A single SQLite database at `state_dir()/command-mru.sqlite` (plus its `-wal`/`-shm` sidecars) records every command-palette invocation the user activates, so the palette floats recently-used commands to the top. Unlike `recent_dirs`, NOTHING auto-records into it — only an explicit palette `record()` writes to it, so a fresh store under a new state dir reads back EMPTY. Same lazy-creation, delete-and-recreate self-heal, monotonic-`seq` ordering, and always-on/disabled fallback as `recent_dirs`.

- `COMMAND_MRU_LIMIT = 100` (re-exported from the crate root) — the newest-first cap `recent()` returns and `record()` prunes down to. Private constants `COMMAND_MRU_DB_NAME = "command-mru.sqlite"` and `COMMAND_MRU_BUSY_TIMEOUT_MS = 2000` mirror `recent_dirs.rs`.
- `CommandMru` (`Clone`, `Arc`-backed) — holds `dir: Option<PathBuf>` and `conn: Arc<parking_lot::Mutex<Option<Connection>>>`. Schema: `command_mru(key TEXT PRIMARY KEY, seq INTEGER NOT NULL)`; the wrong-schema probe is `SELECT key, seq FROM command_mru LIMIT 0`.
- `CommandMru::open(dir: &Path) -> CommandMru` — **infallible**, eagerly opens/creates the DB (so the file exists right after `open`); a failed open is silent and retried-with-heal on the next call.
- `CommandMru::disabled() -> CommandMru` — `dir: None`; every method is a silent no-op (used when `state_dir()` cannot be resolved).
- `record(&self, key: &str)` — **fire-and-forget**: read the next `seq`, upsert `(key, seq)` (move-or-add-to-top), then prune beyond `COMMAND_MRU_LIMIT`. `key` is stored as-given (a static command's registry `id`, or a dynamic `switch_window:<cwd>` / `open_recent:<path>` key). Errors are swallowed.
- `recent(&self) -> Vec<String>` (`#[must_use]`) — the recorded keys newest-first (capped); an empty `Vec` on any failure.

`WolfCore` owns a `command_mru: CommandMru`, constructed always-on in `start` from `state_dir()` (or `CommandMru::disabled()`), but — unlike `recent_dirs` — it is NOT cloned into the redraw handler (nothing auto-records). `WolfCore::command_mru(&self) -> CommandMru` hands out a cheap `Arc`-backed clone for the palette to read/record through. Self-heal machinery is identical to `recent_dirs.rs`, including the `warrants_recreate` classifier — same verdicts, and it likewise destructures **both** `rusqlite::Error::SqliteFailure` and `rusqlite::Error::SqlInputError` so the wrong-schema probe's error shape is not missed — and the `busy_timeout`-before-`journal_mode=WAL` pragma ordering. The three copies are deliberately duplicated rather than shared, so each store's classification stays readable next to the schema probe that feeds it.

## `rank.rs`

Pure, IO-free fuzzy-match + ranking for the picker — unit-tested headlessly (no filesystem, Neovim, or GUI), mirroring how the GNOME `geometry.rs` / `cursor.rs` seams stay testable.

- `rank_matches(query: &str, entries: &[FileEntry]) -> Vec<Match>` (`#[must_use]`) — the query is tokenized on WHITESPACE into TERMS (each ASCII-lowercased; empty terms dropped). An EMPTY or ALL-WHITESPACE query (no terms) returns ALL entries **MRU-first** (ascending `mru_rank`, then non-MRU entries in stable original order). Otherwise an entry is kept iff EVERY term is a **case-insensitive subsequence** of `display` (logical AND, each term matched independently, so terms are ORDER-INDEPENDENT); non-matching entries are dropped, the rest ordered by `MatchKey`.
- `rank_matches_top_n(query: &str, entries: &[FileEntry], n: usize) -> Vec<Match>` (`#[must_use]`) — the BOUNDED companion the picker FFI (`FfiFileSearch::ranked`) actually calls. It returns EXACTLY `rank_matches(query, entries).into_iter().take(n).collect()` for all inputs, but WITHOUT sorting (or cloning `display` for) the whole match set: it selects the top `n` with an `O(M log n)` bounded max-heap keyed by a private borrowed `KeyRef` (a `Copy` mirror of `MatchKey`'s fields plus the `index`, so `index` is the explicit final tiebreak that makes the borrowed key a TOTAL order and matches `rank_matches`'s stable-sort `take(n)`), so NO `display` is cloned during selection; only the `≤ n` survivors are drained, `sort_unstable`ed, and cloned into owned `Match`es. `n == 0` returns an empty `Vec` immediately; an EMPTY / all-whitespace query delegates to the private `rank_empty_top_n` fast path, which emits the (small, `MRU_LIMIT`-bounded) MRU entries sorted by `mru_rank` ascending, then the non-MRU entries in original index order, and takes the first `n` — no global sort, at most `n` clones. `rank_matches` and `rank_empty` themselves are UNCHANGED.
- `Match { index: usize, key: MatchKey }` (derives `PartialEq, Eq` so tests can `assert_eq!` a `Vec<Match>` structurally) — `index` points into the input `entries` slice (callers map results back by index); `key` is the sort key.
- `MatchKey` (derived `Ord`, every field "lower = better", declared in priority order): (1) `mru_group` (`0` if in the MRU cache else `1` — **MRU first, LOCKED**), (2) `mru_rank` (`u32::MAX` if not in MRU), (3) `score` wrapped in `core::cmp::Reverse` so a HIGHER score sorts first, (4) `match_start` (smallest first-matched index across the terms), (5) `span` (sum over terms of `last - first`), (6) `len` (`display.chars().count()`), (7) `display` lexicographic.

The per-entry `score` SUMS, across all terms, three bonuses computed over the FULL display: `COMPONENT_START_BONUS` (100) if some path COMPONENT (`display` split on `/ \`) starts with the term, `WORD_START_BONUS` (20) if some WORD (`display` split on `/ \ _ - . space`) starts with the term, and `CONTIGUOUS_BONUS` (4) if the display contains the term as a contiguous substring. The ordering `100 > 20 > 4` makes the single-term tiers strict (component-start beats word-start beats contiguous beats a scattered subsequence at score 0); summing is a soft preference for more/stronger term hits, with determinism guaranteed by the `match_start`/`span`/`len`/`display` tie-breaks. The no-terms path is handled by `rank_empty`.

`score_entry` is **allocation-free**: it never lowercases `display` into a `String` and never builds per-entry component/word `Vec`s. All matching folds ASCII case IN PLACE via the private char-comparison helpers `subsequence_span_ci(term, display)` (the case-insensitive subsequence walk returning the `(first, last)` matched char indices, `None` if the term is not consumed), `ci_starts_with(hay, needle)`, and `ci_contains(hay, needle)`; the component/word bonuses iterate `display.split(SEP)` lazily rather than collecting. The folding is ASCII-only (never Unicode), preserving the exact old match semantics — the module's table-driven `#[cfg(test)]` unit tests are the regression guard. Both `rank_matches` and `rank_matches_top_n` call this same `score_entry`. The module has table-driven `#[cfg(test)]` unit tests.

## `palette.rs`

Pure, IO-free candidate assembly + ranking for the command palette — the palette analog of `rank.rs`, which it REUSES for the fuzzy match + MRU-first ordering. Unit-tested headlessly (in `tests/palette_rank.rs`).

- `PaletteRowKind { Static, SwitchWindow, OpenRecent }` (derives `Debug, Clone, Copy, PartialEq, Eq`) — which of the three palette actions a row performs; mirrored in wolf-ffi's `mod palette_row_kind` (STATIC=0, SWITCH_WINDOW=1, OPEN_RECENT=2) and the Swift `PaletteSeam.PaletteRowKind` port.
- `PaletteWindow { index: u16, cwd: String }` — one OTHER open window fed to `rank_palette` (the current window is excluded by the caller); its front-end window index (the raise target) and cwd.
- `PaletteRow { display, mru_key, kind, command: Option<Command>, window_index: Option<u16>, path: Option<PathBuf> }` (derives `Debug, Clone`, PUBLIC fields) — one assembled + ranked row: the label, the opaque MRU key, the kind, and the kind-specific payload.
- `rank_palette(recent_dirs: &[PathBuf], windows: &[PaletteWindow], command_mru_recent: &[String], query: &str, max: usize) -> Vec<PaletteRow>` (`#[must_use]`) — assembles candidates in a STABLE order (tie-break-relevant): (1) every `COMMAND_SPECS` row EXCEPT `Command::CommandPalette` → a `Static` row (`display` = spec `title`, `mru_key` = spec `id`); (2) each window → `"Switch to Window: {label}"` (label = `"Untitled"` when cwd empty, else the cwd), `mru_key = "switch_window:{cwd}"`; (3) each recent dir → `"Open Recent Folder: {path}"`, `mru_key = "open_recent:{path}"` (plain path rendering). Each candidate's `mru_rank` is the index of its `mru_key` in `command_mru_recent` (else `None`). The candidates are projected into a parallel `Vec<FileEntry>` (empty path, the display, the mru_rank), ranked via `rank_matches` (UNCHANGED), truncated to `max`, and each surviving `Match.index` maps back to a cloned `PaletteRow`. So an empty query lists all candidates MRU-first; a non-empty query applies the same AND-subsequence filter as the file picker. `Command::CommandPalette` is EXCLUDED from its own candidate list (a palette cannot dispatch itself).

## `buffer_picker.rs`

Pure, IO-free candidate assembly + ranking for the buffer picker — a `palette.rs`-shaped module that REUSES `rank.rs` for the fuzzy match + MRU-first ordering, but over the captive nvim's open buffers rather than the command registry. Given a snapshot of the buffers (queried once at picker-open via the blocking `WolfCore::list_buffers`), the cwd, and the query, it MRU-orders, projects to display strings, and ranks best-first — deliberately view-agnostic (no `winsaveview` payload; per-pane scroll restoration lives in `init.lua`). Unit-tested headlessly (in `tests/buffer_rank.rs`).

- `BufInfo { bufnr: i64, name: String, lastused: i64, modified: bool }` (derives `Debug, Clone`, PUBLIC fields) — one open buffer as decoded from `getbufinfo({'buflisted': 1})`: the handle, full name (absolute path, or `""` unnamed), the `lastused` MRU key, and the modified flag (`changed != 0`).
- `BufferRow { bufnr: i64, display: String, modified: bool }` (derives `Debug, Clone`, PUBLIC fields) — one assembled + ranked row: the buffer handle to switch to, the display label (also the string ranked against the query), and the modified flag for the row chrome.
- `rank_buffers(buffers: &[BufInfo], cwd: Option<&Path>, query: &str, max: usize) -> Vec<BufferRow>` (`#[must_use]`) — sorts a copy of `buffers` by `lastused` DESC (a STABLE sort, tie-broken by `bufnr` ASC), so the current buffer (highest `lastused`) lands at index 0 and IS included. Each sorted buffer is projected into a parallel `FileEntry` (empty path, its display string, `mru_rank` = its sorted index) and ranked via `rank_matches` (UNCHANGED), truncated to `max`, each surviving `Match.index` mapping back to a cloned `BufferRow`. So an empty query lists all buffers MRU-first; a non-empty query applies the same AND-subsequence filter as the file picker. The private `relative_display(name, cwd)` builds the label: an empty name → `NO_NAME` (`[No Name]`, reused from `pane_status`); a name under `cwd` → the cwd-relative remainder (lossy); any other name → the absolute name verbatim (no `~`-home fold, DECISION §13.6).

## `pane_status.rs`

Pure, IO-free display-string math for the macOS per-pane statusbar — unit-tested headlessly (in `tests/pane_status_unit.rs`). It is string/path arithmetic over ALREADY-CANONICAL inputs (the caller canonicalizes the buffer path, cwd, and home before calling), so `strip_prefix` lines up; it draws no pixels and touches no filesystem.

- `NO_NAME: &str = "[No Name]"` — the placeholder filename for an unnamed buffer.
- `PaneStatus { filename: String, display_path: String, abs_path: String }` (derives `Clone, Debug, PartialEq, Eq`, PUBLIC fields) — the strings a pane's statusbar shows: the base `filename`, the `display_path` beneath it, and `abs_path` — the buffer's RAW, never-relativized absolute path (`""` for an unnamed buffer). Unlike `display_path` (which is relativized against cwd/home), `abs_path` is the untouched buffer path the macOS front-end persists as a pane-layout leaf path.
- `pane_status(buf_path: &str, cwd: Option<&Path>, home: Option<&Path>) -> PaneStatus` (`#[must_use]`) — `abs_path` is always the raw `buf_path` (`""` when empty). Precedence for the other two: (1) an EMPTY `buf_path` (unnamed buffer) → `{ NO_NAME, "", "" }`; (2) else `filename` = the path's `file_name()` lossy (falling back to the full `buf_path`), and `display_path` = the cwd-relative remainder when `cwd` is set AND `buf_path` strips its prefix to a NON-EMPTY remainder (cwd WINS; `buf_path == cwd` yields an empty remainder and falls through), else the `~`-prefixed home form when `home` is set and `buf_path` strips its prefix (`"~"` for `buf_path == home`, else `"~/" + remainder`), else the full `buf_path` verbatim.

## `nav_history.rs`

The **per-pane file navigation history** (back / forward) — the single source of truth behind the macOS History menu and its two toolbar buttons. Pure, GUI-free and IO-FREE (the label pipeline is path MATH only and never touches the filesystem), so it sits beside `buffer_picker.rs` / `pane_status.rs` rather than inside the redraw fold; `redraw.rs` derives a `NavTarget` per WINDOW after every `wolf_buffers` / `wolf_preview` emit and hands it to `NavHistory::observe`, and the six `WolfCore::history_*` methods read and move it. Unit-tested headlessly (in `tests/nav_history.rs`), with the live behavior in `tests/nav_history_live.rs`.

**What is tracked.** History is keyed by the nvim **WINDOW handle** (`i64`), not by grid, so a pane's stack follows the window across repaints; it is **not persisted** across restarts, and the front-ends hold **no copy**. A push is triggered by ANY change to a pane's current file, including Neovim-internal navigation (`:e`, `gd`, the buffer picker). The stack is a literal VISIT LOG — `A -> B -> A -> B` is FOUR entries; de-duplication happens only when rendering menu rows. New navigation from a mid-stack cursor TRUNCATES everything ahead of it (browser semantics). The terminal DRAWER is EXCLUDED (it produces no entry at all) while a `:terminal` in a NORMAL split is tracked; unnamed buffers are tracked by bufnr. `NavTarget` is the dedup key, so `Edit(B)` and `Preview(B)` are DISTINCT entries.

- `MAX_ENTRIES: usize = 100` — the per-pane stack cap (pushing past it drops the OLDEST entries and shifts the cursor by exactly the drained count). `MAX_MENU_ROWS: usize = 10` — the maximum number of DISTINCT rows the History menu renders.
- `NavTarget` (derives `Clone, Debug, PartialEq, Eq, Hash`) — `Edit { path: PathBuf }` (a file-backed buffer, by absolute canonical path), `Preview { source: PathBuf }` (a Markdown preview, by its SOURCE file's path), `Terminal { bufnr: i64 }` (a `:terminal` in a normal split, never the drawer), and `Untitled { bufnr: i64 }` (a genuinely unnamed buffer). `path(&self) -> Option<&Path>` (`#[must_use]`) yields the `Edit`/`Preview` path and `None` for the two pathless variants (which are excluded from the label-collision groups and numbered instead).
- `NavMove { from: usize, to: usize, target: NavTarget }` — a cursor move produced by `back`/`forward`/`jump`; the caller issues the nvim RPC for `target` and, on failure, reverts with `revert(from: mv.to, to: mv.from)`. `MenuRow { display: String, index: usize, is_current: bool }` — one rendered menu row: the finished (already home-abbreviated) label, the STACK index to hand back to `jump`, and whether it draws the checkmark.
- `PaneHistory { entries: Vec<NavTarget>, cursor: usize, expected: Option<NavTarget> }` (private fields, borrowing accessors) — ONE pane's stack. `push(target)` truncates ahead of the cursor, pushes, parks the cursor, enforces the cap, and clears `expected`. `observe(target)` applies the four-branch rule: (1) empty stack → SEED; (2) `current() == Some(target)` → absorb + clear `expected`; (3) `expected == Some(target)` → absorb + clear (the LOCKED feedback-loop rule; unreachable single-threaded because branch 2 catches it first, kept as the cross-thread safety net for a fold racing the RPC); (4) otherwise → `push` (a genuine navigation). `can_back()` (`cursor > 0`) / `can_forward()` (`cursor + 1 < len`); `back()` / `forward()` / `jump(index)` → `Option<NavMove>` (each ARMS `expected` with the entry navigated to as part of the same mutation that moves the cursor; `jump` to the cursor's OWN index — or an out-of-range one — returns `None`, a true no-op); `revert(from, to)` restores the cursor and clears `expected` ONLY when the cursor is still at `from` AND `to` is in range (a racing `observe` that already reconciled the pane WINS); plus the borrowing accessors `entries() -> &[NavTarget]`, `cursor()`, `current()`, `expected()` and `menu_rows(limit, home)`.
- `NavHistory { panes: HashMap<i64, PaneHistory>, last: HashMap<i64, NavTarget> }` — every pane's history, keyed by window handle, living behind the `redraw::NavHistoryCell` mutex. `observe(win, target)`, `prune(win)`, `prune_many(&[i64])`, `can_back(win)`, `can_forward(win)`, `back(win)`, `forward(win)`, `jump(win, index)`, `revert(win, from, to)`, `menu_rows(win, limit, home)`, and `pane(win) -> Option<&PaneHistory>`. Its `observe` carries an **emit-level change filter** sitting ABOVE `PaneHistory::observe`: a target IDENTICAL to the last one folded for that window is DROPPED before it reaches the stack. This is necessary because nvim fires the driving autocmds 2–4 times per navigation ACROSS several event-loop ticks, so the Lua side's per-tick coalescing cannot merge them all; a late repeat of the state we just LEFT would otherwise hit branch 4 straight after a `back`/`forward`/`jump` and push, truncating the entry being moved to. `expected` structurally cannot cover that (it names the target being moved TO, and the locked rule deliberately requires a non-matching change to push — that is what the self-heal relies on), whereas "did the pane's derived target actually CHANGE since the last fold" separates the two cases exactly. The locked four-branch rule in `PaneHistory` is UNMODIFIED. `prune`/`prune_many` clear both maps, so a reused key reseeds cleanly.
- `derive_target(buf: Option<&WinBuffer>, preview_source: Option<&Path>) -> Option<NavTarget>` (`#[must_use]`) — the precedence: a preview source present → `Preview` (it wins over the window's buffer); else no `WinBuffer` → `None`; else `is_drawer` → `None`; else `is_terminal` → `Terminal { bufnr }`; else a named buffer → `Edit { path }`; else → `Untitled { bufnr }`. A window in NEITHER map yields `None` — **no entry, no push, no prune** — which is what makes the two notifications' arrival ORDER irrelevant during a preview transition (there is a transient frame in which the window is in neither map).
- `disambiguate(paths: &[PathBuf], home: Option<&Path>) -> HashMap<PathBuf, String>` (`#[must_use]`) — the PREFIX-form, minimal-growth label pipeline. Paths are grouped by file name; a SINGLETON group renders BARE. For a colliding group, for `k = 2, 3, …` the candidate is that path's last `k` NORMAL components joined with `/` (the root `/` is not counted; a path with FEWER than `k` of them contributes its FULL ABSOLUTE form), and the first `k` at which every candidate in the group is distinct wins. Any label that ended up a full absolute path then has `home` abbreviated to `~`. Worked example: `foo/README.md`, `bar/README.md`, `bar/some-other-file.md` render as `bar/README.md`, `foo/README.md`, and a bare `some-other-file.md`; the deeper `a/b/README.md` vs `c/b/README.md` must grow to TWO parent segments. (This is the ONLY prefix-form disambiguation in the tree — the old filename-based `TabTitleSeam` is gone, so there is nothing to keep in lockstep with.)
- `PaneHistory::menu_rows(limit, home) -> Vec<MenuRow>` (`#[must_use]`) — the row pipeline, in this exact order: (1) **row selection** — walk `entries` NEWEST-FIRST, keeping the FIRST occurrence of each distinct `NavTarget` and the stack index it came from, stopping at `limit` distinct rows; then, if a kept row's target equals `entries[cursor]`, its `index` is OVERRIDDEN to `cursor` and it is marked `is_current`, so clicking the checkmark is a true no-op rather than a jump forward to a newer instance (when the cursor's target did NOT survive the cap, NO row is checkmarked); (2) **distinct paths** — `Preview(X)` and `Edit(X)` contribute the SAME path ONCE; (3) **labels** via `disambiguate`; (4) **decorate** — `Edit` renders its label, `Preview` prefixes `"Preview: "`, and pathless rows are EXCLUDED from steps 2–3 and numbered by first appearance in the newest-first ROW order (`Terminal`, `Terminal 2`, …; `Untitled`, `Untitled 2`, …).

**Feedback-loop suppression.** `back`/`forward`/`jump` arm the per-pane `expected` BEFORE the caller issues the nvim RPC, so a fold racing that RPC's autocmds already sees it; the very next `observe` for that pane clears it unconditionally on every branch — a MATCHING change is ABSORBED (our own move landing, echoed back through `wolf_buffers`), a NON-matching one is a genuine navigation and PUSHES. **`expected` is never a gate on pushing**, so a stale one can never wedge history: if a Back fails silently and the pane stays put, the next genuine navigation truncates ahead of the moved cursor, appends, and clears it — history **self-heals in one step**, with no timer, epoch, or reaper. Failed moves are ALSO actively reverted (see `api.rs`'s `apply_nav`).

**Known limits (documented, deliberately NOT fixed).**

- Two Back presses issued faster than the first `wolf_buffers` emit is folded leave that first emit non-matching (`expected` has already been overwritten), producing ONE spurious push. This is exactly what the locked rule specifies; the window is sub-millisecond because `WolfCore::history_back` blocks on the RPC before returning to the main thread, and the worst outcome is slightly odd history, never a wedge.
- A `restart_nvim` clones the SAME redraw handler, so the history cell SURVIVES a respawn by construction. Harmless: the new nvim issues fresh window handles, so stale panes are never queried.
- `win_hide` (fired for every window of a tabpage being LEFT) removes the `Snapshot.windows` entry, so a later `win_close` for that grid cannot resolve its window handle and that pane's history is ORPHANED. nvim never reuses window handles, so an orphan is only memory, bounded at `MAX_ENTRIES` per orphaned pane per nvim-process lifetime. An "absent from `wolf_buffers` for N emits" reaper is deliberately NOT added — a window in a non-current tabpage is absent from both maps by construction, and pruning it would violate the locked no-prune rule.
- Going Back to an `Edit` path whose file was DELETED from disk reports SUCCESS and shows an empty `[New]` buffer, exactly like a plain `:e missing.md`. The revert path covers wiped `Terminal`/`Untitled` bufnrs and dead `Preview` sources, not deleted `Edit` paths — in spec, not a bug.

## `tree.rs`

The **pure, toolkit-free** hierarchical projection of the picker's flat file list — a single, FFI-expressible source of truth shared by every front-end (wolf-gnome's `tree.rs` re-exports it; wolf-ffi exposes it over the bridge for wolf-macos). Unit-tested headlessly in its own `#[cfg(test)] mod tests` (mirroring `rank.rs`). The picker's `FileSearch` produces a flat list of `FileEntry` (relative `/`-separated `display`, absolute `path`); this module turns it into the per-directory children a lazy outline/tree view needs, plus the reveal helpers.

```rust
pub enum TreeNode {
    Dir  { name: String, rel_path: String },
    File { name: String, rel_path: String, abs_path: std::path::PathBuf },
}
pub struct TreeIndex { /* HashMap<dir_rel_path, Vec<TreeNode>> */ }
impl TreeIndex {
    pub fn build(entries: &[crate::FileEntry]) -> TreeIndex
    pub fn children_of(&self, dir: &str) -> &[TreeNode]
}
pub struct TreeIndexCache { /* Option<(version, TreeIndex)> + build_count */ }
impl TreeIndexCache {
    pub fn index_for(&mut self, version: u64, entries: &[crate::FileEntry]) -> &TreeIndex
    pub fn build_count(&self) -> u64
}
pub fn children_of(entries: &[crate::FileEntry], dir: &str) -> Vec<TreeNode>
pub fn ancestors_to_reveal(rel_path: &str) -> Vec<String>
pub fn node_rel_path(node: &TreeNode) -> &str
pub fn rel_path_for(entries: &[crate::FileEntry], abs: &std::path::Path) -> Option<String>
```

- `TreeNode` — one immediate child of a directory. `rel_path` is the full relative path from the cwd root (a dir `b` under `a` has `name = "b"`, `rel_path = "a/b"`); a `File`'s `rel_path` equals the originating `FileEntry::display` and its `abs_path` is that entry's `path`.
- `TreeIndex` (`build` / `children_of` both `#[must_use]`) — a per-snapshot index from a directory's rel-path to its immediate children, built in a **single pass** over the flat entry list (`build`). Each entry's ancestor directories and leaf file are grouped under their parent, dir dedup uses a `HashSet` (no linear `.any()` scan), and each per-directory `Vec` is sorted once. `children_of(dir)` is then an **O(children)** borrowed-slice hash probe (empty slice for an unknown dir), with identical projection semantics to the free `children_of`. This is what keeps a lazy outline's per-child callback storm off a full-list rescan.
- `TreeIndexCache` (`build_count` `#[must_use]`) — a version-keyed cache of one `TreeIndex`. `index_for(version, entries)` rebuilds (bumping `build_count`) only when the cache is empty or holds a different version, else returns the cached borrow untouched — so many `children_of` calls at one snapshot version cost a single index build. `new()` / `Default`.
- `children_of(entries, dir)` (`#[must_use]`) — the IMMEDIATE children of `dir` (`dir == ""` is the cwd root), now implemented as `TreeIndex::build(entries).children_of(dir).to_vec()` (one source of truth). Each `display` is split on `/`; the component just after `dir` becomes a `File` (when it is the entry's final component) or a `Dir`. Dir nodes are **deduped** by `rel_path`, and only dirs that (transitively) contain a listed file appear (automatic — dirs are derived from file paths, so no phantom dirs). The result is sorted **directories first, then files**, each group **case-insensitively by `name`** with `rel_path` as a deterministic tie-break. The free fn builds a throwaway index per call; hot per-directory paths should cache a `TreeIndex` (via `TreeIndexCache`) instead.
- `ancestors_to_reveal(rel_path)` (`#[must_use]`) — the ancestor dir rel-paths from the root down to the file's parent: `"a/b/c.md"` → `["a", "a/b"]`; `"c.md"` → `[]`; `""` → `[]`.
- `node_rel_path(node)` — the `rel_path` of either variant.
- `rel_path_for(entries, abs)` (`#[must_use]`) — the current-file → tree-display mapping used by the sidebars' reveal: returns `entry.display.clone()` for the FIRST entry whose `path == abs` **exactly** (a parent-dir prefix does not match), else `None`.

The separator is always `/` (it is `FileEntry::display`'s separator).

## `search_tree.rs`

The **pure, toolkit-free** projection + display math for the sidebar SEARCH-results tree — the search analog of [`tree.rs`](#treers). [`search.rs`](#searchrs)'s `SearchSession` produces a FLAT `Vec<SearchMatch>` in rg emission order; the panel shows a two-level tree (each matched FILE with its matching LINES beneath it). This module holds the pure projection from the flat list into per-file groups (sorted for display) plus the per-line balanced-context "window" that trims a long line to fit the narrow sidebar. Keeping it toolkit-free lets it be unit-tested headlessly (mirroring `tree.rs`); the only consumer that wraps these in widgets is `wolf-macos`'s `SearchView`. Width is an integer CHARACTER budget (never pixels), so the math is display-server-free — the front-end converts its pixel width to a char budget and adds the ellipsis glyphs. Covered by the external headless `tests/search_projection.rs` plus this module's `#[cfg(test)] mod tests`.

- `SearchFileGroup { abs_path: PathBuf, rel_path: String, label: String, match_indices: Vec<usize> }` (`Debug, Clone, PartialEq, Eq`) — one matched file in the projected tree: its absolute path (used to issue `open_at`), its `/`-separated `rel_path` (the case-insensitive sort key), the display `label` (see `file_label`), and the indices INTO the flat match slice passed to `project`, ordered by line number, of the lines that matched in this file.
- `ContextWindow { text: String, ranges: Vec<(u32, u32)>, truncated_left: bool, truncated_right: bool }` (`Debug, Clone, PartialEq, Eq`) — the visible slice of a matched line: `text` a substring of the original line (sliced on CHAR boundaries, never splitting a scalar); `ranges` the bold match ranges as byte `[start, end)` offsets RE-BASED into `text`; `truncated_left`/`truncated_right` say whether context was hidden on each side (the front-end draws an ellipsis there — kept OUT of `text` so the byte offsets stay clean; AppKit wraps `text` across ≤ 2 lines).
- `project(matches: &[SearchMatch]) -> Vec<SearchFileGroup>` (`#[must_use]`) — the sort-on-read projection: groups matches by `abs_path`, sorts the groups by `rel_path` CASE-INSENSITIVELY (via `to_ascii_lowercase`, with the raw `rel_path` as a deterministic tie-break, mirroring `tree::node_cmp`), and sorts each group's `match_indices` by `line_number` (a STABLE sort, so equal line numbers keep emission order). `matches` accumulate in rg emission order and are ordered only here, at projection time.
- `file_label(rel_path: &str) -> String` (`#[must_use]`) — the display label `"<basename> - <relative parent dir>"`, e.g. `"foo/bar/baz.md"` → `"baz.md - foo/bar"`. A root file (no parent) is just its basename, e.g. `"baz.md"` → `"baz.md"` (no `" - "` suffix). `/`-splitting via `rsplit_once('/')`.
- `context_window(line: &str, ranges: &[(u32, u32)], budget: usize) -> ContextWindow` (`#[must_use]`) — THE balanced-context computation. If `line`'s CHAR count `<= budget` the whole line is returned unchanged (both sides un-truncated, `ranges` untouched). Otherwise it returns a `budget`-char slice centered on the FIRST match range: `remaining = budget - match_len`, `left = remaining / 2`, `right = remaining - left`; when the match sits near one end the clamped side's leftover budget is spent on the other ("balanced but greedy at edges"). The slice is taken on CHAR boundaries (via a `char_indices` boundary table + a `byte_to_char` binary search, so a multibyte scalar/emoji is never split); each input range is clamped to the window and RE-BASED to byte offsets into the returned `text` (ranges fully outside are dropped, partials clamped); `truncated_left`/`truncated_right` reflect whether the window starts/ends INSIDE the line.

## `api.rs`

The FFI-shaped front-end surface. Documented in detail in the crate [`README.md`](../README.md). In brief: `WolfCore` owns the tokio runtime, the `NvimProcess`, the `SharedSnapshot`, the sibling `IntentQueue`, the sibling `CommandQueue`, the ordered input channel, the always-on global `MruStore` (constructed once at `start` from `state_dir()` — or `MruStore::disabled()` when it cannot be resolved — and cloned into the input pump; every row carries the project `directory` it was recorded under, so a single `<state_dir>/file-mru.sqlite` keeps every project's recent list isolated), the sibling `TrackedCwd` cell, the always-on global `RecentDirs` store (constructed once at `start` from `state_dir()` — or `RecentDirs::disabled()` when it cannot be resolved — and cloned into the redraw handler, which records each `wolf_cwd` directory change into `<state_dir>/folder-mru.sqlite`; unlike the `StateStore` it is NOT attached/opt-in), the sibling `NavHistoryCell` (created in `start` next to `intents` / `commands` and cloned into the redraw handler, which folds each pane's derived navigation target into it), and the configured `cwd`; `CoreConfig` (now including `cwd`), `CoreError` (`Runtime`/`Nvim`), and `SnapshotReadGuard` (an owned read guard that `Deref`s to `Snapshot`) round out the surface. `start` attaches the UI then calls `setup_current_file_tracking`, `setup_buffer_tracking`, `setup_full_width`, `setup_layout`, `setup_dir_tracking`, `setup_theme_tracking`, `setup_commands`, `setup_view_tracking`, and (last) `setup_preview` so the captive nvim is wired for current-file, per-window buffer, per-window full-width, split-panes, directory-change, theme-change, command, buffer-picker view-tracking, and Markdown-preview notifications before input flows. A single `INPUT_COALESCE_DELAY` lets a synchronous burst of `send_input` calls coalesce into one applied batch; the input pump records every drained `InputEvent::Open` (and `InputEvent::OpenAt`) into the global MRU under nvim's LIVE cwd (the `TrackedCwd` cell, falling back to the configured `cwd` until nvim first reports) as the `directory` scope. The pump also performs **toast-clear-on-input** (OD8): BEFORE `input::apply_batch`, if the batch carries any `InputEvent::is_toast_dismissing` event (Key/Mouse/Scroll) AND `!snap.toast.is_prompt()`, it takes the write lock, `snap.clear_toast()`, and drops the guard immediately (never across the apply `.await`) — clearing BEFORE apply so a fresh `msg_show` from that same input repopulates the toast afterward. A `confirm` prompt is NOT dismissed (the gate), and the scroll-over-toast exemption is a front-end concern (that wheel gesture is never forwarded, so no `Scroll` reaches the pump). `mru_recent()` reports that same live-cwd store. `recent_dirs(&self) -> Vec<PathBuf>` reads back the always-on global recent-directories MRU (newest first, capped at `RECENT_DIRS_LIMIT`; empty when the store is disabled or unreadable). `WolfCore` ALSO owns an always-on global `command_mru: CommandMru` (constructed at `start` from `state_dir()`, or `CommandMru::disabled()`), but — unlike `RecentDirs` — it is NOT cloned into the redraw handler (nothing auto-records); `command_mru(&self) -> CommandMru` hands out a cheap `Arc`-backed clone the command palette reads/records through. `pane_status(&self, grid: u64) -> PaneStatus` computes the macOS per-pane statusbar strings for the window drawing into `grid`: it joins `grid` → `WinInfo.win` → `Snapshot.buffers` under a read guard that is DROPPED before it reads `live_cwd()` (mirroring `mru_recent`), then formats the buffer path via the pure `pane_status` over the live cwd and the (canonicalized) home directory; a window with no matching buffer (unnamed, or a grid with no window) yields `NO_NAME` with an empty display path. `display_path(&self, abs_path: &str) -> String` (`#[must_use]`) formats a single absolute path into just the cwd/home-relative DISPLAY string (the `PaneStatus.display_path` field) via the same pure `pane_status` over `live_cwd()` and the canonicalized home; it drops the filename half, so the caller derives that separately, and an empty `abs_path` yields an empty display path. It backs the preview pane's secondary statusbar line: `WolfCoreHandle::previews` calls it on each `PreviewInfo.source_path` to fill `FfiPreview.source_display_path()`. `live_cwd(&self) -> Option<PathBuf>` is a cheap synchronous read of that same `TrackedCwd` cell (a clone-out of the `RwLock` guard, no `getcwd()` RPC); the value is already canonicalized (the redraw handler canonicalizes it before storing) and is `None` until nvim first reports its cwd. The macOS file-tree sidebar reads it (over the FFI as `WolfCoreHandle::cwd()`) on each editor wake to re-root on `:cd`/`DirChanged`. `start_file_search(&self, wake) -> FileSearch` seeds the MRU synchronously then spawns the streaming traversal on the runtime, rooted at the captive Neovim's LIVE working directory, resolved OUT-OF-BAND by the private `resolve_search_root` via `live_cwd()` (the tracked-cwd cell fed by the `wolf_cwd`/`DirChanged` notification, no nvim RPC), falling back to the configured `cwd` only before nvim first reports its cwd. Because it issues no RPC, the picker is wedge-independent — it never stalls on a wedged nvim. The MRU seed now FOLLOWS nvim's live cwd: it is the global store's rows FILTERED to the resolved search root (`self.mru.recent(&root)`, the root as the `directory` scope), so the seed's `display` strings relativize against exactly the directory being listed (root-relative, per-project isolation over one global DB). The sidebar CONTENT search adds three methods: `start_search(&self, opts: SearchOptions, wake: WakeFn) -> SearchSession` starts a streaming, ripgrep-backed content search rooted at the same out-of-band `resolve_search_root` (`live_cwd`, no nvim RPC, so it is wedge-independent) — it locates the pinned `rg` via `WOLF_RG_BIN` (set by the front-end from the bundled binary; the Nix devShell exports the Nixpkgs `ripgrep`) and, when it is unset/empty, degrades GRACEFULLY to an immediately-`complete` `SearchSession` carrying `error = Some("WOLF_RG_BIN unset")` (no results) rather than panicking; otherwise it builds the shared `search::SearchHandles` and calls `search::spawn_search` on the runtime, returning the live `SearchSession` (dropping/cancelling it kills the rg subprocess — see [`search.rs`](#searchrs)). `open_at(&self, path: PathBuf, line: u64, col: u64)` is fire-and-forget — it enqueues an `InputEvent::OpenAt { path, line, col }` on the ordered input channel (applied via `:edit` + `nvim_win_set_cursor`), backing the search panel's click-to-jump; the input pump records it into the global MRU exactly like `InputEvent::Open`. `ignorecase(&self) -> bool` (`#[must_use]`) is a BLOCKING one-shot read of the captive nvim's global `ignorecase` (`block_on_rpc("ignorecase", nvim.ignorecase())`, bounded by `rpc_timeout`), degrading to `false` on any RPC error / `Timeout`; the front-end seeds the search panel's "case sensitive" toggle from its inverse (`case_sensitive = !ignorecase`). `resize(cols, rows)` enqueues a global `Resize` (outer grid 1) and `resize_grid(grid, cols, rows)` enqueues a per-window-grid `ResizeGrid`, both on the ordered input channel so they never race pending keystrokes. `drain_intents() -> Vec<LayoutIntent>` consumes the pending `wolf_layout` intents (in arrival order) the front-end applies on each wake; `drain_commands() -> Vec<Command>` likewise consumes the pending `wolf_command` commands (empty right after start — commands are user-triggered only) the front-end maps to native actions; and `focus_win(win: i64)` enqueues an `InputEvent::FocusWin` (so click-to-focus and resolved `FocusDir` moves order with keystrokes). `send_mouse(MouseEvent)` and `send_scroll(ScrollEvent)` are thin convenience wrappers (mirroring `focus_win`/`resize`) that enqueue an `InputEvent::Mouse`/`InputEvent::Scroll` on the same ordered input channel, so mouse clicks/drags and scroll-wheel events target the pane's window grid without racing pending keystrokes. `copy_visual_selection(&self) -> Option<String>` is the one BLOCKING method (it needs a synchronous return value): it `runtime.block_on`s `NvimProcess::yank_visual_selection` and maps `Err` / `Ok(None)` / an empty string to `None` (logging a `tracing::warn!` on error), so the front-end can write the yanked visual selection to the system clipboard; `paste(&self, text: String)` is fire-and-forget — it enqueues an `InputEvent::Paste { text }` on the ordered input channel (applied via `nvim_paste`). `list_buffers(&self) -> Vec<BufInfo>` is a second BLOCKING method (the buffer picker needs its candidates synchronously at open): it `runtime.block_on`s `NvimProcess::list_buffers` (the `getbufinfo({'buflisted': 1})` query), logging + returning an empty list on error; the buffer picker seeds a fresh session from this snapshot + `live_cwd()` and ranks it via `buffer_picker::rank_buffers`. `switch_buffer(&self, win: i64, bufnr: i64)` is fire-and-forget — it enqueues an `InputEvent::SwitchBuffer { win, bufnr }` on the ordered input channel (applied via the `wolf_switch_buffer` init.lua helper: a window-scoped `nvim_win_set_buf` + per-pane view restore), so a buffer switch never races pending keystrokes; the front-end resolves the active window over the FFI (`WolfCoreHandle::switch_buffer(bufnr)`). `toggle_terminal(&self)` is likewise fire-and-forget — it enqueues an `InputEvent::ToggleTerminal` on the ordered input channel (applied via the `wolf_toggle_terminal` init.lua helper: open/hide a per-tabpage bottom `:terminal` drawer showing the shared per-project terminal buffer), so toggling the terminal drawer never races pending keystrokes. `toggle_full_width(&self)` is likewise fire-and-forget — it enqueues an `InputEvent::ToggleFullWidth` on the ordered input channel (applied via the `wolf_toggle_full_width` init.lua helper: flip `b:wolf_full_width` on the effective buffer — the SOURCE buffer for a preview scratch, OQ-1 — and re-emit the current-file / per-window full-width / previews notifications), so the full-width toggle never races pending keystrokes; the two cheap synchronous reads `is_full_width_active(&self) -> bool` (`read_snapshot().is_full_width_active()`, the View-menu "Use full width for content" checkmark) and `full_width_for_win(&self, win: i64) -> bool` (`read_snapshot().full_width_for_win(win)`, the per-pane editor geometry) back the menu checkmark and the pane width mode. The **tabpage** methods back the project/tabpage-per-view model (each macOS view = one nvim tabpage of a shared project nvim): the BLOCKING `create_tabpage(&self, cwd: Option<&Path>) -> i64` (`tabnew` + optional `:tcd`, `0` on error), `cwd_for_tabpage(&self, handle: i64) -> Option<PathBuf>` (canonicalized tab-local cwd, authoritative for a non-current view), and `current_tabpage(&self) -> i64` (the first-view bind, `0` on error), plus the fire-and-forget `set_current_tabpage(&self, handle: i64)` / `close_tabpage(&self, handle: i64)` (ordered `InputEvent::SetTabpage`/`CloseTabpage`). Two tiers: `Snapshot.current_tabpage` (cheap live gate via `read_snapshot`) vs `current_tabpage()`/`cwd_for_tabpage()` (authoritative RPCs), mirroring `live_cwd()` cell vs `current_dir()` RPC. The **pane-layout REBUILD** method backs restore: `rebuild_layout(&self, spec_json: &str) -> Vec<i64>` (`#[must_use]`) realizes a saved pane-split tree (the `PaneLayoutCodec.specJSON` shape — nested `{leaf,path}` / `{orientation,weights,children}`) in the current tabpage's single starting window by driving the `wolf_rebuild_layout` Lua helper over `NvimProcess::rebuild_layout` (`:split`/`:vsplit` + `:edit`), bounded by `block_on_rpc` like `create_tabpage`; it returns the resulting window handles in DFS/leaf order — the SAME order as the front-end `PaneTree.leaves()` / `PaneTree.rebuilt`, so each handle zips to its rebuilt leaf — and `vec![]` on any RPC error / timeout. nvim produces only the window COUNT + TOPOLOGY + per-window BUFFER; the sizes come from the front-end's weights via `syncGridSizes`. The **statusbar** `pane_status(&self, grid: u64) -> PaneStatus` now also carries the buffer's raw `abs_path` (the never-relativized path, joined via the same grid → window → buffer path lookup) so the front-end can persist a leaf's buffer path. The **Markdown preview** adds these methods: `is_markdown_active(&self) -> bool` (a cheap synchronous `read_snapshot().is_markdown_active()` read, the Preview menu gate), `is_preview_active(&self) -> bool` (the mirror cheap synchronous `read_snapshot().is_preview_active()` read, the Edit menu gate), the BLOCKING `open_preview(&self, mode: &str) -> i64` (`block_on`s `NvimProcess::open_preview`, `0` on error / not-markdown — `mode` chosen by the front-end via `PreviewSeam.placementMode`: `"split_right"` / `"active"` / `"reuse_preview_pane"`, the last binding into the OTHER preview pane when a two-pane window already shows one), the BLOCKING `edit_source(&self, mode: &str) -> i64` (Preview's inverse; `block_on`s `NvimProcess::edit_source`, `0` on error / not-a-preview — `mode` chosen by the front-end via `EditSeam.placementMode`: `"split_left"` / `"reuse_editor_pane"` / `"active"`), the BLOCKING `render_preview(&self, source_bufnr: i64) -> String` (`block_on`s `NvimProcess::render_preview`, empty string on error), which the front-end pulls on each wake for any preview pane whose `Snapshot.markdown_ticks` tick advanced, and the BLOCKING `#[must_use] preview_file(&self, win: i64, path: &str) -> i64` (`block_on`s `NvimProcess::preview_file`, `0` on error / empty / unreadable / not-markdown). The front-end calls `preview_file` when the user clicks a file-on-disk link in a preview: `path` is the ABSOLUTE path resolved from WebKit's `file://` URL, and the return is the linked file's SOURCE bufnr (`> 0`) so the pane repoints at it, or `0` (on which the front-end applies its own O3 fallback — hand an existing-but-non-previewable file to the OS default app, no-op if missing).

**Per-pane navigation history (back / forward).** Six methods surface the sibling `NavHistoryCell` (see [`nav_history.rs`](#nav_historyrs)); `win` is always an nvim WINDOW handle. `history_can_back(&self, win: i64) -> bool` / `history_can_forward(&self, win: i64) -> bool` (`#[must_use]`) are cheap reads of that cell — a brief mutex, NO RPC and NO snapshot lock, the same cost class as `live_cwd()` — returning `false` for an unknown window, a never-navigated pane, or the terminal DRAWER (excluded from history entirely). `history_back(&self, win) -> bool` / `history_forward(&self, win) -> bool` / `history_jump(&self, win, index: usize) -> bool` move the cursor (ARMING the pane's `expected` in the SAME mutation, BEFORE the RPC is issued, so a fold racing that RPC's autocmds absorbs the resulting `wolf_buffers` emit instead of pushing a duplicate), then delegate to the private `apply_nav`; each returns whether the pane ACTUALLY moved, so `false` covers the ends of the stack, an unknown window, an out-of-range index, the cursor's OWN index (clicking the checkmarked menu row is a true no-op), and an RPC error. `history_entries(&self, win) -> Vec<MenuRow>` (`#[must_use]`) renders the pane's menu rows NEWEST-FIRST, already capped at `MAX_MENU_ROWS` DISTINCT targets and home-abbreviated, with at most one `is_current`; each `MenuRow.index` is a real STACK index usable verbatim with `history_jump`. The private `apply_nav(&self, win, mv: &NavMove) -> bool` picks the mechanism per target — an `Edit` goes through the window-scoped `_G.wolf_history_open`, a `Preview` REUSES the existing `_G.wolf_preview_file` link-follow path, and a `Terminal` / `Untitled` goes through `_G.wolf_history_set_buf` — all three window-scoped `nvim_win_set_buf` (never `:edit`), so there is no disk re-read and no `current_file` / file-MRU churn. Each is bounded by `block_on_rpc`; a helper result of `0` (or an RPC error) REVERTS the cursor via `NavHistory::revert(win, mv.to, mv.from)` — but only if a racing `observe` has not already reconciled the pane — and returns `false`. **Lock discipline (stated because it is load-bearing):** the nav mutex is NEVER held across `block_on_rpc` and NEVER held while the snapshot lock is held from this side; the fold in `redraw.rs` takes them in the opposite order but has no `.await`/RPC between, so there is no lock-order cycle. The `RefCell` borrow of `self.nvim` is bound to a LOCAL and dropped before the revert (`clippy::await_holding_refcell_ref`).

**Crash & stall recovery (liveness + restart).** `WolfCore` holds a lock-free `liveness: Arc<AtomicU8>` (a [`Liveness`](#livenessrs) cell) and a clone of the redraw `wake`. `liveness(&self) -> Liveness` is a cheap atomic read; `restart_nvim(&self) -> Result<bool, CoreError>` is guarded by a `restarting: AtomicBool` CAS (a concurrent request is `Ok(false)`), early-returns `Ok(false)` when the current liveness is already `Alive` (a redundant restart must not tear down a live nvim), else `runtime.block_on`s `NvimProcess::kill_in_place` on the old process, `liveness::reset_alive`s (the ONLY `Dead → Alive` exit), respawns via `nvim::spawn(&self.nvim_cfg, self.handler.clone(), self.liveness.clone(), self.wake.clone())` + re-runs `ui_attach` + the full `setup_*` chain, then swaps the new `NvimProcess` into `self.nvim` (a `RefCell<NvimProcess>`) and its handle into the input pump's `shared_handle`; a respawn/setup `Err` marks `Dead` (`mark_dead`) and returns `Err`, and success returns `Ok(true)`. `open_files_for_tabpage(&self, handle: i64) -> Option<TabFiles>` is a cheap `Snapshot.open_files` read (no RPC), captured per view by the front-end BEFORE a restart wipes the mirror.

**RPC timeout backstop.** Every interactive synchronous nvim RPC (the BLOCKING methods above) is routed through the central `block_on_rpc<F, T>(&self, what: &'static str, fut: F) -> Result<T, NvimError>` chokepoint on `WolfCore`, which delegates to the private module-level free fn `timeout_block_on(runtime, timeout, what, fut)` — the split lets the mechanism be unit-tested with a never-resolving future and NO live nvim. `timeout_block_on` SPAWNS `fut` as a runtime task (hence the `Send + 'static` bounds) and waits on its `JoinHandle` bounded by `tokio::time::timeout` (built INSIDE the async block so it constructs in a runtime context); on elapse it logs a `tracing::warn!` naming the wedged RPC and returns `NvimError::Timeout(what, rpc_timeout)`, so an unbounded main-thread hang (macOS beach-ball) becomes a bounded stall that degrades to each call site's existing fallback. **On timeout the task's `JoinHandle` is DROPPED, which DETACHES the task to run to completion in the background (NOT aborted).** This is load-bearing for stall recovery and fixes a REAL production bug the recovery tests exposed: the old code used `tokio::time::timeout` DIRECTLY on the nvim-rs call future, which DROPPED that future on elapse, orphaning its response-channel receiver — so when a wedged nvim later recovered and delivered the response, nvim-rs's io loop errored ("Could not send response") and DIED, which the supervisor misread as a CRASH (spurious `Dead`, permanently breaking the channel). Detaching keeps the receiver alive until nvim answers, so a WEDGED-then-recovered nvim's io loop survives and the next call succeeds. (This required converting 11 `block_on_rpc`-reachable `NvimProcess` methods from `async fn(&self)` to `fn(&self) -> impl Future + Send + 'static` — clone the handle + own the args into an `async move`; `setup_*`/`ui_attach`/`shutdown` use a direct `block_on`, not this path, and are unchanged.) `block_on_rpc` ALSO folds LIVENESS at this chokepoint (the stall detector): an `Err(NvimError::Timeout(..))` escalates `Alive → NotResponding` (`liveness::mark_not_responding`, never downgrading `Dead`); a successful `Ok(_)` AUTO-CLEARS a transient stall via a call-site `compare_exchange(NotResponding → Alive)` guard (firing the wake on the change, NEVER touching `Dead` — a crashed core stays `Dead` until `restart_nvim`). The bound is the `rpc_timeout: Duration` field, resolved ONCE at `WolfCore::start` from the `WOLF_RPC_TIMEOUT_MS` env var (parsed as `u64` milliseconds, `> 0` guarded so `0`/invalid/unset all fall back) defaulting to the module-level `RPC_TIMEOUT_DEFAULT` (`Duration::from_secs(5)`, matching `SHUTDOWN_TIMEOUT`). The twelve guarded call sites and their fallback on `Timeout`: `copy_visual_selection` (`yank_visual_selection` → `None`), `list_buffers` (→ empty `Vec`), `render_preview` (→ empty `String`), `open_in_browser`'s three queries (`current_markdown_bufnr` → early `""`, `buffer_path` → `""` root, `current_dir` → no root), `open_preview` / `edit_source` / `preview_file` / `create_tabpage` / `current_tabpage` (each → `0`), and `cwd_for_tabpage` (`tab_cwd` → `None`). `start_file_search` / `resolve_search_root` are NOT in this list: they resolve the search root out-of-band via `live_cwd()` and issue no nvim RPC on that path, so there is nothing to bound (the picker is wedge-independent by construction, not by timeout). Deliberately NOT guarded: the startup `block_on` (a wedge there fails through the `start` error path) and the shutdown `block_on` (already bounded by `SHUTDOWN_TIMEOUT`).

`timeout_block_on` also instruments the success path: on a normal return it logs `tracing::debug!(rpc, ?elapsed, "nvim RPC completed")`, so `WOLF_LOG=wolf_core=debug` yields per-RPC timing for every interactive call. The timeout `warn!` is now enriched with the `rpc` + `?elapsed` fields. These lines are silently dropped unless a subscriber is installed — the process-global stderr subscriber set up by [`logging::init_tracing`](#loggingrs) (called once from `wolf_ffi_start`, default filter `warn`) is what makes the timeout `warn!` — and, at `debug`, the per-RPC timing plus `resolve_search_root`'s `source="live_cwd"` / `source="configured_cwd"` root resolution (both `debug!`) — actually visible.

## `logging.rs`

The process-global `tracing` setup. Standalone (like `config`/`markdown`, it touches no `WolfCore`, snapshot, or nvim) — its one job is to make the app's `tracing` output observable.

- `init_tracing()` (re-exported at the crate root as `wolf_core::init_tracing`) — installs the process-global `tracing-subscriber` `fmt` subscriber writing to **stderr**, with ANSI colour off, targets on, and thread ids on. Verbosity comes from the `WOLF_LOG` environment variable via a standard `EnvFilter` (`EnvFilter::try_from_env("WOLF_LOG")`); when `WOLF_LOG` is unset or unparseable the filter defaults to `warn`, so the RPC-timeout `warn!` is visible with no configuration while normal runs stay quiet. Installed via `.try_init()` with the `Result` discarded, so it is **idempotent** and **never panics**: the FIRST call wins and every subsequent call (e.g. a second `wolf_ffi_start` for another project/window) is a harmless no-op. It is called once, as the FIRST statement of `wolf_ffi_start` (see [`wolf-ffi/src/README.md`](../../wolf-ffi/src/README.md)), so a `WolfCore::start` failure is captured too.
- **`WOLF_LOG` (operator-facing).** Sets the log-level filter using standard [`EnvFilter`](https://docs.rs/tracing-subscriber/latest/tracing_subscriber/filter/struct.EnvFilter.html) directive syntax. Useful directives: `WOLF_LOG=wolf_core=debug` surfaces the per-RPC timing (`nvim RPC completed` with `rpc` + `elapsed`) and the file-search root resolution (`resolved file-search root` with `source="live_cwd"` vs `source="configured_cwd"`, both `debug!`, plus `starting file search` with the seed count); `WOLF_LOG=trace` additionally shows the `spawn_traversal walking` markers (the root each traversal walks — a home-root walk is the picker-falls-back-to-home symptom). Under `bazel run //crates/wolf-macos:Wolf` the inner binary inherits the parent's stderr, so these lines appear on the terminal that launched the app.
