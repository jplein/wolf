## Exec strip

`extra_exec_rustc_flags=-Cstrip=none` is the fix for `error[E0463]: can't find crate for thiserror_impl` on macOS 27. Exec tools build in the opt configuration, where rustc strips proc-macro dylibs with its own bundled `rust-objcopy --strip-debug`, never with the `strip` on `PATH`, and macOS 27 dyld refuses the result with `mis-aligned LINKEDIT string pool`. rustc reports that failed load as a missing crate. The dylib that fails to load is the proc-macro `thiserror_impl`, so E0463 surfaces compiling rules_rust's internal `thiserror`, reached from `@crates//:swift-bridge` through `cargo_toml_variable_extractor`.

Measured on macOS 27.0.1 with Xcode 27.0 and rustc 1.85.0: the unstripped dylib loads, `/usr/bin/strip -S` or `xcrun strip -S` applied to it loads, and `rust-objcopy --strip-debug` applied to it fails at the same offset as the build. So no `PATH` or shell change can fix it, `--incompatible_strict_action_env` included, and removing the flag reproduces E0463. The cost is larger exec tools, which only run during the build and never ship.

Removing the flag is the test of whether a later macOS, Xcode or rustc still needs it.
