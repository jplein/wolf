# Retrospective: the three MRU caches become tables of `wolf.sqlite`

Last verified at commit `192e764c110731a439fdb5f99e4c3f5fe56ec9c1`.

The task moved `MruStore`, `RecentDirs` and `CommandMru` from three SQLite files onto the tables `file_mru`, `folder_mru` and `command_mru` of one `wolf.sqlite`. It added the crate-private `crates/wolf-core/src/db.rs` for the open, the `schema` table, versioning, healing and legacy-file removal, and `crates/wolf-core/tests/db.rs` with its `:db` target. Its commits are `92bfcee` (code and tests) and `192e764` (documentation).

The eight invocations cost about $18.21 and 60 minutes of agent time. One round trip, a coder rejection of one test fixture, added about $2.22 and 7 minutes. Every gate run passed on both workers on its first try.

## What went well

- **The instructions named every file and every duplicated helper.** They listed the three modules, the four copied functions (`init`, `open_or_heal`, `warrants_recreate`, `remove_db_files`), the README entries and the one spec sentence to move. `architect-1` found every test site with one grep for `-mru.sqlite`, and review 1 §6 found nothing out of scope.
- **Headless real-SQLite tests made falsifiers cheap.** `tests/db.rs` uses tempdir files and no Neovim, and `:db` copies the headless `:command_mru` target. Each falsifier run with `--test_arg=--exact` took 0.1 to 0.3 s, so `coder-1` drove fifteen falsifiers through one script and `coder-2` re-ran three in a 17-turn invocation.
- **`specs/application-state.md` §1 settled the design questions.** The plan's choices, such as deleting the file only for `SQLITE_CORRUPT` or `SQLITE_NOTADB` and dropping only the mismatched table, came straight from it. No agent disputed a design point, and the dispute that did happen was about SQLite, not the spec.
- **The rejection kept the finished work.** `coder-1` rejected one test and left `db.rs` and the three stores in the workspace, with the gate green and the other falsifiers' reds recorded. Plan 2 changed one fixture and re-ran three falsifiers, so the round trip cost $2.22 rather than a second implementation.

## What did not go well

- **The one round trip came from a SQLite premise measured against the wrong SQLite.** Plan 1 §4 said a stale `-wal` is deleted by SQLite itself so the `-shm` inode discriminates C3b, a sentence `architect-1` added without a measurement. `test-writer-1` checked the fixture with Python's `sqlite3`, SQLite 3.54, and said so in its report. The library under test is the SQLite 3.45.0 that `rusqlite`'s `bundled` feature vendors, where a garbage `-wal` makes the failing connection delete both sidecars itself, so C3b stayed green on both workers.
- **The round trip cost $2.22 and about 7 minutes, plus `coder-1`'s probing.** The added invocations are `architect-2` ($1.02), `test-writer-2` ($0.44) and `coder-2` ($0.76). `coder-1` also ran two Python experiments and three `eprintln!` probe builds of `db.rs` through Bazel to find the cause, because the macOS worker has no `cargo` and libtest hid the first probe's stderr.
- **The test writer had no sanctioned way to measure through the bundled library.** Its definition asks for a dependency premise to be "measured against the real component" and also says "Run no test", and it lists Neovim, GTK and the compositor as the dependencies meant. A host tool was the only SQLite `test-writer-1` could reach without running a test. Nothing in `notes/wolf-core-decisions.md`, whose dependency row says only `rusqlite` (`bundled`), warns that the host's SQLite behaves differently.
- **zsh's word splitting cost `coder-2` a falsifier batch.** Its first driver loop set `--exact` from an unquoted `$x`, which zsh passes as one word, so every run had an empty test name, ran nothing and reported `PASSED`. The coder's system prompt warns about zsh's `=` word and its `echo`, but not about word splitting.
- **The Done criterion's grep could not see a stale count.** `crates/wolf-gnome/tests/smoke_headless/main.rs` line 1343 still says an unisolated smoke would write "the three MRU sqlite files", which review 1 §5 found and which landed. The task's `-mru.sqlite` grep finds file names, not prose that counts files.
- **Two false statements that predate the task were found and left.** The doc comments of `RecentDirs::record` (`recent_dirs.rs` line 75) and `CommandMru::record` (`command_mru.rs` line 80) say "One transaction", but each runs three autocommit statements. `notes/wolf-core-decisions.md`, "The bundle is Wolf's", says Wolf never modifies anything under `state_dir()` but one directory, though Wolf writes and now deletes databases there. `technical-writer-1` and review 1 §5 flagged both, and neither was theirs to fix.
- **One heal can now cost every store's rows.** Review 1 §2 notes that a connection left on the unlinked inode by another handle's heal can fault later and delete the healthy file the first heal recreated. With one file, that reaches all three stores in every window, and the series' next task puts window and project state in the same file. No test pins the immediate transaction in `ensure_table` either (review 1 §3).
- **`crates/wolf-core/tests/README.md` grew again past the size warning.** It went to 61,761 bytes, 1,489 more, and the documentation gate printed it as a `big-file` warning. [ghostty-2](ghostty-2.md) found the same file past the ceiling at 56,384 bytes; it cost this task nothing, so no recommendation follows from it here.

## Recommendations

1. **Let the test writer measure a premise through the library the test links.** This is recommendation 2 of [regina-land-linux-titlebar](regina-land-linux-titlebar.md) and [nerd-font-3](nerd-font-3.md), and 3 of [gnome-toolbar-1](gnome-toolbar-1.md), come up again. In `.claude/skills/regina/agents/test-writer.md`, name vendored libraries beside Neovim, GTK and the compositor, and allow one scratch probe through the linked build, such as a throwaway test that prints `rusqlite::version()`. It would have saved the $2.22 round trip and most of `coder-1`'s probing.
2. **Have the architect mark an unmeasured premise as one.** Plan 1 §4's `-wal` sentence read as fact, and `test-writer-1` built on it. In `.claude/skills/regina/agents/architect.md`, require a premise about a dependency's behaviour to be either measured or labelled unmeasured, as [fixes-2](fixes-2.md) recommendation 1 asked for a doubted one.
3. **Say which SQLite Wolf links.** In `notes/wolf-core-decisions.md`, extend the `rusqlite` (`bundled`) row's reason: the SQLite is the one `libsqlite3-sys` in `Cargo.lock` vendors, not the host's `sqlite3` or Python's, and their file handling differs, as the sidecar cleanup in `tests/db.rs`'s not-a-database test shows. Any agent reaching for a quick probe reads that row first.
4. **Warn about zsh's word splitting in the worker definitions.** This is recommendation 4 of [nerd-font-3](nerd-font-3.md), come up again, and `coder-2`'s system prompt still lacks it. Add to the zsh paragraph under `.claude/skills/regina/agents/` that an unquoted `$var` is one word, so a command in a variable is written as an array, `${=var}` or `sh -c`.
5. **Fix the drift this task found.** Make `main.rs` line 1343 in `crates/wolf-gnome/tests/smoke_headless/` name "the `wolf.sqlite` database". Either wrap the three statements of `RecentDirs::record` and `CommandMru::record` in a transaction or reword their docs, and narrow the `state_dir()` claim in `notes/wolf-core-decisions.md` to the user's `runtime_user` and `parsers_user` directories.
6. **Guard the heal before state tables share the file.** In `crates/wolf-core/src/db.rs`, delete only when the path's inode is still the one the faulting connection opened, as review 1 §2 suggests, and give it a falsifier. The next task of this series adds `window_state` and `project_state` to `wolf.sqlite`, where a second heal would cost a user's windows and not a cache.
