# Retrospective: one home for the test helpers copied between crates

Last verified at commit `4afff0e969c6ed3ea979a361f60e6e83bd2d7ebc`.

The task moved the helpers copied between the wolf-core, wolf-ffi and wolf-gnome tests into a new dev-only crate, `crates/wolf-test-support`. It ran in one pass: `architect-1`, `test-writer-1`, `coder-1`, `technical-writer-1` and `reviewer-1`, with no rejection, no failed gate, no discrepancy and no resume. Both gates passed first time on both workers. The five invocations cost $21.15 in total; `architect-1` alone was $8.58, 81 turns and 21 minutes, spent surveying the three copies.

## What went well

- **The task was an earlier report's recommendation, carried out.** It is [ghostty-4](ghostty-4.md) recommendation 6 and the duplicate `pin_default_shell` that [ghostty-5](ghostty-5.md) found. `git grep -n "fn pin_default_shell"` now prints one line, and the diff is net negative, 1,393 lines added against 1,437 removed.
- **Every real-Neovim `rust_test` lists `tests/common/mod.rs` in its `srcs`.** That made plan 1's wiring rule checkable by count: a target whose `srcs` lists the file gets the new dep. `coder-1` matched 44 and 39 such targets in wolf-core and wolf-ffi, and `reviewer-1` confirmed that no test file with `mod common;` was left unwired.
- **crate_universe drops workspace-member edges.** wolf-core dev-depends on a crate that depends on wolf-core, and the repin accepted it with only a new member in `Cargo.Bazel.lock`. Plan 1 §7 predicted this, and `reviewer-1` confirmed that wolf-core's entry in the lock did not move.
- **The single-test commands made eight falsifiers cheap.** Plan 1 §4 gave `bazel test <target> --test_arg=--exact --test_arg=<name>` and `regina on linux -- cargo test -p <crate> --test <binary> -- --exact <name>`. `coder-1` ran F1a to F5b red and green on each worker the plan named, inside one invocation. The same commands were noted in [round-4-2](round-4-2.md).
- **doc-lint's `bazel-coverage` rule and `tools/lint/BUILD.bazel`'s uniform per-crate targets showed what a new crate needs.** Plan 1 §3 listed the clippy and rustfmt targets and both aggregate filegroups from them, and no lint gate failed.

## What did not go well

- **Adding one dep meant editing 83 `rust_test` targets by hand.** Each real-Neovim target in `crates/wolf-core/BUILD.bazel` and `crates/wolf-ffi/BUILD.bazel` spells out its `srcs`, `tags`, `data`, `env` and `deps`, about 27 lines each. The two files took 415 lines of churn for one dep. `coder-1`'s first wiring script failed on an assertion, because wolf-ffi mixes one-line and multi-line `deps`, and it needed a second script.
- **Plan 1's count was off by one.** It expected 45 `"tests/common/mod.rs"` hits in wolf-core's `BUILD.bazel`, but one hit was a comment, so `coder-1` had to work out why the right count was 44. A count over hand-written targets is a weak check, and `reviewer-1` re-did it target by target.
- **The survey searched by name and missed copies.** Review 1 §3 found `run_child`, `assert_child_passed`, `list_tree` and `planted_home_or_return` identical in `crates/wolf-ffi/tests/state_isolation.rs` and `crates/wolf-gnome/tests/state_isolation.rs`. `plant_home` differs only in its temp-dir type, and `deescape` is in both `cmdline_pum.rs` and `cmdline_ui.rs`. They are outside the task's named categories, so they stayed.
- **Three wording slips landed, as review 1 §5 noted.** `notes/wolf-core-decisions.md` § The one hard rule says every wolf-core and wolf-ffi Bazel test links the crate, but only the real-Neovim targets do. The module doc of `crates/wolf-ffi/tests/common/mod.rs` and the skip banner in `crates/wolf-test-support/src/resolve.rs` say a `WOLF_NVIM_BIN` suffices, where the shared rule needs an absolute path that exists.
- **`rg_bin_or_skip` writes `WOLF_RG_BIN` on every call.** `technical-writer-1` noted that this can race a neighbouring test's `getenv` in a multi-test `search.rs`, unlike the publish-once rule `WOLF_NVIM_BIN` now has. The copies it replaced did the same.
- **Hand-kept counts were stale again.** `technical-writer-1` found "four `rustfmt_test` targets" in `tools/lint/README.md` and "the three workspace crates" in `notes/gates.sh.md` already wrong at the base, since `wolf-vt` had been added. It made both count-free. This is the pattern of [round-4-1](round-4-1.md) recommendation 1.
- **zsh's `:` modifier ate a read again.** `coder-1`'s first `git show $B:crates/...` read nothing, because zsh took `:c` as a history modifier. The cost was one command. This is [round-3-10](round-3-10.md) recommendation 4, and the definitions this task ran under still lack the warning.

## Recommendations

1. **Give the real-Neovim `rust_test` one macro.** Add a Starlark macro, for example `wolf_nvim_test(name, crate)`, that supplies `tests/common/mod.rs`, `crate_root`, `tags = ["no-sandbox"]`, the `nvim_tree` and `init.lua` runfiles, the `WOLF_*` env and the `wolf_test_support` dep. Use it in `crates/wolf-core/BUILD.bazel` and `crates/wolf-ffi/BUILD.bazel`, and point their tests READMEs' "Adding a test file" at it. This task would then have been a one-line edit, with no wiring script, no count check and no target-by-target review.
2. **Move the `state_isolation` child-process helpers into `wolf-test-support`.** Put `run_child`, `assert_child_passed`, `list_tree`, `planted_home_or_return` and `plant_home` in one module and re-export them from the wolf-ffi and wolf-gnome `common` modules, with `deescape` beside them. Review 1 §3 found these copies, and they would otherwise be the next ones to drift.
3. **Correct the three wording slips.** In `notes/wolf-core-decisions.md` § The one hard rule, say the real-Neovim wolf-core and wolf-ffi Bazel tests. In `crates/wolf-ffi/tests/common/mod.rs`'s module doc and the banner in `resolve.rs`, say an absolute `WOLF_NVIM_BIN` that exists.
4. **Publish `WOLF_RG_BIN` once.** In `crates/wolf-test-support/src/resolve.rs`, put `rg_bin_or_skip`'s resolution behind a `OnceLock` and write the variable only when it differs, as `resolve_and_publish_nvim_bin` does. This closes the race `technical-writer-1` noted, in the one place it now lives.
5. **Two earlier recommendations came up again.** Removing hand-kept counts from documents, [round-4-1](round-4-1.md) recommendation 1, came up in two more files. The zsh `:` modifier warning in the definitions under `.claude/skills/regina/agents/`, [round-3-10](round-3-10.md) recommendation 4, is still not there.
