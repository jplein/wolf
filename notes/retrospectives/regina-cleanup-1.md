# Retrospective: give nested test READMEs an owner, a documentation-only route and a notes pass

Last verified at commit `693a19189158ef74a2ad562ec39acecd8cd7b920`.

The task fixed three gaps in regina's flow: `close-followups-4.md` rec 2 and `close-followups-6.md` rec 1 (nested test READMEs), `close-followups-5.md` rec 2 (documentation-only plans) and the unowned minor notes of a review. `coder-1` changed `.claude/skills/regina/flow.yaml` and the six definitions in `1028554`, and `technical-writer-1` changed `.claude/skills/regina/README.md` in `693a191`. No Wolf code changed.

There was no round trip. Every gate passed on both workers on its first run, and review 1 approved with minor notes. The four invocations cost $10.76 over about 38 minutes: `architect-1` $6.32 (75 turns, 22 minutes), `reviewer-1` $2.09 (35), `coder-1` $1.62 (51) and `technical-writer-1` $0.73 (18).

## What went well

- **The earlier retrospective made regina's source cheap to find.** [regina-land-agent-definitions](regina-land-agent-definitions.md) recorded how its architect found regina's documentation among the nix-store sources, and the task instructions pointed to it. `architect-1` found the source in four calls (`ps`, `nix-store -q --deriver`, `--references`), down from about 11 there. Plan 1 recorded both store paths, so `coder-1` and `reviewer-1` searched for nothing.
- **`regina flow validate` made the design testable.** The running build ships `regina flow validate FILE`, which exits 2 on an invalid flow. `architect-1` validated its draft before writing the plan, and checks K2 and K3 turned it into negative controls. `reviewer-1` relied on them to accept the guard and handoff design without its own probe.
- **A plan that gives a file as exact text can be checked by extraction.** Plan 1 §3 held `flow.yaml` as one fenced block. `coder-1` wrote the file with one `awk` extraction, and `technical-writer-1` and `reviewer-1` each diffed the committed file against the block, which found the one changed word at once.
- **The README said up front that nothing under `.claude/` is gated.** Line 5 of `.claude/skills/regina/README.md` told `architect-1` that prettier, the Markdown checker and doc-lint all skip the directory. So plan 1 gave hand checks for every rule a gate would otherwise have held (K5 to K7, K10).
- **Shared sections are checked by hash.** The README's `agents/` entry says `## The project` is word for word the same in all six definitions. K6 and the new K7 check that with `awk` and `shasum`, run by `coder-1`, `technical-writer-1` and `reviewer-1` in one command each.

## What did not go well

- **"Measured from the comment marker" was read two ways.** `architect-1` measured each `flow.yaml` comment after stripping `# `, so plan 1 called a 101-character line "measured". `doc-lint` counts the marker too (`tools/doc-lint/src/rules.rs:29`, `line.from_marker`). `coder-1` caught it only by reading that source, and the fix cost an edit, a re-run of K1 and a second `./gates.sh` run, since its first run had started before the fix.
- **Nothing gates `.claude/`, so its rules drift.** The base `flow.yaml` already failed the task's own prettier check, with the `coder` state at 81 columns (plan 1 §3, K5 at the base). No gate runs prettier on the YAML, the comment limits on `flow.yaml`, or `regina flow validate`. This is recommendation 1 of [round-3-6](round-3-6.md) and recommendation 4 of [round-3-4](round-3-4.md), and it came up again here.
- **The gates ran three times for a change no gate reads.** `coder-1` ran `./gates.sh` twice, as its definition requires before `passed`, and Regina ran the implementation gate on both workers. Plan 1's K8 itself said no gate reads `.claude/`. Each run cost time and proved nothing about the change.
- **The reviewer read regina's format again.** `reviewer-1` spent five calls reading the same sections of regina's `specifications/agent-workflow.md` that `architect-1` had read and quoted in plan 1. This is the price of checking the design against its source, and it was cheap. Nothing to change.
- **Four review notes landed unfixed.** The run used the base flow, so review 1's notes went "to a later reader", the very gap the task closes. Recommendations 3 to 5 carry them, as the notes pass would have done.
- **Nothing in this run exercised the new states.** The run started with the base flow, so `documentation-only`, `gate-before-documentation` and the `-notes` chain have only passed the validator. The first request after the merge is the first to take them.

Plan 1 also gave K6 a negative grep that matched the phrase it kept, and `coder-1` narrowed it. That was a slip in one plan, and nothing in the repository invited it.

## Recommendations

1. **Say that the comment width counts the marker.** In `tools/doc-lint/README.md`, line 39 and its rule table, write "from the marker, the marker included", and ask a person to say the same in `CLAUDE.md`'s `## Code comments`, which no agent writes. `architect-1` read "measured from the comment marker" as the text after it, and the slip cost `coder-1` an edit and a second `./gates.sh` run.
2. **Gate the regina harness.** This extends [round-3-6](round-3-6.md) recommendation 1 to the YAML. Add a step to both sides of `gates.sh` that runs `prettier --ignore-path /dev/null --check` on `.claude/skills/regina/`, and let doc-lint's comment rules walk `flow.yaml`. Where the dev shell can reach a `regina` binary, run `regina flow validate .claude/skills/regina/flow.yaml` as well. The base `flow.yaml` failed prettier, and plan 1's K1, K5 and the width check were all run by hand.
3. **Say whether a notes pass with no note of its own runs its gate.** `## The notes pass` in `coder.md`, `test-writer.md` and `technical-writer.md` says to change nothing and return `passed`, while each definition's gate rule says to run the marked gate first. Review 1 §8 note 1 found it. Give the pass an exception, so that `coder-notes` with no coder note does not run `./gates.sh` just before Regina does.
4. **Name the merge in `architect.md`'s `documentation-only` paragraph.** "The failure is a flake or came with the base" leaves out a `clean` merge of the integration branch, which also changes the commit the gate runs on. Write "a flake, or came with the base or the merge", as review 1 §8 note 2 says.
5. **Bring `.claude/agents/reviewer.md` into line.** The `/orchestrate` reviewer still sends minor notes "for the orchestrator to consider", as review 1 §8 note 4 and `technical-writer-1`'s report say. The paired definitions drifting is [retro-fixes-6](retro-fixes-6.md) recommendation 4 and [round-3-4](round-3-4.md) recommendation 3, and it came up again.
6. **Measure the new states on their first run.** Review 1 §8 note 3 says a review whose only note is the test writer's still invokes `coder-notes` and `technical-writer-notes`, each with nothing to do. The retrospective of the first task that takes `documentation-only` or the notes pass should report the cost of each state, and whether the reviewer's handoff and each agent kept to their own notes. If the empty invocations cost much, let the reviewer hand off to a chain that only holds the owners it names.
