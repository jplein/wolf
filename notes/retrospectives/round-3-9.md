# Retrospective: find and fix why macOS sometimes fails to recover after Neovim dies

Last verified at commit `af0ee62c58143f28aab6901df950381210f759d7`.

The task checked each way recovery could fail and confirmed three causes, all in the restart path. A restart kept the dead Neovim's snapshot, intents, history and macOS pane bindings (C1). The first macOS view came back in the wrong folder (C2). A hung Neovim went unreported while the user only typed (C3).

It took three plans, because `coder-1` and `coder-2` each sent a test back to the architect: T5's `:qa!` round, and a race in T1's precondition. Both gates passed on both workers on their only run, `implementation-1` and `documentation-1`, and review 1 approved with minor notes.

The eleven invocations cost about $41.91. The first pass, `architect-1` through `coder-1`, cost $23.26, of which `architect-1` was $10.26 over 102 turns and `coder-1` $9.36 over 151. The T5 round cost $3.80 and the T1 round $2.92, about 15 and 14 minutes. `technical-writer-1` and `reviewer-1` cost $11.93 together.

## What went well

- **wolf-gnome's restart path was a port target.** Plan 1 modelled `PaneContainerView`'s reset on `PaneInner::reset_after_restart` in `crates/wolf-gnome/src/pane_view.rs`, and the open order in `restoreSteps(for:)` on its `reopen_order`. Review 1 found no conformance defect in either. Keep wolf-gnome's restart code documented to that level, because it turned two fixes into ports.
- **The ledger in `notes/macos-followups.md` named C1's macOS half.** Its 2026-08-08 finding said `rebind(tabpageHandle:)` keeps every pane bound to its dead window handle. Plan 1 §1 cites it, and `technical-writer-1` deleted it once the fix closed it.
- **Every new test went into a target that was already wired.** `nvim_restart.rs` and `nvim_liveness.rs` had `rust_test` targets, `LivenessSeamTests.swift` was in `WolfKeyMapTests`' `srcs`, and U1 and U2 joined the existing `#[cfg(test)]` module in `render.rs`. Plan 1 §2 created no file, and no `BUILD.bazel` changed.
- **The pure `LivenessSeam` made C2 testable on macOS.** `restoreSteps(for:)` went into `WolfKeyMap` beside the existing seam, so S1 to S4 needed no Neovim and no AppKit, and all six of their falsifiers went red in `coder-1`. Without that seam, C2 would have been manual-only, like C1's pane half.
- **`regina on linux` let the coder settle Linux before the gate.** `coder-1` to `coder-3` ran `cargo fmt`, `clippy -D warnings`, the restart and liveness stress loops and the three wolf-gnome restart smokes there. The Linux gate then passed all 16 steps on its first run.

## What did not go well

- **T5's `:qa!` round rested on a false premise.** The instructions listed "a clean `:qa!`" as a death mode, and plan 1 typed it through `ex_command`. In Wolf a typed `:qa!` is `:WolfQuitAll!`, a window close, as `runtime/nvim/README.md` and `specs/command-lifecycle.md` both say. `architect-1` opened neither, but it read `crates/wolf-core/tests/nvim_liveness.rs`, whose module doc calls `qa!` a clean exit whose death "would be suppressed".
- **Nothing ran T5 before the coder did.** The test writer runs no test, so T5's first run was in `coder-1`, after the whole fix was written. It failed at round 3, 20 of 20 on macOS and 10 of 10 on Linux. The round cost `architect-2`, `test-writer-2` and `coder-2`.
- **The helper that types Ex commands is copied into ten test files, and no copy says what typing implies.** `ex_command` is defined in `nvim_restart.rs`, `nvim_liveness.rs`, `swap_recovery.rs`, `commands.rs` and six more files under `crates/wolf-core/tests/`, and `self_sigkill` in three of them. None of them warns that a typed command goes through `init.lua`'s abbreviations. The `self_sigkill` docs in `nvim_liveness.rs` and `swap_recovery.rs` each set it against "a clean `qa!`", which repeats the claim that misled plan 1.
- **T1's precondition relied on frames that a dying Neovim can lose.** `nvim-rs` runs its io loop and handler loop under one `try_join`, so at stdout end-of-file it drops every notification still queued. `architect-1` used that same `try_join` to justify `kill_in_place`'s wait (plan 1 §3), yet planned T1 to read the dead process's last `cmdline_show`. The base `deferred_sigkill` doc in `nvim_restart.rs` said `self_sigkill` leaves the command line active, and T1 built on it.
- **The race showed only under load.** `coder-1`'s stress skipped T5 and passed. With T5 back the binary ran one more Neovim, and `coder-2` saw the race once in 60 runs. The round cost `architect-3`, `test-writer-3` and `coder-3`.
- **Five invocations read `nvim-rs`'s source, three ways.** `architect-1` searched the disk, found nothing in the cold output root, and fetched the same docs.rs page twice. `coder-1` found it under Bazel's `external`, and `coder-2`, `architect-3` and `reviewer-1` found it in the task's cargo registry. Each read the same `io_loop` and `handler_loop`. `notes/wolf-core-decisions.md` holds the drop rule, which spares the next reader the why but not the where.
- **Eight README entries had no words to spare.** `technical-writer-1` found the `api.rs`, `nvim.rs`, `redraw.rs`, `render.rs`, `nvim_restart.rs`, `LivenessSeam.swift`, `PaneContainerView.swift` and `Project.swift` entries at or near the 250-word budget, and cut each before it could add. `WolfKeyMap/README.md` ended at 60542 bytes, `WolfMacOS/README.md` at 51313, `crates/wolf-gnome/tests/README.md` at 90040 and `notes/wolf-gnome-decisions.md` at 89726. All four are over the checker's 50000-byte warning.
- **C1's macOS half and the glue that calls `restoreSteps` have no automated test.** `PaneContainerView` needs a live `WolfCoreHandle`, and neither Swift target stages a Neovim (plan 1 §4). Review 1 checked the reset against all 17 per-window preview maps by hand, and its manual checks M1 and M2 are still unrun. S1 to S4 would still pass if `Project.respawnNeovim` stopped calling `restoreSteps`.
- **Three test comments are wrong after this task.** The `nvim_liveness.rs` module doc, at lines 27 to 30, and its crash test's doc, at lines 113 and 114, still say a clean `qa!` would be suppressed, though T5's scripted `qa!` ends in `Dead`. Review 1 §5 notes that the README entry was corrected and the test's own doc was not. The `deferred_sigkill` doc in `nvim_restart.rs` still says `self_sigkill` leaves the command line active, which is the race plan 3 removed from T1. Plan 3 §1 kept that doc as true.

## Recommendations

1. **Share `ex_command` and the kill helpers, and say what each one implies.** Move `ex_command` and `self_sigkill` into `crates/wolf-core/tests/common/mod.rs`, beside the shared `poll_until`, and delete the copies. Give `ex_command` a doc saying that a typed command goes through `init.lua`'s abbreviations, so the `:q` family closes a window and a native quit is `lua vim.cmd('qa!')`. Add a helper that kills a pid from outside, as T1 does, with a doc that links the drop rule in `notes/wolf-core-decisions.md`.
2. **Correct the claims both disputes grew from.** In the same pass, fix the `qa!` claims in `nvim_liveness.rs` and `swap_recovery.rs`, and the `deferred_sigkill` doc in `nvim_restart.rs`. Recommendations 1 and 2 together would have spared both rounds, $6.72 and about 29 minutes.
3. **Let the test writer run the tests the plan expects green on base.** T5 was such an evidence test, and its round 3 failed every time, but the test writer's "Run no test" rule made `coder-1` its first runner. In `.claude/skills/regina/agents/test-writer.md`, allow one run of each such test, with `rejected` if one goes red, and say the same in `architect.md` item 6. That would have sent T5 back before `coder-1` built on it, and narrows the rule that [open-items-1](open-items-1.md) and [open-items-13](open-items-13.md) asked the architect's definition to state.
4. **Make the macOS pane reset impossible to leave half done.** Gather `PaneContainerView`'s per-window state, the pane tree, the panes and the preview maps keyed by window handle, into one value that `rebind(tabpageHandle:)` replaces whole. A map added later then cannot survive a restart by being left off the reset's list. Review 1 had to check 17 maps by hand, and review 1 §3 suggests the same factoring as a way to make the reset testable.
5. **Say where a pinned crate's source is.** This came up again: it is recommendation 4 of [open-items-13](open-items-13.md) and recommendation 6 of [round-3-8](round-3-8.md). Here five invocations read `nvim-rs`, one of them over the network twice.
6. **Split the over-budget READMEs.** This came up again: it is recommendation 4 of [round-3-7](round-3-7.md), and [round-3-8](round-3-8.md) saw it too. In this task eight entries sat at the budget, and four documents are over 50000 bytes.
