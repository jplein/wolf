Last verified at commit `bae4fe9cc1a8175d2c7cf71c79512902991c0614`.

The task implemented `specs/application-state.md` §8 on macOS. `Project.swift` became `TabCore.swift`, one core per tab, with `TabFocusSeam` driving `set_ui_focus`, and `runtime/nvim/init.lua` gained `shortmess+=A`, a dead-owner re-arm and the focus-triggered `:checktime`. One round trip, review 1's "Needs revision" with three blockers, added `architect-2`, `coder-2`, `technical-writer-2` and `reviewer-2`: $5.56 and about 21 minutes, plus one more run of each gate on both workers. ## What went well

- **The `WolfKeyMap` seams made the focus and restore rules cheap to test.** `TabFocusSeam`, `RestoreSeam` and `LivenessSeam` are pure Swift, so F1 to F3, R1, R2, L1 and L2 run in `WolfKeyMapTests` in under a second. `coder-2` recorded the F4a and F4b reds in 19 turns for $0.74, each with its own one-line edit to `TabFocusSeam.edges`.
- **`LiveCore` let the controller-free tests start real Neovims.** `WolfWindowController` cannot be built offscreen, but K1 to K3 in `TabCoreTests.swift` start cores through the production `TabCore.start` over the staged Neovim and `init.lua`. Only the view is a stand-in, and review 1 §3 found no test that passes with its feature removed.
- **The pinned version made the Neovim premises checkable.** `bazel/nvim/extensions.bzl` pins `_VERSION = "0.12.6"`, and `architect-1` read `findswapname` in `memline.c` at that tag. D4, that `A` also stops `SwapExists`, came from that reading, and C1 and the existing `swap_recovery.rs` falsifiers confirmed it.
- **The instructions named every document to rewrite.** They listed the decisions-note section, the five README entries, the two spec passages and `README.md` line 5. Review 1 §6 and review 2 §6 found nothing changed outside scope.

## What did not go well

- **Every blocker of review 1 had been seen by an earlier agent.** The three blockers were an unplanned test with no falsifier ID, a second `Project.swift` on `notes/flake.nix.md` line 91, and the smoke harness's P0 and P2 failure messages, which blamed the removed key-gated current view. `test-writer-1`'s report lists the unplanned test, and `technical-writer-1`'s report names both smoke messages. None of the three was routed to the agent who owned it, so the round trip cost $5.56.
- **The unplanned test fell between two definitions again.** `test-writer-1` added `testActivatingAndResigningReportOneEdge` beyond plan 1 and reported it under F1 to F3. `coder-1` read that report and saw the test pass in its test log, but recorded no red, though its definition says an unplanned test gets an ID the coder makes up. The test writer's definition still says nothing about an unplanned test. This is the gap [sidebar-toggles-1](sidebar-toggles-1.md) found.
- **The technical writer saw wrong code text, and passed with a note.** `technical-writer-1` found that the `describe_p0` and `describe_p2` messages in `tools/wolf-macos-app-smoke.py` sent diagnosis to a removed mechanism. It filed them under "Notes for the retrospective" and returned `passed`, though its definition says code that is wrong is a `rejected`. This is the reading [sidebar-toggles-1](sidebar-toggles-1.md) found, too.
- **Plan 1's sweep covered comments, not strings.** Its grep included `tools/wolf-macos-app-smoke.py`, but its phrase list had "when a view becomes key", and the message said "a restored view becomes current only when its window becomes key". The harness has no Bazel target and its messages run only when a manual smoke fails, so nothing else could catch them.
- **A writer's sed fixed one of two mentions on a line.** `technical-writer-1` replaced `` `Project.swift` sets both`` on `notes/flake.nix.md` line 91 by phrase, and its last run of plan 1's sweep grep came before that edit. doc-lint checks Markdown links, and the second mention is a code span, so the documentation gate passed with it.
- **Deleting a file forced the coder into three writer-owned documents.** Plan 1 §5 gave the writer `runtime/nvim/README.md` line 13, but deleting `Project.swift` broke its link (`md-link`), and the implementation gate runs before the writer. `coder-1` also edited the `PaneContainerView.swift.md` mirror and added `## Dead-owner re-arm` to `notes/runtime/nvim/init.lua.md` for its new comment's link. Review 1 §1 accepted all three; the cost was the adjudication, not a round.
- **`architect-2` read Neovim's master, not the pin.** D13, which `notes/runtime/nvim/init.lua.md#dead-owner-re-arm` now states as fact, rests on three `WebFetch` summaries of `buffer.c` and `ex_cmds.c` on `master`. `architect-1` had used `curl` on the `v0.12.6` tag. Nothing in the repository says where to read the pinned Neovim's C source.

This is recommendation 5 of [titlebar-colours-2](titlebar-colours-2.md), come up again; it cost this task nothing.

## Recommendations

1. **Give an unplanned test its own ID at the test writer.** This is recommendation 1 of [sidebar-toggles-1](sidebar-toggles-1.md), come up again, and `test-writer-1`'s system prompt still lacks it. In `.claude/skills/regina/agents/test-writer.md`, require a test the plan does not ask for to come with a proposed ID and disabling edit in the report. That would have given `coder-1` an F4 to run and removed one of review 1's three blockers.
2. **Make wrong code text a `rejected` for the technical writer.** This is recommendation 2 of [sidebar-toggles-1](sidebar-toggles-1.md), come up again. In `.claude/skills/regina/agents/technical-writer.md`, say that a comment, docstring or message the change makes false is a `rejected`, never a note for the retrospective. `technical-writer-1`'s `rejected` would have sent the smoke messages to the coder before review 1.
3. **Extend the architect's sweep rule to strings.** In `.claude/skills/regina/agents/architect.md`, beside the rule that a sweep is planned by rule and check, say that a sweep for a removed model covers docstrings and user-facing string literals, matched on the removed names and the behaviour they implied. Plan 1's grep would then have printed the smoke messages for `coder-1`.
4. **Check code-span file names in doc-lint.** Add a rule to `tools/doc-lint` that a code span naming a source file, such as `` `Project.swift` ``, matches a file in the tree, with `notes/retrospectives/` exempt. It would have failed `documentation-1` on `notes/flake.nix.md` line 91, and it would make a rename's writer sweep the gate's work.
5. **Give the coder every Markdown edit the implementation gate needs.** This widens recommendation 1 of [followups-1](followups-1.md), which asked it for a new mirror heading, and that rule is still missing from the architect's definition. In `.claude/skills/regina/agents/architect.md` item 5, say that a link a deleted or renamed file breaks, and a mirror heading a new comment links, are the coder's, since doc-lint fails them at the implementation gate. `coder-1`'s three departures are the evidence.
6. **Say where to read the pinned Neovim's source.** This is the Neovim form of recommendation 5 of [round-3-10](round-3-10.md). In `runtime/nvim/README.md`, say that the version is `_VERSION` in `bazel/nvim/extensions.bzl` and that the C source is read with `curl` at that tag, not with `WebFetch` on `master`. It would have put D13 on the pinned code.
7. **Close what this task left open.** Give the `:saveas` gap of D13 a `BufFilePre` disarm in `runtime/nvim/init.lua` with a real-Neovim falsifier in `crates/wolf-core/tests/swap_recovery.rs`. The GNOME task should rewrite the D9 comments, the `fixture_guards.rs` message and `notes/crates/wolf-gnome/tests/smoke_headless/restore.rs.md` for `A`.
