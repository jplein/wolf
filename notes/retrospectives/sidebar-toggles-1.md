# Retrospective: the macOS toolbar's sidebar panel control

Last verified at commit `fb3af7c7dbde949c6b0ab03478d2729178170c36`.

The task replaced the system `.toggleSidebar` toolbar item with a Project/Search `NSSegmentedControl` after Back and Forward, derived its selection in a new `SidebarToolbarSeam`, and removed the header strip from `SidebarContainerView`. It took ten invocations, $16.20 in all. The first pass, `architect-1` to `reviewer-1`, cost $12.59, and one review round trip added $3.61. Every gate run passed on both workers the first time.

## What went well

- **`MainWindow` can be built offscreen, and an existing test showed how.** `TitlebarColourTests` already hosted a real `MainWindow` over a `LiveCore`. Plan 1 §1 moved `showSidebar(panel:)` from `WolfWindowController` into `MainWindow` for that reason, so `SidebarToolbarTests` drives the real toolbar and the real `isCollapsed` KVO with no window server and no mock.
- **The pure-seam pattern in `WolfKeyMap` carried the rule.** The task asked for one place that derives the selection, and `SidebarToolbarSeam` sits beside `SidebarMenuSeam`, which now delegates `isChecked` to it. Its six headless tests and nine falsifiers ran in under a second each in `coder-1`, and the menu checkmarks and the toolbar cannot drift apart.
- **The locked toolbar order had a test.** `HistorySeam.itemIdentifiers` and `testItemIdentifiersFollowTheLockedToolbarOrder` turned the order change into one signature and one expected array, with falsifier K7 behind it.
- **The implementation gate and the documentation gate passed at first run** on both workers, in both rounds. The plan's rule that a new comment links no anchor the technical writer has yet to write (plan 1 §2) kept doc-lint from failing the implementation gate.

## What did not go well

The one round trip was review 1, which rejected for two independent misses. Either alone would have forced the round, so both causes need fixing to avoid it. It added `architect-2`, `test-writer-2`, `coder-2`, `technical-writer-2` and `reviewer-2`, at $0.79, $0.30, $0.60, $0.31 and $1.61, plus a second run of both gates on both workers.

- **A test beyond the plan had no falsifier ID of its own.** `test-writer-1` added `testSelectedPanelIsTheVisiblePanelOrNothing` and its report mapped it under K1a and K1b, which already keyed another test. The architect's definition says one ID never covers several tests, and the coder's says an unplanned test gets an ID the coder makes up. `coder-1` read that table, ran K1a and K1b only against `testSelectedSegmentFollowsVisibilityAndMode`, and never ran the new test red.
- **The test writer's definition is silent on unplanned tests.** It says nothing about an ID or a disabling edit for a test the plan did not ask for. So the gap ran through two definitions that each had half the rule, and only the reviewer's held all of it.
- **A doc comment that lists its callers went stale.** The `focusSearchField()` doc comment in `crates/wolf-macos/Sources/WolfMacOS/SearchView.swift` named "the magnifier button" among its invocation paths. `architect-1` grepped `magnifier` across `crates/` and its output showed that line, yet plan 1 §3 listed only the two `WolfWindowController.swift` comments. `coder-1` grepped `magnifier` in `*.md` only.
- **The technical writer's definition was read two ways on that comment.** It says a comment that must change is a `rejected`, and one that is merely stale is a note. `technical-writer-1` called it merely stale and noted it, while `reviewer-1` held it blocking under plan 1 §8, "keep no comment that names the removed header". This is the same shape as [titlebar-colours-2](titlebar-colours-2.md)'s stale `theme.rs` comment, which the plan and the writer missed and only the review caught.
- **A test step checked nothing its message claimed.** Plan 1 §4 defined a click as setting `selectedSegment` and then sending the action, so steps 1, 3 and 4 of `testAToolbarClickTakesTheSamePath` select the segment themselves. Their `meaning:` strings blamed a missing refresh that cannot show there (review 1 §3), and `test-writer-2` rewrote them. It was minor, and rode along in the round the two blockers forced.
- **Two fixtures build the same offscreen window.** `SidebarToolbarTests.swift` and `TitlebarColourTests.swift` each start a `LiveCore`, build a `PaneContainerView`, a `SidebarContainerView` over a real `FileTreeView` and `SearchView`, and a `MainWindow` at fixed `cols` and `rows`, in near-identical lines. A change to `MainWindow.init` or `SidebarContainerView.init` now has two test files to edit, where `TerminalViewFixture.swift` and `PreviewViewFixture.swift` show the shared pattern.
- **The `WolfKeyMap` README is at its size limit again.** `technical-writer-1` held `crates/wolf-macos/Sources/WolfKeyMap/README.md` under the 50000-byte warning by trimming, and left it at 49964 bytes. It also trimmed the `MainWindow.swift` entry in `crates/wolf-macos/Sources/WolfMacOS/README.md` to fit, and it stands at 253 words. This is recommendation 5 of [titlebar-colours-2](titlebar-colours-2.md), come up again.
- **The commit attribution misled the reviewer.** `test-writer-2`'s edit to `SidebarToolbarTests.swift` landed in the coder's commit `162ed6c`, and `reviewer-2` had to read the transcript to show the test writer made it. That is the flow's commit grouping, not the repository's, and cost a few turns.

## Recommendations

1. **Give an unplanned test its own ID at the test writer.** In `.claude/skills/regina/agents/test-writer.md`, say that a test the plan does not ask for comes with a proposed ID of its own and its disabling edit in the report, and never under an existing plan ID. In `coder.md`, say that a report table mapping one ID to several tests does not excuse the made-up ID. That would have given `coder-1` a K8 to run and saved this task's round, $3.61.
2. **Make a comment that names removed code a `rejected` for the technical writer.** In `.claude/skills/regina/agents/technical-writer.md`, define "must change" to include a comment that names something the task removes, or one the plan's lint section forbids. `technical-writer-1` found the `SearchView.swift` comment, and a `rejected` there would have fixed it a reviewer invocation sooner.
3. **Have the architect turn a stale-name grep into a list of edits.** In `.claude/skills/regina/agents/architect.md`, say that when a task removes a named control, the plan lists every source comment the grep finds, in files it does not otherwise open as well. `architect-1` had the `SearchView.swift` hit in its own output, and [titlebar-colours-2](titlebar-colours-2.md) shows the same miss.
4. **Stop comments from enumerating their callers.** Rewrite the `focusSearchField()` doc comment to say the palette case defers and every other path has no competing refocus, without naming them. In `CLAUDE.md`'s rule against counting callers, add listing them, since a list goes stale the same way a count does; only the user edits that file.
5. **Extract one `MainWindow` test fixture.** Move the shared setup of `SidebarToolbarTests.swift` and `TitlebarColourTests.swift` into a `MainWindowFixture.swift` in `crates/wolf-macos/Tests/WolfMacOSTests/`, wired into `WolfMacOSTests` `srcs`, beside `TerminalViewFixture.swift`. The next change to either initializer then edits one file, and the next toolbar test starts from it.
6. **Trim the `WolfKeyMap` README before the next seam.** This repeats [titlebar-colours-2](titlebar-colours-2.md) recommendation 5, now with 36 bytes of room. The GNOME tasks of this request add no macOS seam, but the next macOS one will meet the warning in its documentation gate.
