# Retrospective: `:q` and `:qa` close only their own tab, and refuse on unsaved buffers

Last verified at commit `1bb366d18dd354a136af3e01f011b923b4632829`.

The task added the registry command `close_tab`, a tab-wide unsaved check `_G.wolf_refuse_unsaved()` in `runtime/nvim/init.lua`, and made the `:q` and `:qa` families notify `close_tab` instead of `close_window` on both platforms. It took eight invocations at about $32.58 and 102 minutes: `architect-1` $9.07, `test-writer-1` $7.91, `coder-1` $3.74, `architect-2` $2.62, `test-writer-2` $0.84, `coder-2` $1.13, `technical-writer-1` $2.92 and `reviewer-1` $4.35. There was one round trip, a coder rejection over test C13a. Both gates passed on both workers on their only run.

## What went well

- **The test probed its own premise, so the rejection was quick and backed by measurements.** C13a read `&modified` and `&buftype` before it typed `:q`, so its failure read `left: ["0", "nofile", "0"]` rather than a wrong verdict, and `test-writer-1`'s report had already named the premise as unmeasured. `coder-1` settled it with three headless Neovim runs, and `architect-2` replanned in 27 turns. The test writer's definition asks for this ("State any premise about how Neovim, GTK or the compositor behaves").
- **Adding a registry command was cheap.** `specs/command-lifecycle.md` §8 lists every face, and `EXPECTED_DISPATCHED_IDS` and `CASES` in `crates/wolf-gnome/src/command_action.rs` catch a missing one. `CloseTab` cost 10 lines in `command.rs`, 3 in `crates/wolf-ffi/src/lib.rs` and 4 in each Swift file. No gate failed on it.
- **The native-tabs smoke helpers carried the GNOME bug's red.** `test-writer-1` built G1 in `crates/wolf-gnome/tests/smoke_headless/panes.rs` from the existing Neovim-count and readback helpers there. G1 went red at the base with its own exit code, 23, before any code.
- **The real-Neovim harness in `crates/wolf-core/tests/commands.rs` took 17 new cases with no new infrastructure.** `ex_command`, `probe` and a few helpers in the file were enough. The only file added was the macOS `CloseTabDispatchTests.swift`, which was wired on the first try.

## What did not go well

- **The round trip came from a Neovim premise that plan 1 stated as fact.** Plan 1 D1 counted only buftypes `""` and `"acwrite"`, saying that the rule left out preview scratches, placeholders and terminal buffers. Neovim 0.12 never reports a `nofile`, `nowrite` or `terminal` buffer as modified, so C13a could not pass on any implementation. `architect-1`'s transcript shows no Neovim run, since its definition says it "run[s] no build", and `test-writer-1`, which flagged the premise, may "Run no test".
- **That round cost about $4.59 and 25 minutes.** The added invocations were `architect-2` ($2.62), `test-writer-2` ($0.84) and `coder-2` ($1.13), which re-ran both workers' gates. Plan 2 also found that plan 1's E162 name, `bufname()` or `[No Name]`, was not Vim's `buf_spname`, and one probe by `architect-1` would have given both answers. This is recommendation 1 of [application-state-10](application-state-10.md), which says the same of [fixes-2](fixes-2.md), [fixes-3](fixes-3.md), [application-state-1](application-state-1.md) and [application-state-6](application-state-6.md), come up again.
- **The pinned Neovim still has no documented path on macOS.** `architect-2`'s first probe in the macOS dev shell failed with `nvim: command not found`, and it then found the binary by `find` under `bazel-bin/bazel/nvim/nvim_version_test.runfiles`. `coder-1` instead sent its probes to the Linux worker, where `build.md` exports `WOLF_NVIM_BIN`. This is recommendation 6 of [round-3-10](round-3-10.md), come up again.
- **Smoke scenarios end the app by typing Vim's quit commands, so a change to quitting means a sweep.** Plan 1 D10 told the test writer to check every `:q`-family and `:qa`-family site under `crates/wolf-gnome/tests/smoke_headless/`. Fourteen files type `:qa`, and `config.rs` alone defines its own `quit_app()` shell function three times. The sweep took 10 of `architect-1`'s 96 tool calls and 23 of `test-writer-1`'s 102, and changed `restore.rs`, `recovery.rs` and `extras.rs`, and each of the request's three remaining tasks changes how a window or the app closes again.
- **Stale wording that the technical writer found landed, because nobody it could hand to was left.** `technical-writer-1` listed `crates/wolf-gnome/src/shell.rs` lines 43, 1784 and 1807, `crates/wolf-gnome/src/window.rs:798`, and `restore.rs` lines 210 and 1755 as naming only `close_window`. Review 1 repeated them as minor notes, and the `restore.rs` exit-12 message, "The drained close_window command never reached window.close()", is now false after `:qa`. This is recommendation 3 of [application-state-4](application-state-4.md), come up again.
- **One smoke leg does not check its premise.** Review 1 §3 found that `OWNQUIT_SCENARIO` leg (d) in `panes.rs` types `<C-w>v` and then `:qa` without reading back `winnr('$')`. If the split did not happen, the leg would still pass as a one-pane `:qa`. C6 in `commands.rs` covers the core rule.
- **Some falsifier commands on Linux hid their exit status.** Review 1 §4 found that `coder-1` piped its Linux `cargo test` runs through `grep`, so each one exited 0, and the reds can be read only from the quoted `FAILED` lines.

## Recommendations

1. **Let the architect run a scratch Neovim probe, and require one for a premise about Neovim.** This is recommendation 1 of [application-state-10](application-state-10.md), come up again. In `.claude/skills/regina/agents/architect.md`, allow a headless `--clean` run of the pinned Neovim under `TMPDIR` despite "run no build", and require a planned rule that rests on what Neovim does to cite that run. Here it would have saved the $4.59 round, and it would have given plan 1 the `buf_spname` names too.
2. **Name the pinned Neovim's macOS path in `build.md`.** This is recommendation 6 of [round-3-10](round-3-10.md), come up again. In `build.md`'s macOS section, give the command that prints the binary, for example `bazel cquery --output=files //bazel/nvim:nvim_tree`. Both `coder-1` and `architect-2` had to find their own route to it.
3. **Give the cage smokes one shared way to end the app.** Move the `quit_app()` shell functions in `crates/wolf-gnome/tests/smoke_headless/config.rs` and `preview.rs`, and the other scenarios' inline `:qa` exits, into one snippet in the smoke support module. Make it type `:WolfCloseWindow` or `:WolfQuit` rather than a Vim quit. D10's sweep cost about 33 tool calls across two agents here, and each of the three remaining tasks of this request changes quitting again.
4. **Fix the stale wording this task left.** Make `crates/wolf-gnome/tests/smoke_headless/restore.rs:210` and `:1755` name the drained `close_tab`. Make `crates/wolf-gnome/src/shell.rs:43`, `:1784`, `:1807` and `crates/wolf-gnome/src/window.rs:798` name a last-tab `close_tab` beside `close_window`. Add a `winnr('$')` readback of `2` before `:qa` in `panes.rs`'s `OWNQUIT_SCENARIO` leg (d).
