# Retrospective: GNOME tabs titled by their working directory, with a path tooltip

Last verified at commit `dfbb45c0b16c93bcdfc95e4b4d616a825f4bc41c`.

The task titled each `adw::TabPage` in `crates/wolf-gnome` by its own Neovim's cwd through `title::window_title`, gave it a Pango-escaped absolute-path tooltip, and added the cage smoke `smoke_headless/tab_bar.rs` (TB1). Its commits are `fbf605c` (code and tests) and `dfbb45c` (documentation). It took two plans, one review, and eight invocations costing $20.80. One round trip, a test dispute, cost $2.53.

## What went well

- **The pure derivation sat beside an existing seam.** `tabs_ui::tab_label` reuses `title::window_title`, so the selected tab's title and the window title share one rule, and TL1 to TL6 are hand-written table rows over values. `coder-1` measured all seven pure falsifiers with one script in one Linux command. Its first attempt failed only because the Linux shell lacks `perl`, which is covered below.
- **TB1's messages and two OCR readings made the defect cheap to find.** `test-writer-1` chose to take both readings up front, the whole page and the tab bar's band. On the first run, `coder-1`'s red printed the bar reading `~/ttkestrel` and `~/ttpelican` next to a passing readback C. That pointed straight at a cwd Wolf never heard about. One headless `nvim --clean` probe (its Linux command 4) confirmed it.
- **`fixture_guards.rs` took the new names by registration.** The three `TB_OCR_*` terms went into `ASSERTED_OCR_TERMS` with one exemption block, and the plan's audit of the other multi-tab smokes found no conflict. No other smoke changed because of the new directory titles.
- **Snapshot-only falsifiers kept the tree clean.** Both coders applied each disabling edit only in the `regina on linux` snapshot, with a `sha256sum` before and after. Review 1 §6 could confirm from the command logs that no local file moved.

## What did not go well

- **The one round trip: TB1's `:cd` ran inside an autocmd without `++nested`.** Plan 1 §4 step 4 had a `FocusLost` autocmd run `cd ~/C`, and `test-writer-1` wrote it so. Autocommands do not nest by default, so that `:cd` fired no `DirChanged`, and `WolfCore::live_cwd` never moved. `coder-1` rejected the test, and `architect-2` ($1.21), `test-writer-2` ($0.75) and `coder-2` ($0.57) followed, for one keyword and a moved readback.
- **The precondition measured Neovim's state, not the event Wolf listens to.** Readback C wrote `getcwd()` from the same autocmd, so it passed while Z failed, and a test defect looked like a Wolf bug. `test-writer-1`'s report listed the `FocusLost` premise as "measured" by that readback. Plan 2 moved readback C into a `DirChanged` autocmd, so exit 162 now catches the defect.
- **No document says a `:cd` inside an autocmd fires no `DirChanged`.** `runtime/nvim/README.md` says `wolf_cwd` fires on `DirChanged` "so `:cd`, `:lcd`, and `:tcd` all fire it", with no exception. `architect-1` searched `DirChanged|live_cwd` while planning step 4 and found nothing to warn it. `crates/wolf-gnome/tests/README.md` § Smoke conventions holds Neovim pitfalls of the same kind, such as the `winwidth()` one, but not this one.
- **The test writer did not probe a Neovim premise it could have probed.** Its system prompt says to measure every premise about how Neovim behaves against the real component, and it also says "Run no test". The coder's probe was a headless `nvim --clean` run, not a test, and `test-writer-1` had `regina on linux`. The same gap came up in [gnome-toolbar-1](gnome-toolbar-1.md) recommendation 3 and [regina-land-linux-titlebar](regina-land-linux-titlebar.md) recommendation 2, and it comes up again here.
- **A hand-kept count in `fixture_guards.rs` was already wrong.** At the base, the heading said "The seven deliberate, documented exemptions" over eight blocks. Plan 1 §3 took the heading at its word and asked for "eight". `test-writer-1` counted the blocks and wrote "nine". The same doc also numbers the name-subject kinds "the third" to "the seventh" and the blocks "the seventh block" and "the eighth block", and each new entry has to renumber them.
- **The Linux shell still lacks `perl`.** `coder-1`'s first pure-falsifier script (command 6) failed for want of it and had to be rewritten with `sed`. This is [round-3-3](round-3-3.md) recommendation 2, come up again: [followups-1](followups-1.md) added `python3` but not `perl`.
- **`regina on linux` output cost a re-run again.** `coder-2` ran TB1a twice because a `tail -40` cut off the panic line, which added one more smoke run to a 12-minute invocation. The cost is the same kind as in [open-items-13](open-items-13.md) recommendation 3 and [pane-ui-3](pane-ui-3.md), where stderr after stdout made `tail` show the wrong lines.
- **Two small drifts landed, as review 1 §8 notes.** `crates/wolf-gnome/src/title.rs`'s module doc still calls it the window-title seam, while its README entry says it also titles each tab. `notes/crates/wolf-gnome/tests/smoke_headless/panes.rs.md` still hedges between `~/project` and `~/project/tbsub` for what the native-tabs bar draws, a question any run of that smoke could settle.

## Recommendations

1. **Add the nesting rule to the smoke conventions.** In `crates/wolf-gnome/tests/README.md` § Smoke conventions, add one entry: an Ex command typed into an autocmd fires its own autocommands only with `++nested`, and a cwd readback proves that Wolf heard the change only when a `DirChanged` autocmd writes it. In `runtime/nvim/README.md`'s `wolf_cwd` entry, add the exception to "all fire it" as a gotcha. Either would have warned `architect-1` or `test-writer-1`, and saved the $2.53 round trip.
2. **Let the test writer probe a Neovim premise.** This is [gnome-toolbar-1](gnome-toolbar-1.md) recommendation 3 and [regina-land-linux-titlebar](regina-land-linux-titlebar.md) recommendation 2, come up again. In `.claude/skills/regina/agents/test-writer.md`, say that "Run no test" allows a one-line headless `nvim --clean` probe of a premise, with the output quoted in the report. That probe is what found this task's defect, in `coder-1`, after the code was written.
3. **Drop the counts and ordinals from `fixture_guards.rs`'s docs.** Make the heading "The deliberate, documented exemptions". Name each exemption block and each name-subject kind by its smoke rather than as "the seventh". The base heading was already off by one, plan 1 repeated the error, and every new smoke has to renumber the list. `CLAUDE.md` already rules out counts like these in comments.
4. **Add `pkgs.perl` to `linuxShell` in `flake.nix`.** This is [round-3-3](round-3-3.md) recommendation 2, come up again. It cost `coder-1` one failed Linux command here.
5. **Show the smoke-run pattern that keeps the panic line.** In `.claude/skills/regina/agents/coder.md`, where it shows a smoke run through `regina on linux`, write the test's output to a file inside the same `sh -c` and `grep -A40 panicked` it, rather than piping it to `tail`. This extends [open-items-13](open-items-13.md) recommendation 3, and would have saved `coder-2`'s second TB1a run.
