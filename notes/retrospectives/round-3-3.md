# Retrospective: one shared `poll_until` in wolf-core's tests, polled exposed reads and a Bazel `grid_dump`

Last verified at commit `467274753034e7fa45919a5c98f867122a75f5de`.

The task carried out recommendations 1 to 3 of [retro-fixes-3](retro-fixes-3.md), the first of which is recommendation 2 of [open-items-1](open-items-1.md). It moved one value-returning `poll_until` and `POLL_INTERVAL` into `crates/wolf-core/tests/common/mod.rs` and removed the 22 local poll helpers. It made three single-`wait_for_flush` reads poll, gave `crates/wolf-core/examples/grid_dump.rs` a Bazel `rust_binary`, and recorded the no-input flush in `notes/wolf-core-decisions.md`. The change is `934def2` (test writer and coder) and `4672747` (technical writer).

It took one round: no rejection, no failed gate, no discrepancy, nothing resumed. Both gates passed on both workers on their first run, and review 1 approved with minor notes. The five invocations cost about $15.39: `architect-1` $5.95 (61 turns, 16.9 minutes), `test-writer-1` $3.83 (73 turns, 9.7 minutes), `coder-1` $1.54 (40 turns, 11.1 minutes), `technical-writer-1` $1.09 (39 turns, 2.0 minutes) and `reviewer-1` $2.98 (47 turns, 4.5 minutes).

## What went well

- **The retrospective that asked for the work also gave its inventory.** Recommendation 1 of [retro-fixes-3](retro-fixes-3.md) gave the count (22) and the late-frame mechanism. Plan 1 grepped every helper, sorted the call sites into three forms and classified all 37 single `wait_for_flush` reads, so `test-writer-1` converted 26 files in one invocation and review 1 checked the reads by spot-check rather than rederiving them.
- **The shared harness already held every piece the helper needed.** `FlushWaiter`, `wake_channel()`, `FLUSH_TIMEOUT` and the file-wide `#![allow(dead_code)]` in `tests/common/mod.rs` let `poll_until` slot in as one function. The four search pollers dropped their own `search_wake()` for `common::wake_channel()`. No test file was added, so nothing needed wiring into a `rust_test`.
- **A `regina on linux` snapshot let the coder falsify a file it may not write.** The task's falsifier edits `tests/common/mod.rs`, which is the test writer's. Plan 1 ran it inside a snapshot, so the zero-budget edit failed 9 cases across the three stress binaries while the workspace file's `shasum` stayed the same. The Linux stress run of ten iterations went the same way.
- **Every code-side falsifier was a one-line edit in `src/`.** `coder-1` disabled `nvim_input`, `apply_cwd`, `guard.complete = true` and the `InputEvent::Open` arm in turn, and each converted test timed out with its own `desc`. This is the property [retro-fixes-3](retro-fixes-3.md) also found; keep it.
- **The real-nvim `rust_test` targets were a template for the new binary.** The `grid_dump` target copies their `data` and `WOLF_*` `env` from `crates/wolf-core/BUILD.bazel`, and `coder-1`'s first macOS `bazel run` printed the `# Hello, Wolf` grid.

## What did not go well

- **The architect planned a Linux step it could not run, and the Linux worker lacks the tool it named.** `architect-1`'s system prompt grants no `regina on linux`, while `coder-1`'s and `test-writer-1`'s each mention it six times. Plan 1's T1 edit was a `perl -0pi` one-liner, and the Linux dev shell (`linuxShell` in `flake.nix`) has no `perl`. `test-writer-1` checked the one-liner with the macOS `perl`, and `coder-1`'s first Linux command exited 127, so the coder fell back to a `sed` addressed to line 67.
- **This is the third task of this request where the architect was the costliest invocation.** It was 39% of this task's cost, after the largest share in [round-3-1](round-3-1.md) and [round-3-2](round-3-2.md) too. As in round-3-1, its attempt to read Neovim's markdown ftplugin from the Bazel output base found nothing, because the output root was cold.
- **The task instructions named a falsifier that the owner rules forbid.** It told the coder to edit the shared `poll_until`, which lives in a test file. `architect-1` spent two calls reading `.claude/skills/regina/agents/coder.md` and `test-writer.md` to establish that, then reformulated it as a snapshot-only edit. Nothing in the repository says how a request should phrase a falsifier on a test file.
- **Plan 1's T3 falsifier could not fail as written.** Disabling the `win_close` arm alone left `close_removes_grid_and_window` passing, because `grid_destroy` removes the same grid and window. The comment at `crates/wolf-core/src/redraw.rs:1361` says so, so nothing in the repository invited it, and it cost `coder-1` one extra run.
- **Formatting of `crates/wolf-core/tests/` is checked only on Linux.** `//tools/lint:rustfmt_core` targets the library `//crates/wolf-core:wolf_core` alone, while `tools/lint/README.md:48` says `:rustfmt` runs "on each crate". `test-writer-1` formatted by running `cargo fmt` in a snapshot and applying its 900-line diff with `patch`. The plan's `bazel run //tools/lint:rustfmt.fix -- //crates/wolf-core/...`, run afterwards, printed `INFO: Empty results` and changed nothing, which leaves open whether it reaches the test targets at all.
- **Review 1 found two antecedents that the new sentences broke, and they landed.** In `notes/wolf-core-decisions.md:62`, the treesitter bullet sits between the wake-on-`flush` bullet and "That write lock is acquired cooperatively". In `build.md:56`, the macOS `grid_dump` sentence sits between the cargo block and "These select cargo's default profiles", which refers back to the block. As in [round-3-1](round-3-1.md), no agent could edit them after approval.
- **`grid_dump` hangs instead of failing when its `init.lua` is missing.** Its fallback joins `CARGO_MANIFEST_DIR`, which under Bazel names the compile sandbox, gone at run time (`coder-1` showed it with `strings` and `ls`). Plan 1 says Neovim started with `-u <missing>` waits on its "Press Enter" prompt. `bazel run` always sets `WOLF_TEST_INIT_LUA`, but the binary run from `bazel-bin` without it would hang, and nothing exercised that case.

## Recommendations

1. **Give the architect `regina on linux`.** This came up again: it is recommendation 1 of [round-3-2](round-3-2.md). Here it would have let `architect-1` try the T1 edit in a snapshot and find that `perl` is missing before `coder-1` did.
2. **Add `pkgs.perl` to `linuxShell` in `flake.nix`, or say in the regina agent definitions that the Linux snapshot has none.** `test-writer-1` verified plan 1's `perl` edit on macOS, and it failed only in `coder-1`'s first Linux command. A `perl -0pi` multi-line match is the natural tool for a falsifier inside a function, and the `sed` that replaced it is tied to a line number.
3. **Say in `.claude/skills/regina/README.md` how a request names a falsifier in a test file.** One sentence: such a falsifier runs inside a `regina on linux` snapshot, because the coder may not write test files. That would have saved `architect-1`'s two calls reading the agent definitions and the plan's reformulation.
4. **Make `:rustfmt` cover the test targets, or say that it does not.** Either add wolf-core's `rust_test` targets to a `rustfmt_test` in `tools/lint/BUILD.bazel`, or change `tools/lint/README.md:48` from "on each crate" to the library targets it checks. Then record whether `rustfmt.fix -- //crates/wolf-core/...` formats `tests/*.rs`, since this task's run printed `Empty results` and showed neither.
5. **Mend the two antecedents.** Move the treesitter bullet in `notes/wolf-core-decisions.md` below the `try_write` bullet, and move the macOS sentence in `build.md` after "These select cargo's default profiles…". In the same edit, say beside `grid_dump` in `build.md` that it writes to the user's state directory unless `WOLF_STATE_DIR` is set, which review 1 §8 found documented nowhere.
6. **Make `grid_dump` fail fast on a missing `init.lua`.** In `crates/wolf-core/examples/grid_dump.rs`, have `init_lua_path()` panic with the path when it does not exist, rather than start Neovim on a prompt that never returns. `coder-1` could only infer this case from the missing path.
