# Retrospective: the preview's web view spans its pane, and the page caps its content

Last verified at commit `9d1ce78cd9b09565cdbfc37dc86291591182a8e9`.

The task moved the preview's column cap from the web view's frame into the page, on both front-ends. The view now spans its pane below the statusbar strip, and an inline style on `<html>` caps and centres the content. The new seams are `PreviewWidthSeam.swift` and `crates/wolf-gnome/src/preview_width.rs`. The change is `e88be5f`, `3c8c0ed` and `9d1ce78`.

It took thirteen invocations at $43.38. Two round trips added $8.49: `coder-1`'s rejection over two test defects, and review 1's rejection over unfalsified tests and two false comments. Every gate run exited 0 on both workers.

## What went well

- **Pure seams made 24 of the reds cheap.** The style, the placement and the document splice are plain functions, so M1 to M5, M11 to M13 and G1 to G3, G11 and G12 run headless in `WolfKeyMapTests` and `preview_root_style.rs`. `coder-3` recorded ten new reds, one filtered run each, for $0.91.
- **The byte-identical `<head>` contract left the core alone.** `specs/architecture.md` already let a front-end replace only the body, so the style could ride on the `<html>` tag. Core's render did not change, and `wolf-core` took comment edits only (review 1 §2).
- **The occlusion test needed no code change.** `PaneOcclusion` tests containment, not equality, so a frame that strictly contains the capped grid rect still skips the grid paint. Plan 1 §3 saw this, and review 1 §2 confirmed it.
- **The gates passed on every run.** `implementation-1`, `implementation-2`, `documentation-1` and `documentation-2` exited 0 on both workers. No round trip came from a gate.
- **Two earlier recommendations held.** Plan 1 §3 cited [sidebar-preview-1](sidebar-preview-1.md) recommendation 1, and no new doc table has a predicted-red column. Plan 1 §5 gave the writer each full entry's `--entry-words` count, and every entry stayed in budget.

## What did not go well

- **A new fixture variant raced a startup gotcha that one test's entry already documented.** `PreviewViewFixture(split: false)` waited on `is_markdown_active()`, but the startup buffer is `Untitled.md`, so the wait returned before `:edit` landed. `open_preview()` then previewed the wrong buffer (`coder-1` report §1a). The gotcha was written down at the base, but in the `OtherPaneFlowTests.swift` entry of `crates/wolf-macos/Tests/WolfMacOSTests/README.md`, not in `TerminalViewFixture.swift`'s, where the startup buffer comes from.
- **The pickover smoke's sample rectangle was pinned to the web view's top.** In `preview_render.rs`, `file_picker_covers_the_live_preview_under_cage` built its rectangle S from `web_top`. Moving the top from 159 to 139 brought the picker's selected row into S, and the fill fraction fell to 0.9625 against 0.98 (`coder-1` report §1b). The smoke is about the picker covering the preview, and the frame's top was not its subject.
- **Those two defects cost the first round trip, $3.57 and about 19 minutes.** `architect-2`, `test-writer-2` and `coder-2` were added. `test-writer-1` could run neither test, because both new targets reference API the coder adds, so the defects surfaced only at `coder-1`. `coder-1` also spent a diagnostic logging run and a remote PNG decode on them.
- **Moving the frame forced edits in five tests that do not test the frame.** Plan 1 §3 listed the theme smoke in `preview.rs`, the baseline-grid, codehl and pickover smokes in `preview_render.rs`, and `StatusbarStripColourTests.swift`. Each measured from the view's top or left edge, so each had its band or figures re-derived. This is much of why `test-writer-1` cost $9.26.
- **Five added tests had no red, and this caused the second round trip.** `test-writer-1` added tests beyond plan 1 §4 and labelled them with existing IDs, "M2", "M3" and "G3" (its report, "Added cases"). `coder-1` then ran only those IDs' edits, though its definition gives an unplanned test an ID of its own. One added test, M13, could not go red as written, and plan 3 §1 had to change its input.
- **Two false comments were seen and left, the rest of the second round trip.** The claim that the in-sync web frame and grid rect are bit-identical sat in four places at the base: `PaneOcclusion.swift`, `PaneOcclusionTests.swift`, the tests README and the mirror. Plan 1 §5 listed only the two documents. `technical-writer-1` fixed those and filed the two comments as "Stale source comments", and review 1 R2 blocked on them.
- **Review 1's rejection cost $4.92.** It added `architect-3`, `test-writer-3`, `coder-3`, `technical-writer-2` and `reviewer-2`, over about 18 minutes, with no change in behaviour.
- **Who caps the preview was restated in at least sixteen places across four languages.** Plan 1 §3 listed sites in `markdown.rs`, `nvim.rs`, `PaneContainerView.swift` and `StatusbarTextSpan.swift`. `coder-1` found two more, in `crates/wolf-ffi/src/lib.rs` and `runtime/nvim/init.lua`, and plan 2 §5 added `runtime/nvim/README.md`, each restating the "Content width" paragraph of `specs/architecture.md`. `architect-1` cost $10.26 over 97 turns, much of it grepping these sites and paging `pane_view.rs` (304 KB) and `smoke_headless/preview.rs` (278 KB) in `sed -n` ranges.
- **The Swift single-test form is still missing from `build.md`.** `coder-1` first ran `--test_arg=--exact`, the coder definition's form, which XCTest ignores. It then searched the READMEs and found `--test_filter=<Class>/<method>` by trial (its report §6). Plan 2 §1 left the gap to this report.

## Recommendations

1. **Give an unplanned test its own ID at the test writer.** This is recommendation 1 of [sidebar-toggles-1](sidebar-toggles-1.md), come up again after [application-state-2](application-state-2.md), [application-state-9](application-state-9.md) and [cli-open-2-1](cli-open-2-1.md) to [cli-open-2-3](cli-open-2-3.md). `test-writer-1`'s system prompt still contains no "ID", and labelling the added tests "M2" and "M3" is the mistake sidebar-toggles-1 found. With this rule, `coder-1` would have shown the reds, and review 1 R1 would not have blocked.
2. **Say that a comment the change made false is a `rejected`.** This is recommendation 2 of [sidebar-preview-1](sidebar-preview-1.md), come up again. `.claude/skills/regina/agents/technical-writer.md` still contrasts "must change" with "merely stale", and `technical-writer-1` filed two false comments as stale. Under the rule it would have sent them back before `reviewer-1` ran.
3. **Give `TerminalViewFixture` a wait for an opened file.** Add a method to `crates/wolf-macos/Tests/WolfMacOSTests/TerminalViewFixture.swift` that types `:edit <path>` and waits until `current_file()` names the path. Move the `Untitled.md` gotcha from the `OtherPaneFlowTests.swift` entry to the `TerminalViewFixture.swift` entry. `PreviewViewFixture` would have called it, avoiding half of this task's first round trip.
4. **Derive the pickover smoke's rectangle from the picker, not from the web view.** S in `preview_render.rs` now skips the highlighted row by scanning for it. Deriving S from the picker's box and row geometry too would decouple it from the preview's frame. The next change to the preview's frame would then not reach this smoke.
5. **Point non-front-end comments at the spec, not at who caps.** In `crates/wolf-core/src/markdown.rs`, `crates/wolf-core/src/nvim.rs`, `crates/wolf-ffi/src/lib.rs` and `runtime/nvim/init.lua`, say the in-app render is full width and link `specs/architecture.md`'s "Content width" paragraph. Today each says how the front-end caps. That would have taken six comment sites out of plan 1 §3 and two out of `coder-1`'s search.
6. **Name `--test_filter=<Class>/<method>` in `build.md` and in the coder definition.** This is recommendation 3 of [cli-open-2-4](cli-open-2-4.md) and 5 of [application-state-7](application-state-7.md), come up again. Here the coder definition's `--test_arg=--exact` form is also wrong for Swift, which XCTest ignores, and `coder-1` lost a run to it.
7. **Split the large wolf-gnome sources and READMEs.** This is recommendation 7 of [nerd-font-3](nerd-font-3.md) and 4 of [sidebar-preview-1](sidebar-preview-1.md), come up again. `architect-1` and `test-writer-1` paged `pane_view.rs`, `smoke_headless/preview.rs`, `smoke_headless/main.rs` and the 138 KB tests README in ranges.
