# Retrospective: wolf-gnome and wolf-ffi docs stop describing code they do not own

Last verified at commit `ebede029b82496cc232447e13f2faddd0b53c0dd`.

The task carried out the ownership sweep that [open-items-4](open-items-4.md), [open-items-5](open-items-5.md), [open-items-6](open-items-6.md), [open-items-8](open-items-8.md) and [open-items-11](open-items-11.md) asked for. It rewrote about 270 sentences in `crates/wolf-gnome/src/` that described the macOS front-end. It cut wolf-ffi's restatements of wolf-core to links, and stated the macOS drain claim once, in the `LivenessSeam.swift` entry of its README. Its commits are `7f83795`, `ee1881c`, `a6f88e3` and `ebede02`; the earlier ones in the range are retro-fixes 1 to 4.

Plan 1 found the sites with one regex, its rule R1, and kept a closed list of seven accepted divergences, A1 to A7, where wolf-gnome may still name macOS. They are the docs of `focus_target` in `drawer.rs`, `grid_rect` in `editor_inset.rs` and `set_divider_fraction` in `layout.rs`, and one module-doc section each in `scrollbar.rs`, `statusbar_layout.rs`, `preview_link.rs` and `refresh_coalescer.rs`. Each links its macOS counterpart's README entry.

It took three rounds. `technical-writer-1` rejected the first because one site was missed, and review 1 rejected the second because another was missed. Every gate run passed on both workers on its first try. The twelve invocations cost about $25.69, of which `coder-1` was $8.22 (126 turns, 20.6 minutes) and `architect-1` $6.15 (83 turns, 15.7 minutes). The two extra rounds cost $4.37 in added invocations, plus two more implementation gate runs on both workers.

## What went well

- **doc-lint's `same-code` proved each edit was comment-only.** `tools/doc-lint/README.md` documents `doc-lint same-code <old> <new>`, which exits 0 when two files differ only in comments. `coder-1`, `coder-2` and `coder-3` ran it on every changed file, and both reviews relied on it, so no agent had to diff 43 files by eye to show that behaviour had not changed. Keep it.
- **Root-relative links in comments are checked.** Plan 1 sent every counterpart link through a `README.md#anchor` path that doc-lint resolves, since a bare `.swift` path is not checked. Both reviews could say that every new link resolves without opening one, because the documentation and implementation gates had already checked them.
- **The owning notes already held the shared contracts.** Every shared-contract owner plan 1 linked existed at the base commit: `notes/wolf-gnome-decisions.md#frame-time-instrumentation`, `#the-accelerator-namespace`, `#typography` and `notes/feat-list.md#navigation-and-file-access`, among others. A parity sentence could become a link instead of a new paragraph, and the sweep removed about 490 net lines without adding any note.
- **`regina on linux` made wolf-gnome checkable from the macOS worker.** wolf-gnome builds only on Linux, so its rustfmt, clippy `doc_lazy_continuation` and doctest checks exist only there. `coder-1` and `coder-3` ran them through `regina on linux` before handing off, and no implementation gate failed.

## What did not go well

- **The first miss: zsh's `echo` broke the coder's sweep pattern.** `coder-1` saved plan 1's R1 regex with `echo "$R" > $S/R`, and zsh's builtin `echo` turns `\b` into a backspace. The `\bNS[A-Z][A-Za-z]+` alternative then matched nothing, and the coder's last "R1" run omitted `tree_view.rs:58` ("GTK has no `NSOutlineView` equivalent"), which the intact regex matches. `coder-1`'s report then claimed that R1 found only A1 to A7. `technical-writer-1` ran the regex correctly and rejected, which added `architect-2`, `coder-2` and `technical-writer-2` ($1.56) and implementation gate run 2.
- **The second miss: neither check could see the site, and the plan's recipe did not fit it.** Plan 1 said "lines 68, 205, 368, 483, 543 and 678: delete 'shared with' and 'port of'". At the base commit, line 368 reads "the `min_drawer_height` floor `DrawerLayout.swift` shares", which contains neither phrase. `coder-1` located sites by text because the plan's line numbers had drifted, so it missed this one. Plan 1's R1 grep and the task's done-when grep both match `Swift` case-sensitively, so neither found `.swift`.
- **Every agent re-typed its own completeness check.** `architect-1`, `coder-1`, `technical-writer-1` to `-3`, and both reviews each ran their own variant of the sweep grep, and each variant had a different blind spot: the case-sensitive `Swift`, the mangled `\b` and the missing `.swift`. Review 1 caught the `.swift` site by reading the plan's line list, not with any grep. Review 1 cost $4.00, and its rejection added `architect-3`, `coder-3`, `technical-writer-3` and `reviewer-2` ($2.81) and implementation gate run 3.
- **Nothing keeps the sweep from growing back.** The done-when condition ("a grep finds only accepted-divergence links") is a one-time check. No gate enforces it, so the next wolf-gnome change that names a Swift type lands unnoticed, as the sentences this task removed did.
- **Plan 1 was a site-by-site transcript of 270 hits.** It listed line numbers in 38 files, about 27 KB of text. `coder-1` reports that several had drifted by the time it read them, because of the test writer's commit and its own earlier edits. `architect-1` claimed the R1 grep had "no false positives" at the base, but did not check for false negatives, which is the kind of gap that let `drawer.rs:368` through.
- **No gate checks rustdoc intra-doc links.** The task added `mod@wolf_core::pane_status`, `WolfCore::recent_dirs`, `PaneStatus::filename`, `focus_target`, `grid_rect` and `PaneTree::set_divider_fraction` links. Only `coder-1`'s manual `RUSTDOCFLAGS=-D rustdoc::broken_intra_doc_links cargo doc --no-deps` run on Linux checked them. That run also showed errors that predate the task: an ambiguous `crate::liveness_ui` in five wolf-gnome files, and private or unresolved links in `crates/wolf-ffi/src/lib.rs`.
- **Residual cross-platform wording outside the task.** Review 2 notes "this port" at `preview_link.rs:44` and `pane_view.rs:2050`, both meaning "this front-end". `crates/wolf-gnome/README.md` line 31 ("as it does on macOS") was out of scope. `coder-1` flagged `notes/wolf-gnome-decisions.md` lines 11, 215 and 217, and plan 2 kept them because they are true.
- **One factual slip, not invited by the repository.** `coder-1` wrote that a short cell is "a whole row lost" in `cell_metrics_math.rs`, when a shorter cell fits more rows. Review 1 caught it, and plan 3 folded the fix into round three at no extra cost.

## Recommendations

1. **Make the sweep a committed lint with an allowlist.** Add a check under `tools/lint/` that fails when `crates/wolf-gnome/src/` matches `macos|swift|appkit` case-insensitively, or `\bNS[A-Z]`, outside a listed set of sites: A1 to A7 and the `scroll_direction_is_inverted_from_macos` identifier. Wire it with an `sh_test` and a Linux `run` line, as `CLAUDE.md` asks. It would have failed implementation gate 1 on both missed sites, saving the $4.37 of rework, and would stop the regrowth that [open-items-8](open-items-8.md) recommendation 1 records across four tasks.
2. **Warn about zsh's `echo` in the worker definitions.** The six definitions under `.claude/skills/regina/agents/` already warn that zsh expands an unquoted `=` word. Add that zsh's builtin `echo` interprets backslashes, so a pattern is saved with `printf '%s\n'` or a quoted heredoc. That paragraph is copied into all six files, so the change touches six places; keeping it in one shared file that each definition links would make the next correction one edit.
3. **Plan a sweep by rule and check, not by line.** When a check like recommendation 1 exists, a plan can name the rule, the closed allowlist and the check, and leave the sites to the check's output. Plan 1's 27 KB list drifted under `coder-1`, and its one wrong recipe at `drawer.rs:368` cost a review round. Without such a check, a plan should list each site by the exact text to match, not by a line number and a phrase.
4. **Gate rustdoc's intra-doc links on Linux.** Fix the pre-existing errors `coder-1` listed (`crate::liveness_ui` in `appearance.rs`, `clipboard_ui.rs`, `nav_ui.rs`, `state_seam.rs` and `tabs_ui.rs`, and the wolf-ffi links), then add a `cargo doc --no-deps` step with `-D rustdoc::broken_intra_doc_links` to the Linux gates of `gates.sh`. This task added six intra-doc links that only one manual run checked.
5. **Finish the residual wording when those files are next opened.** Change "this port" to "this front-end" at `preview_link.rs:44` and `pane_view.rs:2050`, and decide whether `crates/wolf-gnome/README.md` line 31 should link its rule instead of comparing it to macOS. With recommendation 1 in place, the check's allowlist would decide each of these.
