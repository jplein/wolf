# Retrospective: the GNOME empty tab's view takes its own Neovim's `Normal` background

Last verified at commit `e9d971881376c093a3ad35d0d204616b6f81a76e`.

The task ran once through, with no rework: `architect-1` ($4.12), `test-writer-1` ($1.91), `coder-1` ($1.77), `technical-writer-1` ($1.92) and `reviewer-1` ($2.34), about $12.06 in all. Plan 1 was the only plan, both gates passed on both workers at their first run, and review 1 approved with minor notes. This task's commits are `e70039b` (code and tests) and `e9d9718` (documentation).

## What went well

- **The titlebar's colour machinery was already pure and small.** `titlebar_background.rs` held the colour rule, the CSS and `stylesheet_update` as pure functions, beside a thin provider type. Plan 1 §3 could turn the provider into a private `ClassStyle` and add `EmptyStateStyle` beside `TitlebarStyle`, whose API stayed the same, so no caller in `shell.rs` or `window.rs` changed. Review 1 §1 confirmed it. Keep the pure functions apart from the GTK provider.
- **The `titlebar.rs` smoke harness carried the new smoke.** `tb_read`, `tb_assert_band`, `tb_bands`, `tb_rect` and `Lighthouse::from_env` gave the test writer bands from named constants and expected colours with no literal. The printed table of expected and measured colours made each of the coder's ES7 to ES9 reds name its cause on the first run. Plan 1 put the smoke in `titlebar.rs` rather than the `new_tab.rs` the instructions suggested, for that reason.
- **The plan's falsifier table held, row for row.** All nine of ES1 to ES9 went red as plan 1 §4 predicted. The pre-change smoke measured libadwaita's `#222226` against Lighthouse's `#1b1b1b`, which settled ES7's premise before any code was written.
- **`fixture_guards.rs`'s registry is keyed by name.** The new smoke reused `TB_READ_NAME`, so it needed a doc bullet and no registry row (review 1 §1).

## What did not go well

- **A spec sentence the task did not open misled plan 1.** `specs/architecture.md`'s Theming paragraph says "The macOS front-end realizes both" directions, through `nvim_set_hl`, which no production source calls. Plan 1 §5 asked the new `notes/wolf-macos-decisions.md` bullet to lean on it, and `technical-writer-1` found it false and left it out, which review 1 §5 checked. Two notes repeat it, and `notes/wolf-macos-decisions.md` contradicts it ("Appearance flows one way only").
- **The refactor left a falsifier description stale in another test.** The doc table of `tabs_join_the_header_bar_from_the_second_tab_under_cage` in `crates/wolf-gnome/tests/smoke_headless/titlebar_tabs.rs` describes C4d as "in `TitlebarStyle::install`, delete `tab_bar.add_css_class(&class)`". `e70039b` moved that statement into `ClassStyle::install`'s loop, and nothing checks such a description. Neither plan 1 nor the coder named the file; review 1 §5 found it and did not reject over it.
- **Per-tab scoping is unproven.** The tests README records that no smoke tells a tab's own `Normal` from the selected tab's. Review 1 §3 notes that a class shared between tabs is observable: two empty tabs on different `background` values, the first re-selected. Plan 1 §4 said no smoke could observe scoping, so none was written.
- **zsh's word splitting cost `coder-1` one batch.** Its first ES1 to ES6 loop put the command in `$T` and passed it unquoted, so `regina on linux` got one word and ran nothing (exit 127). It was cheap here, but it is the finding of [nerd-font-3](nerd-font-3.md) and [application-state-1](application-state-1.md), come up again, and `coder-1`'s system prompt still warns only about `=` words and `echo`.
- **The GNOME READMEs grew again past the size warning.** `crates/wolf-gnome/src/README.md` went to 102,962 bytes and `crates/wolf-gnome/tests/README.md` to 144,434, against the 50,000-byte `big-file` warning that the documentation gate printed. The `shell.rs` entry was at 249 of 250 words, so `technical-writer-1` merged two existing bullets to fit one new one. This is the finding of [application-state-6](application-state-6.md) and [application-state-9](application-state-9.md), come up again.

## Recommendations

1. **Open the Theming paragraph of `specs/architecture.md` in a task of its own.** Make it say that neither front-end realizes the front-end-to-Neovim direction, and turn its Front-end to Neovim paragraph into a present limitation or cut it. Correct `notes/feat-list.md`'s theming row and `notes/wolf-gnome/present-limitations.md`'s `nvim_set_hl` mention with it. Plan 1 §5 relied on the false sentence, and only the writer's check of the code kept it out of a new note.
2. **Describe C4d by what it breaks, not by the statement it deletes.** In `titlebar_tabs.rs`'s B4 row, write C4d as "`TitlebarStyle::install` leaves the tab bar out of the widgets that take the class". That survives a refactor of the provider, as this task's did not.
3. **Add a two-empty-tab smoke for the empty view's per-tab class.** In `smoke_headless/titlebar.rs`, open two empty tabs, set the other `background` in the second, re-select the first and sample its view through `tb_empty_view_bands`. It would catch a class shared between tabs, and replace half of the tests README's unproven bullet for the empty view.
4. **Warn about zsh's word splitting in the worker definitions.** This is recommendation 4 of [nerd-font-3](nerd-font-3.md) and of [application-state-1](application-state-1.md), come up again. Add to the zsh paragraph under `.claude/skills/regina/agents/` that an unquoted `$var` is passed as one word, so a command held in a variable must be spelled out or split with `${=var}`.
5. **Split the wolf-gnome READMEs.** This is recommendation 5 of [application-state-9](application-state-9.md), come up again. Both are over twice the warning, and each new GNOME feature is paid for by cutting a neighbouring bullet, as `technical-writer-1` did in the `shell.rs` entry here.
