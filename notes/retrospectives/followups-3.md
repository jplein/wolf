# Window-resize smokes through cage's headless output, and the clamp refusal

Last verified at commit `2d41e511176f17fb5774c6a2e4783f6a4997d807`.

The task asked whether the GNOME behaviours that need a window resize could be smoke-tested, by resizing `cage`'s headless output with `wlr-randr`. They could. `pkgs.wlr-randr` joined `linuxShell`, `drawer_divider.rs` and `zoom_pane.rs` each gained a resize smoke (DR and ZR), and both exposed that GTK's clamp on a resize was written back as a drag. `DividerGuard::last_position` in `crates/wolf-gnome/src/pane_view.rs` fixes it. The eight invocations cost $24.23, and one round trip, a test dispute, added $1.45 of it.

## What went well

- **The gap list named its mechanisms.** The "What is still unproven" bullets of `crates/wolf-gnome/tests/README.md` named the `max != last_max` arm and the drawer's `max-position` re-apply, so the instructions could quote them as the tests' subjects. `technical-writer-1` then rewrote or deleted each bullet in place, and review 1 found them matching the code and M2.
- **The pinned nixpkgs made the plan's prediction exact.** `architect-1` read cage 0.3.1, wlroots 0.20.2, GTK 4.22.4 and GLib 2.88.3 at the `flake.lock` revision through `builtins.getFlake`, and plan 1 §2 predicted GLib's reversed notify queue. `coder-1`'s base run matched it to the row: DR's grow back read `3 5`, the clamp's share the plan derived, and ZR went red at U-B only.
- **The smoke premises derive from production functions.** `DrawerShare::drag_to`, `editor_inset::grid_size_for_pane` and `min_pane_size`, with `drawer_strip_edges` factored into `drawer_paned_at` in `terminal.rs`, let `test-writer-1` derive DR's pass rows (1, 7) and its fail rows (3, 5) apart before launch. Review 1 §3 found the measured rows equal to the derivation, so no falsifier needed interpreting.
- **The readback files explain every red.** Each leg writes a file under the smoke's `TMPDIR`, and `coder-2` printed them after each of C1 to C5, M1 and M2. Review 1 matched all seven against the command logs without a rerun.
- **No wiring and no late gate.** wolf-gnome has no Bazel target and both tests sit in modules `smoke_headless/main.rs` already declares, so nothing needed wiring. `implementation-1` and `documentation-1` passed first time on both workers.

## What did not go well

- **The architect could not run the probe the instructions asked it for.** The instructions said to decide feasibility "with evidence from `nixos.local`" in the plan, but `architect-1`'s system prompt has no `regina on linux`, as every earlier report on it found. It tried `ssh` (calls 5 and 6) and `/etc/nix/machines` (call 55), then fetched five source trees (calls 18 to 26, 49 to 57, 78 to 82). It cost $8.88 over 97 turns, 37% of the task, and the probe itself moved to `test-writer-1`, where it took three commands.
- **One round trip: a check that could never pass.** Plan 1 §4's A4 said "B's `&lines` equals L's", and `test-writer-1` added an outer-grid check against L to A4 and U-B. L is read with the drawer closed, where `&lines` is 14, and every later launch-size readback, with the drawer open, reads 15 (`coder-1`'s readbacks `45 14 11 11 0 1` and `45 15 6 1 1 2`). `coder-1` returned `rejected`, and `architect-2` ($1.00) and `test-writer-2` ($0.45) moved two comparisons from L to G.
- **Nothing in the repository says `&lines` depends on the drawer.** No document records that the outer grid differs between drawer states at one window size, which is what plan 1 and `test-writer-1` both missed. Plan 2 §0 suspects `PaneInner::resize_global` reads `cmdline_area.height()` before the first allocation, but neither verified it nor wrote it down, and `technical-writer-1` left it out on purpose. The trap is still there for the next smoke that compares the outer grid across drawer states.
- **The first run of DR was the coder's.** By its definition `test-writer-1` ran no test, so the outer check's failure surfaced only in `coder-1`, after the fix was written. A base run of DR, which finishes in about 17 s, would have failed at A4's outer check instead of its height check and shown L's `45 14` beside it.
- **A store path did not survive between `regina on linux` commands.** `test-writer-1`'s second probe command used the `wlr-randr` path the first had built and found nothing there, so the third built it again inside the same command. [regina-land-terminfo-2](regina-land-terminfo-2.md) saw the same, and it cost one command here.
- **The wolf-gnome READMEs are still past their limits.** `crates/wolf-gnome/tests/README.md` went from 117452 to 119134 bytes, and `architect-1` read it in nine `sed` and `grep` calls (7 to 15). The `pane_view.rs` entry of `crates/wolf-gnome/src/README.md` was at 250 words, and `technical-writer-1` cut seven to fit the refusal in.
- **Three defects landed, all from review 1 §8.** That budget cut turned "restore materialization is its only legal caller" into "only restore materialization calls it" (line 603), which drops the rule. `DividerGuard::drag_span`'s doc ends "so the caller writes nothing else first" (`pane_view.rs:4362`), which is unclear. M1 showed the drawer's `max-position` handler is redundant beside `apply_drawer_frame`'s wake, and no document says so; nor does any say that no smoke clamps a tree divider on a resize.

## Recommendations

1. **Give the architect `regina on linux`.** This is recommendation 1 of [round-3-2](round-3-2.md), [round-3-3](round-3-3.md), [round-3-5](round-3-5.md) and [nerd-font-3](nerd-font-3.md), come up again. Here the instructions asked the architect for Linux evidence it could not gather, and `test-writer-1`'s three-command probe would have replaced most of `architect-1`'s source reading, a share of its $8.88.
2. **Settle the drawer-dependent `&lines`.** Verify plan 2 §0's suspected cause in `PaneInner::resize_global`, and either fix it so `&lines` is the same at one window size whatever the drawer's state, or add a Smoke conventions paragraph to `crates/wolf-gnome/tests/README.md` saying a smoke compares the outer grid only between readbacks with the same drawer state. Either would have spared this task's round trip, $1.45.
3. **Let the test writer run the tests the plan expects green, or red at a named leg, on base.** This is recommendation 3 of [round-3-9](round-3-9.md), come up again, and [pane-ui-5](pane-ui-5.md) saw the same. In `.claude/skills/regina/agents/test-writer.md`, allow one run of each such test, with `rejected` if it fails anywhere but the predicted leg. Here a 17 s run of DR would have shown the outer check failing.
4. **Split the wolf-gnome READMEs.** This is recommendation 5 of [pane-ui-5](pane-ui-5.md) and recommendation 6 of [round-3-9](round-3-9.md), come up again. Here the tests README cost the architect nine reads, and a word-budget cut in the `src` README lost a rule that review 1 had to catch.
5. **Mend review 1's leftovers.** Restore "is its only legal caller" in the `pane_view.rs` entry of `crates/wolf-gnome/src/README.md`, and rewrite the last clause of `drag_span`'s doc to say the caller need not record the position. In "What is still unproven" of the tests README, add that deleting the drawer's `max-position` handler alone leaves DR green (M1), and that no smoke clamps a tree divider on a resize.
