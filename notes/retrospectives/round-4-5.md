# Split the `wolf-macos` source READMEs, pin `OffscreenRenderer` to known colours, say how to dump a terminal frame

Last verified at commit `e4ef6196d3318dd291b370adb67c1d15bef57e07`.

The task carried out recommendations 1, 3 and 4 of [ghostty-3](ghostty-3.md) and recommendation 4 of [round-3-7](round-3-7.md). It ran straight through: `architect-1`, `test-writer-1`, `coder-1`, `technical-writer-1` and `reviewer-1` each ran once, and both gates passed on both workers on their first run. There was no rejection, non-zero gate, discrepancy or resume, and review 1 approved with three minor notes.

The five invocations cost about $9.30 and 27 minutes. `architect-1` was the largest at $3.90, 45 turns and 11 minutes. The others were `test-writer-1` $0.56, `coder-1` $1.18, `technical-writer-1` $1.61 and `reviewer-1` $2.05.

## What went well

- **A Swift subdirectory compiles into its parent module, so the move touched no Swift text.** Git records all 21 moves in `7c61750` as 100% renames, and only `crates/wolf-macos/BUILD.bazel` changed besides. `coder-1` saw `Executed 557 tests` and `Executed 14 tests` before and after, with identical sorted test names. `wolf_macos_lib` and `swift_format_srcs` glob `**/*.swift`, so the next `WolfMacOS` subdirectory needs no `BUILD.bazel` edit; `wolf_key_map` keeps its explicit list.
- **The markdown checker's `[big-file]` warning gave the split a number to aim at.** Plan 1 measured each module README with its candidate entries removed before choosing the groups, and predicted about 48 KB. `technical-writer-1` measured 48,314 and 48,088 bytes with `markdown_check.sh`, and review 1 §7 checked the done-when against the Linux gate log.
- **doc-lint's `md-anchor` rule caught the link the plan missed.** Plan 1 §5 listed four `wolf-gnome` terminal links to repoint, and there were five. `technical-writer-1`'s own doc-lint run named the fifth, so it cost one rerun and never reached a gate.
- **An explicit `srcs` list let the coder falsify a test without writing a test file.** `OffscreenRenderer.swift` is the test writer's, so F1 swapped it in `WolfMacOSTests` `srcs` for a scratch copy that skips the sRGB conversion. All three stripes went red, and the `BUILD.bazel` checksum matched after the restore.

## What did not go well

- **README anchors linked from comments pinned files in place.** Eight `wolf-gnome` doc comments link a `WolfKeyMap` or `WolfMacOS` README entry, and `tools/lint/wolf_gnome_wording_allowlist.txt` quotes each line verbatim. Moving such a file needs the coder to edit both, but the new anchor exists only once the technical writer has run, and `doc-anchor` fails at the implementation gate in between. So plan 1 D2 left eight files in place, among them `PaneTree`, `PaneGeometry` and `PaneContainerView`.
- **Finding those pins took the architect's time.** `architect-1` spent about ten of its forty commands grepping for anchor and path references before it could choose the groups. Three Swift comments link their own README anchors the same way, and the coder's report lists them.
- **The pane group that would have split most naturally stays, and the margin is small.** The module READMEs end 1,686 and 1,912 bytes under the 50,000-byte warning. [ghostty-3](ghostty-3.md) grew `WolfKeyMap/README.md` by about 3.5 KB in one task, so one more feature task touching panes can trip it again.
- **A quoted figure travelled into the test before anyone measured it, and three values landed.** The `srgb(x:y:)` doc comment in `OffscreenRenderer.swift` says the calibrated-tag misread shifts colours "by up to about 0.12". [ghostty-3](ghostty-3.md) repeated it, plan 1 §4 turned it into "near 0.1", and `test-writer-1` put that in the failure message of `OffscreenRendererTests.swift`. `coder-1`'s F1 run then measured pure blue at 0.199; `technical-writer-1` corrected the README to "about 0.2", but the comment and the message are the test writer's and still say 0.12 and 0.1 (review 1 note 1).
- **The frame-dump paragraph is incomplete under Bazel.** The paragraph added to the `terminal_bridge.rs` entry of `crates/wolf-ffi/tests/README.md` says to pass `--test_arg=--nocapture`. Review 1 note 2 found that the output then goes to the target's `test.log`, and a passing test shows it on the console only with `--test_output=all` or `streamed`.
- **Counting the tests in an XCTest target took a look outside `build.md`.** T2 asked for each target's `Executed N tests` line, and `--test_output=errors` prints nothing for a pass. `coder-1` found it through `bazel info bazel-testlogs` (its report says that is the only route), and `build.md` does not mention it. The cost was two commands.
- **A deeper path pushed one line over the checker's 800-character limit.** The `SessionSeamTests.swift` Covers line in `Tests/WolfKeyMapTests/README.md` grew to 805 characters with its `Persistence/` link, and `technical-writer-1` split a clause into its own paragraph. This is the pattern [round-4-4](round-4-4.md) saw with deeper mirror paths in comments, at the cost of one command.

## Recommendations

1. **Let a counterpart comment point at the macOS source file instead of its README anchor.** Extend doc-lint's `doc-ref` rule in `tools/doc-lint` to check that a root-relative `crates/…/*.swift` path in a comment exists, then repoint the eight allowlisted `wolf-gnome` comments and their allowlist lines at the Swift files. [retro-fixes-5](retro-fixes-5.md) routed these links through README anchors because a bare `.swift` path was unchecked. A move would then be the coder's edit alone, and plan 1 D2 could have moved the pane group and left both READMEs well below the warning.
2. **Correct the misread figure in the harness and the test.** In `crates/wolf-macos/Tests/WolfMacOSTests/OffscreenRenderer.swift`, change "up to about 0.12" to "about 0.2", and in the failure message of `OffscreenRendererTests.swift` change "near 0.1" to "between 0.1 and 0.2". `coder-1`'s F1 run measured 0.125, 0.199 and 0.105, so the message as written would point the next debugger of a 0.2 failure away from the cause it names.
3. **Finish the Bazel instruction in the frame-dump paragraph.** In the `terminal_bridge.rs` entry of `crates/wolf-ffi/tests/README.md`, add `--test_output=streamed` next to `--test_arg=--nocapture`. Without it a developer who follows the paragraph on macOS sees nothing printed, which is the scratch-program detour [ghostty-3](ghostty-3.md) recorded.
4. **Say in `build.md` where an XCTest target's test count is.** One sentence under the macOS test commands: the `Executed N tests` line is in `$(bazel info bazel-testlogs)/crates/wolf-macos/<target>/test.log`, and `--test_output=errors` does not print it for a pass. A done-when that says a target "runs every test file it ran before" needs that count, as this task's did.
