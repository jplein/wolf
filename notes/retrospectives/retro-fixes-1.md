# Retrospective: make `//tools/lint:swift_format` lint the real files

Last verified at commit `43a1876c372defcffc1b77ffbd1a3597a25c41c7`.

The task added `--follow-symlinks` to `tools/lint/swift_format_check.sh`, formatted the six Swift files the working check then flagged, added the macOS-only `//tools/lint:swift_format_check_test` and corrected `tools/lint/README.md`. It carried out recommendations 1 to 3 of [open-items-5](open-items-5.md). It ran in one pass with no rejection, `non-zero`, discrepancy or resume: plan 1, one invocation per agent, both gates green on both workers on their first run, and review 1 approved with minor notes. The five invocations cost about $4.89, and `architect-1` was $1.75 of it.

## What went well

- **The earlier report gave the task its cause and its test.** [open-items-5](open-items-5.md) named the symlinked runfiles, the flag, the four findings in `PaneTreeWeightsTests.swift` and the model test, `tools/lint/markdown_check_test.sh`. `architect-1` confirmed each by hand in 31 turns and listed every finding the fixed check would raise, file by file. `coder-1` said the predictions made each step a check, and finished in 21 turns and about 2 minutes.
- **`markdown_check_test.sh` made the new test cheap to write.** Plan 1 copied its shape (locate the checker, run cases, print a summary, exit 1), and `test-writer-1` finished in 20 turns. Its finding-line check let `coder-1` show three falsifiers fail for three different reasons. Keep that test as the model for checker tests.
- **The out-of-task rewrites by the formatter did not happen.** [open-items-11](open-items-11.md) counted six tasks in which `bazel run //tools/lint:swift_format.fix` rewrote files outside the task. Plan 1 forbade the fixer and had `test-writer-1` and `coder-1` run `xcrun swift-format format -i` on the paths each owned, and the diff held exactly the six planned files. That was a workaround in the plan: the fixer still formats every file, which is recommendation 2 of [open-items-4](open-items-4.md) and left to the next task.
- **The repository has no `.swift-format` file.** Review 1 noted that, with defaults on both sides, it did not matter whether swift-format looked up a configuration from the symlink or from its target. Adding such a file later reopens that question for `--follow-symlinks`.

## What did not go well

- **Plan 1 again asked the test writer to run tests.** Its Test plan told `test-writer-1` to run `bazel test //tools/lint:swift_format_check_test` and `//crates/wolf-macos:WolfKeyMapTests`, which the test writer's definition forbids ("Run no test"). `test-writer-1` built both targets instead and left the runs to `coder-1`, and review 1 accepted that. It cost nothing here, but it is the fourth report to find it.
- **Both swift-format targets cache a pass across host swift-format changes.** `:swift_format` and `:swift_format_check_test` run the host Xcode binary, which is not a Bazel input, and neither carries a tag that stops Bazel caching the result. In the implementation gate both were cache hits ("Executed 0 out of 9" for `//tools/lint:check`), reusing `coder-1`'s run. An Xcode upgrade that adds a rule would fail neither until an input changes, and a gate that cannot see the tool fails late.
- **`CLAUDE.md` disagrees with the tree.** Its "Lint scripts" rule asks for a Linux `run` line in `gates.sh` for every `tools/lint/*_test.sh`, and `swift_format_check_test.sh` deliberately has none. The task left the exception to the user, and `technical-writer-1` and review 1 both flagged it. Until it is written, the next agent to read the rule may add the line, which would fail on Linux for lack of swift-format.
- **`tools/lint/README.md` pinned a tool version nothing else pins.** Its Toolchains bullet said swift-format was "the host Xcode 26 binary (v6.3.0)", while the worker had Xcode 27.0 and a swift-format that prints `main`. `technical-writer-1` changed it to "the host Xcode binary". A version written into a doc with nothing to check it drifts without notice.

## Recommendations

1. **Say in the architect's definition that the test writer runs no test.** This came up again: it is recommendation 3 of [open-items-1](open-items-1.md), recommendation 1 of [open-items-3](open-items-3.md) and recommendation 2 of [open-items-13](open-items-13.md). Plan 1 here repeated the conflict, which `.claude/skills/regina/agents/architect.md` still does not rule out. One sentence in its item 4 would end a deviation every reviewer has to weigh.
2. **Stop Bazel caching the host-tool lint results.** Add `"external"` to the `tags` of `:swift_format` and `:swift_format_check_test` in `tools/lint/BUILD.bazel`, so each `bazel test //...` reruns them against the swift-format the host has now. The implementation gate in this task reused a cached pass for both. The cost is a few seconds a gate, against a gate that stays blind to a toolchain change until an unrelated edit.
3. **Write the `CLAUDE.md` exception for `swift_format_check_test.sh`.** In the "Lint scripts" bullet, say that a script needing the host Xcode swift-format gets the `sh_test` alone, because Linux has no swift-format. This is the user's edit, since no agent writes `CLAUDE.md`. It saves the next agent a rule that the tree visibly breaks.
