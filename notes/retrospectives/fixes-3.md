# Retrospective: menu shortcuts dropped over a clicked Markdown preview

Last verified at commit `b501cbc903eaa424800cb757b0fe0129ea77ce14`.

The task found why ⌘W, ⌘P and other menu shortcuts sometimes did nothing over a Markdown preview on macOS, and fixed it. A click leaves the preview's `WKWebView` first responder, and WebKit resends an unhandled key equivalent to the menu only when its `noop:` command reaches the end of the responder chain. `PaneContainerView.doCommand(by:)`, added for terminal panes in `eb604cf`, swallowed it; the fix passes it on to `super`. C1 and C7 guard it on macOS, and the cage smoke L1 shows GNOME is not affected.

The twelve invocations cost about $27.05 and 81 minutes of agent time. Two round trips added about $6.88: a coder rejection over a premise the plan had doubted ($4.22) and a review rejection over one sentence of documentation ($2.66). Every gate run passed on both workers on its first try.

## What went well

- **The live fixtures made a real preview cheap to host.** `PreviewViewFixture` is 119 lines on top of `TerminalViewFixture` and `LiveCore`, and gives C1 and C7 a real core, Neovim, a `PaneContainerView` and a hosted `WKWebView`. `OffscreenWindow.reportsKey`, added in [fixes-2](fixes-2.md), needed no change.
- **`AppMenu.install(target:)` runs headless.** C7 installs the production menu and retargets its items to a recorder, so its `control:` leg proves the synthesized ⌘W and ⌘P match the real Close and Command Palette… items. `coder-2` recorded that leg holding on the base code, which makes C7's red under the disabling edit mean the chain and nothing else.
- **GNOME's design made Linux safe by construction, and the smoke helpers made it cheap to show.** The preview web view is unfocusable and the chord controller runs in the capture phase. `test-writer-1` built L1 from `assert_inside_extents`, `preview_theme_preview_columns()` and the command MRU readback of sibling smokes, and `coder-1` took its red by deleting `install_chord_controller()`.
- **Commit history pointed straight at the cause.** `architect-1` found `eb604cf` with one `git log -S` on the override. The WebKit mechanism it read from WebKit's source is now in the `## Key equivalents over a preview` section of `notes/wolf-macos-decisions.md`, so no later agent has to fetch `WebViewImpl.mm` again.
- **This task wrote down the fact that cost it a round trip.** `crates/wolf-macos/Tests/WolfMacOSTests/README.md` now says that no page loads in a `WKWebView` under the worker's Seatbelt, and why. Keep that paragraph: it is what stops the next plan from building a page-state harness.

## What did not go well

- **Plan 1 rested five tests on a premise it doubted, and handed off without settling it.** Its branch for a failed premise names "no WebContent process under Seatbelt", and `architect-1` grepped `notes/` and the tests for `WebContent` and found nothing. `test-writer-1` ($6.75, 81 tool calls) then built C2–C6 and a resend-detecting harness behind a 15-second page wait. `coder-1` found that WebKit cannot issue its sandbox extensions in the worker, so no page loads and C2–C6 never got past their premise.
- **That round trip cost about $4.22 and 14 minutes, and threw away most of `test-writer-1`'s Swift.** The added invocations are `coder-1` ($0.91), `architect-2` ($2.11) and `test-writer-2` ($1.20), which deleted C2–C6 and the harness and added C7. The architect's definition says not to "settle by measurement a detail the coder will see for itself", which `architect-1` could read as licence to leave the premise to the coder. This is recommendation 1 of [fixes-2](fixes-2.md), come up again at a higher cost.
- **The page states the task asked about stay unmeasured.** Fresh, reloading, text selected and a real click are checks only a person can run, and the web-process step in C7 is modelled from WebKit's source rather than run. Nothing in the repository can change that while the worker's Seatbelt profile denies WebKit's `launchservicesd` and file sandbox extensions.
- **Plan 2's summary said Copy is a command WebCore runs itself, and it landed in the decisions note.** Plan 1 had said ⌘C is dropped like ⌘W, and the decisions note's paragraph on Edit > Copy says Copy reads the pushed selection cache. `architect-2` wrote the contrary sentence, `coder-2`'s report repeated it, and `technical-writer-1` copied it into the note with "either way" added. Review 1 rejected it as finding D1.
- **That round trip cost $2.66 and about 10 minutes for two sentences and a doc comment.** It added `architect-3` ($0.79), `coder-3` ($0.36, mostly the implementation gate on both workers), `technical-writer-2` ($0.37) and `reviewer-2` ($1.14). The task instructions listed Copy beside Select All and arrow-key scrolling as "keys the preview needs", which invites the reading that WebKit owns it. The `AppMenu.swift` entry of `crates/wolf-macos/Sources/WolfMacOS/README.md` does not say that Edit > Copy is a Wolf command item rather than AppKit's `copy:`.
- **The regression came from a coupling no document named.** `PaneContainerView` (3142 lines) is both a terminal pane's text-input client and the next responder of every preview `WKWebView`. The base doc comment on its `NSTextInputClient` extension said "for terminal panes only", so `eb604cf` swallowed commands in a method the preview's chain also reaches, with no test to notice. `technical-writer-1` and review 1 both flagged the stale comment, and `coder-3` fixed it in the second round; C1 now guards the route.
- **The macOS test posture is stated in four documents, and one task had to edit all four.** "Menus and event delivery have no automated coverage" stood in the testing posture of `notes/wolf-macos-decisions.md`, "What renders under `bazel test`" in the `WolfMacOSTests` README, the Testing paragraph and Layout row of `crates/wolf-macos/README.md`, and the line in `crates/wolf-macos/Tests/README.md`. Plans 1 and 2 each listed all four, and `technical-writer-1` rewrote each one.
- **L1's five readback names took 27 lines in `fixture_guards.rs`.** Each `KC_*` constant was imported and listed in `RELAUNCH_FIXTURE_NAMES` with its name repeated as a string. This is recommendation 7 of [fixes-1](fixes-1.md), come up again.

## Recommendations

1. **Make the architect settle a doubted premise before handoff.** This is recommendation 1 of [fixes-2](fixes-2.md), come up again. Here it would have saved about $4.22 and most of `test-writer-1`'s $6.75: one scratch `WKWebView` that loads an HTML string under the worker, or one existing-target run, would have shown no script runs. Reword the architect definition's "do not settle by measurement a detail the coder will see for itself" so that it excludes a premise a whole test plan rests on.
2. **Say in the `AppMenu.swift` entry that Edit > Copy is a Wolf command item.** In `crates/wolf-macos/Sources/WolfMacOS/README.md`, add a Decisions bullet: Copy is a tagged `commandItem` targeted at `AppDelegate`, not AppKit's `copy:`, so a `WKWebView` never runs it and ⌘C over a preview needs the same route as Close. `architect-2` read Copy as WebKit's own, and the $2.66 second round trip came from it.
3. **State the macOS test posture in one document and link it from the rest.** Keep the list of what `WolfMacOSTests` can and cannot reach in "What renders under `bazel test`" of `crates/wolf-macos/Tests/WolfMacOSTests/README.md`. Cut the restatements in `notes/wolf-macos-decisions.md`, `crates/wolf-macos/README.md` and `crates/wolf-macos/Tests/README.md` to a link, as `CLAUDE.md` asks. This task edited all four for one change of coverage, and the next harness change will again.
4. **Derive `RELAUNCH_FIXTURE_NAMES` entries from the constants.** This is recommendation 7 of [fixes-1](fixes-1.md), come up again for L1's five entries.
