# Retrospective: Zoom Pane's three new rules on core and macOS

Last verified at commit `f2db28d9d065ae8421099c97d08256ceda95fa73`.

The task changed three Zoom Pane rules: a focus move unzooms, Toggle Terminal unzooms, and `state.json` records each tab's zoomed leaf so a relaunch re-zooms it. It touched the contract in `specs/architecture.md` and `specs/terminal-panes.md`, `wolf-core`'s `PaneNode::Leaf`, `wolf_rebuild_layout` in `runtime/nvim/init.lua`, the FFI push-builder, and the macOS seams and container. Its commits are `e9cf36f` and `f2db28d`. No gate failed, and nothing was resumed or flagged as a discrepancy.

It took one round trip: `coder-1` rejected one line of a test, and plan 2 had the test writer fix it. The eight invocations cost about $31.60. `architect-1` was $8.02 (86 turns, 22 minutes), `test-writer-1` $5.30, `coder-1` $5.48 (22 minutes), `technical-writer-1` $6.63 (119 turns) and `reviewer-1` $4.15. The round trip added $2.01.

## What went well

- **Every test edit landed in a file its target already listed.** Plan 1 D11 kept all new cases in existing files, so no `BUILD.bazel` changed and nothing could be silently unrun. Review 1 confirmed the wiring by line number in three `BUILD.bazel` files in one pass.
- **A serde-defaulted field kept GNOME and old state files cheap.** `zoomed` is `#[serde(default, skip_serializing_if = …)]`, so `STATE_VERSION` stayed 1. GNOME needed only `zoomed: false` in its literals and `..` in `is_empty_leaf`, and `coder-1` confirmed that with one Linux `cargo build` before the gate. The Linux implementation gate passed on its only run.
- **The pure zoom seam in `WolfKeyMap` carried the rules.** `PaneZoom.swift` took `.focusMove`, `.toggleTerminal` and `.restore` as events, and `DrawerFocusSeam.focusTarget` was `applyFocus`'s resolution moved over unchanged. So the rule cases K11 to K14 run in the fast `WolfKeyMapTests` tier, and the live `ZoomPaneTests` only check the wiring.
- **Falsifier records with checksums kept the rework to one test.** `coder-1` recorded each of C1 to C24d with its red and equal `sha256` before and after. Plan 2 D14 kept C1 to C23 and asked `coder-2` to re-run only C24a to C24d ($0.84, 3.4 minutes).

## What did not go well

- **Z13 wrote its fixture where the Seatbelt worker cannot, and only the coder could find out.** `test-writer-1` built Z13's directory on `FileManager.default.temporaryDirectory`, the per-user `/var/folders/…/T`. The macOS test step failed on Z13's own premise with `NSCocoaErrorDomain Code=513`, 146 of 147 targets passing. The test writer runs no test by its definition, so `coder-1` met it at its first test run.
- **The convention lived only in code, twice, and the copies differ.** `LiveCore.swift` (`prepare()`) takes `TEST_TMPDIR` and treats an empty value as unset; `LighthouseColours.swift` line 152 takes `TEST_TMPDIR` without that check. Neither the base's `crates/wolf-macos/Tests/WolfMacOSTests/README.md` nor plan 1's Z13 section said where a live test's fixture files go. Z13 is now a third copy, and plan 2 §5 added the rule to that README.
- **That cost the round trip, and part of it was done twice.** `coder-1` could not edit the test file, so it copied the workspace to scratch, patched Z13 there and ran C24a to C24d in the copy. `architect-2`, `test-writer-2` and `coder-2` then cost $2.01 to make the one-expression edit and re-run the same four falsifiers in the workspace.
- **`PaneContainerView.swift` was read by every agent again.** It is 3,328 lines. `architect-1` named it in 12 of its 85 tool calls, and `coder-1` read it in five ranges. This is recommendation 2 of [pane-ui-4](pane-ui-4.md), come up again.
- **Entries at their word budget cost the technical writer a third of its run.** After its additions, the entries for `state.rs`, `rebuild_layout.rs`, `state_layout.rs`, `AppDelegate.swift` and `wolf_rebuild_layout` were over 250 words. `technical-writer-1` spent roughly its last 35 tool calls trimming older wording, and cut the per-batch split of the barrier-race measurement in the `rebuild_layout.rs` test entry to totals. The budget did its job here, so this has no recommendation of its own.
- **Two small defects landed, both noted by review 1.** The `//!` of `crates/wolf-gnome/tests/pane_zoom.rs` says it mirrors `PaneZoomTests.swift` "case for case, K1 to K10, with the same ids", which this task made false: Swift K7 and K9 now test the new rules, and K11 to K14 have no GNOME case. `notes/wolf-macos-decisions.md#zoom-pane` calls `toggleZoom()` "the one zoom change made outside a render wake", but `toggleTerminal()`'s unzoom is one too.

## Recommendations

1. **Give the live macOS tests one scratch-directory helper.** Add a function to `crates/wolf-macos/Tests/WolfMacOSTests/LiveCore.swift` that returns a fresh directory under `TEST_TMPDIR`, empty treated as unset, falling back to `NSTemporaryDirectory()`. Use it in `LiveCore.prepare()`, `LighthouseColours.swift` and Z13 in `ZoomPaneTests.swift`, and have the README paragraph name the helper. A test writer copying a sibling would have found it, and that saves a round trip like this one's $2.01 and `coder-1`'s scratch-copy detour.
2. **Make the lint step refuse `FileManager.default.temporaryDirectory` under `crates/wolf-macos/Tests/`.** A grep check in `tools/lint`, with an `sh_test` and its entry in `tools/lint/README.md`, fails with a message naming the helper. It would have caught Z13 before the 146-target test run, and the test writer can run it, which it cannot do for the live tests.
3. **Split `PaneContainerView.swift` and its entry.** This is recommendation 2 of [pane-ui-4](pane-ui-4.md), come up again. The zoom state, `applyFocus`, `toggleTerminal()` and the re-zoom in `rebuildLayout` were this task's change, and a zoom extension file with its own entry would have held them.
4. **Mend review 1's two leftovers in v01.** Rewrite the `//!` of `crates/wolf-gnome/tests/pane_zoom.rs` when GNOME takes the new rules, and drop "case for case" unless a test checks it. Change "the one zoom change made outside a render wake" in `notes/wolf-macos-decisions.md` to "the one zoom change no wake follows".
