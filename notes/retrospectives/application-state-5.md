# Retrospective: macOS saves and restores its windows through the app-state store

Last verified at commit `aeb16198bdb3fcf86edb0b31277eb3ac4ae20ee7`.

The task switched the macOS front-end from `state.json` to the `window_state` row of `wolf.sqlite`. It added the `StackingOrder` and `WindowStateCodec` seams, `Window::minimized` in `wolf-core`, and `FfiAppTab::restored` and `WolfCoreHandle::rebuild_tab` in `wolf-ffi`, and it deleted the whole `state.json` bridge from `crates/wolf-ffi/src/lib.rs`. Its commits are `34fc5f4` (code and tests) and `aeb1619` (documentation), 48 files in all.

The five invocations cost about $35.52 and 85 minutes of agent time: `architect-1` $9.13 (25 min), `test-writer-1` $5.94 (14 min), `coder-1` $9.34 (23 min), `technical-writer-1` $5.58 (11 min) and `reviewer-1` $5.53 (11 min). There was no round trip. Every agent ran once, `implementation-1` and `documentation-1` passed on both workers on their first run, and review 1 approved with minor notes.

## What went well

- **Plan 1 §5 gave the Swift seams' API, and the Swift tests compiled against it unseen.** The test writer cannot build Swift tests against code that does not exist. `coder-1`'s first `bazel test //crates/wolf-macos:WolfKeyMapTests` passed two minutes after it started on the Swift side, after one fix in its own code (`get(index: UInt(i))` for swift-bridge's vectors). Review 1 §6 found that it edited no test file.
- **The pure `WolfKeyMap` seams kept 38 falsifiers cheap.** `StackingOrder`, `SessionSeam`, `RestoreSeam`, `StateSeam` and `WindowStateCodec` have no AppKit in them, so `coder-1` drove all 38 plan IDs through one script, each with a restore checksum. Its transcript shows the pass running from 01:25 to 01:33, about eight minutes, with the Linux `./gates.sh` running alongside. This is the strength [application-state-2](application-state-2.md) recorded for the seams.
- **The test writer type-checked the Rust tests on Linux over a stub.** As in [application-state-4](application-state-4.md), `test-writer-1` copied the tree to a scratch directory on the Linux worker, stubbed plan §5.5's `wolf-ffi` surface there and ran `cargo clippy` over the new tests. The workspace never held the stub, and the four Rust targets passed on the coder's first Bazel run after its Rust change.
- **The previous retrospective's wording drift was planned in.** Plan 1 §5.4 and §6 assigned the rewording of `app_state.rs`'s `project_tab` doc and `app_state_model.rs`'s "only in later tasks" lines, from [application-state-4](application-state-4.md) recommendation 6. `git grep -i 'later task'` outside `notes/retrospectives/` and `.claude/` is now empty.
- **`--entry-words` was used to spend the word budget.** Plan 1 §7 said to run `./tools/lint/markdown_check.sh --entry-words <file>` before adding to an entry, and `technical-writer-1` ran it after each edit. It cut `SessionSeam.swift` from 291 to 249 words and `AppDelegate.swift` from 296 to 249 in six scripted edits, without the `wc -w` counting [application-state-4](application-state-4.md) recorded. No agent definition names the flag yet; the plan carried it.

## What did not go well

No rework happened, so nothing below cost a round trip. The findings are drift that landed and gaps that no automated test covers.

- **Deleting `crates/wolf-ffi/tests/state.rs` left eight references to it in sibling test files.** Review 1 §5a names `file_actions.rs:21` and `:39`, `multi_window.rs:5`, `:11` and `:24`, and `recent_dirs.rs:20`, `:39` and `:59`, where `:24` falsely claims coverage by `tests/state.rs`. Plan 1 §7 swept a README gotcha that named `state.rs` but no test module doc, and `technical-writer-1` grepped for `state.json`, `FfiPaneNode` and `rebuild_layout(` but not the file name. doc-lint checks only root-relative paths, so the crate-relative `tests/state.rs` passed both gates.
- **The launch assembly in `AppDelegate` has no automated test, and the test mirrors it.** `assembleWindows` in `crates/wolf-macos/Sources/WolfMacOS/AppDelegate.swift` builds the `StackingOrder.SeedWindow`s and chooses each window's selected tab. `WindowStateRoundTripTests.swift` builds its own seeds and does not call this code, so review 1 §3 notes that a wrong `selected` index there would pass every automated test.
- **The seed rests on an unmeasured AppKit premise.** Review 1 §2a found that `refreshTabFocus()` runs straight after the seed is installed, and that a stale `NSApp.mainWindow` would move a backmost, possibly minimized, window to the front of the next save. Only the double relaunch in review 1 §7 can show it. Nothing in the repository invited it, beyond the glue having no seam.
- **The `db.rs` heal guard is still open, and the risk is now live on macOS.** Plan 1 D12 put it out of scope, because the instructions did not include it. This is recommendation 6 of [application-state-1](application-state-1.md) and 5 of [application-state-4](application-state-4.md), come up a third time: a second heal can now delete the file that holds a macOS user's windows.
- **`LEGACY_DB_NAMES` at `crates/wolf-core/src/db.rs:33` still names `Table::open`.** This is the one item of [application-state-4](application-state-4.md) recommendation 6 that plan 1 did not pick up, and it landed again.
- **Three READMEs sit at or past their size limits.** `crates/wolf-macos/Sources/WolfMacOS/README.md` is 49,996 bytes against the 50,000-byte warning, and its `WolfWindowController.swift` entry is at 250 words, which is why the minimize edges plan 1 §7 asked for are not there (review 1 §5b). `crates/wolf-core/tests/README.md` (65,118 bytes) and `crates/wolf-macos/Sources/WolfKeyMap/README.md` (53,119) are still over it. This is recommendation 5 of [titlebar-colours-2](titlebar-colours-2.md), come up again; it cost this task nothing.

## Recommendations

1. **Check crate-relative file paths in comments.** In `tools/doc-lint`, resolve a code span in a Rust or Swift comment that looks like `tests/<name>.rs` or `src/<name>.rs` against the crate root, and fail when the file is missing. It would have failed `implementation-1` on the eight `tests/state.rs` references. This widens recommendation 4 of [application-state-2](application-state-2.md), which asked the same for Markdown code spans, and the deleted-file sweep of [application-state-3](application-state-3.md) recommendation 5, both come up again.
2. **Move the seed construction into a seam.** Put the part of `AppDelegate.assembleWindows` that turns `WindowStateCodec.LoadedWindow`s and the materialized positions into `[StackingOrder.SeedWindow]` and selected indices into a pure function in `crates/wolf-macos/Sources/WolfKeyMap/Persistence/`. `WindowStateRoundTripTests.swift` would then call it rather than mirror it, closing review 1 §3's untested `selected` index.
3. **Put the heal guard into the next task's instructions.** This is recommendation 6 of [application-state-1](application-state-1.md), come up a third time and now urgent, since macOS writes a user's windows to `wolf.sqlite`. Whoever writes the GNOME switch's instructions should include it.
4. **Fix the drift this task left.** Make `crates/wolf-ffi/tests/file_actions.rs`, `multi_window.rs` and `recent_dirs.rs` name `tests/app_state.rs` where the precedent holds, and drop `multi_window.rs:24`'s coverage claim, as review 1 §5a says. Make `crates/wolf-core/src/db.rs:33` name `Table::open_all`.
