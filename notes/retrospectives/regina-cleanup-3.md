## Recommendations

1. **Gate the regina harness.** This is [regina-cleanup-1](regina-cleanup-1.md) recommendation 2 and [regina-cleanup-2](regina-cleanup-2.md) recommendation 2, and it came up again. A `gates.sh` step running `prettier --ignore-path /dev/null --check` and `markdown_check.sh` on `.claude/` would have replaced V10, V11 and the architect's scratch checks, and would fail on `coder.md:84` and `:104` until someone splits them.
2. **Check the shared worker sections in that step.** Add a script under `tools/lint/` that extracts `## In a regina worker`, `## The project` and the zsh paragraph from each file in `.claude/skills/regina/agents/` and fails when the copies differ from the two versions the regina README names. It would replace the hash comparison three agents ran in this task and two in each earlier cleanup task, and the README could then drop "Nothing checks that here".
3. **Mend review 1's two notes.** In `coder.md:108`, write "never excuses leaving it out". In the source-route paragraph of each definition, say that the walk uses macOS `ps -o comm=` and give the Linux form, `ps -o args=` or `/proc/<pid>/exe`, should an agent ever run on the Linux worker.
4. **Measure the new test-writer rules on their first use.** The retrospective of the first task after the merge whose test writer runs should say whether it ran base-code tests or probes under "What you may run", what they cost, and whether a `rejected` on an unpredicted outcome saved or added a round. This sits beside [regina-cleanup-1](regina-cleanup-1.md) recommendation 6 and [regina-cleanup-2](regina-cleanup-2.md) recommendation 7, which ask the same of the notes pass and the architect's Linux probes.
