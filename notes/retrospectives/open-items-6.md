# Retrospective: exclude `.git` and `.wolf` from project search, hide vanished folders in Open Recent, and name the terminal pane in its status bar

Last verified at commit `b9091392b5fb4b5d09ab9a8d9881dd785e6da858`.

The task ran in one pass, with no rework. Plan 1 was followed by the test writer, the coder and the technical writer. Both gates passed on their first run on both workers, and review 1 approved the work with minor notes. The five invocations cost $12.85 and about 35 minutes: `architect-1` $4.46 (70 turns, 11 minutes), `test-writer-1` $1.78, `coder-1` $2.08, `technical-writer-1` $2.10 and `reviewer-1` $2.43.

## What went well

- **Every new case fit an existing file of an existing target.** The search case went into `crates/wolf-core/tests/search.rs`, the terminal rows into `pane_status_unit.rs`, and the drawer and delete-and-recreate cases into `crates/wolf-ffi/tests/pane_status.rs` and `recent_dirs.rs`. Plan 1 §6 needed no `BUILD.bazel` change, and review 1 confirmed each new test name ran on macOS and on Linux.
- **The shared search helpers made the `.git` test cheap.** `rg_bin_or_skip`, `temp_cwd`, `start_core_in`, `run_search` and `rel_paths` in `search.rs` let plan 1 specify `git_and_wolf_dirs_are_excluded` in a few lines, and `test-writer-1` wrote it in one pass. The Linux dev shell exports `WOLF_RG_BIN`, so the test runs against a real `rg` on both workers rather than skipping.
- **One shared constant now joins the picker walk and the content search.** The coder moved `.git` and `.wolf` into `EXCLUDED_DIR_NAMES` in `crates/wolf-core/src/files.rs`, and `search.rs` reads it. The existing `.git`/`.wolf` assertions in `file_search.rs` guarded that refactor at no extra cost.
- **Checks on the Linux worker caught formatting before the gate.** `coder-1` ran `cargo fmt --check` and `clippy` on the Linux worker before `./gates.sh`, and the check reported a diff in `crates/wolf-core/src/pane_status.rs`. The coder fixed it by hand, so the gate passed on its first run.
- **The ffi drawer test measured its own premise.** Setting `SHELL=/bin/sh` made the expected name fixed. The falsifier printed a `display_path` of `term://~/…//30320:/bin/sh`, which also confirmed that Neovim names the drawer buffer after `$SHELL`.

## What did not go well

- **A core change forced prose edits in two other crates.** Of 22 files changed, 9 were outside `wolf-core` and changed no behaviour: `palette.rs`, `pane_view.rs`, `smoke_headless.rs`, both wolf-gnome READMEs and `notes/wolf-gnome-decisions.md`, plus `wolf-ffi`'s `lib.rs` and `src/README.md`. Each restated how core behaves: that the recent-dirs store is never pruned, or that the drawer shows the raw `term://…//<pid>:…` name. Finding them took about 15 of `architect-1`'s 69 tool calls, most of why it was the costliest invocation.
- **Even so, one stale sentence landed.** `crates/wolf-gnome/tests/smoke_headless.rs` line 31432 says `wolf_core::redraw`'s `TERMINAL_BUFFER_PREFIX` "is private", and this task made it `pub(crate)`. Plan 1 listed three passages in that file by approximate line (186, 30644, 32990) and missed this one. `coder-1` and `technical-writer-1` flagged it, but the file is the test writer's, whose turn was over, and in 37,508 lines every agent navigated by `sed -n` at line numbers.
- **`wolf-ffi` describes each status field twice.** `FfiPaneStatus::filename` and `display_path` carry a `//` comment in the bridge block and a `///` doc on the impl, and `recent_dirs` has both as well. Plan 1 §3 had the coder edit both copies, and `crates/wolf-ffi/src/README.md` a third. Each copy restates the rules that `crates/wolf-core/src/pane_status.rs` and `api.rs` own.
- **`:rustfmt.fix` rewrote the doc-lint fixtures again.** `test-writer-1` ran `bazel run //tools/lint:rustfmt.fix`, the only `rustfmt` on the macOS worker. It rewrote `blocks.rs`, `lexing.rs` and `limits.rs` under `tools/doc-lint/tests/fixtures/lang/rust/`, exited 1 on `E0753` parse errors, and the agent restored the three files from `HEAD`. This came up again: it is recommendation 4 of [open-items-1](open-items-1.md), and `tools/lint/README.md` still does not mention the hazard, so `coder-1` avoided the target and formatted by hand from the Linux diff.
- **The ledger needed parsers again.** `technical-writer-1` edited three rows of `notes/macos-followups.md` with Python scripts and `awk -F' \\| '` to pull out cells. `reviewer-1` wrote its own Python diff against `c7c243e` to prove that only lines 35, 36 and 61 changed. This came up again: it is recommendation 2 of [open-items-2](open-items-2.md), also repeated in [open-items-3](open-items-3.md) and [open-items-4](open-items-4.md).
- **Two small doc defects and a weak fixture landed, as review 1 notes.** The `WolfCore::display_path` doc in `crates/wolf-core/src/api.rs` says that every terminal buffer name yields `""`, but `term://` with no command word falls through and is shown raw. The `term_scheme_inside_a_path_is_not_a_terminal` fixture in `pane_status_unit.rs` has no `//<digits>:`, so it does not isolate the prefix rule its name claims: `coder-1` replaced `strip_prefix` with a search anywhere, and the test plan 1 §3 specified stayed green.
- **Plan 1's reason for the glob order was wrong.** Plan 1 said the exclusion globs must follow the include globs because a later `rg` glob wins. `coder-1` built an `rg` fixture and found that either order gives the same result, because `!.git` prunes the directory. It cost a few commands, and nothing in the repository invited the guess.

## Recommendations

1. **Stop wolf-gnome's docs from restating core's behaviour.** This came up again, for `wolf-core`: it is recommendation 1 of [open-items-4](open-items-4.md) and 4 of [open-items-5](open-items-5.md). In `crates/wolf-gnome/src/palette.rs`'s `open_recent_candidates` docs, link `WolfCore::recent_dirs` rather than describe what it keeps. In `pane_view.rs`'s `refresh_pane_state` doc and `smoke_headless.rs` (from line 31432), name `wolf_core::pane_status` rather than describe its string or `TERMINAL_BUFFER_PREFIX`, which saves about four files and `architect-1`'s search.
2. **Make `wolf-ffi`'s status docs point at core.** In `crates/wolf-ffi/src/lib.rs`, cut the bridge `//` comments on `FfiPaneStatus::filename`, `display_path` and `recent_dirs` to a short line that names the `wolf_core` item. Have the `///` docs link `wolf_core::pane_status::PaneStatus` and `WolfCore::recent_dirs` rather than list their cases. Plan 1 §3 had the coder edit two copies in `lib.rs` and the technical writer a third in `crates/wolf-ffi/src/README.md`, all restating rules that `pane_status.rs` and `api.rs` own.
3. **Keep `:rustfmt.fix` away from the doc-lint fixtures.** This came up again: it is recommendation 4 of [open-items-1](open-items-1.md), unchanged. `test-writer-1` lost the same commands to it, and `coder-1` avoided it and hand-formatted. Until the formatter excludes `tools/doc-lint/tests/fixtures/`, every Rust edit on the macOS worker either cleans up after `:rustfmt.fix` or waits for a Linux `cargo fmt` diff.
4. **Change the ledger's format when it is pruned.** This came up again: it is recommendation 2 of [open-items-2](open-items-2.md), now seen in a fourth task. Here the reviewer wrote a parser as well as the technical writer.
5. **Correct the two doc defects and the fixture that review 1 left.** In `crates/wolf-core/src/api.rs`, narrow the `display_path` doc to "a terminal buffer name with a command". In `crates/wolf-core/tests/pane_status_unit.rs`, give `term_scheme_inside_a_path_is_not_a_terminal` a fixture that holds a pid separator, such as `/home/u/proj/term://x//1:sh`, so that only the prefix rule rejects it. Fix `smoke_headless.rs` line 31432 as part of recommendation 1.
