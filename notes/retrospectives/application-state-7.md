# macOS saves and restores the per-tab and per-pane extras

Last verified at commit `04cfdd6f967b9400a3a73684c36128057764493d`.

The task made macOS write and read every extra of `specs/application-state.md` §2: a tab's `focused`, `sidebar` and `drawer`, an edit pane's `cursor` and `top_line`, and a preview's `scroll`, captured at §4's moments. It added `WolfCore::window_cursor`, a `focused` mark in the rebuild document, and the Swift model, codec, capture and restore. The eight invocations cost $40.76. There was one round trip, `coder-1`'s `rejected` over an existing test, and every gate run passed on both workers on its first try.

## What went well

- **The earlier tasks had built the whole wire surface.** Plan 1 §1 found that the wolf-ffi builder and readers already carried every extra, and that `wolf_rebuild_layout` in `runtime/nvim/init.lua` already clamped and applied a saved cursor. The change added one FFI type, `FfiWindowCursor`, and review 1 §1 found no discriminant table changed. The task's work was the Swift side and one core read, not a format change.
- **The `WolfKeyMap` seams gave every pure rule a home in an existing test file.** `SessionSeam`, `WindowStateCodec`, `PreviewScrollSeam` and `DrawerLayout` took S1 to S9 in files `WolfKeyMapTests` already lists, so only the two new `WolfMacOSTests` files needed wiring. Plan 1 §3 named both `srcs` edits, and review 1 §3 found every test wired.
- **The entry budgets were planned before they were spent.** Plan 1 §6 named the entries at 246 to 250 words and told the writer to run `./tools/lint/markdown_check.sh --entry-words` before and after. `technical-writer-1` used the flag and ended every touched entry within 250 words, and `documentation-1` passed on both workers. Neither the architect's nor the writer's definition names the flag, so this came from `architect-1` alone.
- **One XCTest method can run alone.** `coder-2` took 50 falsifier reds, each one build of one `--test_filter=<Class>/<method>`, for $2.63. That makes a 50-row falsifier table affordable, though `build.md` still does not name the flag (see Recommendations).

## What did not go well

- **An existing test pinned the number of places that clear a flag, and nothing pointed the plan at it.** `testStateScriptJSInPlaceUpdateDoesNotClearTheUserScrollFlag` in `crates/wolf-macos/Tests/WolfKeyMapTests/PreviewScrollSeamTests.swift` asserted exactly two `__wolfUserScrolled = false` assignments. Plan 1 D4's new `__wolfScrollFraction` adds a third, as it must, so `coder-1` got "3 is not equal to 2" and returned `rejected`.
- **Neither the architect nor the test writer looked for it.** `architect-1` read `PreviewScrollSeam.swift` lines 600 to 850, but never searched the test directories for `__wolfUserScrolled`. `test-writer-1` added S6 to S8 to the same 2,600-line file and did not see the test either.
- **That round trip cost about $2.03 and two invocations.** `architect-2` ($1.49) wrote plan 2, and `test-writer-2` ($0.54) rewrote the test to count three sites and find each clear inside its function's body. `coder-1` stopped before its falsifiers, so `coder-2` ($2.63) started cold. Most of `coder-2`'s work, the 50 reds and both gates, was owed anyway.
- **The source still names only one clear site.** The `stateScriptJS` doc at `crates/wolf-macos/Sources/WolfKeyMap/PreviewScrollSeam.swift:606` and the `restoreJS` doc at `:826` say `__wolfRestore` clears the flag, and neither names `__wolfScrollFraction` or the test that pins the clears. Review 1 §5 and `technical-writer-1` both noted this, and it landed, so the next plan that reads only this doc is misled the same way. `crates/wolf-macos/Tests/WolfKeyMapTests/README.md` names the three sites at `04cfdd6`, but at the base commit it did not mention the flag.
- **A falsifier written as an addition stayed green.** Plan 1 worded M7a as "applies the pane zoom at once despite the open drawer". Added that way, the deferred path still re-zoomed, so M7 passed. `coder-2` had to make up a replacing edit, `pendingDrawerRestore = (nil, focus)` with the zoom applied at once, which review 1 §4 accepted, at the cost of one more build.
- **`crates/wolf-macos/Sources/WolfMacOS/README.md` crossed the 50,000-byte warning.** It went from 49,996 to 50,576 bytes. [application-state-5](application-state-5.md) recorded it at 49,996, and this task's additions to the `PaneContainerView`, `MainWindow` and `WolfWindowController` entries went over. `technical-writer-1` ran 113 turns ($7.54), paying for most additions with cuts in the same entry.
- **A false doc comment stays out of scope.** `SearchView.seedToggles()` at `crates/wolf-macos/Sources/WolfMacOS/SearchView.swift:133` says it is one-shot, but `MainWindow.sidebarPanelsToolbarAction` calls it on every switch to search. So a restored search sidebar's toggles are replaced when the user picks the toolbar's search segment. Plan 2 E3 kept the fix out of scope, and `notes/wolf-macos-decisions.md` records the limitation.

## Recommendations

1. **Have the architect search the tests for each identifier a decision changes.** In `.claude/skills/regina/agents/architect.md`, say that a decision changing a function, script or constant lists every test that names it, found by searching `crates/*/tests/` and `crates/wolf-macos/Tests/` for its identifier, and says what each test must come to assert. A search for `__wolfUserScrolled` would have put S10 into plan 1 and saved `architect-2`, `test-writer-2` and the cold start of `coder-2`.
2. **Name the clear sites and their guard in `PreviewScrollSeam.swift`.** Rewrite the `stateScriptJS` doc at `:606` and the `restoreJS` doc at `:826` to say that each function whose JavaScript re-applies late, `__wolfRestore` and `__wolfScrollFraction`, clears `__wolfUserScrolled` first. Name `testStateScriptJSInPlaceUpdateDoesNotClearTheUserScrollFlag` as the test that pins where each clear sits. `architect-1` read this doc and not the test, so naming the test there would have shown it the guard.
3. **Word a falsifier as the edit that turns the guarded mechanism off.** In the falsifier item of `.claude/skills/regina/agents/architect.md`, say that an edit replaces or removes the mechanism the test guards, and that an added extra path usually leaves the original one working. M7a's wording cost `coder-2` a green run and a made-up edit.
4. **Split `crates/wolf-macos/Sources/WolfMacOS/README.md`.** This is recommendation 3 of [ghostty-3](ghostty-3.md) and 4 of [round-3-7](round-3-7.md), come up again, and the file is now over the warning. Moving the persistence glue or the pane views into a subdirectory with its own README, as `Preview/` already is, would give the next writer room.
5. **Name `--test_filter=<Class>/<method>` in `build.md`.** This is recommendation 2 of [nerd-font-2](nerd-font-2.md), 3 of [fixes-1](fixes-1.md) and 5 of [open-items-11](open-items-11.md), come up again. `coder-2` searched for how to run one method before it ran its 50 reds.
