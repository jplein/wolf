# Retrospective: verify the no-code macOS ledger rows, measure lint cost and three time budgets

Last verified at commit `62dccfa874fadd381a42fd743af267fc3daf1d86`.

The task closed 19 rows of `notes/macos-followups.md` by verification only. It measured how much the `//tools/lint` checks add to `bazel test //...` and timed three test targets against their budgets. It also fixed one false Swift doc comment and set the placeholder header of `notes/.bazelrc.md`.

Everything went through the flow once, with no rework: `architect-1`, `coder-1`, the implementation gate at exit 0 on both workers, `technical-writer-1`, the documentation gate at exit 0 on both workers, and `reviewer-1`, which approved. The four invocations cost about $9.34. `architect-1` was the largest at $4.20 (65 turns, 708 s), then `reviewer-1` at $1.95, `technical-writer-1` at $1.69 and `coder-1` at $1.50.

## What went well

- One Bazel target per test file made each measurement a single command. `coder-1` ran each of `//crates/wolf-core:nav_history_live`, `//crates/wolf-core:nvim_restart` and `//crates/wolf-ffi:history` alone three times, and each `history` test alone with `--test_arg=--exact`. It ran the swap falsifier against one test of `//crates/wolf-core:swap_recovery`. All of that, plus four full `bazel test` runs and the gate, fit in one 510 s invocation.
- The lint checks are all in one package, so the clippy question was cheap. Clippy runs only as the build actions of the three `rust_clippy` targets in `tools/lint/BUILD.bazel`, and `.bazelrc` attaches no aspect. So `-//tools/lint/...` removes all lint work. Plan 1 settled this by reading, and `coder-1` confirmed it with one `grep`.
- `doc-lint same-code` gave a mechanical proof that the `PickerSeam.swift` edit only touched a comment. `coder-1` ran it once, exit 0, and `review-1` accepted it without rereading the Swift.
- The architect read the code first, and that saved the coder from a falsifier that could not fail. The task's example falsifier disabled only `swap_fname_matches` in `runtime/nvim/init.lua`. Plan 1 §2.9 predicted that the exact-`.swp` criterion alone still finds the test's swap, and planned a fallback edit. `coder-1` saw the first edit pass and the second fail, as predicted, with no return to the architect.
- `regina on linux` gave the macOS coder the Linux doc-lint run it needed for the new `doc-ref` anchor (`coder-1`).

## What did not go well

No step was redone: no rejection, no failed gate, no discrepancy. These things cost effort or left a defect behind.

- **`build.md` misled the task text and the plan about where the bundle is.** Before this task, "The optimized build" said `bazel-bin` is wrong only for `:WolfRelease`. So the instructions and plan 1 §4 step 9 both looked for `Wolf.app/…/init.lua` under `bazel-bin`, where `coder-1` found no bundle and needed a `bazel cquery` to find `Wolf.zip` under a transitioned `-fastbuild-macos-` directory. `technical-writer-1` fixed `build.md` in commit `62dccfa`.
- **The same wrong claim is still in code.** The docstring in `crates/wolf-macos/release.bzl` (around line 41) says `bazel-bin/crates/wolf-macos/Wolf_archive-root/Wolf.app` may be a stale fastbuild bundle, where on the measured layout it is always absent. The technical writer may not edit a `.bzl` file, and the task allowed only one code-comment fix, so `review-1` left it for a later coder. `.claude/verify-results.md` (lines 29 and 33) gives the same wrong path.
- **Three agents checked the same facts.** `git diff 5d9d257 HEAD -- .bazelrc` ran in `architect-1`, `technical-writer-1` and `reviewer-1`. The `:Wolf` output path was checked by `coder-1`, by `technical-writer-1` (three `cquery` calls) and by `reviewer-1`. The writer and the reviewer both re-read the plan §2 code citations (`sidebarVisible`, `composedLine`, `ToastView.scrollBy`, `isEmptyLeaf`). Re-checking is the reviewer's job, and nothing in the repository asked the writer to repeat it, so this is a flow matter with no recommendation here.
- **Every agent that touched the ledger had to write its own parser for it.** `notes/macos-followups.md` was 101,936 bytes, one table row per line, with cells several hundred characters long. `architect-1` spent seven `awk`/`sed` calls just reading rows by line number. `technical-writer-1` wrote a Python script to rewrite the 19 cells, and `reviewer-1` wrote more to compare them cell by cell. The file is still 91,800 bytes and still triggers the `big-file` warning.
- **The all-caps rule forced a change to a quoted failure.** The verbatim test failure contains `ATTENTION`, Neovim's swap dialog. `tools/lint/markdown_check.sh` flagged row 20 with `allcaps`, so `technical-writer-1` put that one word in backticks and ran the checks again. `review-1` noted that the ledger quote no longer matches the output.
- **The `notes-header` rule accepted a placeholder.** `notes/.bazelrc.md` had carried `Last verified at commit` followed by 40 zeros since commit `b8ca389`. The rule in `tools/lint/README.md` checks only that the value is 40 hex digits. Fixing it took a task step and a precondition that the architect had to reason about (plan 1 §2.1).
- **A gap in test coverage came to light.** No test fails when only the owner-path scan in `_G.wolf_untitled_swap_exists` (`swap_fname_matches`) is disabled. The `coder-1` falsifier's first edit passed. That scan is the fix the ledger row 2026-08-01 "`runtime/nvim/init.lua`: `_G.wolf_untitled_swap_exists` fixed" names (`review-1` §3).
- **A divergence was recorded, but nothing tracks it.** On macOS, a tab saved in the empty state persists `sidebar_visible = false` whatever the user chose, and Linux reads that back as the user's preference (plan 1 §2.6). It is recorded only in a row now marked `Verified`, and the last task of the request prunes the ledger.

## Recommendations

1. **Correct the `bazel-bin` clause in `crates/wolf-macos/release.bzl`.** Cut its clause `or, far worse, a STALE fastbuild -Onone bundle`, so the docstring says what `build.md` now says. That is the only `bazel-bin/crates/wolf-macos` path left in project files. Its predecessor in `build.md` sent the instructions and plan 1 to the wrong directory, which cost `coder-1` a `cquery` and `technical-writer-1` three more.
2. **Change the ledger's format when it is pruned.** Give each open row of `notes/macos-followups.md` its own `###` heading with short fields, in place of one long table line. Then `Read` and `Grep` work on it without a parser. All three agents in this task wrote their own parsers, and the file is still almost twice the `big-file` limit.
3. **Make `notes-header` reject a placeholder SHA.** In doc-lint or `tools/lint/markdown_check.sh`, flag 40 zeros, and ideally any SHA that `git cat-file -e` does not resolve. Add a fixture under `tools/lint/testdata/notes/`. `notes/.bazelrc.md` passed every gate with a placeholder from `b8ca389` until this task fixed it by hand.
4. **Exempt quoted tool output from `allcaps`, or document the workaround.** Either have `tools/lint/README.md` say that quoted output goes in a code span, or exempt blockquotes from `allcaps`. `technical-writer-1` changed a verbatim failure to get past the rule.
5. **Add a test that only the owner-path scan can pass.** In `crates/wolf-core/tests/swap_recovery.rs`, use a stale swap whose name the exact-`.swp` criterion does not produce, so that only `swap_fname_matches` can find it. Today, the `home_replace` comparison that the 2026-08-01 fix added can break without any test failing (`coder-1` falsifier, edit 1).
6. **Track the sidebar divergence somewhere that survives the prune.** Before the last task of this request prunes `notes/macos-followups.md`, give the macOS-versus-Linux `sidebar_visible` difference its own `Open` row or a section in `notes/wolf-macos-decisions.md`. Otherwise it is deleted together with the row 2026-08-04 `linux-feat/nav-history`.
