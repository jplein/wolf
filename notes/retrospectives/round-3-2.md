# Retrospective: the wolf-gnome wording lint and the Linux rustdoc link gate

Last verified at commit `1cb8eeb521f154d925a39b3cef19ef0a9af0740d`.

The task carried out recommendations 1, 4 and 5 of [retro-fixes-5](retro-fixes-5.md). It added `tools/lint/wolf_gnome_wording_check.sh` with its allowlist, test and fixtures, wired as `//tools/lint:wolf_gnome_wording` and `:wolf_gnome_wording_check_test` on macOS and as two Linux `run` lines in `gates.sh`. It fixed the broken intra-doc links in wolf-gnome, wolf-ffi and wolf-core, then added the Linux gate `rustdoc-links`. The change is `3b8f982` (coder, with the test writer's files) and `1cb8eeb` (technical writer); the three earlier commits in the range are round-3-1's.

It took one round: no rejection, no failed gate, no discrepancy, nothing resumed. Both gates passed on both workers on their first run, and review 1 approved with minor notes. The five invocations cost about $9.86: `architect-1` $3.23 (38 turns, 10.8 minutes), `test-writer-1` $0.94 (13 turns, 3.3 minutes), `coder-1` $2.01 (40 turns, 12.5 minutes), `technical-writer-1` $1.44 (29 turns, 3.3 minutes) and `reviewer-1` $2.25 (34 turns, 6.5 minutes).

## What went well

- **`wolf_core_deps_check.sh` and its test were a template to copy.** Plan 1 named them for the helper set, the `|| rc=$?` handling of grep's exit 1 and the empty-listing rule. `test-writer-1` wrote 11 cases in that shape without running anything, and `coder-1`'s first checker passed all of them. Its 14 falsifying edits each failed the case they aimed at.
- **The instructions' sites were exact enough to check against.** The task named A1 to A7 and the identifier, and plan 1 listed the 16 lines they make at the base. `coder-1` generated the allowlist from the checker's own output against an empty list, and the count matched, so no site was retyped by hand. This is the "plan by rule and check" that recommendation 3 of [retro-fixes-5](retro-fixes-5.md) asked for.
- **`regina on linux` carried every Linux-only step.** `coder-1`'s nine commands listed the rustdoc errors, ran both gate falsifiers, ran `./gates.sh` twice and measured the new gate's cost. The Linux gate then passed first time with all three new steps.
- **doc-lint's `same-code` proved the Rust edits comment-only.** `coder-1` ran it on all 13 changed `.rs` files, plus a one-token code change as a control, and review 1 relied on it instead of reading each diff.
- **The root `BUILD.bazel` already globbed into wolf-gnome.** `comment_srcs` and `markdown_srcs` were the precedent for the `//:wolf_gnome_srcs` filegroup, which brings the sources to a Bazel test without making wolf-gnome a Rust target. `coder-1`'s Bazel run scanned the same 54 files as the checkout.

## What did not go well

- **The architect could not measure what it was planning to fix.** `architect-1` has no `cargo` and, unlike the coder and the test writer, no `regina on linux`; it looked for the command, then spent six calls reading `crates/wolf-ffi/src/lib.rs` links with `grep` and `awk`. Plan 1 then said "this plan names no wolf-ffi line because none was measured". `coder-1`'s first two Linux commands found six more errors in wolf-core that neither retro-fixes-5 nor the plan listed, which the plan's "the run is the list" absorbed with no rework.
- **This is the second task running where the architect planned blind.** In [round-3-1](round-3-1.md) the cold output root kept `architect-1` from reading the `rules_rust` source, and a plan sentence was wrong as a result. Here the architect was the most expensive invocation, at a third of the task's cost.
- **Two of plan 1's falsifiers could not fail as written.** Dropping `-i` does not lose the lowercase `DrawerLayout.swift` line, which `test-writer-1` and `coder-1` both noticed. Removing the no-`.rs` guard alone still exits 2 because grep then fails on the directory, so `coder-1` used a well-formed variant. Neither cost a round, and nothing in the repository invited them.
- **The docs say every allowlist entry links its counterpart, and two do not.** `tools/lint/README.md:120`, `notes/wolf-gnome-decisions.md:49` and the allowlist's header comment all say so. The two `mouse.rs` identifier lines link no macOS README entry: they cite `crates/wolf-ffi/tests/mouse_scroll.rs` (review 1 §5). A later agent may take the identifier as a model and admit an entry that links nothing.
- **`notes/gates.sh.md:43` states more than was measured.** It says `rustdoc-links` "compiles nothing after `clippy`", but `coder-1`'s runs changed only wolf-gnome, a leaf crate. Review 1 §5 doubts it holds after a wolf-core edit, because clippy's artifacts may not serve rustdoc, and gave a command to settle it.
- **The allowlist's link points at the wrong heading, and no agent could fix it.** Its header links `tools/lint/README.md#files`, because the coder writes it before the technical writer adds `#what-wolf_gnome_wording-checks` and doc-lint checks the anchor at the implementation gate. `coder-1`, `technical-writer-1` and `reviewer-1` each wrote a sentence about it, and none owned the file afterwards. The same ordering was planned around in [open-items-8](open-items-8.md), [retro-fixes-4](retro-fixes-4.md) and [round-3-1](round-3-1.md).
- **Review 1 §3 found three cases the test lacks.** Nothing tells `grep -qxF` from a substring match, so a `grep -qF` checker passes all 11 cases and would excuse a prefix of an entry. No fixture has a nested `src/<dir>/*.rs`, and no case trims trailing whitespace.
- **The zsh `echo` warning is still restated by hand.** Plan 1's checker contract had to say that zsh's builtin `echo` turns `\b` into a backspace. This came up again: it is recommendation 2 of [retro-fixes-5](retro-fixes-5.md), and the six definitions under `.claude/skills/regina/agents/` still warn only about `=`.

## Recommendations

1. **Give the architect `regina on linux`.** Grant it the command the coder and test writer have, and add the `regina on linux` paragraph to `.claude/skills/regina/agents/architect.md`. `architect-1` could then have run the one `cargo doc` command that `coder-1` ran first, and plan 1 would have listed wolf-core's six errors and wolf-ffi's lines instead of guessing at them with `awk`.
2. **Make the docs name the identifier as the one exception.** In `tools/lint/README.md:120` and `notes/wolf-gnome-decisions.md:49`, say that A1 to A7 link their counterpart and that `scroll_direction_is_inverted_from_macos` is admitted as a name, not a divergence. In the allowlist's header, change "Each names its macOS counterpart" to match, and point its link at `tools/lint/README.md#what-wolf_gnome_wording-checks`. Three agents of this task noted the link and could not change it.
3. **Settle or narrow the `rustdoc-links` cost sentence.** Run review 1 §7's command, which touches `crates/wolf-core/src/lib.rs` and greps the gate's log for `Checking` lines, and record the result in `notes/gates.sh.md:43`. If it cannot be run, limit the sentence to "with no workspace crate changed since `clippy`".
4. **Add the three missing checker cases.** In `tools/lint/wolf_gnome_wording_check_test.sh`, add a fixture whose tree holds only a prefix of an allowlisted line, one with a nested `src/<dir>/*.rs`, and one with trailing whitespace on an allowlisted line. Each closes a falsifier review 1 §3 showed would pass all 11 cases today.
5. **Add the zsh `echo` warning to the definitions.** This came up again: it is recommendation 2 of [retro-fixes-5](retro-fixes-5.md), and plan 1 restated it in the checker contract.
