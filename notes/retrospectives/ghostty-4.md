# GTK terminal panes over core sessions (g03 of the libghostty-vt series)

Last verified at commit `4fc5d9a39e23cee5477fa295fb84f4fd30d57fe7`.

The task was g03: `crates/wolf-gnome/src/terminal/` (style, damage, geometry, input seams and a Cairo canvas), and the glue in `pane_view.rs`, `window.rs`, `shell.rs` and five other files that paints a session and routes keys, commits, pointer, scroll, sizing, focus, copy and paste to it. It added `tests/terminal_seams.rs`, `tests/terminal_paint.rs` and one cage smoke. It took five invocations and about $34.53 and 75 minutes, and review 1 approved with minor notes.

There was no round trip. Each agent ran once, and both gates passed on both workers on their first run. The costs were `architect-1` $8.59 (84 turns), `test-writer-1` $8.02 (93), `coder-1` $8.75 (102), `technical-writer-1` $4.85 (87) and `reviewer-1` $4.31 (55).

## What went well

- **g02's macOS seams were a template the plan could copy file by file.** `architect-1` read the four `WolfKeyMap` `Terminal*` files and `TerminalPaneView.swift` in two commands, and plan 1 mapped each to one file of `src/terminal/`. `technical-writer-1` linked every entry of the new README to its counterpart and named each divergence. Keep the two front-ends' seams parallel in name and split.
- **`specs/terminal-panes.md` named g03's scope in one sentence.** Review 1 §1 checked delivery against "the same for `wolf-gnome` … including `im_commit`" and found nothing missing. No agent asked what was in scope.
- **Pure seams made 34 falsifiers mechanical.** Each rule of `style.rs`, `damage.rs`, `geometry.rs` and `input.rs` is a function of its arguments, so `coder-1` scripted every falsifier as an edit, one `cargo test --exact` on the Linux worker, and a checksummed restore. Review 1 §4 matched each one with nothing missing. This came up before, in [round-3-11](round-3-11.md) and [ghostty-3](ghostty-3.md).
- **The new files got a directory and a README of their own.** `src/terminal/README.md` is 6,463 bytes, while `src/README.md` is 85,910. The next agent to change the canvas reads the small one. This is the shape recommendation 3 of [ghostty-3](ghostty-3.md) asks for on macOS.
- **The wording lint runs standalone on macOS.** `coder-1` ran `./tools/lint/wolf_gnome_wording_check.sh` locally before either gate, so plan 1's D13 was checked without the Linux worker.
- **`regina on linux` let the test writer typecheck against an API that did not exist yet.** One command of `test-writer-1` wrote `todo!()` stubs with plan 1 §2's signatures inside the remote snapshot, ran `clippy` on the two new test files, and removed the stubs. The coder then received tests that failed only on the missing API.

## What did not go well

- **Formatting wolf-gnome from the macOS worker is done by hand.** wolf-gnome has no Bazel targets, so `//tools/lint:rustfmt.fix` cannot reach it. `test-writer-1` looked for a `rustfmt` binary under the Bazel output base, then applied `cargo fmt --check`'s hunks with a Python replace script (its commands 73 to 78). `coder-1` ran `cargo fmt` on the Linux worker and copied six files back through a scratch directory (its command 71).
- **`smoke_headless.rs` is 38,343 lines, and one smoke touched it in 19 hunks.** `test-writer-1` spent about 20 commands finding the smoke conventions, constants and registries in it. Recommendation 5 of [round-3-11](round-3-11.md) and 2 of [ghostty-1](ghostty-1.md), to split it by feature, came up again.
- **The smoke count is written out by hand in about 15 places.** Adding one smoke meant changing "sixty-two", "thirty-eight", "seven" and `76 passed` through the module doc of `smoke_headless.rs` and in `crates/wolf-gnome/tests/README.md`. One sentence, that the vertical-split smoke was "the only pixel reading here taken outside a preview or an overlay", went false and had to be rewritten. Recommendation 7 of [round-3-11](round-3-11.md), to drop hand-kept counts, came up again.
- **The word budget sent the writer to count words again.** Several `src/README.md` entries were at 243 to 250 of 250 words. `technical-writer-1` ran the checker on the base file and wrote a Python word counter (its commands 70 and 71), then cut two bullets and linked the decisions note instead. This is recommendation 3 of [open-items-12](open-items-12.md), come up a fifth time.
- **The wolf-gnome documents grew past the size warning again, and the decisions note is no longer re-verified.** `src/README.md` went to 85,910 bytes, `tests/README.md` to 94,173 and `notes/wolf-gnome-decisions.md` to 96,325. `technical-writer-1` edited sections of the decisions note and `notes/feat-list.md` but did not bump either SHA, since it could not re-check 96 KB. The decisions note's SHA is 122 commits behind `HEAD`.
- **Two of the nine stale doc statements predated this task.** `tests/README.md`'s intro said seam rules live in each seam's `mod tests` "rather than here", while `gdk_key.rs` was already a table file there. The decisions note's Scope said every pixel comes from a `Snapshot`, which previews already contradicted. The coder report says the `mouse.rs` claim of a primary-only gesture was found only by a grep for "primary".
- **The session helpers are a second copy.** Plan 1 §2 asked for `sh_script`, `open_session`, `frame_of`, `frame_text`, `poll_frame`, `wait_for_text` and `POLL_INTERVAL` in `crates/wolf-gnome/tests/common/mod.rs`, mirroring `crates/wolf-core/tests/common/mod.rs`. It cost nothing here, but a change to core's terminal API now edits both.
- **Falsifier runs took most of the coder's time.** `coder-1` ran 34 falsifiers one after another on the Linux worker, at 30 to 40 seconds each including the snapshot, about 20 of its 21 minutes. Nothing in the repository made that avoidable, so no recommendation follows.
- **Review 1 records three issues in the landed work.** The `PS1` pin of `typed_keys_reach_a_terminal_pane_shell_under_cage` has no effect where `/bin/sh` is bash, because `cage` runs the scenario as `sh -c` and a non-interactive bash drops the inherited `PS1`, so `TP_PS1`'s doc is false. The new `src/terminal/README.md` and the decisions note's § Terminal panes both write out the backing-surface and cursor decisions.
- **Core repaints a whole pane on a resize to the same size.** `Session::resize` in `crates/wolf-core/src/terminal/session.rs` marks every row damaged even when the size is unchanged. The GTK sizer resends the size on each wake until the next frame shows it, so each resend repaints the whole pane (review 1 §2).

## Recommendations

1. **Let the macOS worker format wolf-gnome.** In `tools/lint/`, add a script or `bazel run` target that runs the `rules_rust` toolchain's `rustfmt` binary on the files it is given, outside any Bazel target, and list it in `tools/lint/README.md`. Both `test-writer-1` and `coder-1` would have formatted in place instead of applying remote hunks by hand. Failing that, add one line to `build.md` saying that wolf-gnome is formatted on Linux, and how to bring the files back.
2. **Split `smoke_headless.rs` by feature.** This is recommendation 5 of [round-3-11](round-3-11.md), come up again. The terminal smoke's constants, scenario and test would sit in one module, and the next terminal smoke (g04) would not have to search 38,000 lines.
3. **Drop the hand-kept smoke counts.** This is recommendation 7 of [round-3-11](round-3-11.md), come up again. In the module doc of `smoke_headless.rs` and in `crates/wolf-gnome/tests/README.md`, replace "sixty-three", "thirty-nine" and `77 passed` with the rule they describe, or with a guard test that counts the `_under_cage` tests and fails on a mismatch, so a new smoke edits one place.
4. **Let the markdown checker report an entry's word count.** This is recommendation 3 of [open-items-12](open-items-12.md) and 2 of [ghostty-3](ghostty-3.md), come up again. A mode of `tools/lint/markdown_check.sh` that prints each `####` entry's count would have replaced `technical-writer-1`'s counter.
5. **Split `notes/wolf-gnome-decisions.md` so a section can be re-verified.** This is recommendation 6 of [round-3-11](round-3-11.md), come up again, with a new cost: a 96 KB note is edited in sections but never re-checked whole, so its SHA stops meaning anything. Moving § Terminal panes and its siblings into topic files under `notes/`, linked from the decisions note, would let a writer bump the SHA of the file it checked. `CLAUDE.md`'s layout list would need to allow it.
6. **Share the session helpers between wolf-core's and wolf-gnome's tests.** Give the seven helpers one home, for example a small dev-only crate under `crates/` that both `tests/common/mod.rs` files re-export, with a `rust_library` for wolf-core's Bazel tests. g04 and later tasks then change one copy when core's terminal API moves.
7. **Fix the three issues review 1 left.** In `crates/wolf-gnome/tests/smoke_headless.rs`, pass the prompt as `TP_PS1` and `export PS1="$TP_PS1"` inside `TERMPANE_SCENARIO`. In `crates/wolf-gnome/src/terminal/README.md`, cut the `canvas.rs` and `damage.rs` Decisions bullets that `notes/wolf-gnome-decisions.md#terminal-panes` also states, and link it. In `Session::resize`, return early on an unchanged size, which fixes the redundant repaints on both front-ends.
