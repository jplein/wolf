# Retrospective: GNOME wiring of the `wolf` command, the open channel and tab IDs

Last verified at commit `2d7391ff4343030cb5469db8d9f580647f5bc79f`.

The task wired `crates/wolf-gnome` to the core work of `specs/cli-and-file-open.md`: tab IDs, the listener, directory and file requests, the Linux launcher in `crates/wolf-core/src/bin/wolf.rs`, and the package's `bin/wolf` and desktop entry. It took two rounds and 10 invocations, for about $48.97 and 171 agent-minutes. One review rejection caused the rework, and round 2 cost $7.20 over 16 minutes. Every gate run exited 0 on both workers at the first try: both implementation runs and both documentation runs.

## What went well

- **The core's shared rules left GNOME nothing to decide.** `wolf_core::choose_pane` and `wolf_core::project_directory` carry §4 and §5.2. So `crates/wolf-gnome/src/open_request.rs` only maps a route and a leaf index, and plan 1 could say that it ports `FileOpenSeam.swift`. Review 1 §2 found no logic error in it.
- **The pure seam kept reds cheap.** R1 to R6, M1, G1, T1 and Z1 run headless in `tests/open_request.rs` and `tests/pane_zoom.rs`. `coder-1` ran all 18 of those Linux falsifier commands (W1 to Z1) in under two minutes, against more than an hour for the compositor smokes. Keep new routing logic in a GTK-free seam.
- **The Open Folder fixtures carried over.** `test-writer-1` reused `open_folder::LiveWindow` unchanged and made four helpers of `smoke_headless/open_folder.rs` `pub(crate)` (`make_dir`, `canonical`, `edit`, `plant`), so `file_open.rs` added no planting code of its own.
- **Plan 1 §2.8 foresaw that `cargo test -p wolf-gnome` does not rebuild `target/debug/wolf`.** `wolf_command_bin` fails loudly when the binary is missing, and `coder-1` built it in every smoke command. No run used a stale binary.

## What did not go well

- **Review 1 sent the task back on three small gaps.** Round 2 was `architect-2` ($2.37), `test-writer-2` ($0.38), `coder-2` ($0.38), `technical-writer-2` ($1.40) and `reviewer-2` ($2.67), plus a second run of each gate. Not one line of product code changed. Each gap has its own cause, below.
- **An unplanned test assertion had no red, in a sixth task.** `test-writer-1` added check 17 to `every_cage_gets_a_private_runtime_dir_and_no_host_session`, asserting that `cage_command` removes `WOLF_TAB_ID`. It reported the check, but gave it no ID. Plan 1 §3 had invited guard edits ("whatever its source-scanning guards need").
- **That guard checks harness code, so no agent could red the check.** The only falsifier deletes a line in `crates/wolf-gnome/tests/smoke_headless/main.rs`, which a coder may not edit. Plan 2 §2.1 removed the check rather than prove it. Neither the test writer's definition nor the coder's has a rule for a test the plan does not ask for (`test-writer-1` and `coder-1` system prompts).
- **The word budget silently dropped planned documentation (D1).** `technical-writer-1`'s first markdown check put the `layout.rs` entry at 258 words, `pane_zoom.rs` at 263, `coordinator.rs` at 294 and `window.rs` at 315, against 250. To pass, it cut `split_root_left`, `hide_empty_state`, the tab-ID ordering rule and `ZoomEvent::OpenFile`, which plan 1 §5 had asked for. Its report did not say so.
- **The round-2 fix only moved the loss.** `technical-writer-2` fit the D1 items at 249, 249 and 250 words by cutting `PaneTree::neighbor`'s API line and a `FocusMove` sentence, which review 2 §8 note 1 then flagged. `crates/wolf-gnome/src/README.md` is 99,045 bytes and `tests/README.md` is 132,596, both over the 50,000-byte warning.
- **A falsifier row named a function the coder renamed (D2).** Plan 1's W1, W2a and S4a rows name `platform_launcher`, the function at the task's start (`bin/wolf.rs` lines 56 and 61 at `1dae242`). `coder-1` replaced it with a per-platform `launcher`, and the copy in `file_open.rs`'s doc table went stale. Nothing checks such rows, and review 2 §8 note 3 found another misleading row in the same table (S2d). The fix cost $0.38, so nothing is recommended for it.
- **Smoke failures were slow to diagnose on the Linux worker.** `coder-1` ($15.31, 141 turns, 100 minutes) spent about 44 minutes on Linux commands 8 to 22, finding why S2 and S4 failed. Command 9's `ls` of the kept `wolf-smoke-rt-*` directory failed, because it does not outlive a `regina on linux` command. The harness prints only `CAGE_LOG_TAIL_LINES` (80) lines of `cage.log`, so it took temporary `WOLFDBG` traces.
- **Product code is ordered to suit the `cage` harness.** S4 failed in 15 of 20 runs until `coder-1` moved the listener's bind before `restore_session`. `FO_COLD_BODY` primes the keyboard only after `wolf` returns, and windows that mapped first never got focus. `Coordinator::listen`'s doc gives that harness effect as the reason, and plan 2 §2.4 records a race that is narrowed but still open.
- **Two documents disagree about `cage`, and both landed.** `crates/wolf-gnome/src/ready_seam.rs` says `cage` "activates every toplevel as it maps, before it looks for a keyboard". `Coordinator::listen`'s doc and `notes/wolf-gnome/the-coordinator-and-its-windows.md` say that a window mapped before any keyboard is never focused. `coder-1`'s `is-active` trace saw neither window activated, and review 2 §8 note 4 left the conflict open.
- **One packaged smoke fails on the Linux worker whatever the change.** `packaged::the_packaged_binary_opens_a_preview_under_cage` reads a 0.0 dark band because WebKit's bubblewrap cannot run in the container. The `smoke_headless/packaged.rs` entry does not say so. `coder-1` reverted the flake change and ran `./tools/wolf-package-smoke.sh` again to prove it, which took about 7 of the 11 minutes it spent on the package.

## Recommendations

1. **Give an unplanned test its own ID at the test writer.** This is recommendation 2 of [cli-open-2-2](cli-open-2-2.md) and 1 of [cli-open-2-1](cli-open-2-1.md), come up again in a new form: a check in a guard over harness code, which only a test-file edit can falsify. In `.claude/skills/regina/agents/test-writer.md`, require such a check to be planned with a falsifier the coder may make, or left out, which would have saved part of round 2's $7.20.
2. **Make a budget cut of planned content visible.** In `.claude/skills/regina/agents/technical-writer.md`, require the report to list every plan §5 item that the word budget kept out of an entry. Review 1 would then have read it as a known gap rather than an omission. Without this, `technical-writer-1`'s silent cuts became D1.
3. **Split the wolf-gnome READMEs.** This is recommendation 4 of [followups-3](followups-3.md) and 5 of [pane-ui-5](pane-ui-5.md), come up again. Here the `layout.rs`, `pane_zoom.rs`, `tab_view.rs`, `coordinator.rs` and `window.rs` entries could not take one public method more without dropping another. That cost D1 and the `neighbor` line.
4. **Let a smoke print the whole `cage.log`.** Make `CAGE_LOG_TAIL_LINES` in `crates/wolf-gnome/tests/smoke_headless/main.rs` overridable by an environment variable. In the tests README's smoke conventions, say that the kept runtime directory does not outlive a `regina on linux` command, so read it in the same command. `coder-1` lost about 44 minutes and a failed command to the missing log.
5. **Measure `cage`'s activation once and settle both documents.** Re-measure whether `cage` activates a toplevel that maps before any keyboard exists, then rewrite whichever of `ready_seam.rs`'s module doc and `Coordinator::listen`'s doc is wrong. Then move `wtype ""` before `fo_wolf` in `FO_COLD_BODY`, and give the bind order a product reason or none. That closes S4's open race in the gate.
6. **Say where the packaged preview smoke cannot pass.** In the `smoke_headless/packaged.rs` entry of `crates/wolf-gnome/tests/README.md`, say that the preview smoke fails in a container where bubblewrap cannot run, as on the Linux worker. That would have saved `coder-1`'s revert and rerun.
