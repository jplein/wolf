# Retrospective: Toggle Terminal focuses an open drawer that is not the active pane

Last verified at commit `44b16a4dba66f22ae9827013d1764c36babeaf42`.

The task changed `wolf_toggle_terminal(id)` in `runtime/nvim/init.lua` to three cases: open a closed drawer, close it when it is Neovim's current window, and otherwise make it current. It ran in one pass: `architect-1`, `test-writer-1`, `coder-1`, `technical-writer-1` and `reviewer-1`, about $16.36 and 52 minutes of agent time in all. No rejection, discrepancy or resume occurred, and both gates exited 0 on both workers at their first run.

## What went well

- **Both front-ends follow Neovim's current window, so the behaviour changed in one Lua function.** Every view-made focus change queues `focus_win` on core's ordered input channel, and `updateActivePane()` and `PaneInner::update_active_pane` adopt `active_win` on every wake. Plan 1 §1 settled "active" from that, and commit `027983c` changed 11 lines of `init.lua` and no front-end behaviour. Zoom needed no code either, because `PaneZoom.Event.toggleTerminal(drawer:)` and `ZoomEvent::ToggleTerminal` already unzoomed first.
- **Every test file was already wired.** `//crates/wolf-core:terminal_drawer`, the `WolfMacOSTests` `srcs` and Cargo's `smoke_headless` held the files the plan named, so no `BUILD.bazel` changed. `test-writer-1` wrote tests on three platforms for $3.49 in about seven minutes.
- **Single-edit falsifiers on the Lua helper gave every test its own red.** Because the logic sits in one `if`, plan 1 §4's 17 falsifiers were one-line edits of `init.lua` or `PaneContainerView.swift`. `coder-1` reported each red verbatim, plus base reds for C3, M1 and M2, in about 24 minutes for $2.41.

## What did not go well

- **The toggle's behaviour is restated in about fifteen places, and four agents searched for them.** The task rewrote "opens or hides" in nine doc comments over seven source files, two specs and four documents. `architect-1`, `coder-1`, `technical-writer-1` and `reviewer-1` each ran their own search for "opens or hides" and its variants. Review 1 §5 still found three left: `crates/wolf-ffi/tests/terminal.rs`, a case in `command_action.rs`'s test block, and `specs/architecture.md`'s "in either direction".
- **An existing test was pinned to the old toggle rule.** `TerminalClosePaneTests.testCloseIsRefusedOnTheLastEditorPaneBesideTheDrawer` tests the refused Close gate, but used one `toggle_terminal()` from the editor to hide the drawer afterwards. Plan 1 did not name it, though `architect-1` grepped that file. `test-writer-1` found it by checking every test that toggles the drawer, and made it toggle twice. Nothing was reworked, and no cheap change to the repository would have flagged it.
- **One GNOME smoke readback still costs edits in a second file.** Leg i's two readback names were imported into `smoke_headless/fixture_guards.rs` and listed in `RELAUNCH_FIXTURE_NAMES` with each name repeated as a string, and `cargo fmt` then reflowed the whole import block. Recommendation 7 of [fixes-1](fixes-1.md) comes up again.
- **One new exit code in `zoom_pane.rs` was written in four places.** Exit 95 went into the shell script, the `OWN_EXITS` range, the doc's exit table and the `ZOOM_PANE_EXITS` string, which `require_leg` prints. `test-writer-1` kept them in step by hand, and review 1 found no slip.
- **The READMEs grew past the size warning again.** `crates/wolf-ffi/src/README.md` went from 50,603 to 50,688 bytes and is newly over the `big-file` warning, and `runtime/nvim/README.md` reached 57,870. `architect-1`'s search for `toggle_terminal` over `crates/` overflowed the tool's output and was re-read from a file. Recommendation 1 of [cli-open-2-4](cli-open-2-4.md), to split the over-budget READMEs, comes up again, as it did in [app-state-fixes-2](app-state-fixes-2.md).
- **A documented claim was not measured.** The `zoom_pane.rs` doc and the GNOME tests README say that keeping the zoom on `ZoomEvent::ToggleTerminal` leaves H green, because the drawer's `WinEnter` unzooms anyway. `technical-writer-1` and review 1 §3 both note that nobody ran that edit; the code supports it, and `pane_zoom.rs`'s K7 pins the toggle's own unzoom.

## Recommendations

1. **Let the pass-through doc comments link the drawer spec instead of listing the cases.** `WolfCore::toggle_terminal`, `InputEvent::ToggleTerminal`, `PaneInner::toggle_terminal`, `PaneHandle::toggle_terminal`, `AppShell::toggle_terminal`, `UiAction::ToggleTerminal` and `PaneContainerView.toggleTerminal()` only forward the call, so each could say "toggles the drawer; see `specs/terminal-panes.md#the-drawer`". This task rewrote nine such comments, four agents searched for them, and three stale copies remain. The same fix applies to the three copies review 1 §5 lists.
2. **Derive `RELAUNCH_FIXTURE_NAMES` entries from the constants.** This is recommendation 7 of [fixes-1](fixes-1.md), come up again for leg i's two entries in `crates/wolf-gnome/tests/smoke_headless/fixture_guards.rs`.
3. **Derive `ZOOM_PANE_EXITS` and `OWN_EXITS` from one table in `zoom_pane.rs`.** A `const` slice of code and leg pairs could give both the range check and the message `require_leg` prints, leaving the script and the doc's exit table. Exit 95 was written in four places here, and each new leg of this smoke will repeat that.
4. **Split the over-budget READMEs.** This is recommendation 1 of [cli-open-2-4](cli-open-2-4.md), come up again. `crates/wolf-ffi/src/README.md` joins `runtime/nvim/README.md` and `crates/wolf-core/tests/README.md` over the warning.
