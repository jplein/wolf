## What went well

- **A plan that quotes every replacement made the edits mechanical.** Plan 1 §3 gave E1 to E15 as exact old and new text, and `architect-1` had spliced each into a scratch copy and run the markdown checker and prettier on it first. `coder-1` applied all fifteen for $0.87, and `reviewer-1` checked each one against the word diff. Plan 2 did the same, and `coder-2` cost $0.34.
- **`tools/doc-lint/README.md`'s rule table settled R1 quickly.** Its scope column lists `doc-anchor` as "both" and `md-anchor` as `--root`. `reviewer-1` used the table and `tools/doc-lint/src/refs.rs` to show that the plan named the wrong rule, and `technical-writer-3` checked the fix against the same table. Keep the scope column.
- **`markdown_check.sh` runs on files no gate reads.** The task's "Done means" asked for no new finding on `architect.md`. `coder-1` recorded the four baseline findings, and `coder-2` showed the same four before and after its edits. Without the standalone script, nothing could have checked the definitions' paragraph limits.
- **The coder's `regina on linux` turned a guess into a measurement.** Plan 1 marked the Linux forms in E3 as unmeasured from the architect's sandbox. `coder-1`'s V2 checked `stat -f /tmp` and `$WOLF_NVIM_BIN` in one remote command, so E3's last sentence landed measured.
- **The validator and the section hashes came up again.** `regina flow validate` rejected `commands: on` at the architect's line, so V3 had a negative control. The `awk` and `cmp` extraction kept D3's shared sections provably unchanged in two reviews. Both are already in [regina-cleanup-1](regina-cleanup-1.md) and held here too.

## What did not go well

- **Review 1 R2: plan 1 stated one rule twice, and the two copies differed.** E8 gave the coder "the fix of a Markdown link that a deleted file breaks" in `architect.md`, while E13 and E12 gave `coder.md` "a file you deleted" and "its deletions". `reviewer-1` found a real case: a test writer deleting `crates/wolf-core/tests/markdown_render.rs` would break a README link that no agent could fix. The rule lives in three places, `architect.md` item 5 and `coder.md`'s description and Rules bullet, and nothing compares them.
- **Review 1 R1: a rule name copied from retrospectives was wrong.** Plan 1 E8 said that a missing mirror heading fails "as `md-anchor`", where doc-lint reports a comment's missing anchor as `doc-anchor`. The wrong name comes from [followups-1](followups-1.md) recommendation 1, and [close-followups-2](close-followups-2.md), [retro-fixes-4](retro-fixes-4.md) and [app-state-fixes-1](app-state-fixes-1.md) use it too. `CLAUDE.md` already says to verify a note, but the two rules print the same message, `<file> has no heading with anchor #x`, so only the bracketed rule name tells them apart.
- **`technical-writer-1`'s commit subject was three characters over.** Its first line was 65 characters, where its definition allows 60 and the mechanics 62. `technical-writer-2` fixed the message for $0.21, and ran the documentation gate again although no file had changed. [zoom-rules-2](zoom-rules-2.md) records the same slip by an architect, so this is its second occurrence.
- **Each gate ran seven times on a change that no gate reads.** `coder-1` ran `./gates.sh` on macOS, and `coder-2` on macOS and through `regina on linux`, though plan 1 V7 said Linux needed no run. Regina ran both gates on both workers in both rounds, and `technical-writer-1` to `-3` each ran the documentation gate. The task's real checks, prettier with `--ignore-path /dev/null` and `markdown_check.sh` on `.claude/`, were run by hand by `coder-1` and `coder-2`, and this is [regina-cleanup-1](regina-cleanup-1.md)'s third finding and recommendation 2, and it came up again.
- **Two gaps that review 1 found landed unfixed.** `architect.md:80` lists SQLite "as the linked `rusqlite` builds it" as a premise to measure, but the architect cannot build against it: macOS has no `cargo`, and line 72 forbids a `cargo` build on Linux. The test sweep at `architect.md:84` names `crates/*/tests/` and `crates/wolf-macos/Tests/` but not the `#[cfg(test)]` blocks in `src/`. The run used the base flow, which has no notes pass, so both notes went "to a later reader" as in [regina-cleanup-1](regina-cleanup-1.md).
- **Regina's source was found by searching again.** `architect-1` spent about nine calls on `which regina`, `ps`, `ls /nix/store` and `nix-store` queries to reach `specifications/agent-workflow.md`, and `reviewer-1` three more. Nothing in `.claude/skills/regina/README.md` says where the running build's source is. [regina-cleanup-1](regina-cleanup-1.md) recorded four calls for the same search.
- **What the task added is still unexercised.** Every agent ran on the base definitions, so no architect has used `commands: allowed`, a read-only Linux probe or the `swiftc` probe from its own `writes: nothing` sandbox. Plan 1 §8 and both reviews say so. The `documentation-only` route and notes pass of [regina-cleanup-1](regina-cleanup-1.md) were not taken either.

## Recommendations

1. **State each agent's documentation write rule once.** `architect.md` item 5 restates what `coder.md`'s Rules bullet lets the coder write, and plan 1 changed the two copies in different words, which cost review 1's R2 and the $1.87 round. Keep the rule in `coder.md` and have `architect.md` item 5 link to it, or keep one table of who writes which document in `.claude/skills/regina/README.md` that each definition links.
2. **Gate the regina harness.** This is [regina-cleanup-1](regina-cleanup-1.md) recommendation 2 and [round-3-6](round-3-6.md) recommendation 1, and it came up again. A `gates.sh` step running `prettier --ignore-path /dev/null --check` and `markdown_check.sh` on `.claude/skills/regina/` would have replaced the hand checks four invocations ran. It would also have flagged the two 931-character paragraphs at `coder.md:82` and `:102` that the task leaves in place.
3. **Mend the two gaps review 1 found in `architect.md`.** At line 80, say that a SQLite premise is marked unmeasured for the coder to probe through `regina on linux -- cargo test`, since the architect cannot build `rusqlite`. At line 84, add the `#[cfg(test)]` blocks under `crates/*/src` to the test sweep. Both are in review 1 §8 and review 2 §8, and neither cost a round here.
4. **Give `doc-anchor` a message of its own.** In `tools/doc-lint/src/refs.rs`, make the `Rule::DocAnchor` message name the comment, as in `comment path <file> has no heading with anchor #x`, and update the table in `tools/doc-lint/README.md`. Five retrospectives and plan 1 E8 named a comment's missing anchor `md-anchor`, and the identical messages give no hint that they differ.
5. **Say where Regina's source is.** Add one sentence to `.claude/skills/regina/README.md` on how to reach the running build's `specifications/agent-workflow.md`: the store path that `ps` shows, then `nix-store -q --deriver` and `--references` to its `-source` path. `architect-1` and `reviewer-1` spent about twelve calls on this, and [regina-cleanup-1](regina-cleanup-1.md)'s architect four.
6. **Have each definition count its commit subject.** The message rule in every regina definition could end "count the first line with `printf '%s' '<line>' | wc -c` before writing the output". This is the second time an agent exceeded its limit, after [zoom-rules-2](zoom-rules-2.md), and the fix cost $0.21 here and $0.97 there. A message-only discrepancy also re-ran a gate that the files had already passed.
7. **Read the first architect transcript that probes Linux.** The retrospective of the first task whose architect runs on this flow should say whether `regina on linux` worked from a `writes: nothing` sandbox and whether the `swiftc` probe ran there. Plan 1 §8, both reviews and `coder-1`'s report all leave this open.
