# g04: route every terminal to core sessions and remove the Neovim terminal path

Last verified at commit `af0efe629c1b46b5e88594e9cbd0f89b8788e785`.

The task made the drawer, typed `:terminal` and its prefixes, terminal-leaf restore and post-restart rebinds use core sessions on both front-ends, and deleted the `init.lua` terminal path, `WinBuffer.is_terminal`, `TERMINAL_BUFFER_PREFIX` and `NavTarget::Terminal`. It took 16 invocations and $78.81, four plans and two reviews. Three round trips cost about $18.39 between them, and a Linux worker outage added about eight hours of wall clock.

## What went well

- **Pure restore seams made the restart logic cheap to falsify.** `liveness_ui::terminal_restore` and `LivenessSeam.terminalRestore` are functions of their arguments, so G1 and M3 each took four falsifiers as plain table edits. `coder-1` ran 37 falsifiers across both workers and implemented all of plan 1 in one invocation of 34 minutes. [ghostty-4](ghostty-4.md) and [ghostty-3](ghostty-3.md) record the same for the g02 and g03 seams, so keep the seam-then-glue split.
- **The smokes' exit codes and stderr name the leg that failed.** Exit 14 is a Neovim readback that never appeared and exit 15 a shell readback, and each scenario prints the leg. `coder-2` measured every S1 to S4 falsifier from the panic text alone, though a remote run's `/tmp` is gone afterwards, so no capture could be read.
- **Remote-only patches let the coder test the test writer's file without writing it.** `coder-1` patched `smoke_headless.rs` in a `regina on linux` snapshot, saw 77 smokes pass and the restart smoke fail, and handed plan 2 the exact three fixes and a capture-backed diagnosis. That kept `architect-2` at $2.15 and `test-writer-2` at $0.89.
- **The task's done-criterion was a `git grep`.** Every agent from `coder-1` to `reviewer-2` checked "no live Neovim terminal path" with the same command, and the reviews agreed on what each hit was. A criterion a later task can rerun is worth keeping.
- **The documentation gate passed first time, both rounds.** `documentation-1` and `documentation-2` exited 0 on both workers, with only the existing `big-file` warnings.

## What did not go well

- **`coder-1` was rejected on the test writer's smoke file ($5.91).** Three `Some(PaneNode::Leaf { path, preview })` patterns in the 38,536-line `smoke_headless.rs` were missed, though plan 1 §3 asked for `..` on every one. `test-writer-1` could not see them: its `cargo clippy` run failed on the APIs the coder had yet to add, which also hid two unused constants. Only the field's arrival broke the patterns, so `architect-2`, `test-writer-2` and `coder-2` followed; `coder-2`'s S1 to S4 falsifier runs were owed by plan 1 anyway.
- **The restart smoke could not hold as written.** Its pane marker shared a row with the prompt, and the restore's half-width split sends `SIGWINCH`, so readline redraws and clears that row. `test-writer-1` cannot run a smoke, and nothing in `crates/wolf-gnome/tests/README.md` § Smoke conventions said that a resized pane loses its prompt row. Plan 2 D11 fixed it and the notes mirror of `smoke_headless.rs` now records why, so nothing more is recommended.
- **A known-false `PS1` pin was copied into the new smokes.** [ghostty-4](ghostty-4.md) recommendation 7 had said `TP_PS1` never reaches a shell, because `cage` runs the scenario with `sh -c` and a non-interactive bash drops `PS1`. `test-writer-1` built `pin_terminal_smoke_shell` the same way, and `architect-2` found it again (plan 2 D13). The `SMOKE_PS1` channel through `READINESS_PRELUDE` now fixes both, so that part of the recommendation is done.
- **`coder-2` was rejected on five predicted reds in S1's leg table ($4.26).** The table in the doc of `terminal_drawer_opens_and_is_not_persisted_under_cage` named a red leg per edit, but the scenario stops at the first readback that fails, so edits went red at legs d, f-vsplit and h instead. Plan 3 was a text-only rewrite of the table, its messages and its `## Ordering` section. This is [round-3-11](round-3-11.md) recommendation 2 come up again.
- **Review 1 found three falsifiers never run ($8.22 for the round, shared with the `:te` work).** Plan 1's C9 bundled three tests and their falsifiers into one bullet, and C11 said only "keeping its falsifier". `coder-1` reported by C number, one test each, so `a_failed_back_returns_false_and_reverts_the_cursor` and two `state_layout.rs` tests had no recorded red. Plan 2 then said all were measured; `reviewer-1` caught it only by reading `coder-1`'s transcript.
- **A comment that counted routes went false.** `crates/wolf-gnome/src/window.rs:622` called the test hook "the cage smokes' one route to a terminal pane", which S3 and S4 made false. `technical-writer-1` saw it but may not edit code, so review 1 had to block on it and plan 4 D22 had `coder-4` rewrite it.
- **Neovim's `:te` prefixes were outside the spec.** `specs/terminal-panes.md` named only `terminal`, `term` and `ter`, though Neovim's command is `:te[rminal]`, so typed `:te` to `:termina` still opened Neovim's terminal. `reviewer-1` raised it as non-blocking and plan 4 D23 added four abbreviations. Nothing in the repository invited the gap beyond the spec's own wording.
- **The Linux worker stopped answering in round 3.** `coder-4` sent four `regina on linux` requests, `echo hi` among them, and each timed out after about 20 minutes, which is 80 of its 83 minutes. Gate run `implementation-2` was cancelled on Linux, and `implementation-3` ran eight hours later. Nothing in the repository caused it.
- **The hand-kept smoke counts were edited in two places again.** `test-writer-1` changed the module doc of `smoke_headless.rs` to 64 smokes and `78 passed`, and `technical-writer-1` changed `crates/wolf-gnome/tests/README.md`, which still said 62 and `76 passed` at the base. This is [round-3-11](round-3-11.md) recommendation 7 and [ghostty-4](ghostty-4.md) recommendation 3.
- **The `PaneContainerView.swift` entry is at its word budget.** `technical-writer-1` moved `capturedTerminals()` and `requestTerminalRestore(_:)` to `notes/wolf-macos-decisions.md`, review 1 flagged their absence from the API, and `technical-writer-2` trimmed the entry to 248 of 250 words to add them. This is [round-3-7](round-3-7.md) recommendation 4 and [ghostty-3](ghostty-3.md) recommendation 3.
- **One more test helper exists twice.** `test-writer-1` added `pin_default_shell()` to both `crates/wolf-core/tests/common/mod.rs` and `crates/wolf-ffi/tests/common/mod.rs`, beside the session helpers [ghostty-4](ghostty-4.md) recommendation 6 already wants shared.
- **Every edit of `smoke_headless.rs` is heavy for an agent.** Each `Edit` result in `test-writer-2` and `test-writer-3` carried the whole 2 MB file, giving transcripts of 25 MB and 34 MB for 31 turns each. The file still holds every feature's smokes; [round-3-11](round-3-11.md) recommendation 5 and [ghostty-4](ghostty-4.md) recommendation 2 came up again.

## Recommendations

1. **Give each falsifier its own ID naming one test.** In `.claude/skills/regina/agents/architect.md` item 4, require one ID per test and disabling edit, such as C9a to C9c, and in `.claude/skills/regina/agents/coder.md` require the report's evidence to be keyed by those IDs. Plan 1's C9 and C11 would have listed R1 to R3 by name, and `coder-1` would have run them; that saves review 1's blocking item and most of round 3.
2. **Name where a smoke's falsifier goes red only after it is measured.** This is [round-3-11](round-3-11.md) recommendation 2 come up again. In `crates/wolf-gnome/tests/README.md` § Smoke conventions, say that a scenario's first missing readback ends it, so a leg table names the edit and its red is the coder's to record in its report. Plan 3 and its $4.26 round would not have been needed.
3. **Destructure `PaneNode::Leaf` through helpers in the smokes.** `leaf_tail` and `leaf_preview` in `smoke_headless.rs` already read one field each; add one for the full path and route the three `Some(PaneNode::Leaf { path, preview, .. })` sites through them, so a new field reaches one place. Plan 1 §3's instruction would then have had nothing to miss.
4. **Split `smoke_headless.rs` by feature.** This is [round-3-11](round-3-11.md) recommendation 5 and [ghostty-4](ghostty-4.md) recommendation 2, come up a third time. A `terminal` module holding S1 to S4, their constants and `pin_terminal_smoke_shell` would have been one file to search for every `PaneNode::Leaf` site.
5. **Drop the hand-kept smoke counts.** This is [round-3-11](round-3-11.md) recommendation 7 and [ghostty-4](ghostty-4.md) recommendation 3, come up again, with a stale README count at the base as new evidence.
6. **Keep comments from counting their callers.** In `CLAUDE.md` § Code comments, add that a comment states what the code does, not how many tests or callers use it. `window.rs:622`'s "one route" went false the moment g04 added a route, and cost a review block.
7. **Fail `regina on` fast when the worker is gone.** In the regina skill's remote-command path, probe the worker before a long request and fail in seconds when it does not answer. `coder-4` spent 80 minutes on four requests that each waited about 20 minutes to time out.
