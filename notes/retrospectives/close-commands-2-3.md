# Retrospective: Close Pane closes the tab on the tab's last pane

Last verified at commit `c277bd53fea8db676358f9dab9dcb8e2c9bc6746`.

The task renamed Close to Close Pane on both platforms and made `InputEvent::ClosePane` run a new `_G.wolf_close_pane()`, which takes `:q`'s `do_quit({})` path on the tab's last pane. macOS lost `canClosePane` and its menu gate. It took five invocations, about $20.73 and 66 minutes of agent time: `architect-1` $7.43, `test-writer-1` $4.51, `coder-1` $2.83, `technical-writer-1` $2.43 and `reviewer-1` $3.53. There was no round trip: review 1 approved, and both gates passed on both workers on their first run.

## What went well

- **The earlier tasks of this request left the change one helper wide.** Both front-ends already closed the tab that queued a drained `close_tab`, from close-commands-2-1 and close-commands-2-2, so the Lua change is seven lines in `runtime/nvim/init.lua` and GNOME needed only a label (plan 1 D4, review 1 §1). `coder-1`, falsifiers included, cost $2.83.
- **The test helpers took the new cases without new support code.** C18 was rewritten as one call to `quit_beside_the_drawer(Quit { … })` in `crates/wolf-core/tests/drawer_last_pane.rs`, P2–P4 reused `commands.rs`'s `refused`, `expect_close_tab` and `hide_a_modified_second_file`, and W22 reused `wolf_wait.rs`'s `shut_down_on_close_tab`. The new smoke borrowed `close_tab.rs`'s readbacks once the test writer moved them into `READBACK_HELPERS`.
- **The registry's title has a drift check on GNOME.** The in-source `menu_labels_match_the_registry` in `crates/wolf-gnome/src/actions.rs` goes red until the `MENU_SECTIONS` label matches `command.rs`, so plan 1 §3 could name the test instead of a manual check.
- **Plan 1 carried two earlier recommendations itself, and both paid off.** Its §5 gave each entry's word count, which [close-commands-2-2](close-commands-2-2.md) recommendation 2 asked for, and `technical-writer-1` had no overrun in 41 commands. Its §4 told the coder to print each run's status before filtering, recommendation 3 there, and all 15 Linux falsifier commands of `coder-1` did, so review 1 §4 matched every red to its exit.
- **Plan 1 kept the coder off a doc-lint ordering trap.** It said not to link `runtime/nvim/README.md#wolf_close_pane` from the `init.lua` comment, because the technical writer adds that heading later and doc-lint would fail the implementation gate first. `implementation-1` passed on its first run.

## What did not go well

- **The Linux load flake came up a third time.** `coder-1`'s first Linux `./gates.sh` failed only in `bd_beside_the_drawer_shows_neovims_jumplist_pick` in `drawer_last_pane.rs`, which this task does not touch, on the 10 s `FLUSH_TIMEOUT`: 14.83 s against 1.94 s alone. It cost five diagnostic runs and a second gate run of about 6 minutes. [tabs-and-preview-5](tabs-and-preview-5.md) and [close-commands-2-2](close-commands-2-2.md) record the same timeout in the same suites.
- **A comma list in `--test_filter` ran no test, again.** `coder-1` passed several `WolfMacOSTests` classes in one filter, bare and with the `WolfMacOSTests.` prefix, and both runs matched 0 tests and exited 3. `build.md` still does not name the flag, and `.claude/skills/regina/agents/coder.md` still gives `--test_arg=--exact` as the single-test form, which XCTest ignores. [nerd-font-2](nerd-font-2.md) recorded the same two lost runs.
- **The coder serialised its macOS and Linux falsifiers.** Its Linux falsifier edits were local, and `coder-1` could not tell when a `regina on linux` request's snapshot had been taken. So it held every edit until each Linux result came back, rather than run the macOS reds beside them, because an `init.lua` edit meant for Linux would have reached the macOS real-Neovim tests. `coder-1` ran 27 minutes, the longest invocation of the task.
- **Plan 1 carried what the definitions lack.** The entry counts and the exit-status form above came from `architect-1`, not from a definition: neither the architect's nor the coder's system prompt mentions `--entry-words` or the `echo "exit=$?"` form. The next architect may not repeat them.
- **The READMEs grew further past the size warning.** `runtime/nvim/README.md` went to 63,351 bytes and `crates/wolf-gnome/tests/README.md` to 147,043, and the `wolf_wait.rs` entry is at 250 of 250 words, so the next task that adds a `wolf --wait` route must cut first. Many earlier reports record this, among them [app-state-fixes-2](app-state-fixes-2.md) and [application-state-6](application-state-6.md).

## Recommendations

1. **Fix the `FLUSH_TIMEOUT` races under the Linux gate's load.** This is recommendation 4 of [tabs-and-preview-5](tabs-and-preview-5.md) and 5 of [close-commands-2-2](close-commands-2-2.md), come up again, and it is now three tasks running. In `crates/wolf-core/tests/drawer_last_pane.rs` and `commands.rs`, find why a probe-file wait takes seven times longer under the gate's parallel `cargo test`. Each occurrence has cost a full Linux gate run of about 6 minutes.
2. **Name `--test_filter=<Class>/<method>` in `build.md`, and fix the coder definition's Swift form.** This is recommendation 3 of [cli-open-2-4](cli-open-2-4.md) and 6 of [sidebar-preview-3](sidebar-preview-3.md), come up again. Say that it takes one class or method, and that a comma list runs nothing and exits 3. Here it cost two runs.
3. **Move the plan's two working habits into the definitions.** This is recommendations 2 and 3 of [close-commands-2-2](close-commands-2-2.md), come up again: `--entry-words` in `.claude/skills/regina/agents/architect.md`, and the status-before-filter form in `coder.md`. This task shows both work when the plan states them.
4. **Have a Linux falsifier make its edit inside the remote command.** This extends recommendation 1 of [nerd-font-1](nerd-font-1.md) from `flake.nix` to every file. Where `.claude/skills/regina/agents/coder.md` says "A remote snapshot carries the disabling edit", say to apply the edit in the `regina on linux -- sh -c` command itself. The workspace then stays clean, and `coder-1` could have run its macOS reds alongside the Linux ones.
