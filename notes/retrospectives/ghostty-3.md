# macOS terminal panes over the session bridge (g02 of the libghostty-vt series)

Last verified at commit `8f709eb15d864bc45c7172968af4fa7af65a1ef7`.

The task was g02: the `wolf-ffi` session bridge, four `WolfKeyMap` seams, `GlyphPainter.swift` and `TerminalPaneView.swift`, and the `PaneContainerView` and `WolfWindowController` wiring, with a bridge test, seam tests and an offscreen render test. It took eight invocations, about $40.50 and 94 minutes, and review 1 approved with minor notes. `coder-1` alone was $12.41 (140 turns, 28 minutes).

The one round trip was `coder-1` rejecting the test helper `OffscreenRenderer.swift` over how it reads a pixel. It added `architect-2` ($1.51), `test-writer-2` ($0.34) and `coder-2` ($0.89), about $2.74 and 11 minutes. Every gate run passed on both workers on its first try.

## What went well

- **The offscreen render target from [round-3-7](round-3-7.md) carried a new kind of test.** `//crates/wolf-macos:WolfMacOSTests` already linked `WolfMacOS`, set `CFProcessPath` and had `OffscreenRenderer.swift`, so `test-writer-1` added only `LiveCore.swift` and `TerminalPaneRenderTests.swift` to render a real shell session's pixels. None of the `CFProcessPath` diagnosis that round-3-7 recorded happened again.
- **Pure seams in `WolfKeyMap` kept most of the logic cheap to test.** Cell style, damage, geometry and input routing went into `TerminalCellStyle`, `TerminalDamage`, `TerminalGeometry` and `TerminalInputSeam`, and their 44 test methods each got a recorded falsifier in `coder-1`'s run. Review 1 §4 checked them against the report with nothing missing.
- **AppKit probes with `xcrun swiftc` work in the worker, so the dispute arrived settled.** `coder-1` compiled a scratch program that captured as `OffscreenRenderer` does and read crimson back as (229.3, 45.7, 76.3) against raw samples of (220, 20, 60). Plan 2 upheld it in 21 turns, and `test-writer-2` fixed it in 8.
- **The spec's g02 Tests bullet ended a scope question in one line.** It names three kinds of test, so plan 2's D12 declined container-level input tests and left their on-screen check to g04.

## What did not go well

- **The round trip came from a test helper that had never read a saturated colour.** `OffscreenRenderer.swift`, added in commit `33b60a6` for round-3-7, read pixels with `colorAt(x:y:)?.usingColorSpace(.sRGB)`. `colorAt` tags the samples by `colorSpaceName` (calibrated RGB), not by the bitmap's sRGB `colorSpace`, which shifts saturated colours by up to 0.12. `FileTreeViewTests` only checks colours whose shift stayed inside its tolerance, so nothing caught it until g02's crimson test.
- **The helper is outside the coder's reach, so a one-function fix took three invocations.** `coder-1` spent about 3.5 minutes and some 17 tool calls on the diagnosis, then had to reject, because the file is the test writer's. Before the fix, the cursor test's default-background check passed at about 0.09 against a 0.1 tolerance, close enough to have flaked.
- **The per-entry word budget cost a writer its time again.** The `PaneContainerView.swift` and `WolfWindowController.swift` entries of `crates/wolf-macos/Sources/WolfMacOS/README.md` were each at 249 of 250 words. `technical-writer-1` read `tools/lint/markdown_check.sh` and counted words with `awk` to learn this, then moved facts into `notes/wolf-macos-decisions.md`. Plan 1 §8 warned about bytes but did not count either entry.
- **The `wolf-macos` READMEs keep growing past the size warning.** `crates/wolf-macos/Sources/WolfKeyMap/README.md` went from 60,542 to 64,066 bytes and `crates/wolf-macos/Sources/WolfMacOS/README.md` from 51,349 to 53,260. `architect-1`, `technical-writer-1` and `reviewer-1` ran 6, 22 and 3 commands on them.
- **There is no way to print a session's cells except a scratch program.** To check that cells 0 to 3 carried a crimson background, `coder-1` wrote `crates/wolf-ffi/examples/dbg_term.rs` inside the repository, ran it on the Linux worker, then deleted it. It was cleaned up, but a scratch file under a crate is easy to leave behind.
- **Review 1 §2 and §3 record gaps in the landed work.** Each render test captures once, so a `TerminalPaneView.update` that never invalidated a row after its first frame would pass. `paintRow` builds a `ClosedRange` from `row_selection_start` and `row_selection_end`, which traps if they are ever reversed. Marked text is left on the old pane when the active pane changes.
- **One `WolfMacOSTests` run died with `Broken pipe`.** `coder-1` saw it once and not in about 20 later runs. Nothing in the repository ignores `SIGPIPE`, so a pty write after a shell exits could kill the test host, and plan 2's D13 left it to be reported if it recurs.
- **`notes/wolf-macos-decisions.md` § Threading was stale before this task.** It said `WakeBridge` calls `setNeedsDisplay`, while `WakeBridge.install` calls `Project.onWake()`. `technical-writer-1` corrected it, but `architect-1` and `coder-1` had both read the note as a lead first.

## Recommendations

1. **Pin the offscreen read to known colours with a test of its own.** Add a test to `crates/wolf-macos/Tests/WolfMacOSTests/` that fills a plain `NSView` with sRGB crimson, pure blue and a dark grey, captures it with `OffscreenRenderer`, and asserts each pixel within 0.01. Had it existed when round-3-7 added the helper, the misread would have failed there, and g02 would have saved its $2.74 round trip and `coder-1`'s diagnosis. g03 and g04 will render more colours through the same helper.
2. **Let the markdown checker report an entry's word count.** This came up again: it is recommendation 3 of [open-items-12](open-items-12.md), recommendation 2 of [open-items-14](open-items-14.md) and recommendation 3 of [round-3-7](round-3-7.md). Here it would have let plan 1 see the two full `WolfMacOS` entries and plan the move to the decisions note, instead of `technical-writer-1` reverse-engineering the checker.
3. **Split the two `wolf-macos` source READMEs.** This is recommendation 4 of [round-3-7](round-3-7.md), come up again, now for `WolfKeyMap/README.md` too. Moving the terminal files (`TerminalPaneView.swift`, `GlyphPainter.swift` and the four `Terminal*` seams) into `Terminal/` subdirectories with their own READMEs would give g03 and g04 a small document to read. The globs in `crates/wolf-macos/BUILD.bazel` would need the new paths.
4. **Add a frame-dump example to `wolf-ffi`, or say how to dump one.** A committed `crates/wolf-ffi/examples/` program that opens a session, runs a command and prints each cell's text and colours would replace `coder-1`'s scratch file. If that is too much, one paragraph in `crates/wolf-ffi/tests/README.md` naming the `terminal_bridge` helper to copy would do.
