# Retrospective: a message toast survives terminal input, the drawer and terminal focus

Last verified at commit `8ef4fafc06b84ad16f4185b8c1ba1a85ee74dcc8`.

The task made a non-`confirm` message toast dismiss on input to a terminal session, on `ToggleTerminal`, and on a `FocusWin` into a terminal pane. The rule lives in core, and the task opened one sentence each of `specs/architecture.md` and `specs/terminal-panes.md`. The run went straight through: `architect-1`, `test-writer-1`, `coder-1`, `technical-writer-1` and `reviewer-1`, one plan and one approving review. Both gates passed on their first run on both workers.

The five invocations cost about $19.03 and 50 minutes of agent time. `architect-1` cost $6.23 over 85 turns, `test-writer-1` $4.82, `reviewer-1` $3.69, `coder-1` $2.63 and `technical-writer-1` $1.66. There was no round trip between agents, so nothing below cost an extra invocation.

## What went well

- **Core owns the toast, and both front-ends repaint it on every wake.** Plan 1 §1 found that macOS (`PaneContainerView.onRenderWake` → `refreshOverlays`) and GNOME (`on_render_wake` → `refresh_message_surfaces`) gate nothing on `seq`. So the fix was core-only: `coder-1` changed no front-end code beyond two comments. F11 and F12 then showed both front-ends hiding the toast from core's wake alone. A later change to front-end wake handling must keep this property.
- **The test helpers already held everything the new tests needed.** Plan 1 §2 told the test writer to change neither `crates/wolf-core/tests/common/mod.rs` nor `wolf-test-support`, and `test-writer-1` changed neither. It used `open_session`, `wait_for_text`, `pin_default_shell`, the recording wake log, and `messages.rs`'s `toast_text` pattern. On macOS, `TerminalViewFixture` gave F11 a real core and drawer with no new fixture code. Both test files compiled on the first build, before any production change.
- **Exact disabling edits let the coder script every falsifier.** Plan 1 §4 named each edit as a one-line change in a named function. `coder-1` ran F1 to F10 from one script, each with a checksum before and after, and no edit had to be improvised. [fixes-1](fixes-1.md) recommendation 6 asked for this, and it paid off here.
- **`regina on linux` let the coder record the Linux-only red.** `coder-1` ran the F12 smoke green, red (exit 101) and green again on the Linux worker, then ran the Linux gate, all before handoff. The implementation gate then passed first time on both workers.
- **The split `smoke_headless` modules kept the GNOME smoke local.** `test-writer-1` appended F12 to `crates/wolf-gnome/tests/smoke_headless/terminal.rs` and read the toast smokes in `smoke_headless/editor.rs` by range. In [round-4-1](round-4-1.md), finding these meant searching one 39,100-line file.

## What did not go well

- **Plan 1 assigned bullets to four README entries that had no room.** Plan 1 §5 gave a Decisions bullet to the `pump.rs`, `render.rs`, `input.rs` and `terminal.rs` entries of `crates/wolf-core/src/README.md`, which stood at 250, 245, 246 and 250 of 250 words. `architect-1` read `tools/lint/markdown_check.sh` for the line cap, but never ran `--entry-words`. Its system prompt never mentions the word budget.
- **The technical writer undid the plan's bullets.** On its first check, `technical-writer-1` got 302, 278, 265 and 317 words. It deleted the four bullets, left three reasons to the doc comments, and moved two decisions into `notes/wolf-core-decisions.md` § Terminal sessions. That took about a fifth of its 45 tool calls, and review 1 had to accept it as a deviation from the plan.
- **Two of those entries are still at the limit.** After the task, `pump.rs` and `terminal.rs` in `crates/wolf-core/src/README.md` are at 250 of 250 words, and `input.rs` is at 239. The next decision in core's pump or terminal registry has nowhere to go but a notes file.
- **The new `rust_test` was copied by hand again.** `test-writer-1` built `//crates/wolf-core:terminal_toast` by copying `terminal_input`'s target: the runfiles, the three `WOLF_*` env entries, `no-sandbox`, `size` and deps. This is [round-4-3](round-4-3.md) recommendation 1, come up again.
- **One GNOME smoke needed two entries in a separate guard file.** F12 added `TOAST_OCR_TERM` to `ASSERTED_OCR_TERMS` and `TOAST_PROBE_NAME` to `RELAUNCH_FIXTURE_NAMES`, both in `smoke_headless/fixture_guards.rs`, apart from the smoke itself. [fixes-1](fixes-1.md) recommendation 7 covers the second table.
- **A plan-local ID landed in source.** The doc comment of the F10 in-source test at `crates/wolf-core/src/render.rs:1286` begins `F10:`, a falsifier ID that means nothing outside plan 1. Review 1 said no other source file carries one. In fact, `crates/wolf-core/src/markdown.rs` labels ten in-source tests `U1:` to `U10:`. No definition or `CLAUDE.md` rule says to keep falsifier IDs out of the code.
- **A test may flake on the wake.** Review 1 found that `a_dismissal_by_terminal_input_wakes_the_front_end_and_none_without_a_toast` reads the wake log only once (`crates/wolf-core/tests/terminal_toast.rs`, around line 486). It reads right after the poll sees the toast dismissed, but `dismiss_toast_and_wake` fires the wake only after the write guard drops, so a preempted runtime thread can fail the test spuriously. It passed in every recorded run, and it landed unchanged.
- **A crash-restart restore now dismisses a toast.** Review 1 notes that both front-ends restore an open drawer by calling `toggle_terminal()`: `PaneContainerView.runPendingTerminalRestore`, and `TerminalRestore::Drawer` in `crates/wolf-gnome/src/pane_view.rs`. Since `ToggleTerminal` now dismisses, a startup message showing at that moment is cleared by an action the user did not take. The plan's rule allows this, and it landed as is.
- **The tests READMEs grew past the size warning again.** The documentation gate warned that `crates/wolf-core/tests/README.md` is at 58,916 bytes and `crates/wolf-gnome/tests/README.md` at 101,148, both over the 50,000-byte ceiling. Both were already over at the base. This is [round-3-10](round-3-10.md) recommendation 7 and [round-4-6](round-4-6.md) recommendation 4, come up again.

## Recommendations

1. **Have the architect count every entry it plans to grow.** In `.claude/skills/regina/agents/architect.md`, where plan §5 is described, require `./tools/lint/markdown_check.sh --entry-words <README>` on every README that §5 adds to, with each count, and a cut or a notes destination for an entry without room. Here plan 1 would have sent the two decisions to `notes/wolf-core-decisions.md` itself, sparing the writer's rework and review 1's deviation. In [fixes-1](fixes-1.md) and [fixes-2](fixes-2.md) the plans counted, and the writers did not have to cut.
2. **Make room in the `pump.rs` and `terminal.rs` entries of `crates/wolf-core/src/README.md`.** Both are at 250 of 250 words. Move their longest Decisions bullets to `notes/wolf-core-decisions.md`, or to the files' doc comments where those already give the reason, until each has about 30 words free. This task lost its four planned bullets to that limit.
3. **Give the real-Neovim `rust_test` one macro.** This is [round-4-3](round-4-3.md) recommendation 1, come up again for `//crates/wolf-core:terminal_toast`.
4. **Poll the wake log in the F9 test.** In `crates/wolf-core/tests/terminal_toast.rs`, replace the one-shot `wakes.instants()` check after the dismissal with `poll_until` on a non-empty log, as review 1 suggests. That closes the spurious-failure window before a gate run hits it.
5. **Keep falsifier IDs out of the code.** In `.claude/skills/regina/agents/test-writer.md` and `coder.md`, say that a plan's falsifier IDs belong in reports and test names never carry them. Then drop the `F10:` prefix at `crates/wolf-core/src/render.rs:1286` and the `U1:` to `U10:` prefixes in `crates/wolf-core/src/markdown.rs`. A reader of the repository has no plan to look them up in.
6. **Split the two tests READMEs.** This is [round-3-10](round-3-10.md) recommendation 7 and [round-4-6](round-4-6.md) recommendation 4, come up again. Here `crates/wolf-core/tests/README.md` grew by another 1,141 bytes.
