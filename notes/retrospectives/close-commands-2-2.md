# Retrospective: Close Tab becomes a user-facing command that refuses unsaved changes

Last verified at commit `9a96f5756ceea063d45abebeb3a0fcad0534e92d`.

The task put Close Tab in the macOS File menu, the GNOME primary menu and the palette, and made it, `:WolfCloseTab` and the tab's close button ask the tab's Neovim through a new `_G.wolf_close_tab()` before closing. It took ten invocations, about $37.95 and 123 minutes of agent time. Round 1 was `architect-1` $11.12, `test-writer-1` $5.60, `coder-1` $4.08, `technical-writer-1` $5.85 and `reviewer-1` $4.76. There was one round trip, review 1's F-1, and every gate passed on both workers on each of its runs.

## What went well

- **Both registry-driven surfaces took the new menu rows without a gate failure.** `close_tab` was already a registry command from close-commands-2-1, so the work was a `MenuOnly` row in `MENU_SECTIONS` in `crates/wolf-gnome/src/actions.rs` and tag 31 in `AppMenu.swift`. `implementation-1` passed on both workers on its first run, and review 1 §3 found no unwired test file.
- **The `wolf --wait` harness made the fix's test one function.** `crates/wolf-core/tests/wolf_wait.rs` already had `new_case`, `spawn_wait`, `open_waited` and `shut_down_on_close_tab`. W21 was built from them alone, and `test-writer-2` took 21 turns ($0.66).
- **The rejection came with a design the next round could carry out as written.** Review 1 F-1 quoted the §6 row, gave the two options and specified the test with its falsifier. Plan 2 took option (a) unchanged, and the whole second round cost $6.54, about a fifth of the first.
- **The technical writer listed every planned item the word budget kept out.** `technical-writer-1`'s report named the five skipped entries and where each fact went instead, so review 1 §1 could check each one and not call it an omission. This is what recommendation 2 of [cli-open-2-3](cli-open-2-3.md) asked for.

## What did not go well

- **The round trip came from reusing `do_quit` without its contract.** Plan 1 D1 made `_G.wolf_close_tab` be `do_quit({ all = true })`, "as a quit does". So every Close Tab ended a pending `wolf --wait` with `0`, where the `specs/cli-and-file-open.md` §6 row "The tab, window or app closed by any other route" gives `1`. The task did not open that spec, and review 1 F-1 sent it back.
- **Nothing at the code `architect-1` read pointed at §6.** It read `do_quit` and its comment, which links `notes/runtime/nvim/init.lua.md#waits-end-before-the-tab-closes`. That section, and the `runtime/nvim/README.md` paragraph "A quit that closes the tab ends the waits", explain the ordering of the `0` and the shutdown's `1`, never why a quit may answer `0`. Its searches of `specs/` either looked for `close tab`, `close_tab` and `close button`, which §6's wording does not match, or covered other specs, and its transcript never reads the table.
- **W8 modelled the route instead of taking it.** `closing_the_tab_exits_1` in `wolf_wait.rs` closes the tab with a bare `core.shutdown()`. Neither front-end does that for a live tab once this task lands, so W8 passed while the user-facing route broke the spec (review 1 §3). W21 now takes the real route, and W8's doc calls it the unchecked close.
- **The round cost $6.54 and about 30 minutes.** The added invocations were `architect-2` $1.56, `test-writer-2` $0.66, `coder-2` $0.94, `technical-writer-2` $1.03 and `reviewer-2` $2.35. The later Close Window task of this request changes a close route again, and it meets the same unlinked contract.
- **Plan 1 assigned words to entries that had none.** Plan 1 §5 named no entry's count, and `architect-1` never ran `--entry-words`. `technical-writer-1` first counted at its 72nd tool call, after 19 scripted edits, then reworked five and dropped planned items from `AppDelegate.swift`, `AppMenu.swift`, `WolfWindowController.swift`, `tab_view.rs` and `shell.rs`. This is recommendation 4 of [application-state-4](application-state-4.md), come up again: `.claude/skills/regina/agents/architect.md` still does not name the flag.
- **The stale `close_window` wording that close-commands-2-1 listed is still there.** `restore.rs:210` and `:1755`, and `shell.rs:43`, `:1784` and `:1807`, still name only `close_window`, though this task edited `shell.rs`. It also left K1's failure text at `crates/wolf-core/tests/commands.rs:1050`, "without running the quit's check", which names plan 1's design (review 2 §5). This is recommendation 4 of [close-commands-2-1](close-commands-2-1.md), come up again.
- **A Linux test timed out under the gate's load.** `coder-2`'s first Linux `./gates.sh` failed only in `no_quit_command_notifies_close_window` in `--test commands`, with the 10 s `FLUSH_TIMEOUT` on `:xit`, and the suite took 29.49 s against about 5.4 s alone. It cost five diagnostic runs and a second gate run of about 5.5 minutes. [tabs-and-preview-5](tabs-and-preview-5.md) records the same 10 s timeout in `drawer_last_pane`.
- **The Linux falsifier runs hid their exit status again.** All 26 of `coder-1`'s falsifier runs on Linux piped `cargo test` into `grep`, so each recorded exit 0 and review 1 §4 read the reds from the `FAILED` lines. [close-commands-2-1](close-commands-2-1.md) found the same and made no recommendation.

## Recommendations

1. **Say why a quit may end a wait with `0`, where `do_quit` links.** In `notes/runtime/nvim/init.lua.md#waits-end-before-the-tab-closes`, add that the `0` is §6 row 1's buffer close, that it holds only for the quit family, and that any other close must leave the waits to the shutdown's `1`, linking `specs/cli-and-file-open.md#6-waiting`. Give `do_quit`'s `end_waits` comment in `runtime/nvim/init.lua` the same link. Plan 1 D1 rested on exactly that section, and it would have saved the $6.54 round, which the Close Window task can still hit.
2. **Have the architect count entry budgets.** This is recommendation 4 of [application-state-4](application-state-4.md), come up again. In the documentation item of `.claude/skills/regina/agents/architect.md`, require `./tools/lint/markdown_check.sh --entry-words <file>` for every entry plan §5 adds to, and a cut or a destination for each entry at its cap. [fixes-1](fixes-1.md) and [pane-ui-1](pane-ui-1.md) show the writer then has no overrun; here five planned items were dropped instead.
3. **Make a Linux falsifier report its own status.** In `.claude/skills/regina/agents/coder.md`, where falsifiers are described, say to write the run to a file and print its status before filtering, as `cargo test … >"$log" 2>&1; echo "exit=$?"; grep … "$log"`. It came up in both tasks of this request, and each review had to read the reds from the output.
4. **Fix the stale wording, as [close-commands-2-1](close-commands-2-1.md) recommendation 4 lists it.** Add `crates/wolf-core/tests/commands.rs:1050`'s "the quit's check" to that list. The remaining tasks of this request edit `shell.rs` again, and each one reads the wrong command names there.
5. **Look at the `commands` suite's timeouts under load.** Check whether `no_quit_command_notifies_close_window`'s 10 s wait in `crates/wolf-core/tests/commands.rs` races the gate's parallel `cargo test`, as [tabs-and-preview-5](tabs-and-preview-5.md) recommendation 4 asks of `drawer_last_pane`. One flake cost a Linux gate run here.
