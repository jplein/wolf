# Linux project search moves from an overlay into a sidebar panel

Last verified at commit `10d54dda13a1b5e2f89376e58df02623b2756ea4`.

The task replaced `crates/wolf-gnome/src/search_overlay.rs` with `search_panel.rs` and `sidebar.rs`, a Files/Search `gtk::Stack` in the sidebar. It added `tests/sidebar_search.rs` and two cage smokes, and recorded the GTK divergences under allowlist entry A8. It took eight invocations and about $40.57, and review 1 approved with minor notes. The only round trip was a Linux implementation gate that failed on a smoke this change did not touch.

## What went well

- **The macOS counterpart was documented file by file.** The instructions could name the `SearchView.swift`, `SidebarContainerView.swift` and `SearchWakeBridge.swift` entries, and review 1 §1 checked parity against `CommandDispatcher.swift` and `showSidebar(panel:)` directly. No agent had to work out what macOS does from the Swift alone.
- **wolf-core's search API was enough as it stood.** `start_search`, `SearchSession`, `project`, `context_window`, `open_at` and `preview_file` covered the panel, so the diff touches no file outside `crates/wolf-gnome`, its docs and the wording allowlist. `search_status` and `search_options_for` moved over byte for byte, and `tree_gate::TreeRefreshGate` served the second page unchanged.
- **The pure-seam split made falsifiers cheap.** Every panel rule sits in a pure function of `search_panel.rs` or `sidebar.rs`, so `coder-1` measured about 30 falsifiers as single `cargo test --exact` runs on Linux (its commands 14 to 42), and review 1 §4 matched each to its command log. Keep new GTK logic in such seams.
- **The divergence convention was ready to use.** [retro-fixes-5](retro-fixes-5.md) and the wolf-gnome wording lint told plan 1 exactly how to record the four GTK divergences: a module-doc section linking `#searchviewswift`, and two allowlist lines under A8. Review 1 §1 found them matching, with no rework.

## What did not go well

- **An unrelated smoke failed the Linux gate, and the round trip cost $3.71.** `implementation-1` failed on Linux only in `three_tabs_survive_a_relaunch_under_cage`, where run 1's tab 2 saved `tbravo.md` and not `tcharlie.md`. The same sources had passed it in `coder-1`'s own Linux gate. `architect-2` ($2.83, 45 turns) proved by sha256 and by reading the smoke that the change was not the cause, then `test-writer-2` ($0.46) and `coder-2` ($0.42) ran, and both gates ran again. `coder-2` ran the smoke 5 times alone and it passed every time.
- **Plan 2's lead on that flake is recorded nowhere in the repository.** In `pane_view::pick_initial_window`, when `Snapshot::active_win` is not yet in `Snapshot::windows`, the fallback takes the lowest visible grid. After `:tabnew`, `WinEnter` and `TabEnter` arrive before the redraw flush that adds the new window, so that grid can be the previous tab's, and tab 2's pane binds tab 1's window. Plan 2 chose not to document it because it is unproven, so this report is its only record.
- **This is the third first-action race in recent reports.** [open-items-12](open-items-12.md) and [open-items-14](open-items-14.md) recorded real-nvim tests whose first action seems to land before startup state settles. Those cost a coder's gate rerun, but this one hit Regina's gate, where the only way forward is a new plan.
- **Plan 1 named falsifiers the tests it planned could not show.** It listed "drop the advance guard" for `char_budget`, but every row that guard catches the quotient guard also catches, and `coder-1`'s command 25 stayed green. In the same way, plan 1's smoke A falsifiers for assertions 3 and 4 failed at assertion 2 first, and smoke B row 3's named a call the panel cannot make. `test-writer-1` runs no tests and `coder-1` may not edit them, so these gaps were closed only because the flake forced plan 2, which says a reviewer would otherwise have sent each one back.
- **A smoke's classification is written twice, and one copy went stale.** Each smoke in `crates/wolf-gnome/tests/smoke_headless.rs` classifies its assertions in a doc-comment table and again in an inline `// Assertion N (discriminator)` comment. Plan 2 reclassified smoke A's assertions 3 and 4 but kept `test-writer-2` to doc comments, so lines 18726 and 18740 still say "discriminator" (review 1 note 1). This defect landed.
- **The OCR smokes depend on a style class.** On the first green-path run both smokes failed with the panel drawn correctly, because tesseract `--psm 11` read nothing from a row under Adwaita's accent selection. `coder-1` spent six Linux runs and a fetched capture (its commands 5 to 10) before adding libadwaita's `navigation-sidebar` class. That is recorded on `SEARCH_LIST_CSS` and in the `search_panel.rs` entry, but not in "Smoke conventions" in `crates/wolf-gnome/tests/README.md`, where the next writer of an OCR smoke would look.
- **One smoke's parts are spread across a 38,021-line file.** The task's diff to `smoke_headless.rs` has 53 hunks, in the fixture constants near line 1600, the scenario script near 3300, `ASSERTED_OCR_TERMS`, `RELAUNCH_FIXTURE_NAMES`, two guards near 14100 and 14800, and the smokes near 18700. `test-writer-1` ran about 40 shell commands against the file and cost $7.98. [open-items-6](open-items-6.md) saw agents navigate it by line number at 37,508 lines, but recommended nothing for it.
- **Documents were at their limits again.** The `shell.rs` entry of `crates/wolf-gnome/src/README.md` was at 250 words, so `technical-writer-1` put the focus-parking rule in `notes/wolf-gnome-decisions.md`. That note ended at 90,982 bytes and `crates/wolf-gnome/tests/README.md` at 91,381, both past the 50,000-byte warning. `src/README.md` ended at 83,451.
- **Hand-kept counts drifted.** `notes/feat-list.md` said 26 commands, 21 dispatched and 4 deferred before this task, while `ui_action_for` already had 28 arms. `technical-writer-1` recounted it to 28, 24, 1 and 3, and counted `#[test]` and `*_under_cage` by `grep` to update the smoke and OCR counts in `tests/README.md`.
- **Smaller landed defects.** Review 1 note 2: a click on the switcher's Files button runs no focus-parking code, and whether focus leaves the entry is unmeasured. Note 3: `palette.rs:447` says "(as in `search_panel`)" of Pango ellipsizing, which holds only for the panel's file rows.

## Recommendations

1. **Fix or rule out the first-pane binding race.** In `crates/wolf-gnome/src/pane_view.rs`, have `pick_initial_window` refuse, not fall back to the lowest grid, when `current_tabpage` changed and `active_win` is not yet in `windows`, and add a table row for it. Measure it red against `three_tabs_survive_a_relaunch_under_cage`. This task's gate failure cost $3.71 and a second run of both gates, and it is the third such race after [open-items-12](open-items-12.md) and [open-items-14](open-items-14.md).
2. **Let the architect check a planned falsifier against the planned rows.** In `.claude/skills/regina/agents/architect.md`, require that each falsifier the test plan names is caught by a row the plan itself lists, and that a smoke's falsifier is said to fail at the assertion it is listed under only when that assertion comes first. Plan 1's `char_budget` and smoke A rows 3 and 4 fail that check. [open-items-7](open-items-7.md) recorded a planned falsifier that could not turn half its test red, and here it needed a second plan and a second test writer.
3. **Classify each smoke assertion once.** In `smoke_headless.rs`, drop "(discriminator)" and "(corroboration)" from the inline `// Assertion N` comments and leave the kind to the doc table, starting with lines 18726 and 18740, which are wrong now. A reclassification then edits one place, and a doc-only plan like plan 2 cannot leave the code comments behind.
4. **Add the accent-selection fact to "Smoke conventions".** In `crates/wolf-gnome/tests/README.md`, say in one bullet that tesseract reads no text from a row under Adwaita's accent selection, and link the `search_panel.rs` entry's `navigation-sidebar` decision. `coder-1` spent six Linux runs to find this.
5. **Split `smoke_headless.rs` by feature.** Turn it into `tests/smoke_headless/main.rs` with a module per feature, holding its constants, scenario script and smokes, and keep the shared registries and guards (`ASSERTED_OCR_TERMS`, `RELAUNCH_FIXTURE_NAMES`, `restore_fixture_names_cannot_satisfy_their_own_assertions`) in one module. The file's mirror under `notes/` would follow it. Two smokes here touched eight regions of one file, and [open-items-6](open-items-6.md) saw the same cost.
6. **Split the over-budget documents.** This came up again: it is recommendation 6 of [round-3-9](round-3-9.md) and 7 of [round-3-10](round-3-10.md). Here `notes/wolf-gnome-decisions.md` and `crates/wolf-gnome/tests/README.md` passed 90,000 bytes, and a rule went to the decisions note because its entry had no words left.
7. **Drop hand-kept counts from prose.** In `notes/feat-list.md`, replace "Of the 28 commands, 24 dispatch…" with a link to `ui_action_for` and `EXPECTED_DISPATCHED_IDS` in `command_action.rs`, and do the same for the smoke and OCR counts in `crates/wolf-gnome/tests/README.md`. This is the pattern of [open-items-4](open-items-4.md) recommendation 1, and here a count was already wrong before the task began.
