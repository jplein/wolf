# Retrospective: split and cut the GNOME tests and src READMEs under 50 KB

Last verified at commit `2b8e222ce748550ac0faac99a0edf46d0aca6d73`.

The task moved the `smoke_headless/*` entries, Smoke conventions and Pointer injection into a new `crates/wolf-gnome/tests/smoke_headless/README.md`. It moved the "What is still unproven" ledger to `notes/crates/wolf-gnome/tests/what-is-still-unproven.md` and cut `crates/wolf-gnome/src/README.md` by the two-question test. The four files ended at 42,619, 45,956, 44,771 and 47,485 bytes, from 150,307 and 103,749 for the two READMEs. This carries out recommendation 1 of [cli-open-2-4](cli-open-2-4.md) for `wolf-gnome`.

There was one round trip: review 1 rejected the technical writer's work on two findings. The eight invocations cost $31.55 in about 94 minutes. They were `architect-1` $6.72 (74 turns), `test-writer-1` $3.55 (81), `coder-1` $0.64 (22), `technical-writer-1` $11.61 (93), `reviewer-1` $5.17 (66), `architect-2` $1.97 (37), `technical-writer-2` $0.74 (15) and `reviewer-2` $1.15 (23).

## What went well

- **`doc-lint same-code` made the comment-only rule checkable.** The task allowed no code change beyond comment links. `test-writer-1` and `coder-1` each proved every edited `.rs` with one `same-code` run against a base copy, and `coder-1` showed the check can fail with a renamed `fn` (exit 1). The coder's whole share cost $0.64.
- **doc-lint `--root` found the broken links mechanically.** Once the sections had moved, it listed every relative Markdown link and anchor into them. `technical-writer-1` fixed about 22 such links in the parent from its output, and the plan's moved-anchor grep printed nothing afterwards. Only the anchor-less prose citations in plan 1 §5 needed a hand search.
- **The `wolf-gnome` module docs already held the decisions.** `technical-writer-1`'s first pass, on R1 to R5 only, reached 73 K, and its second cut a Decision only where the comment at the site states it, logged as `file:line`, which reached 43 K. `reviewer-1` sampled about 25 of those cuts against the code, and all held. Keep each module's rules in its module doc, and keep the src README intro's sentence that says so, which stops agents copying them back.
- **The markdown checker's `--entry-words` gave a per-entry measure.** Plans 1 and 2 set their targets in words per entry, and both writers and reviewers checked them in one command. The src README's largest entry is 176 words, down from a cap of 250 that most entries had reached.

## What did not go well

- **Review 1 rejected on 67 pure-seam names the cut had dropped.** Plan 1 D8 R1 kept "each pure seam's name", because `notes/wolf-gnome-decisions.md` "The pure seams" says `src/README.md` "names them file by file". `technical-writer-1` rewrote the 100 KB file whole with `Write`, twice, and the names went with the signatures. Plan 1 exempted R1 cuts from the cut log, so only `reviewer-1`'s own script, listing the `pub` items each entry no longer named, found the loss.
- **What that round trip cost.** `architect-2`, `technical-writer-2` and `reviewer-2` added $3.86 and about 12 minutes. Of that, $1.97 was `architect-2` deciding which names count as seams: D10 had to rule out the glue types (`*Handle`, `*Parts`, `Coordinator` and others) one by one. The writer finished at 43,298 bytes against an aim of 47,000, so there was room for the names. The cause in the repository is a claim in one document about another document's content, with nothing checking it.
- **One ledger cut reversed a fact.** The zoom item's "onto the open drawer Toggle Terminal focuses" became "onto the drawer Toggle Terminal opens", contrary to leg H of `zoom_pane.rs` (review 1, finding 2). That is a wording slip in a 12 KB cut, and nothing in the repository invited it. Three more ledger clauses lost without a cut-log line were restored in the same round (plan 2 D12).
- **The new smoke README belongs to the test writer alone, against its definition.** In `.claude/skills/regina/flow.yaml`, the `tests` set's `/crates/*/tests/**` matches the `smoke_headless` directory, and gitignore semantics let no later `!` take a file back out. Plan 1 D2 therefore had `test-writer-1` write and cut a README, which its definition forbids ("Write no `README.md`"). `technical-writer-1` was told not to touch the file. This cost nothing here, but every later task that changes a smoke's entry will meet the same refusal.
- **Some citations were stale at the base and still are.** `pane_view.rs` has four "See `crates/wolf-gnome/src/README.md`" focus references, and `wolf-core/tests/nav_history_live.rs` makes four claims about history recording that the entries do not hold (review 1 §5). `smoke_headless/config.rs:465` cites a third ledger item that exists in neither version of the ledger. The panic strings in `smoke_headless/editor.rs` and `pointer.rs` still name `tests/README.md`, which is why the parent keeps a stub "What is still unproven" heading (plan 1 D4).
- **Two connectives in the landed src README are loose.** In `open_folder.rs`'s entry, "over `LiveWindow` readings" reads as if it applies to `plan` and `fill_size` too, but only `step` takes them. In `liveness_ui.rs`'s entry, "as a `TerminalRestore`" describes a `Vec` (review 2 §2).

## Recommendations

1. **Make the pure-seam inventory one checked fact.** `notes/wolf-gnome-decisions.md:45` defers the list of seams to `crates/wolf-gnome/src/README.md`, and nothing holds the README to that, which here cost a rejection and $3.86. Plan 2 §4's `check.sh`, which checks that each listed name appears backticked in its entry, could become a markdown-checker rule once the seam and glue split that D10 worked out by hand is written down where a script can read it. Short of that, move the inventory into each module's `//!` doc and rewrite line 45 to say so, so that a README cut cannot remove it.
2. **Keep nested test READMEs in `docs`.** In `.claude/skills/regina/flow.yaml`, replace `/crates/*/tests/**` and its negation with `/crates/*/tests/**/*.rs` and `/crates/*/tests/testdata/**`. The only other tracked files under `crates/*/tests/` are the five READMEs, so this gives `smoke_headless/README.md` to the technical writer and moves nothing else. Plan 1 D2 and its closing note asked for it, to be made between requests.
3. **Fix the stale citations in a task that may change code.** Re-point or delete the focus references at `pane_view.rs:163`, `:3056`, `:3389` and `:4262`, rewrite the claims at `nav_history_live.rs:34`, `:1938`, `:2021` and `:2131`, and drop `config.rs:465`'s third ledger item. Then re-point the `editor.rs` and `pointer.rs:1599` panic strings to the ledger, which lets the parent drop its stub heading.
4. **Carry recommendation 1 of [cli-open-2-4](cli-open-2-4.md) on to the eight files still over the warning.** The documentation gate warned on `crates/wolf-core/tests/README.md` (75,659 bytes), `runtime/nvim/README.md`, `WolfKeyMap/README.md`, `notes/wolf-macos-decisions.md`, `crates/wolf-core/src/README.md`, `WolfKeyMapTests/README.md`, `WolfMacOS/README.md` and `crates/wolf-ffi/src/README.md`. Reuse plan 1's R6 rule, a Decision cut only where its site's comment states it, logged as `file:line`. Check names as plan 2 did wherever a document relies on them.
