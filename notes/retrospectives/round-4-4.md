# Split `smoke_headless.rs` by feature and give the `flake.nix` guards their own binary

Last verified at commit `98cc8977f6744f393c8b19a7f37366c82124f966`.

The task ran straight through: `architect-1`, `test-writer-1`, `coder-1`, `technical-writer-1` and `reviewer-1` each ran once, and both gates passed on both workers on their first run. There was no rejection, non-zero gate, discrepancy or resume. The five invocations cost about $25.15: the architect $7.79 (21 minutes), the test writer $8.64 (122 turns), the coder $2.44, the technical writer $2.87 and the reviewer $3.39.

## What went well

- **Cargo discovers `tests/<name>/main.rs` as a test target, and wolf-gnome has no `BUILD.bazel`.** The 39,100-line file became `crates/wolf-gnome/tests/smoke_headless/` with fifteen modules, and `--test smoke_headless` kept working with no wiring. Review 1 §3 confirmed nothing needed Bazel. The largest file is `main.rs` at 5,204 lines.
- **The base file's naming prefixes made the split scriptable.** Items already carried feature prefixes (`PICKER_*`, `DRAWER_*`, `TWOWIN_*`), so plan 1's module map could assign them by prefix plus one placement rule. `test-writer-1` sliced the file with three Python scripts (its commands 13 to 25), rather than moving items by hand. Its one deviation, `write_relaunch_fixtures` in `main.rs`, followed the plan's own rule.
- **`doc-lint strip` gave a mechanical verbatim check.** Plan 1's E3 compared stripped line multisets of the old and new files. `test-writer-1`, `coder-1` and `reviewer-1` each ran it, and review 1 §1 could approve the move without reading 39,000 lines. Keep `strip` as a subcommand.
- **doc-lint's `md-link` rule let the architect predict the one gate finding.** Plan 1 D8 knew that `doc-lint --root` in the implementation gate would fail on `tools/wolf-pointer-inject/README.md`'s link to the old file, and gave that link to the coder. The implementation gate passed on its first run because of it.
- **The cage-slot design is written where an architect finds it.** The instructions said the smokes "share a compositor and must stay serial", which is wrong. Plan 1 D2 read `CAGE_SLOTS` and `smoke_jobs()` and kept one binary for the right reason, a per-process semaphore, at no cost.
- **The split binary does what the reports asked.** `cargo test -p wolf-gnome --test flake_exports` took 0.3 s after a `touch` (`coder-1`, E4), against a cage run of about 70 s. A `flake.nix` comment now leads to it through `notes/flake.nix.md#shellhook-exports`.

## What did not go well

- **Formatting wolf-gnome from the macOS worker was still done by hand.** `test-writer-1` ran `cargo fmt --check` on the Linux worker and applied its hunks locally with a script it wrote, `applyfmt.py` (its commands 98 to 100). Plan 1 step 1.4 told it to, because no other route exists. This is [ghostty-4](ghostty-4.md) recommendation 1, which came up again.
- **A deeper mirror path pushed five link comments over the width limit.** `See notes/crates/wolf-gnome/tests/smoke_headless/<module>.rs.md#<anchor>` is about 20 characters longer than the old link. `test-writer-1`'s doc-lint run found five comments over 100 characters that plan 1 had not foreseen, and it took seven commands to rewrap them, four of them on one `sidebar.rs` comment (commands 107 to 113). In `preview_render.rs`, `See ` plus the path alone is over 100, so the path sits alone on the second line.
- **A suite count survived the count sweep.** `crates/wolf-gnome/tests/smoke_headless/main.rs` line 4540 still opens "The fifth compositor-free guard:", an ordinal from the guard catalog this task removed. Plan 1 D6 listed the count sites by their text, and an ordinal was not among them. `technical-writer-1` and review 1 N1 both flagged it, and it landed. Counts have been stale before: see [round-4-1](round-4-1.md) recommendation 1 and [round-4-3](round-4-3.md).
- **`assert_reads_every_module` accepts only a bare `mod <name>;` line.** Review 1 N2 found that a `pub(crate) mod` or a `#[path]` module in `smoke_headless/main.rs` would go unchecked by the new vacuity check, and no red run covers it. Nothing breaks today, because every declaration is bare.
- **A stale assertion message moved with the code.** In `crates/wolf-gnome/tests/smoke_headless/restore.rs`, the `!preview` assertion of `single_pane_file_survives_relaunch_under_cage` says "wolf-gnome has no Markdown preview" and that `encode` sets the flag to false unconditionally. Neither is true: `preview.rs` tests the preview, and `encode` writes `content.preview`. `coder-1` saw it while running F6, and the task forbade changing a smoke.
- **The plan was read two or three times by every agent.** Plan 1 is 42 KB, over the Bash tool's output limit, so `test-writer-1`, `coder-1` and `technical-writer-1` each ran `cat` on it, got a truncated preview and read it again in pieces. The cost is a few calls each, and [retro-fixes-5](retro-fixes-5.md) recommendation 3 already asks for plans by rule rather than by site.
- **The tests README grew again.** `technical-writer-1` added one entry per module and `crates/wolf-gnome/tests/README.md` went from 93,785 to 98,572 bytes, about twice the big-file warning. This is [round-3-10](round-3-10.md) recommendation 7, which came up again.

## Recommendations

1. **Let the macOS worker format wolf-gnome.** This is [ghostty-4](ghostty-4.md) recommendation 1, and it came up again: `test-writer-1` applied remote `cargo fmt` hunks with a script of its own. It would have saved three commands and a script here, and it saves the same in every task that edits wolf-gnome Rust.
2. **Exempt a `See <single token>` line from doc-lint's width limit.** In `tools/doc-lint`, treat a comment line whose text is `See ` followed by one whitespace-free path as the width rule already treats a bare path. `test-writer-1`'s seven rewrap commands and the bare-path line in `preview_render.rs` both come from mirror links under nested test directories, which this split made deeper.
3. **Remove the leftover ordinal and fix the stale message.** In `crates/wolf-gnome/tests/smoke_headless/main.rs` line 4540, write "A compositor-free guard:". In `restore.rs`, rewrite the `!preview` message of `single_pane_file_survives_relaunch_under_cage` to say what the check guards, a single-pane file restored with `:edit`, without claiming wolf-gnome has no preview.
4. **Make `assert_reads_every_module` read any `mod` declaration.** In `crates/wolf-gnome/tests/smoke_headless/main.rs`, strip a visibility prefix before matching `mod <name>;`, and fail on a `#[path]` attribute in front of one, with a falsifier run that adds `pub(crate) mod x;`. Review 1 N2 found the gap, and closing it keeps the source guards from going vacuous after the next module is added.
