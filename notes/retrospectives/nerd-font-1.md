# Task 1 of nerd-font: vendor Symbols Nerd Font Mono and ship it on macOS and GNOME

Last verified at commit `3ae95f85520fa100f757c78f4ca756cbfeff2926`.

The task pinned the Nerd Fonts v3.5.1 symbols-only release, added `//bazel/nerd-fonts-symbols`, bundled the Mono face into `Wolf.app`, installed it in the GNOME package and the devShell's `fonts.conf`, and added a fifth `FONT_LICENSES` row. It took seven invocations and about $22.80: `architect-1` $7.75, `test-writer-1` $2.68, `coder-1` $5.07, `architect-2` $1.20, `coder-2` $0.43, `technical-writer-1` $3.18 and `reviewer-1` $2.46. Review 1 approved with minor notes on its first pass.

The one round trip was `coder-1` returning `failed` because the Linux worker's disk was full. `architect-2` wrote plan 2 to drop the coder's own Linux gate run, and `coder-2` made one comment reflow. Both implementation gate runs passed on macOS; the first was unreachable on Linux, and the second passed there after the disk was freed outside the flow.

## What went well

- **Sibling pin packages made the Bazel side a copy.** Plan 1 §2 told the coder to model `extensions.bzl` and `BUILD.bazel` on `bazel/jetbrains-mono`, and the tree, its `sh_test` and the `Wolf` `resources` entry went green on macOS without a fix. `FontRegistration.swift` already registers every `.ttf` under `fonts/`, so the Swift change was a doc comment.
- **`crates/wolf-gnome/tests/vendored_pins.rs` guarded the two-sided pin.** It already compared `flake.nix`'s `wolfVendoredPins` with each `extensions.bzl`, so plan 1 D4 only taught it a release-version pin beside the commit pin. This is the third task to lean on it, after [open-items-3](open-items-3.md) and [regina-land-terminfo-2](regina-land-terminfo-2.md).
- **The licence registry's per-surface tests named every place to touch.** `licenses.rs`, `about.rs`, `markdown_render.rs` and `font_license_notices.rs` each check every row by phrase, so C8a to C13a each went red at one surface. The `compile_data` glob `src/licenses/*.txt` in `crates/wolf-core/BUILD.bazel` picked up the new text with no build edit.

## What did not go well

- **The Linux worker's disk filled during `coder-1`, and its `flake.nix` falsifiers fed it.** The definition in `.claude/skills/regina/agents/coder.md` says "A remote snapshot carries the disabling edit", so `coder-1` edited `flake.nix` locally for C6a, C6b and C7a. Each distinct `flake.nix` provisions a new podman image, and requests 14, 16 and 18 failed provisioning with "no space left on device". Its own `regina on linux -- ./gates.sh` then failed at build and test with `os error 28`, and `coder-1` returned `failed`.
- **What the round trip cost.** `architect-2` ($1.20, 18 turns) and `coder-2` ($0.43, 12 turns) were added, plus an unreachable Linux leg in the first implementation gate run. The full disk itself was the host's, and nothing in the repository caused it. What the repository could change is that no document told the coder that a local `flake.nix` edit costs a full image; `coder-1` found the remedy, a `sed -i` inside the remote `sh -c`, only after the failures.
- **A known Podman failure cost a base-package build to rule out.** `smoke_headless`'s `packaged::the_packaged_binary_opens_a_preview_under_cage` failed under `tools/wolf-package-smoke.sh`, and `coder-1` built the base commit's package in a worktree on Linux to show it fails there too. That it cannot pass under Podman was already in plan 2 §8 of the `terminfo` task, recorded only in [regina-land-terminfo-2](regina-land-terminfo-2.md), not in `crates/wolf-gnome/tests/README.md` where a coder looks.
- **Hand-kept font counts drove a sweep of about 25 sites in 12 files.** Plan 1 §3 and §5 listed each "four fonts", "three of the four", "both font families" and `[(&str, &str); 4]` to reword, in `licenses.rs`, `lib.rs`, `markdown.rs`, `about.rs`, `pane_view.rs`, `markdown_render.rs`, `vendored_pins.rs`, `flake.nix`, `fonts.conf` and four READMEs. The plan missed `build.md`'s "three vendored families", which `coder-1` reported and plan 2 D13 added.
- **The task added new counts while removing old ones.** Plan 1 asked for the `fonts.conf` header to count "four pinned font directories" and the `NO_SUCH_FAMILY` doc in `paint_golden.rs` to say "exactly four pinned font trees". Review 1 flagged both, and `crates/wolf-macos/release.bzl` still says the bundle carries "two font families". The next face edits all three again.
- **`fonts.conf` comments are outside doc-lint.** `coder-1` left two 104-character lines in the XML header of `crates/wolf-gnome/testdata/fonts.conf`, and only `architect-2` noticed, so `coder-2` spent an invocation on a reflow. doc-lint does not scan XML comments, so no gate would have caught it.
- **No font tool was available, so the architect wrote a TrueType parser.** To settle the Mono-versus-proportional question of plan 1 D2, `architect-1` wrote `struct`-based Python scripts for `cmap`, `hmtx` and glyph bounds, and rewrote one at the end to correct its overshoot count. `technical-writer-1` then found that "850 glyphs reach past that advance" holds only counting either side, and worded the pin README that way.
- **Plan 1 D7 kept the new package's comments from linking its README.** The README is the technical writer's, and the implementation gate runs before it exists, so a link would fail doc-lint's `doc-ref`. The comments in `BUILD.bazel`, `extensions.bzl` and the tree test say "this package's README.md", which doc-lint does not check, where `bazel/jetbrains-mono/BUILD.bazel` links its README by path.

## Recommendations

1. **Tell the coder how to falsify `flake.nix` on Linux.** In `.claude/skills/regina/agents/coder.md`, next to "A remote snapshot carries the disabling edit", say that a disabling edit to `flake.nix` goes inside the remote command, as `regina on linux -- sh -c 'sed -i … flake.nix && …'`, because a local edit provisions a new image. `coder-1`'s requests 14, 16 and 18 each tried to build one, and all three failed on a full disk; plan 2 D10 had to state the rule after the fact.
2. **Record the Podman-only cage failure where the package tests are documented.** In the `smoke_headless` entry of `crates/wolf-gnome/tests/README.md`, say that `packaged::the_packaged_binary_opens_a_preview_under_cage` fails under rootless Podman and why. `coder-1` spent a base-commit `nix build` of `wolf-gnome` on a nearly full disk to learn it, and the fact sat only in a retrospective.
3. **Drop the hand-kept font counts.** This is recommendation 7 of [round-3-11](round-3-11.md), recommendation 3 of [ghostty-4](ghostty-4.md) and recommendation 5 of [ghostty-5](ghostty-5.md), come up again for fonts. Reword the `fonts.conf` header, the `NO_SUCH_FAMILY` doc in `paint_golden.rs` and the bundle list in `crates/wolf-macos/release.bzl` to name the trees without a number, and make the `PHRASES` tables in `about.rs` and `markdown_render.rs` slices so only `EXPECT_FONT_COUNT` in `licenses.rs` holds the count. s01 and s02 of this request touch the same files.
4. **Link the new package's README from its comments.** Replace "this package's README.md" with `bazel/nerd-fonts-symbols/README.md` in `bazel/nerd-fonts-symbols/BUILD.bazel`, `extensions.bzl` and `nerd_fonts_symbols_tree_test.sh`, as `bazel/jetbrains-mono/BUILD.bazel` does, so doc-lint checks the reference. Review 1 noted the same.
