# Retrospective: a click in a GNOME preview's page makes the preview active

Last verified at commit `b4d4272b3fcaf112106c98e7fb559c6b80d64034`.

The task fixed `crates/wolf-gnome/src/pane_view.rs`: a press on a preview's page went to the `webkit6::WebView`, so the pane's own gesture never saw it. `sync_preview_view` now gives each web view a capture-phase primary `gtk::GestureClick` that calls `on_pane_clicked` and never claims. The test writer added the cage smoke `preview_page_click_activates_the_preview_under_cage` and current-window readbacks in the link smoke. It took five invocations, one each, at $14.29 and about 49 minutes, with no rejection, failed gate, discrepancy or resume.

## What went well

- **One focus path made the fix one gesture.** `on_pane_clicked` was already the strip press's whole focus path: `focus_win`, `set_active_pane` with its capture, and focus parked on the strip. Plan 1 §1 routed the page press through it, so the unzoom and capture rules needed no new code and no new test (plan 1 §4). The change to `pane_view.rs` was 32 lines, and review 1 §2 confirmed the task's "same rules" by construction.
- **A public constant let a pixel test read the chrome.** `STATUSBAR_INACTIVE_ALPHA` is `pub` in `crates/wolf-gnome/src/statusbar_layout.rs`, so the new smoke's strip rule reads the inactive dim from the source, not a retyped copy. That made "the active pane's chrome" observable from raw pixels, which the tests README had listed as unproven. Falsifier C1b showed the rule separates the strips (both inks 104, ratio 1.000, in `coder-1`'s request 8).
- **`regina on linux` made four falsifiers cheap.** Each of C1a, C1b, C2a and C2b ran as one Linux command of 9 to 12 seconds (`coder-1` requests 6 to 9), with the pre-fix reds in requests 2 and 3. `coder-1` cost $1.46 for the fix, the reds and both gates.
- **The previous report's first recommendation held.** Plan 1 §3 cited [sidebar-preview-1](sidebar-preview-1.md) recommendation 1, and the new smoke's doc table has no predicted-red column or list of falsifying edits. No falsifier claim in the test file could go stale, and review 1 §4 found each red where the plan put it.
- **`--entry-words` gave the plan the budget.** `architect-1` measured the `pane_view.rs` entry of `crates/wolf-gnome/src/README.md` at 249 of 250 words, and plan 1 §5 told the writer to cut as many words as it added. `technical-writer-1` landed it at 250 with no lint failure.
- **No wiring was needed.** `preview` is already a module of `smoke_headless`, and wolf-gnome has no Bazel target (`build.md`), so the new smoke ran in Linux's `implementation-1` with no edit outside the test file.

## What did not go well

- **The plan was a third of the cost, mostly reading.** `architect-1` cost $5.11 of $14.29 (70 turns, 14 minutes). It read `pane_view.rs` (302 KB), `smoke_headless/preview.rs` (256 KB at the base) and `crates/wolf-gnome/tests/README.md` (137 KB) in `sed -n` ranges, and fetched WebKit's `WebKitWebViewBase.cpp` once from GitHub. Its system prompt does not mention `regina on linux`, so the claim that a bubble-phase gesture would be denied is from source reading and was never run (review 1 note 4).
- **The test writer applied a remote `cargo fmt` diff by hand again.** `test-writer-1`'s definition says to read `regina on linux -- cargo fmt --all -- --check` and apply its diff. Its request 3 failed on the re-flowed import block of `fixture_guards.rs` and a `SampleRect` in `preview.rs`, and it rewrote the block with a Python script before request 4 passed. `//tools/lint:rustfmt_files.fix` exists and is listed in `tools/lint/README.md`, but neither the test writer's nor the coder's system prompt names it.
- **Five names in a smoke that OCRs nothing took 37 added lines in `fixture_guards.rs`.** Plan 1 §3 had `PCA_SOURCE_FILE`, `PCA_CUR_BEFORE_NAME`, `PCA_CUR_AFTER_NAME` and two `LINK_CUR_*` names imported and registered in `RELAUNCH_FIXTURE_NAMES`, each with the "this smoke reads no OCR term" comment. The long import list is also what `cargo fmt` re-flowed above.
- **The strip layout is derived by the same call in six smokes.** `preview.rs` added a sixth copy of `statusbar_layout(cell.size_px, secondary_font_size(cell.size_px), STATUSBAR_VERTICAL_PADDING, STATUSBAR_LINE_GAP)`, beside `symbols.rs`, `terminal.rs`, `terminal_colours.rs`, `titlebar.rs` and `zoom_pane.rs`. Plan 1 §3 had to spell it out "as `titlebar.rs` does", and a change to the strip's arguments must reach all six.
- **The `pane_view.rs` README entry is full.** At 249 words before the task, `technical-writer-1` needed three Python edit scripts on `crates/wolf-gnome/src/README.md` to cut words elsewhere in the entry for one bullet, and left it at 250. The Linux documentation gate still warns that the file is 99,468 bytes and the tests README 136,976.
- **The landed work keeps three small inaccuracies, all in review 1 §8.** In `crates/wolf-gnome/tests/README.md`, the "Pointer injection" paragraph still calls the link smoke's click "the only injected point aimed at something WebKit drew", which the mirror's matching sentence no longer says. `PCA_ALPHA_TOLERANCE`'s doc in `preview.rs` says "three quarters coverage" where the bound works out at about 77%. The link smoke's assertion 4 message does not list a claiming gesture among its causes, though C2b shows it is one.
- **The gates ran twice on an unchanged tree.** `coder-1` ran `./gates.sh` on both workers for about 7 of its 13 minutes, and Regina's `implementation-1` then ran them again for about 5. This is the coder definition's rule, and it cost wall time only, as [app-state-fixes-2](app-state-fixes-2.md) also found.

## Recommendations

1. **Point the agent definitions at `:rustfmt_files.fix`.** This is [round-4-6](round-4-6.md) recommendation 1, come up again: the test writer's and the coder's definitions under `.claude/skills/regina/agents/` still say to apply the remote `cargo fmt` diff. Naming `nix develop --command bazel run //tools/lint:rustfmt_files.fix -- <files>` would have saved `test-writer-1` a failed `fmt` run and a rewrite script.
2. **Exempt OCR-free smokes from `RELAUNCH_FIXTURE_NAMES`, or derive its entries.** This is [fixes-1](fixes-1.md) recommendation 7 and [regina-land-linux-titlebar](regina-land-linux-titlebar.md) recommendation 3, come up again. Here it was 37 lines in `crates/wolf-gnome/tests/smoke_headless/fixture_guards.rs` for five names that no assertion OCRs, and the import list that `cargo fmt` re-flowed.
3. **Give the smokes one strip-layout helper.** Add a function to `crates/wolf-gnome/tests/smoke_headless/main.rs` that takes the cell metrics and returns the `statusbar_layout` result. Replace the six identical four-argument calls in `preview.rs`, `symbols.rs`, `terminal.rs`, `terminal_colours.rs`, `titlebar.rs` and `zoom_pane.rs` with it. The next smoke that reads a strip, as this one did, would call it, and plan 1 would not have had to spell out the derivation.
4. **Give the architect `regina on linux`.** This is [nerd-font-3](nerd-font-3.md) recommendation 1 and [sidebar-preview-1](sidebar-preview-1.md) recommendation 3, come up again. A scratch run of a bubble-phase gesture would have measured what `architect-1` took from WebKit's source, which review 1 note 4 flags as unmeasured.
5. **Split the wolf-gnome READMEs.** This is [nerd-font-3](nerd-font-3.md) recommendation 7 and [round-4-6](round-4-6.md) recommendation 4, come up again. Here the `pane_view.rs` entry, at 249 of 250 words, cost three edit scripts to take one bullet.
6. **Fix review 1's three notes.** Reword the "Pointer injection" sentence in `crates/wolf-gnome/tests/README.md`, correct the coverage figure in `PCA_ALPHA_TOLERANCE`'s doc, and add a claiming gesture to the causes in `preview_link_click_repoints_the_pane_under_cage` assertion 4's message. Each is one sentence, and each is false or incomplete as it stands.
