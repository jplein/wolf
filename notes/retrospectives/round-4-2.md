# Retrospective: state the wake rule as a condition, skip an unchanged terminal resize, cut a GTK README restatement

Last verified at commit `c229a6e2b227f21089183336ea8da6f5f8232739`.

The task carried out three recommendations of [ghostty-2](ghostty-2.md) and [ghostty-4](ghostty-4.md). `specs/architecture.md` § The core↔front-end contract states which notifications wake as a condition, and the two READMEs link it. `Session::resize` skips a resize that changes nothing, and `crates/wolf-gnome/src/terminal/README.md` links the GTK note instead of restating it. Checking every notification against the new condition also removed a needless wake from `wolf_terminal_open`.

Its commits are `c9d8b22`, `fea6447`, `a870067` and `c229a6e`. The range from the base also holds `c9da7ed`, `633694e` and `f58e1e9`, which belong to [round-4-1](round-4-1.md).

There were two round trips. Review 1 rejected the resize guard (C1), which added plan 2. Then the Linux implementation gate failed on an unrelated flake, which added plan 3. Twelve invocations cost about $15.09, of which `architect-1` cost $4.09 (60 turns, 11.5 minutes), and the two round trips about $6.21.

## What went well

- **The task instructions were the earlier reports' recommendations, almost word for word.** Item 3 is [ghostty-4](ghostty-4.md) recommendation 7, and items 1 and 2 are [ghostty-2](ghostty-2.md) recommendations 1 and 2. Plan 1 needed no discovery for them. The spec edit, the two README links and the GTK cut passed review 1 unchanged.
- **The resize tests needed no wiring.** `crates/wolf-core/tests/terminal_session.rs` was already in `srcs` of `//crates/wolf-core:terminal_session`, with the real-Neovim runfiles. Both new tests went in as plain functions, and plans 1 and 2 could say "no wiring" with confidence. `test-writer-1` cost $0.78 and `test-writer-2` $0.72.
- **The single-test Bazel command made falsifiers cheap.** Plans 1 and 2 gave `bazel test //crates/wolf-core:terminal_session --test_arg=<name> --test_arg=--exact`. With it, `coder-1` recorded F1 to F3 red for $1.05, and `coder-2` recorded F4 and F5 for $0.68. Each restore was checked by checksum.
- **`regina on linux` let a flake be cleared without a code change.** `coder-3` ran `cargo test -p wolf-core --test nav_history_live` on Linux three times, all green. That took $0.27, nine turns and 69 seconds, and the next gate passed on both workers.
- **The front-ends' decisions notes held the resend rule that review 1 needed.** `notes/wolf-gnome-decisions.md` and `notes/wolf-macos-decisions.md` § Terminal panes both say a front-end resends a size when the frame's size differs. `reviewer-1` cited them to show that the plan 1 guard broke that resend.

## What did not go well

- **Plan 1's guard compared the wrong size, because the base code did not say that core keeps two.** Plan 1 D3 compared the request with `TermState.size`, which at the base commit had no doc comment, beside a `vt` whose grid libghostty-vt resizes by itself on `DECCOLM`. No document said so. Neither `crates/wolf-vt/src/README.md` nor the `Effect` enum mentions a grid change without a resize. Review 1 C1 caught it, and fixing it cost plan 2, `test-writer-2`, `coder-2` and a second technical writer and reviewer, about $5.10.
- **The resend that the guard broke is a cross-crate contract, written down only on the front-end side.** Core must apply a resize that the front-ends send when the frame's size differs. That rule lives in the two front-end decisions notes, not in `specs/terminal-panes.md`, `notes/wolf-core-decisions.md` or `crates/wolf-core/src/terminal/README.md`. Starting from core's documents, `architect-1` had no way to find it. The `Session::resize` and `TermState.size` doc comments added by `a870067` now give the reason on core's side, but the spec still does not.
- **Two invocations unpacked the libghostty-vt source to check the same fact.** `reviewer-1` and `architect-2` each ran 8 commands that found the source tarball in Bazel's cache, extracted it into scratch, and read `stream_terminal.zig` and `Terminal.zig` for `deccolm`. This is recommendation 3 of [ghostty-1](ghostty-1.md) and 4 of [ghostty-2](ghostty-2.md), come up again. `bazel/ghostty-vt/README.md` still does not say where the extracted source is.
- **A wolf-core live test flaked in the Linux gate.** `implementation-2` failed on Linux only, at `nav_history_live.rs:563` in `preview_transition_and_link_follow_are_tracked`. It reported "`preview_file(win, <abs b.md>)` must return b.md's source bufnr, got 0". The binary took 15.4 seconds, against about 8.2 seconds in each of `coder-3`'s green runs, which plan 3 D11 put down to the 5-second `RPC_TIMEOUT_DEFAULT` on a loaded worker. It cost `architect-3` and `coder-3`, $1.12, and a third implementation gate on both workers.
- **Flakes like this are not recorded anywhere.** `notes/crates/wolf-core/tests/nav_history_live.rs.md` says nothing about it, and neither does any other note. [round-4-1](round-4-1.md) lost a gate run to a different wolf-core flake, `open_existing_markdown`, in the task just before this one. So `architect-3` had to rule out this task's change by reading `init.lua`'s return paths. A note recording the flake would have let it skip that.
- **A defect from the base commit remains, now easier to see.** `TermState::cell_at` (`crates/wolf-core/src/terminal/session.rs`) says "clamped to the grid" but clamps to `self.size`, which the new doc comment calls the pty's size. When a `DECCOLM` grid differs from the pane, a click is mapped against the wrong width until the next resend. Plan 3 D12 and review 2 left it for a follow-up.
- **The markdown checker's all-caps rule flags a terminal sequence's name.** `technical-writer-2` searched `tools/lint/markdown_check.sh` for the `allcaps` rule and wrote out the escape sequence instead of the name `DECCOLM`, as review 2 §1 notes. This report's first documentation gate run failed on the same word in prose. The checker's message offers only bold or lowercase, though a code span passes.

## Recommendations

1. **Put the resize resend in the spec.** In `specs/terminal-panes.md`, state that a front-end resends its pane's size when the frame's size differs from it, and that core must apply such a resize even when the size matches what was last sent. Have both front-end decisions notes link that sentence. This task's C1 round trip, about $5.10, came from a core-side plan that could not see the rule.
2. **Document that the emulator's grid can change without a resize.** In the `lib.rs` entry of `crates/wolf-vt/src/README.md`, say that `Terminal::size()` can change inside a write, on `DECCOLM` once mode 40 is set, and that no `Effect` reports it. `architect-1` would then have compared `vt.size()` in plan 1 D3. `reviewer-1` and `architect-2` would not each have needed 8 commands of source reading to show it.
3. **Say where the pinned libghostty-vt source is.** This is recommendation 3 of [ghostty-1](ghostty-1.md) and 4 of [ghostty-2](ghostty-2.md), come up a third time. Add to `bazel/ghostty-vt/README.md` a command that extracts the `ghostty_vt_src` tarball from `$(bazel info output_base)/external/` into a scratch directory.
4. **Record the `nav_history_live` preview flake, and make its failure explain itself.** Add a `##` section to `notes/crates/wolf-core/tests/nav_history_live.rs.md` with the failing assertion and the slow run time from this task. Then make the assertion at `nav_history_live.rs:563` tell an RPC error or timeout in `WolfCore::preview_file` apart from a 0 returned by `init.lua`. The next `architect-3` would then read a cause rather than reason its way to one.
5. **Clamp `cell_at` to the grid.** In `TermState::cell_at`, clamp to `vt.size()` rather than `self.size`, as the doc comment already says, and test it with a click while the grid has a `DECCOLM` width. Plan 3 D12 and review 2 both left this open.
6. **Name the code span in the all-caps message.** In `tools/lint/markdown_check.sh`, add "or put a term in a code span" to the `allcaps` message, so a writer facing a name such as `DECCOLM` or `SIGWINCH` does not have to read the script, as `technical-writer-2` did.
