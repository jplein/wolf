# Retrospective: GNOME saves and restores through the app-state store, and `state.json` is removed

Last verified at commit `db6cc7c9c605b0386db1a830d03ab31356d8e5e8`.

The task switched `wolf-gnome` from `state.json` to `AppStateStore`, with stacking order and tab recency in `crates/wolf-gnome/src/stacking.rs`. It deleted the old model from `crates/wolf-core/src/state.rs` and made `Table::open_all` delete `state.json` and `state.json.tmp`. Its commits are `3e6c8fd` and `a927159` (code and tests) and `738e77f` and `db6cc7c` (documentation), 69 files from `cc9c7da`.

The 14 invocations cost about $71.49 and 174 minutes of agent time. Round 1 came to $54.50: `architect-1` $11.50, `test-writer-1` $17.50, `coder-1` $14.22, `technical-writer-1` $6.93 and `reviewer-1` $4.35. A review rejection, a coder dispute and one discrepancy added $16.99 and 53 minutes. Every gate run passed on both workers on its first try, so no rework came from a gate.

## What went well

- **The smokes read saved state through the store's own API.** At `cc9c7da` eight smoke files under `crates/wolf-gnome/tests/smoke_headless/` named `state.json` 119 times, 57 of them in `restore.rs`. `test-writer-1` replaced those reads with `freeze_state`, `frozen_window_state` and `frozen_project_state` in `main.rs`, which open a frozen copy through `AppStateStore::open(dir)`, and no smoke file queries the database itself. A later change to `window_state` or `project_state` touches those helpers and not the scenarios, so keep them the one route.
- **Pure seams made the F1 fix cheap, and it stood.** `state_seam::present_after` takes `&[bool]`, so `test-writer-2` wrote G7 as a table test with a compile red before code. `coder-2` ($2.00, 7.6 minutes) built the present chain and `WindowHandle::cancel_present` on it, plan 3 §2 kept that code as it was, and review 2 found no defect in it. `stacking.rs` and `app_state_seam.rs` did the same in round 1, where `coder-1` ran 28 falsifiers, G1a to G5e, with no compositor.
- **The instructions' done-grep was a mechanical finish line.** "A grep for `state.json` under `crates/`, `specs/` and `runtime/` finds only the launch-time deletion and its tests and docs" let review 1 §1 and review 2 §1 each confirm the removal with one command.
- **One deletion point served both front-ends.** `LEGACY_FILE_NAMES` in `crates/wolf-core/src/db.rs`, deleted on every `Table::open_all`, gave C1 a real-database test on both workers, and the macOS side of the task was an import path (review 1 §7).

## What did not go well

- **The same false note cost a round trip for the second time.** `notes/wolf-gnome-decisions.md` § The readiness file and the module doc of `crates/wolf-gnome/src/ready_seam.rs` said that under `cage` a toplevel "turns active only after a real key arrives". Plan 2 §1 built S3 on it as the seed's falsifier, although review 1 §3 had said that under `cage` every restored window takes focus. [regina-land-linux-titlebar](regina-land-linux-titlebar.md) found the same sentence false and asked for it to be corrected (its recommendation 1), and no cleanup round did.
- **The dispute cost $4.21 and was settled by one log line.** `coder-2` logged `focus 0`, `focus 1`, `focus 2` in map order before any key, S3a stayed green, and it returned `rejected`. `architect-3` ($1.95), `test-writer-3` ($0.68), `coder-3` ($0.79) and `coder-4` ($0.79) followed. Plan 3 corrected the claim in `ready_seam.rs`, the decisions note, S3's doc and `crates/wolf-gnome/tests/README.md`, and `test-writer-3` found a third copy in `tests/tab_focus.rs` ("turns active once and never resigns"). At `db6cc7c` `git grep` finds no copy outside `notes/retrospectives/`.
- **Review 1's F1 came from a premise plan 1 stated as fact.** Plan 1 D9 took build order as map order, and `coder-1` found it false under `cage` about twenty minutes in, from S1's run-2 readback. It built a frontmost-last wait rather than a chain, and S1 has two windows, so no test could see that three windows still came back out of order. This is recommendation 2 of [application-state-1](application-state-1.md), come up again: `.claude/skills/regina/agents/architect.md` still has no rule that an unmeasured premise is marked as one.
- **What `coder-1` measured reached the architect only through the review.** Its report named D9's false premise, S1c's edit that no longer reds, and C1's missing `\` continuations, and it returned `passed`. The last two were in test files the coder may not write, and they became review 1's F3 and F4. This is recommendation 2 of [application-state-3](application-state-3.md), come up again; a `rejected` would have saved one review and one writer pass.
- **The review round trip cost $12.78.** It took `architect-2` $3.40, `test-writer-2` $2.91 and `coder-2` $2.00, then `technical-writer-2` $1.47 and `reviewer-2` $3.00 after the dispute was settled.
- **A deleted test file lost a guard the plan said was covered.** Plan 1 deleted `crates/wolf-core/tests/state_layout.rs` because "everything it tests is deleted or covered", but `rebuild_layout_spec_escapes_paths` had no successor. `notes/wolf-core-decisions.md` § The rebuild-layout wire format gives that property as the reason the renderer is not hand-rolled. Review 1's F2 caught it, and C4 in `crates/wolf-core/tests/app_state_rules.rs` restored it.
- **`coder-3` ended its turn while the Linux gate ran, and its work was lost.** It had started `regina on linux -- ./gates.sh` in the background, and its last text was "I'll wait for it to complete". A worker's tools are `Bash`, `Edit`, `Glob`, `Grep`, `Read` and `Write`, and none wakes an agent when a background command ends, so the invocation ended with no output document. Regina removed its report, and `coder-4` ($0.79, 6.9 minutes) re-ran S3b, S3c and both gates.
- **The poll that works is not written down.** `coder-1` and `coder-4` waited on their background runs with a foreground `until grep -q '^exit ' <log>; do sleep 20; done`. The shared paragraph at `.claude/skills/regina/agents/coder.md:44` says only "poll it".
- **The fixture guard again took names from a smoke that OCRs nothing.** `a927159` changed 26 lines of `smoke_headless/fixture_guards.rs` to register S3's `wsa.md`, `wsb.md` and `wsc.md`, whose own comment in `restore.rs` says that they "serve the generic fixture loop only". This is recommendation 3 of [regina-land-linux-titlebar](regina-land-linux-titlebar.md) and 7 of [fixes-1](fixes-1.md), come up again.
- **The GNOME READMEs grew further past the ceiling.** `crates/wolf-gnome/tests/README.md` went from 118,166 to 121,885 bytes and `crates/wolf-gnome/src/README.md` from 93,187 to 94,452, against the 50,000-byte `big-file` warning. This is the finding of [regina-land-linux-titlebar](regina-land-linux-titlebar.md) and [regina-land-toast](regina-land-toast.md), come up again.
- **A spec the task did not open changed because it named a deleted type.** `specs/terminal-panes.md` § Session restore spelled the saved shape as `PaneNode::Leaf { path: <cwd>, preview: false, terminal: true }`, so deleting the model made it false. Plan 1 D16 rewrote it to link `specs/application-state.md`, and review 2 §6 flagged it for the user. - **The heal guard is still missing, and GNOME now writes a user's windows as well.** `open_or_heal` in `crates/wolf-core/src/db.rs` calls `remove_db_files` with no check that the file is the one that faulted. - **One landed doc overstates.** Review 2 §2 found that `present_after`'s doc at `crates/wolf-gnome/src/state_seam.rs:551` says a minimized window "never takes the focus" from the frontmost. With only one window not minimized, the two are presented in one burst, so that is not guaranteed.

## Recommendations

1. **Correct the documents retrospectives find false before anything else.** The `cage` sentence cost [regina-land-linux-titlebar](regina-land-linux-titlebar.md) $6.41 and this task $4.21, and only the second plan it misled corrected it. A cleanup round should take every recommendation of the form "this note or doc says X, and X was measured false" first, since each one waits for its next reader.
2. **Make the architect measure or mark a compositor premise, and prefer a measurement to a note.** This is recommendation 2 of [application-state-1](application-state-1.md) and 1 of [fixes-2](fixes-2.md), come up again. In `.claude/skills/regina/agents/architect.md`, say that a premise about the compositor or a toolkit is measured or labelled unmeasured, and that a note a review or a report's measurement contradicts is measured before the plan chooses, as `CLAUDE.md` treats `notes/` as leads. Plan 1 D9 and plan 2's S3 were both such premises, and each cost a round trip.
3. **Make a measured contradiction of a test a `rejected` for the coder.** This is recommendation 2 of [application-state-3](application-state-3.md), come up a second time. In `.claude/skills/regina/agents/coder.md`, say that a red that disproves a test's own table or message, or a false premise of the plan the coder works around, is a `rejected`. `coder-1` had S1c, C1's messages and D9 in hand, and would have sent them to the architect before `technical-writer-1` and `reviewer-1` ran.
4. **Say that ending a turn ends the invocation, and give the poll.** In the paragraph "The Bash tool stops a foreground command after 10 minutes" of `coder.md`, `test-writer.md`, `technical-writer.md` and `retrospective.md` under `.claude/skills/regina/agents/`, add that nothing wakes the agent when a background command ends. Name the idiom `coder-1` and `coder-4` used: a foreground `until grep -q '^exit ' <log>; do sleep 20; done`, repeated until the run ends. It would have saved `coder-4`.
5. **Have a deleting plan map each test function to its successor.** In the sweep rule of `.claude/skills/regina/agents/architect.md`, say that a test file the plan deletes is listed function by function, each with the test that covers it after the change or a reason it is gone. `rebuild_layout_spec_escapes_paths` would then have been ported in round 1, not as review 1's F2.
6. **Close what this task left open.** Put the heal guard of [application-state-1](application-state-1.md) recommendation 6 into the next GNOME task's instructions, since both front-ends now write a user's windows. Qualify the sentence at `crates/wolf-gnome/src/state_seam.rs:551` to "presented no later than the chain's first link", as review 2 §2 suggests.
