# Retrospective: the `All` toggle in the GNOME search panel

Last verified at commit `3663b2db186c1535a849f19cf14e653bb70784cb`.

The task gave `wolf-gnome`'s search panel a third toggle, `All`, that starts off, so the panel opens Markdown-only as macOS does. It extended `tests/sidebar_search.rs`, added one cage smoke to `smoke_headless/search_toggles.rs`, and made seven smokes with `.txt` fixtures turn `All` on. The eight invocations cost about $17.56, and every gate run passed on both workers on its first try. One round trip, `coder-1`'s rejection of a step order that plan 1 prescribed, added `architect-2`, `test-writer-2` and `coder-2`, about $2.24 and 13 minutes.

## What went well

- **Whole-struct comparisons made the behaviour free.** `enter_action` and `search_status` compare `SearchToggles` as a whole, so the new field made Enter re-run and the status line go stale with no edit to either. Plan 1 §1 saw this, and falsifiers C18a and C19a, which blank out `all_files` alone, proved the tests would notice if it stopped. Keep those comparisons whole.
- **The instructions named every site and every test.** They named the field, `INITIAL`, `search_options_for`, the module-doc bullet and both README entries, and said core and macOS stay as they are. Review 1 found no deviation, and nothing outside `crates/wolf-gnome/` changed.
- **`regina on linux` let the test writer measure geometry and OCR.** `test-writer-1` measured `ST_ALL_LABEL_PX` at 21 px with `pango-view` rather than estimating it, and read the new fixture lines with `tesseract --psm 11` before keeping them. No OCR term or click target needed a second round.
- **`fixture_guards.rs` took the new fixtures by registration again.** Registering two terms in `ASSERTED_OCR_TERMS` and two files in `RELAUNCH_FIXTURE_NAMES` was all it took to keep them clear of other smokes, as [gnome-toolbar-1](gnome-toolbar-1.md) also found.
- **A recommendation of [sidebar-toggles-3](sidebar-toggles-3.md) was carried out.** Its recommendation 2, to rewrite the false "status line reaches no assertion" bullet in `crates/wolf-gnome/tests/README.md`, went into plan 1 §5, and `technical-writer-1` rewrote it.

## What did not go well

- **Plan 1 put the `All` click before the Search page was showing.** Plan 1 §3 had the regex and paren smokes start step 0 with `st_click "$ST_ALL_X"`, before `st_field`. The sidebar opens on its Files page, so the click landed on the file tree, `All` stayed off and both smokes read `no matches`. `coder-1` found it, returned `rejected`, and plan 2 moved one `st_field` ahead of the click. This was the task's one round trip, about $2.24.
- **The fact was documented, but not where the plan's author read.** `crates/wolf-gnome/src/README.md`'s `sidebar.rs` entry says `build` "opens on Files". At base, the `ST_HELPERS` doc in `search_toggles.rs` said only that `st_field` "focuses the panel's field", and nothing said a body must show the Search page before its first click. Neither `architect-1` nor `test-writer-1` read that README entry. `test-writer-2` added the constraint to the `ST_HELPERS` doc, where the next author of a step body will read it.
- **No run before the code could catch it.** Before the code, the panel searched every file, so a misplaced click changed nothing and both smokes passed. Only the code turned the defect red, so a test-writer run would not have saved this round, unlike the premise in [gnome-toolbar-1](gnome-toolbar-1.md).
- **Prose that counts the toggles had to be found by hand, and some was missed.** "a field and two toggles", "Neither toggle", the "No file-type toggle" bullet and the "every file" sentences were each a site to rewrite. Plan 2 also had to rule on the blank-query sentence, which `coder-1` had argued still held. After landing, review 1 §5 still found "left of both toggles" (C6c) and "delete both `connect_toggled` handlers" (C7e) in `search_toggles.rs`, and "a measured label width" at `crates/wolf-gnome/tests/README.md:293`, all false with three toggles and two measured widths.
- **The wording allowlist pins a count.** Entry `A8` in `tools/lint/wolf_gnome_wording_allowlist.txt` matches the module-doc line ending "except in four" by exact text. So the number of divergences from macOS is fixed by the lint as well as by the doc. Plan 1 §3 and §8 and plan 2 §8 each had to warn that the line must stay byte-identical. It cost no rework here, but a task that removes a divergence must edit the allowlist too.
- **The wolf-gnome READMEs are still too big, and an entry is at its budget.** `crates/wolf-gnome/tests/README.md` is about 120 KB and `crates/wolf-gnome/src/README.md` about 93 KB. `architect-1` named the tests README 14 times in its transcript, `technical-writer-1` 15 and `reviewer-1` 17. The `search_panel.rs` entry reached 249 of its 250 words, and `technical-writer-1` shortened the focus-on-click bullet to make room for one sentence.

## Recommendations

1. **Drop the toggle counts that review 1 found.** In `crates/wolf-gnome/tests/smoke_headless/search_toggles.rs`, make C6c read "the click lands left of the toggles" and C7e "delete the `connect_toggled` loop". At `crates/wolf-gnome/tests/README.md:293`, write "measured label widths". Each became false when this task added a toggle, and each will mislead whoever adds the next falsifier.
2. **Move the count out of the allowlisted line.** Rewrap the `search_panel.rs` module-doc lead-in so that the line `A8` matches ends before "except in four", and the count sits on a line the wording check does not pin. Plan 1 and plan 2 spent three warnings guarding that line. The next task to change the divergences would then edit only the doc.
3. **Say in § Smoke conventions where the sidebar opens.** In `crates/wolf-gnome/tests/README.md`, add that the sidebar opens on its Files page, so a pointer smoke shows the Search page with Ctrl+Shift+F before it clicks inside it. `test-writer-2` put this in `ST_HELPERS`'s doc, but `sidebar_toggles.rs` and any new smoke file read their own helpers. This is the same pattern as [gnome-toolbar-1](gnome-toolbar-1.md) recommendation 1: a launch-state fact documented in `src/` and missing where smoke authors read.
4. **Split the two wolf-gnome READMEs.** This is recommendation 3 of [sidebar-toggles-3](sidebar-toggles-3.md) and recommendation 4 of [gnome-toolbar-1](gnome-toolbar-1.md), come up again. Here the `search_panel.rs` entry had to give up a sentence to take a new one, and four of the eight invocations read in the tests README.
