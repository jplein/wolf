# Retrospective: one Neovim per GNOME tab

Last verified at commit `17433640e47e92cbb4956588fefffb6aac74dbfe`.

The task implemented `specs/application-state.md` §8 on Linux. In `crates/wolf-gnome`, each tab starts, wakes, restarts and shuts down its own core. The tabpage machinery and the restart collapse were deleted, restore is capped by `MAX_RESTORE_NEOVIMS`, and `tabs_ui::focus_edges` drives the `:checktime` focus trigger. Its commits are `63cb77c` and `e41e66f` (code and tests) and `6c7c0cb` and `1743364` (documentation): 54 files, 3,109 lines added and 4,991 deleted.

The ten invocations cost about $63.22 and 142 minutes of agent time. There was one round trip: review 1's "Needs revision", with three blockers, added `architect-2`, `test-writer-2`, `coder-2`, `technical-writer-2` and `reviewer-2`. That cost $5.93 and about 21 minutes, plus a second run of each gate on both workers. All four gate runs exited 0 on both workers on their first try.

## What went well

- **The pure seams made the new rules cheap to test.** `tabs_ui::{focused_tab, focus_edges}` and `state_seam::restore_plans` are GTK-free. So `tests/tab_focus.rs` (TF1 to TF4) and `tests/restore_caps.rs` (RC1 to RC3) run without a compositor, and `coder-1` recorded each of their reds with a one-line edit.
- **Cargo discovery is the wiring for `wolf-gnome`.** The crate has no `BUILD.bazel`, by design (`specs/architecture.md`), so two new test files needed no target. Review 1 §3 confirmed from `coder-1`'s full run that both ran.
- **The smoke helpers carried over to one Neovim per tab.** `with_nvim_pid_helper` and `wait_nvim_count` already existed in `smoke_headless`, and `test-writer-1` rebuilt the NT, AR, CR and TR smokes on them. It also moved the `terminal.rs` and `titlebar.rs` preconditions from `tabpagenr()` to pids. Review 1 §4 found that none of these edits touched what the tests discriminate.
- **Plan 2 kept plan 1's measured reds.** It accepted review 1 item by item, named the four TR IDs to run again, and kept the rest of `coder-1`'s reds. `coder-2` cost $0.89 in 26 turns, and the round cost $5.93 against $57.29 for the first.
- **The instructions named every document to rewrite.** Review 1 §6 and review 2 §6 found nothing changed outside scope, and `technical-writer-1` shrank `crates/wolf-gnome/tests/README.md` by 1,713 bytes, deleting nine bullets about removed code.

## What did not go well

- **Every blocker of review 1 had been reported earlier, by an agent that returned `passed`.** This is the finding of [application-state-2](application-state-2.md) and [sidebar-toggles-1](sidebar-toggles-1.md), come up a third time.
  - R1, the TR smoke's false falsifier table: `coder-1` measured it and wrote it into its report's falsifier notes.
  - R2, the stale code text in `recovery.rs`: `test-writer-1` and `coder-1` both reported it.
  - R3, the `Blocker::CoreNotAlive` doc: `technical-writer-1` reported it.
- **The writer's definition splits "must change" from "merely stale" and does not define either.** `technical-writer-1`'s system prompt says a comment that must change is a `rejected` and one that is merely stale is a note. The writer called `ready_seam.rs:81` "wrong only in a minor way" and noted it, and review 1 made the same sentence blocker R3. [sidebar-toggles-1](sidebar-toggles-1.md) recommendation 2 asked for that definition, and the system prompt still lacks it.
- **The coder returned `passed` on a test whose own table its measurement disproved.** `coder-1`'s definition says a test that cannot fail where it matters is a `rejected`, and so is whatever needs somebody to act. It found that TR1a and TR1b red at exit 24, not at assertion 1, and still passed. [zoom-rules-2](zoom-rules-2.md) found the same reading of a stale leg row.
- **A "predicted red" column went stale again.** Plan 1 predicted that TR1a and TR1b would red at assertion 1, and `test-writer-1` copied that into the "predicted red" column of `restore.rs`'s table. No agent could measure it before `coder-1`. Recommendation 1 of [zoom-rules-2](zoom-rules-2.md), to drop the column, was never carried out, and 15 tables in `crates/wolf-gnome/tests/smoke_headless/` still have one.
- **The prediction was wrong because the smoke read the exit status first.** A save that drops tabs also leaves run 2 one Neovim short, so the scenario exits 24, and the Rust side panicked on `status.success()` before it read run 1's frozen file. Assertion 1's diagnosis of the save could not be reached. `crates/wolf-gnome/tests/README.md` § Smoke conventions says the Rust side stops at its first failing assertion, but not that this hides frozen evidence. `test-writer-1` half saw it, and put "check run 1's frozen file before blaming the restore" into exit 24's text.
- **The sweep matched a name that both a deleted method and a kept one carried.** Plan 1 §9's grep had `reset_after_restart` for the deleted `TabsHandle::reset_after_restart`, and `PaneHandle::reset_after_restart` stays. `technical-writer-1` listed the pane view's method among the allowed hits, and `test-writer-1` left `recovery.rs`'s `self.inner.panes.reset_after_restart();` alone for the same reason. The call path changed to `tab.panes()`, which no name grep can see.
- **Texts that point at a file the code moved out of were not swept.** The pattern had no entry for `app.rs`, whose drain loop and wake-bridge tests moved to `shell.rs` and `tab_view.rs`. Plan 2 §2 found two more such texts in `recovery.rs`, and the `appearance.rs` module doc named `crate::app` as its call site, which was already stale at `9851fcf`. One more such text landed (next bullet).
- **One stale comment landed.** `crates/wolf-gnome/src/shell.rs:1684`, in `restart_nvim`'s `Respawned` arm, says "Belt and braces, as `app.rs` does", and `app.rs` does no such refresh. Review 2 §8 recorded it as outside both plans.
- **Test texts quote statements of the code they test.** `recovery.rs`'s revert table and the pane-grid failure message quoted `self.inner.panes.reset_after_restart();` verbatim. Any refactor of the call site makes the text false, and only a test writer may fix it, so R2 needed a test writer's invocation after the coder had already seen it.
- **A wall-clock bound in `wolf-core` failed under load.** In `coder-1`'s first ad hoc `./gates.sh` on linux, `api::tests::timeout_block_on_times_out_on_never_resolving_future` (`crates/wolf-core/src/api.rs:2116`) took 2.54 s against its 2 s bound. It cost `coder-1` a second full gate run, and this task did not touch that code.

## Recommendations

1. **Route what an agent sees to its owner before the review.** This is recommendation 2 of [sidebar-toggles-1](sidebar-toggles-1.md) and of [application-state-2](application-state-2.md), come up a third time, and it is what to do first. In `.claude/skills/regina/agents/technical-writer.md`, replace "must change" and "merely stale" with one rule: a comment, doc or message the change makes false is a `rejected`. `technical-writer-1`'s R3 would then have reached the coder before review 1.
2. **Make a disproved test table a `rejected` for the coder.** In `.claude/skills/regina/agents/coder.md`, say that a measured red that contradicts a test's own doc, and stale code text in a test, are a `rejected` naming the file, never a note. `coder-1` had R1 and R2 in hand. A `rejected` would have sent both to the architect with the code already written, saving `reviewer-1` ($7.18) and the writer's second pass.
3. **Drop the "predicted red" column.** This is recommendation 1 of [zoom-rules-2](zoom-rules-2.md), come up again. Remove it from the 15 tables in `crates/wolf-gnome/tests/smoke_headless/` (`grep -n 'predicted red'` lists them), and in `.claude/skills/regina/agents/architect.md` say that a plan names a falsifier's edit, not its red. R1's false table would not have existed.
4. **Read frozen evidence before the exit status.** In `crates/wolf-gnome/tests/README.md` § Smoke conventions, beside the rule that a scenario ends at its first failed readback, add one sentence: a frozen file that tells one cause from another is asserted before `status.success()`. The fixed `three_tabs_survive_a_relaunch_under_cage` is the example. Plan 1 would have designed TR that way, and the TR half of review 1 would not have been needed.
5. **Sweep for call paths and moved-out files.** In `.claude/skills/regina/agents/architect.md`'s sweep rule, say that a name kept by a surviving item is swept by its old call path (`self.inner.panes.`), and that a file the code moves out of is swept as `` `app.rs` ``. Both would have printed R2's texts, `appearance.rs`'s call site and `shell.rs:1684` for `coder-1`.
6. **Name the function, not its statement, in test texts.** In `crates/wolf-gnome/tests/README.md` § Smoke conventions, say that a failure message names the function to check, as `AppShell::restart_nvim`, and never quotes a line of it. Only the measured revert row needs the line. The pane-grid message would then have stayed true through D4.
7. **Fix the remaining stale comment.** Drop "as `app.rs` does" from `crates/wolf-gnome/src/shell.rs:1684`.
8. **Give the `wolf-core` timeout test room under load.** In `crates/wolf-core/src/api.rs`, raise `RETURN_BOUND`, 2 s against a 50 ms `SHORT_TIMEOUT`, to a bound a loaded Linux worker meets, or drop the elapsed check and keep the timeout error check. It cost `coder-1` one gate run here, and would cost a full round if it ever fails in Regina's gate.
