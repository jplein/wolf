# Retrospective: `gtk-titlebar-style`, GNOME tabs in the header bar

Last verified at commit `39e19d2927b7c8f35aa0a7a1fea766dd8481e6db`.

The task added `gtk-titlebar-style` (`tabs` | `native`, default `tabs`) to `crates/wolf-core/src/config.rs`, and `crates/wolf-gnome/src/tab_bar_slot.rs`, which moves the tab bar into the header bar from the second tab. It also pinned `native` in every two-tab smoke whose geometry assumes the row. Its commits are `c37c430` (code and tests), `473a039` (documentation) and `39e19d2` (review 1's revisions). It took two plans, two reviews and ten invocations costing $34.98, of which the one round trip cost $6.19.

## What went well

- **The window-structure note made the geometry plan right the first time.** `notes/wolf-gnome/window-structure.md` says why the header's height and the bar's autohide hold up the pointer smokes. Plan 1 §1 used it to keep the one-tab window in the row and to hold the in-header bar at 47 px with a stylesheet. It predicted the 13 px growth that `coder-1`'s C4c red then measured (S2's shade row 59 against S1's 46). No smoke constant changed.
- **The measurement procedure was written down where the constant is.** `OVERLAY_ORIGIN_X_EXPECTED`'s doc in `smoke_headless/main.rs` records how the origin was measured. Plan 1 §3 sent `coder-1` to it, and its tick-callback table answered every number the instructions asked for in one run (`coder-1` command 6).
- **Named geometry made the native-pin sweep a grep.** Two-tab smokes derive their clicks from `tab_bar_y`, `two_tab_x`, `TAB_BAR_HEIGHT_EXPECTED` and the `*_TAB_CENTRE_FRACTION` constants. So plan 1 §3 could give the pin rule as one `grep` and list its hits at the base. `test-writer-1` pinned exactly that list, and the first whole-smoke run (`coder-1` command 18) and both implementation gate runs passed on both workers.
- **Modelling the key on `appearance` kept it to one crate.** `FfiConfig` is built field by field, so plan 1 could leave `wolf-ffi` and every macOS file alone. GT1 and GT2 ran on macOS through Bazel, and each of C1a to C2a went red as plan 1 §4 predicted.
- **A recorded idle-ordering fact let plan 2 fix a flash without guessing.** `shell.rs`'s `RESTART_DEFER` doc records when a `DEFAULT_IDLE` idle beats the paint. `architect-2` read it, saw why the case here differs, and chose `HIGH_IDLE`. `coder-2`'s M1 runs confirmed it: no frame under `HIGH_IDLE` drew the bar in its row, against one frame per control run.

## What did not go well

- **The round trip: review 1 blocked on an unplanned test and on counts in comments.** It added `architect-2` ($1.99), `test-writer-2` ($0.54), `coder-2` ($1.23), `technical-writer-2` ($0.40) and `reviewer-2` ($2.03), and a second run of both gates. The HT3 reds themselves were two short Linux commands (`coder-2` commands 5 and 6). Most of `coder-2`'s 14 minutes went to the optional M1 measurement and the NT3a red, which plan 2 added.
- **An unplanned test had no red, in an eighth task.** `test-writer-1` added `titlebar_pins_parse_to_their_styles` and listed it in its report with no ID and no disabling edit. `coder-1` gave it the ID `coder-T1` as its definition says, but wrote "I ran no separate falsifier for it", and review 1 §4 blocked. `test-writer-1`'s system prompt still has no rule for a test the plan does not ask for; it does not contain the word "ID".
- **Five new comments counted smokes, though plan 1 warned against counts.** Plan 1 §3 told the test writer not to count the new `fixture_guards.rs` blocks, citing [tabs-and-preview-1](tabs-and-preview-1.md). `test-writer-1` still wrote "The two smokes", "Both pin", "Both smokes", "both bodies" and "The two pinned config files". Review 1 §5 found three and `architect-2` found two more; `CLAUDE.md` forbids them, and nothing checks.
- **The exemptions heading in `fixture_guards.rs` is false at `HEAD`.** It reads "The nine deliberate, documented exemptions", but this task added a tenth, "The `gtk-titlebar-style` smokes add one more". Both `test-writer-1` and `test-writer-2` edited that doc without fixing the heading, and neither review saw it. The ordinals under it, such as "The sidebar-toggle smoke is the third" and "the widest block of the five", were already inconsistent.
- **Three agents read the same libadwaita stylesheet three ways.** `architect-1` has no `regina on linux`, so it made 13 `WebFetch` calls into GTK's and libadwaita's `main` branches to learn the paddings and the centre layout. `test-writer-1` (commands 1 and 2) and `coder-1` (command 1) then read the pinned 1.9.3 CSS from the Linux worker with `gresource extract`. The predictions held, so nothing was redone, but `architect-1` was $8.48 and 25 minutes, a quarter of the task.
- **The same temporary probe was written twice.** `coder-1` and `coder-2` each added a tick callback to `window::build` that logs `compute_bounds` of the header, the bar and the overlay. Each removed it again and checked the restore by checksum. Nothing in the repository keeps such a probe.
- **A README contradicts itself, and the task left it so.** `crates/wolf-gnome/src/README.md`'s `stacking.rs` entry says "a GNOME window's tabs never move to another window". The `tab_bar_slot.rs` entry and `TabsHandle::n_pages`'s doc say a dragged tab moves the page, and nothing in `crates/wolf-gnome/src` handles `create-window`. Both reviews flagged it and left it to a person check that only a GNOME session can run.

## Recommendations

1. **Give an unplanned test its own ID at the test writer.** This is recommendation 1 of [sidebar-toggles-1](sidebar-toggles-1.md), come up again after [cli-open-2-3](cli-open-2-3.md) and [sidebar-preview-3](sidebar-preview-3.md). In `.claude/skills/regina/agents/test-writer.md`, require each test the plan does not ask for to appear in the report with a proposed ID and disabling edit. Here that would have handed `coder-1` the C6a edit and removed the blocking half of the $6.19 round.
2. **Drop the count and ordinals from `fixture_guards.rs`'s exemptions doc.** This is recommendation 3 of [tabs-and-preview-1](tabs-and-preview-1.md), come up again and now false. Make the heading "The deliberate, documented exemptions", and name each block by its smoke rather than as "the third" or "the ninth". Each new smoke then adds a paragraph without renumbering the others.
3. **Let doc-lint flag a count of smokes or tests in a comment.** In `tools/doc-lint`, add a rule that warns when a number word or "both" comes just before "smokes", "tests", "callers", "routes" or "bodies" in a comment. It would have caught three of this task's five ("The two smokes", "Both smokes", "both bodies") before review. [ghostty-5](ghostty-5.md) put the rule in `CLAUDE.md`, and this task shows that the rule alone does not stop new counts.
4. **Give the architect `regina on linux`.** This is recommendation 1 of [followups-3](followups-3.md) and [nerd-font-3](nerd-font-3.md), come up again. With it, `architect-1` could have read the pinned libadwaita CSS as the next two agents did, instead of `main` through 13 web fetches.
5. **Keep an env-gated geometry probe in `crates/wolf-gnome/src/window.rs`.** Add a tick callback behind a variable such as `WOLF_GEOMETRY_LOG` that writes each distinct bound of the header, the tab bar and the overlay. Then name it in `OVERLAY_ORIGIN_X_EXPECTED`'s doc as the way to measure. `coder-1` and `coder-2` each wrote and removed the same callback, and the next layout task will need it again.
6. **Settle the cross-window drag and rewrite the losing document.** Run review 2 §7's drag check on a GNOME session. If the page moves, rewrite the `stacking.rs` entry of `crates/wolf-gnome/src/README.md` and record that the tab registry does not follow the page. If it does not, rewrite the `tab_bar_slot.rs` entry's last decision and `TabsHandle::n_pages`'s doc.
