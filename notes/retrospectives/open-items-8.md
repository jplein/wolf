# Retrospective: defer and cap macOS crash restarts, and drain commands behind the crash overlay

Last verified at commit `4937b1ad1686bf5fac95563a105902f7971b3334`.

The task ran with no rework. Each agent ran once, in order: architect, test writer, coder, technical writer, reviewer. Both gates passed on both workers on the first run, and review 1 approved with two minor notes. The five invocations cost about $10.05 in total: `architect-1` $3.39, `test-writer-1` $0.61, `coder-1` $1.69, `technical-writer-1` $1.67 and `reviewer-1` $2.69.

## What went well

- **The Linux reference was a pure function, so the port was mechanical.** `crates/wolf-gnome/src/liveness_ui.rs` maps a liveness reading to overlay and restart decisions with no GTK. Plan 1 could give the macOS seam's exact API and decision table, and `test-writer-1` wrote six tests against that API before the code existed, in 14 turns.
- **The `WolfKeyMap` pure-seam pattern gave the new rules a home.** `notes/wolf-macos-decisions.md#the-pure-seam` and the sibling seams told `architect-1` where `LivenessSeam.swift` belonged and how to test it headlessly. Review 1 found no mock to question, and the falsifiers ran in seconds under `//crates/wolf-macos:WolfKeyMapTests`.
- **The reason for the timer was already written down.** The `schedule_restart` comments in `crates/wolf-gnome/src/shell.rs` record that an idle callback never presented the overlay and that a 50 ms timer did. The note `notes/crates/wolf-gnome/src/shell.rs.md#one-press-two-respawns` bounded the retry case. Plan 1 adopted both instead of measuring again, and review 1 checked the cap against the second.
- **`CLAUDE.md`'s rule on explicit `srcs` lists was followed in the plan.** Plan 1 §3 named both list edits in `crates/wolf-macos/BUILD.bazel`, one for the test writer and one for the coder. Neither was missed, and the coder's run showed `LivenessSeamTests` executing.
- **Plan 1 avoided a gate failure that doc-lint would have caused.** It told both new Swift files to open with a comment that links no README anchor, because doc-lint runs at the implementation gate, before the technical writer adds the anchor. The test file used the anchorless `// See …/README.md` form that two siblings already use.

## What did not go well

- **wolf-gnome's docs described macOS's code again.** The module doc of `crates/wolf-gnome/src/shell.rs` said macOS's `onWake` returns before its drain, and `schedule_restart`'s doc said macOS's `.dead` overlay is never drawn, so this task made both false. `architect-1` grepped `shell.rs` for macOS to find them, and plan 1 §3 had the coder edit a Linux file for doc text alone. `coder-1` then ran `cargo fmt`, `cargo doc` and `cargo clippy` through `regina on linux` for that edit.
- **One overstated sentence is in five places.** "The drain issues no RPC" is in `shell.rs:49`, `LivenessSeam.swift:53`, the `LivenessSeam.swift` entry of `crates/wolf-macos/Sources/WolfKeyMap/README.md`, `WolfWindowController.swift:420` and a doc comment in `LivenessSeamTests.swift`. Review 1 found it true of the queue read only: a dispatched `.newTab` makes a blocking `create_tabpage` call, so behind a `.notResponding` overlay it blocks the main thread once for the RPC timeout. Review 1 left it unfixed, and a fix means editing five copies.
- **The overlay's message choice is not under test.** The mapping from `dead(retrying:)` to its message lives in `NvimStatusOverlayView.show(mode:)`, an AppKit view. wolf-gnome tests the same mapping as the pure `overlay_message`. Review 1 noted that a swapped message string would only be caught by the user's manual check 2.
- **An entry went over its word budget.** `technical-writer-1` brought the `Project.swift` entry of `crates/wolf-macos/Sources/WolfMacOS/README.md` to 328 words and the `WolfWindowController.swift` entry to 270, against 250, and cut existing text in three Python replace passes. Plan 1 §5 had warned of this, and review 1 accepted the cuts. [open-items-5](open-items-5.md) recorded the same overrun on a neighbouring entry of this README.
- **The ledger needed a parser once more.** `technical-writer-1` replaced one cell of `notes/macos-followups.md` through a scratch copy and a script, because each row is one table line of several hundred characters. The file is 80,328 bytes. It and two of the three README files this task edited were over the 50,000-byte size warning before the task began.

## Recommendations

1. **Stop wolf-gnome's docs from describing macOS's code.** This came up again: it is recommendation 1 of [open-items-4](open-items-4.md) and 4 of [open-items-5](open-items-5.md), and [open-items-6](open-items-6.md) raised it for `wolf-core`. This task adds `shell.rs`, where two such sentences cost a plan step, a Linux-file edit and three Linux checks. A sweep of `crates/wolf-gnome/src/` for macOS mentions, with each one cut to a link or deleted, would have kept this task on the macOS side.
2. **Narrow the drain's "no RPC" claim to the queue read, and keep it in one place.** State it once, in the `LivenessSeam.swift` entry of `crates/wolf-macos/Sources/WolfKeyMap/README.md`, as "reading the queue issues no RPC; some dispatched commands do", and correct `shell.rs:49` the same way. Have `LivenessSeam.swift`, `WolfWindowController.swift` and `LivenessSeamTests.swift` link that entry instead of repeating it. Review 1 is the evidence, and the next correction would then touch one file.
3. **Move the overlay message choice into `LivenessSeam`.** Add a pure `overlayMessage(_:)` next to `decision`, as wolf-gnome's `overlay_message`, and have `NvimStatusOverlayView` call it. Then one case in `LivenessSeamTests.swift` pins the two `dead` messages, and the manual check 2 that review 1 relied on would no longer be the only test.
4. **Change the ledger's format when it is pruned.** This came up again: it is recommendation 2 of [open-items-2](open-items-2.md), now seen in a sixth task. Here `technical-writer-1` scripted a one-cell edit.
