Last verified at commit `171da5c0086e05830b778ee818708666362c7ab7`.

The task carried out the follow-ups that [ghostty-1](ghostty-1.md) to [ghostty-4](ghostty-4.md) kept raising. It ran straight through: `architect-1`, `test-writer-1`, `coder-1`, `technical-writer-1` and `reviewer-1` each ran once. Both gates passed on both workers on their first run, and review 1 approved with six minor notes. There was no rejection, non-zero gate, discrepancy or resume.

The five invocations cost about $22.00 and 54 minutes. `architect-1` was the largest at $6.19, 56 turns and 18 minutes, then `technical-writer-1` at $5.93 and 106 turns. The others were `test-writer-1` $2.55, `coder-1` $3.18 and `reviewer-1` $4.16.

## What went well

- **The lint-script tests had templates to copy.** `:markdown_check_test` already globs `testdata/**`, and `gates.sh` already ran `markdown-check-test`, so cases W1 to W4 needed no wiring. `rustfmt_files.sh` and its test copied the validation and scratch-checkout pattern of `swift_format_fix.sh` and `swift_format_fix_test.sh`, as plan 1 asked. `coder-1` then had no failed gate or rework.
- **doc-lint's `doc-ref` rule made the comment sweep checkable.** `test-writer-1`'s doc-lint run reported exactly the nine expected `doc-ref` findings for topic files that did not exist yet. Plan 1 D4 used the same rule to decide that `coder-1` creates the topic files, so the implementation gate could pass between the two commits.
- **Keeping every `##` heading in place kept every old anchor valid.** Plan 1 D3 kept each moved section's heading with a short entry, so `specs/` and the earlier reports under `notes/retrospectives/` needed no edit. Naming each topic file after its heading's slug made the retargeting mechanical.
- **`--entry-words` was used in the same task.** `technical-writer-1`'s link edits pushed the `coordinator.rs` and `tab_view.rs` entries of `crates/wolf-gnome/src/README.md` to 254 and 251 words. The new mode showed the margin while the writer trimmed them to 248 and 249, with no counter script of the writer's own, which [ghostty-4](ghostty-4.md) had recorded.

## What did not go well

- **`notes/wolf-gnome-decisions.md` was verified at a commit 148 commits back.** Its line names `24af640`. `technical-writer-1` checked each of the ten topic files in full and found five false statements: a count of "eight" smokes that is three, `Ctrl+Shift+I` and `Ctrl+Shift+M` called bound when no row binds them, the emit check called the last statement of the drain loop, two actions disabled where `set_empty_state` disables three, and an unchecked "five invariants".
- **The sections that stay are as stale as before.** Plan 1 D5 kept the decisions file at `24af640`, because re-checking all of it was not this task's work. Review 1 note 6 found one more false claim in what stayed: "The headless smoke test" puts the packaged smokes "at the end of the same file", but `smoke_headless` is a directory and they are in `packaged.rs`. Review 1 notes 1 and 3 found two more imprecisions carried into the topic files.
- **`tools/lint/README.md` gave the wrong rustfmt version.** At `056461c` it said rustfmt comes from the `rules_rust` toolchain "(Rust 1.85.0)", and plan 1 repeated that for the `formatted.rs` fixture. `test-writer-1` measured `rustfmt 1.9.0-nightly`, the separate rustfmt toolchain's, and `technical-writer-1` corrected the README. It cost two measurements and no rework.
- **Most citations of the decisions file named their section in prose, or not at all.** At `056461c`, 143 lines in `crates/wolf-gnome/src`, `crates/wolf-gnome/tests` and `crates/wolf-macos/Sources` cite the file, and only 51 carry an anchor. So `architect-1` read each site to decide its section, and plan 1 lists about sixty sites by their text. doc-lint checks an anchor but not a heading named in quotes, and at least seven such prose citations remain in code, for example in `layout.rs` and `scrollbar.rs`.
- **The topic files cite each other in prose.** Review 1 note 2 found section names with no link in `frame-time-instrumentation.md`, `window-structure.md` and the decisions file. Those names pointed into the same file before the split. They now point into another file, and nothing checks them.
- **The architect read `rules_rust` source from the shared repository cache.** To confirm that `@rules_rust//rust/toolchain:current_rustfmt_toolchain` is public and what it outputs, `architect-1` searched the cache's content-addressed tarballs for the `rules_rust` archive in about seven commands. `technical-writer-1` has since written D6's reasons into the toolchain bullet of `tools/lint/README.md`, so the next agent can read them there.
- **The agent definitions still tell agents to format wolf-gnome by hand.** `.claude/skills/regina/agents/test-writer.md` says to apply the diff that `regina on linux -- cargo fmt --all -- --check` prints, and `coder.md` names only `:rustfmt.fix`. Plan 1 left the definitions out of scope. Until they change, agents will keep applying the remote hunks by hand, as [round-4-4](round-4-4.md) recorded.
- **The two largest wolf-gnome READMEs still exceed the size ceiling.** The Linux documentation gate warned that `crates/wolf-gnome/src/README.md` is 86,094 bytes and `crates/wolf-gnome/tests/README.md` is 98,580. `technical-writer-1` edited both for the link sweep.

## Recommendations

1. **Point the agent definitions at `:rustfmt_files.fix`.** In `.claude/skills/regina/agents/test-writer.md`, replace the sentence about applying the remote `cargo fmt` diff with `nix develop --command bazel run //tools/lint:rustfmt_files.fix -- <files>`, with Linux's `fmt` gate as the judge. Add the target beside `:rustfmt.fix` in `coder.md`. This completes [ghostty-4](ghostty-4.md) recommendation 1 and [round-4-4](round-4-4.md) recommendation 1, and it saves the hand-applied hunks in every task that edits wolf-gnome Rust.
2. **Re-verify the rest of `notes/wolf-gnome-decisions.md` and bump its SHA.** Check the twelve sections that stay against the code, as `technical-writer-1` did for the ten topic files, and fix review 1 notes 1, 3 and 6. The file is now 32 KB, so a whole-file check fits one task. The topic files took five corrections after 148 commits, which suggests what the rest holds.
3. **Cite a note section by its anchored path, never by a quoted heading.** Rewrite the remaining prose citations in code, in `appearance.rs`, `layout.rs`, `scrollbar.rs`, `smoke_headless/editor.rs`, `smoke_headless/main.rs` and `crates/wolf-core/src/state.rs`, as `notes/<file>.md#<slug>`, so that doc-lint's `doc-anchor` checks them. Link the cross-file section names from review 1 note 2. The next split of a notes file would then need no hand-made list of sites, which took about sixty entries in plan 1.
4. **Split `crates/wolf-gnome/src/README.md` and `crates/wolf-gnome/tests/README.md`.** This is [round-3-10](round-3-10.md) recommendation 7 and [round-3-11](round-3-11.md) recommendation 6, come up again. [round-4-5](round-4-5.md) shows that subdirectory READMEs work for `wolf-macos`, and `--entry-words` now gives a writer the measurement.
