# Retrospective: the GNOME header bar's sidebar toggle group

Last verified at commit `e5e9cb66f63e12674c22273edc117f4435956e25`.

The task replaced wolf-gnome's sidebar toggle button with an `adw::ToggleGroup` of Files and Search after Back/Forward, removed the sidebar's `gtk::StackSwitcher`, and derived the group's state in the new `crates/wolf-gnome/src/sidebar_toggles.rs`. Its commits are `86394c6` (code and tests) and `e5e9cb6` (documentation). It ran once through the flow with no rework: no rejection, no failed gate, no discrepancy, and review 1 approved with minor notes.

The five invocations cost $23.01 over about 67 minutes. `architect-1` was the largest ($7.59, 80 turns, 23 minutes), then `test-writer-1` ($6.05, 76 turns), `reviewer-1` ($3.21), `coder-1` ($3.11) and `technical-writer-1` ($3.05).

## What went well

- **The decision-and-glue pattern had precedents to name.** The task instructions pointed at `appearance.rs` and `titlebar_background.rs`, and plan 1 put the rule in four pure functions of `sidebar_toggles.rs`. Its seven tests in `crates/wolf-gnome/tests/sidebar_toggles.rs` each went red under its own edit in `coder-1`'s commands 6 to 12, with no compositor or Neovim.
- **`SidebarHandle`'s relay was already the one place every sidebar change passes.** The accelerator, `win.search-in-project`, `:WolfSidebarShowProject`, the empty state and launch all reach it, so `coder-1` set the group from `relay()` alone. Review 1 §2 checked every path against it and found none missing.
- **The feature-split smoke harness took a new module cheaply.** `test-writer-1` added `smoke_headless/sidebar_toggles.rs` and one `mod` line in `main.rs`, and the source-scanning guards found it from that line. It reused `projsearch_sidebar_band` and the `TB_HEADER_*` constants by making them `pub(crate)`.
- **Both new smokes passed on their first run.** Nobody had run them before `coder-1`'s commands 4 and 5, though their click targets were derived from libadwaita's metrics with no probe.
- **An existing guard covered the header height.** `pointer::click_positions_the_cursor_under_cage` pins `PANE_ORIGIN_Y_EXPECTED`, so the task's "the group must not change the height" needed no new test: it became falsifier C16, red under a taller group in `coder-1`'s command 21.
- **Both gates passed on their first Regina run on both workers.**

## What did not go well

No finding below cost a round trip. Each cost minutes inside one invocation, or landed as a defect that review 1 §8 lists as non-blocking.

- **A comment budget in the plan was off by one line.** Plan 1 §3 told the coder to replace one `crates/wolf-gnome/Cargo.toml` comment line "with a comment of two lines at most". That line sits under another `#` line, and doc-lint joins consecutive full-line comments into one block, so one line was all the room there was. `coder-1`'s first Linux `./gates.sh` (command 23) failed on `comment-lines` after about 4 minutes 45 seconds, a check `doc-lint` alone runs in 2 seconds.
- **`CLAUDE.md` does not say how comment lines are counted.** It says "A non-doc comment is at most two lines"; the block rule is only in `tools/doc-lint/README.md`, which plan 1 did not read for this edit.
- **A test file landed misdescribing its own falsifier.** `test-writer-1` predicted C8's red in a sidebar capture, without a run. `coder-1` measured it in the group assertion on captures 2 and 5, and said so, but may not edit test files. So the C8 row of the falsifier table and capture 1's causes string in `crates/wolf-gnome/tests/smoke_headless/sidebar_toggles.rs` are wrong (review 1 §8.1). This is the gap of [ghostty-5](ghostty-5.md) recommendation 2, come up again.
- **The planner read libadwaita from the web, at `main` rather than the pinned 1.9.3.** `architect-1` found only `.drv` files for libadwaita in `/nix/store` and no cargo registry, then made five `WebFetch` calls, one refused with HTTP 406. Plan 1's 34 px group height and the smoke's metric constants rest on those reads; C16 showed they held, but nothing tied them to 1.9.3.
- **The architect has no Linux worker.** Only the test writer's and the coder's system prompts offered `regina on linux`, and `coder-1` used it to read the libadwaita crate's source (command 1). [open-items-13](open-items-13.md) recommendation 4 covers Rust crates under Bazel's `external/`, which does not hold a C library that only the Linux build links.
- **The wolf-gnome READMEs grew again.** `crates/wolf-gnome/tests/README.md` went from 104,832 to 106,722 bytes and `crates/wolf-gnome/src/README.md` from 89,517 to 91,255, and the Linux documentation gate warned on both. `test-writer-1` printed the whole tests README in one `cat`. This came up in [regina-land-linux-titlebar](regina-land-linux-titlebar.md) and [ghostty-4](ghostty-4.md).
- **One smoke module cost 120 lines in `fixture_guards.rs`.** Three rows went into the shared registries, and because `TG_TREE_FILE`'s name carries its own OCR term, a hand-written exemption block repeats for it what the project-search smokes' block already does. Each later smoke that reads a tree row by file name will write a third.
- **Comments that count landed again.** "The one site that sets the group" on `SidebarInner::relay` and "the only writer of the page" in `crates/wolf-gnome/src/sidebar.rs` state counts (review 1 §8.4). This is [ghostty-5](ghostty-5.md) recommendation 6 and [sidebar-toggles-1](sidebar-toggles-1.md) recommendation 4, come up again.
- **Two documents kept a claim this task made false.** `notes/wolf-gnome/window-structure.md` still says every pointer smoke derives its targets from the pane origin, though its SHA was bumped after a whole-file check. The sidebar toggle smoke's doc in `smoke_headless/sidebar.rs` keeps a "covers that nothing else does" heading over a paragraph naming S2 (review 1 §8.2 and §8.3).

## Recommendations

1. **Say in `CLAUDE.md` § Code comments that consecutive full-line comments are one comment.** One clause, linking `tools/doc-lint/README.md`'s block rule, would have had plan 1 §3 budget one line. Only the user edits that file. Separately, in `.claude/skills/regina/agents/coder.md`, have the coder run `doc-lint --root` before `./gates.sh` after a comment edit, which would have saved `coder-1` a 5-minute Linux gate run.
2. **Fix C8's description in `crates/wolf-gnome/tests/smoke_headless/sidebar_toggles.rs`** as review 1 §8.1 words it: the table row names captures 2 and 5, the 2/5 `assert_same` causes string names an unclaimed press, and capture 1's drops "instead". The process fix is [ghostty-5](ghostty-5.md) recommendation 2, which this task supports again.
3. **Give the planner the pinned libadwaita source.** Either offer `regina on linux` to the architect in `.claude/skills/regina/agents/architect.md`, or check whether `nix build --inputs-from . nixpkgs#libadwaita.src` fetches the 1.9.3 tarball on the macOS worker and, if so, add that line to `build.md`. `architect-1`'s five web reads and their `main`-branch risk would then be one local read.
4. **Split the two wolf-gnome READMEs.** This repeats [regina-land-linux-titlebar](regina-land-linux-titlebar.md) and [ghostty-4](ghostty-4.md). `architect-1`, `test-writer-1` and `technical-writer-1` each read in `crates/wolf-gnome/tests/README.md`, and one read all 105 KB.
5. **Turn the OCR-term exemptions in `fixture_guards.rs` into a table.** A row naming the file constant, the term its name carries, and the terms it must not cross would replace the project-search block and this task's block. The next tree-row smoke would add one row, not 50 lines. It sits beside [regina-land-linux-titlebar](regina-land-linux-titlebar.md) recommendation 3, which is about the same file.
6. **Mend the three leftovers of review 1 §8.2 to §8.4.** Narrow the pointer-smoke sentence in `notes/wolf-gnome/window-structure.md` as the tests README already does, retitle the sidebar toggle smoke's heading in `smoke_headless/sidebar.rs`, and reword the two count comments in `sidebar.rs` as invariants ("the group's state is set here and nowhere else").
