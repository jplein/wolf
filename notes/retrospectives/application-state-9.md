# Open Folder focuses, fills or opens a window on both platforms

Last verified at commit `71451d6875de434e473596b24556d719f9c31aeb`.

The task implemented `specs/application-state.md` §6 on macOS and GNOME. Open Folder and Open Recent now focus a tab already on the directory, fill an empty current tab, or open a new window, instead of re-rooting the current one. The change is `b5a9316`, `1d5ad2f`, `20f3965` and `71451d6`. The ten invocations cost $52.67. One round trip, review 1's rejection, added $6.09.

## What went well

- **Pure seams carried the decision on both platforms.** Plan 1 put the §6 step in `crates/wolf-gnome/src/open_folder.rs` and `OpenFolderSeam.swift`, both calling `wolf_core::app_state::project_tab`. That gave G1 to G8 and M1 to M7 homes in pure tests, and review 1 §2 found no logic defect.
- **Existing helpers were shared, not copied.** `open_folder::plan` reuses `state_seam`'s new `saved_tab_plan` and `fresh_tab_plan`, and `WindowStateCodec.projectTab` shares `feed` with `submit`, as plan 1 asked. Review 1 §1 confirmed both.
- **The gates passed on their first run.** `implementation-1`, `implementation-2`, `documentation-1` and `documentation-2` all exited 0 on both workers, so the only rework was the review's.
- **A falsifier driver made 38 reds cheap.** `coder-1` wrote one script that applied each plan edit, ran the test alone and restored the checksum, and recorded C1a to S5a plus its own W1a and W1b. Review 1 §4 found every plan ID with its own red.
- **The second round was small.** `architect-2`, `test-writer-2`, `coder-2`, `technical-writer-2` and `reviewer-2` cost $6.09 together. Plan 2 restated nothing from plan 1, and checked each suggested edit against the code before passing it on.

## What did not go well

- **Five tests beyond the plan were never run red.** `test-writer-1` added `testWithNoCurrentTabAnOpenTabIsStillFocused`, `testWithNoCurrentTabAndNoTabOnTheDirectoryANewWindowOpens`, `testCanonicalDirectoryKeepsThePrivatePrefixCoreUses`, `testCanonicalDirectoryFallsBackToAMissingPathAsGiven` and `the_open_folder_queries_select_exactly_their_folder_row`. Its report listed them under "Additions beyond the plan's IDs", the Swift ones as "extra cases" of M1, M4 to M6, and proposed no ID for any.
- **The coder's driver ran only the plan's IDs.** `coder-1`'s definition says an unplanned new test gets an ID the coder makes up, and it did that for its own in-source `reroot_decision_table` (W1a, W1b). Its driver was built from plan 1 §4, so the test writer's five additions had no entry. Review 1 R1 found them, and one of them, M12a, is the only guard of D2's rule against `resolvingSymlinksInPath`.
- **That is the same miss [sidebar-toggles-1](sidebar-toggles-1.md) found.** Its recommendation 1 asked the test writer to give an unplanned test a proposed ID and edit. Neither `test-writer-1.system.md` nor `.claude/skills/regina/agents/test-writer.md` says so yet.
- **A stale test comment was in the architect's own search output.** `architect-1` counted matches of `open recent` across the tree, and the result listed `crates/wolf-core/tests/nav_history_live.rs:2`. Plan 1 §3 never gave that file to the test writer, so its comments kept calling `InputEvent::Chdir` the Open Recent path. That is recommendation 1 of [application-state-7](application-state-7.md) and 3 of [sidebar-toggles-1](sidebar-toggles-1.md), come up again.
- **The technical writer made the comment contradict its mirror.** `technical-writer-1` rewrote `notes/crates/wolf-core/tests/nav_history_live.rs.md` to name the crash restart's `.chdir`, then reported the test comment as "stale, not mine to edit". Its definition says a comment that must change is a `rejected` and a merely stale one is a note, and the writer read this case as the latter. Review 1 R2 read it as a defect, because the comment and its mirror now disagreed.
- **The rejection's cost.** R1 and R2 together sent the task back, and the round cost $6.09: `architect-2` $1.45, `test-writer-2` $0.41, `coder-2` $1.01, `technical-writer-2` $0.61 and `reviewer-2` $2.61. R1 alone would have forced it, so better handling of R2 would have saved little.
- **A word budget dropped a fact.** The `AppDelegate.swift` entry of `crates/wolf-macos/Sources/WolfMacOS/README.md` was at 249 of 250 words, and `technical-writer-1` cut what the About credits hold to fit `openFolder`. Review 1 named it as minor, and `technical-writer-2` put it back by cutting elsewhere in the same entry. The file is 50,656 bytes, over the advisory ceiling.
- **The GNOME READMEs cost the writer again.** `technical-writer-1` ran 115 turns ($7.51) with 42 `python3` commands across 20 files, paying for each GNOME addition with a cut. `crates/wolf-gnome/tests/README.md` grew to 127,590 bytes and `crates/wolf-gnome/src/README.md` to 97,093.
- **One row kind is documented three times.** The "opens-or-raises" doc of Open Recent's palette row stood in `wolf_core::PaletteRowKind`, wolf-ffi's `palette_row_kind` and Swift's `PaletteSeam.PaletteRowKind`. Review 1 found one site, and plan 2 had to find the other two before `coder-2` changed all three.

## Recommendations

1. **Give an unplanned test its own ID at the test writer.** This is recommendation 1 of [sidebar-toggles-1](sidebar-toggles-1.md), come up again. In `.claude/skills/regina/agents/test-writer.md`, say that a test the plan does not ask for comes in the report with a proposed ID and disabling edit, never as an extra case of an existing ID. It would have given `coder-1`'s driver M10a to S6a and saved this task's round, $6.09.
2. **Have the architect turn a stale-name search into a list of test edits.** This is recommendation 1 of [application-state-7](application-state-7.md) and 3 of [sidebar-toggles-1](sidebar-toggles-1.md), come up again. In `.claude/skills/regina/agents/architect.md`, say that every test file its search for a changed behaviour lists is either given to the test writer or named as unaffected. `architect-1` had `nav_history_live.rs` in its own output.
3. **Say that a comment contradicting its own mirror must change.** In `.claude/skills/regina/agents/technical-writer.md`, define a comment that must change to include one whose `notes/` mirror the writer has just rewritten to say otherwise. `technical-writer-1` would then have returned `rejected` at its own turn, and the comment fix would not have waited for a review.
4. **Point the three palette row kind docs at one.** Keep the meaning of each row kind on `wolf_core::PaletteRowKind`, and have the wolf-ffi `palette_row_kind` constants and Swift's `PaletteSeam.PaletteRowKind` link it rather than restate it. Plan 2 had to search for the other two sites, and the next change to a row's behaviour would meet the same three.
5. **Split `crates/wolf-macos/Sources/WolfMacOS/README.md` and the wolf-gnome READMEs.** This is recommendation 4 of [application-state-7](application-state-7.md) and 8 of [application-state-8](application-state-8.md), come up again. The full `AppDelegate.swift` entry cost review 1 a finding and `technical-writer-2` a turn, and the GNOME entries cost `technical-writer-1` most of its 115 turns.
