# Retrospective: scope `:swift_format.fix` to its arguments and keep `:rustfmt.fix` off doc-lint's fixtures

Last verified at commit `4d6407c49e05b8c46cd0bafb7b6c663f03923444`.

The task gave `tools/lint/swift_format_fix.sh` a per-file mode, added the macOS-only `//tools/lint:swift_format_fix_test`, and moved doc-lint's fixtures into the `:fixtures` and `:files_mode_fixtures` filegroups out of the reach of the rules_rust writer behind `:rustfmt.fix`. It carried out recommendation 4 of [open-items-1](open-items-1.md), recommendation 2 of [open-items-4](open-items-4.md) and recommendation 1 of [open-items-10](open-items-10.md). Its commits are `6cc6e25` and `4d6407c`; the rest of `588bdbe..HEAD` is the previous task's, reported in [retro-fixes-1](retro-fixes-1.md).

It ran once through the flow with no rejection, `non-zero`, discrepancy or resume. Plan 1, one invocation per agent, both gates green on both workers on their first run, and review 1 approved with minor notes. The five invocations cost about $6.72: `architect-1` $2.48 (33 turns, 10 minutes), `reviewer-1` $1.55, `coder-1` $1.08, `technical-writer-1` $0.92 and `test-writer-1` $0.68.

## What went well

- **Plan 1 measured the hard part once, so the coder did not.** `architect-1` read rules_rust 0.71.2's `tools/rustfmt/src/main.rs`, ran its query on the base (162 files, 16 of them fixtures), found the two targets with `rdeps`, and showed that a filegroup moves files out of the depth-1 query. `coder-1` then needed one query to confirm 146 files and no fixture, and finished in 27 turns. The mechanism is written down in the `:rustfmt.fix` bullet of `tools/lint/README.md` and in the Fixtures decisions of `tools/doc-lint/tests/README.md`, so a later task can skip that reading.
- **The checker test was the model for the fixer test.** `swift_format_check_test.sh` and the `testdata/swift_format/` pair from the previous task gave `test-writer-1` the shape and the fixtures, and it wrote the test in 12 turns. The test's failure lines let `coder-1` show the task's falsifier (28 failures) and a second one, the under-root check without its trailing `/` (4 failures, all in the `ws-sibling/E.swift` case), fail for distinct reasons.
- **Plan 1 named the bash the test would run under.** `architect-1` ran a probe `sh_test` and found Bazel's test `PATH` gives macOS `/bin/bash` 3.2, where the old fixer's `mapfile` fails. The plan's step 5 told the coder so, and the first gate passed. The constraint is in the `swift_format_fix.sh` entry of `tools/lint/README.md`; keep it there.

## What did not go well

- **Plan 1 again asked the test writer to run a test.** Its step 1 had `test-writer-1` confirm that the test fails on the base, which the test writer's definition forbids ("Run no test"). `test-writer-1` left it to `coder-1`, which ran it (13 failures, `mapfile: command not found`), and review 1 had to weigh the deviation. It cost little here; it is the fifth report to find it.
- **Three agents read the rules_rust runner's source.** `architect-1` fetched it from GitHub, then `technical-writer-1` and `reviewer-1` each found and read it in the output base. The second reading found that plan 1's "a Rust target with an `edition`" was too narrow, since the runner also queries targets with no edition. The README bullet now holds the fact, so this should not recur unless rules_rust changes.
- **The fix rests on a private query that nothing checks.** Plan 1 decided against an automated test, because `genquery` forbids wildcards and would have to copy the runner's query. A rules_rust bump that widens the query's depth would put the fixtures back in reach without failing any gate, and the first sign would be another task restoring `blocks.rs`, `lexing.rs` and `limits.rs`.
- **The swift-format lookup and file list are kept in three places.** Plan 1's step 4 copied `find_swift_format` from `swift_format_check.sh` into `swift_format_fix.sh` byte for byte. `tools/lint/fix_all.sh` (`:fix`) has a third, divergent copy using `xcrun` alone, its own `find` over `crates/wolf-macos/Sources` and `Tests`, and `mapfile`. `technical-writer-1` found `tools/lint/README.md` describing the fallback chain for all three and corrected it, and review 1 listed `:fix` as a follow-up.
- **`:fix` still formats every Swift file.** `build.md` gives `bazel run //tools/lint:fix`, and its swift-format step does not go through the scoped fixer. An agent that follows `build.md` instead of `tools/lint/README.md` still rewrites all wolf-macos Swift files, which is the hazard this task removed from `:swift_format.fix`.
- **The macOS gate log again showed only totals.** `coder-1` grepped `target/gates/test.log`, found no per-target line, and read `bazel-testlogs` to show that `doc_lint_fixtures_test` and `swift_format_fix_test` ran. `reviewer-1` repeated the search, down to `test.cache_status`.
- **`CLAUDE.md`'s lint-script rule is broken a second time.** `swift_format_fix_test.sh` has no Linux `run` line in `gates.sh`, by plan 1's design and the task's instruction, as `swift_format_check_test.sh` has none. The rule still asks for one.
- **The new test inherits the caching gap.** `:swift_format_fix_test` runs the host Xcode swift-format and carries only `no-sandbox`, so Bazel caches its pass across a swift-format change, like the two targets [retro-fixes-1](retro-fixes-1.md) names.

## Recommendations

1. **Say in the architect's definition that the test writer runs no test.** This came up again: it is recommendation 3 of [open-items-1](open-items-1.md), recommendation 1 of [open-items-3](open-items-3.md), recommendation 2 of [open-items-13](open-items-13.md) and recommendation 1 of [retro-fixes-1](retro-fixes-1.md). `architect-1`'s system prompt in this task still did not rule it out.
2. **Make `:fix` call the scoped fixer.** In `tools/lint/fix_all.sh`, replace the swift-format step's lookup and `find` with a run of `swift_format_fix.sh` (a `data` dependency of `:fix`), and move `find_swift_format` into one file that `swift_format_check.sh` and `swift_format_fix.sh` both source. That removes the divergence `technical-writer-1` had to document, the `mapfile` copy, and the whole-checkout rewrite behind `build.md`'s `:fix`.
3. **List each test target's result in the macOS gate log.** This came up again: it is recommendation 5 of [open-items-9](open-items-9.md) and recommendation 4 of [open-items-10](open-items-10.md). Here both `coder-1` and `reviewer-1` went to `bazel-testlogs` for it.
4. **Write the `CLAUDE.md` exception for host-swift-format scripts, and tag them `external`.** These came up again: they are recommendations 3 and 2 of [retro-fixes-1](retro-fixes-1.md), and `:swift_format_fix_test` is now a third target each applies to.
5. **Tie the rules_rust bump to the fixture query.** Next to the `rules_rust` pin in `MODULE.bazel`, or in the `:rustfmt.fix` bullet of `tools/lint/README.md`, say that a bump must rerun plan 1's query (`filter("^//.*\.rs$", kind("source file", deps(attr(edition, ".*", //...), 1)))`) and confirm no `tools/doc-lint/tests/fixtures/` path appears. That is the check `coder-1` ran by hand, and it would catch the regression no gate sees.
