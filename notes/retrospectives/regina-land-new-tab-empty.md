# Retrospective: New Tab opens New Window's empty tab, with a captured sidebar

Last verified at commit `041db59fb87a3d1eee8f168d2c3e2bc9ab7f95fc`.

The task made New Tab, on both front-ends, open the empty tab New Window opens, and made a folder opened into it take the origin's sidebar visibility when the folder has no project state. It touched 42 files: GNOME code and twelve `smoke_headless` files, the macOS seam and `AppDelegate`, §6 and §7 of `specs/application-state.md`, and the docs. Every gate passed on its first run on both workers.

The nine invocations cost about $45.40 and 96 minutes of agent time. The first pass, `architect-1` to `reviewer-1`, cost $40.64; `coder-1` alone was $12.50 over 237 turns. Review 1's rejection added `architect-2`, `coder-2`, `technical-writer-2` and `reviewer-2`, for $4.76, plus a second run of both gates on both workers. There was no failed gate, discrepancy or resumed turn.

## What went well

- **New Window's plan function made "the same empty tab" one call.** `AppShell::new_tab` builds its tab from `state_seam::restore_plans(None, None, home, Path::is_dir)` through `window::tab_parts`, the call `Coordinator::open_new_window` makes, and macOS's `makeNewTab(from:)` reuses `startEmptyStateWindow`. Plan 1 D1 needed no new construction path, and both reviews found the two kinds of empty tab identical by construction.
- **The macOS rule fitted a pure seam.** `OpenFolderSeam.sidebarVisible(stored:newTab:)` holds the whole precedence, so OS1 to OS3 test it in `//crates/wolf-macos:WolfKeyMapTests` with no AppKit. This is the pattern [application-state-10](application-state-10.md) praised for `StateSeam.newWindowFrame`, and it kept working.
- **doc-lint made the §7 heading rename safe.** Renaming `## 7. New windows` broke nine links in seven files; plan 1 listed them, and the `md-anchor` check confirmed none was left. It also checked the root-relative path that `coder-2` put in `Command::NewTab`'s doc.
- **`regina on linux` let `coder-1` measure every GNOME red before the gate.** The OP, TT, NE, NT2b, E22b and C1 reds were all taken on the Linux worker, and review 1 matched each to Regina's command logs. This has been recorded in several earlier reports and held again.
- **The OCR fixture guards made the new smokes prove their terms.** `fixture_guards.rs` refused `wolf` in `ASSERTED_OCR_TERMS` because `TEMP_CWD_PREFIX` spells it, which pushed `test-writer-1` to find that the pointer helper's files and typed runtime paths also put `wolf` on screen. The resulting `the_new_tab_fixtures_cannot_draw_their_terms` guard is what makes NE2 and NE3 non-vacuous.

## What did not go well

- **Review 1 rejected the work for one stale doc comment in a crate the plan did not touch.** `Command::NewTab` in `crates/wolf-core/src/command.rs` said New Tab opens "a new captive Neovim in the same directory". Plan 1's sweeps were split by owner: the test sweep grepped test directories, the doc sweep grepped `*.md`, and the coder's covered the GNOME files plan 1 named. No sweep reached `crates/wolf-core/src`, and the round trip cost $4.76 and two more gate runs for a two-line change.
- **The command registry's doc restates front-end behaviour that the spec owns.** The variant docs in `crates/wolf-core/src/command.rs` describe each command's behaviour, so every behaviour change in `specs/application-state.md` leaves a copy in core to go stale. [application-state-2](application-state-2.md) recommendation 3 asked the architect's sweep rule to cover docstrings; it came up again here.
- **Twelve inline New Tab presses in seven smoke files depended on directory inheritance.** `drawer_divider.rs`, `extras.rs`, `panes.rs`, `recovery.rs`, `restore.rs`, `terminal.rs` and `titlebar.rs` each press `wtype -M ctrl -M shift -k t` in their own script to get a second folder tab. `test-writer-1` added a `:cd` after each (plan 1 D7), with its own env var, comment and doc sentence in every smoke.
- **The D7 smokes first ran in `coder-1`'s full Linux gate, and nine failed.** The test writer does not run tests, and `coder-1` ran only `new_tab::` before `regina on linux -- ./gates.sh`. The failures exposed a latent bug: `settle_reroot` left an empty tab empty when a `:cd` landed in the folder the sidebar was already rooted at, which New Tab now makes common. Finding and fixing it took a second full Linux gate and about 70 of `coder-1`'s 236 tool calls, most of them polling.
- **Plan 1 D5 rested on a fallback that a live tab never shows.** It assumed an empty GNOME tab is titled "Untitled", from `TAB_TITLE_FALLBACK` in `crates/wolf-gnome/src/tabs_ui.rs`. Every Neovim names its anonymous buffer `Untitled.md` (`runtime/nvim/init.lua`), so the tab drew `Untitled.md`, and `coder-1` learned it from S1's first OCR run. Nothing next to `tab_title` said so at the base; `notes/wolf-gnome/application-state.md` says it after this task.
- **`notes/wolf-macos-decisions.md` crossed the size warning.** `technical-writer-1` took it from 49,834 to 50,294 bytes, over the 50,000-byte ceiling of `tools/lint/markdown_check.sh`. This is [app-state-fixes-1](app-state-fixes-1.md) recommendation 2, come up again.
- **A false doc on New Window was left out of scope twice.** The `dispatch` doc in `crates/wolf-macos/Sources/WolfMacOS/CommandDispatcher.swift` says `.newWindow` inherits `originatingCwd`, and `makeNewWindow` ignores it. Review 1, plan 2 and review 2 each noted it and left it, as [application-state-7](application-state-7.md) did for another false macOS doc.
- **The macOS AppKit glue has no automated test.** `makeNewTab(from:)`, `fill(_:from:)`'s hand-over and `build()`'s collapse are covered only by the person checks in review 2 §7, as plan 1 D8 decided. Review 2 also notes that no GNOME smoke sends `wolf DIR` into New Tab's tab.

## Recommendations

1. **Make `Command`'s variant docs link the spec instead of restating behaviour.** In `crates/wolf-core/src/command.rs`, have each variant's doc say what the command is and link the spec section that owns its behaviour, as `coder-2`'s rewrite of `NewTab` does. Review 1's only code finding was such a restatement, and it cost the round trip.
2. **Extend the architect's sweep rule to doc comments in every crate.** In the architect definition, beside the rule that a sweep is planned by rule and check, say that a behaviour change sweeps `///` docs across all of `crates/*/src` and `crates/wolf-macos/Sources`, not only the crates the plan edits, and assigns the hits to the coder. This is [application-state-2](application-state-2.md) recommendation 3, come up again; it would have caught `Command::NewTab` in plan 1.
3. **Give the GNOME smokes one shell helper for a second folder tab.** Add a function to a shared preamble in `crates/wolf-gnome/tests/smoke_headless/main.rs`, beside `with_nvim_pid_helper`, that presses New Tab and `:cd`s it to the project, and call it from the twelve sites. `test-writer-1` edited seven files for D7, and the next change to New Tab or to the empty state would touch one function.
4. **Have the coder run every smoke the test writer changed before the full gate.** In the coder definition, say that test files the test writer reworked, not only new ones, run on their worker before `./gates.sh`. `coder-1` would have met the `settle_reroot` bug in a targeted run of the nine D7 smokes rather than in a full Linux gate.
5. **Keep `wolf` out of the GNOME smoke fixture names.** Rename `TEMP_CWD_PREFIX` (`wolf-gnome-smoke-`), `RUNTIME_DIR_PREFIX` (`wolf-smoke-rt-`) and the `wolf-pointer.*` names in `smoke_headless/main.rs` to prefixes that do not spell the app's title. Then `wolf` can join `ASSERTED_OCR_TERMS`, and `new_tab.rs` drops its runtime-dir overrides and private guard; `test-writer-1` spent three of its seven departures working around these names.
6. **Say at `tab_title` what a fresh tab's current file is.** In the `tabs_ui.rs` entry of `crates/wolf-gnome/src/README.md`, say that every Neovim's anonymous buffer is `Untitled.md`, so a folder tab with no opened file is titled by it and not by `TAB_TITLE_FALLBACK`. Plan 1 D5 would then have planned the empty-state filter `coder-1` had to add.
7. **Split `notes/wolf-macos-decisions.md` and fix the `CommandDispatcher` doc.** Both are known: the first is [app-state-fixes-1](app-state-fixes-1.md) recommendation 2, now over the ceiling, and the second is one false sentence about `originatingCwd` that two reviews flagged and left.
