# macOS follow-ups

Last verified at commit `cc60afb1257ee0c5474105e363d0d452ba050afb`.

Wolf's macOS side — the `wolf-ffi` Swift bindings and the `wolf-macos` AppKit app — builds and tests **only** under Bazel/bazelisk on a macOS Tahoe (26) host with Xcode 26+ (see [`build.md`](../build.md), "Building on macOS (Bazel)"). This development machine is Linux/NixOS with no Bazel and no Xcode, so nothing done on a Linux branch can be verified against macOS here. This file is the ledger the later macOS merge pass works through.

The standing rule that fills it: any change to a `wolf-core` public API consumed by `wolf-ffi` or `wolf-macos` must be (a) reflected in the relevant README or [`specs/architecture.md`](../specs/architecture.md), and (b) appended here. Likewise any new `crates/wolf-core/tests/*.rs` needs a matching `rust_test` in `crates/wolf-core/BUILD.bazel` — which cannot be validated from Linux, since Bazel does not auto-discover test files — and so does any `BUILD.bazel` or `MODULE.bazel` edit.
